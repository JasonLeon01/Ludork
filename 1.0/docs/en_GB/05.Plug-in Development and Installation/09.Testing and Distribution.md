# Testing and Distribution

## Goal

Prepare a source plug-in directory that another Ludork 1.0.0 user can review, import, restart and verify without relying on the author's build tree.

## Prerequisites

- A valid manifest with a globally unique ID and a `minimumEditorVersion` of at least `1.0.0`.
- Source that compiles through **Import Plugin**.
- A licence for the plug-in, and notices for every redistributed third-party component or asset.

## Steps

1. Remove build outputs, local settings, secrets, credentials, test projects and `.data` from the distribution directory.
2. Keep `plugin.json`, every required `.cs` file, plug-in-owned resources, licence files, and concise installation and restart instructions.
3. Build the optional IDE project with .NET 9. This catches normal compiler diagnostics but does not replace host compilation.
4. Import the clean directory into a fresh development editor, restart, and check **Manage Plugins**.
5. Test every registered command, text provider and operation hook in `en_GB` and `zh_CN`. Exercise the missing-project, cancellation, invalid-input and handled-failure paths.
6. For before-Export, before-Run and before-Pack hooks, test ordering, failure blocking and output. For Export hooks, verify the editor detects added, modified or deleted declared inputs and missing or modified outputs across project reopen; verify no successful record is published if input changes during export. Confirm Pack runs Export once before before-Pack hooks. Inspect `Packaging` only during Pack, and verify every compiled directory and excluded file in the final package.
7. For map or Blueprint bridges, force a revision conflict and confirm that the plug-in refuses to overwrite newer editor state. For Resource Cleanup, change a project input after scanning and verify recycling is refused, test cancellation and a recycling failure, and restore disposable test files from the operating-system Trash. Verify empty project keep lists are not created and native protected entries are never written into project additions.
8. Import the same directory into a clean published editor and repeat the user-facing smoke test.
9. Archive the exact source directory, and publish a checksum, version history, supported editor range, licence and support contact.

## Limitations

Ludork does not provide a plug-in marketplace, signature authority, dependency resolver, NuGet restore or prebuilt binary plug-in format. Distribution trust, release signing, update communication and third-party legal compliance remain the publisher's responsibility.

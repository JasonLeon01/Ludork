# Script Mixin 运行时契约

运行时把选中的模块按 `Mixins.<点分路径>` 加载，并要求它返回一个不带元表的 Lua 表。本页约定生成蓝图类的成员、实例默认值、保留名称与父方法分派规则。

## 表的规则

- 每个键都必须是字符串。
- 函数会成为生成蓝图类上的方法。
- 非函数值会深复制到类默认值与实例默认值。
- 继承来的成员不能在字段与函数之间改变种类。
- 已保存的蓝图属性不能替换 mixin 方法。

以下名称属于保留名称：

```text
__*  init  new  scriptMixin  scriptPath
_GENERATED_CLASS  _graph  _hasImplementationOwner
```

`init` 是保留名称，因此直接挂载的 Script Mixin 不声明构造函数。私有实例状态在所属类型提供的生命周期回调（如 `onCreate`）中初始化，订阅与资源在对应的清理回调中释放。

## 调用父方法

在 mixin 方法内用 `super()` 继续蓝图与原生继承链：

```lua
local Door = {}

function Door:onCollision(other)
    if self.opening then
        return
    end
    super().onCollision(other)
    self:openDoor()
    self.opening = true
end

return Door
```

父类必须提供 Mixin 使用的原生属性和方法。缺失成员会在调用时触发错误。

## 热更新

控制台的 `$r` 命令更新已使用 Script Mixin 中已有的方法，不会重新执行 `onCreate` 或清理回调。mixin 默认值与实例状态保持不变，结构改动需要重启。兼容性与失败规则见 [Lua 热更新](<../Lua 运行时与模块.md#lua-热更新>)。

Lua 编译和 `.ldpak` 打包不会改变 Mixin 的模块路径或重新加载规则。打包选项见[运行、调试与打包](<../../编辑器用户指南/运行、调试与打包.md>)。

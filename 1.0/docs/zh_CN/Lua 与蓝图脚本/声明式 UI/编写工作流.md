# 声明式 UI 编写工作流

Ludork 的声明式 UI 由 JSON 资产生成 Lua View，业务行为则写在手写 Controller 中。可视化编辑请使用 [UI 资产编辑器](<../../编辑器用户指南/UI 资产编辑器.md>)。

| 层 | 拥有内容 |
|---|---|
| JSON View | 层级结构、资产内节点名、静态控件属性、Slot、动画 Timeline 与仅用于设计的预览数据 |
| 生成的 Lua View | 完整的类型化控件与子 View 树、资产身份、挂载与所拥有对象的生命周期 |
| Lua Controller | 模型访问、回调、本地化与格式化文本、状态刷新与动态组合 |
| 窗口 UI | 原生窗口与输入状态，以及该窗口持有的生成 View 与私有 Controller |
| 原生控件 | 渲染、测量、命中测试、焦点与基础交互状态 |
| UIManager | 挂载和移除已准备的根控件 |

Controller 函数、表达式、事件处理器与 `LOC(...)` 调用一律不得写入 UI 资产。

固定位置、尺寸、间距和文本样式写在 JSON 中。内容需要测量或改变尺寸时，Controller 读取准备好的控件，静态排布交给资产。修改固定值时，编辑对应资产并重新生成 View。

## 步骤

### 文件布局

资产根目录固定为 `Data/UI/Assets`：

```text
Data/UI/Assets/
    ├── Inventory.json
    └── Parts/
        ├── Inventory/ItemRow.json
        └── Shared/KeyPrompt.json
```

完整的屏幕、窗口、HUD 与浮层直接放在 `Assets` 下。某个大型 UI 自有的部件放入 `Parts/<Owner>`，多个 UI 共用的部件放入 `Parts/Shared`。不得创建只按控件形态划分的目录。

生成的 Lua View 与资产层级一一对应。`Scripts/Internal/UI` 与 `Scripts/stub/Internal/UI` 下的每个文件都由生成器维护：

```text
Scripts/Internal/UI/
├── Inventory.lua
└── Parts/
    ├── Inventory/ItemRow.lua
    └── Shared/KeyPrompt.lua
```

手写基础模块放在 `Scripts/Internal/UIBase` 下。窗口模块（例如 `Scripts/Source/Windows/WindowInventory.lua`）在文件内定义私有 Controller，并通过 `Ui.DefineWindow` 返回 UI 类。独立行 Controller 与 Scene Controller 各自单独成模块，例如 `Source.Windows.WindowInventory.ItemRow.Controller` 与 `Source.Scenes.SceneTitle.Controller`。

配套的窗口 stub 只声明私有 Controller，使用不带模块名的 `---@meta`。公开窗口声明生成到 `Scripts/stub/Internal/UIWindows`，不得手工修改。声明格式见[声明式 UI Controller 示例](<Controller 示例.md#业务成员只声明一次>)。

### 创建 UI 并添加业务行为

1. 在 UI 资产编辑器中创建 JSON 资产，为运行时访问的节点取稳定的名称。
2. 启用 **Exposed**，资产才会出现在 Project Palette 中。
3. 保存资产，再点击 **导出** 生成 View，然后在窗口模块中 require 该 View。
4. 定义局部 Controller，返回 `Ui.DefineWindow(ViewClass, Controller, nativeBase?)`。业务初始化写在 `init` 中，回调写在 `bind` 中，状态更新交给 `watch` 或 `refresh`。
5. 窗口的初始行为用 `windowOptions`，资产中已有的子界面用 `createChild`，行数随模型变化的行用集合。参见[声明式 UI 运行时契约](<运行时契约.md>)与[声明式 UI Controller 示例](<Controller 示例.md>)。
6. 维护私有 Controller 声明并重新生成。由所属场景或窗口创建并挂载，不再需要时将其释放。可选弹窗各自持有 `Internal.UIBase.LazyWindow` 句柄，由其工厂完成完整构造、回调与焦点配置以及挂载；显示入口使用 `get()`，查询使用 `peek()`，详见[首次使用时创建窗口](<运行时契约.md#首次使用时创建可选窗口>)。

使用 `WindowBase` 或 `WindowSelectable` 的资产嵌套共用部件 `Parts/Shared/WindowChrome` 与 `Parts/Shared/WindowPauseMark`，节点名分别为 `WindowChrome` 与 `WindowPauseMark`。Slot 将窗口部件覆盖在边框上，将暂停标记放在内容底边。这两个资产负责返回按钮、手柄提示和暂停标记的布局，窗口基类绑定其行为。

### 资产变更后重新生成

移动资产或重命名节点之后，更新手写的 `require` 调用与节点引用，再点击 **导出**。也可运行 `ScriptTools ui-assets generate <project-root>`，只同步 UI View 和声明并删除不再需要的生成文件。普通保存和编译不生成这些文件；直接从命令行运行或打包前，需要先导出。完整导出流程见[运行、调试与打包](<../../编辑器用户指南/运行、调试与打包.md>)。

## 限制

每个可见界面只有一个顶层资产。多窗格界面从 `Parts/<TopLevelName>/` 嵌套该界面的专用部件。嵌套部件设置 `palette.exposed = true`，只供运行时使用的辅助资产可以不暴露。

`#TAB`、`#ITEM` 子项与 Game 视觉资源只取有代表性的样例，仅作预览数据，不用于填补缺失的游戏数据。显示之前，业务代码负责本地化 Tab 标签并填充动态集合。固定控件与固定行始终是 JSON 创建的那一份实例。字面 `text` 只留给永久且与语言无关的符号。

逐帧动画的角色与敌人使用 `Engine.CharacterView`。资产提供预览值，运行时把真实的纹理、Rect、缩放、动画、Shader 与 Hue 传给 `setCharacter`。Lua 不负责裁剪或合成 Actor 视觉。

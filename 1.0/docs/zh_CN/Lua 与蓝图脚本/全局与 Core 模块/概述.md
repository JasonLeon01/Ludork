# 全局与 Core 模块总览

本组是三个原生 Core 模块的 API 参考——每个 Lua 状态都用 `require` 加载 `Engine`、`GlobalCore` 与 `GlobalFunctions`——同时覆盖 Game 项目的共享 Lua 模块层 `Global`。这里按 Lua 根名称而不是按主题划分，因为根名称决定成员的调用方式、是否出现在 Blueprint 图中，以及由哪些文件声明它。

## 四个名称

`Engine`、`GlobalCore` 与 `GlobalFunctions` 是从 `Engine/Source` 构建的 C++20 模块。[构建与模块布局](<../../C++ 原生开发/构建与模块布局.md>) 列出它们的职责与原生依赖方向，[生成 Metadata 与 Stub](<../../C++ 原生开发/生成 Metadata 与 Stub.md>) 说明 Core bindgen 为每个模块生成的 `Scripts/stub/<Module>.d.lua` 声明与 `Scripts/<Module>_meta.lua` metadata。`Global` 不是原生模块：它是 `Scripts/Global` 下的普通项目 Lua，其在项目布局中的位置见 [项目设置与资产布局](<../../编辑器用户指南/项目设置与资产布局.md>)。

| 名称 | 是什么 | 定义位置 | 本组页面 |
|---|---|---|---|
| `Engine` | 引擎类型、服务、状态与玩法基础的原生根模块：`Actor`、`Character` 与 `Component`；曲线与动画数据；TileLayer、Tilemap、自动图块与材质；输入；`Clock`、`RenderStates`、粒子与 `Emitter`；控件、文本与窗口类；`EventBus` 与模块根。`LudorkRuntime` 不暴露自己的 Lua 根，因此 Runtime 持有的值与 Blueprint 类型同样注册在这里。 | C++ 位于 `Engine/Source` 与 `Engine/Runtime`，通过 `require("Engine")` 加载；生成 `Scripts/stub/Engine.d.lua` 与 `Scripts/Engine_meta.lua`。Game 项目没有 `Scripts/Engine/` Lua 目录。 | `Core Modules/Engine/`，13 页 |
| `GlobalCore` | 全局游戏类与服务的原生根模块：`Camera` 与焦点相关类；`GameMapBase`、雾效、全景与世界流式加载；`Animation` 与 `Light`；`AudioManager`、`FontManager`、`ShaderManager` 与 `TextureManager`；`TimeManager`；`SceneBase`、`SceneManager`、`System`、`Display`、`Graphics`、`ScreenEffects` 与 `Transition`；`UIManager` 与 `WeatherController`；以及能力系统。 | C++ 位于 `Engine/Source`，通过 `require("GlobalCore")` 加载；生成 `Scripts/stub/GlobalCore.d.lua` 与 `Scripts/GlobalCore_meta.lua`。Game 项目没有 `Scripts/GlobalCore/` Lua 目录。 | `Core Modules/GlobalCore/`，7 页，另有 [GlobalCore Gameplay API](<Global APIs/Gameplay.md>) |
| `GlobalFunctions` | 自由函数的原生根模块，分为四个分组 table：`Components`、`Manager`、`NodeGraph` 与 `UI`。`Scripts/GlobalFunctions_meta.lua` 为空，因此这些函数是 Lua API，而不是 Blueprint 节点。 | C++ 位于 `Engine/Source/GlobalFunctions/include/GlobalFunctions`，通过 `require("GlobalFunctions")` 加载；生成 `Scripts/stub/GlobalFunctions.d.lua`。 | [GlobalFunctions Lua API](<Core Modules/GlobalFunctions.md>)，1 页 |
| `Global` | Game 项目的共享 Lua 模块，通过点分路径 require，例如 `require("Global.GameMap")` 与 `require("Global.Utils.Logging")`。静态依赖从原生根模块流向 `Scripts/Global`，再流向 `Scripts/Source`；Global 模块不得 require Source。 | Lua 位于 `Scripts/Global/`，对应声明镜像在 `Scripts/stub/Global/`，并按模块提供 metadata，例如 `Scripts/Global/GameMap_meta.lua`。 | [Global.GameMap](<Global APIs/GameMap.md>)，1 页 |

`Scripts/Global` 还包含根模块 `ActorTree`、`Pool`、`Tutorial`、`WorldGameMap`、`WorldGeometry` 与 `WorldMapConstants`，`Components`、`CustomEffects`、`CustomParticles` 与 `Utils` 目录，以及 `GameMap.lua` 与 `WorldGameMap.lua` 的同名实现目录。其中只有 `Global.GameMap` 在本组有页面。

第五个名称与第三个重名：`Scripts/GlobalFunctions/` 中的 Lua 蓝图函数库以独立模块加载，例如 `require("GlobalFunctions.Math")`，不会加入原生根表。它们记录在 [节点函数总览](<../节点函数/概述.md>)，不在本组。

### `Global APIs` 中的两个命名空间

目录名并不对应命名空间，两个页面的 H1 也互不相关：

- [Global.GameMap](<Global APIs/GameMap.md>) 记录 `Scripts/Global/GameMap.lua` 中的 Lua 类。它的 `Metadata 来源：` 一行标明 `Scripts/Global/GameMap_meta.lua`，其中声明的基类是 `{ "GlobalCore", "GameMapBase" }`：项目类继承自原生 `GlobalCore` 类型，原生一侧见 [GameMapBase](<Core Modules/GlobalCore/地图与雾效.md#gamemapbase>)。
- [GlobalCore Gameplay API](<Global APIs/Gameplay.md>) 记录 `require("GlobalCore")` 暴露的能力系统：`AttributeSet`、`AbilitySystemComponent`，以及能力、结果、事件、效果与 spec 等类型。它属于原生模块，尽管位置在 `Core Modules/GlobalCore/` 之外。

判断自己在调用哪个根模块时，要看页面的 H1，而不是它所在的目录。表格中的类型写法遵循 metadata schema：Core 类型写作 `{ "Module", "Type" }`，例如 `{ "Engine", "Actor" }` 或 `{ "GlobalCore", "Camera" }`；项目 Lua 类则带上模块路径，例如 `{ "Global.GameMap", "GameMap" }`。这一写法以及 `Execution and metadata` 列中的 `Pure`、`ExecSplit` 条目，由 [Metadata 结构与 Decorator](<../蓝图脚本/Metadata 结构与 Decorator.md>) 定义。

## 目录结构

本组共有 23 个参考页面加上本页总览，嵌套三层。

```text
全局与 Core 模块/
├── 概述.md                       本页
├── Global APIs/                  2 页
└── Core Modules/
    ├── Engine/                  13 页
    ├── GlobalCore/               7 页
    └── GlobalFunctions.md        1 页
```

| 子目录 | 内容 | 页数 | 起始页面 |
|---|---|---|---|
| `Global APIs/` | 两个不按模块划分的页面：项目 Lua 类 `Global.GameMap`，以及 `require("GlobalCore")` 暴露的能力系统。 | 2 | [Global.GameMap](<Global APIs/GameMap.md>) |
| `Core Modules/Engine/` | `Engine` 模块的绑定类，分为 13 个主题页面，从 `标量曲线.md` 到 `交互与声明式 UI 控件.md`。 | 13 | [Engine：标量曲线](<Core Modules/Engine/标量曲线.md>) |
| `Core Modules/GlobalCore/` | `GlobalCore` 模块的绑定类，分为 7 个主题页面，从 `摄像机与焦点.md` 到 `UI、天气与模块根.md`。 | 7 | [GlobalCore：摄像机与焦点](<Core Modules/GlobalCore/摄像机与焦点.md>) |
| `Core Modules/GlobalFunctions.md` | 原生 `GlobalFunctions` 根模块：四个分组 table、三个根模块的加载顺序，以及各加载函数的资源路径规则。 | 1 | [GlobalFunctions Lua API](<Core Modules/GlobalFunctions.md>) |

Engine 与 GlobalCore 页面会列出每个绑定类的直接 metadata 基类、可编辑属性，以及带 Blueprint 执行 metadata 的函数与事件。部分页面在开头给出一条适用于该页所有类的规则说明，例如 [Engine：地图与材质](<Core Modules/Engine/地图与材质.md>) 与 [GlobalCore：资源管理器](<Core Modules/GlobalCore/资源管理器.md>) 的资源路径规则。

## 阅读顺序

1. [Lua 运行时与模块](<../Lua 运行时与模块.md>) —— 三个原生根模块的加载顺序、`.lua`、`stub/**/*.d.lua` 与 `_meta.lua` 三类文件的归属，以及 `Global` → `Source` 的依赖方向。
2. [GlobalFunctions Lua API](<Core Modules/GlobalFunctions.md>) —— 单页内容：四个分组 table，以及各加载函数的类别相对路径规则。
3. [Engine：玩法类型](<Core Modules/Engine/玩法类型.md>) —— `Actor`、`Character` 与 `Component`，这些类型出现在大多数其他页面的参数与返回列中。
4. [GlobalCore：场景与系统](<Core Modules/GlobalCore/场景与系统.md>) —— `SceneBase`、`SceneManager`、`System`、`Display` 与 `Graphics`：持有运行中游戏的各项服务。
5. [Global.GameMap](<Global APIs/GameMap.md>) 配合 [GameMapBase](<Core Modules/GlobalCore/地图与雾效.md#gamemapbase>) —— 项目 Lua 类如何继承原生 `GlobalCore` 类，以及两个页面如何划分地图 API。
6. [GlobalCore：摄像机与焦点](<Core Modules/GlobalCore/摄像机与焦点.md>) —— 地图的视图与焦点导航。

其余 Engine 与 GlobalCore 页面是参考表格而不是连续叙述，按上面的清单依主题查阅即可。当项目使用属性、能力与效果时，再读 [GlobalCore Gameplay API](<Global APIs/Gameplay.md>)。

# GlobalCore：资源管理器

通用管理器要求大小写精确的 `/Game/Assets/...` 路径，既能读取松散文件，也能读取 `.ldpak` 归档。原生绝对路径、`Assets/...` 路径和类别相对路径均无效。

归档压缩对这些 API 透明。可 seek 的流逐块解压，文件大小与字节位置均以原始数据为准。每个读取的块都校验 CRC32，完整读取还会校验文件 CRC32。

## AudioManager

`AudioManager.setEffect(audioType, effect)` 接受 `Sound`、`Voice` 或 `Music`，为该类别后续的播放保存回调；传入 `nil` 清除回调，不影响已经播放的声源。回调签名为 `fun(source: sf.SoundSource, control: GlobalCore.AudioEffectControl, sampleRate: integer)`，其中 source 和 control 均不为 nil。每个新声源在播放前调用一次回调，传入当前播放设备的采样率。回调必须安装且只安装一个非空处理器；未安装或重复安装都会同步报错。

使用 Lua 处理器时，调用 `control:attachLuaProcessor(source, moduleName, resolverName, effectName, sampleRate)`。三个名称都是项目必须提供的字符串，原生层没有默认项目模块或解析函数。每次挂接都会创建独立 Lua 状态，通过 `require(moduleName)` 取得模块表，用 `effectName` 调用其中名为 `resolverName` 的函数，再以 `(nil, control, sampleRate)` 调用返回的 attacher，得到 `sf.SoundSource.EffectProcessor`。隔离状态中的 control 只暴露 `isCancelled()`、`beginTail()` 和 `finishTail()`，不能再次挂接处理器。模块加载、解析和处理器创建失败均同步向外传播，不会退回无处理器播放；后续音频回调中的错误通过 Manager 更新传播。

隔离状态使用 AudioManager 初始化时捕获的模块搜索路径，因此额外路径应在加载 `GlobalCore` 前配置。主状态中的闭包和对象不会传入音频状态。模块名称、解析函数和预设注册表由项目管理；内置预设、播放生命周期与取消规则见[默认玩法音频](<../../../Game 玩法/资源、音频、视频与特效.md#音频>)。

## TextureManager

### 函数与事件

| 名称 | 种类 | 参数 | 返回 | 执行语义与 metadata |
|---|---|---|---|---|
| `load` | `function` | filePath: string; sRGB: bool = false; area: sf.IntRect = nil; smooth: bool = false | return: sf.Texture | — |
| `getPath` | `function` | texture: sf.Texture | return: string or nil | 仅 Lua；`metadata = false` |
| `getMemory` | `function` | — | return: int | — |

`TextureManager.getPath(texture)` 按实际贴图实例查询管理器的当前缓存，返回原始资源路径。它不读取或加载文件，也不持有该贴图。管理器之外创建的贴图，或清理缓存后已不在其中的贴图，返回 `nil`。返回路径不包含 `load` 的 `area` 裁剪、sRGB 或平滑选项。

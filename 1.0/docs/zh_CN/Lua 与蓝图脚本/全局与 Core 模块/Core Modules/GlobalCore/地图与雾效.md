# GlobalCore：地图与雾效

## FogController

每个地图会话构造自己的 `GlobalCore.FogController.new()`。控制器持有配置，共用渲染器持有 GPU 资源。Game 为每个 `GameMap` 创建并连接一个控制器，因此修改一张地图不会覆盖另一张地图的雾。

| 实例方法 | 参数 | 返回 |
|---|---|---|
| `applyFromMapData` | `settings: Engine.MapFogSettings` | — |
| `applyWorldFromMapData` | `settings: Engine.MapFogSettings` | — |
| `setWorldRegionFog` | `key: string`、`cellRect: sf.IntRect`、`settings: Engine.MapFogSettings` | — |
| `removeWorldRegionFog` | `key: string` | — |
| `clearFog` | — | — |
| `getSettings` | — | `Engine.MapFogSettings` 副本 |
| `getWorldRegionSettings` | `key: string` | 配置副本或 `nil` |

区域方法与 `applyWorldFromMapData` 仅供运行时 Lua 使用。`applyFromMapData` 替换基础配置并保留区域配置。`applyWorldFromMapData` 清除原有区域并初始化大地图配置；`clearFog` 同时清除基础雾和区域配置。不再调用全局 `update` 或 `drawOverlay`。地图合成在材质与光照之后、前景天气和粒子之前，使用当前帧的绝对时间采样雾。

雾由 GPU 在大地图坐标中生成程序噪声，不需要贴图路径。先合成基础雾，再按稳定的摆放顺序合成驻留子区域雾，各自裁剪到摆放范围。同样的配置和时间可在相邻区域产生连续噪声。Lit 雾采样场景环境光与直接光，Unlit 使用配置颜色。字段与默认值见 [Engine.MapFogSettings](<../Engine/地图与材质.md#mapfogsettings>)。

## PanoramaController

### 函数与事件

| 名称 | 种类 | 参数 | 返回 | 执行语义与 metadata |
|---|---|---|---|---|
| `applyFromMapData` | `function` | mapData: { "GlobalCore", "MapPanoramaSettings" } | — | — |
| `clear` | `function` | — | — | — |
| `isActive` | `function` | — | return: bool | Pure |

`MapPanoramaSettings` 接受一个 Lua 表：`panorama` 为字符串。`panorama` 缺失或为 nil 时默认为 `""`。地图中的其他字段一律忽略。类型无效会报错。`panorama` 为空字符串时关闭底层远景。`applyFromMapData` 与 `applyWorldFromMapData` 共用这份配置。路径非空时立即加载贴图，加载失败会向上传播。

`getPath()` 返回当前远景路径。远景由共用合成器绘制，保留 Cover 缩放与跟随 Camera 的滚动规则。

### 区域可见性

对于普通有限地图，`setHideDisconnectedRegions(enabled)` 开关区域隐藏。`setVisibilityObserver(position)` 接受 `sf.Vector2i` 格子坐标，供预览指定观察位置；传入 `nil` 恢复跟随玩家。`isCellVisible(position)` 查询 tile 显示掩码，其中不可通行格保持可见。`isActorVisibleOnMap(actor)` 检查 Actor 及每个祖先的可见性标记和区域规则：可通行锚点按所属区域判断，不可通行锚点要求变换后的图像矩形覆盖可见的可通行格。`getHideDisconnectedRegions()` 是运行时查询当前开关的接口。`getVisibilityRevision()` 返回供显示与预览缓存使用的当前版本，关闭隐藏时也会跟踪地形变化。可见性查询在返回前处理待更新的变化。

地形变化后重新计算连通区域和替换源。同一区域内移动复用掩码，跨区域移动更新绘制与灯光。渲染器使用独立显示图层，保留真实 tilemap。选取规则和玩法效果见 [Global.GameMap](<../../Global APIs/GameMap.md#非连通区域隐藏>)。

## 共用地图渲染

`GlobalCore.GameMapRenderer` 把实时地图与 Actor 状态适配为 Core `MapRenderer` 输入，不再另行持有灯光算法。`drawContent` 保留调用者的 render states 并绘制有序内容。`composeFrame(ambientLight, time)` 将 Camera 内容与材质、光照、远景和雾合成。`prewarm(ambientLight, time)` 预热同一条渲染路径。`setFogController(controller)` 连接本地图的控制器实例，`setLayerOrder(names)` 同步大地图图层变化。

Core 渲染器接受场景、区域、精灵、光源和视口数据，不依赖 Actor 或 Lua，并在帧间保留渲染目标与光照缓存。编辑器普通地图、大地图画布和缩略图通过 PreviewHost 使用同一个渲染器。Unlit 使用白色环境光，不计算直接光或阴影，同时保留不透明度、反射、Actor/图层 shader 和色相。远景和雾是独立显示选项。Lit 使用输入的环境光与 Actor 灯光。

## 静态预览绘制

`GlobalCore.PreviewSprite` 与 `GlobalCore.GameMapRenderer` 是仅供运行时 Lua 使用的 API（`metadata = false`），不是蓝图节点。`PreviewSprite.new(table)` 接受以下显示字段：

| 字段 | 含义与默认值 |
|---|---|
| `layer`、`texture`、`rect` | 图层名、持有的 `sf.Texture` 或 `nil`、`sf.IntRect` 源矩形。 |
| `position`、`mapPosition`、`translation` | 像素锚点、区域可见性格子坐标、像素显示偏移。 |
| `rotation`、`scale`、`origin` | 角度制旋转（默认 `0`）、缩放（默认 `{1, 1}`）、像素原点。 |
| `visible`、`parentIndex` | 自身可见性（默认 `true`）；父记录使用从零开始的先前记录下标，根使用 `-1`。 |
| `hue`、`shaderPath` | 角度制色相（默认 `0`）与片段 shader 路径（默认空）。 |

`renderer:setPreviewSprites(records)` 只允许构造时设置了 `previewOnly = true` 的渲染器调用。它持有所需显示资源，在每个配置图层内保留记录顺序。父记录必须先于子记录，非法父下标会报错且不替换已安装记录。显式安装空数组表示不绘制静态精灵；安装记录之前，渲染器保持普通 Actor 绘制契约。

`renderer:setPreviewVisibility(flags)` 要求已经安装记录，且按相同顺序为每条记录提供一个布尔值。它只更新自身可见性，有效可见性还受祖先和地图区域规则控制。`texture = nil` 不绘制图像，但保留几何信息与父节点作用。几何数据已解析为地图坐标；`parentIndex` 只控制显隐，不组合父子变换。

静态 shader 绘制支持色相叠加，提供 `texture`、`textureSize`、`textureRect` 与传入的绝对 `time`（楼层预览为 `0`），并将精灵变换与调用者的 render states（包括世界偏移）组合。shader 加载失败时报告错误，并以洋红色绘制图像。仅供 C++ 使用的 `GameMapBase::isSpriteVisibleOnMap(position, bounds, transform)` 与实时 Actor 共用几何可见性判断，不提供 Lua 绑定。

## WorldStreamingState

`WorldRegionState` 暴露 `Unloaded`、`Reading`、`Prepared`、`Active` 和 `Dormant`。`WorldRegionDemand` 暴露 `None`、`Prepared` 和 `Active`。`WorldStreamingState` 使用从 1 开始的下标，持有 demand 队列，并负责 Camera 排序、last-used 与缓存核算、淘汰和统计。Camera 排序把 Active 区域排在前面，其次按区域中心的平方距离排序，距离相同时按 region index 决定先后。它的方法均为 `metadata = false`。Blueprint 使用带上下文的世界地图节点。

Lua 调用 `updateCameraCenter` 和 `updateDemand`，消费 `takeReadBatch` 和 `takePublishItem`，上报读取与发布的完成或取消，标记激活、停用和淘汰，并读取 `getEvictionList` 和 `getStats`。文件、builder 和数据仍由 Lua 持有。

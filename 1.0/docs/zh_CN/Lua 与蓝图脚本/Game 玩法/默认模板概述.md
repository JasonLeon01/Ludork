# 默认模板概述

Game 项目提供可运行的默认玩法，也是项目模板的来源。你可以在此基础上修改游戏规则、界面和资源。

## 入口与模块

Entry 保留静态 `APP_NAME`，用于应用身份和产物文件名。发行版本与 dev 设置属于 `Main.proj` 和打包窗口，移动端及 macOS 显示名称来自 System 标题。统一规则见[打包](<../../编辑器用户指南/运行、调试与打包.md#打包>)。

`Scripts/Entry.lua` 初始化游戏并进入原生循环，模块加载顺序见 [Lua 运行时与模块](<../Lua 运行时与模块.md#入口与模块顺序>)。

启动时会显式调用下列函数。仅 require 模块不会初始化服务：

| 调用 | 职责 |
|---|---|
| `Source.Locale.Core.Init()` | 在读取配置与选择语言之前加载语言字典。 |
| `Source.Configs.Main.LoadOrCreate()` | 读取 `Main.ini`；文件缺失时用默认设置创建。 |
| `Source.Data.InitializeRuntime()` | 向 `Global.Data.InitializeRuntime(options)` 传入项目回调和预览基类，由其在首个场景之前创建共享数据服务并注册数据与蓝图提供程序。 |
| `Source.System.InstallRuntimeProviders()` | 在首个场景之前注册配置提供程序。 |
| `Source.System.Init()` | 应用游戏与音频配置，并在进入原生主循环前通过 `GlobalCore.Display` 准备显示资源。 |

入口还会在构造 `SceneInit` 之前初始化 latent 图与原生 System。提供程序每个会话只注册一次。热重载不会重新执行启动流程，详见 [Lua 运行时与模块](<../Lua 运行时与模块.md#lua-热更新>)。配置与存档位置见 [运行时数据、配置与存档](<运行时数据、配置与存档.md>)。

Android 与 iOS 在同一进程内从后台返回时，继续当前场景与 Lua 状态，不重新执行 Entry，也不补算后台时间；详见 [SceneBase 生命周期](<../全局与 Core 模块/Core Modules/GlobalCore/场景与系统.md#scenebase>)。

## 玩法布局

- `Scripts/Global` 保存共享基础设施，包括 `Global.Data`、`Global.Audio` 下的地图音频模块和 `Global.Utils.MapPath`。[数据服务](<运行时数据、配置与存档.md#数据服务>)约定区分了这些共享服务与项目启动装配、玩法查询的职责。
- `Scripts/Source/MapActors` 保存可复用的地图 Actor 类。`Scripts/Source/Utils` 保存玩法辅助模块，包括 Enemy 与 GameInstance 的实现模块以及 `Source.Utils.AnimationCache`；场景、业务窗口和组件仍保留各自的目录。
- `Scripts/GlobalFunctions` 保存独立的 Lua 蓝图函数库；图数据中的路径以 `GlobalFunctions.` 开头，原生根模块保持独立。
- `Scripts/Internal` 保存实时调试与 UI 基础层，包括共用窗口基类。
- `Scripts/Internal/UI` 保存导出时由 `Data/UI` 生成的 View。生成的 UI 与语言文件不进入模板和版本管理，首次运行前需先导出项目。手写基础模块位于 `Internal.UIBase`，业务窗口位于 `Source.Windows`，详见 [声明式 UI 编写工作流](<../声明式 UI/编写工作流.md>)。
- `Scripts/Mixins` 保存可直接挂载的 Lua 行为。
- `Data/Blueprints` 保存游戏专用的 Actor 类。
- `Data/Materials` 保存源材质图；导出将运行时着色器和元数据写入 `Assets/Shaders/MaterialGenerated`，这些产物被版本管理忽略，不进入模板。
- `Data/General` 提供物品、敌人、装备、职业、玩家、状态与特殊效果。
- `Data/Maps` 与 `Data/Tilesets` 提供可玩世界。
- `Engine/` 包含原生运行时、模块与依赖。

原生源码的归属与依赖见 [构建与模块布局](<../../C++ 原生开发/构建与模块布局.md>)。

## 模板变体

`Cpp` 保留原生源码并逐项目构建，`Cpp-ffmpeg` 在此基础上增加视频支持。Standalone 变体内含已构建的运行时，供打包使用。iOS、HarmonyOS 与 Android 发行包只能从 C++ Source 变体构建；启用视频时，改用带 FFmpeg 的 C++ Source 变体。修改 Game 不会更新已有项目，因此需要重新生成模板，或把改动显式应用到该项目。

运行时 Lua、`Scripts/stub` 声明与 `_meta.lua` 的文件分层规则见 [Lua 运行时与模块](<../Lua 运行时与模块.md>)。

# 窗口、菜单、输入与控件

本页介绍默认游戏的窗口与输入行为。创建自己的 UI 时，从[声明式 UI 编写工作流](<../声明式 UI/编写工作流.md>)开始。

## 窗口与菜单

窗口视图遵循 [声明式 UI 运行时契约](<../声明式 UI/运行时契约.md>)。菜单把稳定的命令标识符与显示文本分开保存。较长的说明使用现有的换行与格式化辅助函数。

标题的 Save/Load、Config 和地图可选窗口各自持有独立的 [`LazyWindow` 句柄](<../声明式 UI/运行时契约.md#首次使用时创建可选窗口>)。进入地图时直接创建 HUD 与 Region Title。Menu、Item、Equip、商店、商店记录、Save/Load、Config、Enemy Book、Encyclopedia、Floor Teleporter 和 Player Name 在首次显示时创建；Message 在首次消息或选项显示时创建。打开 Menu 不会创建尚未使用的子窗口。

游戏内菜单列出物品、装备、存档、设置和返回标题。`WindowMenu.new(player, windows, onExit)` 接收场景提供的退出动作，并在菜单关闭动画结束后调用。目标场景由场景所有者决定，菜单及其独立子窗口的层级也由场景统一设置。选择设置会在菜单之上打开共用的 Config 窗口，并停用命令列表；关闭 Config 窗口后焦点回到菜单。

每个默认界面使用一个顶层资产，多窗格嵌套在同一根节点下。并列的输入 host 复用其中的列表与滚动框。

顶层窗口的转场是线性的，默认时长 0.2 秒。内部窗格与页签立即切换。播放期间禁用输入，关闭结果在 `FadeOut` 隐藏根之后执行。初始化与销毁则立即隐藏。

| UI | Timeline 行为 |
|---|---|
| 默认窗口与 Config | `FadeIn`：中心 Scale `0.5` 到 `1` 并改变 colour；`FadeOut`：仅 colour。 |
| Title command | `FadeIn`：本地 Y `80` 到 `0` 并改变 colour。打开 Config 或 Save/Load 不会隐藏它。 |
| Map Menu | `FadeIn`/`FadeOut`：本地 X `-192` 到 `0` 再返回，并改变 colour。 |
| Item 与 Equip | 仅 Menu 动画。Save/Load 同时提供默认与 Menu 两套；Config 始终使用默认那一套。 |
| Message | 仅 `Panel` 的 colour。 |
| Game Over | 仅改变 colour 的 `FadeIn`（0.5 秒）与 `FadeOut`（1 秒）。场景切换等待 `FadeOut`，它保持透明末帧直到场景销毁。 |
| Region Title | `Display` 保持 colour 一秒，再用一秒淡出。 |

相关的 `FadeOut` 转场可以并行播放。使用道具后，完成回调在道具窗口隐藏后执行；若菜单仍打开，则随后关闭菜单，并在没有阻挡窗口时恢复行动。

默认资产包含 `#TAB` 和 `#ITEM` 预览子项。Enemy Book 与 Encyclopedia 使用 [`CharacterView`](<../全局与 Core 模块/Core Modules/Engine/布局与图像控件.md#characterview>) 和资产中定义的单元格尺寸，Controller 在这些区域内测量本地化名称与特殊能力标签。

标题的 `WindowCommand` 绑定 `Parts/Title/CommandWindow` 中已有的四个命令行，由父级 `Title` 资产确定位置。

可选择列表取得焦点时，当前选中项会滚动到可见位置，鼠标指针保持原位。打开窗口、切换窗格或返回上级列表时也遵循该规则。

移动端点击另一行只移动选择光标，不执行确认；点击当前已选中的行才确认，拖动只滚动列表。标题命令窗口、共用存读档列表和其他可选择窗口都遵循该规则。

在标题界面，Config 或 Save/Load 窗口打开后，底层的命令窗口不会收到同一触摸手势的任何部分。

共用资产 `Parts/Shared/WindowChrome` 在 `Content` 之外的左上边框提供 16 × 16 返回按钮。`WindowBase` 绑定该按钮，可取消的窗口通过 `windowOptions.returnButton = true` 启用它，并用 `Controller:onReturn()` 实现与其他 Cancel 输入相同的、根据当前窗口状态执行的返回操作。这个共用的返回步骤只播放一次系统 CancelSE，第二个 Cancel 来源不得再播一次。多窗格组只在当前活动的可交互窗格上显示该按钮。隐藏、未激活或被抑制的窗口不会显示它。

`WindowChrome` 还在 `Content` 之外的底部边框布置 `Engine.GamepadHintBar`，并定义其文本样式。只有连接手柄且窗口设置了提示时才显示。窗口用 `setGamepadHints` 设置至多三条 `Engine.GamepadHint`，用 `setGamepadHintEnabled` 切换单条，用 `getGamepadHintCount` 与 `isGamepadConnected` 查询状态，并通过 `setOnGamepadHintTriggered` 处理触发完成。独立的 `Parts/Shared/WindowPauseMark` 资产确定暂停标记的尺寸和位置，`WindowBase` 负责皮肤动画与显隐。渲染与长按一秒行为见 [GamepadHintBar](<../全局与 Core 模块/Core Modules/Engine/交互与声明式 UI 控件.md#gamepadhintbar>)。

静态命令行保存 `localeKey`，动态行保存字面量 `text`。同一行绝不能同时定义两者。命令行在刷新时解析 `localeKey`，因此语言变化可以更新已有的控件，而不必替换它们的回调或游标状态。运行时语言变化时，标题命令、游戏内菜单、存读档页签、商店页签与详情，以及正在显示的地图区域标题都会立即更新。

可复用的选择窗口每次重新打开时，选择器都从 0 开始并滚动到顶部；选择器为空时使用 `nil`。这条规则适用于游戏内菜单、物品与装备窗口、商店、Config 和 Enemy Book。同一会话内的焦点变化和直接刷新已有控件会保留当前选择。

公开的 `WindowShop:setMode(mode)` 使用 `Enums.ShopMode` 中的 `BUY = "buy"` 与 `SELL = "sell"`。打开 Item、Equip 和 Save/Load 窗口时，通过 `Enums.WindowTransitionProfile.DEFAULT`（`"Default"`）或 `.MENU`（`"Menu"`）选择过渡样式。

商店的两列物品列表保持焦点，Q/E、LB/RB、鼠标或触摸用于切换买/卖。切换页签会重置游标与滚动，交易刷新则保留仍然有效的选择。购买格和出售格都显示图标及当前持有数量；详情显示本地化名称、说明、本地化的“价格”标签和右对齐价格。出售获得 `floor(price / 2)` GOLD，卖出价格为 0 的商品不会列出。仅能购买的商店隐藏页签，并把其余窗格居中。Cancel 关闭商店。关闭后恢复先前的移动状态，并屏蔽一帧地图输入。

内容溢出的列表使用 [`Engine.ScrollBox`](<../全局与 Core 模块/Core Modules/Engine/布局与图像控件.md#scrollbox>)，负责裁剪、滚动和保持选中项可见。

消息窗口使用全屏 Canvas 和透明的 `FunctionalImage`，为普通消息的确认消耗一次点击或触摸。选项模式会禁用该层，因此点击空白处无法选中选项。最多四个选项可以直接放进面板，不需要 ScrollBox。`SceneMap` 只在对话进行期间阻断地图输入。

`SceneMap` 为长生命周期的地图窗口维护一个 `LocaleChanged` 订阅。活动对话保留原始说话者、消息或选项、显式的 `localeArgs`，以及节点局部变量和实例变量的快照。刷新时，它重新执行模板本地化、本地化 `localeArgs` 中的字符串、应用这些参数，再应用两份变量快照，最后更新已有的 `WindowMessage` 控件。物品与装备详情、商店页签与详情、属性商店、Enemy Book、`WindowEnemyEncyclopedia` 以及 Teleporter（`WindowFloorTeleporter`）同样在直接刷新已有控件本地化文本，并保留当前选择、模式、焦点和预览状态。隐藏窗口在下次打开时按当前语言解析；Config、存档槽与玩家 HUD 的 Controller 各自保留订阅。玩家 HUD 还订阅 `Enums.EventKey` 中的 `AbilitySystemChanged` 与 `PlayerChanged`，忽略 `owner` 为其他 battler 的数据，并在当前玩家的相关状态变化时只刷新受影响的控件。 变更数据使用 `Enums.AbilitySystemChangeKind`（`Attribute`、`State`）或 `Enums.PlayerChangeKind`（`Inventory`、`Name`、`Map`），其共享记录声明为 `Source.Configs.EventChangePayload`。

Teleporter 只列出当前区域内有传送点记录的地图。没有符合条件的地图时，即使持有该物品也无法打开，并播放 Buzzer 音效；不会禁用移动、抢占焦点或生成预览。只有一张地图时，直接打开该地图的传送点列表并选中第一项，取消会关闭窗口；即使只有一个传送点，仍需确认后才会传送。有多张地图时，先打开楼层列表，选中当前地图对应的楼层项并滚动到可见位置；当前地图不在列表中时回退到第一项。此时左侧槽位在楼层列表与传送点列表之间切换，取消传送点选择会恢复楼层列表。传送点选择从第一项开始。打开时先确定最终选择与列表模式，再只生成一次预览。过长的地图名和传送点名称通过 [ListView 子项滚动](<../全局与 Core 模块/Core Modules/Engine/布局与图像控件.md#listview>) 在单元格内显示，选择框保持固定。传送点列表滚动时，右侧预览不移动。组合式清单始终是一个楼层身份，子地图按大地图偏移拼合。

为每个楼梯蓝图设置 `stairDirection`，以便传送时寻找反方向楼梯作为落点。选择与记录规则见 [Teleporter](<../源码类/Teleporter.md>)。

楼梯传送或 `Teleporter:goToMap` 会发现传送点，无需先获得 Teleporter 物品。打开窗口或靠近楼梯不会记录访问。地图未配置区域时，没有可用楼层，因此无法打开窗口。端点记录规则见 [Teleporter](<../源码类/Teleporter.md>)，记录结构与去重见[运行时数据、配置与存档](<运行时数据、配置与存档.md#存档>)。

传送点名称用 `LOC` 解析记录的标签。空的或自动生成的标签使用本地化的 `POINT` 编号格式；缺少译文时保留原始标签。

键盘、鼠标和触摸选择都会在确认之前更新目的地与预览。预览保持固定缩放并限制在地图边界内，小于视图的轴居中显示。组合式预览使用完整的清单边界。

楼层预览使用[静态 Actor 显示记录](<运行时数据、配置与存档.md#actor-静态显示数据>)，保留配置的视觉与材质参数，材质时间固定为 `0`。预览不执行玩法逻辑，因此不会显示仅由玩法脚本生成的外观。

已销毁标签及其子树在创建显示记录或加载纹理之前过滤；新增、移动记录与地形破坏按记录恢复。声明式 `childActorComp` 子对象保留偏移、标签和祖先显隐，不执行组件回调。普通地图沿用区域隐藏规则，组合式子地图保留世界偏移。

静态记录使用当前游戏变量判断 [ConditionalActor](<../源码类/ConditionalActor.md>) 可见性，其他楼层与组合式子地图也遵循此规则，预览对象不注册变量订阅。缓存预览依赖的变量变化时，纹理缓存失效，下次绘制会重新判断缓存记录。重新打开窗口时清空预览模型、纹理与类显示模板。

属性商店通过 `getOffers()` 提供展示快照，并通过 `purchaseAttribute(key)` 校验购买。价格引用为标量时由所有商品共用，为数组时逐项设置价格。购买后对应价格增加。

对话、教程和窗口 API 返回 `Engine.AsyncOperation`。完成结果见 [Scene 操作](<../节点函数/Scene.md#lua-等待与结果>)，顺序等待用法见 [Lua 异步任务](<../../快速入门/Ludork Lua 进阶.md>)。

### 已访问商店

松开 **V** 可打开 `WindowShopRecords`，前提是商店记录功能开启、当前玩家持有楼层传送器、至少有一条商店记录，并且场景当前允许打开窗口。列表包含所有区域的记录。单列列表的子项直接使用文本控件，显示本地化后的地图 `mapName`（大地图使用 `worldName`）、一个空格及本地化后的记录 tag。过长文本在行内滚动。重新打开时选中第一项并滚动到顶部；切换语言时刷新文本，保留选中项和滚动位置。

普通物品商店与属性商店都会在成功打开时记录访问。[商店节点](<../节点函数/Scene.md#商店-actor>)负责确定商店 Actor；没有地图身份的开店调用仍可使用，但不产生记录。记录结构、脚本方法及记录开关见[运行时数据、配置与存档](<运行时数据、配置与存档.md#存档>)。

确认一项后关闭列表，完整执行该商店的 `onCollision` 事件，并将当前 player 作为 `other` 传入。玩家留在当前地图。商店 Actor 根据原地图放置记录独立构造，包含该实例的 `BPClassVarChanged`；大地图中的放置实例保留大地图坐标。目标地图不会作为场景加载，不修改共享类默认值，也不执行 `onCreate`。商店图因此应使用配置字段与当前游戏变量，不依赖目标地图归属或仅由 `onCreate` 初始化的状态。入口中的对话、条件以及商店关闭后的逻辑都会正常执行。

关闭商店后直接返回地图操作，不重新打开列表。取消列表会恢复先前的移动状态。地图或放置 tag 已不存在时播放 Buzzer 音效，保留列表和已有记录；过期记录可用 `removeShop` 删除。远程打开不会把商店追加到玩家当前所在地图名下。

### 地图新手引导

`Map_01` 通过不可见的 `BP_MapIntroduction` Actor，在入场转场结束后依次介绍 HUD 菜单头像和各类代表 Actor，全部完成后记录并销毁自身。

`Source.Configs.Tutorial` 将键映射为 `{ rect: sf.IntRect, text: string }`。矩形使用固定逻辑屏幕坐标，不跟随 Actor。`BP_MapIntroduction` 蓝图在 `ForEach` 输入中按顺序填写引导键，并逐项调用 `ShowTutorial`。场景组件按传入的键读取配置并管理展示，不根据地图名或 Actor 标签选择引导。调整布局时需同步更新矩形。

开口在 0.25 秒内收缩至矩形，期间阻断交互。矩形外的整个游戏画面（包括 HUD 和空白边缘）覆盖 40% 不透明度的灰幕，边框闪烁一次，收缩完成后才接受[确认输入](<../全局与 Core 模块/Core Modules/Engine/输入与服务.md#inputcapture>)。

说明默认使用 12 号描边字体和本地化短句，切换语言时刷新。左对齐文字从矩形底边中点开始，右侧越界时左移，下方放不下时改放在顶边中点上方；超出屏幕宽度时先换行。调用方式见[引导节点](<../节点函数/Scene.md#新手引导>)。

### 玩家改名窗口

`Map_01` 中出生点旁的 NPC 会打开 `WindowPlayerName`，并在窗口关闭前暂停地图输入。用 Confirm 操作激活输入框才能编辑。Tab/Shift+Tab 与方向操作在输入框和 Confirm 之间移动。

Confirm 在所有输入设备下均保持可见。鼠标和触摸可以激活按钮；键盘 Enter/Space 在 Confirm 取得焦点时应用名字，否则进入文本编辑。资产把 Confirm 绑定为长按 X 一秒（`gamepadButton = "X"`、`gamepadLongPress = true`），并且不填充窗口底部提示栏。A 只进入文本编辑，即使焦点在 Confirm 上也是如此；活动窗口内任意焦点均可长按 X 应用名字。空纹理与提示外观见 [Button](<../全局与 Core 模块/Core Modules/Engine/运行时值与功能控件.md#button>)。返回按钮或 Cancel 会丢弃草稿；编辑期间，Cancel（B 或 Escape）先结束编辑，再按一次才关闭窗口。完成移动端输入弹窗只会更新草稿。名字无效时 Confirm 不可用，校验规则见 [Source.MapActors.Player](<../源码类/Player.md>)。HUD 在等级上方显示已确认的名字，过长时缩短以适配。

### 按区域隐藏的地图预览

启用 `GameMap.HideDisconnectedRegions` 后，怪物手册在分组与去重之前排除当前区域规则隐藏的 Actor。楼层传送器预览使用同一规则：当前楼层使用玩家位置，其他楼层使用选中的落点格。切换到其他落点区域或修改地形后，预览缓存失效。区域隐藏只影响显示，传送点记录与目标位置保持不变。详见 [Global.GameMap](<../全局与 Core 模块/Global APIs/GameMap.md#非连通区域隐藏>)。

## 输入

`Source.Configs.HotKey` 把原生按键映射到 `Scene`、`Filter` 以及可选的 `FunctionWhenPressed` / `FunctionWhenReleased` 回调。每个回调都会收到场景实例。

运行时输入来自 C++ 输入服务。应使用文档中的键盘、鼠标、控制器与注入输入 API，而不要读取编辑器状态。Windows 嵌入模式通过运行时协议转发兼容输入；独立游戏直接使用原生窗口。

在 Android 和 HarmonyOS 上，宿主把系统返回键或返回手势转换成一次 Cancel/Escape 脉冲，而不是关闭应用或将其切到后台。这条转换路径与 HarmonyOS 的外接键盘转发保持独立：后者把 SFML 映射的普通按键作为 scancode 边沿发送，在能够解析时补充 logical 键边沿，并保留修饰键状态。双指触摸仍是独立的鼠标右键取消手势。系统返回与双指触摸都会触达焦点窗口的 `onReturn()`，但只有后者会产生鼠标右键输入。

物理 Enter 与 Space 使用 Confirm 操作，Escape 使用 Cancel。键盘的按下与释放都是边沿事件，参见 [Engine：输入与服务](<../全局与 Core 模块/Core Modules/Engine/输入与服务.md>)。

手柄按钮使用 `Engine.JoystickButton.getA()` 至 `getShare()` 的逻辑值。Confirm 为 A/Cross，Cancel 为 B/Circle。按手柄解析、映射与提示见 [Engine：输入与服务](<../全局与 Core 模块/Core Modules/Engine/输入与服务.md>)。

默认的移动与菜单方向只使用左摇杆的 `X`/`Y` 和十字键的 `PovX`/`PovY`。`|X| >= |Y|` 时取水平方向，否则取垂直方向；恰好 45 度的输入算作水平。触发式导航与按住移动都使用这条扇区规则，右摇杆和扳机轴无法夺取方向。

`WindowSelectable` 负责默认的 Cancel 键和鼠标右键关闭行为。派生窗口把未处理的输入交回给它，因此每个边沿只产生一次 Cancel 音效和一次关闭转场。

## 焦点与导航

键盘与控制器导航需要明确的焦点顺序。已禁用或已隐藏的控件不得继续作为活动焦点目标。

## 设置控件

Config 打开时位于 Graphics 页并聚焦第一行。Q/E、LB/RB、鼠标悬停和触摸点击会切换页签并播放 CursorSE。本次打开会话期间，各页签保留游标与滚动位置。重新打开会重置所有页签，语言刷新则保留它们。

切换页签会静默收起已展开的 DropBox。Cancel 和返回按钮也会先收起它，下一次输入才关闭 Config。[游戏设置参考](<游戏设置参考.md>) 定义各项设置。

在移动端，点击 Slider 会在释放时设置数值。超过拖动阈值后，水平移动归 Slider，垂直或两侧均等的移动归 Config 列表。手势归属在释放前保持不变；列表仅在内容超出可见区域时滚动。

展开的 Config DropBox 会覆盖设置行并独占输入，直到它收起或 Config 关闭；两者都会恢复父列表的输入。高度受限的弹出层在内部滚动，移动端触摸采用先预览后确认。参见 [Engine：交互与声明式 UI 控件](<../全局与 Core 模块/Core Modules/Engine/交互与声明式 UI 控件.md>)。

Save/Load 使用同一份槽位列表。切换 Load/Save 页签会保留游标、滚动位置与详情。重新打开时默认选中 Load 和最新的已有存档，没有存档时选中 0 号槽；地图快捷键 S 则打开 Save 页签。Cancel 关闭窗口。标题界面的仅加载模式不显示页签，并把其余窗格居中。

精确的 UI 与输入 API 见 API 参考，从 [GlobalFunctions.Container](<../节点函数/Container.md>) 开始。游戏内的本地化标签遵循 [游戏本地化工作流](<../../插件开发与安装/Official 插件/游戏本地化工作流.md>)。

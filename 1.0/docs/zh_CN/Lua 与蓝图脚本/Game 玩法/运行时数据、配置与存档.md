# 运行时数据、配置与存档

## 配置

可选的[远端账号字典](<../../简易服务器/原生客户端 API.md>)是独立服务，不会自动上传、下载或替代本页所述本地存档；哪些字段需要读写由游戏业务决定。

`Data/Configs` 存放游戏配置 JSON，可变的用户设置使用[当前平台的游戏配置](<../../编辑器用户指南/项目设置与资产布局.md#游戏配置>)。应使用配置 API 与编辑器字段，让未知的配置节和键在一次读写往返后仍然保留。

资源型 Config `file` 字段保存完整的 `/Game/Assets/...` 路径，`base` 与 `ext` 只约束选择器。Data 引用单独处理：`System.json` 的 `startPlayerBlueprint` 以 `root = "Data"` 相对 `Data/Blueprints` 保存，并转换为 `Data.Blueprints.*`；`startRegion` 指定初始区域。两者都只影响新游戏，存档保留自己的玩家类与区域。

格子尺寸由引擎编译时确定，默认为 `32`。使用 `Engine.GetCellSize()` 读取，`System.json` 不配置它。

Game 项目的 Lua 配置模块位于 `Scripts/Source/Configs`，通过 `Source.Configs.*` 加载。

`Source.Locale.Core.DEFAULT_LANGUAGE` 统一定义初始语言和回退语言（`en_GB`），`Source.Configs.Main` 使用同一值。`Source.Configs.MapConstants.WORLD_MANIFEST_FILE` 定义组合世界清单文件名（`_world.json`）。数据读取和存档统一使用 `Engine.ResourceFileConstants` 的后缀。

初始数据键使用相对于所属类别目录的路径，以 `/` 分隔，并仅去除最后一个扩展名。目录名和文件名中的点会保留，例如 `folder.v1/item.v2.json` 对应 `folder.v1/item.v2`。动画键去除完整的 `.anim.json` 缓存后缀。

`Engine.getUserDataPath(appNameOverride?)`、`Engine.getMainConfigPath(appNameOverride?)` 和 `Engine.getSavePath(appNameOverride?)` 分别解析应用的用户数据目录、配置文件和 `Save/` 目录。Entry 在加载配置或存档前调用 `Engine.setAppName(APP_NAME)`。可选参数只为这次查询指定另一个应用名称，不改变当前名称。所有启动方式遵循相同的[目录规则](<../../编辑器用户指南/项目设置与资产布局.md#游戏配置>)，`LUDORK_EDITOR` 不会改写这些路径。

`Source.Configs.Main.LoadOrCreate()` 返回用户配置路径及对应的 `ConfigParser`。文件存在时读取，缺失时用默认设置创建当前平台的文件。无法读取或格式损坏的 plist 会报错，不会被默认设置覆盖。启动脚本独立于这些偏好选择，见[入口与模块顺序](<../Lua 运行时与模块.md#入口与模块顺序>)。

Android 发行包会在原生运行时启动之前，把不可变的运行时资产镜像到 `filesDir/ludork/runtime/<runtime-hash>`。可变配置与存档使用 `filesDir/ludork/user-data/<APP_NAME>`，绝不会写回该带版本的运行时目录，也不需要外部存储权限。

### 共享玩法配置

`Data/Configs/Gameplay.json` 为以下共享脚本设置保存项目级覆盖值，通过[数据库 → 系统配置 → Gameplay](<../../编辑器用户指南/项目设置与资产布局.md#系统配置>)编辑。

| 键 | 类型 | 脚本默认值 | 作用 |
|---|---|---|---|
| `enemyDamageHintLevel` | `Enums.DamageHintLevel` | `BATTLE`（`1`） | 设置 `EnemyDamageText.EnemyDamageHintLevel`：`NONE`（`0`）隐藏预计伤害提示，`BATTLE` 显示敌人伤害数值，`MAP`（`2`）还显示移动危险格的合计伤害。提示仍要求持有指定 Item；实际受伤时的伤害粒子不受影响。 |
| `enemyDefeatShatterEffectEnabled` | boolean | `true` | 设置 `Enemy.DefeatShatterEffectEnabled`，控制[敌人击败粉碎特效](<资源、音频、视频与特效.md#shader雾与转场>)。 |
| `hideDisconnectedRegions` | boolean | `false` | 设置 `GameMap.HideDisconnectedRegions`，为新构造的普通地图启用[非连通区域 Tile 遮罩](<../全局与 Core 模块/Global APIs/GameMap.md#非连通区域隐藏>)。 |
| `enableShopRecord` | boolean | `true` | 设置 `GameInstance.EnableShopRecord`。关闭后停止新增商店记录，并禁用[已访问商店快捷入口](<窗口、菜单、输入与控件.md#已访问商店>)，已有记录仍然保留。 |
| `maxSaveSlots` | 正整数 | `100` | 设置 `WindowSaveSlot.MAX_SAVE_SLOTS`，统一存档列表、快捷存档、快捷读档和最新存档查找的槽位范围。调小后会隐藏较大编号的槽位，不会删除其文件。 |
| `tutorialShrinkDuration` | 有限正数，单位为秒 | `0.25` | 设置 `WindowTutorial.SHRINK_DURATION`，决定教学遮罩收缩到目标区域所需的时间。 |

字段保留原有的字符串 `type`，例如 `"int"`、`"float"` 或 `"bool"`；`nullable: true` 允许使用脚本默认值，`enum: "Enums.DamageHintLevel"` 指定伤害提示的枚举选项。每个字段将覆盖值保存在 `value` 中，不另外保存 `useDefault` 布尔值。`null` 表示 **Use default（使用默认值）**，保留脚本当前的默认值，而不是给脚本字段赋 nil。显式的 `false` 和 `0` 仍是具体值，因此伤害提示枚举中的 `0` 选择 `NONE`，但两个要求正值的设置不接受 `0`。新建 Gameplay 数据的所有覆盖值均为 `null`。移动速度、`GameMap.MapViewRect` 等 Actor 或地图实例的默认属性，仍在原有类或蓝图属性中配置。

每个可空字段都需要通过 `scriptDefault: { module, field }` 指定编辑器读取默认值的来源。`module` 指向 `Scripts` 下的 Lua 文件，`field` 指定其中的 `table.field` 赋值，例如 `Controller.MAX_SAVE_SLOTS`。这里保存的是源码引用，不是默认值的副本。源码必须有唯一的无条件顶层赋值，表达式支持标量字面量、导入的枚举成员或简单标量算术。编辑器读取该表达式，不执行模块及其函数；来源缺失或表达式不受支持时，保持勾选 Use default 并报告错误。

`Source.System.Init()` 在应用其他系统配置后调用 `Source.Configs.Gameplay.Apply()`。`Apply()` 读取并校验 Gameplay 数据，在玩法开始前应用共享覆盖值。类型、枚举值或数值范围无效时启动失败，不会静默改用默认值。编辑后需要保存并重新启动游戏；Lua 热重载不会重新读取这份 JSON，也不会重新执行启动流程。

脚本可以在运行时直接修改 `GameInstance.EnableShopRecord`。它与 Gameplay Config 使用同一个共享类变量，修改开关不会清空商店记录。

## 数据服务

`Global.Data` 负责共享数据加载、资源查询、蓝图类与图、Actor 构造和静态预览，使用这些功能时直接 require 该模块。`Source.Data` 负责项目启动装配，以及默认游戏的通用数据查询（例如 `GetGeneralPlayerData`、`GetGeneralItemData`）和 `CreateGeneralAttributeSet(typeName, memberID)`。

默认的 `Source.Data.InitializeRuntime()` 调用 `Global.Data.InitializeRuntime(options)`，在首个场景之前创建共享服务并注册数据与蓝图提供程序。每个 Lua 会话必须初始化一次，重复调用会报错；仅 require 任一模块不会执行初始化。自定义项目在自己的启动代码中传入 `Global.Data.RuntimeOptions` 的四个必需字段：

| 必需选项 | 类型与用途 |
|---|---|
| `configResolver` | `(configName: string, settingName: string) -> string`；为值为空字符串的覆盖解析配置引用。 |
| `nodeModuleCandidates` | `(prefix: string) -> string[]`；按搜索顺序提供额外的节点模块路径。解析时先尝试未加前缀的模块路径。 |
| `conditionalActorBase` | `Class.ClassType<Engine.Actor>`；指定条件 Actor 基类，预览从其派生类读取 `conditionVariable`、`conditionOperator` 和 `conditionValue`。 |
| `childActorComponentBase` | `Class.ClassType<Engine.Component>`；指定子 Actor 组件基类，预览从其派生类型的 `childActorComp` 读取 `className` 和 `relativePosition`。 |

两个基类选项必须传入已完成类构造的类对象，不能传模块名字符串或实例；它们必须分别通过针对 `Engine.Actor`、`Engine.Component` 的 `Class.isSubclass` 检查。默认项目传入 `Source.System.GetConfigValue`、依次搜索 `Source.` 和 `Global.` 的节点候选函数、`Source.MapActors.ConditionalActor` 和 `Source.Components.ChildActorComponent`。这些依赖由项目传给 Global，Global 不导入 Source。配置提供程序仍由启动时独立调用的 `Source.System.InstallRuntimeProviders()` 注册。

## 运行时状态

不可变的定义放在蓝图、Config 或通用数据文件中，可变的游玩期状态放在游戏实例、Actor 或组件上。不要把临时状态写回源 JSON。

`Global.Data.GetClassData(path)` 公开共享的会话定义，参见 [执行流、事件与变量](<../蓝图脚本/执行流、事件与变量.md#类定义与会话生命周期>)。

用 `Source.Configs.GeneralDataTypes.Create` 构造通用数据属性集。类型键通过 `Enums.GeneralDataKey` 加载，成员键通过 `Enums.GeneralData.<TypeName>` 加载，例如 `Enums.GeneralData.Item`。编辑器从实时项目数据解析这些枚举，包括尚未保存的编辑。保存时生成对应的运行时源码，以及 `Enums.Animation` 与 `Enums.Particle`；运行时调用者读取已保存的模块。[通用数据与文本配置](<../../编辑器用户指南/通用数据与文本配置.md>) 页面说明值转换与默认值。

### Actor 静态显示数据

`Global.Data.GetActorPreviewData(classPath, classVarChanges?)` 返回 `Global.Data.ActorPreviewData`，空类路径返回 `nil`，非法类路径报错。它解析蓝图与 Script Mixin 的继承默认值，再按既有类型转换应用已声明的显示与条件覆盖。未知覆盖名称会报错；无关玩法值与 `BlueprintOnly` 覆盖不会应用。解析后的类必须派生自 `Engine.Actor`。

记录包含纹理与材质资源路径、配置的首帧 `rect`、`translation`、角度制旋转、`scale`、`origin`、`visible`、`materialParameters`、条件字段，以及可选的递归 `child` 与 `childOffset`。声明式 `childActorComp` 提供子类和偏移，循环子对象引用会报错。每次调用返回独立记录，并复制参数字典以及可变的 `sf` 矩形与向量，调用者不能借此修改共享类默认值或缓存模板。

提取过程不构造玩法 Actor、不实例化事件图、不加载引用的纹理、不触发组件或生命周期回调，也不初始化战斗状态。`Global.Data.ClearActorPreviewCache()` 丢弃类显示模板，不修改共享类定义；清理楼层预览缓存时会自动调用。

### 玩家

`GameInstance` 用 `_playerKeys` 保存玩家顺序，用 `_players` 保存玩家对象，键是 `Player.ID` 中稳定的 Player 通用数据键。Player 键必须非空且唯一。`getPlayers()` 返回实时的键字典，`getPlayerKeys()` 返回实时的有序键数组；数组的第一个键标识 `getPlayer()` 使用的主 Player。`getPlayerByIndex()` 按同一顺序解析零基索引，`setPlayer(playerKey)` 把已存在的键移到首位，`setPlayerByClass(playerClass)` 先按 class path 解析再执行同样的重排。

存档用同级的 `playerKeys` 与 `players` 字段保留同样的结构。顺序由 `playerKeys` 决定，其中每个键必须在 `players` 中恰好有一项与之对应，且恢复后的 `Player.ID` 相同。`addPlayerByClass(playerClass, mapPath, position)` 把成员追加到队尾，并为该键写入必需的地图路径与格子。`removePlayerByClass` 同时删除该键的地图记录。

每个 Player 在 `attr` 下保存 `getNumericAttributeBases()` 返回的全部数值型 Attribute Set Base。派生的 Current 值不保存，非数值属性从 Player 通用数据重建。数值必须有限，并符合生成的 `int` 或 `float` 结构定义。旧存档缺少的字段保留恢复后的成员初始 Base。

存档保留库存与装备的数量、已装备 ID 和 State 层数。读取时先恢复全部 Base 值，再恢复 Item ability、装备 Effect 与 State Effect，不执行初始装备或成员图。Handle、派生 Current 值、临时 Effect、ability spec 与标签都不保存。需要持久化的新增内容必须有自己的稳定记录与重建步骤。

玩家存档要求 `attr` 同级存在字符串 `customName`。`""` 表示使用通用数据的本地化默认名。非空值必须已去除首尾空白，并符合 [Source.MapActors.Player](<../源码类/Player.md>) 中的规则。

### 游戏变量

运行时从生成的 `Scripts/Source/Configs/GameVariables.lua` 读取初始值。启动运行时之前，先在 [通用数据与文本配置](<../../编辑器用户指南/通用数据与文本配置.md#游戏变量管理器>) 中保存修改。list 与 dictionary 初始值是普通 Lua 表，而不是 Standard 容器；空表经过 JSON 序列化后不保证保留 array 或 object 形状。

`GameInstance:init` 会深拷贝生成的运行时映射，因此每个新游戏都获得彼此独立的可变初始值。Game 声明了 `MTExample = 0` 与 `ShopPrice = 20`。运行时系统仍可创建动态名称，但只有编辑器声明过的名称会出现在 `InstVar` 选择器中。

读取存档时，会用该存档保存的表替换新建实例上的变量表。因此生成的初始值只作用于新游戏：修改、增加或删除声明都不会迁移或合并已有存档槽。修改声明的类型同样只重置项目初始值，不会改变存档中已经保存的值。

变量快照包含被监听字段的当前逻辑值。`deepcopy` 不复制 monitor 代理与订阅，因此 ConditionalActor 的监听只存在于当前游戏实例中。恢复记录之后，`onCreate` 订阅恢复后的变量并重新计算可见性，不需要额外的存档字段。

### 地图 Actor 身份

地图 JSON 中的摆放 `tag` 会成为 Actor 的地图持久化标签。`GameMap:getActorByTag` 与 `GameInstance` 的持久化记录只通过 `Actor:getMapTag()` 识别 Actor，`Actor.tag` 保持独立。没有地图持久化标签的 Actor 不会被记录，这些记录中的地图路径通过 `Global.Utils.MapPath.Normalise` 统一规范化。

需要在重建地图后继续存在的运行时生成 Actor，用自己的地图摆放标签写入 added Actor 记录。该 Actor 之后被销毁时，对应的 destroyed 记录会屏蔽这条已保存的新增记录。Reborn 敌人沿用这组成对的既有记录，而不复用原摆放对象的标签。

大地图运行时标签在摆放中使用 `<child-file-stem>.runtime_default_<N>`，在空洞中使用 `<world-directory>.runtime_default_<N>`。所有标签在大地图存续期间都会保留，冲突会失败。编辑器标签在整个大地图范围内唯一，且在地图重命名时保持稳定。

地图 `BPClassVarChanged` 与持久化的 `classVarChanges` 只保存已声明类字段的值。编辑器和运行时通过 metadata、Script Mixin 与蓝图 `attrDefs` 解析类型，实例不能新增字段或改变字段类型。未知覆盖名称或不符合解析后结构定义的值会使加载失败。枚举覆盖保存底层标量，已声明的向量和记录在应用时按其类型转换。

### 组合式大地图持久化

即使从子地图进入，主控玩家的 `map` 条目也保存清单路径。Player、added、moved 与 destroyed 记录都使用该身份、大地图坐标和全局标签。added 或 moved 记录冲突会导致加载失败。

added Actor 在 `actorPositions[tag]` 存在时按该位置恢复，否则恢复在原始位置。destroyed 标签会被跳过。摆放 Actor 随子地图数据一起恢复，不产生远处子地图的 I/O；空洞中的 Actor 可以立即恢复。

`worldMovedActors` 管理位于定义子地图之外的 authored root，保存身份、所属对象、图层覆盖和大地图位置。它们只在该所属对象处重建。返回或销毁会移除 moved 记录。

销毁某个标签会移除它的 moved 记录，并在不加载缺失子地图的前提下屏蔽 authored、added、驻留和进行中的实例。被屏蔽的标签保持保留状态；非法记录与冲突都会失败。

地形记录使用子地图路径与局部坐标。它们在该子地图构建时应用，并只更新受影响的存活图层。空洞不能拥有地形改动。

任一 player 的地图是大地图清单时，存档必须包含 `worldMovedActors`。moved 快照保留重建身份、类变量覆盖、图层与位置，但不保留任意实例字段、Lua 私有状态或计时进度。这些内容需要单独持久化，或通过 `onWorldWake` 补算时间。

## 存档

[实时调试](<../../编辑器用户指南/运行、调试与打包.md#实时调试>) 不写入项目文档，也不改变存档结构、存档槽或持久化记录。该次运行中存档仍可能保留被实时修改影响的玩法状态。

Game 项目的存档结构保持 v1，实际序列化值仍为数值 `1`，只支持当前结构与版本。`SaveCodec` 会拒绝不兼容的存档，不做迁移。

存档结构版本独立于应用版本和打包 dev 选项。格式变更在开发期使用 `vN-dev`，发布前冻结为 `vN`；普通游戏发布不递增存档版本。当前格式仍使用数字 `1`，不提供迁移。

`telepoints` 把规范化后的地图路径映射为有序的 `{ position = {x, y}, tag = "raw tag" }` 记录。运行时位置使用 `sf.Vector2u`，标签保持未本地化的字符串。`GameInstance:recordTelepoint(mapPath, position, tag)` 为每个“地图 + 坐标”组合保留第一条记录，`getTelepoints(mapPath)` 返回这些记录。大地图记录使用清单身份与大地图坐标。

`triggeredTutorials` 按首次展示顺序保存不重复的引导键，运行时为原生 `list<string>`，存档中为 JSON 数组；写入时保留空数组形状。加载接受原生 JSON 读取器的长度字段 `n`，要求它与元素数量一致，并拒绝空洞及非法键。`hasTriggeredTutorial(key)` 查询记录，`recordTriggeredTutorial(key)` 只追加尚未记录的非空键。引导在收缩开始时记录，排队时不记录，并随正常存档保存。缺少该字段的旧 v1 存档按空列表读取，版本仍为 `1`。

`shops` 是由长度为 2 的数组组成的数组：`[[mapPath, mapTag], ...]`，由同一存档中的玩家共享。每项保存规范化后的地图路径，以及 `Actor:getMapTag()` 返回的未本地化地图放置 tag，不保存蓝图名或 `Actor.tag`。组合式大地图使用清单路径。记录按完整的“地图 + tag”组合去重，并保留首次访问顺序；空记录保存为 `[]`。缺少 `shops` 的旧 v1 存档按空集合读取，之后访问商店仍可正常追加，不改变存档版本。

`GameInstance:getShops()` 返回独立副本。`recordShop(mapPath, tag)` 仅在 `GameInstance.EnableShopRecord` 开启时追加新组合；`removeShop(mapPath, tag)` 删除指定组合，关闭记录功能后仍可使用。两个方法都返回集合是否发生变化。只有实际新增或删除记录时才发布 `Enums.EventKey.ShopRecordsChanged`，数据为 `{ instance = self }`；重复访问、删除不存在的记录以及关闭记录功能时的新增请求均不发布事件。通知数据声明为 `Source.Configs.ShopRecordsChangePayload`，订阅方可先比较 `instance` 是否为当前绑定的游戏实例，再进行刷新。删除后再次访问同一商店可以重新记录。商店成功打开即记录访问，无需购买；开店与再次访问的规则见[已访问商店](<窗口、菜单、输入与控件.md#已访问商店>)。

`map` 是以玩家键为键的对象。每个 `playerKeys` 条目必须对应一条非空、已规范化的地图路径，多余的键会导致加载失败。`GameInstance:getCurrentMapPath()` 返回主控玩家的已存地图或 `nil`。`applyMapInfo` 写入同一条目。`getVisitedMapPaths()` 返回排序后的传送点地图路径，`getTelepointsForMap(key)` 匹配时忽略扩展名。两个集合查询都返回副本。`restoreFromData(data)` 把校验通过的存档恢复到实例中。

`SAVE_AS_LDC` 为 `false`（默认）时使用普通 `.json` 存档，为 `true` 时使用经过压缩与混淆的二进制 `.ldc` 存档。**加密存档内容** 设置 C++ Source 包的原生默认值。包括 Standalone 在内的任何项目，都可以在 `Scripts/Entry.lua` 顶部、所有 `require` 之前用全局赋值 `SAVE_AS_LDC = true` 或 `false` 覆盖它。`Source.Save` 在首次加载时确定格式，之后再赋值不再生效。

`Source.Save` 使用 `Engine.saveData` 与 `Engine.loadData`；LDC 直接解码为运行时数据，不经过 JSON 文本。载荷为压缩 JSON 的旧 LDC 存档不再支持，改变 `SAVE_AS_LDC` 不会迁移它们。

`GetSavePath(slot)` 根据从 1 开始的槽位编号返回当前格式的存档路径。

存档预览异步读取，不会创建玩法对象。确认读档时，`Save.LoadGame(filePath)` 才会完整恢复游戏。

存读档窗口的 `open` 方法通过 `initialMode` 接收 `Enums.SaveLoadMode.LOAD`（`"load"`，默认）或 `SAVE`（`"save"`）；仅读档窗口始终保持读档模式。窗口关闭后，宿主的 `onClose(reason)` 回调接收 `Enums.SaveLoadCloseReason.CANCEL`（`"cancel"`）、`SAVED`（`"saved"`）或 `LOADED`（`"loaded"`）。

窗口显示加载中、空槽或读取失败状态。每次打开时选中修改时间最新的存档，没有存档时选中第一槽。入场动画结束后，键盘焦点交给所选槽位。

新存档截图保持宽高比，最大为 224 × 168 像素。已有的大尺寸截图仍可读取。

存档加密与项目 JSON 加密彼此独立，尽管 Pack Options 把两者都归入 **加密游戏数据**。

## 数据边界上的原生容器

把 Standard 的 `list`、`tuple` 与 `dict` 值保存为 JSON 或 LDC 之前，先转换为 Lua 表：

```lua
local Engine = require("Engine")
Engine.saveData("slot.ldc", payload:toTable())
```

两种格式解码后都得到普通 Lua 表。数组用 `n` 保留逻辑长度；根 null 与数组 null 槽位为 nil，对象 null 字段保留为 `cjson.null`。元组键字符串、`cjson.null` 空槽和记录数组的重建见 [Ludork Lua 进阶](<../../快速入门/Ludork Lua 进阶.md>)。绝不要持久化内部元组哈希值。

## 限制

切换存档格式不会重命名或迁移已有存档槽。应在发行前确定格式，或自行提供迁移。存档升级、原子写入、备份、云同步与 tuple-键记录格式仍由项目负责。

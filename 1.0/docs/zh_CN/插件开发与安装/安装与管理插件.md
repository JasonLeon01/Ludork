# 安装与管理插件

新建、引入、更新或卸载源码插件，并选择对所有项目生效或仅对当前项目生效。新建、引入、刷新状态和卸载耗时较长时会显示进度窗口，完成前不能在相关窗口中重复操作或关闭窗口。引入前仍须单独确认信任所选插件。

编辑器插件属于可信代码，以编辑器进程的权限运行，不受沙箱隔离。只引入来源可信的目录。

插件拥有自己的源码、窗口、标签、设置、保留数据与第三方声明。宿主负责注册、生命周期、命令上下文、受限的地图、蓝图与资源清理桥接，以及操作时序。

插件可通过[公开注册接口](<注册点与 Hook 参考.md>)添加命令、文本提示和操作 Hook。扩展游戏运行时则使用[原生 C++](<../C++ 原生开发/构建与模块布局.md>)。

## 新建插件

1. 打开 **插件 → 插件管理**，点击 **新建插件...**。
2. 填写显示名称和唯一插件 ID，通过单选按钮选择 **带界面** 或 **不带界面**，默认选择 **带界面**。
3. 选择 **全局插件** 或 **当前项目插件**。打开项目时默认当前项目；启动页只能选择全局。
4. 创建插件。编辑器生成并编译模板，校验入口类型后才安装和登记；失败不会留下创建到一半的插件或覆盖已有目录。
5. 源码文件夹会自动打开。编辑生成的文件后，重启 Ludork 使改动生效。

两种模板都不会自动注册命令或打开窗口。目录布局与入口类见[生成的模板](<Manifest 与最小插件.md#自动生成模板>)。

## 引入第三方插件

1. 关闭不应暴露给所选代码的工作，然后检查插件的源码、manifest 与来源。
2. 选择 **插件 → 引入插件** 或插件管理中的 **引入插件**。已打开项目时先选择 **全局插件** 或 **当前项目插件**，再选中完整源码目录，并接受信任确认。默认引入当前项目；启动页只能引入全局插件。
3. 阅读引入结果。manifest 或编译错误必须先解决，才能继续。
4. 重启 Ludork。引入的源码不会热加载。
5. 打开 **插件 → 插件管理**，确认插件在对应作用域下的状态为 **已加载**。项目插件需先打开对应项目。

![Import Plugin 源码目录选择](../../../images/plugins/import-plugin.png)

*选择包含 `plugin.json` 的目录，而不是单个源码文件或构建输出。*

引入的插件沿用原目录名。清单无效、编译失败、有效的“全局＋当前项目”集合内 ID 重复，或目标目录已存在时，都不会安装。`__ProjectPlugins` 用于存放项目插件，不能作为普通插件目录引入。

目录必须包含 `plugin.json` 和至少一个参与编译的 `.cs` 源文件。不可访问的路径、链接（包括断链）、重解析点（reparse point）、内嵌 `.data`、宿主共享 DLL、F# 或 VB 项目，以及零散的 Avalonia XAML 源码，都会在安装前被拒绝。C# 项目文件可以保留供 IDE 使用，但插件编译器不会执行它。`bin`、`obj`、`.git` 与 `.vs` 下的源码会被忽略。

## 全局与项目存储

Windows 与 macOS 上，新建和引入的插件通常保存到 `~/Ludork/Plugins`，注册记录保存在 `~/Ludork/plugins.json`。`~` 表示当前用户的主目录，Windows 上通常为 `C:\Users\<用户名>`。插件的保留数据始终存放在该用户目录中。

编辑器启动时会同时读取工作目录的 `plugins.json`、同级 `Plugins` 目录，以及用户目录中的插件。开发构建从其他目录启动且该目录没有注册表时，会使用构建标记指定的仓库路径。每个作用域内优先采用工作目录的注册记录：同一插件 ID 只加载工作目录中的版本，两边各自独有的 ID 也会加载。选中版本加载失败时会报告错误，不会改用另一份副本。注册表缺失时跳过该位置；注册表无效时报告诊断，另一位置仍可正常加载。源码目录必须已有注册记录，扫描不会自动注册所有文件夹。

插件管理显示实际选中的源码，取消注册或删除源码时会操作对应来源的注册表和目录。引入工作目录插件根目录下尚未注册的直接子目录时，会原地登记；其他引入操作和新建插件仍使用用户目录。取消工作目录中的注册后，如果用户目录仍有同 ID 插件，它会在重启后生效。

因此，仓库中的官方插件可以直接从检出目录加载。Windows 开发压缩包同样在根目录的 `Ludork.exe` 旁包含 `Plugins` 和 `plugins.json`。启动该程序会把工作目录设为解压后的包根目录，随包插件可直接加载，无需安装用户副本。Windows 正式包中的 `tools/OfficialPlugins` 用作安装输入；启动编辑器不会复制或替换官方插件。其他编辑器数据与手动迁移方式见[用户数据目录](<../编辑器用户指南/启动页、工作区与快捷键.md#用户数据目录>)。

项目插件在两个扫描根目录下都采用以下布局，同样优先使用工作目录中的版本；可写的 `.data` 始终位于用户目录下：

```text
Plugins/__ProjectPlugins/<项目标识>/
├── plugins.json
├── .data/<插件 ID>/
└── <插件目录>/
    ├── plugin.json
    └── Plugin.cs
```

`<项目标识>` 按项目的绝对路径区分项目，因此路径不同的同名项目相互独立。新建插件使用插件 ID 作为目录名，引入插件保留原目录名。

每个项目作用域有独立的注册文件与数据。插件管理分别显示 **全局插件** 与 **当前项目插件** 的列表、状态和诊断。项目插件只影响对应项目的菜单、地图右键菜单、文本提示和操作 Hook。移动或重命名项目目录后会形成新作用域，需要把插件重新引入新作用域，不会自动迁移。

## 发行版官方插件

Official Blueprint AI、Official Locale Tools、Official Random Map、[Official Mota Map Fill](<Official 插件/Mota Map Fill.md>) 与 [Official Resource Cleanup](<Official 插件/Resource Cleanup.md>) 作为全局插件发行。准备好的安装内容包含由 manifest 生成的 `plugins.json`，安装后会在下次启动编辑器时加载，不经过引入第三方插件时的信任对话框。官方编辑器发行包不包含项目插件。

两种 Windows 安装器默认都为发起安装的用户安装官方插件。可取消 EXE 向导中的 **Install Official Plugins**，或向 MSI 传入 `INSTALL_OFFICIAL_PLUGINS=0`，跳过此步骤并保留现有插件。请正常启动安装器，这样即使 UAC 授权由另一管理员提供凭据，插件也仍安装到你的用户目录；如果明确以另一账户身份启动安装器，则该账户就是安装用户。服务账户安装必须跳过用户插件。维修会保留用户插件；升级时若选择安装官方插件，仍会重新替换。Windows 卸载编辑器默认删除包括插件在内的用户数据，取消 **Delete user data（删除用户数据）** 可保留；删除范围、身份要求和静默选项见[用户数据目录](<../编辑器用户指南/启动页、工作区与快捷键.md#用户数据目录>)。

安装官方插件前，请关闭 Ludork 并备份需要保留的内容。安装会整体替换 `~/Ludork/Plugins` 和 `~/Ludork/plugins.json`，不会合并现有内容。被删除的内容包括全部第三方源码、注册记录和 `Plugins/.data`，以及 `Plugins/__ProjectPlugins` 下的所有项目插件、注册文件和数据。其他设置与模板缓存会保留。普通失败会回滚到上一次安装；如果回滚无法完成，请按显示的恢复说明处理。替换成功后会清理备份，备份清理失败则单独报告。

macOS DMG 把插件放在 `Ludork.app` 之外。Finder 中可见 `Ludork.app`、`Applications` 链接和 **Install Official Plugins**，而安装器的 `.command` 扩展名与插件载荷都被隐藏。先把应用拖入 Applications，保持 Ludork 关闭，再双击安装器。用户接受其明确警告后，安装器会校验隐藏载荷，并以事务方式把 `~/Ludork/Plugins` 与 `~/Ludork/plugins.json` 作为一个整体替换。

不要把插件文件拖入 Applications。上述整体替换规则同样适用；选择 **Replace and Install** 前，先留存需要保留的内容。

### 从仓库与便携包安装

从仓库运行时可直接加载检出目录中已注册的插件。如果需要安装一份供仓库外运行使用的用户副本，请构建好 ScriptTools、关闭 Ludork，并在仓库根目录运行：

```sh
.tools/ScriptTools/ScriptTools editor-official-plugins prepare Plugins obj/official-plugins
.tools/ScriptTools/ScriptTools editor-official-plugins install-current-user obj/official-plugins
```

Windows 使用 `.tools\ScriptTools\ScriptTools.exe` 替代上面的可执行文件路径。在已安装的 Windows 正式版编辑器目录中重试失败的插件安装时，运行：

```bat
tools\ScriptTools\ScriptTools.exe editor-official-plugins install-current-user tools\OfficialPlugins
```

请以日常使用的用户身份执行，不要使用**以管理员身份运行**或 `sudo`。这些命令会按上述规则替换全部现有插件及其数据。Windows 安装器的插件操作与 `install-current-user` 命令会在位置可写时，将最近一次输出保存到 `~/Ludork/Log/OfficialPluginInstall.log`。如果 EXE 提示插件安装失败，编辑器本身仍已安装；重试前请先检查此日志与安装器输出。如果身份检查在解析用户目录前就失败，请查看安装器输出。macOS DMG 安装器通过自身界面显示结果与恢复信息。

## 重启与状态

新建和引入都会在登记前编译源码。全局插件在编辑器启动时编译并加载；项目插件在本次编辑器会话首次打开对应项目、创建项目窗口前编译并加载，并在项目打开进度窗口中显示进度。重新打开或切换项目时复用加载结果。新建、引入、卸载或直接修改源码后都必须重启；重新打开项目不会重新加载插件。**插件 → 插件管理**会报告已加载、清单无效、编译失败、初始化失败，以及等待重启加载或等待下次启动删除等状态，并给出诊断信息。

已注册插件会在重启后加载其作用域时启用，没有热启用或热禁用开关。把 **已加载** 视为实际生效的启用状态。

![Manage Plugins 状态与操作](../../../images/plugins/manage-plugins.png)

*替换或移除已安装源码前，先查看这里显示的状态与诊断。*

## 数据与卸载

所有运行方式下，全局插件的可写状态都存放在 `~/Ludork/Plugins/.data/<插件 ID>`，插件通过 `PluginDataDirectory` 取得该路径。官方 Blueprint AI 因此使用 `~/Ludork/Plugins/.data/Ludork.OfficialBlueprintAI`。项目插件数据则位于 `~/Ludork/Plugins/__ProjectPlugins/<项目标识>/.data/<插件 ID>`。不同项目作用域中的同 ID 插件分别拥有独立的数据和凭据。设置与历史一律通过 `PluginDataDirectory` 保存，不要写进插件源码目录。

在编辑器内卸载插件会取消其注册，并可安排安全删除其已安装文件。程序集仍在使用时，已加载的目录可能保留到重启。只取消注册、未删除文件的插件，可以重新选择同一作用域插件根目录下现存的直接子目录再次登记。两种插件卸载方式都会保留插件数据，删除数据是另一个显式操作。编辑器运行期间不要手工编辑注册文件。

资源清理的项目追加保留清单由宿主桥保存在 `EditorCache/ResourceCleanupKeep.list`。它属于当前项目，与插件内容及 `PluginDataDirectory` 分开管理。

## 限制

源码编译可以引用 .NET 运行时、`Ludork.Plugin.Abstractions`、`Ludork.Plugin.Avalonia` 以及编辑器共享的 Avalonia 程序集。插件不能引用编辑器实现程序集。

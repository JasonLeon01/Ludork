# 安装与管理插件

## 目标

新建或引入源码插件，选择对所有项目或仅当前项目生效，并完成检查、更新与卸载，同时把插件程序文件与保留的可写数据区分清楚。

## 前置条件

- 需独立保留的插件数据的副本。

编辑器插件属于可信代码，以编辑器进程的权限运行，不受沙箱隔离。只引入来源可信的目录。

插件拥有自己的源码、窗口、标签、设置、保留数据与第三方声明。宿主负责注册、生命周期、命令上下文、受限的地图、蓝图与资源清理桥接，以及操作时序。

API 共提供六个注册方法：普通菜单命令、地图项右键菜单命令、文本提示 provider、before-Export hook、before-Run hook 与 before-Pack hook。停靠面板、工具栏、任意宿主控件、数据类型和通用编辑器事件都没有公开的注册入口。运行时扩展属于原生 C++ 开发，不能写进编辑器插件。参见[构建与模块布局](<../C++ 原生开发/构建与模块布局.md>)。

## 新建插件

1. 打开 **插件 → 插件管理**，点击 **新建插件...**。
2. 填写显示名称和唯一插件 ID，通过单选按钮选择 **带界面** 或 **不带界面**，默认选择 **带界面**。
3. 选择 **全局插件** 或 **当前项目插件**。打开项目时默认当前项目；启动页只能选择全局。
4. 创建插件。编辑器生成并编译模板，校验入口类型后才安装和登记；失败不会留下创建到一半的插件或覆盖已有目录。
5. 源码文件夹会自动打开。编辑生成的文件后，重启 Ludork 使改动生效。

两种模板的 `Register` 都留空。**带界面** 额外生成一个空的 Avalonia 窗口，不会自动注册菜单或打开窗口。生成目录与完整的手写命令示例见 [Manifest 与最小插件](<Manifest 与最小插件.md>)。

## 引入第三方插件

1. 关闭不应暴露给所选代码的工作，然后检查插件的源码、manifest 与来源。
2. 选择 **插件 → 引入插件** 或插件管理中的 **引入插件**。已打开项目时先选择 **全局插件** 或 **当前项目插件**，再选中完整源码目录，并接受信任确认。默认引入当前项目；启动页只能引入全局插件。
3. 阅读引入结果。manifest 或编译错误必须先解决，才能继续。
4. 重启 Ludork。引入的源码不会热加载。
5. 打开 **插件 → 插件管理**，确认插件在对应作用域下的状态为 **已加载**。项目插件需先打开对应项目。

![Import Plugin 源码目录选择](../../../images/plugins/import-plugin.png)

*选择包含 `plugin.json` 的目录，而不是单个源码文件或构建输出。*

编辑器会校验目录与 manifest，在受管理的插件根目录下创建一份安全的暂存副本，再用 Roslyn 动态编译该副本并校验入口类型。以上检查全部通过后，副本才会移入最终位置，并登记为下次重启生效。目标目录沿用所选目录的名称。编译失败、有效的“全局＋当前项目”集合内 ID 重复或目标目录已存在，都会被拒绝。`__ProjectPlugins` 是宿主管理保留目录，不能作为普通插件目录引入。

目录必须包含 `plugin.json` 和至少一个参与编译的 `.cs` 源文件。不可访问的路径、链接（包括断链）、重解析点（reparse point）、内嵌 `.data`、宿主共享 DLL、F# 或 VB 项目，以及零散的 Avalonia XAML 源码，都会在安装前被拒绝。C# 项目文件可以保留供 IDE 使用，但插件编译器不会执行它。`bin`、`obj`、`.git` 与 `.vs` 下的源码会被忽略。

## 全局与项目存储

在仓库检出中构建的编辑器带有显式开发标记，插件根目录为 `./Plugins`，注册文件为 `./plugins.json`。Windows 发布版以包含 `Ludork.exe` 启动器的安装目录作为安装根目录，其插件源码位于 `<安装根目录>/Plugins`，注册文件为 `<安装根目录>/plugins.json`。编辑器本体及其依赖位于 `Binaries`。直接启动编辑器时，使用的仍是同一个安装根目录。macOS 发布版使用 `~/Ludork/Plugins`，注册文件为 `~/Ludork/plugins.json`。发布输出不带开发标记，即使 publish 目录位于检出内也是如此。Windows 不会回退到 `~/Ludork`，也不会与其合并。

Windows 安装根目录必须保持可写，因为 `Ludork.ini`、注册文件更新和 `Plugins/.data` 都存放在这里。按用户安装的 MSI 位于 `%LocalAppData%\Ludork`，可以满足这一要求。放在只读介质上的便携副本无法支持插件管理，也无法保存插件的可写数据。

项目插件存放在同一个插件根目录下：

```text
Plugins/__ProjectPlugins/<项目标识>/
├── plugins.json
├── .data/<插件 ID>/
└── <插件目录>/
    ├── plugin.json
    └── Plugin.cs
```

`<项目标识>` 格式为 `<安全项目名>-<路径哈希>`：项目目录名经过安全化并截取前 48 个字符，路径哈希取规范化绝对路径的 SHA-256 前 16 位小写十六进制值；Windows 会先把路径统一为大写。路径不同的同名项目相互独立。新建插件使用插件 ID 作为目录名，引入插件保留原目录名。

每个项目作用域有独立的注册文件与数据。插件管理分别显示 **全局插件** 与 **当前项目插件** 的列表、状态和诊断。项目插件只影响对应项目的菜单、地图右键菜单、文本提示和操作 Hook。移动或重命名项目目录后会形成新作用域，需要把插件重新引入新作用域，不会自动迁移。

## 发行版官方插件

Official Blueprint AI、Official Locale Tools、Official Random Map 与 [Official Resource Cleanup](<Official 插件/Resource Cleanup.md>) 作为全局插件随编辑器一同发行。官方编辑器发行包不包含项目插件。Windows 发行包把四者安装到安装根目录的 `Plugins` 文件夹下，并附带由各自 manifest 生成的 `plugins.json`。四者已经登记并启用，因此发行包安装时不会显示第三方插件的信任确认。

macOS DMG 把插件放在 `Ludork.app` 之外。Finder 中可见 `Ludork.app`、`Applications` 链接和 **Install Official Plugins**，而安装器的 `.command` 扩展名与插件载荷都被隐藏。先把应用拖入 Applications，保持 Ludork 关闭，再双击安装器。用户接受其明确警告后，安装器会校验隐藏载荷，并以事务方式把 `~/Ludork/Plugins` 与 `~/Ludork/plugins.json` 作为一个整体替换。

不要把插件文件拖入 Applications。这个 macOS 操作会整体替换插件安装，而不是与之合并。普通失败会回滚到上一次安装；如果回滚本身无法完成，按安装器显示的恢复说明处理。安装成功后不保留任何备份，并删除全部现有第三方插件源码、注册记录和 `Plugins/.data`，也会删除 `Plugins/__ProjectPlugins` 下全部项目插件、注册文件和数据。选择 **Replace and Install** 前，先留存需要保留的内容。应用与安装器仍未签名，也未公证。

## 重启与状态

新建和引入都会在登记前编译源码。全局插件在编辑器启动时编译并加载；项目插件在本次编辑器会话首次打开对应项目、创建项目窗口前编译并加载，重新打开或切换项目时复用加载结果。新建、引入、卸载或直接修改源码后都必须重启；重新打开项目不会重新加载插件。**插件 → 插件管理**会报告已加载、清单无效、编译失败、初始化失败，以及等待重启加载或等待下次启动删除等状态，并给出诊断信息。

已注册插件会在重启后加载其作用域时启用，没有热启用或热禁用开关。把 **已加载** 视为实际生效的启用状态。

![Manage Plugins 状态与操作](../../../images/plugins/manage-plugins.png)

*替换或移除已安装源码前，先查看这里显示的状态与诊断。*

## 数据与卸载

全局插件的可写状态存放在 `Plugins/.data/<插件 ID>`，插件通过 `PluginDataDirectory` 取得该路径。在仓库检出中，该路径为 `./Plugins/.data/<插件 ID>`；在 Windows 发布版中为 `<安装根目录>/Plugins/.data/<插件 ID>`；在 macOS 发布版中为 `~/Ludork/Plugins/.data/<插件 ID>`。因此官方 Blueprint AI 使用相应根目录下的 `Plugins/.data/Ludork.OfficialBlueprintAI`。项目插件数据则位于 `Plugins/__ProjectPlugins/<项目标识>/.data/<插件 ID>`。不同项目作用域中的同 ID 插件分别拥有独立的数据和凭据。设置与历史一律通过 `PluginDataDirectory` 保存，不要写进插件源码目录。

卸载会取消插件注册，并可安排安全删除其已安装文件。程序集仍在使用时，已加载的目录可能保留到重启。只取消注册、未删除文件的插件，可以重新选择同一作用域插件根目录下现存的直接子目录再次登记。两种卸载方式都会保留插件数据，删除数据是另一个显式操作。编辑器运行期间不要手工编辑注册文件。

资源清理的项目追加保留清单由宿主桥保存在 `EditorCache/ResourceCleanupKeep.list`。它属于当前项目，与插件内容及 `PluginDataDirectory` 分开管理。

## 限制

源码编译可以引用 .NET 运行时、`Ludork.Plugin.Abstractions`、`Ludork.Plugin.Avalonia` 以及编辑器共享的 Avalonia 程序集。插件不能引用编辑器实现程序集。

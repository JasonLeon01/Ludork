# 游戏本地化工作流

使用 Official Locale Tools 将翻译工作簿导出为供游戏使用的 Lua 语言表。

## 前置条件

- 项目包含 `Scripts/Source/Locale/Core.lua`，且 `Scripts/Entry.lua` 中有常规的语言初始化代码。
- 使用公式时，所用电子表格软件必须能保留公式的缓存计算结果。

## 步骤

1. 按[官方插件安装说明](<../安装与管理插件.md#发行版官方插件>)安装 Official Locale Tools。
2. 在 `Data/Locale/Locale.xlsx` 中添加 ID 和对应翻译。
3. 点击**导出**后运行项目。
4. 按下文说明使用 `LOC("ID")` 或 `{ID}`。

## 工作簿

创建 `Data/Locale/Locale.xlsx`。每个参与导出的工作表都以第 1 行作为表头。A 列必须是 `ID`（不区分大小写），B 列起是 `en_GB`、`zh_CN` 之类的语言名。语言表头为空会被忽略，并且至少需要一个语言列。

ID 为空的行会被忽略。ID 会去除首尾空白，并且区分大小写。多个工作表的内容会合并。ID 重复时会报告首次与重复出现的单元格位置；同一语言下，后出现的单元格值会覆盖先前的值。

公式单元格存在缓存值时使用缓存值。没有缓存值时，导出去掉开头等号的公式文本。字面量 `=` 或 `==` 可以写成 `'=` 或 `'==`。

## 导出

在统一的编辑器导出流程中，插件为每种语言写出一个 UTF-8 编码的 Lua 表：

```lua
return {
    ["TITLE_START"] = "Start",
    ["TITLE_EXIT"] = "Exit",
}
```

导出结果写入 `Scripts/Source/Locale/<language>.lua`。语言名不能为空，不能是根路径，也不能包含分隔符或非法文件名字符。找不到工作簿时跳过导出，不报错；工作簿格式错误则会中止操作。

导出以 UTF-8 保留 Unicode 文本，包括 C1 控制字符。引号、反斜杠和 ASCII 控制字符使用 Lua 转义，编辑器提示与游戏因此能从生成的语言表中读到相同的字符串值。

工作簿与生成的语言表参与[导出变更检测](<../../编辑器用户指南/运行、调试与打包.md#编译导出与运行>)。游戏打包执行导出并排除工作簿；[Standalone 工程转换](<../../编辑器用户指南/运行、调试与打包.md#将-source-转换为-standalone-工程>)保留工作簿及语言表。直接命令行运行或打包需要预先导出。生成的语言文件被忽略且不进入模板，手写 `Core.lua` 则保留。

## 编辑器提示

字段去除首尾空白后的完整文本为 `{TITLE_START}` 时，可以获得提示。提示提供器从 `Scripts/Source/Locale` 中读取与 `EditorLanguage` 匹配的文件，找不到时回退到 `en_GB.lua`。含空格或嵌套花括号的标记无效。

## 运行时

`Scripts/Entry.lua` 先调用 `Source.Locale.Core.Init()` 加载语言表，再用 `Source.Configs.Main.LoadOrCreate()` 读取语言设置。仅加载 Core 模块不会加载语言表。使用方先把格式化函数绑定为局部 `LOC`：

```lua
local Locale = require("Source.Locale.Core")

local LOC = Locale.ApplyStringLocaleFormat

local buttonText = LOC("TITLE_START")
local tabLabels = Locale.ApplyListLocaleFormat({ "MENU_LOAD", "MENU_SAVE" })
local message = LOC(
    "{ITEM_NEW}: {ITEM_NAME}"
)
```

`ApplyStringLocaleFormat` 既能解析单独的语言键，也能解析字符串中的每个 `{ID}`。找不到的键保持原样；语言不可用时尽可能使用 `en_GB`。双写的 `{{` 和 `}}` 输出字面花括号。通用数据中的字符串不会自动翻译，显示时必须调用 `LOC`。

`Locale.ApplyListLocaleFormat(values: string[]): string[]` 按顺序对数组的每个元素应用 `ApplyStringLocaleFormat`，返回新数组且不修改输入。页签标签与选项列表都应使用它；语言变化需要刷新时再次调用。

`Locale.SetLanguage` 切换当前语言，并同步发布 `LocaleChanged`。配置窗口负责保存所选语言。订阅该事件的 UI 从原始语言键刷新文本，不会重置选中项、焦点或当前对话。

新建 `Main.ini` 时，平台语言与支持的语言完全匹配就使用该语言，否则使用 `en_GB`。已有语言设置不会被覆盖。其他配置默认值见[运行时数据、配置与存档](<../../Lua 与蓝图脚本/Game 玩法/运行时数据、配置与存档.md>)。

Lua 编译与 **将 Assets、Data 和 Scripts 打包为 .ldpak** 这两项设置，都会把 Core 和生成的语言文件随其余 Scripts 目录树一起处理。Official Locale Tools 既不检查这两个选项，也不单独处理语言目录。

翻译改动导出后要重启游戏。[Lua 热更新](<../../Lua 与蓝图脚本/Lua 运行时与模块.md#lua-热更新>)会保留已加载的语言表。

## 限制

工作簿属于项目创作源文件，不是运行时数据库，也不是存档格式。插件菜单的本地化独立于这些游戏语言表。

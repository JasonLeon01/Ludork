# Official Mota Map Fill

Official Mota Map Fill 在已有地图上放置门、怪物和奖励。插件根据当前地形识别隘口与房间，并以存档中玩家的状态计算怪物战斗伤害、安排守卫强度。源码位于 `Plugins/OfficialMotaMapFill`，安装方式见[发行版官方插件](<../安装与管理插件.md#发行版官方插件>)。

项目需要保留 Default Gameplay 的 Player、Enemy、DoorBase、Teleporter 和 MotaBattleAbility 契约。插件调用当前项目的游戏程序还原玩家并计算伤害。选择参考存档前，先保存蓝图、脚本和其他非地图数据的修改；源码项目还需要完成最新的**编译**。插件不会替你保存这些其他文档。

## 选择范围与参考玩家

在地图列表中右键点击地图，选择**魔塔 Actor 填充**。选定一个可见图层，在地图预览中拖动框选矩形范围，或选择**恢复全图**。坐标从零开始，拖动的起点格和终点格都包含在选区内。

选择 `.json` 或 `.ldc` 游戏存档。文件选择器优先打开此前所选文件的目录；首次选择时，默认打开当前项目的用户存档目录 `~/<APP_NAME>/Save`。目录不存在时，定位到最近的已有父目录，不会创建目录。无法从 `Scripts/Entry.lua` 解析 `APP_NAME` 时，错误会显示在状态区域。

**参考玩家**下拉列表按存档的 `playerKeys` 顺序列出 `players`，默认选择第一位玩家。显示的 HP、ATK 和 DEF 包含还原后的装备、道具能力与状态效果。切换玩家会重新计算怪物伤害；**重新读取**会重新读取存档和项目定义。

参考存档只提供玩家状态。地形来自编辑器当前地图，不会应用存档中的地图改动。

## 选择 Actor 蓝图

选择**下一步**，再点击**选择蓝图…**打开系统文件选择器，多选当前项目 `Data/Blueprints` 目录下的 `.json` 蓝图文件。选择列表初始为空；再次选择会追加新条目并去除重复项，取消文件选择则维持原列表。如果本次选择中有无效文件或不支持的 Actor 类型，整批新选择都会被拒绝，原列表保持不变。

下方的门、怪物、道具标签页只显示已选择的蓝图。选择条目或将鼠标移到条目上，可在列表下方查看预览。右键条目选择**移除**，或选中高亮条目后按 **Delete** 或 **Backspace**，可将它移出生成候选。伤害评估只读取已选择的蓝图和当前地图已有 Actor 的类引用。

门条目显示继承后的钥匙 ID 和消耗数量。黄门使用 `KEY_Y`，蓝门使用 `KEY_B`；其他门类型不参与此工作流的放置。怪物条目显示项目自身 `MotaBattleAbility` 算出的伤害，包括战斗特殊能力。无法战胜或伤害超过参考玩家当前 HP 一半的怪物，会标为仅用于最大房间守卫。怪物无法对玩家造成伤害时可以显示零伤害；玩家无法战胜的怪物即使伤害字段为零，也仍然标为无法战胜。

道具分组包含 Item、Equip 蓝图、宝石和药瓶等消耗品，以及不属于玩家、门、怪物或传送点的其他 Actor 蓝图。请只选择希望作为奖励放置的拾取物。传送点及其子类不会成为生成候选。

## 放置规则

插件读取所有可见图层的地形通行信息，包括自动图块和方向通行限制。只有属于至少一个完整可通行 2 × 2 区块的格子才算宽房间内部，再按四方向可通行连接归为各个房间；一格宽的直通道、弯道和交叉口不计入这类房间面积。分析使用整张地图，避免把选区边界误认为墙；实际放置只发生在选定图层和范围内。其他图层已有的 Actor，以及需要保留的传送点，会占用对应格子。

- 已选择适用怪物且存在可用位置时，每个房间的室内与直属入口合计安排一只怪物，优先放在室内靠近入口的位置。共享入口已有怪物时，相邻房间可以共用它，不再各自叠加第二只；直属入口之外的独立主通道仍可安排自己的守卫。没有可用门口的房间，也可以在室内空格放置普通怪物。门在可用入口独立放置，不占用这一只怪物的名额。内部不少于九格的房间优先使用蓝门和较强怪物，小房间优先使用黄门和较弱怪物。在能够战胜且伤害不超过玩家半血的怪物中，按伤害排序，前半组向上取整作为弱怪，后半组作为强怪；只有一种符合条件的怪物时，两种位置都可以使用它。
- 每次最多放置一只高危怪物，守卫一个完全位于选区内、存在可用入口的最大大房间；并列最大时随机选择。高危候选包括伤害超过玩家半血、无法战胜，以及反击伤害致死的怪物。它们不会用于补齐普通房间、口袋或走廊缺少的守卫。
- 窄终端口袋由一个隘口与主路分开，内部一至八格，可以呈 L 形或 T 形。口袋内部不能包含宽房间或传送点，入口外侧必须连向宽房间、传送点或主路分叉。这些口袋不增加判断大房间时使用的面积。口袋内部与入口同样合计只安排一只怪物。室内空位足够时，优先在内部放较弱怪物和奖励，入口还可以放黄门；入口已有怪物时直接共用，不再向内部添加第二只。内部仅剩一格可放奖励时，守卫可以放在入口。普通走廊不放道具。
- 有道具候选和合法位置时，房间与口袋优先保证至少一件奖励。已有保留道具即满足这一最低要求；否则先预留一个奖励格，再放守卫。口袋的首件奖励优先放在内部较深处。新增道具目标数量为剩余可用室内格的 40%，向上取整。优先使用随机选定的一种棋盘格颜色，形成 `1010` / `0101` 一类交错布局。放置时禁止道具横向或纵向连续占据三格，并计入保留道具和其他已预留奖励格。空间限制可能使最终数量低于目标。

缺少某类候选时只跳过该类，例如未选择蓝门不会阻止在合适的位置放置强怪。无法安排怪物、守卫或奖励的房间、口袋会在结果中提示原因，不会覆盖已有占位、越出选区或突破高危怪物限制。结果显示实际放置数量、房间与口袋的合计数量和随机种子；**再次生成**使用当前选择生成另一种分布。

## 替换与保存

**生成并保存**会替换选定图层、选定范围内除 `Source.MapActors.Teleporter` 实例及其子类以外的所有 Actor，包括原有事件、装饰、门、怪物和道具。保留的传送点维持原 tag 和实例覆盖；被删除 Actor 的实例覆盖随之移除。Tile、AutoTile、其他图层以及矩形范围外的 Actor 不变。没有可生成的位置时，不会清空或保存地图。

整次替换经过版本检查，只保存目标地图，并记录一步撤销。同一地图已有的未保存修改也会一并保存。地图编辑冲突、Actor 类型无法解析或保存失败时，地图保持不变；版本冲突会重新载入地图，需要再次加载参考存档。完整保存与撤销规则见[地图项右键菜单命令](<../注册点与 Hook 参考.md#地图项右键菜单命令>)。

伤害是以所选存档状态进行的单场战斗预估。生成过程不模拟拾取奖励、消耗钥匙、连续战斗，以及领域、夹击等与位置有关的移动伤害，也不保证生成后的整张地图一定可通关。

# 架构与数据流

PreviewHost 使用项目的原生实现渲染编辑器内容。编辑器负责编辑操作、输入与辅助覆盖，宿主负责原生预览会话和像素传输。各类视图的操作见[地图与世界预览](<地图与世界预览.md>)和 [UI、Actor、粒子与字幕预览](<UI、Actor、粒子与字幕预览.md>)。

## 共用渲染器与模块边界

`Engine/Source/Core/include/Graphics/MapRenderer.hpp` 定义共用原生地图渲染器。Engine 与 `PreviewHostRuntime` 编译 Core Graphics 下的同一份实现。`Scene` 包含有序图层、带世界位置的瓦片区域、已解析精灵外观、组件光源、环境光、远景与雾；`View`、`Options` 提供相机、输出尺寸、时间及显示选项。结果为 `sf::RenderTexture`，渲染器不解析编辑器请求，也不向 CPU 回读像素。

普通地图使用单个区域。世界在每个权威图层内绘制各区域，保留 placement 优先级，以及跨区域光照与遮挡。`GlobalCore.GameMapRenderer` 将玩法状态适配为渲染数据，并提供粒子、Billboard、图层特效及普通地图玩家遮挡插入点。原生 `TileLayer::updateBlock` 重建受影响 chunk 和自动元件邻接范围，并失效材质与遮挡缓存。流式加载保留 `writeBlock` 及正常构建阶段，动画使用明确传入的帧时间。

`Engine/PreviewHost` 负责请求解析、编辑器会话、进程通信、BGRA 像素回读和临时帧传输，位于 Core 递归源码收集范围之外。游戏模块不包含这些实现，也不链接 `PreviewHostRuntime`。`LudorkRuntime` 保持向下依赖，不依赖地图玩法对象。[构建与模块布局](<../C++ 原生开发/构建与模块布局.md>)介绍游戏模块；预览目标与分发规则见[构建、发布与排错](<构建、发布与排错.md>)。

## 场景更新

编辑器提交当前内存中的地图数据，包括未保存修改和蓝图实例覆盖。材质、Actor、地图与 UI 预览使用当前材质文档快照，因此修改节点图或公开参数默认值后无需保存即可预览。地图请求携带 `materialRevision`，首次请求、材质变化和资源刷新时附带完整 `materials` 快照，其他帧和地图切换复用快照及已解析资源。撤销、重命名和删除也会替换快照；缺少请求版本所需的快照时报错。材质覆盖仅在所属预览请求执行期间生效，不影响其他类型的预览。地图编辑还会提供引用的粒子资源，其曲线使用当前内存数据解析。材质节点与参数 Schema 由原生 registry 提供，编辑器不维护另一套着色器模型。解析生成视觉记录，遵循[预览与游戏运行的边界](<概述.md#预览与游戏运行>)。没有贴图的 Actor 仍可提供光源与 Emitter 效果。

材质窗口使用 `renderMaterial` 请求，并以 `materialRevision` 标识当前材质。首次请求、内容或路径变化以及新连接建立时，附带该材质的 `asset` 和 `materialPath`；其他帧只发送时间和预览设置，不携带材质文档。快照排除节点布局，也不包含项目中无关的材质。会话保留已解析材质、生成的 GLSL 和节点图编译错误，在预览设置或源纹理变化时更新场景。缺少请求版本所需的快照时报错；重新发送相同版本和路径会返回缓存的源码与诊断，不再次准备材质。帧间仍会检测纹理文件变化。

材质诊断使用独立的 `diagnosticsRevision`：纹理或帧裁剪错误可能在材质未变化时出现或消失。普通帧仅在诊断变化时携带诊断，空数组表示清除旧错误；快照响应始终包含诊断和生成源码。即使后续编辑使同一响应中的画面过期，客户端仍会保留这些结果。材质失败时显示错误画面，不沿用上一份成功材质；修正节点图或恢复不可用的纹理后，预览恢复正常。

地图会话首次接收完整场景，后续更新场景字段、区域和带标识的精灵／光源记录；相机及动画请求复用已安装场景。仅涉及 Actor 的编辑更新缓存中的视觉记录及受影响光照，不重新扫描地形或构造 Tilemap。结构变化和资源刷新重建必要的场景状态。普通地图、世界画布与缩略图使用同一渲染路径。

Core 渲染器在帧间保留渲染目标和光照缓存。地图切换或场景关闭时保留可复用纹理、着色器和材质程序，同时使场景相关的遮挡与光照缓存失效。原生调用方通过 `MapRenderer::invalidateScene()` 表达这一边界；`reset()` 则释放全部渲染器资源。资源刷新和连接关闭会释放预览资源。仅在可见材质需要反射时绘制表面遮罩。渲染器接收不依赖 Actor 或 Lua 的场景、区域、精灵、光源与视图记录。View Mode、雾与远景选项独立控制画面，操作方式见[地图与世界预览](<地图与世界预览.md>)。运行时雾配置及静态楼层预览 API 仍由 [GlobalCore：地图与雾效](<../Lua 与蓝图脚本/全局与 Core 模块/Core Modules/GlobalCore/地图与雾效.md>)说明。

## 调度与帧所有权

项目地图预览服务懒启动两条连接：前台负责地图／世界视口，后台串行处理缩略图。缩略图数量不会增加进程数。前台同时只执行一个请求，并仅保留最新待处理状态，动画最高 30 FPS。新选中地图的首帧在连接空闲时立即提交，不等待动画帧间隔；已有请求仍须完成，再提交最新待处理地图。隐藏视图停止刷新，交互期间暂停新缩略图任务。缩略图使用时间零，并按场景／资源、尺寸和显示选项缓存。

地图连续编辑期间可以发布已完成的兼容帧，避免新的待处理修改持续阻止画面更新。场景身份、资源及显示选项变化会使不兼容结果失效。发布的位图携带该帧对应的相机变换，交互结束后会渲染最后一次修改。

材质窗口每 100 ms 调度一次 640 × 300 预览，同时最多执行一个请求。窗口隐藏、最小化或禁用预览时不提交帧。`generation` 标识当前材质和预览设置，用于丢弃过期画面，与材质缓存版本分别处理。仅调整节点布局不会替换材质快照。

预览连接持有两块可复用的 BGRA 帧文件映射，仅在容量不足时扩容。响应中的像素会保留到客户端复制完全部页面，包括 Actor 批量预览。宿主直接转换到映射存储，编辑器复用映射视图。UI 先捕获独立的地图请求，再由后台完成序列化、交换、像素读取与位图创建，后台不读取可编辑场景。UI 将独立的不可变位图与对应相机变换一起发布。连接关闭或重建时释放映射和临时文件。这些职责保留在预览宿主与编辑器中，不进入游戏运行库。

## 能力与耗时

连接校验宿主协议及声明的能力。预览传输要求 `persistentFrames`，地图编辑还要求 `map`、`mapActorChanges`、`mapEmitters` 和 `mapMaterialSnapshots`，材质窗口预览要求 `material` 和 `materialSnapshots`。旧宿主需要重新构建或更新，地图预览不会回退到 Avalonia 绘制。处理方式见[构建、发布与排错](<构建、发布与排错.md#排错>)。

`MapPreviewLease.LastFrameTiming` 提供变更到发布的延迟，以及场景更新、序列化、原生场景应用、渲染、回读、传输、客户端像素读取和位图创建各阶段耗时。其中可为空的 `SelectionToPublishMilliseconds` 从地图选择入口、文档准备之前开始，计时至首个兼容帧发布。丢弃的帧不会消耗这次计时，后续动画帧不填写该值。两类发布耗时都结束于编辑器发布帧，不代表屏幕实际呈现的时刻。判断原生绘制是否造成延迟前，应在相同场景、相机与输出尺寸下比较各阶段。3840 × 2160 输出帧在传输开销之外已有超过 33 MB 的 BGRA 像素数据，与地图包含多少格无关。

# 构建、发布与排错

PreviewHost 属于可编辑项目。宿主程序、专用运行库和 UI 注册表必须与项目的原生控件及编辑器协议配套。

## 准备 Source 与 Standalone 项目

C++ Source 项目通过 **编译** 构建 Debug 游戏程序与预览运行时，不启动玩法。完整桌面 `tools/build_cpp` 构建也会生成预览文件。Standalone 项目使用 `Binaries` 中配套的预览运行时。编辑地图后无需每次运行游戏或执行导出，即可查看预览。

Windows x64 预览支持与游戏相同的 MSVC、MinGW-w64、LLVM Clang 构建。工具链的准备方式，以及可编辑项目和游戏包随附的运行库 DLL，见[构建项目](<../C++ 原生开发/构建与模块布局.md#构建项目>)。

仅构建宿主时，Windows 使用：

```text
tools\build_preview_host.bat Game Debug
```

macOS 使用：

```sh
sh tools/build_preview_host.sh Game Debug
```

工具命令统一为 `ScriptTools preview`。使用 `ScriptTools preview validate Game` 校验项目已发布的预览文件；必要时将 `Game` 替换为项目根目录。修改原生 UI 控件后，需要重新构建项目并发布更新后的注册表。控件注册见[原生 UI Adapter](<../C++ 原生开发/原生 UI Adapter.md>)，资产与生成代码归属见[声明式 UI 编写工作流](<../Lua 与蓝图脚本/声明式 UI/编写工作流.md>)。

## 构建配置

| 构建 | `LUDORK_BUILD_PREVIEW_HOST` | `LUDORK_BUILD_GAME_APPLICATION` | UI 校验 |
|---|---|---|---|
| 完整桌面开发 | `ON` | `ON` | 配套的桌面注册表 |
| 仅预览 | `ON` | `OFF` | 宿主发布项目注册表 |
| 仅游戏 | `OFF` | `ON` | 通过 `LUDORK_UI_REGISTRY_PATH` 提供配套桌面注册表 |

移动平台交叉构建必须明确提供桌面端生成的 UI 注册表。原生构建不生成 UI Lua View 或声明，需另行执行 [UI 导出流程](<../Lua 与蓝图脚本/声明式 UI/编写工作流.md>)。运行及打包要求的构建／导出记录见[运行、调试与打包](<../编辑器用户指南/运行、调试与打包.md>)。

## 发布文件与重建

桌面原生构建生成以下文件：

| 文件 | 用途 |
|---|---|
| `PreviewHost` | 地图、Actor、粒子、字幕与 UI 的原生预览进程 |
| `PreviewHostRuntime` | 预览专用运行库 |
| `EditorCache/Preview.json` | 描述配套二进制与注册表的清单 |
| `EditorCache/UiPreview.registry.json` | UI 专用控件注册表 |
| `EditorCache/Preview.building` | 重建期间暂停连接的临时标记 |

Source 预览与游戏二进制共用 `bin/<configuration>`，Standalone 使用 `Binaries`。新文件发布后，编辑器重新连接。编译、链接、描述导出或发布失败时，预览保持不可用，直到下一次成功发布清除构建标记。完整 UI 资产校验在发布后执行，因此资产校验错误可以使构建失败，但保留新发布的预览用于编辑。通用服务与快照名为 `PreviewRuntimeService` 和 `PreviewRuntimeSnapshot`；UI 专用的 `UiPreviewClient`、`UiPreviewSession` 与 `UiPreview.registry.json` 保留其名称。

Standalone 的预览 JSON 缺失、损坏或不匹配时，预览准备、保存、导出或 `ScriptTools preview ensure <project-root>` 会从当前 `Binaries/PreviewHost` 重新生成。恢复只替换两份预览 JSON，保留其他缓存文件。构建标记会阻止恢复；宿主二进制或依赖缺失仍是错误。Source 项目在所选预览元数据不可用时需要构建。

## 可编辑模板与游戏成品

[Source 转换为 Standalone 工程](<../编辑器用户指南/运行、调试与打包.md#将-source-转换为-standalone-工程>)时，会构建并发布配套的 Release 预览。macOS 签名后会刷新预览构建标识，并在发布产物前验证宿主。`EditorCache` 只保留预览元数据，不复制源工程的导出记录。

Source、Standalone 可编辑项目及模板保留预览能力。最终游戏打包使用有效的项目 UI 注册表校验资产，但排除预览可执行文件、专用运行库（包括版本化动态库）、清单、构建标记、临时帧文件和 `Engine/PreviewHost` 源码目录。游戏程序与运行库不链接 `PreviewHostRuntime`。

该排除规则适用于散放、`.ldpak` 资源布局及各平台的二进制／资源目录，包括 macOS 应用包。打包只处理暂存副本，不会从可编辑项目中删除预览能力。一般分发、加密及签名选项仍由[运行、调试与打包](<../编辑器用户指南/运行、调试与打包.md#打包>)说明。

## 排错

| 现象 | 处理方式 |
|---|---|
| 宿主、清单或注册表缺失 | 编译 C++ Source 项目；Standalone 先恢复预览元数据，二进制或依赖缺失时再更新配套运行时，随后校验发布文件。 |
| 协议或能力不兼容 | 重新构建或更新宿主，以满足[预览所需能力](<架构与数据流.md#能力与耗时>)。地图预览不回退到其他渲染器。 |
| 构建期间预览暂停 | 等待发布完成及重新连接；构建失败时先修复错误并重新构建，再重试预览。 |
| 新增原生控件不可用 | 一起重建适配器与注册表；仅添加编辑器 Palette 条目不能注册原生控件。 |
| 打包拒绝 UI 资产或注册表 | 使用配套桌面构建修复报错的资产／注册表不匹配，不用无关项目的注册表替换。 |
| 地图拖拽或动画延迟 | 在实际输出尺寸下检查[架构与数据流](<架构与数据流.md#能力与耗时>)中的各阶段耗时；原生绘制、GPU 回读、像素复制和 UI 发布具有各自开销。 |

各类视图的占位内容与不支持的内容见 [UI、Actor、粒子与字幕预览](<UI、Actor、粒子与字幕预览.md>)；地图显示开关见[地图与世界预览](<地图与世界预览.md>)。

# 函数、事件与执行

## 目标

从同一声明源暴露方法、分组自由函数、事件与蓝图执行协议。

## 前置条件

- 所属模块中已有绑定类，或已有公开的自由函数头文件。
- 已为 pure、分支输出、latent 状态或循环行为定义好蓝图契约。

## 步骤

### 绑定方法与自由函数

`BIND_METHOD` 把类方法公开给原生 Lua 与 LuaLS，逻辑上公开的方法默认还会进入蓝图 Metadata。`BIND_FUNCTION` 公开自由函数，但不改变其既有的 metadata 选择规则。只有蓝图节点确实没有执行输入与执行输出时，才声明 `Pure = true`。非 void 返回并不代表 pure。

```cpp
BIND_FUNCTION(name = "clampValue", Pure = true)
float clampValue(float value, float minimum, float maximum);
```

未分组的自由函数只在模块根公开，例如 `Engine.clampValue`。`name` 用于选择该根字段的 Lua 标识符。group table 才是函数的规范归属时，使用 `BIND_FUNCTION_GROUP`。

非 void 函数会得到一个名为 `return` 的 metadata 输出。void 函数得到空的 return table。普通实例方法还会得到有类型的首个 `self` 输入，默认使用图的 owner，且始终保持可见。静态方法、自由函数与事件入口不添加该参数。参数与默认值的位置规则见[生成 Metadata 与 Stub](<生成 Metadata 与 Stub.md#默认值与类型>)。

### 仅覆盖 Metadata 签名

`metadata_parameters` 按已有业务参数名指定蓝图 schema。`metadata_returns` 按已有返回引脚名指定 schema；普通单返回值的引脚名是 `return`。这些选项不改变 C++ 签名及其 LuaLS 声明，并保留函数原有的 metadata 可见性。

```cpp
BIND_METHOD(
    Pure = true,
    metadata_parameters = {direction = {enum = "Enums.Engine.Direction"}},
    metadata_returns = {return = {enum = "Enums.Engine.Direction"}})
int oppositeDirection(int direction) const;
```

使用注解花括号语法，包括示例中不加引号的 `return` token。Bindgen 会在输出 Lua 时生成所需的带引号键。不存在的引脚名会导致生成失败。实例 `self` 仍单独生成，因此覆盖项直接使用业务参数名，不需要计算接收者偏移。属性 schema 使用 `metadata_type`；递归枚举 schema 与容器、联合类型的组合方式见[Metadata 结构与 Decorator](<../Lua 与蓝图脚本/蓝图脚本/Metadata 结构与 Decorator.md#枚举-schema>)。

### 指定函数组

只包含自由函数的头文件可以开头声明：

```cpp
BIND_FUNCTION_GROUP(name = "Manager")

BIND_FUNCTION(name = "playSE")
void playSE(const std::string &path);
```

该头文件中所有绑定函数都只注册到分组 table。注册、LuaLS stub 与 metadata 使用同一个分组。未分组的函数仍留在模块根。

### 声明执行行为

非 pure 方法默认走普通执行流，不需要显式的执行注解：

```cpp
BIND_METHOD()
void refresh();
```

执行结果需要选择某个具名执行分支时，把各分支写进内联的 `outpins(...)` 块。Bindgen 保留声明顺序：

```cpp
BIND_METHOD(outpins(default = nil))
void setCollisionEnabled(bool enabled);

BIND_METHOD(outpins(success = true, fail = false))
bool tryMove();
```

需要挂起的工作，把恢复状态放进 `latent(...)`：

```cpp
BIND_METHOD(nonnull_return = true, latent(TimeUp = true),
            defaults = {nil, nil, {}, false},
            parameter_types = {float, function, any[], bool})
std::shared_ptr<AsyncOperation> addTimer(
    float interval,
    RuntimeIdentityPtr task = {},
    RuntimeValue::Array params = {},
    bool blocking = false);
```

`defaults` 描述参数默认值，与 `outpins(default = nil)` 无关。列表形式同样适用于构造函数与自由函数的 `defaults`。小写 token 与花括号选项列表见[宏参考](<宏参考.md>)。

`Pure = true` 不能与执行协议同时出现。getter 属性也不能携带执行协议，其顶层单数 `default` 仍是属性默认值。内联 `loop_node(ForEach)` 声明循环，独立的 `BIND_REGISTER_EVENT()` 创建事件入口。没有显式输出的事件会得到默认分支值 `nil`。

显示信息、编辑器信息与执行信息都写在 `BIND_METHOD(...)` 或对应的函数、属性注解里。不支持为 metadata、purity、执行拆分与 latent 各写独立标记。

`nonnull_return = true` 声明方法或自由函数返回一个非空 `std::shared_ptr` 结果。bindgen 会移除 Lua 声明最外层的 `nil` 分支；原生代码实际返回空指针时抛出绑定错误。它不改变 C++ 类型或蓝图执行引脚。

原生 latent 实现返回 `<Runtime/Async/AsyncOperation.hpp>` 中的 `std::shared_ptr<AsyncOperation>`。通过 `AsyncOperation::create(poll?)` 创建，用 `emit` 发布中间阶段，用 `complete` 或 `cancel` 结算。

### 声明严格回调

需要约束回调返回结果数量时，使用 `<Runtime/StrictFunction.hpp>` 中的 `ludork::runtime::StrictFunction<Return(Arguments...)>`：非 void 签名要求 Lua 恰好返回一个结果，`void` 则要求不返回任何结果。结果会按声明的类型转换并校验。

```cpp
using Number = std::variant<std::int64_t, double>;
using Constraint = ludork::runtime::StrictFunction<Number(Number)>;

BIND_METHOD()
void setConstraint(Constraint constraint);
```

回调嵌套在 variant 或容器中时也会执行这些检查。Nil 表示空回调。Lua 回调保留其函数身份，并一直绑定到创建它的会话。Lua 错误与转换失败会传播给调用方。Lua 引用与会话生命周期的规则见[运行时值边界](<运行时值边界.md#lua-引用与会话生命周期>)。

## 限制

注解只描述执行协议，不实现该协议的运行时行为。C++ 函数体与运行时调度器必须实际产生每个已声明的分支、latent 状态或循环转换。

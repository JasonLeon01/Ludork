# Script Mixin 校验与打包

## 目标

保存前先校验挂载的脚本及其 metadata，再确认打包后的游戏能加载每一个被引用的 mixin。

## 前置条件

- 已按 Script Mixin 模式配置的蓝图继承链。
- `Scripts/Mixins` 下的一对运行时文件与 metadata 文件。
- 一张包含所有受影响蓝图的代表性地图。

## 步骤

1. 校验相对脚本路径与同名 metadata 文件。
2. 按报告顺序解决保存时的蓝图诊断与字段诊断。
3. 在编辑器模式下跑通所有生命周期与事件路径。
4. 用预期的 Lua 编译设置打包，然后重做运行时检查。

## 路径校验

`scriptPath` 必须是 `Scripts/Mixins` 下非空、相对的 `.lua` 路径。路径使用正斜杠，且不得包含空段、`.`、`..`、驱动器前缀、绝对根或 `_meta.lua` 后缀。

继承链中第一个 Script Mixin 蓝图必须设置 `scriptPath`。子蓝图可以继承它，也可以提供另一个有效路径。本地路径指向的文件不存在时，校验失败。

## 保存时校验

保存前，编辑器检查父类与模式继承链是否有效、脚本路径与同名 metadata 文件，以及 [Script Mixin Metadata](<04.Metadata.md>) 中的各项规则。先解决第一个报出的路径错误或 metadata 错误，再看下游的字段错误。

## 打包

Pack 会把项目的 `Scripts` 树复制到 staging。**使用 luac 编译脚本**在那里编译 Lua，**将 Assets、Data 和 Scripts 打包为 .ldpak** 把保留下来的脚本归档。两个选项都不改变 mixin 路径、脚本每次执行重新加载的行为或项目源码。发布前，对每个被引用的 Script Mixin 蓝图各做一次打包运行，并确认控制台里没有模块解析错误。

## 限制

编辑器的 metadata 校验不能证明所有父方法都存在。打包会保留有效的源码路径，但无法修复已过期的蓝图 attribute。

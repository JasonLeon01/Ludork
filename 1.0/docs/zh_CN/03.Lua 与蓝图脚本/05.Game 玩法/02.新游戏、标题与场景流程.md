# 新游戏、标题与场景流程

默认入口创建 `Source.Scenes.SceneInit`，随后把控制权交给原生 System 主循环。SceneInit 准备共享数据，然后推进到标题流程。它的逻辑 tick 负责加载与切换检查，渲染线程的 late tick 负责向声明式 UI 发布进度，从而避免逻辑线程改动由 GPU 支撑的控件。标题场景创建包含开始游戏、继续游戏、设置与退出游戏的命令窗口。Save/Load 和 Config 在首次使用时创建，之后复用，直到标题场景销毁。

场景切换使用 `GlobalCore.SceneManager`，冻结画面与转场请求使用 `GlobalCore.Transition`。屏幕闪烁、震动与色调使用 `GlobalCore.ScreenEffects`。

## 目标

调整 Game 项目的标题流程，同时保持项目初始化的确定性、存档处理的明确性和场景切换的安全性。

## 前置条件

- 已确定 New Game 路径使用的初始地图和玩家定义。

## 步骤

### 配置新游戏

新建游戏操作会创建或重置游戏实例，选定初始地图与玩家数据，然后切换到地图场景。`Data/Configs/System.json` 在 `startPlayerBlueprint` 中以相对于 `Data/Blueprints` 的路径保存玩家蓝图，并在 `startRegion` 中保存初始区域。这两个值只用于初始化新游戏；Continue 则恢复所选存档槽中保存的玩家类与当前区域。

进入地图时创建 HUD 与 Region Title，可选弹窗和对话则等到首次显示时才创建。这样能避免场景进入阶段构造未使用的窗口，同时保持原有转场时长。窗口的所有权与复用规则见[窗口、菜单、输入与控件](<04.窗口、菜单、输入与控件.md>)。

`startMap` 可以指向普通地图、`World_01/_world.json` 这样的组合式大地图清单，或 `World_01/Map_03.json` 这样的已摆放子地图。目标是清单时，`startPos` 使用大地图坐标；目标是子地图时，`startPos` 使用子地图局部坐标。编辑器用同一棵地图树展示这三种形式，并保存选中的字符串路径。

### 进入地图与组合式大地图

`GlobalFunctions.Scene.GotoMap` 遵循相同的路径与坐标规则。进入当前大地图的另一张子地图时，仍沿用它的 `WorldGameMap` 门面（facade）。未摆放的子地图不是合法目标。

在大地图中，`Scene:getGameMap()` 与 `Actor:getMap()` 公开同一个大地图坐标的 GameMap 门面。子地图摆放（placement）提供通行性、Dir4、材质与地形；未被覆盖的格子是可通行的空洞。子地图数据缺失或前后不一致都会报错。

门面的 `mapName` 取自 `_world.json` 中必填的 `worldName`，所以玩家 HUD 之类的 UI 标识的是完整大地图，而不是某张被流送的子地图。子地图 JSON 保留自己的 `mapName` 以便单独使用；但子地图属于已加载的大地图时，HUD 不显示该名称。

大地图摆放由原生层建立索引。安装、重建或淘汰子地图都会更新索引。Actor 发布与 Tile chunk 就绪共同决定玩法能否访问。导航与材质查询既不逐格调用 Lua，也不加载缺失的子地图。

进入时，运行时会重新校验扁平的大地图目录、精确匹配的 `_world.json`、必填的大地图名称、直接存放的 JSON 子地图文件、摆放与图层顺序。无关的非 JSON 普通文件会被忽略，非法数据直接失败。

子地图依次经过 `Unloaded`、`Reading`、`Prepared`、`Active` 和 `Dormant` 状态。流送优先处理 Camera 邻域，并取消已过期的读取。只有 Active Actor 参与模拟。在所有可见摆放与 Tile chunk 就绪之前，Camera 保留最后一帧完整画面，启用碰撞的移动也无法进入尚未准备的区域。

流送使用 Camera 四角在大地图坐标中的连续包围范围，包含旋转后的范围。Active 向四周各扩展一屏，Prepared 各扩展两屏，并沿每个移动轴的前进方向再扩展一屏。扩展完成后才向外取整到格子并裁剪至世界边界，因此 Camera 在格内移动不会改变流送所用的一屏尺寸。

位于 Camera 保守大地图边界之外的 Active Actor 仍参与模拟，但不进入颜色与光照 surface 的渲染 pass。区域图层可见性仍在该视口判断之前应用。大地图场景保持 Lua 常规自动垃圾回收；流送通过自身正常生命周期释放区域引用，而不是停用全局回收器、每个 tick 只手动推进一步。

启用转场时，进入大地图会冻结离开时的画面，直到目标视口以及必需的 Actor、灯光和 Tile chunk 就绪。必需数据出错会在释放前向外传播。`blockTransition = true` 跳过遮罩，但保留这道就绪屏障；外围准备工作仍为异步。

非 Active payload 采用 32 区域或估算 256 MiB 的 LRU 策略：先淘汰 Dormant，再淘汰 Prepared。Active 区域与待处理的目标会被固定，因此可能暂时超过软上限。

性能监视器会显示流送状态；某个异步 publish tick 达到 4 ms 时，每个大地图会话记录一条警告，并指出实测最慢的阶段。参见 [启动页、工作区与快捷键](<../../02.编辑器用户指南/01.启动页、工作区与快捷键.md>)。

`RegionDict` 仍只保存楼层传送数据，不定义大地图的拼合方式或流送规则。

### 配置继续游戏

Continue 通过 `GetSavePath(slot)` 读取原生构建所选的普通或加密存档，恢复游戏状态并打开对应场景。存档缺失、格式错误或版本不受支持时，必须走明确的“未找到”或错误路径，不得静默构造不完整的状态。

### 保持场景切换

使用 API 参考中记录的 System 与场景 API。场景切换由 C++ 运行时调度，因此一帧的更新过程不会中途销毁对象。离开的场景所拥有的窗口与临时资源，通过其正常生命周期释放。

### 自定义标题

修改 Lua 场景与窗口的组合方式及对应数据。所有文本标识符都要与 [游戏本地化工作流](<../../05.插件开发与安装/06.游戏本地化工作流.md>) 兼容。测试开始游戏、有存档和无存档的继续游戏、设置、退出游戏，以及从运行中的地图返回标题界面。

## 限制

Game 不规定通用的存档升级策略，也不规定标题界面的设计。正式发行的游戏必须自行声明支持的存档版本，并提供自己的界面呈现与恢复提示。

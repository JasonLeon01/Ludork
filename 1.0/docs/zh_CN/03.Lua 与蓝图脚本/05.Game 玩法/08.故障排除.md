# 故障排除

## 项目无法打开

检查 `Main.proj` 以及 `Data` 下每个已加载文件是否为合法 JSON。路径必须留在项目内。应恢复必需的目录，而不是把编辑器指向一个残缺的包。

## 蓝图无法保存

运行蓝图校验，并先处理第一个父类、环、graph、node、link、pin 或默认值错误。使用 Script Mixin 时，还要检查相对路径、返回的 table 与同名 metadata。

## 游戏无法启动

从控制台的第一个错误开始阅读。按需先编译，再导出；运行按此顺序检查。导出校验、插件失败和 before-Run Hook 失败都会阻止启动。检查生成的 UI 与语言文件、原生模块、`Main.ini` 入口脚本、Core 模块顺序与运行时协议诊断。

## 节点缺失

确认它的 metadata 文件是纯数据、返回 `_METADATA`、把成员声明为 `type = "function"` 或 `"event"`，并且不位于 `Scripts/Mixins` 下。C++ 声明需要重新构建，让 bindgen 重新生成 metadata。

## 资产或数据引用损坏

打开引用树，找到失效的已保存 key 或路径，手工更新它。重命名与删除都不保证自动修复引用。

## 本地化文本缺失

按 [游戏本地化工作流](<../../05.插件开发与安装/06.游戏本地化工作流.md>) 中的 Official Locale Tools 检查项逐条核对：workbook 表头、ID、导出的语言文件、所选语言、回退与 `LOC`/花括号格式。

## 打包后行为不同

检查包内的资产、脚本、原生模块、FFmpeg 变体、可写 `Main.ini` 的位置，以及平台相关的路径处理。绝不要通过路径分隔符推断平台，而应使用注入的 `PLATFORM` 值。

如果 Pack Options 中没有 Android，确认 Android Studio 安装在 `/Applications/Android Studio.app` 或 `~/Applications/Android Studio.app`，且项目为 C++ Source。Android 预检失败会列出每一项缺失要求：SDK Platform 36、Build Tools 36.0.0、本机 SDK 的 `ndk` 目录下完整的稳定版 NDK r27 或更高版本、支持 Unix Makefiles 的系统 CMake 3.28 或更高版本，以及 `/usr/bin/make`。SDK 依次从 `ANDROID_SDK_ROOT`、`ANDROID_HOME`、`~/Library/Android/sdk` 解析。项目本身不含 SDK 或 NDK。打包器不会安装或下载这些组件，也从不要求模拟器、AVD 或 adb。

如果 Android 签名失败，检查 JKS 或 PKCS12 路径是否为绝对路径且可读、alias 是否存在、两个密码是否正确。在对话框中修正过期的已保存值，并重新输入未保存的值。失败的运行既不会发布未签名的中间产物，也不会发布不完整的已签名 APK。后续每个需要更新已安装应用的版本都必须使用同一把密钥。

## 限制

原生崩溃、绑定生成失败与插件加载失败，都需要各自开发专题中的专用诊断方法。

# 简易服务器：部署与编辑器设置

Ludork Server 是带有 Lua 逻辑层的可选 Node.js 服务。项目通过 WebSocket 提供显式数据快照、void RPC 与在线事件。账号数据存放在数据型 `.ldata` 分类文件中，只读管理网页显示带类型的 Lua 值。游戏业务决定何时获取、刷新或写入；服务不会自动同步多人状态或替代本地存档。

后端和前端部署在服务器或独立测试实例上。游戏客户端只需要服务器 URL 和项目密钥，不安装 Node.js，也不部署服务端。配置客户端集成需要 **C++ Source** 工程。转换后的 Standalone 工程可保留已编译进运行时的服务器设置，但不显示两处服务器配置入口。

## 获取服务端包

打开 [Ludork Releases](https://github.com/JasonLeon01/Ludork/releases)，在对应 Release 的 **Assets** 中下载 `LudorkServer-<版本号>.tar.gz`。版本号与同一 Release 中的编辑器正式包一致，例如编辑器 `1.0.0` 对应 `LudorkServer-1.0.0.tar.gz`。临时 CI 产物名为 `LudorkServer-<40位Server提交SHA>.tar.gz`。

所有开发版、正式版编辑器包也附带同一份可部署归档，包括不含项目模板的包。Windows 中位于编辑器目录下的 `Server/LudorkServer.tar.gz`；macOS 中位于 `Ludork.app/Contents/Resources/Server/LudorkServer.tar.gz`。将此归档复制到独立的部署位置。安装或运行编辑器不会启动服务端。

归档的 `LudorkServer/` 目录包含编译后的后端 JavaScript、生产版管理网站、Lua 模块与声明、部署／启动脚本以及锁定的生产依赖清单，不含已安装的 `node_modules`、项目凭据或用户数据。在 Linux 上解压并进入目录：

```sh
tar -xzf LudorkServer-1.0.0.tar.gz
cd LudorkServer
```

如需自行从 `Server` 分支构建，安装 Node.js 24，在该源码目录运行 `npm ci` 和 `npm run build`，再将 `dist/LudorkServer` 复制到独立部署目录。构建会编译后端，并通过 Vite 构建管理网站。源码目录中的 deploy/start 命令会拒绝执行，应部署构建后的目录。若输出中已有 `config/`、`data/`、`projects/` 或 `logs/`，重新构建会拒绝替换；因此部署实例应放在 `dist/LudorkServer` 之外。源码开发说明见 [Server README](https://github.com/JasonLeon01/Ludork/blob/Server/README.md)。

## 部署与启动

在服务器安装 **Node.js 24 和 npm**，然后在解压后的目录执行：

```sh
sh deploy.sh MyGame 'project-key' 'management-password'
sh start.sh
```

Windows 命令提示符使用等价脚本：

```bat
deploy.bat MyGame "project-key" "management-password"
start.bat
```

三个部署参数依次是项目名、项目密钥、管理密码。请按当前 shell 的规则加引号和转义，尤其注意 `$`、`%`、`!`、`&` 和引号。参数可能留在 shell 历史与进程参数中，不要把真实凭据写进版本管理的脚本。

部署会运行 `npm ci --omit=dev` 安装锁定的生产依赖，保存凭据散列并创建项目 Lua 入口，不编译后端或重新构建网站。固定版本的 Wasmoon 依赖包含 Lua 5.4.5 WebAssembly 运行时，无需安装系统 Lua 或原生编译器。Node.js 在 7777 端口运行编译后的后端，在 3333 端口提供已构建的管理网站。start 同时启动两个服务；任一端口被占用时失败，子进程异常退出时停止另一个服务。Ctrl+C 停止两者。部署不安装系统服务，也不配置开机自启。

| 用途 | 地址 |
|---|---|
| 管理网页 | `http://IP:3333/MyGame/` |
| 游戏客户端 URL | `http://IP:7777/MyGame` |
| 派生的 WebSocket 地址 | `ws://IP:7777/MyGame/api/v1/net` |

同一服务实例的所有项目共用 **3333** 和 **7777** 端口。使用另一个项目名再次执行 deploy 可添加项目；以同名部署会修改凭据，并保留数据、Lua 源码和项目设置。请顺序执行部署，重新安装依赖时先停止实例，随后重启以载入配置或 Lua 源码变更。各项目的密钥、密码、数据、Lua 进程和管理会话互相独立。

IP 地址、`localhost` 及其子域名可直接访问。使用其他域名访问管理网站时，启动前设置 `LUDORK_ALLOWED_HOSTS=games.example.com`；多个允许的主机名用逗号分隔，不包含协议或端口，按名称精确匹配。DNS、网络和防火墙访问需要自行配置。

项目名为 1–64 个 UTF-8 字节，不含控制字符、`/`、`\`，也不能是完整的 `.` 或 `..`。在 URL 中将整个项目名编码成一个路径段，支持中文项目名。密钥为 1–4096 个不含空格的 ASCII 可见字符；密码为 1–4096 个不含控制字符的 UTF-8 字节。不提供默认凭据。

## 项目 Lua 入口

部署创建 `projects/<项目名十六进制>/Main.lua`，初始注册 `Modules.Storage`。目录名为项目名 UTF-8 字节的小写十六进制编码，部署会输出准确路径。项目自己的 Lua 模块放在这里；框架模块从 `lua/` 加载，业务模块从此私有目录加载。项目源码不会发送给游戏客户端，也不会由管理网站提供。

`config/projects.json` 中每个项目对象可设置 `luaEntry`，默认为 `Main.lua`。它是项目目录内的相对 `.lua` 文件路径，目录之间使用 `/`；不接受绝对路径、空路径段、`.`／`..`、反斜杠、冒号或控制字符，最多 512 个 UTF-8 字节。重新部署保留该设置和已有入口文件。源码或入口路径变化后须重启。

服务端使用普通 Lua 5.4，没有客户端 Standard、`Engine` 或 `GlobalCore` 模块。公开声明位于 `lua/stub`，配有独立的服务端 `.emmyrc.json`；运行时排除声明文件与 `stub` 目录。模块注册、context 服务与执行限制见[服务端 Lua 模块](<HTTP 协议.md#服务端-lua-模块>)。

## 配置写入间隔

每个项目在 `config/projects.json` 中都有 `ipWriteIntervalSeconds` 字段，示例项目位于 `projects["MyGame"]` 下。新部署默认写入 **180 秒**，省略该字段时也使用 180。请在现有项目对象中修改此字段，保留凭据散列和其他项目：

```json
{"ipWriteIntervalSeconds":180}
```

这是项目对象的片段，不是完整配置文件。设为 `0` 表示关闭此间隔；也可设为不超过 `9007199254740991` 的非负整数，使用其他间隔。不接受小数、字符串、null 或负数。重新部署项目会保留已有间隔和数据。**编辑设置后必须重启服务器**，当前进程不会自动重新加载。

间隔只用于随附的 `Storage.WriteField` RPC，同一 TCP 客户端 IP 对同一项目的此类写入共用间隔。自定义 RPC 实现自己的业务规则，不继承此限制。同一 NAT 或反向代理后的用户可能共用额度，不同项目相互独立。

准入、失败与重启规则见[写入限频](<HTTP 协议.md#写入限频>)；结果不确定时的处理见 [RPC 生命周期](<原生客户端 API.md#调用-rpc-与接收事件>)。

## 配置开发环境客户端

在 C++ Source 工程中打开 **Game → 设置测试服务器**，勾选启用并填写测试 URL 与密钥。初始 URL 为 `http://localhost:7777/<工程目录名>`，目录名会经过 URL 编码。确认后保存，取消不会改变已保存的配置。该窗口只配置客户端；测试服务器仍需自行部署与启动。

Windows 与 macOS 的本机配置位于 `~/Ludork/.localserver/<工程目录名>/test.json`，从仓库运行时也相同。`~` 表示当前用户的主目录。

```json
{
  "enabled": true,
  "url": "http://localhost:7777/MyGame",
  "key": "test-project-key"
}
```

这是本机设置，包含明文测试密钥，由 Git 忽略，不写入 `Main.proj` 或 Lua。目录名相同的工程会共用这一设置位置。文件不存在或 `enabled: false` 时禁用集成。

**Construct** 构建 Debug，**Play** 运行 Debug。有效配置变化后需要重新构建原生代码，可重新 Construct 或接受 Build and Play。Debug 构建通过 `LUDORK_SERVER_CONFIG_FILE` 读取本机配置文件。

## 配置发行客户端

在 **文件 → 打包项目** 中勾选 **启用 Ludork 服务器**，填写正式 URL 与密钥。每次重新打开打包窗口都默认关闭、输入框为空，不缓存正式配置，也不从测试配置复制。URL 使用 `http://主机:7777/项目名`，不追加 `/api/v1`，不含用户名、查询参数或片段。当前客户端集成不支持 HTTPS。

[Standalone 工程转换](<../编辑器用户指南/运行、调试与打包.md#将-source-转换为-standalone-工程>)也提供同样的可选 Release 配置。生成的可编辑工程保留已编译的连接信息；若要修改，须重新从 Source 构建。

打包始终构建 **Release**，包括标记为 dev 的内部测试包。Release 忽略 `LUDORK_SERVER_CONFIG_FILE`。命令行打包或 CI 通过当前进程环境提供 `LUDORK_SERVER_ENABLED=1`、`LUDORK_SERVER_URL`、`LUDORK_SERVER_KEY`；未启用或设置为 `0` 时禁用。正式值应从自己的密钥存储读取，不要把字面量写入版本管理的命令。

例如，在 GitHub Actions 中配置这两个仓库 secret 后，将以下环境变量附加到现有的游戏打包步骤。这份 Windows 示例使用已有打包命令，不要输出 secret 值：

```yaml
- name: Package game
  shell: cmd
  env:
    LUDORK_SERVER_ENABLED: '1'
    LUDORK_SERVER_URL: ${{ secrets.LUDORK_SERVER_URL }}
    LUDORK_SERVER_KEY: ${{ secrets.LUDORK_SERVER_KEY }}
  run: tools\pack_project.bat --release Game
```

启用时，构建会定义 `LUDORK_SERVER_AVAILABLE`，并编译包含 URL 和密钥的传输代码。禁用时网络 API 仍可调用：`Global.Net` 报告字符串错误码 `Disabled`，原生健康检测使用 `ServerErrorCode.Disabled`。最终二进制包含联网所需的凭据。

## 管理与运行边界

打开网页后同时输入项目密钥与管理密码。网页支持账号筛选、分类选择、带类型的 Lua 数据展示、刷新与退出登录，包括精确整数和转义字节字符串。Cookie 作用域与会话有效期见[只读管理](<HTTP 协议.md#http-健康检测与只读管理>)。

生成的 `config/`、私有 `projects/` Lua 源码、用户 `data/`、日志和已安装依赖不进入分发的服务端包。请自行备份 `config/`、`projects/` 和 `data/`，并限制其本机访问权限。后端持有数据目录实例锁；记录的进程已退出时可自动回收旧锁。若锁不完整或 PID 已被复用，应先确认没有实例运行，再手动删除 `data/.server.lock`。

请在可信网络使用：**HTTP 和 WebSocket 明文传输凭据与数据**。共享项目密钥可以访问项目注册的模块；账号 ID 是存储命名空间，不代表独立认证的用户。分发的客户端二进制中的密钥可以被提取。项目 Lua 须自行实施账号授权与业务规则。网络访问限制或独立代理属于部署方职责；此项目不提供 TLS 配置或账号认证系统。

继续阅读[原生客户端 API](<原生客户端 API.md>)和[服务端 Lua 与协议](<HTTP 协议.md>)。

# 简易服务器：部署与编辑器设置

Ludork Server 是可选的 HTTP 数据存储服务。每个项目包含多个账号，每个账号包含多个数据大类文件，每个文件是 JSON 字典。React/TypeScript 管理网页用于列出账号、文件并查看内容，只提供只读操作。服务器不提供联机同步或 RPC，也不会替代游戏的本地存档系统。

后端和前端部署在服务器或独立测试实例上。游戏客户端只需要服务器 URL 和项目密钥，不安装 Node.js，也不部署服务端。客户端集成仅支持 **C++ Source** 工程；Standalone 不显示两处服务器配置入口。

## 获取源码

打开 [Ludork Releases](https://github.com/JasonLeon01/Ludork/releases)，在对应 Release 的 **Assets** 中下载随版本附带的 `LudorkServer-source-<版本号>.zip`。版本号与同一 Release 中的编辑器正式包一致，例如编辑器 `1.0.0` 对应 `LudorkServer-source-1.0.0.zip`。

源码包包含后端、前端和部署脚本。将其解压到服务器，进入解压后的目录，按下方步骤部署即可。

## 部署与启动

在服务器安装 **Node.js 24 和 npm**，然后在解压后的目录执行：

```sh
sh deploy.sh MyGame 'project-key' 'management-password'
sh start.sh
```

Windows 命令提示符使用等价脚本：

```bat
deploy.bat MyGame "project-key" "management-password"
start.bat
```

三个部署参数依次是项目名、项目密钥、管理密码。请按当前 shell 的规则加引号和转义，尤其注意 `$`、`%`、`!`、`&` 和引号。参数可能留在 shell 历史与进程参数中，不要把真实凭据写进版本管理的脚本。

部署会运行 `npm ci`，保存凭据散列并生成 start 脚本。Node.js 直接运行后端 TypeScript，Vite 运行 React/TypeScript 前端，**不进行前端生产构建**。start 同时启动两个服务；任一端口被占用时失败，子进程异常退出时停止另一个服务。Ctrl+C 停止两者。部署不安装系统服务，也不配置开机自启。

| 用途 | 地址 |
|---|---|
| 管理网页 | `http://IP:3333/MyGame/` |
| 游戏客户端 URL | `http://IP:7777/MyGame` |

同一服务实例的所有项目共用 **3333** 和 **7777** 端口。使用另一个项目名再次执行 deploy 可添加项目；以同名部署会修改凭据并保留数据。请顺序执行部署，重新安装依赖时先停止实例，随后重启以载入配置变更。各项目的密钥、密码、数据、token 和管理会话互相独立。

IP 地址可直接访问。使用域名访问 Vite 时，启动前设置 `LUDORK_ALLOWED_HOSTS=games.example.com`；多个允许的主机名用逗号分隔，不包含协议或端口。DNS、网络和防火墙访问需要自行配置。

项目名为 1–64 个 UTF-8 字节，不含控制字符、`/`、`\`，也不能是完整的 `.` 或 `..`。在 URL 中将整个项目名编码成一个路径段，支持中文项目名。密钥为 1–4096 个不含空格的 ASCII 可见字符；密码为 1–4096 个不含控制字符的 UTF-8 字节。不提供默认凭据。

## 配置写入间隔

每个项目在 `config/projects.json` 中都有 `ipWriteIntervalSeconds` 字段，示例项目位于 `projects["MyGame"]` 下。新部署默认写入 **180 秒**，省略该字段时也使用 180。请在现有项目对象中修改此字段，保留凭据散列和其他项目：

```json
{"ipWriteIntervalSeconds":180}
```

这是项目对象的片段，不是完整配置文件。设为 `0` 表示不限写入频率；也可设为不超过 `9007199254740991` 的非负整数，使用其他间隔。不接受小数、字符串、null 或负数。重新部署项目会保留已有间隔和数据。**编辑设置后必须重启服务器**，当前进程不会自动重新加载。

同一 TCP 客户端 IP 对同一项目的全部账号和分类共用写入间隔。IPv4 映射的 IPv6 地址会统一处理，忽略 `X-Forwarded-For`，因此同一 NAT 或反向代理后的用户可能共用写入额度；不同项目的额度相互独立。读取、列表查询、申请 token 和管理请求不占用额度。

通过参数校验和认证、获准执行的写入会在存储前开始计时，后续存储失败仍占用额度。准入前被拒绝的请求不开始计时，HTTP 429 也不延长已有间隔。截止时间只保存在内存，重启后清空。被限频的写入会消费有效 token，应等待 `retryAfterSeconds` 后再申请新 token 重试。参见 [HTTP 限频响应](<HTTP 协议.md#写入限频>)与[原生结果处理](<原生客户端 API.md#token-与超时>)。

## 配置测试客户端

在 C++ Source 工程中打开 **Game → 设置测试服务器**，勾选启用并填写测试 URL 与密钥。初始 URL 为 `http://localhost:7777/<工程目录名>`，目录名会经过 URL 编码。确认后保存，取消不会改变已保存的配置。该窗口只配置客户端；测试服务器仍需自行部署与启动。

本机配置位置：

- Windows：与 `Ludork.ini` 同级的 `.localserver/<工程目录名>/test.json`。
- 其他编辑器平台：`~/Ludork/.localserver/<工程目录名>/test.json`。

```json
{
  "enabled": true,
  "url": "http://localhost:7777/MyGame",
  "key": "test-project-key"
}
```

这是本机设置，包含明文测试密钥，由 Git 忽略，不写入 `Main.proj` 或 Lua。目录名相同的工程会共用这一设置位置。文件不存在或 `enabled: false` 时禁用集成。

**Construct** 构建 Debug，**Play** 运行 Debug。有效测试配置变化会使原生构建过期，需要重新 Construct 或接受 Build and Play。Debug 构建与构建状态检查通过 `LUDORK_SERVER_CONFIG_FILE` 读取该文件；预热的检查进程也会在每次检查时读取当前内容。

## 配置发行客户端

在 **文件 → 打包项目** 中勾选 **启用 Ludork 服务器**，填写正式 URL 与密钥。每次重新打开打包窗口都默认关闭、输入框为空，不缓存正式配置，也不从测试配置复制。URL 使用 `http://主机:7777/项目名`，不追加 `/api/v1`，不含用户名、查询参数或片段。当前客户端集成不支持 HTTPS。

打包始终构建 **Release**，包括标记为 dev 的内部测试包。Release 忽略 `LUDORK_SERVER_CONFIG_FILE`。命令行打包或 CI 通过当前进程环境提供 `LUDORK_SERVER_ENABLED=1`、`LUDORK_SERVER_URL`、`LUDORK_SERVER_KEY`；未启用或设置为 `0` 时禁用。正式值应从自己的密钥存储读取，不要把字面量写入版本管理的命令。

例如，在 GitHub Actions 中配置这两个仓库 secret 后，将以下环境变量附加到现有的游戏打包步骤。这份 Windows 示例使用已有打包命令，不要输出 secret 值：

```yaml
- name: Package game
  shell: cmd
  env:
    LUDORK_SERVER_ENABLED: '1'
    LUDORK_SERVER_URL: ${{ secrets.LUDORK_SERVER_URL }}
    LUDORK_SERVER_KEY: ${{ secrets.LUDORK_SERVER_KEY }}
  run: tools\pack_project.bat --release Game
```

启用时定义 `LUDORK_SERVER_AVAILABLE`，并编译带有 URL/密钥的传输实现。禁用时不定义宏，跳过网络实现；Lua 入口仍存在，会输出未启用提示，并以 `ServerErrorCode.Disabled` 完成。打包执行结束后会清理生成的 Release 配置头，编辑器取消时也会清理。最终二进制必然包含联网所需的凭据。

## 管理与运行边界

打开网页后同时输入项目密钥与管理密码。网页支持账号筛选、文件选择、JSON 展示、刷新与退出登录。会话使用各项目独立的 HttpOnly、SameSite=Strict Cookie，八小时后过期，后端重启后失效。

生成的 `config/`、用户 `data/`、日志、依赖与 start 脚本不进入源码归档。请自行备份 `config/` 和 `data/`，并限制其本机访问权限。后端持有数据目录实例锁；记录的进程已退出时可自动回收旧锁。若锁不完整或 PID 已被复用，应先确认没有实例运行，再手动删除 `data/.server.lock`。

请在可信网络使用：**HTTP 明文传输凭据与数据**。共享项目密钥可以访问该项目的所有账号；账号 ID 是存储命名空间，不代表独立认证的用户。分发的客户端二进制中的密钥可以被提取。一次性 token 限制重放，但不能让不可信客户端成为可信数据来源。网络访问限制或独立代理属于部署方职责；此项目不提供 TLS 配置或账号认证系统。

继续阅读[原生客户端 API](<原生客户端 API.md>)和 [HTTP 协议](<HTTP 协议.md>)。

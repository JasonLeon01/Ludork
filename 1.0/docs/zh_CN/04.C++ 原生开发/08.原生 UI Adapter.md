# 原生 UI Adapter

## 目标

把原生控件加入 Ludork 声明式 UI 契约，让运行时、preview host 与编辑器的实时 Control Registry 对同一个控件给出相同描述。

## 前置条件

- 一个 C++ Source 项目。
- 一个原生控件类型，以及用于构造、属性赋值、测量、排布与挂载子控件的通用 adapter 操作。
- 已了解[声明式 UI 运行时契约](<../03.Lua 与蓝图脚本/04.声明式 UI/02.运行时契约.md>)。

## Descriptor 契约

系统控件描述定义在 `Engine/Source/Core/include/UI/UiControlAdapterDescriptors.hpp` 中，使用私有 `BIND_UI_CONTROL` X-macro，而不是 Core bindgen 注解。其逻辑签名为：

```cpp
BIND_UI_CONTROL(TAG, CONTROL_ID, ADAPTER, DISPLAY_NAME, CATEGORY,
                CHILD_POLICY, SLOT_TYPE, ...PROPERTIES)
```

| 参数 | 含义 |
|---|---|
| `TAG` | 用于特化 `UiControlAdapterTraits` 的唯一 C++ tag |
| `CONTROL_ID` | 稳定的系统控件序列化标识符；使用原生类的规范模块根路径 |
| `ADAPTER` | 运行时 adapter 标识符；使用同一条规范模块根路径 |
| `DISPLAY_NAME` | Palette 标签 |
| `CATEGORY` | Palette 分类 |
| `CHILD_POLICY` | `UiChildPolicy::None`、`Single` 或 `Multiple` |
| `SLOT_TYPE` | `UiControlSlotType::None`、`Canvas` 或 `List` |
| `...PROPERTIES` | 一个或多个属性 descriptor |

属性使用三种 descriptor 宏之一。`UI_CONTROL_COMMON_PROPERTY` 适用于所有控件。`UI_CONTROL_PROPERTY` 会被写入并由运行时 adapter 消费。`UI_CONTROL_EDITOR_PROPERTY` 只对编辑器或 preview 可用。每个宏接收 `(ID, DISPLAY_NAME, TYPE, REQUIRED, DEFAULT_JSON)`。纯文本控件使用 `UI_CONTROL_PLAIN_TEXT_PROPERTIES(DEFAULT_SIZE)`，富文本控件使用 `UI_CONTROL_RICH_TEXT_PROPERTIES`。这些属性组同时决定编辑器与打包校验所期望的 TextConfig 类型。

导出 descriptor 之前，原生 registry 会校验 ID、属性类型与默认值、属性职责以及 adapter 注册情况。

系统控件的两个路径字段必须完全相同。因此 Engine 中绑定的 `Canvas` 在 `CONTROL_ID` 与 `ADAPTER` 上都使用 `Engine.Canvas`。嵌套或缩写标识符无效。

资产 JSON 按 `RuntimeData` 读取，每个属性再经其 descriptor 解码为 `UiControlPropertyValue`。工厂函数收到由此得到的 `UiControlProperties` 字典，setter 收到单个带类型的属性值。

Image 的 `drawAs` 使用绑定的 C++ `Image::DrawAs` 枚举，导出名为 `Engine.ImageDrawAs`。JSON 保存成员名，原生解码和运行时 setter 则传递枚举本身。因此，运行时调用 `AssetInstance:setProperty` 时传入 `Engine.ImageDrawAs.Tile`。解码器、属性值 variant、检查器的枚举下拉框、ScriptTools 校验与生成声明必须保持一致。

`Engine.WrapBox` 声明 `UiChildPolicy::Single` 和 List Slot。唯一的作者子节点是实例化模板，而非所有重复项共用的单个控件对象。原生资产构造负责创建各份重复子树，每份子树拥有独立实例边界，生成 View 在边界处停止展开。修改数量时追加或释放尾部实例，普通排布保留已有实例。预览为每份重复项提供对应作者模板节点的身份，因此选中或编辑任一重复项时仍指向唯一模板。

## 步骤

1. 实现原生控件。
2. 在 `LUDORK_UI_CONTROL_DEFINITIONS` 中增加一条 `BIND_UI_CONTROL`。选择稳定的 control ID，并准确写明 child policy 与 Slot type。
3. 用现有的受支持类型与资源处理方式声明属性。新增属性类型还需要同步改动原生解码器、编辑器与 ScriptTools。
4. 在 `UiControlAdapterRegistry` 中注册 tag，提供 descriptor 所需的 factory、setter、arranger 与 child 函数。Registry 会从 descriptor 复制 adapter 属性 ID。
5. 用平台的 `tools/build_cpp` 入口构建 C++ 项目，以更新 Host 与 registry 并校验 UI 资产。属性类型受支持的控件无须重建编辑器或 ScriptTools。
6. 需要单独校验时，运行：

   ```bash
   ScriptTools ui-adapter-check <project-root>
   ScriptTools ui-assets validate <project-root>
   ```

   `ui-adapter-check` 将 registry 与对应 Host 编译出的描述做比较，不改动任何文件。

7. 在 UI Asset Editor 中打开一个有代表性的资产，验证渲染与交互。

`Engine.TabView` 是无子节点的 Input 示例：只序列化构造与视觉资源，标签与 callback 在运行时绑定。细节见 [UI 资产 Schema 与 Control Registry](<../03.Lua 与蓝图脚本/04.声明式 UI/04.资产 Schema 与 Control Registry.md>)与 [Engine：交互与声明式 UI 控件](<../03.Lua 与蓝图脚本/08.全局与 Core 模块/02.Core Modules/01.Engine/13.交互与声明式 UI 控件.md>)。

`Engine.CharacterView` 是无子节点的动画 Visual 示例。其 adapter 依据 `size`、纹理/Rect、Actor 缩放、动画、Shader 与 Hue 属性构造原生预览状态。裁切、逐帧推进与特效合成由控件类负责，资源路径转换与属性赋值则由 adapter 负责。

## 项目预览产物

每个项目使用自己的 Host。`EditorCache/UiPreview.json` 指定项目相对的运行目录：源码构建为 `bin/<configuration>`，Standalone 为 `Binaries`。编译出的 `UiPreviewHost --describe` 提供 `EditorCache/UiPreview.registry.json`，供编辑器与 ScriptTools 共用。

源码构建在编译前断开已有的预览连接。配套 Host 与 registry 成功发布之前，预览一直不可用，因此 C++ UI 改动必须重新构建。此后即使 UI 资产校验失败，新预览仍然保留，便于修正资产。Standalone 可以用 `ui-preview ensure` 从随附的 Host 恢复缺失的 JSON。损坏或不匹配的产物会被拒绝。

## 限制

原生控件必须通过项目自己的 Core UI 源码与 adapter 注册加入，并且满足预览运行时的依赖边界。编辑器插件无法通过 palette 注册它们。`UiChildPolicy::None` 的控件不能包含子控件，`Single` 最多接受一个子控件。

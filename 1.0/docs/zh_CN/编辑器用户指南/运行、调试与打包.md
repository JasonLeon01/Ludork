# 运行、调试与打包

运行项目、调整运行中的游戏状态，并为目标平台生成发行包。

## 编译、导出与运行

工具栏按钮按 **编译 → 导出 → 运行** 排列，Standalone 项目隐藏编译按钮。**编译** 保存项目并构建 Debug 游戏程序与预览运行时，完成后不启动游戏。原生绑定仍随构建生成，UI、本地化与材质运行文件则通过独立的导出操作生成。

预览运行时的准备方式见 [PreviewHost：构建、发布与排错](<../PreviewHost/构建、发布与排错.md>)。

**导出**会保存项目、执行导出插件 Hook，并生成 UI View、声明、语言文件和[材质程序](<材质.md#导出运行文件>)。材质检查覆盖材质、地图、图块集、自动图块和可选的 `MaterialExport.json` 的新增、修改、移动与删除，已发布的原生编译器／预览运行时身份，以及生成文件的缺失或内容变化；发生这些变化后需要重新导出。所有需要的材质组合编译成功后，才会统一安装文件并删除废弃产物。导出失败或取消不计为成功导出。

变量与通用数据仍在保存时生效，其 Lua 文件继续受版本管理，不属于导出范围。普通保存、编译、直接运行和模板创建不生成 UI 或材质运行文件。显式 `ui-assets generate` 命令只生成 UI 文件，不执行 Export Hook，也不发布完整的编辑器导出记录。

首次成功导出后才可运行。C++ Source 项目还需要通过**编译**或 `tools/build_cpp` 完成一次 Debug 构建；直接执行 CMake 构建不会启用运行按钮。

打开 C++ Source 项目时，编辑器先检查生成的原生绑定、构建与预览文件，以及 UI、材质和插件导出文件，再校验项目数据。如果缺少这些文件或准备记录，会自动执行 Debug 编译和导出。进度对话框显示当前操作，完整输出保存在 `Log/Ludork.log`。这一步直接构建和导出磁盘上的文件，不会保存尚未完整加载的项目数据。

如果生成文件存在，但 Blueprint 字段或地图中的 Actor 覆盖属性未通过 schema 校验，编辑器会询问是否**重新构建并导出工程**。确认后重新编译、导出，再从磁盘加载并检查一次；取消则退出程序。如果仍有错误，使用通常的数据无效对话框报告，不会重复询问重建。单纯的 JSON 语法错误不会触发此修复流程。

编译或导出失败会停止打开项目，并报告日志路径。仅修改源码不会在打开项目时自动触发编译。删除 `EditorCache` 后，C++ Source 项目会在下次打开时重新准备；Standalone 项目仍需手动导出后才能运行。

首次编译和导出成功后，如果相关文件发生变化，运行时会提示**编译并运行**或**导出并运行**。取消或失败都会终止启动。Lua、UI JSON、游戏数据和本地化内容的修改不需要重新编译原生代码。

运行准备期间与游戏运行中，该按钮变为 **停止**，点击可取消准备或停止当前进程。编译与导出期间禁止重复操作和项目编辑。游戏自然退出、取消和失败都会恢复编辑，关闭项目会取消活动中的准备操作。

上述操作保持当前标签页，需要时手动打开**控制台**查看日志。

**独立窗口** 使用单独的游戏窗口，并保留编辑器中当前地图或大地图的画面。准备、编译与导出期间，项目编辑、已打开的文档窗口、撤销/重做及编辑快捷键均不可用。运行时默认保持这些限制；只有在运行前开启 **实时调试**，才按下文规则开放临时编辑。控制台、性能监视器与帮助仍可使用。嵌入模式则在编辑器内部显示 Windows 运行时，并锁定游戏视口布局。只有 Windows 可以配置这一窗口选择，其他平台始终使用独立窗口。Windows 上无法取得嵌入句柄时，会以 `EmbeddedHandleUnavailable` 失败。

操作对话框和控制台报告失败。导出失败会阻止运行或打包继续；先修复首个校验、Hook 或生成错误，再重新导出。

## 服务器连接

C++ Source 项目通过**游戏 → 测试服务器设置**配置本地开发连接，之后重新编译 Debug。**打包项目 → 启用 Ludork Server** 单独配置 Release 连接，每次打开时均为空；dev 包也使用 Release 连接。Standalone 项目不显示这两个选项。部署和连接设置见[简易服务器](<../简易服务器/部署与编辑器设置.md>)。

## 实时调试

运行前开启 **编辑 → 开发工具与设置 → 实时调试**，即可从编辑器修改正在运行的地图。该项目偏好默认关闭，准备或运行期间不能修改。它仅适用于 **独立窗口**；切换到嵌入模式会将其清除并禁用。准备、编译与导出仍保持原有编辑锁定。

游戏运行后，编辑器跟随玩家所在的普通地图或组合式大地图中的当前子地图，禁止手动切换地图。大地图空洞、尚未加载完成的地图、没有存活玩家的场景，以及连接不可用时均为只读。**文件浏览器** 可以浏览和定位资源，但项目文件的新建、重命名、移动、删除以及文档编辑仍被禁止。

实时视口的显示规则见[地图与世界预览](<../PreviewHost/地图与世界预览.md#视口选项>)，编辑权限仍以下文为准。

在已有的可编辑图层上，实时调试允许：

- 使用与[项目地图编辑](<图块集、自动图块与地图.md#图层与绘制>)相同的图块画笔：绘制、擦除、取样和填充。图层结构、显隐、图块集绑定、地图属性及大地图摆放保持锁定。
- 选中和删除存活 Actor，包括玩家、运行时生成的 Actor 与子 Actor，并移动顶层 Actor。编辑器不能新增、粘贴或复制 Actor。
- 查看 **角色信息** 并修改普通变量，包括内层类型受支持的 `Optional[T]`。Optional 值允许为 `nil`，非 nil 值仍须符合声明类型。**组件**、父类、蓝图身份和地图 tag 保持只读。

Actor 的位置、生成、销毁以及所查看的变量值会随游戏更新。移动 Actor 会取消其当前移动路线；删除使用正常 Actor 销毁及既有生命周期回调。隐藏 Actor 按[地图预览规则](<../PreviewHost/地图与世界预览.md#actor-与图层辅助显示>)保留检查能力，隐藏图层仍只读。实时编辑不支持撤销/重做，不写入项目文档，也不会把项目数据标为已修改。

**世界大纲** 将子 Actor 嵌套在其当前父 Actor 下。在地图上单击或拖动子 Actor，会选中其所属的顶层 Actor；拖动时由该顶层对象带着全部后代一起移动。可在 **世界大纲** 中单独选择子 Actor，检查或修改普通变量，或通过正常生命周期删除它。禁止直接移动子 Actor，包括修改 **角色信息** 中的坐标。

修改属于存活的 Actor 或地图实例。只要同一实例仍存在，修改就会保留，包括大地图的休眠实例；销毁、换图或卸载之后，不会向重建实例重放这些修改。重建使用项目定义和正常玩法持久化记录。游戏存档保持正常工作，可能保存受到实时编辑影响的玩法状态；此模式保护项目源数据，不隔离存档槽。

点击停止、游戏自然退出或启动失败后，会恢复项目地图视图和运行前选中的地图，并丢弃临时快照。焦点位于编辑器时，**独立窗口** 中的游戏仍继续运行。

## 运行中重载 Lua

在外部编辑器保存改动过的 Lua 源文件，在控制台输入 `$r`，再按 `Enter` 或点击 **发送**。这会更新已有函数，同时保留场景、对象和运行时状态。游戏必须由编辑器启动，并使用散放的 Lua 源文件。

控制台会报告结果。数据或模块结构的变化可能需要重启；支持的改动范围与失败处理见 [Lua 热更新](<../Lua 与蓝图脚本/Lua 运行时与模块.md#lua-热更新>)。

## 打包

选择 **文件 → 打包项目**，从左侧列表选择可用平台。Windows 上提供 Windows；macOS 上提供 macOS。macOS 上的 C++ Source 项目还提供 iOS，检测到 DevEco Studio 时提供 HarmonyOS，检测到 Android Studio 时提供 Android。

右侧首先显示所选平台的选项，随后是发行版本、服务器、加密和归档等通用设置。勾选签名后，签名表单显示在右侧内容的最下方，与上方选项之间用横线分隔。切换平台会保留当前窗口中已填写的内容，确认时只采用所选平台的设置。点击窗口底部的 **确认** 即开始打包，可在日志中查看进度。

项目必须有有效的入口脚本和兼容的模板。在 `Scripts/Entry.lua` 顶层只定义一个 `local APP_NAME`，赋值为非空的静态字符串字面量，使用该游戏专用的名称，不包含控制字符，也不在之后重新赋值。打包窗口打开或重新获得焦点时会检查名称。如果仍为 `LudorkSample`，**确认** 按钮会置灰；只有将鼠标悬停在该按钮上时，才会提示修改 `Scripts/Entry.lua` 中的 `APP_NAME`。定义缺失或不合法时，包括使用需要执行 Lua 才能确定名称的表达式，也会禁用确认，原因同样通过悬停提示查看。

如果打包提示输出路径访问被拒绝，请关闭仍在运行的发行包以及打开输出目录的文件资源管理器窗口，再重试。语言服务或杀毒软件也可能占用生成文件。

编辑器要求签名材料使用绝对路径，且路径不得包含 NUL、回车或换行符。签名表单在接受路径前检查文件是否可读；读取或保存凭据时也会校验其 keystore 或证书路径。签名别名和密码同样不得包含 NUL、回车或换行符。

移动端和 macOS 的应用显示名称使用 `Data/Configs/System.json` 中 `title.value` 的原始文本。标题必须非空且不包含控制字符，打包不解析本地化键。`APP_NAME` 用于生成稳定的 application ID、bundle identifier，以及符合文件名要求的 `<game-name>`。修改标题或版本不改变应用标识；修改 `APP_NAME` 可能需要重新配置签名或描述文件。

编辑器每次打包都会先完整导出一次，包括 Export Hook、UI 与材质生成，成功后继续执行 before-Pack Hook 和打包。Official Locale Tools 的 before-Pack Hook 只排除 `Data/Locale/Locale.xlsx`。直接命令行运行或打包会读取预先导出的文件，并拒绝缺失、被修改或已过期的材质产物，不执行完整导出或隐式生成。`ScriptTools material-assets validate <project-root>` 可单独执行材质检查，不会写入文件。GLSL 可以由 Debug 导出，再用于 Release 或其他目标平台的打包；命令行校验不要求与导出机器的预览构建身份一致。

**加密游戏数据** 控制脚本编译，以及 shader、JSON 和存档加密；只勾选其中一部分时，复选框显示为不确定状态。**加密存档内容** 设置 C++ Source 运行时的默认值。Standalone 项目通过 `Scripts/Entry.lua` 中的 `SAVE_AS_LDC` 配置它；生效时机与格式规则见[存档](<../Lua 与蓝图脚本/Game 玩法/运行时数据、配置与存档.md#存档>)。`.ldpak` 选项与加密相互独立。数据加密会将暂存副本中的 JSON 值转换为经过压缩与混淆的二进制 `.ldc`，源 JSON 仍可编辑。使用旧压缩 JSON 载荷 LDC 格式的包须重新打包。

着色器加密覆盖 `Assets/Shaders`，包括其中的 `Assets/Shaders/MaterialGenerated`。数据加密同时处理普通 Data JSON 和生成的材质运行元数据，两者使用相同的 `.ldc` 格式。选择 `.ldpak` 后，生成的运行文件写入 `Assets.ldpak`。打包会将可选的 `MaterialExport.json` 携带至暂存目录完成材质校验，再在加密和归档前移除它以及材质生成目录根部的 `export.json` 记录。这两份编写／校验文件及加密后的 `export.ldc` 都不会进入游戏包，源项目仍保留原文件。游戏发行包仍保留 `Data/Materials` 下的源文件，运行时材质加载使用生成的着色器、`resource.json` 和 `program.json`。

预览注册表校验及排除规则见 [PreviewHost 游戏成品规则](<../PreviewHost/构建、发布与排错.md#可编辑模板与游戏成品>)。

打包只处理暂存副本，不改动项目源文件。产物会移除开发文件、项目根目录的 `EditorCache`/`Cache`，以及 UI 中仅供设计使用的 `editor` 数据。无论 Data 采用 JSON、加密 `.ldc` 还是归档，UI 资产标识均不带扩展名，Controller 引用均保留 Lua 逻辑模块路径。位于 `Assets`、`Data` 或 `Scripts` 内部的同名 `EditorCache`、`Cache` 目录仍作为普通项目内容保留。

### 发行包与开发包

在打包窗口设置 **发行版本**。C++ Source 项目还会显示 **内部测试包（dev）**。窗口读取 `Main.proj` 的 `packaging.version`，并对 C++ Source 项目读取 `packaging.dev`，默认值分别为 `"1.0.0"`、`false`。确认有效参数后保存版本及适用的 dev 设置，取消不写入。Standalone 项目始终保存 `packaging.dev=false`，包括旧项目原先为 `true` 的情况。版本使用 `1.0.0` 或 `0.1.0` 这样的三段非负十进制整数，总长度不超过 127 字节，不允许 `v` 前缀、前导零、日期或预发布后缀；发行版本不在 Entry 中定义。

所有游戏打包命令均接受 `--version 1.0.0` 和 `--release`。C++ Source 项目还接受 `--dev`；传入渠道选项只在本次打包覆盖 `packaging.dev`。Standalone 项目始终按正式版打包，忽略旧配置中的 `packaging.dev=true`，并拒绝显式传入的 `--dev`。命令行不回写项目配置。

正式包使用基础版本号。dev 包按打包开始时的 UTC+8 时间追加 `YYYYMMDDHH`，例如在 `2026-01-01T07:00:00+08:00` 打包，`1.0.0` 对应的完整版本号为 `1.0.0.2026010107`。dev 不改变 Release 优化、签名、加密或应用标识。

| 平台字段 | 两种模式共用的值 | 上述时间的示例 |
|---|---|---|
| Android/HarmonyOS `versionName`；Apple `CFBundleShortVersionString` | 基础版本 | `1.0.0` |
| Android/HarmonyOS `versionCode` | `YYMMDDHH` 整数 | `26010107` |
| iOS/macOS `CFBundleVersion` | `YYMM.DD.HH` | `2601.1.7` |

构建日期限定为 2000–2099 年，替换已有输出前会校验平台上限。同一小时重新打包视为同一构建号，需要新的商店构建记录时应在下一小时打包。产物路径在原有平台、架构、变体和签名后缀前使用 `<game-name>-<full-version>`。重新打包同一标识会替换对应产物，其他版本及无关文件保留。

打包暂存区会生成 `Data/BuildInfo.json`，包含 `version`、`fullVersion`、`dev` 和 `builtAt`（带 `+08:00` 的 ISO 8601 时间）。dev 和 release **游戏包**都通过既有 Data 加密与 `.ldpak` 流程保留该文件，不写回源项目 Data。应用发行版本独立于顶层的[工程兼容版本](<项目设置与资产布局.md#mainproj>)和[存档 schema 版本](<../Lua 与蓝图脚本/Game 玩法/运行时数据、配置与存档.md#存档>)。

### 散放与归档

所有平台默认都把运行时文件、`Assets`、`Data` 与运行时 `Scripts` 作为散放目录保留。`.ldpak` 选项默认不勾选；勾选后，三个目录的完整内容分别成为根级 `Assets.ldpak`、`Data.ldpak` 与 `Scripts.ldpak`。归档条目保留相对于原目录的路径，因此资源路径、Data 路径与 Lua 模块名都保持不变。加密与 Lua 编译在归档之前执行；归档本身不会加密其内容，该选项也与加密相互独立。移动端发行包执行同样的散放或归档契约，且 Android 与 HarmonyOS 都不会重新压缩 `.ldpak`。

资源打包会拒绝符号链接、大小写冲突、非法路径和输出冲突。一个发行包要么同时包含三个散放目录（`Assets`、`Data`、`Scripts`），要么同时包含三个根级归档。损坏的归档、缺少根目录、布局混用以及旧式的分组归档都会被拒绝。

打包会移除仅供开发使用的 `Scripts/stub` 目录。`Scripts` 下若还留有其他 `.d.lua` 文件，打包就会失败。

### Windows 与 macOS

Windows 输出为 `dist/<game-name>-<full-version>/Main.exe`，同目录包含所需运行时文件。macOS 输出为 `dist/<game-name>-<full-version>.app`，应用显示名称取 System 标题。指定自定义输出目录时，该目录替代 `dist`，作为发行包的父目录。发行包目录及其祖先目录不得是符号链接或目录联接。

Windows 与 macOS 发行包复制运行时文件、`Assets`、`Data` 与运行时 `Scripts`。Standalone 发行包在根部保留启动器，并把运行时二进制放在平台包目录中（Windows 为 `Binaries`，macOS 应用的 `Contents/Frameworks`）。适用时会附带 FFmpeg 声明与源码提供材料；发行要求见 [FFmpeg 选项](<../快速入门/项目模板.md#ffmpeg-选项>)。Windows 发行包排除 PDB 文件，应将它们与对应构建一起保留用于调试。

选择 macOS 后会出现 **签名应用**，默认不勾选。保持不勾选时使用本机环境变量中配置的签名，例如 `LUDORK_MACOS_SIGNING_IDENTITY`、`LUDORK_MACOS_SIGNING_CERTIFICATE` 与 `LUDORK_MACOS_NOTARY_*` 公证凭据；都没有配置时应用只获得 ad-hoc 临时签名。勾选后，在下方表单中选择 `.p12` 证书并填写口令、可选的签名身份，并可选填公证信息：Apple ID 配合 Team ID 与专用口令，或 App Store Connect 密钥配合密钥 ID 与 Issuer ID。本次打包以表单设置为准，忽略环境变量。公证要求真实的签名身份，会提交给 Apple 并将通过后的公证票据附加到应用；ad-hoc 身份会被拒绝。选择同一证书后会自动恢复已保存的签名信息。临时签名不能替代发行方的证书签名与公证。

### iOS

在 macOS 上选择 iOS 16.3 或更高版本的目标，需要 C++ Source 项目、带 iPhoneOS SDK 的完整 Xcode 安装，以及已完成首次启动设置的 Xcode。选择 iOS 后会出现 **签名应用**，默认不勾选。保持不勾选时使用已登录的 Apple Development 团队，设置了 `LUDORK_IOS_DEVELOPMENT_TEAM` 时以它为准，并由 Xcode 自动签名。勾选后，在下方表单中填写 Team ID、`.p12` 证书与其口令，以及 `.mobileprovision` 描述文件；打包器随后使用该身份与描述文件手动签名，并拒绝团队或 application identifier 不匹配的描述文件。本次打包以表单设置为准，忽略环境变量。证书与描述文件必须同时提供，选择同一证书后会自动恢复已保存的记录。

默认情况下，iOS 打包只生成 `dist/<game-name>-<full-version>.ipa`，无需连接任何 iPhone。勾选 **导出到 iPhone** 后，还会把应用安装到设备上并启动。该模式要求 iPhoneOS 平台上恰好有一台物理设备，iPhone 或 iPad 均可，且 `xcdevice` 报告它可用。模拟器不符合要求。解锁、信任或开发者模式之类的提示都来自设备本身。安装之后，设备还必须信任开发者描述文件，目前该问题会表现为签名错误。

### HarmonyOS

HarmonyOS 打包需要 C++ Source 项目、Apple Silicon 的 macOS，以及带 OpenHarmony native SDK 的 DevEco Studio。所有 HarmonyOS 变体都使用 HarmonyOS 6.0.2 / API 22。面向 OpenGL ES 的手机与平板宿主请选择 **Mobile**；或选择 **2in1**，再选 OpenGL（默认）或 OpenGL ES。

选择 HarmonyOS 后会出现 **签名 HAP**，默认不勾选。保持不勾选时，在 `dist` 中生成一个 arm64-v8a 的未签名 HAP：`<game-name>-<full-version>-harmony-mobile-unsigned.hap`、`<game-name>-<full-version>-harmony-2in1-opengl-unsigned.hap` 或 `<game-name>-<full-version>-harmony-2in1-opengl-es-unsigned.hap`。勾选后，在下方表单中选择 `.p12` keystore、`.cer` 证书与 `.p7b` Profile，并填写密钥 alias 与密码。密钥密码默认与 keystore 密码相同。签名成功时发布对应的 `-signed.hap`；仅签名无需连接设备，也不会安装或启动游戏。

签名信息可以保存在本机，选择同一 keystore 后会自动恢复。编辑器把材料路径与 alias 保存在 `Ludork.ini` 旁边的 `harmony-signing.json`，macOS 上位于 `~/Library/Application Support/Ludork`，密码则保存在系统 Keychain。签名材料应放在项目与仓库之外。打包日志会隐藏密码与材料信息，不会向生成的 HarmonyOS 工程写入凭据或签名配置。

支持 Debug 和 Release Profile。Profile 必须有效、已签名，且与项目包名匹配。打包或签名失败时，会保留上一次成功的产物。命令行选项见 [tools/README.md](https://github.com/JasonLeon01/Ludork/blob/main/tools/README.md)。

勾选 **导出到匹配的 HarmonyOS 设备** 会启用签名，并额外把签名 HAP 安装到设备上启动游戏。只有设备导出会调用 HDC 并检查 Profile 对目标设备的授权。Mobile 导出接受上报为 `default`、`phone` 或 `tablet` 的已连接设备，尽管 Mobile HAP 自身声明的是 `deviceTypes: ["phone","tablet"]`。2in1 导出只接受 `2in1`。必须恰好有一台已连接设备与所选形态匹配，另一形态的设备可以保持连接。已连接设备的类型无法读取时，即使它属于另一形态，也会中止导出。2in1 OpenGL 包要求设备上存在 `libGLv4.so`，部分模拟器没有提供。应用会报告模块缺失，而不会回退到 OpenGL ES，因此在这些映像上请改用 OpenGL ES 包。

发行包内的原生库已剥离符号；需要调试时，请保留与该包对应的原生构建产物。

### Android

Android 打包适用于 macOS 上的 C++ Source 项目，并要求 Android Studio 安装在 `/Applications` 或当前用户的 `Applications` 目录。需要 SDK Platform 36、Build Tools 36.0.0、完整的稳定版 NDK r27 或更新版本，以及 CMake 3.28 或更新版本；打包时选用本机 SDK 中符合要求的最高 NDK 版本。SDK 和 NDK 需要单独安装。APK 以 API 36 为目标，支持 Android 7.0 / API 24 及以上版本，可使用两个横屏方向。打包只生成 APK，不安装或启动游戏。

选择 Android 后会出现 **签名 APK**，默认不勾选。保持不勾选时发布 `dist/<game-name>-<full-version>-android-arm64-v8a-unsigned.apk`。勾选后，在下方表单中选择 JKS 或 PKCS12 keystore，填写它的 alias 与密码，并可选地把这些信息保存在本机。选择器接受 `.keystore`、`.p12`、`.pfx` 和 `.pkcs12` 文件，并自动识别类型。key 密码默认与 keystore 密码相同；已保存的记录会自动恢复 keystore 路径与 alias。签名成功时只发布 `dist/<game-name>-<full-version>-android-arm64-v8a-signed.apk`。

保存的记录位于编辑器的当前用户设置目录中，即 `Ludork.ini` 旁边的 `android-signing.json`，macOS 上则在 `~/Library/Application Support/Ludork` 下。记录只保存 keystore 路径与 alias，密码交由操作系统的凭据存储保存。密码永远不会写入项目、Gradle 文件或日志。Android 平台本身要求更新已安装应用时使用相同的签名证书，因此用不同密钥签名的更新会被设备拒绝。

发行包内的原生库已剥离符号；需要调试时，请保留与该包对应的原生构建产物。

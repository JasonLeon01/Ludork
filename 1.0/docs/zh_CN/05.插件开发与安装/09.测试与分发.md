# 测试与分发

## 目标

准备一个源码插件目录，让其他 Ludork 1.0.0 用户无需依赖作者的构建树，即可检查、引入、重启并验证它。

## 前置条件

- 有效的 manifest，包含全局唯一 ID，且 `minimumEditorVersion` 不低于 `1.0.0`。
- 可以通过 **引入插件** 编译的源码。
- 插件的许可证，以及所有再分发的第三方组件或资产的声明。

## 步骤

1. 从分发目录中删除构建输出、本地设置、密钥、凭据、测试项目与 `.data`。
2. 保留 `plugin.json`、所有必需的 `.cs` 文件、插件自有资源、许可证文件，以及简明的安装与重启说明。
3. 用 .NET 9 构建可选的 IDE 项目。这能发现常规的编译器诊断，但不能替代宿主编译。
4. 把干净的目录引入一个全新的开发版编辑器，重启后检查 **插件管理**。
5. 在 `en_GB` 与 `zh_CN` 下测试每一条已注册命令、文本 provider 与操作 hook。覆盖项目缺失、取消、无效输入与已处理失败的路径。
6. 对 before-Export、before-Run 与 before-Pack Hook，测试执行顺序、失败阻断与输出。对导出 Hook，确认编辑器在重新打开项目后仍能检测已声明输入的新增、修改或删除，以及输出缺失或被改写；导出期间输入变化时不得发布成功记录。确认 Pack 先执行一次 Export，再执行 before-Pack Hook。只在 Pack 期间读取 `Packaging`，并在最终发行包中核对每个已编译目录与已排除文件。
7. 对地图或蓝图桥，制造一次 revision 冲突，确认插件拒绝覆盖更新的编辑器状态。对资源清理，在扫描后修改项目输入，确认拒绝执行回收；测试取消与回收失败，并从系统回收站／垃圾篓恢复临时测试文件。确认空的项目保留清单不会被创建，固定原生资源不会写入项目追加清单。
8. 把同一目录引入干净的发布版编辑器，重复面向用户的冒烟测试。
9. 归档完全相同的源码目录，并发布校验和、版本历史、支持的编辑器版本范围、许可证与支持联系方式。

## 限制

Ludork 不提供插件市场、签名机构、依赖解析器、NuGet 还原或预构建的二进制插件格式。分发信任、发行签名、更新沟通与第三方法律合规仍由发布者负责。

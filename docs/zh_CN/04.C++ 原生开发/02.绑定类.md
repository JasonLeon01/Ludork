# 绑定类

## 目标

把同一个 C++20 类一致地暴露给原生 Lua、LuaLS 与蓝图 Metadata 目录。

## 前置条件

- 所属模块与依赖方向已经确定。
- 该类已在该模块下具备公开头文件与实现文件。

## 步骤

### 1. 声明类

```cpp
#pragma once
#include <CoreMinimal.hpp>

BIND_CLASS()
class Counter {
public:
  BIND_INIT()
  explicit Counter(int initial = 0);

  BIND_PROPERTY()
  int value = 0;

  BIND_METHOD(Pure = true)
  int getValue() const;

  BIND_METHOD()
  void add(int amount);
};
```

头文件依赖与运行时值类型遵循[构建与模块布局](<01.构建与模块布局.md#core-头文件与-runtime-边界>)。`BIND_METHOD(name = "...")` 用来指定 Lua 方法名，对 `metadata = false` 的方法同样有效。

声明放在所属模块的 `include/Counter.hpp`，成员定义放在 `src/Counter.cpp`：

```cpp
#include "Counter.hpp"

Counter::Counter(int initial) : value(initial) {}

int Counter::getValue() const {
  return value;
}

void Counter::add(int amount) {
  value += amount;
}
```

CMake 会扫描 `include/**/*.hpp` 与 `src/**/*.cpp`。重新构建模块即可重新生成绑定。若 `Counter` 位于 `Engine`，Lua 可以这样使用：

```lua
local Engine = require("Engine")
local Logging = require("Global.Utils.Logging")

local counter = Engine.Counter.new(4)
counter:add(3)
Logging.info(counter:getValue())
```

模块根是该类唯一的公开运行时位置。`name` 用于选择该根字段的 Lua 标识符。不得为同一个原生类再建一条 table 路径。

`BIND_CLASS(callbacks = true)` 让当前类的非 static 虚绑定方法经 Lua 派发。该 opt-in 不会被继承，但针对基类已选为 callback 的方法所做的 override 仍然生效。

`BIND_METHOD(callback = false)` 排除当前类的方法，但不会移除继承来的 callback。这一选择与 metadata、event 无关。不支持字符串清单，也不支持非 virtual 的构造 callback。

Bindgen 从 C++ 声明推断转换基类。`cast_bases = {"BaseA", "BaseB"}` 用于补充祖先，或在 `bind_bases = false` 时提供祖先。它必须是有序的非空类型名列表，不能写成逗号分隔的字符串。

已注册 Lua 类型的转换基类还会提供其原生方法和属性，C++ 直接返回的 userdata 也可访问这些成员。生成器对这类基类使用 `BindBase`，对未注册 Lua 类型的接口使用 `BindCast`。`bind_bases = false` 关闭从声明基类自动推断，不会隐藏显式指定的已注册基类成员；`runtime_bases` 仍控制独立的 Ludork 类组合继承层次。

所有逻辑上公开的 `BIND_METHOD` 默认进入编辑器 metadata。内部方法或次要适配重载若要继续供原生 Lua 与 LuaLS 使用、又不生成额外的蓝图节点，可标记为 `metadata = false`：

```cpp
BIND_METHOD(metadata = false)
void _updateCache();
```

该标记不会移除运行时注册，也不会移除 LuaLS stub。纳入 metadata 的方法名在同一类型内必须唯一。

### 2. 声明属性

`BIND_PROPERTY()` 公开数据成员。安全的布尔、数值、字符串与 `{}` 初始化器可以成为 metadata 默认值。需要显式默认值时，使用注解语法本身支持的纯数据。无法从类型推断的属性编辑器语义写在 `BIND_PROPERTY(meta(...))` 中。

```cpp
BIND_PROPERTY(
    default = {0.0, 0.0})
sf::Vector2f defaultOrigin{0.0f, 0.0f};
```

位置项构成数组，命名项构成对象。这是 bindgen 直接读取的注解语法，不必是合法的 C++ 表达式。用 `BIND_METHOD(property = ...)` 声明的 getter 属性同样使用单数形式的 `default`。

`meta(...)` 内的结构化纯数据使用同一套花括号 DSL。两种写法都可以嵌套：

```cpp
BIND_PROPERTY(
    meta(Rely = {source = "autoSound", op = "!=", value = ""}))
float autoSoundInterval = 0.0f;

BIND_METHOD(defaults = {{}},
            meta(MoveRouteVars = {"route"}),
            outpins(default = nil))
void setRoute(
    const std::optional<std::vector<sf::Vector2i>>& route = {});
```

这类数据中的布尔值一律写作小写 `true` 与 `false`。花括号语法、协议 `nil` 以及拒绝带引号 JSON 的规则见[宏参考](<04.宏参考.md>)。

普通属性与方法不声明 `DisplayName` 或 `DisplayDesc`。编辑器自动格式化标识符，因此 `defaultOrigin` 显示为 `Default Origin`，而 C++ 与 Lua 成员名仍是 `defaultOrigin`。真正的运算符别名可以使用 `+` 这类直接的字面显示名，但不得使用 `LOC(...)`，也不得使用默认描述。

无参 getter 可以公开为属性：

```cpp
BIND_METHOD(property = "volume", setter = "setVolume")
float getVolume() const;

void setVolume(float value);
```

属性类型取自 getter 的返回类型，可用 `type` 覆盖。这种写法只公开一个属性，不会再公开 getter 与 setter 节点。

计算属性也可以声明 `component = true`，保留与数据成员一致的组件 metadata，并让赋值经过 setter。`Actor.emitterComp` 使用这种形式，在替换或赋 `nil` 时立即释放旧效果，Actor 休眠时也同样生效。

### 3. 复核构造函数与排除项

`BIND_INIT` 标记构造函数。不需要公开的声明就不写绑定标记。类级值使用 `BIND_CLASS_PROPERTY`，模块级值使用 `BIND_MODULE_PROPERTY`。

绑定构造器使用 `.new(...)`。实例属性访问原生实例存储，类属性访问 C++ 静态存储。标记 `copyable = true` 的完整记录，只有在所有成员具有经过验证的独立值语义时，才提供 `copy()`、`deepcopy()`。标量、字符串、容器与嵌套独立值可以符合条件；指针、Lua 引用、共享资源不会仅凭 `copyable` 获得深复制。私有状态必须由显式的完整类型复制策略保证安全，不能只复制已绑定字段。

### 4. 绑定 scoped 枚举

固定原生值集合需要与 Lua 共享时使用 `BIND_ENUM`：

```cpp
BIND_ENUM()
enum class WeatherType {
  NONE = 0,
  RAIN = 1,
};
```

Bindgen 生成 `Module.WeatherType` 及其 LuaLS 类型。不要再用模块属性重复这些值。枚举值以底层整数跨越 Lua 边界，蓝图 Metadata 使用 `int`。

### 5. 绑定宿主专用的嵌套类型

公开的嵌套 struct 或 enum 使用与顶层声明相同的绑定标记：

```cpp
class Owner {
public:
  BIND_CLASS()
  struct Data {
    BIND_PROPERTY()
    int value = 0;
  };
};
```

该类型在 C++ 中名为 `Owner::Data`，在 Lua 中公开为 `Module.Data`，也可以用 `name` 改名。宿主自身不必绑定，但嵌套类型必须能通过每一层外层类公开访问。采用公开前置声明加单独的限定名定义时，绑定标记放在完整定义上。

同一模块内 C++ 短名相同的类型，需要配置彼此不同的 Lua `name`。

## 值转换契约

用 `BIND_CLASS(table_init = true)` 可以从 Lua 表初始化字段固定的类型。表中提供的非 nil 可写属性按声明的编解码规则转换，缺失或为 nil 的字段保留 C++ 默认值。已有的原生实例同样可以传入。加上 `strict_fields = true` 后，未知字段与非字符串键会被拒绝：

```cpp
BIND_CLASS(table_init = true, strict_fields = true)
struct Limits {
  BIND_PROPERTY()
  std::optional<double> minimum;

  BIND_PROPERTY()
  std::optional<double> maximum;
};
```

`strict_fields` 不会把可选字段变成必填字段。

`RuntimeData` 这类递归值容器使用 `BIND_CLASS(pure_data = true)`。可接受的值与 variant 转换规则见[运行时值边界](<09.运行时值边界.md#lua-值转换>)。

`pure_data`、`dynamic_value`、`opaque_identity` 与 `table_init` 是互斥的转换模式。它们生成的类型表示见[生成 Metadata 与 Stub](<05.生成 Metadata 与 Stub.md#默认值与类型>)。

## 限制

Bindgen 不推断项目专用的转换规则，也不解析不完整的跨模块类型。

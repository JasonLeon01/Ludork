# 绑定类

## 目标

将一个 C++20 类一致地暴露给原生 Lua、LuaLS 与 Blueprint metadata 目录。

## 前置条件

- 已确定所属模块与依赖方向。
- 该类在所属模块下具有公开头文件与实现文件。

## 步骤

### 1. 声明类

```cpp
#pragma once
#include <CoreMinimal.hpp>

BIND_CLASS()
class Counter {
public:
  BIND_INIT()
  explicit Counter(int initial = 0);

  BIND_PROPERTY()
  int value = 0;

  BIND_METHOD(Pure = true)
  int getValue() const;

  BIND_METHOD()
  void add(int amount);
};
```

头文件依赖与运行时值类型遵循 [构建与模块布局](<01.构建与模块布局.md#core-头文件与-runtime-边界>)。`BIND_METHOD(name = "...")` 指定 Lua 方法名，也适用于 `metadata = false` 的方法。

把声明放在所属模块的 `include/Counter.hpp`，成员定义放在 `src/Counter.cpp`：

```cpp
#include "Counter.hpp"

Counter::Counter(int initial) : value(initial) {}

int Counter::getValue() const {
  return value;
}

void Counter::add(int amount) {
  value += amount;
}
```

CMake 会发现 `include/**/*.hpp` 与 `src/**/*.cpp`；重新构建模块即可生成绑定。对于放在 `Engine` 的 `Counter`，Lua 可这样调用：

```lua
local Engine = require("Engine")
local Logging = require("Global.Utils.Logging")

local counter = Engine.Counter.new(4)
counter:add(3)
Logging.info(counter:getValue())
```

模块根是该类唯一的公开运行时位置。`name` 用于选择该根字段的
Lua 标识符。不得为同一个原生类再创建第二条 table 路径。

`BIND_CLASS(callbacks = true)` 通过 Lua 派发当前类的非 static 虚绑定方法。opt-in 不继承，但基类已选择 callback 的 override 仍有效。

`BIND_METHOD(callback = false)` 排除当前类的方法，但不移除继承 callback。选择与 metadata 和 event 独立；不支持字符串清单或非 virtual 构造 callback。

Bindgen 会从 C++ 声明识别转换基类。`cast_bases = {"BaseA", "BaseB"}` 用于补充祖先，或在 `bind_bases = false` 时提供祖先；它必须是有序的非空类型名列表，不能写成逗号分隔字符串。

所有逻辑公开的 `BIND_METHOD` 默认进入编辑器 metadata。内部方法或次要适配重载若需要继续供原生 Lua 与 LuaLS 使用、但不应生成第二个 Blueprint 节点，应标记为 `metadata = false`：

```cpp
BIND_METHOD(metadata = false)
void _updateCache();
```

该选项不影响运行时注册或 LuaLS stub。同一类型中，纳入 metadata 的方法名必须唯一。

### 2. 声明属性

`BIND_PROPERTY()` 公开数据成员。安全的布尔、数值、字符串和 `{}` 初始化器可以生成 metadata 默认值。显式默认值应使用注解语法本身支持的纯数据。无法从类型推导的属性编辑器语义写在 `BIND_PROPERTY(meta(...))` 内。

```cpp
BIND_PROPERTY(
    default = {0.0, 0.0})
sf::Vector2f defaultOrigin{0.0f, 0.0f};
```

位置项组成数组，命名项组成对象。这是 bindgen 读取的注解语法，不需要构成合法 C++ 表达式。通过 `BIND_METHOD(property = ...)` 声明的 getter 属性也使用相同的单数 `default` 语法。

`meta(...)` 内的结构化纯数据使用相同的花括号 DSL，两种形式都可以按相同规则嵌套：

```cpp
BIND_PROPERTY(
    meta(Rely = {source = "autoSound", op = "!=", value = ""}))
float autoSoundInterval = 0.0f;

BIND_METHOD(defaults = {{}},
            meta(MoveRouteVars = {"route"}),
            outpins(default = nil))
void setRoute(
    const std::optional<std::vector<sf::Vector2i>>& route = {});
```

其中布尔值使用小写 `true`、`false`。花括号语法、协议 `nil` 与带引号 JSON 的拒绝规则见[宏参考](<04.宏参考.md>)。

普通属性和方法不声明 `DisplayName` 或 `DisplayDesc`。编辑器自动格式化标识符，因此 `defaultOrigin` 显示为 `Default Origin`，C++ 与 Lua 成员名仍为 `defaultOrigin`。真正的运算符别名可以使用 `+` 之类的直接显示字面量，但不得使用 `LOC(...)`，也不得使用默认描述。

无参 getter 可公开为属性：

```cpp
BIND_METHOD(property = "volume", setter = "setVolume")
float getVolume() const;

void setVolume(float value);
```

默认使用 getter 返回类型作为属性类型，必要时用 `type` 覆盖。这种写法只公开一个属性，不公开 getter 或 setter 节点。

### 3. 检查构造与排除

`BIND_INIT` 标记构造函数。无需公开的声明不写绑定 marker。类级值使用 `BIND_CLASS_PROPERTY`，模块级值使用 `BIND_MODULE_PROPERTY`。

### 4. 绑定 scoped enum

固定原生值集合需要与 Lua 共享时使用 `BIND_ENUM`：

```cpp
BIND_ENUM()
enum class WeatherType {
  NONE = 0,
  RAIN = 1,
};
```

Bindgen 生成 `Module.WeatherType` 及其 LuaLS 类型，不应再用模块属性重复枚举值。枚举值以底层整数跨越 Lua 边界，Blueprint metadata 使用 `int`。

### 5. 绑定宿主专用的嵌套类型

公开的嵌套 struct 或 enum 使用与顶层声明相同的绑定标记：

```cpp
class Owner {
public:
  BIND_CLASS()
  struct Data {
    BIND_PROPERTY()
    int value = 0;
  };
};
```

C++ 类型名为 `Owner::Data`，Lua 在模块根公开为 `Module.Data`，也可通过 `name` 改名。宿主自身不必绑定，但嵌套类型必须能通过每一层宿主公开访问。采用公开前置声明和单独的限定名定义时，绑定标记放在完整定义上。

同一模块中 C++ 短名相同的类型须配置不同的 Lua `name`。

## 值转换契约

使用 `BIND_CLASS(table_init = true)`，即可用 Lua 表初始化字段固定的类型。表中非 nil 的可写属性按声明类型转换，未提供或为 nil 的字段保留 C++ 默认值；已有的原生实例也可直接传入。添加 `strict_fields = true` 后，未知字段和非字符串键会报错：

```cpp
BIND_CLASS(table_init = true, strict_fields = true)
struct Limits {
  BIND_PROPERTY()
  std::optional<double> minimum;

  BIND_PROPERTY()
  std::optional<double> maximum;
};
```

`strict_fields` 不会把可选字段变为必填。

`RuntimeData` 这类递归值容器使用 `BIND_CLASS(pure_data = true)`。支持的值和 variant 转换规则见[运行时值边界](<09.运行时值边界.md#lua-值转换>)。

`pure_data`、`dynamic_value`、`opaque_identity` 与 `table_init` 是互斥的转换模式。生成的类型表示见[生成 Metadata 与 Stub](<05.生成 Metadata 与 Stub.md#默认值与类型>)。

## 限制

Bindgen 不会推断项目专用转换规则，也不会解析不完整的跨模块类型。

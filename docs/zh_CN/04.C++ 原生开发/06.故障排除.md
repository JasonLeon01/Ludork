# C++ 绑定故障排查

## 范围

从第一条 bindgen 或编译器诊断开始。按声明、生成、runtime 路径的顺序解决问题，每次修正后重新构建，再调查后续症状。

## 声明没有生成

确认标记位于模块会解析的公开声明上，头文件已加入 CMake 绑定输入，注解语法与现有示例一致。重新构建并阅读第一个 bindgen 诊断。

## C++ 编译成功但 Lua 找不到成员

检查 Lua 模块或规范函数 group 路径、生成注册与 require 顺序。类、未分组函数和
模块属性只存在于模块根；分组函数只存在于自身 group table。

## LuaLS 可见但 Blueprint 不可见

检查方法是否按内部 helper 或次要适配重载的用途显式标记了 `metadata = false`。除此以外，每个逻辑公开的 `BIND_METHOD` 都应出现在生成的根 `*_meta.lua` 中；应阅读 bindgen 诊断，不得手写重复声明。

## Bindgen 报告 metadata 方法重名

保留逻辑上应公开给 Blueprint 的重载，并把次要转换或适配重载标记为 `metadata = false`。不得增加重载专用生成分支，也不得允许一份声明静默覆盖另一份。

## 类型转换失败

使用受支持的基础、STL、SFML 和已声明 Core 类型。跨模块签名包含完整声明。可复用转换通过通用 adapter/trait 增加；不得让 bindgen 按单个业务类或成员名分支。

## Metadata 默认值错误

属性/方法的 `Meta` 写入自身注解，并使用注解原生的 `default`（见[宏参考](<04.宏参考.md>)与[生成 Metadata 与 Stub](<05.生成 Metadata 与 Stub.md>)）。重新构建全部生成输出，并复查“Blueprint API 参考”的覆盖率。

方法/函数顶层的 `default`、`success` 或 `fail` 会触发校验诊断，要求改用 `outpins(...)`；`outpins`/`defaults` 的区别与小写 token 规则见[函数、事件与执行](<03.函数、事件与执行.md>)与[宏参考](<04.宏参考.md>)。

## 验证

修正后从干净配置重新构建，对比注册、stub 与 metadata，并通过公开 Lua 路径以及适用的 Blueprint 节点执行该成员。

## 限制

本页处理声明与生成故障。成员调用后的崩溃或错误行为需要使用普通 C++ runtime 调试方法。

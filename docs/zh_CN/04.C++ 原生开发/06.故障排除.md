# C++ 绑定故障排除

先看第一条 bindgen 或编译器诊断。按声明、生成、运行时路径的顺序处理故障，每次修正后重新构建，再去排查后面的症状。

## 声明没有生成

确认标记位于模块会解析的公开声明上，头文件已加入该模块的 CMake 绑定输入，注解语法与现有示例一致。重新构建，并阅读第一条 bindgen 诊断。

## C++ 编译成功但 Lua 找不到成员

检查 Lua 模块路径或规范函数组路径、生成的注册代码与 `require` 顺序。类、未分组函数与模块属性只存在于模块根。分组函数只存在于所属的 group table。

## LuaLS 可见但蓝图不可见

确认该方法是否因内部 helper 或次要适配重载而被有意标记为 `metadata = false`。若没有，生成的根 `*_meta.lua` 应当收录每一个逻辑公开的 `BIND_METHOD`。阅读 bindgen 诊断，不要手写重复声明。

## Bindgen 报告 metadata 方法重名

保留逻辑上面向蓝图的那个重载，把次要转换或适配重载标记为 `metadata = false`。不要添加针对重载的生成分支，也不要让一份声明悄悄取代另一份。

## 类型转换失败

使用受支持的基础类型、STL 类型、SFML 类型与已声明的 Core 类型。跨模块类型必须带完整声明。可复用的转换交给通用 adapter 或 trait 提供；绝不能让 bindgen 针对某个业务类或成员名分支。

## Metadata 默认值错误

把属性或方法的 `Meta` 放进它自己的注解，并使用注解语法本身支持的 `default`（见[宏参考](<04.宏参考.md>)与[生成 Metadata 与 Stub](<05.生成 Metadata 与 Stub.md>)）。重新构建全部生成输出，并复查“Blueprint API 参考”的覆盖情况。

方法或函数顶层的 `default`、`success` 或 `fail` 会触发校验诊断，要求改用 `outpins(...)`。`outpins` 与 `defaults` 的区别以及小写 token 规则见[函数、事件与执行](<03.函数、事件与执行.md>)与[宏参考](<04.宏参考.md>)。

## 限制

本页只覆盖声明与生成阶段的故障。成员被调用之后出现的崩溃或行为错误，需要按常规方式调试 C++ 运行时。

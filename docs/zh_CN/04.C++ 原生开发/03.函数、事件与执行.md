# 函数、事件与执行

## 目标

从同一声明源暴露方法、分组自由函数、事件与蓝图执行协议。

## 前置条件

- 所属模块中已有绑定类，或已有公开的自由函数头文件。
- 已为 pure、分支输出、latent 状态或循环行为定义好蓝图契约。

## 步骤

### 1. 绑定方法与自由函数

`BIND_METHOD` 把类方法公开给原生 Lua 与 LuaLS，逻辑上公开的方法默认还会进入蓝图 Metadata。`BIND_FUNCTION` 公开自由函数，但不改变其既有的 metadata 选择规则。只有蓝图节点确实没有执行输入与执行输出时，才声明 `Pure = true`。非 void 返回并不代表 pure。

```cpp
BIND_FUNCTION(name = "clampValue", Pure = true)
float clampValue(float value, float minimum, float maximum);
```

未分组的自由函数只在模块根公开，例如 `Engine.clampValue`。`name` 用于选择该根字段的 Lua 标识符。group table 才是函数的规范归属时，使用 `BIND_FUNCTION_GROUP`。

非 void 函数会得到一个名为 `return` 的 metadata 输出。void 函数得到空的 return table。

### 2. 指定函数组

只包含自由函数的头文件可以开头声明：

```cpp
BIND_FUNCTION_GROUP(name = "Manager")

BIND_FUNCTION(name = "playSE")
void playSE(const std::string &path);
```

该头文件中所有绑定函数都只注册到分组 table。注册、LuaLS stub 与 metadata 使用同一个分组。未分组的函数仍留在模块根。

### 3. 声明执行行为

非 pure 方法默认走普通执行流，不需要显式的执行注解：

```cpp
BIND_METHOD()
void refresh();
```

执行结果需要选择某个具名执行分支时，把各分支写进内联的 `outpins(...)` 块。Bindgen 保留声明顺序：

```cpp
BIND_METHOD(outpins(default = nil))
void setCollisionEnabled(bool enabled);

BIND_METHOD(outpins(success = true, fail = false))
bool tryMove();
```

需要挂起的工作，把恢复状态放进 `latent(...)`：

```cpp
BIND_METHOD(latent(TimeUp = true),
            defaults = {nil, nil, {}, false},
            parameter_types = {float, function, any[], bool})
TimerHandle addTimer(float interval,
                     RuntimeIdentityPtr task = {},
                     RuntimeValue::Array params = {},
                     bool blocking = false);
```

`defaults` 描述参数默认值，与 `outpins(default = nil)` 无关。列表形式同样适用于构造函数与自由函数的 `defaults`。小写 token 与花括号选项列表见[宏参考](<04.宏参考.md>)。

`Pure = true` 不能与执行协议同时出现。getter 属性也不能携带执行协议，其顶层单数 `default` 仍是属性默认值。内联 `loop_node(ForEach)` 声明循环，独立的 `BIND_REGISTER_EVENT()` 创建事件入口。没有显式输出的事件会得到默认分支值 `nil`。

显示信息、编辑器信息与执行信息都写在 `BIND_METHOD(...)` 或对应的函数、属性注解里。不支持为 metadata、purity、执行拆分与 latent 各写独立标记。

### 4. 声明严格回调

需要约束回调返回结果数量时，使用 `<Runtime/StrictFunction.hpp>` 中的 `ludork::runtime::StrictFunction<Return(Arguments...)>`：非 void 签名要求 Lua 恰好返回一个结果，`void` 则要求不返回任何结果。结果会按声明的类型转换并校验。

```cpp
using Number = std::variant<std::int64_t, double>;
using Constraint = ludork::runtime::StrictFunction<Number(Number)>;

BIND_METHOD()
void setConstraint(Constraint constraint);
```

回调嵌套在 variant 或容器中时也会执行这些检查。Nil 表示空回调。Lua 回调保留其函数身份，并一直绑定到创建它的会话。Lua 错误与转换失败会传播给调用方。Lua 引用与会话生命周期的规则见[运行时值边界](<09.运行时值边界.md#lua-引用与会话生命周期>)。

## 限制

注解只描述执行协议，不实现该协议的运行时行为。C++ 函数体与运行时调度器必须实际产生每个已声明的分支、latent 状态或循环转换。

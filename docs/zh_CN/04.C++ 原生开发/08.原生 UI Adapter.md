# 原生 UI Adapter

## 目标

把原生控件加入 Ludork 声明式 UI 契约，使运行时、preview host 与编辑器实时 Control Registry 对同一控件保持一致描述。

## 前置条件

- 一个 C++ Source 项目。
- 原生控件类型，以及用于创建、设置属性、测量、布局和挂载子控件的通用 adapter 操作。
- 已了解[声明式 UI 运行时契约](<../03.Lua 与蓝图脚本/05.声明式 UI/02.运行时契约.md>)。

## Descriptor 契约

系统控件描述在 `Engine/Source/Core/include/UI/UiControlAdapterDescriptors.hpp` 中通过私有 `BIND_UI_CONTROL` X-macro 定义，不属于 Core bindgen 注解。其逻辑签名为：

```cpp
BIND_UI_CONTROL(TAG, CONTROL_ID, ADAPTER, DISPLAY_NAME, CATEGORY,
                CHILD_POLICY, SLOT_TYPE, ...PROPERTIES)
```

| 参数 | 含义 |
|---|---|
| `TAG` | 用于特化 `UiControlAdapterTraits` 的唯一 C++ tag |
| `CONTROL_ID` | 稳定的可序列化系统控件标识符；使用原生类的规范模块根路径 |
| `ADAPTER` | 运行时 adapter 标识符；使用同一条规范模块根路径 |
| `DISPLAY_NAME` | palette 显示名称 |
| `CATEGORY` | palette 分类 |
| `CHILD_POLICY` | `UiChildPolicy::None`、`Single` 或 `Multiple` |
| `SLOT_TYPE` | `UiControlSlotType::None`、`Canvas` 或 `List` |
| `...PROPERTIES` | 一个或多个属性 descriptor |

属性使用三类 descriptor 宏之一。`UI_CONTROL_COMMON_PROPERTY` 适用于所有控件；`UI_CONTROL_PROPERTY` 会被写入并由运行时 adapter 消费；`UI_CONTROL_EDITOR_PROPERTY` 仅用于编辑器或 preview。每个宏接收 `(ID, DISPLAY_NAME, TYPE, REQUIRED, DEFAULT_JSON)`。普通文本控件使用 `UI_CONTROL_PLAIN_TEXT_PROPERTIES(DEFAULT_SIZE)`，富文本控件使用 `UI_CONTROL_RICH_TEXT_PROPERTIES`；这些属性组也决定编辑器与打包校验要求的 TextConfig 类型。

原生 Registry 在导出描述前校验 ID、属性类型与默认值、属性职责和 Adapter 注册完整性。

系统控件的两个路径字段必须完全一致。Engine 中绑定的 `Canvas` 同时以
`Engine.Canvas` 作为 `CONTROL_ID` 与 `ADAPTER`；嵌套或缩写路径无效。

资产 JSON 先读入 `RuntimeData`，再根据属性描述解码为 `UiControlPropertyValue`。工厂函数接收 `UiControlProperties` 属性字典，setter 接收单个已转换的属性值。

## 步骤

1. 实现原生控件。
2. 在 `LUDORK_UI_CONTROL_DEFINITIONS` 中增加一项 `BIND_UI_CONTROL`。选择稳定的 control ID，并准确声明 child policy 与 Slot type。
3. 使用已有支持的属性类型和资源处理机制。新增属性类型还需要同步修改原生解码器、编辑器和 ScriptTools。
4. 在 `UiControlAdapterRegistry` 中注册 tag，提供 descriptor 所需的 factory、setter、arranger 与 child 函数。Registry 会从 descriptor 复制各 adapter 属性 ID。
5. 通过当前平台的 `tools/build_cpp` 构建项目，更新 Host 与 Registry 并校验 UI 资产。使用现有支持的属性类型新增控件，无须重建编辑器或 ScriptTools。
6. 如需单独校验，运行：

   ```sh
   ScriptTools ui-adapter-check <project-root>
   ScriptTools ui-assets validate <project-root>
   ```

   `ui-adapter-check` 比较 Registry 与对应 Host 编译后的描述，不修改文件。

7. 在 UI Asset Editor 中打开代表性资产，验证绘制和交互。

`Engine.TabView` 是无子节点 Input 的示例：只序列化构造与视觉资源，并在运行时绑定标签与 callback。细节见[资产 Schema 与 Control Registry](<../03.Lua 与蓝图脚本/05.声明式 UI/04.资产 Schema 与 Control Registry.md>)和[交互与声明式 UI 控件](<../03.Lua 与蓝图脚本/07.API 参考/04.Core 模块/02.Engine/13.交互与声明式 UI 控件.md>)。

`Engine.CharacterView` 是无子节点的动画 Visual 示例。其 Adapter 根据 `size`、纹理/Rect、Actor 缩放、动画、Shader 与 Hue 属性构造原生预览状态；控件类负责裁帧、逐帧推进和特效合成，Adapter 负责资源路径转换和属性赋值。

## 项目预览产物

每个项目使用自己的 Host。`Temp/UiPreview.json` 指定项目相对运行目录：源码构建使用 `bin/<configuration>`，Standalone 使用 `Binaries`。编译后的 `UiPreviewHost --describe` 提供 `Temp/UiPreview.registry.json`，供编辑器与 ScriptTools 共用。

源码构建在编译前停止已有预览连接，直到配套 Host 与 Registry 成功发布才恢复预览，因此 C++ UI 修改需要重编。随后 UI 资产校验即使失败，也保留新预览供修正资产。Standalone 可通过 `ui-preview ensure` 从随附 Host 恢复缺失 JSON，损坏或不匹配的产物会被拒绝。

## 限制

原生控件须通过项目 Core UI 源码和 Adapter 注册加入，并满足预览 runtime 的依赖边界；编辑器插件不能通过 palette 注册原生控件。`UiChildPolicy::None` 控件不能包含子控件，`Single` 最多接受一个子控件。

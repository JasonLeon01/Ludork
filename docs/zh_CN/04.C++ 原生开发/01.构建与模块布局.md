# 构建与模块布局

当 Lua 与 Blueprint API 不足、需要新的原生 UI adapter，或需要生成 iOS/HarmonyOS/Android 构建时，使用 C++ Source 项目。运行时使用 C++20、CMake 与声明驱动绑定。

## 目标

选择正确的原生模块，构建其生成绑定，并按受支持顺序加载生成的 Lua 模块。

## 前置条件

- 具备一个 C++ Source 项目，并已安装 CMake、C++20 工具链及目标平台依赖。
- 面向目标平台的干净构建配置。
- 受支持的目标：Windows 10 或更高版本（x64）、macOS 13.3 或更高版本（Apple Silicon）、iOS 15.0 或更高版本（arm64）、HarmonyOS 6.0.2 / API 22 或更高版本（arm64-v8a），或 Android 7.0 / API 24 或更高版本（arm64-v8a）。

公开头文件包含普通 C++ 声明和编译期为空的 `BIND_*` 标记。Core bindgen 读取模块与共享 Runtime 声明根，并生成按类稳定拆分的 sol2 源码、一个模块聚合/stub 源码、LuaLS stub 和编辑器 metadata。

## 步骤

### 1. 选择模块

| 模块 | 职责 | 原生依赖方向 |
|---|---|---|
| `LudorkRuntime` | 值、VM/绑定服务、蓝图执行、类型与组件数据、JSON 及 Asset/Data/Script 存储 | Standard、SFML 与私有 zlib；完整模式还依赖 LuaSF；不得依赖 Core 模块 |
| `Engine` | Engine 类型、服务、状态和玩法基础 | LudorkRuntime 与 SFML |
| `GlobalCore` | Global 游戏类与服务 | Engine、Standard 与 SFML；可选平台/FFmpeg 库 |
| `GlobalFunctions` | `Components`、`UI`、`NodeGraph`、`Manager` 自由函数组 | GlobalCore 与 SFML |

`LudorkRuntime` 在桌面端为共享库、移动端静态链接，不提供 Lua 根；绑定仍位于 `Engine`。AssetStore、DataStore 与 ScriptStore 分别为 loose 和 `.ldpak` 布局提供只读 Asset、Data 与 Lua 模块边界。Standard 只接收 DataStore 文件访问，因此脚本归档不会出现在文件系统 API 中。私有 zlib 仅用于归档 CRC32。玩法模块保持固定加载顺序、不反向链接 `GlobalFunctions`，跨模块签名须有完整声明。

`.ldpak` v1 使用 little-endian。`LDPK` header 保存版本、分组、条目数、索引范围与 CRC32；按 UTF-8 字节排序的文件/目录索引保存 64 位 offset/size 与数据 CRC32，原始正文按 8 字节对齐。

Runtime 负责蓝图类生成、Script Mixin、图执行与潜伏调度；Engine 提供 Actor 图查询、EventBus 与帧循环接入。 `RuntimeProviders.installBlueprint(classDataByPath, compileGraph, instantiateGraphTemplate)` 安装三个 Blueprint 回调。ClassDict 转发到 VM resolver；缓存与定义身份遵循 [Blueprint 运行时合同](<../03.Lua 与蓝图脚本/04.蓝图脚本/01.执行流、事件与变量.md#类定义与会话生命周期>)。

仅用于启动的原生模块由宿主负责：应用注册 `cjson` 与 `cjson.safe`，Standard 负责注册 `Class`，Engine 使用已初始化的原生 table 和 API，不建立反向模块链接。由资产和 metadata 驱动的动态模块解析保持不变。

`LUDORK_SAVE_AS_LDC` 是默认 `OFF` 的 CMake 选项，Standard 在 Entry 执行前将其公开为 `SAVE_AS_LDC`；C++ Source 打包通过**加密存档内容**设置该值。

Android 与 HarmonyOS 应用外壳位于 `Engine/PlatformHosts/Android` 和 `Engine/PlatformHosts/Harmony`。构建支持位于 `Engine/cmake/`，其中 FFmpeg 构建位于 `Engine/cmake/FFmpeg/`。

`LUDORK_WITH_LUA` 默认为 `ON`，构建游戏时必须启用。`UiPreviewHost` 独立构建时将其设为 `OFF`，使用原生 Runtime/Standard 和 SFML，不包含 Lua、LuaSF 绑定或蓝图执行功能。

预览与游戏的构建目录彼此独立：预览使用 `.tools/UiPreviewHost/build` 和 `.tools/UiPreviewHost/bin/<configuration>`，游戏使用 `Sample/build`、`Sample/Intermediate` 和 `Sample/bin`。

### 会话与模块生命周期

Standard 拥有 Lua 会话。`runtime::initialize` 要求 Standard 会话正在运行，重复调用会保留已挂载的 Runtime 状态。`runtime::shutdown` 卸载 Runtime 后，重新启动需要新的 Standard 会话与 Lua VM。

Standard 按依赖逆序关闭 Global、Engine、Runtime，最后释放自身状态。宿主拥有 Lua VM，必须等待发起关闭的线程完成 shutdown 后才能调用 `lua_close`。

AssetStore、DataStore、ScriptStore 与 Standard 的只读文件 provider 属于宿主配置，独立于 VM 会话，在会话关闭后继续保留。

### 宿主与实现源码

每个独立类或绑定类型使用同名头文件，必要时提供同名源文件。公开声明放在 `include`，成员定义放在 `src`。宿主专用数据类型可内嵌，共享数据与辅助类型可集中存放。

宿主私有实现放在 `src` 下并使用 `Impl` 后缀，例如定义 `Host::Impl` 的 `HostImpl.hpp`。较大的实现可使用同名子目录，通过 `target_sources` 添加源码。依赖由宿主流向实现。子目录不得包含父目录私有头，也不能通过 include 搜索路径绕过；公开头不得包含私有头。

Runtime 的共享 Lua 服务位于 `Runtime/src/LuaServices`，纯 ConfigVars 解析位于 `Runtime/src/Metadata`。

Standard ClassRuntime 的依赖方向为 `Class → Composite → Instance → Native → Detail`，允许跨级向下依赖。Detail 持有中立状态与查询；Native 负责 native 成员与属性；Instance 负责 native 构造与释放；Composite 负责索引与元表；Class 协调分配、构造完成与 super。边界检查覆盖 Standard，拒绝向上层包含、父私有头包含及这些边形成的循环。

System 私有组合 Display、FramePipeline、SceneStack 和 Lifecycle。Display 持有窗口，FramePipeline 持有画布、效果与过渡目标，SceneStack 持有操作队列与退役场景，Lifecycle 持有关闭状态。组件通过操作接口协作，不暴露可写状态聚合。帧呈现仍在场景逻辑锁之外执行，渲染目标在帧间重建。

`EngineState::CellSize` 是正整数 C++ 编译期常量。编辑器构建通过 ScriptTools 从该声明生成对应的 `EngineConstants.CellSize`。修改后须重建引擎、编辑器和模板，没有项目级或运行时覆盖入口。

### Core 头文件与 Runtime 边界

Core 的 Lua 绑定头包含 `Engine/Runtime/include` 提供的 `<CoreMinimal.hpp>`，共用注解、运行时类型、常用 C++ 类型与 SFML Graphics/Window/System。模块导出和直接类型依赖须显式包含，每个公开头都须可以独立编译。

手写 Core（包括私有源码）通过 Runtime 访问 VM 与绑定服务，不直接或间接依赖 sol。Runtime 还负责隔离音频执行，Core 保留玩法和播放策略。生成绑定可使用 sol。Runtime 内部在已进入的 `RuntimeScope` 中调用私有操作，Facade 提供对外入口。

API 类型选择、容器所有权和 Lua 引用操作见[运行时值边界](<09.运行时值边界.md>)。

### 2. 构建项目

```sh
./tools/build_cpp.sh Sample Debug
./tools/build_cpp.sh Sample Release
```

```bat
tools\build_cpp.bat Sample Debug
tools\build_cpp.bat Sample Release
```

`LUDORK_DEBUG_SOL_SAFETIES` 默认 `OFF`，开启后仅在 Debug 启用完整 sol 安全检查；`LUDORK_OPTIMIZE_DEBUG` 默认 `ON`，独立控制 Debug 优化。

构建前可在本地验证宿主到 Impl 的依赖方向：

```sh
.tools/ScriptTools/ScriptTools impl-boundary-check Sample
```

```bat
.tools\ScriptTools\ScriptTools.exe impl-boundary-check Sample
```

该命令根据宿主源码与同名目录自动发现 C++ 边界。Lua 边界使用对应的宿主文件/同名模块目录约定；子模块若有镜像 `.d.lua`，则自动视为独立宿主。CMake 以 `ImplBoundaryValidate` target 暴露同一验证，并让 Engine 依赖该 target；Windows 与 macOS CI 也会在原生输入验证阶段直接运行该命令。违规诊断包含源文件和行号，不需要维护第二份边界清单。检查也会拒绝手写 Core 中的 sol 使用及已解析的间接 sol include。

CMake 默认从 `Sample/Engine/ThirdParty/LuaSF` 读取 LuaSF。可用 `cmake -S Sample -B Sample/build -DLUDORK_LUASF_SOURCE_DIR=/absolute/path/to/LuaSF/output` 选择本地生成的目录树。该覆盖仅影响当前构建目录，依赖初始化仍使用 `versions.conf` 固定的版本。

CMake 自动运行 `ScriptTools core-bindgen`。生成的 C++ 文件按构建目录和模块归入顶层 `Intermediate/`，LuaLS stub 与 metadata 输出到 `Scripts`。输出与重新生成规则见[生成 Metadata 与 Stub](<05.生成 Metadata 与 Stub.md>)。

模板不携带 `Intermediate/`，目录缺失时由正常构建重建。`bin/` 与 `build/` 仍位于项目顶层。

HarmonyOS 打包是通过 DevEco Studio OpenHarmony native SDK 从 Apple Silicon macOS 执行的交叉构建。每次打包都会重建 Stage 与原生构建目录，避免 CMake cache 跨设备形态或图形后端复用。HAP target SDK 与 compatible SDK 均为 `6.0.2(22)`，CMake 接收 `OHOS_COMPATIBLE_SDK_VERSION=22`；因此工具链会以 `aarch64-linux-ohos22.0.0` 为 Ludork、Lua、LuaSF 与 SFML 编译，并启用 API availability 诊断。已安装的更新 SDK 只作为 compile SDK，不会提高该 deployment target。

Mobile 变体使用 `SFML_HARMONY_DEVICE_FORM=MOBILE` 与 `SFML_OPENGL_ES=ON`，声明 `phone` 与 `tablet`，并使用固定横屏移动宿主。2in1 变体使用 `SFML_HARMONY_DEVICE_FORM=2IN1`，只声明 `2in1`，支持 `fullscreen` 与 `floating` 窗口，声明 `NEED_OPENGL=1`、请求 `ohos.permission.LOCK_WINDOW_CURSOR`，并在 OpenGL 后端下设置 `SFML_OPENGL_ES=OFF`，在 OpenGL ES 后端下设置为 `ON`。启用 FFmpeg 的 HarmonyOS 构建会在 C/C++ 编译与链接中使用相同的带版本 compiler target，同时保留 OpenHarmony sysroot、MUSL 选择与 availability 检查。

2in1 OpenGL 二进制硬依赖 `libGLv4.so`。若镜像缺少该库，动态加载器会在原生初始化之前拒绝 NAPI 模块；二进制不会切换到 OpenGL ES。

Android 打包是从 Apple Silicon macOS 执行的交叉构建。打包器使用本机 CMake 3.28 或更高版本与 `Unix Makefiles`，从本机 SDK 的 `ndk` 目录选择完整稳定版 NDK r27 或更高版本中的最高版本，并传入 `ANDROID_PLATFORM=android-24`、`ANDROID_ABI=arm64-v8a` 和 `ANDROID_STL=c++_static`。项目不会自带 SDK 或 NDK。Lua、LuaSF、Runtime、Core、cjson、SFML 与可选 FFmpeg target 均为静态库；唯一共享输出为 `libludork.so`，Gradle 将其作为预构建 `jniLibs` 使用。此流程不使用 Android Studio SDK CMake 或 Ninja。

### 3. 加载运行时模块

```lua
local Engine = require("Engine")
local GlobalCore = require("GlobalCore")
local GlobalFunctions = require("GlobalFunctions")

local Components = GlobalFunctions.Components
local UI = GlobalFunctions.UI
local NodeGraph = GlobalFunctions.NodeGraph
local Manager = GlobalFunctions.Manager
```

以上三个根模块必须按所示顺序加载。`GlobalFunctions` 分组通过对应 table 访问，不得泄漏到模块根。Standard 全局已经安装；`CoreSystem` 不是运行时模块。

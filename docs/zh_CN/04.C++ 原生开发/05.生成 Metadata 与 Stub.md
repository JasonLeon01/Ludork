# 生成 Metadata 与 Stub

生成文件属于构建产物，不得手工修改。

一份声明生成四类输出：

1. 稳定的 `<Module>.<NativeClass>.auto.cpp` 注册单元，以及原生 Lua 模块使用的唯一 `<Module>.stub.auto.cpp`；
2. Lua 语言工具使用的 `Scripts/stub/<Module>.d.lua`；
3. 编辑器使用的 `Scripts/<Module>_meta.lua`；
4. `<Module>.traits.auto.hpp`，包含模块内部使用的类型转换特征。

这些输出必须在规范模块路径、类名、函数分组与参数顺序上保持一致。Metadata 还携带 Blueprint 执行信息与编辑器信息。

类文件名由完整限定 C++ 类型名决定，不受 Lua `name` 选项影响。`<Module>.stub.auto.cpp` 负责模块注册、按绑定顺序调用类单元，并提供 LuaLS stub 写入函数。

生成的名称和 metadata 收录范围由声明决定，规则见[绑定类](<02.绑定类.md>)和[函数、事件与执行](<03.函数、事件与执行.md>)。LuaLS stub 包含完整的脚本 API，也包括未纳入蓝图 metadata 的成员。

Core bindgen 和 LuaSF 会在 `.d.lua` 中保留多行 `///` 文档，并将 `\param`、`\return` 等已识别的 Doxygen 命令转换为对应的 `@` 形式。

## 默认值与类型

| C++ 值类型 | Blueprint metadata | LuaLS |
|---|---|---|
| 具名绑定类型 | 完整模块/类型引用 | 完整限定类型名 |
| `std::vector<T>` 或 `std::array<T, N>` | `{ list = T }` | `T` 数组 |
| 字符串键映射 | `{ dict = T }` | 以字符串为键、`T` 为值的字典 |
| `std::pair<T1, T2>` 或 `std::tuple<T...>` | `{ tuple = { T1, T2, ... } }` | 固定位置的字段，如 `{ [1]: integer, [2]: string }` |
| `std::variant<T...>` | `{ union = { T1, T2, ... } }` | 各分支组成的联合类型 |
| `std::monostate` | `"nil"` | `nil` |
| `std::optional<T>` | `T` | `T` 或 nil |
| `pure_data` 类型 | `any` | 递归类型别名 `<Module>.<Name>Value` |
| `std::function` 或 `StrictFunction` | `function` | 声明的回调签名 |

这些映射同样适用于嵌套类型。显式声明的 metadata 类型 `Pair` 用于选择双分量数值控件，与 C++ 中可包含不同类型元素的 pair 或 tuple 不同。Lua 转换规则见[运行时值边界](<09.运行时值边界.md#lua-值转换>)，回调返回值校验见[严格回调](<03.函数、事件与执行.md#4-声明严格回调>)。

Bindgen 可从受支持的布尔、数值、字符串或空表成员初始化表达式中推导默认值。复杂默认值使用[注解的花括号语法](<02.绑定类.md#2-声明属性>)。Variant 的 `{}` 初始化选择首个分支；默认值有歧义时，应显式指定分支。显式指定的联合类型默认值不受支持时，生成会失败。

末尾参数的默认值保留其声明位置；显式 nil 默认值使对应输入保持未设置。生成的结构、带分支标记的联合类型字面量及编辑器行为见[蓝图 metadata 契约](<../03.Lua 与蓝图脚本/04.蓝图脚本/02.Metadata 结构与 Decorator.md>)。

LuaSF 通过 `LUASF_CALLBACK_CODECS_FILE` 提供具有特殊调用约定的回调别名。Bindgen 在展开底层类型前按别名选择转换器，并在嵌套容器中保留这一选择。清单缺失、不兼容或底层类型不匹配时，生成或编译会失败。

## 重新生成

正常运行 CMake 构建即可新增、更新或删除生成的类文件和模块输出。Bindgen 只写入有变化的内容，其余文件保留原名与时间戳。如果生成结果未更新，请确认带注解的头文件已纳入模块的公开头文件配置，再检查生成器诊断并重新构建。

即使生成内容未变，修改头文件仍可能触发依赖它的类文件重新编译。

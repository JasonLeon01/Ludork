# Blueprint Metadata

`_METADATA` 是 Blueprint 字段、签名、编辑器控件与执行协议的纯数据 schema。它告诉编辑器哪些 Lua 与 C++ 成员可编辑或作为 Blueprint 节点。metadata 文件在隔离的 Lua state 中运行，最终必须返回一个名为 `_METADATA` 的纯数据 table。

```lua
local _METADATA = {
    SoundFilter = {
        attrs = {
            "volume",
        },
        volume = {
            type = "float",
            default = 1.0,
        },
        apply = {
            type = "function",
            parameters = {
                "source",
                source = { "Engine", "SoundSource" },
            },
            ["return"] = {},
            Pure = false,
        },
    },
}

return _METADATA
```

## 类型与字段

每个类型 table 包含有序 `attrs`，不得依赖 Lua table 键顺序。字段必须声明 `type`；只有 Blueprint 已保存该字段或 metadata 提供 `default` 时，才会作为普通有值字段显示。

基础类型名包括 `bool`、`int`、`float`、`string`、`function`、`event`、`any` 和 `Pair`。SFML 类型使用 `sf.` 前缀。Core 类型写成 `{ "Module", "Type" }`，数组在第二项添加 `[]`。

容器类型可以递归组合：`T[]` 是同一元素类型的可变长度列表，`Dict[string, T]` 是仅允许字符串键的字典，`Tuple[T1, T2, ...]` 是固定长度的异构数组。例如 `Dict[string, Tuple[string, any]]`、`Dict[string, int[]]` 和 `int[][]`。

大写的 `Dict[...]` 和 `Tuple[...]` 用于描述元数据类型，与 Standard 的运行时容器 `dict` 和 `tuple` 不同。元数据默认值必须是可转换为 JSON 的纯数据；容器使用普通 Lua 表，不能使用原生 `list`、`tuple` 或 `dict`。接受原生容器的节点引脚必须声明完整类型，如 `{ "_G", "list" }`，或将其列入联合类型。`T[]` 引脚接受 Lua 数组，原生列表需要先通过转换节点处理。

`string` 字段原样保留文本，包括 `"nil"`。将整个值作为表达式输入时，表达式会求值一次，因此 `any` 表达式中的 `nil` 会得到 Lua 空值；保存的容器内部的字符串仍按原文处理。

未设置的节点输入保存为 JSON `null`；若声明了默认值，运行时会采用该值。JSON 值编辑框可直接输入 `null`，函数表达式则通过清空内容来取消设置。

序列化形式由声明的类型决定，空容器也不例外：`Dict` 保存为 JSON 对象，列表和 `Tuple` 保存为 JSON 数组。已知数据结构时，必须使用明确的递归类型。

运行时调用必须传入声明类型的值，转换规则见[运行时值边界](<../../04.C++ 原生开发/09.运行时值边界.md>)。

`component = true` 标记组件字段。复合控件由实际类型决定：矢量、颜色、矩形与 Pair。`Pair` 是二分量数值控件类型，不是固定异构容器 `Tuple`。`RectRangeVars` 为 `sf.IntRect` 增加纹理/范围语义。

## 联合类型与保存字面量

联合类型通过 `{ union = { T1, T2 } }` 列出可选类型分支，在编辑器中显示为 `Union[T1, T2]`。它可以与 `{ list = T }`、`{ dict = T }`、`{ tuple = { T1, T2 } }` 嵌套使用，这三种写法分别对应 `T[]`、`Dict[string, T]` 和 `Tuple[...]`。

初始分支和值由已声明的默认值决定；未声明时，新节点选择第一个能提供有效字面量默认值的分支，无法提供的分支保持未设置。切换分支会将值重置为所选分支的默认值。

```lua
type = { union = { "sf.Vector2f", "sf.Vector2u", "nil" } },
default = { ["$type"] = "sf.Vector2u", ["$value"] = { 64, 32 } },
```

对应 JSON 为 `{ "$type": "sf.Vector2u", "$value": [64, 32] }`。`$type` 通过完整类型名或递归容器定义（如 `{ "list": "sf.Vector2u" }`）标识分支，区分存储形式相同的不同类型。

显式空值在 JSON 中写作 `{ "$type": "nil", "$value": null }`，在 Lua 元数据中写作 `{ ["$type"] = "nil" }`。它表示选中 `nil` 分支，不会像“未设置”状态那样采用默认值。

只在类型定义声明了联合类型的位置使用这种封装，嵌套联合类型也适用。运行时调用收到的是还原后的值，不包含封装。值无效时，错误信息会指出具体字段或节点参数。

## 继承

`bases` 是直接 metadata 基类的有序数组，每项完整写成 `{ "Module", "Type" }`。只列参与编辑器字段继承的基类。Script Mixin metadata 不得声明 bases。

## 函数与事件

`parameters` 与 `["return"]` 包含有序名称数组和 name→type 映射。可选 `default` 数组与参数对齐。`Pure` 必须显式声明。`ExecSplit`、`Latent`、`LoopNode` 和事件声明描述由图形运行时（graph runtime）消费的执行协议。

```lua
calculate = {
    type = "function",
    parameters = {
        "value",
        "clamp",
        value = "float",
        clamp = "bool",
    },
    default = {
        nil,
        true,
    },
    ["return"] = {
        "result",
        result = "float",
    },
    Pure = true,
}
```

数组部分固定 pin 顺序，字符串键固定 pin 类型。每个参数默认值必须占据与参数相同的位置，`nil` 表示没有默认值。`["return"]` 中明确列出的 `nil` 仍是输出 pin，空 table 才表示没有输出。只有 `Pure = true` 会移除执行 pin。

## 执行声明

- `ExecSplit = { "success", "fail", success = true, fail = false }` 固定执行输出顺序，并把输出映射到运行时结果值。
- `Latent = true` 表示挂起；有序 `LatentStates` 声明恢复输出及其值类型。
- `Loop = true` 表示循环节点；`LoopNode = "ForEach"` 或 `"ForLoop"` 选择运行时协议。
- `type = "event"` 只创建事件入口；参数和返回仍使用相同签名格式。未显式声明 split 时，事件获得 `ExecSplit = { "default", default = "nil" }`；字符串 `"nil"` 是默认分支的 metadata 标记。

这些声明是对 Blueprint 运行时的执行承诺。Lua 或 C++ 实现必须实际返回 split 值、恢复 latent 状态或执行所声明的迭代。

## 编辑器名称与 decorator

普通类型、字段、函数、事件、pin 和 Blueprint 变量的显示文本由编辑器根据标识符生成。编辑器会拆分 camel case、Pascal case 和下划线边界，并把每个显示单词的首字母大写。例如，`textureRect` 显示为 `Texture Rect`。这只改变显示，metadata 键、运行时成员名和 Blueprint 序列化名称保持不变。

普通成员不得声明 `DisplayName`、`DisplayDesc`、`VariableDisplayNames`、`VariableDisplayDescs`、`ParameterDisplayNames`、`ParameterDisplayDescs`。编辑器不得通过求值 `LOC(...)` 或其他表达式获取 schema 显示名或默认说明。

`ADD`、`IADD` 等运算符节点是唯一例外。当标识符格式化无法表达目标显示时，可以用直接字面量 `Meta.DisplayName`，例如 `+` 或 `+=`。不得用 `LOC(...)` 包装，也不得添加默认 `DisplayDesc`。

`Meta` 保留无法从声明类型推导的编辑器语义，例如 `DropBox`、`PathVars`、`ProgressVars`、`SliderVars`、`RangeVars`、`MoveRouteVars`、`Transfer`、`BlueprintClassVars`、`CommonFunctionVars`、`GeneralDataVars`、`ConfigVars`。

游戏资源的 `PathVars` 使用 `/Game/Assets/Sounds` 这类完整选择根，字段保存完整逻辑路径；`PathRoot = "Project"` 则选择 Script Mixin 等原生工程文件。

`InstVar` 把 string 字段或参数标记为游戏变量名。编辑器用可搜索选择器替换自由文本输入，读取当前游戏变量声明，包括未保存的修改。直接字段使用 `InstVar = true`；若只保留指定 metadata 类型，则使用 `InstVar = { types = { "int", "float" } }`。函数 metadata 通过 `InstVar = { "valueName" }` 把 decorator 投影到指定参数。

`InstVarValue` 将另一个字段或参数关联到已选名称。直接字段把同级字段名写成字符串，例如 `InstVarValue = "openConditionName"`；函数使用 table 投影参数关联，例如 `InstVarValue = { value = "valueName" }`。选择名称后，关联值会使用该声明类型的通用编辑器。Decorator 只改变编辑器选择与输入控件；运行时读写仍由实际的游戏变量实现负责。

```lua
openConditionName = {
    type = "string",
    Meta = {
        InstVar = {
            types = {
                "int",
                "float",
            },
        },
    },
}
openConditionVal = {
    type = "int",
    Meta = {
        InstVarValue = "openConditionName",
    },
}
```

容器 metadata 在直接容器层细化编辑器，但不会改变声明 schema 或序列化形状。`DictKeyMeta` 将其中的编辑器 decorator 应用于每个 string key；`ItemMeta` 应用于每个直接 list item 或 dictionary value。当该 item 是 `Tuple` 时，`ItemMeta.TupleMeta` 用从 1 开始的位置分别声明各槽位的 decorator。`DropBox` 提供 dropdown 的有序字面值。在 dictionary value 的 `TupleMeta` 内，`InstVarValue = "$dictKey"` 是保留引用，解析为当前这一行的 dictionary key；它不是字段名，离开该行就没有意义。

```lua
afterBattleVarChanges = {
    type = "Dict[string, Tuple[string, any]]",
    default = {},
    Meta = {
        DictKeyMeta = {
            InstVar = {
                types = { "int", "float" },
            },
        },
        ItemMeta = {
            TupleMeta = {
                [1] = {
                    DropBox = { "=", "+", "-", "*", "/", "//", "%", "**" },
                },
                [2] = {
                    InstVarValue = "$dictKey",
                },
            },
        },
    },
}
```

该示例仍保存为 JSON object，其 value 是两个元素的 JSON array。key 选择器只列出已声明的 `int` 与 `float` 游戏变量；tuple 第一项是运算符 dropdown，第二项使用已选 key 对应的数值编辑器。Metadata 只约束编辑器创作；运行时游戏变量 table 不强制声明类型。

`InvalidVars` 列出不应出现在普通 Blueprint 属性编辑器和序列化中的字段。`RectRangeVars` 将 `sf.IntRect` 与图片区域选择器需要的纹理/范围字段关联。Decorator 名称及其有序数据应原样保留，不得另造 `fields`、`nodes`、`events` 等包装结构。

## 安全规则

Metadata 不能包含函数、userdata、thread、循环引用、无限数值或副作用。默认值必须是可转为 JSON 的纯数据。Metadata 字符串只是数据，不得通过求值生成编辑器成员名或节点名；运行时本地化和已本地化的选项值是另一套职责。

Core metadata 根据 `BIND_*` 注解生成，不得手工修改；参见 [生成 Metadata 与 Stub](<../../04.C++ 原生开发/05.生成 Metadata 与 Stub.md>)。

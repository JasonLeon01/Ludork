# Blueprint Metadata

## 范围

本参考定义用于 Blueprint 字段、签名、编辑器控件与执行协议的纯数据 `_METADATA` schema。

Metadata 告诉编辑器哪些 Lua/C++ 成员可编辑或可作为 Blueprint 节点。metadata 文件在独立 Lua State 中执行，最终必须返回名为 `_METADATA` 的纯数据 table。

```lua
local _METADATA = {
    SoundFilter = {
        attrs = {
            "volume",
        },
        volume = {
            type = "float",
            default = 1.0,
        },
        apply = {
            type = "function",
            parameters = {
                "source",
                source = { "Engine", "SoundSource" },
            },
            ["return"] = {},
            Pure = false,
        },
    },
}

return _METADATA
```

## 类型与字段

每个类型 table 包含有序 `attrs`，不得依赖 Lua table 键顺序。字段必须声明 `type`；只有 Blueprint 已保存该字段或 metadata 提供 `default` 时，才会作为普通有值字段显示。

基础类型名包括 `bool`、`int`、`float`、`string`、`function`、`event`、`any` 和 `Pair`。SFML 类型使用 `sf.` 前缀。Core 类型写成 `{ "Module", "Type" }`，数组在第二项添加 `[]`。

容器类型可以递归组合：`T[]` 是同一元素类型的可变长度列表，`Dict[string, T]` 是仅允许字符串键的字典，`Tuple[T1, T2, ...]` 是固定长度的异构数组。例如 `Dict[string, Tuple[string, any]]`、`Dict[string, int[]]` 和 `int[][]`。

首字母大写的 `Dict[...]` 与 `Tuple[...]` 是 metadata schema 描述，不是 Standard 小写运行时容器 `dict` 与 `tuple` 的构造函数。Metadata default 必须使用可转为 JSON 的纯 Lua table；不得把原生 `list`、`tuple` 或 `dict` 值放入 `_METADATA`。运行时容器跨越 metadata、Blueprint、Core 或 JSON 边界前必须显式转换。

声明的 schema 优先于 Lua table 或 JSON 值的当前形状，空容器也不例外。`Dict` 序列化为 JSON object，列表和 `Tuple` 序列化为 JSON array。已知结构的 metadata 必须使用明确的递归类型。

声明的类型也是运行时的权威契约。入口不会为了满足类型而 eval 字符串，也不会猜测 table、tuple 或 vector 的形状。数据读取器在调用接收 API 前，必须构造与声明类型完全匹配的值，例如 `sf.Vector2i` 实例。

`component = true` 标记组件字段。复合控件由真实类型决定：vector、colour、rectangle 和 Pair。`Pair` 是二分量数值控件类型，不是固定异构容器 `Tuple`。`RectRangeVars` 为 `sf.IntRect` 增加纹理/范围语义。

## 继承

`bases` 是直接 metadata 基类的有序数组，每项完整写成 `{ "Module", "Type" }`。只列参与编辑器字段继承的基类。Script Mixin metadata 不得声明 bases。

## 函数与事件

`parameters` 与 `["return"]` 包含有序名称数组和 name→type 映射。可选 `default` 数组与参数对齐。`Pure` 必须显式声明。`ExecSplit`、`Latent`、`LoopNode` 和事件声明描述由 graph runtime 消费的执行协议。

```lua
calculate = {
    type = "function",
    parameters = {
        "value",
        "clamp",
        value = "float",
        clamp = "bool",
    },
    default = {
        nil,
        true,
    },
    ["return"] = {
        "result",
        result = "float",
    },
    Pure = true,
}
```

数组部分固定 pin 顺序，字符串键固定 pin 类型。每个参数默认值必须占据与参数相同的位置，`nil` 表示没有默认值。`["return"]` 中明确列出的 `nil` 仍是输出 pin，空 table 才表示没有输出。只有 `Pure = true` 会移除执行 pin。

## 执行声明

- `ExecSplit = { "success", "fail", success = true, fail = false }` 固定执行输出顺序，并把输出映射到运行时结果值。
- `Latent = true` 表示挂起；有序 `LatentStates` 声明恢复输出及其值类型。
- `Loop = true` 表示循环节点；`LoopNode = "ForEach"` 或 `"ForLoop"` 选择运行时协议。
- `type = "event"` 只创建事件入口；参数和返回仍使用相同签名格式。未显式声明 split 时，事件获得 `ExecSplit = { "default", default = nil }`。

这些声明是对 Blueprint runtime 的执行承诺。Lua 或 C++ 实现必须实际返回 split 值、恢复 latent 状态或执行所声明的迭代。

## 编辑器名称与 decorator

普通类型、字段、函数、事件、引脚和蓝图变量的显示文本由编辑器根据标识符生成。编辑器会拆分 camel case、Pascal case 和下划线边界，并把每个显示单词的首字母大写。例如，`textureRect` 显示为 `Texture Rect`。这只改变显示，metadata 键、运行时成员名和蓝图序列化名称保持不变。

普通成员不得声明 `DisplayName`、`DisplayDesc`、`VariableDisplayNames`、`VariableDisplayDescs`、`ParameterDisplayNames`、`ParameterDisplayDescs`。编辑器不得通过求值 `LOC(...)` 或其他表达式获取 schema 显示名或默认说明。

`ADD`、`IADD` 等运算符节点是唯一例外。当标识符格式化无法表达目标显示时，可以用直接字面量 `Meta.DisplayName`，例如 `+` 或 `+=`。不得用 `LOC(...)` 包装，也不得添加默认 `DisplayDesc`。

`Meta` 保留无法从声明类型推导的编辑器语义，例如 `DropBox`、`PathVars`、`ProgressVars`、`SliderVars`、`RangeVars`、`MoveRouteVars`、`Transfer`、`BlueprintClassVars`、`CommonFunctionVars`、`GeneralDataVars`、`ConfigVars`。

`InstVar` 把 string 字段或参数标记为游戏变量名。编辑器会以 `GameVariables_meta.lua` 为数据源，用可搜索选择器替换自由文本输入。直接字段使用 `InstVar = true`；若只保留指定 metadata 类型，则使用 `InstVar = { types = { "int", "float" } }`。函数 metadata 通过 `InstVar = { "valueName" }` 把 decorator 投影到指定参数。

`InstVarValue` 将另一个字段或参数关联到已选名称。直接字段把同级字段名写成字符串，例如 `InstVarValue = "openConditionName"`；函数使用 table 投影参数关联，例如 `InstVarValue = { value = "valueName" }`。选择名称后，关联值会使用该声明类型的通用编辑器。Decorator 只改变编辑器选择与输入控件；运行时读写仍由实际的游戏变量实现负责。

```lua
openConditionName = {
    type = "string",
    Meta = {
        InstVar = {
            types = {
                "int",
                "float",
            },
        },
    },
}
openConditionVal = {
    type = "int",
    Meta = {
        InstVarValue = "openConditionName",
    },
}
```

容器 metadata 在直接容器层细化编辑器，但不会改变声明 schema 或序列化形状。`DictKeyMeta` 将其中的编辑器 decorator 应用于每个 string key；`ItemMeta` 应用于每个直接 list item 或 dictionary value。当该 item 是 `Tuple` 时，`ItemMeta.TupleMeta` 用从 1 开始的位置分别声明各槽位的 decorator。`DropBox` 提供 dropdown 的有序字面值。在 dictionary value 的 `TupleMeta` 内，保留引用 `InstVarValue = "$dictKey"` 指向当前行的 dictionary key；它不是字段名，在该行以外没有含义。

```lua
afterBattleVarChanges = {
    type = "Dict[string, Tuple[string, any]]",
    default = {},
    Meta = {
        DictKeyMeta = {
            InstVar = {
                types = { "int", "float" },
            },
        },
        ItemMeta = {
            TupleMeta = {
                [1] = {
                    DropBox = { "=", "+", "-", "*", "/", "//", "%", "**" },
                },
                [2] = {
                    InstVarValue = "$dictKey",
                },
            },
        },
    },
}
```

该示例仍保存为 JSON object，其 value 是两个元素的 JSON array。key 选择器只列出已声明的 `int` 与 `float` 游戏变量；tuple 第一项是运算符 dropdown，第二项使用已选 key 对应的数值编辑器。Metadata 只约束编辑器创作；运行时游戏变量 table 不强制声明类型。

`InvalidVars` 列出不应出现在普通 Blueprint 属性编辑器和序列化中的字段。`RectRangeVars` 将 `sf.IntRect` 与图片区域选择器需要的纹理/范围字段关联。Decorator 名称及其有序数据应原样保留，不得另造 `fields`、`nodes`、`events` 等包装结构。

## 安全规则

Metadata 不能包含函数、userdata、thread、循环引用、无限数值或副作用。默认值必须是可转为 JSON 的纯数据。Metadata 字符串只是数据，不得通过求值生成编辑器成员名或节点名；运行时本地化和已本地化的选项值是另一套职责。

Core metadata 根据 `BIND_*` 注解生成。不得手改生成的 Core metadata；参见“C++ Runtime 与绑定”。

## 验证

- 在编辑器 metadata state 中加载每个 `_meta.lua`，确认返回 `_METADATA`。
- 对照 runtime 声明检查 `attrs`、`bases`、parameters 与 returns。
- 根据声明的递归 schema 校验空容器。
- 在 Blueprint runtime 测试中执行每种声明的执行协议。

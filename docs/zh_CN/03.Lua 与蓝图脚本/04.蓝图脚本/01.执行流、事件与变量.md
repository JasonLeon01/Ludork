# 事件、Common Function 与 Blueprint 流程

Blueprint 将类默认值与可视化图保存在 `Data/Blueprints`。Common Function 保存可复用图。两者均根据当前项目 metadata catalogue 校验。

通过 **游戏 → 新建蓝图**创建 Blueprint，选择有效父类，添加受支持的事件入口，连接执行与数据 pin，然后校验并保存。多个图需要相同操作时，按 F7 打开 Common Functions。Script Mixin Blueprint 遵循独立的 [Script Mixin](<../03.脚本 Mixin/01.编写工作流.md>)契约，不执行其图。

![带有事件图和已连接节点的 Blueprint 编辑器](../../../_images/editor/blueprint-editor.png)

*图通过执行 pin 表达执行顺序，通过类型化数据 pin 传递值。*

![显示可操作诊断的 Blueprint 校验窗口](../../../_images/editor/blueprint-validation.png)

*校验会指出普通保存前必须修正的 class、graph、node、link 或 pin。*

## 目标

构建具有明确执行流、类型化数据 pin、可复用 Common Function 与有意默认值的有效事件 graph。

## 前置条件

- 具有当前 metadata 的图模式 Blueprint。
- 受支持事件入口与工作流需要的节点 API。
- Common Function 与被引用项目数据的稳定名称。

## 步骤

1. 添加一个受支持事件入口。
2. 添加节点，先连接执行再连接数据，并设置每个必需的未连接输入。
3. 把重复逻辑移动到通过 F7 打开的 Common Function。
4. 校验、保存，再保持 Console 可见并运行事件。

## 事件

事件是以 `type = "event"` 声明的入口，提供有序数据 pin 和执行输出。没有显式 split 的事件会获得默认执行输出。

## Common Function

打开 **数据库 → 公共函数**（F7）。Common Function 拥有一个可复用 graph，可新建、重命名、复制、删除、整理和校验。应通过对应节点调用，不要复制图片段。

## 执行语义

- `Pure = true` 移除执行输入输出；存在返回值并不代表 pure。
- `ExecSplit` 把命名执行输出映射到结果值。
- `Latent` 节点挂起 graph，并在之后通过声明状态恢复。
- 所有蓝图事件在同一 graph 实例、同一事件 key 的当前执行仍有未完成 latent 节点时，都会直接丢弃重复触发；该次执行的全部 latent 工作结束后才接受新触发，不同 graph 实例和事件 key 互不阻塞。
- `LoopNode` 描述循环体与完成行为。
- 数据 link 连接类型兼容 pin；执行 link 连接流程 pin。

## 默认值与引用

参数默认值按位置与参数名数组对应。显式 `nil` 返回类型仍是数据输出；空 return table 才表示没有输出。

## 调试

从事件起点开始跟随执行 link，再检查数据来源和未连接默认值。移动或重命名节点函数后应校验。

## 限制

Graph 校验检查结构与 metadata 契约，不会证明玩法正确，也不会执行 latent 工作。

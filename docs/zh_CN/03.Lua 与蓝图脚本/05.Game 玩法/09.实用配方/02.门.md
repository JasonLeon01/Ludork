# 门

## 目标

创建通过背包钥匙或命名游戏状态条件开启的门。

## 前置条件

- 有效的 `Source.MapActors.DoorBase.DoorBase` 蓝图父类，以及门的 sprite sheet。
- 与所选工作流匹配的 Item 或游戏变量标识符。

## 步骤

门的蓝图集成了碰撞行为、开门动画、门状态，以及可选的钥匙或条件。

开门动画结束后，只要地图放置 tag 非空，`DoorBase` 就把它记录为已销毁。地图重建时会跳过这个放置实例，因此门在跨地图与存读档后依然消失。

`DoorBase` 继承 `tickable = false`，只在开门或反向过程中启用 tick。

### 钥匙门

1. 从 `Source.MapActors.DoorBase.DoorBase` 派生一扇通用门，配置纹理、矩形、碰撞与开门默认值。
2. 再派生一扇按颜色区分的门。Game 项目的 `BP_Door_Y.json` 继承 `BP_Door_General`，保存 `needKeyID = "KEY_Y"`。
3. 在 `onCollision` 中拒绝正在开门的门，并要求满足 `MeetPlayer`。
4. 读取 `needKeyID`，调用 `GetItemCount`，再把数量与 1 比较。
5. 成功后通过 `SUPER` 调用继承的碰撞流程，然后移除一把钥匙。失败分支可以不连接，也可以接上明确的反馈。

钥匙 ID 必须同时匹配 Item 成员与它对应的拾取蓝图，例如 `KEY_Y` 与 `BP_Item_Key_Y.json`。

### 条件门

`Mixins/Doors/ConditionDoor.lua` 轮询 `openConditionName`，并与 `openConditionVal` 比较。名称为空时不轮询。配置了名称却没有对应变量时，从 0 开始取值。值达到阈值后调用 `openDoor`。

`openConditionName` 使用仅限数值类型的 `InstVar` 选择器，因此只列出游戏变量管理器中的 `int` 与 `float` 声明。`openConditionVal` 使用 `InstVarValue`，因此沿用所选声明的数值编辑器。Game 生成的声明中包含 `MTExample = 0`，供这条工作流使用。

测试时覆盖以下情况：没有钥匙、只有一把钥匙，以及开门过程中反复碰撞。还要测试钥匙缺失或改名、数值选择器过滤、条件低于、等于和高于阈值、存档变量恢复与地图重载。打开多扇已放置的门，离开地图再回来，然后存读档。确认每扇门都能独立保持消失。重命名 ID 之前先检查引用。

## 限制

门逻辑不负责场景跳转，跨地图移动使用 Teleporter。重命名钥匙或条件标识符时，必须同步更新所有已存储的引用。

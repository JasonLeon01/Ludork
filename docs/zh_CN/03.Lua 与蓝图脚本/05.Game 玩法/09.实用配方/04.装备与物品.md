# 装备与物品

## 目标

创建背包 ID 稳定、槽位有效、成员图行为职责聚焦的物品与装备记录。

## 前置条件

- 包含所需背包标识符与槽位标识符的 Item、Equip 与 Class 通用数据。
- 从 `Source.Item` 或 `Source.Equip` 派生的蓝图父类。

## 步骤

Item 与 Equip 的 schema 把可复用定义与背包实例分开。

- 用 Item 的 `usable` 与 `cost` 字段控制菜单可用性与是否消耗。
- 背包内的使用逻辑放在 `onUse`，敌人掉落行为放在 `onDrop`。运行时把两者都作为 `GeneralDataGraphAbility` 激活：`onUse` 以 Player 为 target，`onDrop` 以生成的 Item Actor 为 target。
- Equip 的 `slot` 必须匹配所选 Class 的槽位字典。
- 属性变化写进 `attrPlus`。`onEquip` 与 `onUnequip` 图只留给特殊行为。
- 图标放在 `Assets/Icons` 下，并通过资源选择器指定。

## Game 装备

`BP_Equip_Sword_A.json` 继承 `Source.Equip`，设置 `ID = "Sword_A"`，由该 ID 解析 Equip 成员。

`attrPlus` 会变成以槽位为来源的 Infinite Gameplay Effect。装备时先应用它，再执行 `onEquip`；卸下时先移除它，再执行 `onUnequip`，因此替换装备不会留下旧的 modifier。

## Game 物品

`BP_Item_Key_Y.json` 继承 `Source.Item`，设置 `ID = "KEY_Y"`，同时匹配 Item 成员与黄门的 `needKeyID`。

持有一件 Item 会授予它的 `onUse` ability，移除最后一件时撤销。`Player:activateItem` 的目标就是该 Player，由成员图决定何时消耗 Item。`cost` 始终是菜单策略，而不是 Ability System 的 cost。

测试购买、出售、掉落、使用、装备替换与存档恢复。读档会重建已保存的 Item ability 与装备 Effect，但不重放成员图。还要测试图标缺失、未知 ID、非法槽位与成员改名。

## 限制

重命名成员不会自动修复已存储的引用。Class 槽位不匹配和未知记录 ID 同样是明确的数据错误。

# 运行时数据、配置与存档

## 配置

`Data/Configs` 存放游戏配置 JSON，`Main.ini` 存放可变的启动与用户设置。应使用配置 API 与编辑器字段，让未知的 section 和 key 在一次读写往返后仍然保留。

资源型 Config `file` 字段保存完整的 `/Game/Assets/...` 路径，`base` 与 `ext` 只约束选择器。Data 引用单独处理：`System.json` 的 `startPlayerBlueprint` 以 `root = "Data"` 相对 `Data/Blueprints` 保存，并转换为 `Data.Blueprints.*`；`startRegion` 指定初始区域。两者都只影响新游戏，存档保留自己的玩家类与区域。

格子尺寸由编译后的引擎固定（默认 `32`），通过 `Engine.GetCellSize()` 读取。`System.json` 与 System 配置编辑器都不配置该值。遗留的 `System/cellSize` 字段既不会被使用，也不可编辑，更不会转换为运行时设置。

Game 项目的 Lua 配置模块位于 `Scripts/Source/Configs`，通过 `Source.Configs.*` 加载。

`Source.Locale.Core.DEFAULT_LANGUAGE` 统一定义初始语言和回退语言（`en_GB`），`Source.Configs.Main` 使用同一值。`Source.Configs.MapConstants.WORLD_MANIFEST_FILE` 定义组合世界清单文件名（`_world.json`）。数据读取和存档统一使用 `Engine.ResourceFileConstants` 的后缀。

编辑器模式下，`LUDORK_EDITOR=1` 选择项目内的 `Main.ini`。普通打包运行使用平台用户数据位置，并在适用时以打包的配置作为初始来源。

Android 发行包会在原生运行时启动之前，把不可变的运行时资产镜像到 `filesDir/ludork/runtime/<runtime-hash>`。可变配置与存档使用 `filesDir/ludork/user-data`，绝不会写回该带版本的运行时目录，也不需要外部存储权限。

## 运行时状态

不可变的定义放在蓝图、Config 或通用数据文件中，可变的游玩期状态放在游戏实例、Actor 或组件上。不要把临时状态写回源 JSON。

`Data.GetClassData(path)` 公开共享的会话定义，参见 [事件、公共函数与蓝图流程](<../03.蓝图脚本/01.执行流、事件与变量.md#类定义与会话生命周期>)。

用 `Source.Configs.GeneralDataTypes.Create` 构造通用数据属性集。[通用数据与文本配置](<../../02.编辑器用户指南/05.通用数据与文本配置.md>) 页面说明值转换与默认值。

### 玩家

`GameInstance` 用 `_playerKeys` 保存玩家顺序，用 `_players` 保存玩家对象，键是 `Player.ID` 中稳定的 Player 通用数据 key。Player key 必须非空且唯一。`getPlayers()` 返回实时的 key 字典，`getPlayerKeys()` 返回实时的有序 key 数组；数组的第一个 key 标识 `getPlayer()` 使用的主 Player。`getPlayerByIndex()` 按同一顺序解析零基索引，`setPlayer(playerKey)` 把已存在的 key 移到首位。

存档用同级的 `playerKeys` 与 `players` 字段保留同样的结构。顺序由 `playerKeys` 决定，其中每个 key 必须在 `players` 中恰好有一项与之对应，且恢复后的 `Player.ID` 相同。

每个 Player 在 `attr` 下保存 `getNumericAttributeBases()` 返回的全部数值型 Attribute Set Base。派生的 Current 值不保存，非数值属性从 Player 通用数据重建。数值必须有限，并符合生成的 `int` 或 `float` schema。旧存档缺少的字段保留恢复后的成员初始 Base。

存档保留库存与装备的数量、已装备 ID 和 State 层数。读取时先恢复全部 Base 值，再恢复 Item ability、装备 Effect 与 State Effect，不执行初始装备或成员图。Handle、派生 Current 值、临时 Effect、ability spec 与 tag 都不保存。需要持久化的新增内容必须有自己的稳定记录与重建步骤。

玩家存档要求 `attr` 同级存在字符串 `customName`。`""` 表示使用通用数据的本地化默认名。非空值必须已去除首尾空白，并符合 [Source.Player](<../07.源码类/09.Player.md>) 中的规则。

### 游戏变量

运行时从生成的 `Scripts/Source/Configs/GameVariables.lua` 读取初始值。启动运行时之前，先在 [通用数据与文本配置](<../../02.编辑器用户指南/05.通用数据与文本配置.md#游戏变量管理器>) 中保存修改。list 与 dictionary 初始值是普通 Lua table，而不是 Standard 容器；空 table 经过 JSON 序列化后不保证保留 array 或 object 形状。

`GameInstance:init` 会深拷贝生成的运行时映射，因此每个新游戏都获得彼此独立的可变初始值。Game 声明了 `MTExample = 0` 与 `ShopPrice = 20`。运行时系统仍可创建动态名称，但只有编辑器声明过的名称会出现在 `InstVar` 选择器中。

读取存档时，会用该存档保存的 table 替换新建实例上的变量表。因此生成的初始值只作用于新游戏：修改、增加或删除声明都不会迁移或合并已有存档槽。修改声明的类型同样只重置项目初始值，不会改变存档中已经保存的值。

变量快照包含被监听字段的当前逻辑值。`deepcopy` 不复制 monitor 代理与订阅，因此 ConditionalActor 的监听只存在于当前游戏实例中。恢复记录之后，`onCreate` 订阅恢复后的变量并重新计算可见性，不需要额外的存档字段。

### 地图 Actor 身份

地图 JSON 中的摆放 `tag` 会成为 Actor 的地图持久化 tag。`GameMap:getActorByTag` 与 `GameInstance` 的持久化记录只通过 `Actor:getMapTag()` 识别 Actor，`Actor.tag` 保持独立。没有地图持久化 tag 的 Actor 不会被记录，这些记录中的地图路径会统一规范化。

需要在重建地图后继续存在的运行时生成 Actor，用自己的地图摆放 tag 写入 added Actor 记录。该 Actor 之后被销毁时，对应的 destroyed 记录会屏蔽这条已保存的新增记录。Reborn 敌人沿用这组成对的既有记录，而不复用原摆放对象的 tag。

大地图运行时 tag 在摆放中使用 `<child-file-stem>.runtime_default_<N>`，在空洞中使用 `<world-directory>.runtime_default_<N>`。所有 tag 在大地图存续期间都会保留，冲突会失败。编辑器 tag 在整个大地图范围内唯一，且在地图重命名时保持稳定。

### 组合式大地图持久化

即使从子地图进入，当前 `map` 也保存清单路径。Player、added、moved 与 destroyed 记录都使用该身份、大地图坐标和全局 tag。added 或 moved 记录冲突会导致加载失败。

added Actor 在 `actorPositions[tag]` 存在时按该位置恢复，否则恢复在原始位置。destroyed tag 会被跳过。摆放 Actor 随子地图 payload 一起恢复，不产生远处子地图的 I/O；空洞中的 Actor 可以立即恢复。

`worldMovedActors` 管理位于定义子地图之外的 authored root，保存身份、owner、图层覆盖和大地图位置。它们只在该 owner 处重建。返回或销毁会移除 moved 记录。

销毁某个 tag 会移除它的 moved 记录，并在不加载缺失子地图的前提下屏蔽 authored、added、驻留和进行中的实例。被屏蔽的 tag 保持保留状态；非法记录与冲突都会失败。

地形记录使用子地图路径与局部坐标。它们在该子地图构建时应用，并只更新受影响的存活图层。空洞不能拥有地形改动。

大地图存档必须包含 `worldMovedActors`。moved 快照保留重建身份、类变量覆盖、图层与位置，但不保留任意实例字段、Lua 私有状态或计时进度。这些内容需要单独持久化，或通过 `onWorldWake` 补算时间。

## 存档

[实时调试](<../../02.编辑器用户指南/08.运行、调试与打包.md#实时调试>) 不写入项目文档，也不改变存档 schema、存档槽或持久化记录。该次运行中存档仍可能保留被实时修改影响的玩法状态。

Game 项目的存档 schema 版本为 `1`，只支持当前结构与版本。`SaveCodec` 会拒绝不兼容的存档，不做迁移。开发期的 schema 改动可以不提升版本号。

`telepoints` 把规范化后的地图路径映射为有序的 `{ position = {x, y}, tag = "raw tag" }` 记录。运行时位置使用 `sf.Vector2u`，tag 保持未本地化的字符串。`GameInstance:recordTelepoint(mapPath, position, tag)` 为每个“地图 + 坐标”组合保留第一条记录，`getTelepoints(mapPath)` 返回这些记录。大地图记录使用清单身份与大地图坐标。

`GameInstance:getCurrentMapPath()` 返回当前地图或 `nil`。`getVisitedMapPaths()` 返回排序后的传送点地图路径，`getTelepointsForMap(key)` 匹配时忽略扩展名。两个集合查询都返回副本。`restoreFromData(data)` 把校验通过的存档恢复到实例中。

`SAVE_AS_LDC` 为 `false`（默认）时使用普通 `.json` 存档，为 `true` 时使用加密 `.ldc` 存档。**加密存档内容** 设置 C++ Source 包的原生默认值。包括 Standalone 在内的任何项目，都可以在 `Scripts/Entry.lua` 顶部、所有 `require` 之前用全局赋值 `SAVE_AS_LDC = true` 或 `false` 覆盖它。`Source.Save` 在首次加载时确定格式，之后再赋值不再生效。

`GetSavePath(slot)` 按从 1 开始的 slot 编号选择扩展名。应使用稳定的编号，在序列化之前校验数据，显式处理文件缺失，并避免硬编码存档目录。

存档加密与项目 JSON 加密彼此独立，尽管 Pack Options 把两者都归入 **加密游戏数据**。

## 数据边界上的原生容器

把 Standard 的 `list`、`tuple` 与 `dict` 值保存为 JSON 之前，先转换为 Lua table：

```lua
local cjson = require("cjson")
local encoded = cjson.encode(payload:toTable())
```

解码 JSON 得到的是普通 Lua table。tuple-key 字符串、`cjson.null` 空槽和 record-array 的重建见 [Ludork Lua进阶](<../../01.快速入门/04.Ludork Lua进阶.md>)。绝不要持久化内部 tuple hash。

## 限制

切换存档格式不会重命名或迁移已有存档槽。应在发行前确定格式，或自行提供迁移。存档升级、原子写入、备份、云同步与 tuple-key 记录格式仍由项目负责。

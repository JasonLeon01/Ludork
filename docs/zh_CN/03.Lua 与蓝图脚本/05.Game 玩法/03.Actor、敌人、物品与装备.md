# Actor、敌人、物品与装备

## Actor 与 Character

`Actor` 提供地图归属、位置、生命周期以及与碰撞相关的行为。Character 风格的类在此基础上增加移动与朝向。公开的类默认值应写在 Lua 类表上，`init` 只用于构造参数和私有运行时状态。

`Actor.visible` 默认为 `true`。直接赋值只修改 Actor 自身的标记，`getVisible` 读取该值；`setVisible(value, applyToChildren = true)` 还可以一并更新子 Actor。自身或祖先隐藏时，Actor 不绘制、不遮挡光线、不碰撞、不触发 overlap、不占用寻路格，也不接受地图点击交互。隐藏的敌人不贡献移动危险，也不进入 Enemy Book 列表。可见性变化会刷新受影响的缓存。隐藏只保留实例，不停止 Tick，也不改写碰撞与动画设置。

### 条件出现

[Source.ConditionalActor](<../07.源码类/12.ConditionalActor.md>) 增加了 `conditionVariable`、`conditionOperator` 和 `conditionValue`。先选择一个已声明的数值、布尔或字符串变量，再选择比较运算符和比较值；比较值的控件由变量类型决定。变量名为空时不进行条件控制。数值支持 `==`、`~=`、`>`、`>=`、`<`、`<=`，布尔和字符串只支持 `==`、`~=`。非法数据直接报错，不做类型转换。

Enemy、Item、Equip、DoorBase、Teleporter 以及 Game 项目中直接放置在地图上的 Actor 蓝图都继承这一行为，Bottle 和 Gem 则保留各自的 Script Mixin。`onCreate` 完成订阅并立即求值；之后再写入变量会更新可见性，条件转为不成立时 Actor 重新隐藏。隐藏期间 Actor 仍在监听。`onDestroy` 和大地图休眠会退订，大地图唤醒则重新订阅并求值。覆盖生命周期时必须继续调用父事件。EnemyDamageText 保留自己独立的提示行为与 Tick 策略。

普通地图加载会先绑定 Scene、当前地图身份和玩家位置，恢复 added、moved 与 destroyed 记录，然后在地图的 Player 就绪之后初始化存活的 Actor。切图与 Scene 销毁会释放旧订阅，且不产生销毁或拾取事件。存档保存变量当前值，但不保存订阅，也不保存由条件推导出的可见性。已拾取的 Actor 继续沿用原有的销毁记录保持缺失。

### 组合式大地图中的 Actor

`WorldGameMap` 维护一份大地图坐标的 Actor registry。跨过已就绪的子地图边界时，同一个实例迁移到新的归属。空洞仍属于大地图。启用碰撞的 Actor 不能进入未加载的摆放，无碰撞的 root 则休眠并异步请求它们。

只有位于 Active 32×32 格 chunk 中的 root 参与模拟与绘制。离开时调用 `onWorldSleep()`，返回时调用 `onWorldWake(elapsedSeconds)`，两者都不替代 `onCreate` 或 `onDestroy`。从未激活过的 Prepared root 不接收生命周期回调，也不会被玩法查询返回。

Tile 与 Actor 的绘制顺序遵循清单中的 `layerOrder`。仅运行时存在的图层按首次使用的顺序追加。Player 在所属图层中始终保持最后。隐藏子地图的某个 Tile 图层时，该图层的 Actor 也退出颜色与光照 surface 绘制。

`getActorByTag` 会在不加载子地图的前提下查找 Active Actor 以及激活后休眠的驻留 root。被淘汰的 Actor 在重新加载前保持缺失。

地图索引与流送使用原生 root-first BFS 遍历 Actor 树，并保持 child 顺序。重复的 Actor 和环都属于错误。

`SceneMap:recordDestroyedActorTag` 会在驻留 payload 和后续子地图 payload 中屏蔽该身份，且不会加载缺失的子地图。被屏蔽的 Actor 无法执行生命周期、无法被查询，也不会在淘汰后重新出现。接收 Actor 参数的 `recordDestroyedActor` API 仍然只负责记录。

## 移动、寻路与动画

`GameMap` 缓存图块通行性和动态 Actor 占用。Actor 列表或地形发生变化时，会重建相应缓存。普通移动只更新一个 Actor 的占用；寻路在运行 A* 之前，先核对占用格发生变化的 Actor。A* 与实际移动使用同一条 Dir4 边规则：每个新进入的前导格都必须允许从来源图块离开，并允许从目标图块的反方向进入。点击移动对普通目标和单格受阻目标都复用直接 A* 的结果。若移动 Actor 的完整占用范围使该结果不可用，点击移动改为搜索目标的相邻格。碰撞目标仍是最后尝试的一步，因此它的碰撞交互照常执行。使用该回退且不可通行的目标没有碰撞体时，玩家停在相邻格，而不是向目标顶撞。朝普通无碰撞、且 `onOverlap` 可执行的 Actor 移动时，玩家停在它旁边，不进入其格子。显式点击 Teleporter 时则会进入选中的占用格，由 overlap 完成传送。

大地图寻路可以跨越已加载的子地图边界，但把未加载的子地图视为不可用，且不产生隐式 I/O。空洞仍可通行，其顶层材质为 `nil`。

稀疏大地图的就绪、通行性、Dir4 与顶层材质查询都在原生层完成。Prepared 范围决定移动能否进行，材质查询则使用独立的就绪规则。

`GameMap.MapViewRect` 定义逻辑屏幕上的地图画布，默认值为 `sf.IntRect.new(192, 32, 416, 416)`。它的位置决定画布落点，尺寸同时决定裁剪后的绘制范围和 Camera 视野大小。某个轴小于画布时，地图在该轴内居中；轴大于画布时，限制在可滚动范围内。地图绘制、指针坐标转换、世界与 UI 定位、动画、光照、雾、远景和天气共用这个矩形。矩形之外的指针输入会被忽略。

`PathRouteState` 持有路线的一份副本，并公开一个随路线变化的 revision。只有该 revision 变化后，预览渲染器才刷新缓存路线；它复用矩形图形，并在玩家进入另一个地图格时裁剪可见路线。图集帧只改源位置、纹理矩形尺寸不变时，Actor 边界不会刷新；帧尺寸变化仍会刷新缓存边界与占用格。

Domain、Flank 与 Blockade Effect 授予 `Gameplay.Movement.Hazard`。移动与 `MovementDangerGrid` 都使用 `MovementSpecials.Preview`，由它派发 `Event.Movement.QueryHazard`，因此空间规则要保留在这条路径上。Domain 使用曼哈顿距离范围，Flank 要求敌人位于相对的相邻两侧，Blockade 影响相邻格。正贡献会累加。

取得 Enemy Book 后，`EnemyDamageHintLevel` 可选择不显示提示（`NONE`，`0`）、显示敌人读数（`BATTLE`，`1`，默认）或同时显示敌人与地图格读数（`MAP`，`2`）。提示不影响玩法。

点击寻路始终排除正危险格，即使提示尚未显示；显式点击的目的地除外。点击 Domain 或 Blockade 敌人时，只移除该目标的贡献，包括它在 Flank 中的那一侧。玩家不会占用的碰撞与 overlap 目标忽略目的地格的危险。

新进入 Active 的大地图 chunk 会使危险缓存失效。完整网格只在需要地图提示或点击寻路时才生成，单格查询仍只计算本格。危险 revision 只在影响剩余路线或某个可进入的敌人目标时才使移动失效。失效的路线退回最后一个完整的格子并重新规划。

## 敌人

Enemy 蓝图选择一个 Enemy 通用数据成员。`GeneralDataTypes.Create` 把它复制为 `EnemyAttributeSet`；`Battler` 通过 `attributes` 公开该属性集，并持有它自己的 `AbilitySystemComponent`。Enemy 通用数据没有成员事件，战斗行为使用显式的 Gameplay Ability 与 Effect。

`MAXHP` 是敌人的虚拟耐久，敌人自身不保存可变的 `HP`。Player 的 `HP` 属于 `PlayerAttributeSet`，初值 `1000` 来自 Player 通用数据，不作为蓝图 attribute override 保存。

Player 的 HP Current 在 modifier 之后钳制到 `0..MAXHP`。永久 MAXHP 与 LEVEL 成长只响应 Base 变化，因此临时的 Infinite Effect 不会改变永久成长。

敌人的 `special` 会保留整数次数/范围、仅表示存在的 `""`、`Vampire` 比率、`FixDmg` 数值/表达式以及 `Reborn` 类路径。每一项都会转为一个 Infinite 的 `Special.<id>` Effect，带有同名 tag 和专用的 ability。战斗类 special 修改战斗 Gameplay Event；移动类 special 使用 `Event.Movement.QueryHazard` 与 `Gameplay.Movement.Hazard`。

每个 Enemy 都授予 `Ability.Combat.MotaBattle`。它的计算没有副作用，返回伤害明细和数值形式的 `BattleResult`（`WIN`、`CANNOT_DAMAGE` 或 `LETHAL_COUNTER_DAMAGE`）。碰撞会在 `CommitResult(result)` 之前校验伤害、Game Over、奖励和 State Effect Spec。预览复用同一套计算，但不会修改状态。

`drops` 把每个 Item 蓝图路径映射到一个 `sf.Vector2i` 偏移。有效的掉落会在敌人所在图层生成，作为 added Actor 持久化，并通过 `GeneralDataGraphAbility` 激活其通用数据的 `onDrop` 图。摆放 tag 重复时跳过该掉落。路径无效或目标不是 Item 蓝图都会报错。

[资源、音频、视频与特效](<05.资源、音频、视频与特效.md#shader雾与转场>) 中的击败粉碎特效只影响画面。敌人被销毁时，立即不再阻挡移动和光线。

胜利且双方攻击动画播放完毕后，运行 Enemy Actor 蓝图的 `onDefeat` 事件。事件完成后进入固定结算：应用游戏变量改动、记录并销毁 Enemy、生成掉落或 Reborn 替代者，最后应用奖励与 State。Enemy 通用数据没有 `onDefeat` 图。

带 `Reborn` special 的敌人把该 special 的非空字符串值作为蓝图类路径。原敌人被记录并销毁后，替代者以新的地图摆放 tag 在同一个格子和图层生成，正常执行 `onCreate`，并被记录为 added Actor。因此地图切换与存读档会保持原摆放对象处于销毁状态，并且只恢复一次替代者。`Reborn` 路径无效属于必需数据错误。

`afterBattleVarChanges` 为已声明的 `int` 或 `float` 变量保存 `variableName = { operator, operand }`。运算符包括 `=`、`+`、`-`、`*`、`/`、`//`、`%` 和 `**`。存档中的形状仍是值为双元素数组的对象。

击败准备在结算战斗伤害之前校验已配置的运算。`onDefeat` 之后，结算通过固定的 `Engine.Eval` 表达式和全新的局部变量，按当前变量值再次求值。保存的运算符永远不会作为源码执行。

伤害预览会统计致命一击之前的反击次数。没有回复时，最大 HP `H` 与正的来袭伤害 `D` 产生 `max(ceil(H / D) - 1, 0)` 次反击。`Vampire = R` 在每次非终结反击后回复 `floor(counterDamage * R)`。若非一击必杀的伤害不超过回复量，攻击方无法取胜；否则次数为 `ceil((H - D) / (D - healing))`。`First` 在玩家第一次攻击之前额外增加一次攻击，且敌人满血时无法回复。`FixDmg` 直接使用数值，或先替换当前的 `{m<attribute>}` 与 `{e<attribute>}` 值再对字符串求值。结果为有限非负值时向下取整，并加在回合伤害与先攻伤害之后。

当累积的 Domain、Flank 或 Blockade 伤害击败玩家时，Game 会立即应用该伤害，但要等同批启动的攻击动画中最长的一个播放完毕才进入 Game Over 场景，与普通敌人战斗的时序一致。

## 物品

Item 的成员图把 `onUse` 与 `onDrop` 实现为显式激活的 `GeneralDataGraphAbility` 实例，而不是 Actor 事件。`onUse` 的目标是 Player，`onDrop` 的目标是生成出来的 Item Actor。因此绑定目标的节点要使用 `GameplayEventData.target`，Player State 节点应放在 `onUse` 中。

EnemyBook 物品在自己的 `onUse` 图中通过 [NodeFunctions.Scene](<../06.节点函数/08.Scene.md#showenemybook>) 打开怪物手册。

最高占用图块图层上的碰撞回调，从视觉上最靠上的 Actor 依次执行到最靠下的 Actor。同一图层内，Actor 列表中靠后的条目先绘制、先触发。因此多个可拾取 Item 占据同一格时，一次受阻的移动尝试拾取的是视觉上最靠上的 Item。它的销毁会结束本次碰撞派发，下一次移动尝试再拾取下一个 Item。持续按住方向键时，后续 fixed update 可以继续拾取，不需要先松开按键。

`NodeFunctions.Mota.CenterSymmetricTeleport`、`GoUpstairsSamePos` 和 `GoDownstairsSamePos` 提供 CenterSymmetricTeleport、UpstairsTransportation 与 DownstairsTransportation 的可复用逻辑。相邻楼层节点遵循当前区域的地图顺序，并在切换地图之前按玩家当前的零基坐标检查带持久状态的目标地图。中心对称节点以当前地图上的 `(width - 1 - x, height - 1 - y)` 为目标。每个节点都公开 `Success` 与 `Failed` 执行分支。失败时解析 `FLY_FAIL` 并作为 common tip 显示，且不消耗物品。配置消耗型物品的图时，只把 `Success` 接到 `NodeFunctions.Player.RemoveItem`。

## 装备

装备的 `attrPlus` 会变成一个以 slot 为 source 的 Infinite Effect。它在显式的 `onEquip` 图之前应用，在 `onUnequip` 之前移除。slot 名称必须与 Class 数据一致。

State 是携带 `State.<id>`、stack、modifier 与 ability 的 Infinite Effect。Weak 每层减少 1 点 ATK/DEF，最小为 0。HUD 显示 Ability System 的 Current 值和 Weak 层数，因此 Base 为 10、两层 Weak 时显示 `8 (-2)`。Poisoned 通过 `Event.Combat.ResolveIncomingDamage` 增加伤害。State 图监听 `Event.Movement.Step`（`onWalk`）或 `Event.State.Trigger.<id>`（显式 hook）。

## 运行时引用

把通用数据标识符当作稳定的 key 使用。运行时应用会原样保留每个字符串，因此 class、animation 和装备槽位的 key 都不依赖所选语言。显示名称与说明可以写成带花括号的本地化标识符，只在展示时用 `LOC` 解析，并在语言变化后重新解析。查找表由 [游戏本地化工作流](<../../05.插件开发与安装/06.游戏本地化工作流.md>) 管理。重命名标识符时必须更新每一处引用。

Game 项目的确切 schema 与成员列表见通用数据参考各页，从 [Class](<../../02.编辑器用户指南/09.通用数据参考/01.Class.md>) 开始。Bottle、Gem、门和敌人的实用范例见实用配方各页，从 [消耗品](<09.实用配方/01.消耗品.md>) 开始。

## 限制

通用数据标识符属于项目契约，重命名时不会自动修复。Game 项目的战斗与库存规则只是示例，不是引擎强制行为。

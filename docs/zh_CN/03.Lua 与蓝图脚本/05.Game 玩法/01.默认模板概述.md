# 默认模板概述

Game 既是可运行的参考，也是可复用模板的来源。它展示的是预期的项目形态，而不是最小化的空程序。借助它可以理解归属关系与数据流；复制某个模式之前，先弄清它依赖什么。

Game 只是素材，不是引擎的隐含契约。要在其他项目中依赖某项行为，先在 metadata、LuaLS 声明和 API 参考中确认它属于公开行为。

## 入口与模块

`Scripts/Entry.lua` 初始化游戏并进入原生主循环，按以下顺序加载 Core 模块：

```lua
local Engine = require("Engine")
local GlobalCore = require("GlobalCore")
local GlobalFunctions = require("GlobalFunctions")

local Components = GlobalFunctions.Components
local UI = GlobalFunctions.UI
local NodeGraph = GlobalFunctions.NodeGraph
local Manager = GlobalFunctions.Manager
```

启动时会显式调用下列函数。仅 require 模块不会初始化服务：

| 调用 | 职责 |
|---|---|
| `Source.Locale.Core.Init()` | 在读取配置与选择语言之前加载语言字典。 |
| `Source.Configs.Main.LoadOrCreate()` | 读取 `Main.ini`；文件缺失时用默认设置创建。 |
| `Source.Data.InitializeRuntime()` | 初始化数据服务，并在首个场景之前注册数据提供程序与蓝图提供程序。 |
| `Source.System.InstallRuntimeProviders()` | 在首个场景之前注册配置提供程序。 |
| `Source.System.Init()` | 应用 System 与 Audio 配置，并在进入原生主循环前准备显示资源。 |

入口还会在构造 `SceneInit` 之前初始化 latent 图与原生 System。提供程序每个会话只注册一次。热重载不会重新执行启动流程，详见 [Lua 运行时与模块](<../01.Lua 运行时与模块.md#lua-热更新>)。配置与存档位置见 [运行时数据、配置与存档](<06.运行时数据、配置与存档.md>)。

## 玩法布局

- `Scripts/Source` 保存可复用的 Lua 类、场景、窗口、组件与节点函数。
- `Scripts/Source/UI` 保存导出时由 `Data/UI/Assets` 生成的 View。生成的 UI 与语言文件不进入模板和版本管理，首次运行前需先导出项目。手写基础模块位于 `Source.UIBase`，业务窗口位于 `Source.Windows`，详见 [声明式 UI 编写工作流](<../04.声明式 UI/01.编写工作流.md>)。
- `Scripts/Mixins` 保存可直接挂载的 Lua 行为。
- `Data/Blueprints` 保存游戏专用的 Actor 类。
- `Data/General` 提供物品、敌人、装备、职业、玩家、状态与特殊效果。
- `Data/Maps` 与 `Data/Tilesets` 提供可玩世界。
- `Engine/` 包含原生运行时、模块与依赖。

其他公开 Lua 模块把私有实现服务归入同名目录。这些服务既不 require 宿主，也不扩展宿主。带独立 `.d.lua` 契约的模块保持独立。

原生源码的归属与依赖见 [构建与模块布局](<../../04.C++ 原生开发/01.构建与模块布局.md>)。

`Source.Data.Blueprints` 把蓝图、公共函数与通用数据的图定义编译为原生 `Engine.Graph` 模板，再用 `instantiate` 创建实例。

## 模板变体

`Cpp` 保留原生源码并逐项目构建，`Cpp-ffmpeg` 在此基础上增加视频支持。Standalone 变体内含已构建的运行时，供打包使用。iOS、HarmonyOS 与 Android 发行包只能从 C++ Source 变体构建；启用视频时，改用带 FFmpeg 的 C++ Source 变体。修改 Game 不会更新已有项目，因此需要重新生成模板，或把改动显式应用到该项目。

运行时 Lua、`Scripts/stub` 声明与 `_meta.lua` 的文件分层规则见 [Lua 运行时与模块](<../01.Lua 运行时与模块.md>)。

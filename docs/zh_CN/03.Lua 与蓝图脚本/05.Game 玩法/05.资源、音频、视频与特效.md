# 资源、音频、视频与特效

## 资源路径

持久化资源使用大小写精确的 `/Game/Assets/...` 路径，以 `/` 分隔并带扩展名。通用 Manager 要求这种完整形式；`loadCharacter("actors/Hero.png")`、`playSE("cursor.ogg")` 之类的类别辅助函数只接受类别内相对参数，并自行补上前缀。

运行时把逻辑路径解析到松散文件或 `.ldpak` 条目；Standard 文件系统 API 与直接使用 LuaSF 文件构造函数的代码不会解析。music 与 video 以可 seek 的条目流式读取。只有确实存在平台差异时才使用 `PLATFORM`。

## 动画缓存

动画源数据位于 `Data/Animations`。无论 Data 是松散目录还是归档，`Engine.getAnimationCacheRoot()` 都会在 `Engine.getUserDataPath()` 下创建 `Cache/Animations`。在 Windows 上，用户数据根目录就是运行时的工作目录；其他平台使用应用的用户数据位置。

初始化会生成缺失的 `.anim.json`/`.anim.ldc` 缓存，并在源数据或引用的帧资产变化时重建，同时保留相对 `Data/Animations` 的路径。缓存可以随时丢弃，不进入模板与玩家包。

## 音频

音乐、音效与语音在 `Main.ini` 中各有独立的开关和音量。GlobalFunctions 的 Manager 分组提供面向玩法的辅助函数。缺失的可选音效路径要显式处理。用不同拼写反复加载同一资源会让缓存失效。

玩法 Manager 与蓝图节点使用的音频效果，是由 `Source.AudioEffects` 定义的 Lua DSP processor。Game 提供区分大小写的 `Echo`、`Distortion`、`Underwater` 和 `BehindWall` 预设，默认值分别是 0.3 秒/0.5 衰减的 echo、2.0 drive/0.7 threshold 的 distortion、0.7 depth/0.3 bubble 的 underwater，以及 900 Hz/0.35 transmission 的 behind-wall filter。

`NodeFunctions.Audio.SetEffect(audioType, effect)` 用 `AudioEffects.Get` 解析名称，并把得到的 attacher 分别按 `Sound`、`Voice` 或 `Music` 类别保存。metadata 把两个参数都呈现为下拉框。选择不会创建 processor，也不会修改已在播放的声源。之后创建的每个声源都会调用 attacher，由它为这个声源创建隔离的音频 Lua state 和全新的 processor。选择字面量字符串 `nil` 会清除后续播放使用的预设；其他未知名称立即报错。`Source.AudioEffects` 是唯一的预设注册表，因此改动预设注册表时也必须同步更新 `SetEffect` 的 metadata 下拉选项。效果选择不属于 `SoundFilter` 或 `MusicFilter`。

预设非空时，创建声源会在播放前记录当前播放设备的采样率。设备改道后，活动声源仍保留这些系数；要使用新的采样率，需要通过 Manager 重新发起一次播放。attacher 必须恰好安装一个非空 processor，因此选中的预设不会以 dry 方式播放。SFML 为每个声源只保存一个 processor，预设之间不会串联或混合。

热重载后需要重新发起播放，才会使用更新后的音频代码，参见 [Lua 运行时与模块](<../01.Lua 运行时与模块.md#lua-热更新>)。正在播放的声源与已缓冲的尾音不受影响。

`Echo` 会在流自然结束后排空已缓冲的尾音。通过 Manager 显式停止、跳过对话或关闭会丢弃剩余尾音。直接调用 `sf.SoundSource:setEffectProcessor` 属于另一套底层 API，不具备 Manager 的隔离、EOS 与取消协议。

`NodeFunctions.Scene.ShowVoiceMessageByTag` 与 `ShowVoiceMessage` 会在对话存续期间捕获并持有本次调用实际启动的 Voice handle。对话结束时，它们的 latent 条件先停止该 handle，再由 `FinishedDialogue` 继续执行下游蓝图。因此紧随其后的 `SetEffect` 配置的是下一段 Voice。离开或销毁地图场景同样会停止当前全局 Voice。普通消息节点不会改变 Voice 播放。

## Shader、雾与转场

用户自行编写的 Actor 与图层 shader 仍是可选项。若玩法在没有它们时也能运行，应先用 `sf.Shader.isAvailable()` 或 `sf.Shader.isGeometryAvailable()` 检查可用性。内置天气与雾效则依赖跨平台共用的 shader 资产，加载或编译失败会向外传播。进入大地图时，每个大地图或 Active 图层 shader 会预热一次；重建后的 shader 对象会再次预热。HarmonyOS 跳过人为的 1×1 预热，改为在完整渲染状态与 uniform 绑定完成后，于首次正常绘制时编译每个 shader。HarmonyOS OpenGL ES 把未声明版本的 shader 视为 ESSL 1.00，并保留公开的 `setUniform("texture", ...)` 名称；显式声明的版本必须与后端一致。

Actor 的 fragment shader 按精确的 shader 路径缓存，直到本次 Engine 运行时结束。因此使用同一路径的 Actor 从 `Actor:getShader()` 得到的也是同一个 `sf.Shader`。标准的 `texture`、`time`、`textureSize` 与 `textureRect` uniform 会在每次绘制 Actor 的地图图像或预览图像前立即重新绑定。其他 uniform 仍是 shader 中共享的可变状态，不得当作每个 Actor 各自的持久值。加载失败的 shader 不会进入缓存；受影响的 Actor 通过 `Actor:hasShaderError()` 报告错误，并继续走现有的回退绘制路径。

雾贴图沿用普通 RGBA 语义：RGB 提供颜色，alpha 提供逐像素密度，`fogPower` 缩放不透明度。普通地图与裁剪后的组合式大地图区域在所有受支持的图形后端上使用同一个 shader。

地图雾效数据采用严格的可选字段协议。`fog` 是字符串；缺失、为 `nil` 或为空白时禁用雾效。`fogPower`、`fogOx`、`fogOy` 与 `fogDistort` 必须是 float 范围内的有限数值，且仅在缺失或为 `nil` 时默认为 `0`。`fogPower` 小于或等于 `0` 时同样禁用雾效。强度与扭曲度向下取整并 clamp 到 `0..100`，两个 offset 字段控制滚动。不接受数值字符串或其他标量强转。

地图远景数据使用同样的可选字符串协议。`panorama` 是规范的 `/Game/Assets/...` 路径；缺失、为 `nil` 或为空白时禁用远景。图片在保持宽高比的前提下按 Cover 缩放铺满 `GameMap.MapViewRect`，超出部分按摄像机原点在 `(mapPixels - viewPixels)` 各轴上的比例裁剪。某轴没有摄像机移动时取 `0.5`。透明图块与画布边距露出的远景只乘以环境光；点光源仍然作用于不透明图块。贴图缺失属于必需资源失败。

### 组合式大地图环境

大地图清单可以定义全局雾与全局远景，但不能定义 BGM、BGS、音频 filter 或环境光。全局雾覆盖 Camera。子地图雾裁剪到它的摆放范围内，并按大地图坐标采样；淘汰子地图会移除其区域雾，重新加载后才恢复。全局远景覆盖大地图 Camera，并按大地图尺寸计算滚动。子地图的 `panorama` 只在该子地图作为独立地图加载时生效。

BGM、BGS 与环境光跟随玩家所在的子地图。音频切换淡变 0.5 秒；淡出期间返回会恢复原声源。之后的环境光变化同样混合 0.5 秒，空洞中使用白色。大地图雾与远景在该处仍然生效。

Game 项目的高级敌人击败特效由全局类设置 `Enemy.DefeatShatterEffectEnabled` 控制，默认 `true`，且不是蓝图字段。它的 shader 把快照渲染成世界空间的逻辑像素碎片，在约 0.65 秒内从中心径向向外散开。被击败的敌人此时已经被记录并销毁，因此快照不影响通行性、碰撞或遮光。该设置为 `false`，或 `sf.Shader.isAvailable()` 返回 false 时，敌人改为立即消失。

## 视频

视频播放需要启用 FFmpeg 的项目或模板。文件放在 `Assets/Videos` 下，并以 `/Game/Assets/Videos/...` 引用。松散文件与根级 `Assets.ldpak` 中的条目遵循同一套可 seek 播放契约。Android 支持 MOV、H.264/AAC、swscale 与 swresample，但不支持 network、JNI、MediaCodec 和硬件加速。构建与分发要求见 [项目模板](<../../01.快速入门/02.项目模板.md#ffmpeg-选项>)。

## 限制

shader 是否可用由运行时图形环境决定；编辑器预览成功并不保证目标硬件具备同等支持。

大地图光照使用大地图坐标，因此 Active Actor 灯光与子地图静态灯光可以跨子地图边界照明或投影。Tile mask 仍裁剪到各自的摆放范围，空洞既不贡献 surface 也不贡献 blocker。编辑器的拼合预览不显示雾、远景和光照。

可见的 Tile blocker 在原生层合并为 occupancy texture 与积分 mask；Actor 遮挡按灯光批次分析一次。owner 排除、图层可见性、blocker 边界与 transmission padding 均保持不变。

# 窗口、菜单、输入与控件

默认的 Lua UI 使用 JSON 资产和生成的 View 树。场景创建窗口，View 提供完整的控件与嵌套窗格，UI 管理器控制层叠关系，业务 Controller 负责模型更新与输入回调。

## 窗口与菜单

窗口视图遵循 [声明式 UI 运行时契约](<../04.声明式 UI/02.运行时契约.md>)。菜单把稳定的命令标识符与显示文本分开保存。较长的说明使用现有的换行与格式化辅助函数。

标题的 Save/Load 和 Config 窗口，以及地图的可选窗口，各自使用独立的 `Source.UIBase.LazyWindow` 句柄。进入地图时直接创建 HUD 与 Region Title；Menu、Item、Equip、商店、Save/Load、Config、Enemy Book、Encyclopedia、Floor Teleporter 与 Player Name 都在首次显示时创建。消息窗口在首次消息或选项显示时创建。打开 Menu 不会创建它的 Item、Equip、Save/Load 或 Config 窗口。每个窗口已编写的完整子树在首次使用时一并构造，之后复用，直到所属场景销毁。

游戏内菜单列出物品、装备、存档、设置和返回标题。`WindowMenu.new(player, windows, onExit)` 接收场景提供的退出动作，并在菜单关闭动画结束后调用。目标场景由场景所有者决定，菜单及其独立子窗口的层级也由场景统一设置。选择设置会在菜单之上打开共用的 Config 窗口，并停用命令列表；关闭 Config 窗口后焦点回到菜单。

每个可见的默认界面都有一个顶层资产：Init、Title、Game Over、Region Title、HUD、Menu、Config、Message、Item、Equip、Shop、Save/Load、Attribute Shop、Enemy Book、Encyclopedia、Floor Teleporter 与 Player Name。多窗格界面把各窗格嵌套在同一个根下，同级输入宿主复用其中的嵌套列表与滚动框。

顶层窗口的转场是线性的，默认时长 0.2 秒。内部窗格与页签立即切换。播放期间禁用输入，关闭结果在 `FadeOut` 隐藏根之后执行。初始化与销毁则立即隐藏。

| UI | Timeline 行为 |
|---|---|
| 默认窗口与 Config | `FadeIn`：中心 Scale `0.5` 到 `1` 并改变 colour；`FadeOut`：仅 colour。 |
| Title command | `FadeIn`：本地 Y `80` 到 `0` 并改变 colour。打开 Config 或 Save/Load 不会隐藏它。 |
| Map Menu | `FadeIn`/`FadeOut`：本地 X `-192` 到 `0` 再返回，并改变 colour。 |
| Item 与 Equip | 仅 Menu 动画。Save/Load 同时提供默认与 Menu 两套；Config 始终使用默认那一套。 |
| Message | 仅 `Panel` 的 colour。 |
| Game Over | 仅改变 colour 的 `FadeIn`（0.5 秒）与 `FadeOut`（1 秒）。场景切换等待 `FadeOut`，它保持透明末帧直到场景销毁。 |
| Region Title | `Display` 保持 colour 一秒，再用一秒淡出。 |

相关的 `FadeOut` 转场可以并行播放。

资产中包含具有代表性的 `#TAB` 与 `#ITEM` 子项以及 Game 项目的视觉资源。动态集合在显示前替换列表占位项，Controller 本地化 TabView 条目时不会改变条目数量。Enemy Book 与 Encyclopedia 使用 `CharacterView`：运行时传入真实的 Actor 快照，裁帧、动画、缩放和 Shader/Hue 特效由原生代码负责。 怪物图鉴通过集合的 `logicalSize` 参数传入单元格尺寸。单元格 Controller 复用该尺寸排列名称和特殊能力标签，切换语言时也保持一致。

`Source.Windows` 模块通过 `Ui.DefineWindow` 导出 UI 类，业务行为放在私有 Controller 中。`WindowCommand` 是共用的原生命令窗口工具。UI 的编写方式与文件布局见 [声明式 UI 编写工作流](<../04.声明式 UI/01.编写工作流.md>)。

在标题界面，Config 或 Save/Load 窗口打开后，底层的命令窗口不会收到同一触摸手势的任何部分。

`WindowBase` 在 `Content` 之外的左上边框提供可选的 16 × 16 返回按钮。可取消的窗口通过 `windowOptions.returnButton = true` 启用它，并用 `Controller:onReturn()` 实现与其他 Cancel 输入相同的、感知状态的步骤。这个共用的返回步骤只播放一次系统 CancelSE，第二个 Cancel 来源不得再播一次。多窗格组只在当前活动的可交互窗格上显示该按钮。隐藏、未激活或被抑制的窗口不会显示它。

`WindowBase` 还在 `Content` 之外的底部边框嵌入 `Engine.GamepadHintBar`。它和返回按钮一样属于窗口而非某个资产，只有连接手柄且窗口设置了提示时才显示。窗口用 `setGamepadHints` 设置至多三条 `Engine.GamepadHint`，用 `setGamepadHintEnabled` 切换单条，用 `getGamepadHintCount` 与 `isGamepadConnected` 查询状态，并通过 `setOnGamepadHintTriggered` 处理触发完成。渲染与长按一秒行为见 [GamepadHintBar](<../08.全局与 Core 模块/02.Core Modules/01.Engine/13.交互与声明式 UI 控件.md#gamepadhintbar>)。

静态命令行保存 `localeKey`，动态行保存字面量 `text`。同一行绝不能同时定义两者。命令行在刷新时解析 `localeKey`，因此语言变化可以更新已有的控件，而不必替换它们的 callback 或游标状态。运行时语言变化时，标题命令、游戏内菜单、存读档页签、商店页签与详情，以及正在显示的地图区域标题都会立即更新。

可复用的选择窗口每次开始新的打开会话时，选择器都从 0 开始并滚动到顶部；选择器为空时使用 `nil`。这条规则适用于游戏内菜单、物品与装备窗口、商店、Config 和 Enemy Book。同一会话内的焦点变化和原位刷新会保留当前选择。

商店的两列物品列表保持焦点，Q/E、LB/RB、鼠标或触摸用于切换买/卖。切换页签会重置游标与滚动，交易刷新则保留仍然有效的选择。购买格显示图标，出售格还显示持有数量；详情显示本地化名称、说明和右对齐价格。出售获得 `floor(price / 2)` GOLD，价格为 0 的商品不予发放。仅能购买的商店隐藏页签，并把其余窗格居中。Cancel 关闭商店。

内容溢出的列表使用 `Engine.ScrollBox`。它裁剪绘制与命中测试，只滚动溢出的轴，并保证键盘与控制器选择始终可见。原生边缘提示显示剩余内容。参见 [Engine：布局与图像控件](<../08.全局与 Core 模块/02.Core Modules/01.Engine/10.布局与图像控件.md>)。

消息窗口使用全屏 Canvas 和透明的 `FunctionalImage`，为普通消息的确认消耗一次点击或触摸。选项模式会禁用该层，因此点击空白处无法选中选项。最多四个选项可以直接放进面板，不需要 ScrollBox。`SceneMap` 只在对话进行期间阻断地图输入。

`SceneMap` 为长生命周期的地图窗口维护一个 `LocaleChanged` 订阅。活动对话保留原始说话者、消息或选项、显式的 `localeArgs`，以及节点局部变量和实例变量的快照。刷新时，它重新执行模板本地化、本地化 `localeArgs` 中的字符串、应用这些参数，再应用两份变量快照，最后更新已有的 `WindowMessage` 控件。物品与装备详情、商店页签与详情、属性商店、Enemy Book、`WindowEnemyEncyclopedia` 以及 Teleporter（`WindowFloorTeleporter`）同样在原位刷新本地化文本，并保留当前选择、模式、焦点和预览状态。隐藏窗口在下次打开时按当前语言解析；Config、存档槽与玩家 HUD 的 Controller 各自保留订阅。玩家 HUD 还会轮询轻量的地图、战斗 revision、成长、钥匙和有序状态签名，某个签名变化时只刷新受影响的控件。

语言切换、读档后的玩家重绑定、可见性查询与输入检查都只通过 `peek()` 访问已创建的窗口。尚未使用的窗口不会阻断地图输入或获得焦点，工厂会在实际打开时读取当前玩家、游戏实例与配置。场景销毁时释放句柄，清理已有窗口而不构造未使用的窗口。

Teleporter 打开时选中当前地图对应的楼层项并滚动到可见位置；当前地图不在列表中时回退到第一项，列表为空时使用 `nil`。传送点选择从第一项开始。左侧槽位在楼层列表与传送点列表之间切换，取消传送点选择会恢复楼层列表。传送点列表滚动时，右侧预览不移动。组合式清单始终是一个楼层身份，子地图按大地图偏移拼合。

早在获得 Teleporter 物品之前，传送点就会通过楼梯传送被发现。打开窗口或靠近楼梯都不会记录访问。记录结构与去重规则见 [运行时数据、配置与存档](<06.运行时数据、配置与存档.md>)。

传送点名称用 `LOC` 解析记录的 tag。空的或自动生成的 tag 使用本地化的 `POINT` 编号格式；缺少译文时保留原始 tag。

键盘、鼠标和触摸选择都会在确认之前更新目的地与预览。预览保持固定缩放并限制在地图边界内，小于视图的轴居中显示。组合式预览使用完整的清单边界。

属性商店通过 `getOffers()` 提供展示快照，并通过 `purchaseAttribute(key)` 校验购买。价格引用为标量时由所有商品共用，为数组时逐项设置价格。购买后对应价格增加。

### 玩家改名窗口

`Map_01` 中出生点旁的 NPC 会打开 `WindowPlayerName`，并在窗口关闭前暂停地图输入。用 Confirm 操作激活输入框才能编辑。Tab/Shift+Tab 与方向操作在输入框和 Confirm 之间移动。

Confirm 在所有输入设备下均保持可见。鼠标和触摸可以激活按钮；键盘 Enter/Space 在 Confirm 取得焦点时应用名字，否则进入文本编辑。资产把 Confirm 绑定为长按 X 一秒（`gamepadButton = "X"`、`gamepadLongPress = true`），并且不填充窗口底部提示栏。A 只进入文本编辑，即使焦点在 Confirm 上也是如此；活动窗口内任意焦点均可长按 X 应用名字。空纹理与提示外观见 [Button](<../08.全局与 Core 模块/02.Core Modules/01.Engine/09.运行时值与功能控件.md#button>)。返回按钮或 Cancel 会丢弃草稿；编辑期间，Cancel（B 或 Escape）先结束编辑，再按一次才关闭窗口。完成移动端输入弹窗只会更新草稿。名字无效时 Confirm 不可用，校验规则见 [Source.Player](<../07.源码类/09.Player.md>)。HUD 在等级上方显示已确认的名字，过长时缩短以适配。

## 输入

`Source.Configs.HotKey` 把原生按键映射到 `Scene`、`Filter` 以及可选的 `FunctionWhenPressed` / `FunctionWhenReleased` 回调。每个回调都会收到场景实例。

运行时输入来自 C++ 输入服务。应使用文档中的键盘、鼠标、控制器与注入输入 API，而不要读取编辑器状态。Windows 嵌入模式通过运行时协议转发兼容输入；独立游戏直接使用原生窗口。

在 Android 和 HarmonyOS 上，宿主把系统返回键或返回手势转换成一次 Cancel/Escape 脉冲，而不是关闭应用或将其切到后台。这条转换路径与 HarmonyOS 的外接键盘转发保持独立：后者把 SFML 映射的普通按键作为 scancode 边沿发送，在能够解析时补充 logical key 边沿，并保留修饰键状态。双指触摸仍是独立的鼠标右键取消手势。系统返回与双指触摸都会触达焦点窗口的 `onReturn()`，但只有后者会产生鼠标右键输入。

物理 Enter 与 Space 使用 Confirm 操作，Escape 使用 Cancel。键盘的按下与释放都是边沿事件，参见 [Engine：输入与服务](<../08.全局与 Core 模块/02.Core Modules/01.Engine/07.输入与服务.md>)。

手柄按钮使用 `Engine.JoystickButton.getA()` 至 `getShare()` 的逻辑值。Confirm 为 A/Cross，Cancel 为 B/Circle。按手柄解析、映射与提示见 [Engine：输入与服务](<../08.全局与 Core 模块/02.Core Modules/01.Engine/07.输入与服务.md>)。

默认的移动与菜单方向只使用左摇杆的 `X`/`Y` 和十字键的 `PovX`/`PovY`。`|X| >= |Y|` 时取水平方向，否则取垂直方向；恰好 45 度的输入算作水平。触发式导航与按住移动都使用这条扇区规则，右摇杆和扳机轴无法夺取方向。

`WindowSelectable` 负责默认的 Cancel 键和鼠标右键关闭行为。派生窗口把未处理的输入交回给它，因此每个边沿只产生一次 Cancel 音效和一次关闭转场。

## 焦点与导航

键盘与控制器导航需要明确的焦点顺序。已禁用或已隐藏的控件不得继续作为活动焦点目标。指针激活与键盘/控制器激活要分别测试。

## 设置控件

Config 打开时位于 Graphics 页并聚焦第一行。Q/E、LB/RB、鼠标悬停和触摸点击会切换页签并播放 CursorSE。本次打开会话期间，各页签保留游标与滚动位置。重新打开会重置所有页签，语言刷新则保留它们。

切换页签会静默收起已展开的 DropBox。Cancel 和返回按钮也会先收起它，下一次输入才关闭 Config。[游戏设置参考](<07.游戏设置参考.md>) 定义各项设置。

在移动端，点击 Slider 会在释放时设置数值。超过拖动阈值后，水平移动归 Slider，垂直或两侧均等的移动归 Config 列表。手势归属在释放前保持不变；列表仅在内容超出可见区域时滚动。

展开的 Config DropBox 会覆盖设置行并独占输入，直到它收起或 Config 关闭；两者都会恢复父列表的输入。高度受限的弹出层在内部滚动，移动端触摸采用先预览后确认。参见 [Engine：交互与声明式 UI 控件](<../08.全局与 Core 模块/02.Core Modules/01.Engine/13.交互与声明式 UI 控件.md>)。

Save/Load 使用同一份槽位列表。切换 Load/Save 页签会保留游标、滚动位置与详情。重新打开时选中 Load 和最新的已有存档，没有存档时选中 0 号槽。Cancel 关闭窗口。标题界面的仅加载模式不显示页签，并把其余窗格居中。

精确的 UI 与输入 API 见 API 参考，从 [NodeFunctions.Container](<../06.节点函数/01.Container.md>) 开始。游戏内的本地化标签遵循 [游戏本地化工作流](<../../05.插件开发与安装/06.游戏本地化工作流.md>)。编辑器的语言切换不属于本节。

## 限制

嵌入式输入转发只适用于受支持的 Windows 编辑器运行模式。最终输入、焦点与手柄测试仍应以原生独立窗口为准。

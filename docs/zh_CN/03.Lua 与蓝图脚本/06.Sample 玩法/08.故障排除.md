# 故障排查

## 适用范围

复现 Sample 或项目故障并保留 Console 中首条相关消息后，再使用本页。应按最早失败阶段排查：项目加载、校验、原生构建、运行时启动、资源访问，最后是打包。

## 项目无法打开

检查 `Main.proj` 以及 `Data` 下所有已加载文件是否为合法 JSON。路径必须留在项目内。应恢复必需目录，而不是让编辑器打开不完整打包目录。

## Blueprint 无法保存

运行 Blueprint 校验，按顺序处理第一个 parent、循环、graph、node、link、pin 或默认值错误。Script Mixin 还要检查相对路径、返回 table 和同名 metadata。

## 游戏无法启动

从 Console 第一个错误开始阅读。before-run 插件 hook 可能在编译前失败；否则检查 C++ 构建、生成模块、`Main.ini` 入口、Core 模块顺序和 runtime 协议诊断。

## 节点缺失

确认 metadata 是纯数据、返回 `_METADATA`，成员声明 `type = "function"` 或 `"event"`，并且不在 `Scripts/Mixins` 下。C++ 声明需要重新构建以让 bindgen 生成 metadata。

## 资源或数据引用损坏

打开引用树，找到保存的旧 key/path 并手工更新。重命名和删除不保证自动修复引用。

## 本地化文本缺失

按“插件系统与本地化”中的 Official Locale Tools 检查项处理：workbook 表头、ID、导出语言文件、选择语言、fallback 和 `LOC`/花括号格式。

## 打包后行为不同

检查包内资源、脚本、原生模块、FFmpeg 变体、可写 `Main.ini` 位置和平台路径处理。不得通过路径分隔符推测平台，应使用注入的 `PLATFORM`。

## 验证

每次修正后重复完全相同的失败操作，再从干净启动状态执行对应校验或打包。后续 warning 不代表原错误已经解决，必须确认最早的失败消息已消失。

## 限制

本页覆盖常见项目与 Sample 故障。原生崩溃、绑定生成错误和插件加载错误应使用对应开发专题中的专用诊断方法。

# 新游戏、标题与场景流程

默认入口创建 `Source.Scenes.SceneInit`，再把控制权交给原生 System 主循环。SceneInit 准备共享数据并进入标题流程：逻辑 tick 负责加载和切换判断，渲染线程的 late tick 负责向声明式 UI 发布进度，避免逻辑线程修改由 GPU 支撑的控件。标题场景构建开始游戏、继续游戏、设置和退出游戏等菜单窗口。

## 目标

在保持项目初始化顺序、明确存档处理和安全场景切换的前提下，调整 Sample 标题流程。

## 前置条件

- 已确定 New Game 使用的初始地图和玩家定义。

## 步骤

### 配置新游戏

New Game 会创建或重置游戏实例，选择初始地图与玩家数据，并切换到地图场景。`Data/Configs/System.json` 的 `startPlayerBlueprint` 保存相对于 `Data/Blueprints` 的玩家蓝图路径，`startRegion` 保存初始区域。这两个值只初始化新游戏；Continue 会恢复所选 slot 中保存的玩家类与当前区域。

`startMap` 可以指向普通地图、`World_01/_world.json` 形式的组合式大地图清单，或 `World_01/Map_03.json` 形式的已摆放子地图。目标是清单时，`startPos` 是大地图坐标；目标是子地图时，`startPos` 是子地图局部坐标。编辑器通过同一棵地图树展示三种形式，并保存选中的字符串路径。

### 进入地图与组合式大地图

`NodeFunctions.Scene.GotoMap` 遵循相同的路径与坐标规则。进入当前大地图的另一张子地图时保留 `WorldGameMap` facade；未摆放子地图不是合法目标。

在大地图中，`Scene:getGameMap()` 和 `Actor:getMap()` 公开同一个大地图坐标 GameMap facade。通行、Dir4、材质和地形来自子地图 placement；未覆盖格是可通行空洞。缺失或不一致的子地图数据会报错。

大地图 placement 由原生索引管理；安装、重建或淘汰子地图时更新索引，Actor 发布与 Tile chunk 就绪控制玩法访问。导航与材质查询不再逐格调用 Lua，也不会加载缺失子地图。

进入时，runtime 会重新校验扁平目录、严格匹配的 `_world.json`、子地图文件、placement 和图层顺序；非法数据直接失败。

子地图依次使用 `Unloaded`、`Reading`、`Prepared`、`Active` 和 `Dormant` 状态。流送优先满足 Camera 邻域并取消过期读取。只有 Active Actor 参与模拟；所有可见 placement 和 Tile chunk 就绪前，Camera 保留最后完整画面，启用碰撞的移动不能进入未准备区域。

启用转场时，大地图入口会冻结离开前画面，直到目标视口及必需 Actor、灯光和 Tile chunk 就绪；必需数据错误会在释放前传播。`blockTransition = true` 跳过遮罩但保留该屏障，外围预备仍为异步。

非 Active payload 使用 32 区域或估算 256 MiB 的 LRU。先淘汰 Dormant，再淘汰 Prepared；Active 和 pending 目标会固定，因此可暂时超过软上限。

Performance Monitor 显示流送状态；异步 publish tick 达到 4 ms 时，每个大地图会记录一次 warning，并指出最慢实测阶段。字段见[启动页、工作区与快捷键](<../../02.编辑器用户指南/01.启动页、工作区与快捷键.md>)。

`RegionDict` 仍是楼层传送数据，不定义大地图拼合或流送。

### 配置继续游戏

Continue 通过 `GetSavePath(slot)` 读取当前 `SAVE_AS_LDC` 配置所选择的标准存档：默认是 `.json`，开启后是包含 JSON 序列化数据的加密 `.ldc`。它会恢复游戏状态并打开对应场景。缺失、损坏或不受支持的存档必须进入明确的 NotFound/错误路径，不能静默构造不完整状态。

### 保持场景切换契约

使用“Blueprint API 参考”记录的 System 与 scene API。场景切换由 C++ runtime 调度，避免在一帧更新中途销毁活动场景。离场景拥有的窗口和临时资源应通过正常生命周期释放。

### 自定义标题

修改 Lua 场景/窗口组合和对应数据，并使所有文本标识符符合[游戏本地化工作流](<../../05.插件开发与安装/06.游戏本地化工作流.md>)。应测试开始游戏、有/无存档的继续游戏、设置、退出游戏，以及游戏中返回标题。

## 限制

Sample 不规定通用的存档升级策略或标题界面设计。正式游戏必须自行定义支持的存档版本、视觉呈现和恢复提示。

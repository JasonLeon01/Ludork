# 新游戏、标题与场景流程

默认入口创建 `Source.Scenes.SceneInit`，再把控制权交给原生 System 主循环。SceneInit 准备共享数据并进入标题流程：逻辑 tick 负责加载和切换判断，渲染线程的 late tick 负责向声明式 UI 发布进度，避免逻辑线程修改由 GPU 支撑的控件。标题场景构建开始游戏、继续游戏、设置和退出游戏等菜单窗口。

## 目标

在保持项目初始化顺序、明确存档处理和安全场景切换的前提下，调整 Sample 标题流程。

## 前置条件

- 已确定 New Game 使用的初始地图和玩家定义。

## 步骤

### 配置新游戏

New Game 会创建或重置游戏实例，选择初始地图与玩家数据，并切换到地图场景。`Data/Configs/System.json` 的 `startPlayerBlueprint` 保存相对于 `Data/Blueprints` 的玩家蓝图路径，`startRegion` 保存初始区域。这两个值只初始化新游戏；Continue 会恢复所选 slot 中保存的玩家类与当前区域。

### 配置继续游戏

Continue 通过 `GetSavePath(slot)` 读取当前 `SAVE_AS_LDC` 配置所选择的标准存档：默认是 `.json`，开启后是包含 JSON 序列化数据的加密 `.ldc`。它会恢复游戏状态并打开对应场景。缺失、损坏或不受支持的存档必须进入明确的 NotFound/错误路径，不能静默构造不完整状态。

### 保持场景切换契约

使用“Blueprint API 参考”记录的 System 与 scene API。场景切换由 C++ runtime 调度，避免在一帧更新中途销毁活动场景。离场景拥有的窗口和临时资源应通过正常生命周期释放。

### 自定义标题

修改 Lua 场景/窗口组合和对应数据，并使所有文本标识符符合[游戏本地化工作流](<../../05.插件开发与安装/06.游戏本地化工作流.md>)。应测试开始游戏、有/无存档的继续游戏、设置、退出游戏，以及游戏中返回标题。

## 验证

分别在 `SAVE_AS_LDC` 关闭和开启时，确认标准 slot 分别使用 `.json` 与 `.ldc`，且 Console 没有窗口未释放、场景无效或存档只恢复一部分等错误。

## 限制

Sample 不规定通用的存档升级策略或标题界面设计。正式游戏必须自行定义支持的存档版本、视觉呈现和恢复提示。

# 窗口、菜单、输入与控件

默认 Lua UI 由运行时窗口与控件类构建。场景创建窗口，控件接收焦点和输入，UI manager 管理层叠与所有权。

## 窗口与菜单

在所属窗口中创建控件，按可预测顺序添加，并在窗口关闭时释放回调。菜单应把稳定命令标识符与显示文本分离。长说明应使用现有换行和格式化辅助函数。

游戏内菜单包含物品道具、装备、存档、设置与回到标题。选择设置会在菜单之上打开共享的 Config 窗口并停用命令列表；关闭 Config 窗口后焦点回到菜单。

标题界面打开 Config 或 Save/Load 后，底层 command window 不会收到同一触摸手势的任何阶段。

`WindowBase` 在 `Content` 外的左上边框提供可选的 16 × 16 返回按钮。可取消窗口通过 `setHasReturnBtn(true)` 启用它，并覆盖默认无操作的 `onReturn()`，执行与其他 Cancel 输入相同的状态返回步骤。多面板窗口只在当前活动的交互面板显示按钮；隐藏、停用或被抑制的窗口不显示该按钮。

静态命令行保存 `localeKey`，动态命令行保存字面量 `text`，同一行不得同时定义两者。命令行在刷新时解析 `localeKey`，因此语言切换可以原位更新已有控件，而不替换 callback 或游标状态。运行时语言变化后，标题命令、游戏内菜单、存读档命令、商店命令和当前可见的地图区域标题都会立即更新。

`SceneMap` 为长生命周期地图窗口统一持有一个 `LocaleChanged` 订阅。活动对话会保留原始说话者、消息或选项、显式 `localeArgs`，以及节点局部变量和实例变量快照；刷新时依次重新解析模板、解析 `localeArgs` 中的 string、应用这些参数，再应用两份变量快照，最后原位更新现有 `WindowMessage` 控件。物品和装备详情、属性商店、怪物手册与百科、楼层传送器也会原位刷新本地化文本，并保持当前选择、焦点和预览状态。隐藏窗口下次打开时按当前语言解析；Config 与存档槽 controller 保留各自订阅，玩家 HUD 则在常规刷新中解析展示文本。

## 输入

运行时输入来自 C++ input service。应使用文档中的键盘、鼠标、控制器和注入输入 API，不要读取编辑器状态。Windows 嵌入模式通过 runtime 协议转发兼容输入；独立游戏直接使用原生窗口。

在 Android 与 HarmonyOS 上，宿主把系统返回键或返回手势转换为一次 Cancel/Escape 脉冲，而不关闭应用或使其退到后台。双指触摸仍是独立的鼠标右键取消手势；两者都调用焦点窗口的 `onReturn()`，但只有后者产生鼠标右键输入。

## 焦点与导航

键盘/控制器导航需要明确焦点顺序。禁用或隐藏控件不应继续作为活动焦点。指针激活与键盘/控制器激活应分别测试。

## 设置控件

默认 Config 窗口修改语言、帧率、垂直同步和音频选项。显示缩放默认为 `1.0`。桌面 Config 提供全屏（`0`）及 `1`、`1.25`、`1.5`、`1.75`、`2`；独立运行只保留能放入当前显示器工作区的正数预设值，以及能放下的当前非预设值。移动端不显示缩放行；再次确认当前项仍会重新应用。启动与持久化规则见[游戏设置参考](<07.游戏设置参考.md>)。

桌面窗口模式仍可自由调整大小。手动调整成与游戏不同的宽高比时，画布以黑边居中；黑边区域不接收指针输入。

移动端的 Slider 点击会在释放时设置数值。超过拖动阈值后，横向移动归 Slider，纵向或等量斜向移动归 Config 列表。手势归属在释放前保持不变，列表仅在内容超出可视区域时滚动。

展开的 Config DropBox 独占输入，直至折叠或关闭 Config；两种操作都会恢复父列表输入。

全屏使用桌面尺寸的无边框窗口，不切换显示模式。嵌入运行继续跟随宿主尺寸，移动端继续使用平台全屏行为。

精确 UI 与输入 API 见“Blueprint API 参考”。游戏本地化标签归“插件系统与本地化”；本节不介绍编辑器语言切换。

## 验证

分别使用指针和键盘或控制器打开每个已修改菜单。遍历所有可用控件、执行每条命令，在控件可见时切换运行时语言，并确认文本变化不会移动游标、改变焦点或重复注册 callback。确认高度为 192 逻辑单位的游戏内菜单能完整显示五个 32 单位高的行。关闭窗口后再次打开，确认没有残留焦点。桌面端验证缩放过滤与黑边；触摸端验证模态窗口、Slider/列表及 DropBox 的输入归属。每种 Cancel 输入都只能执行一次相同的返回步骤，且只有活动面板可以显示返回按钮。

## 限制

嵌入式输入转发仅适用于受支持的 Windows 编辑器运行模式。最终输入、焦点和控制器测试仍应以原生独立窗口为准。

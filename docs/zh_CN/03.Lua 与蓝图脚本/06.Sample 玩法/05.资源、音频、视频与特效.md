# 资源、音频、视频与效果

## 资源路径

使用 `Assets/System/Icon.png` 这类不带前导 `./` 的项目相对资源路径和 metadata 驱动的选择器。C++ manager 会缓存 texture、shader 和 audio 资源；Lua 中不要自行拼接操作系统路径分隔符。Android 会把最终化资源作为 APK assets 保存，并在原生启动前镜像到内部 runtime 目录，因此 SFML 与普通文件系统调用都使用同一个 `Assets/...` key。只有行为确实因平台而异时才读取 `PLATFORM`。

## 音频

音乐、音效和语音在 `Main.ini` 中拥有独立开关与音量。GlobalFunctions 的 Manager 分组提供玩法侧辅助函数。缺失的可选音效路径应显式处理；用不同拼写重复加载同一资源会破坏缓存效果。

玩法 Manager 与 Blueprint 节点使用的音频 Effect 是原生 C++ processor，通过 `GlobalCore.AudioEffects` 字符串 token 表选择。Sample 提供大小写敏感的 `Echo`、`Distortion`、`Underwater` 和 `BehindWall` 四个 preset。默认参数仍分别为 0.3 秒/0.5 衰减的 Echo、2.0 drive/0.7 threshold 的 Distortion、0.7 depth/0.3 bubble intensity 的 Underwater，以及 900 Hz/0.35 transmission 的 BehindWall。`BehindWall` 使用两级低通滤波和音量衰减，产生声音隔着实体障碍物传来的沉闷效果。

`NodeFunctions.System.SetEffect(audioType, effect)` 分别为 `Sound`、`Voice` 或 `Music` 类别保存所选 preset；metadata 会把两个参数都显示为下拉框。选择操作不会创建 processor，也不会修改已经开始播放的声源。之后创建的每个声源都会在播放前获得一个全新的 processor，因此 delay line、滤波历史、随机状态和 fault 状态均逐声源隔离。选择字面量字符串 `nil` 可清除后续播放使用的 preset。Lua token 表只是用于发现的快照，C++ registry 仍会验证每一个字符串。运行时 preset 的实现和登记集中在原生音频 Effect 文件中；新增或删除 key 时，还需手动同步 `SetEffect` metadata 下拉框以及对应文档和测试。Effect 选择不属于 `SoundFilter` 或 `MusicFilter`。

使用非空 preset 时，系统会在创建声源之后、挂接 processor 和调用 `play` 之前获取并验证当前播放设备采样率。processor 会在其生命周期内保留该采样率。设备 reroute 后，活动声源继续使用创建时的系数；如需使用新设备采样率，应停止并重新播放。SFML 的每个声源只保存一个 processor，preset 不会自动串联或混合。

Manager Effect 链路在音频线程中只执行有界的原生 DSP，绝不进入 gameplay Lua。preset 状态会在播放前完成分配；有状态的原生 processor 不接受超过八个输出声道的声源，状态分配失败会同步中止播放。非法 callback buffer 或处理失败会输出静音而不是未经处理的原声；Manager 会停止该声源，并在主线程 update 中报告首个 fault。`Echo` 会在自然 EOS 后排空已缓存尾音；通过 Manager 显式停止、跳过对话或 shutdown 时，会先取消 processor 并丢弃剩余尾音，场景代码则在 teardown 时停止自己持有的声源。直接使用 LuaSF 的 `sf.SoundSource:setEffectProcessor` 属于另一套低层 callback API，不属于此 preset registry，并继续遵循 LuaSF 的 best-effort state entry 与 fallback 行为。

`NodeFunctions.Scene.ShowVoiceMessageByTag` 和 `ShowVoiceMessage` 会在对话生命周期内持有当前 Voice。对话结束时，它们的 latent condition 会先停止该 Voice，再通过 `FinishedDialogue` 恢复后续 Blueprint 执行。因此，紧随其后的 `SetEffect` 会配置下一段 Voice，而不会修改刚结束对话所使用的音频。普通消息节点不会改变 Voice 播放。

## Shader、雾与转场

图层 shader、屏幕转场、雾、闪烁、色调和震动由 runtime 实现。请通过 `sf.Shader.isAvailable()` 与 `sf.Shader.isGeometryAvailable()` 检测可选能力，保留可玩的 fallback，并测试关闭可选效果后的相同地图。

雾贴图遵循普通 RGBA 语义：RGB 提供雾颜色，Alpha 提供逐像素密度，地图的 `fogPower` 缩放最终不透明度。Shader 路径和 Sprite fallback 使用相同的颜色与 Alpha 解释。

Sample 的高级敌人击败特效由全局类设置 `Enemy.DefeatShatterEffectEnabled` 控制；该设置默认为 `true`，且不是 Blueprint 字段。它的 Shader 会把视觉快照绘制为世界空间逻辑像素碎片，并在约 0.65 秒内从中心径向向外消散。此时敌人已经被记录并销毁，所以快照不影响可通行性，也不参与碰撞或遮光。当该设置为 `false`，或 `sf.Shader.isAvailable()` 返回 false 时，敌人会改为立即消失。

## 视频

视频播放需要启用 FFmpeg 的项目或模板。视频放在 `Assets/Videos`，并打包正确 runtime 变体。Windows 与 macOS 的 FFmpeg 构建使用共享库或动态库；iOS、HarmonyOS 与 Android 视频需要 C++ Source + FFmpeg，并使用 `Sample/cmake/FFmpeg` 构建的静态 `.a` 库。下游发行必须满足 `Licenses/FFmpeg/README.md` 所述的适用 LGPL 重链接材料要求。Android 裁剪构建保留 file protocol、MOV demuxer、H.264/AAC decoder 与 parser、swscale 和 swresample，不启用 network、JNI、MediaCodec 或硬件加速。资源存在并不表示非 FFmpeg 模板能够播放。

## 验证

测试资源缺失、不支持的 shader、静音通道、音量边界、重复场景切换和打包相对路径。必须检查最终包，不能只检查开发目录。

## 限制

Shader 可用性由运行时图形环境决定；编辑器预览成功不代表目标硬件具备同等支持。

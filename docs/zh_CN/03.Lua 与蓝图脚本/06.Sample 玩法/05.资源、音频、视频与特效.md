# 资源、音频、视频与效果

## 资源路径

使用 `Assets/System/Icon.png` 这类不带前导 `./` 的项目相对资源路径和 metadata 驱动的选择器。C++ manager 会缓存 texture、shader 和 audio 资源；Lua 中不要自行拼接操作系统路径分隔符。Android 会把最终化资源作为 APK assets 保存，并在原生启动前镜像到内部 runtime 目录，因此 SFML 与普通文件系统调用都使用同一个 `Assets/...` key。只有行为确实因平台而异时才读取 `PLATFORM`。

## 音频

音乐、音效和语音在 `Main.ini` 中拥有独立开关与音量。GlobalFunctions 的 Manager 分组提供玩法侧辅助函数。缺失的可选音效路径应显式处理；用不同拼写重复加载同一资源会破坏缓存效果。

玩法 Manager 与 Blueprint 节点使用的音频 Effect 是定义在 `Source.AudioEffects` 中的 Lua DSP processor。Sample 提供大小写敏感的 `Echo`、`Distortion`、`Underwater` 和 `BehindWall` 四个 preset。默认参数仍分别为 0.3 秒/0.5 衰减的 Echo、2.0 drive/0.7 threshold 的 Distortion、0.7 depth/0.3 bubble intensity 的 Underwater，以及 900 Hz/0.35 transmission 的 BehindWall。`BehindWall` 使用两级低通滤波和音量衰减，产生声音隔着实体障碍物传来的沉闷效果。`Underwater` 以秒为单位调度确定性的 bubble 密度，并把每个事件渲染为带固定逐事件声道扩散的 8 毫秒 Hann 窗正弦短音。它替换了已退役实现中会被听成宽频 click 的单 sample bubble 脉冲，同时保留 preset 的 LCG、频率/振幅范围、intensity 与输出 clamp。

`NodeFunctions.System.SetEffect(audioType, effect)` 通过 `AudioEffects.Get` 解析名称，并分别为 `Sound`、`Voice` 或 `Music` 类别保存返回的 attacher；metadata 会把两个参数都显示为下拉框。选择操作不会创建 processor，也不会修改已经开始播放的声源。之后创建的每个声源都会在播放前调用 attacher。attacher 委托给声源 control，由它创建一个隔离的音频 Lua state，并在其中解析同一 preset 以获得全新的 closure。因此 delay line、滤波历史、phase、envelope 和确定性随机状态均逐声源隔离，也不会与玩法 Lua VM 或其他活动声源争夺执行权。选择字面量字符串 `nil` 可清除后续播放使用的 preset；其他未知名称会立即报错。`Source.AudioEffects` 是唯一的 preset registry 与实现；新增或删除 key 时，还需手动同步 `SetEffect` metadata 下拉框以及对应文档和测试。Effect 选择不属于 `SoundFilter` 或 `MusicFilter`。

使用非空 preset 时，系统会在创建声源之后、挂接 processor 和调用 `play` 之前获取并验证当前播放设备采样率。processor 会在其生命周期内保留该采样率。设备 reroute 后，活动声源继续使用创建时的系数；如需使用新设备采样率，应通过 Manager 发起一次新播放并创建新声源。attacher 必须恰好安装一个非空 processor；未安装、安装空 processor 或重复安装都会让声源创建同步报错，因此已选择的 preset 不会静默以 dry 模式播放。SFML 的每个声源只保存一个 processor，preset 不会自动串联或混合。

Effect callback 使用 LuaSF copying contract。输入和输出是以 1 为起始索引、flat、dense 的交错 sample 数组；数组长度以 sample 为单位，`inputFrameCount` 与 `outputFrameCount` 则以 frame 为单位。EOS 严格表示为 `nil` 输入加零 input frame count。LuaSF 会复用 callback-scope 的 input/output scratch table，覆盖或清零完整的当前范围，并在 block 变短时删除旧的尾部条目；processor 返回后不得保留这些 table。每个 preset 同样复用一个 result table。旧 `.value` 与 `.capacity` callback shape 不再接受。有状态 preset 不接受超过八个输出声道，并在声道数变化或声源到达 EOS 时重置历史状态。

每个活动 preset processor 都独占一个隔离 Lua state。processor 构造完成后会停止该 state 的 collector，而 copying bridge 与第一方 processor 会复用全部 callback table，因此稳态 block 不产生可回收的 Lua garbage。音频线程使用 LuaSF 的非阻塞 try-enter；隔离 state 不承载玩法或其他声源工作，shutdown/quiesce 时也只会收到 copying fallback，不会等待。LuaSF 的 GC guard 仍会在 scratch table 填充、受保护 Lua 调用与结果解析期间保留进入前的 GC 状态。callback generation 静止后，isolated state 会在逻辑线程关闭，finalizer 不会在音频线程执行。Lua 或 callback protocol 错误会被锁存，并由 Manager update 从对应 state 取出后在逻辑线程报告。直接安装在 raw source、且使用共享 Lua VM 的 processor 则遵循 LuaSF 通用 try-enter contract；竞争时可能 dry-bypass 单个 block，不具备 Manager 的隔离保证。

SFML 可能已经把声源报告为 `Stopped`，但该状态下第一次被观察到的 effect callback 仍包含最后一个真实输入 block；后续调用则可能是正 frame count 的静音，而不是空 EOS。Manager 返回 handle 上的第一方 trampoline 会把这一个真实尾块完整处理一次，经过原子的 natural-ending 阶段后，才把后续调用规范化为 `nil` 加零 input frame。Manager 的无 callback 兜底会等待一个逻辑 update，不能抢先吞掉该尾块。Managed preset generation 会保持 EOS pending，直到 Lua 确认完成。EOS 完成后，trampoline 会直接在原生层返回 `0/0`，不再进入 Lua，直到声源重播。直接安装在 raw `sf.Sound` 或 `sf.Music` 上的 processor 遵循 SFML 原始 callback stream，不具备这套 managed EOS/control 协议。该桥接不修改 SFML。

`Echo` 每次处理输入后都会把 control 标记为 tail-pending。最后一个非空尾音 block 输出后仍保持 pending，直到下一次空 EOS callback 返回 `0/0` 才变为 drained，防止最后一块尾音被截断。每个 managed preset 只有在 Lua processor 确实收到 EOS 并重置状态后才会结束 EOS 确认屏障。因此，SFML 的 `Stopped` 状态可能在 managed EOS 和尾音排空前就已可见，不能把它当作可立即重播的安全信号。保留的 handle 只有在 EOS 完成后重播才保证重置 preset 状态；若要立即重启，应通过 Manager 创建新声源。

通过 Manager 显式停止、通过 Manager 返回的 `sf.Sound` 或 `sf.Music` handle 直接停止、替换 processor、跳过对话或 shutdown 时，都会先 cancel 并丢弃剩余尾音。每个 managed source 都会在播放前只安装一次稳定的原生 trampoline；替换或清空 processor 时只会原子切换 trampoline 的目标，不会在音频线程可能正在使用 callback 时覆写 SFML 内部 callback。无锁 generation gate 会在 cancel 后拒绝新的 activity，并让已经开始的 processor 调用退出后再让 replace 或 clear 返回。被取消的 generation 会由 managed source 持有，直到观察过它的 callback 全部静止；随后其 Lua callback 引用与 isolated state 会在 audio lock 之外由调用线程销毁，绝不交给音频线程析构。Effect processor 不是 lifecycle callback；在这个音频 callback 内调用 managed `play`、`pause`、`stop`、替换或清空 processor，或调用对应的 Manager 操作，都会被拒绝并通过 LuaSF deferred-error 路径报告。取消后的真实输入 block 会被消费并输出静音，EOS 返回 `0/0`。Manager 挂接、播放发布、停止和 shutdown 时，调用 Lua、等待音频或销毁 callback 引用均不会持有 Manager 音频 mutex。Shutdown 会拒绝新播放并移出 Manager record/attacher，取消并停止声源，等待正在进行的声源挂接，销毁它们的 isolated state，关闭 audio-effect runtime，之后才允许玩法 LuaSF state 与 Lua VM 关闭。raw source 不提供这套 generation gate、cancellation protocol 或 self-wait 拒绝，因此 raw effect callback 绝不得对自己所属的 source 调用需等待 producer 的生命周期操作。

`NodeFunctions.Scene.ShowVoiceMessageByTag` 和 `ShowVoiceMessage` 会在对话生命周期内捕获并持有本次调用实际启动的 Voice handle。对话结束时，它们的 latent condition 会先停止该 handle，再通过 `FinishedDialogue` 恢复后续 Blueprint 执行，因此旧 latent condition 不会误停后来启动的 Voice。紧随其后的 `SetEffect` 会配置下一段 Voice，而不会修改刚结束对话所使用的音频。离开或销毁地图场景时也会停止当前全局 Voice。普通消息节点不会改变 Voice 播放。

## Shader、雾与转场

图层 shader、屏幕转场、雾、闪烁、色调和震动由 runtime 实现。请通过 `sf.Shader.isAvailable()` 与 `sf.Shader.isGeometryAvailable()` 检测可选能力，保留可玩的 fallback，并测试关闭可选效果后的相同地图。

雾贴图遵循普通 RGBA 语义：RGB 提供雾颜色，Alpha 提供逐像素密度，地图的 `fogPower` 缩放最终不透明度。Shader 路径和 Sprite fallback 使用相同的颜色与 Alpha 解释。

地图雾效数据采用严格的可选字段协议。`fog` 是字符串；缺失、为 `nil` 或为空白时禁用雾效。`fogPower`、`fogOx`、`fogOy` 与 `fogDistort` 必须是 float 范围内的有限数值，并且仅在缺失或为 `nil` 时默认为 `0`。小于等于 `0` 的 `fogPower` 同样禁用雾效。强度与扭曲度会向下取整并 clamp 到 `0..100`，两个 offset 字段控制滚动。不接受数值字符串或其他标量 coercion。

Sample 的高级敌人击败特效由全局类设置 `Enemy.DefeatShatterEffectEnabled` 控制；该设置默认为 `true`，且不是 Blueprint 字段。它的 Shader 会把视觉快照绘制为世界空间逻辑像素碎片，并在约 0.65 秒内从中心径向向外消散。此时敌人已经被记录并销毁，所以快照不影响可通行性，也不参与碰撞或遮光。当该设置为 `false`，或 `sf.Shader.isAvailable()` 返回 false 时，敌人会改为立即消失。

## 视频

视频播放需要启用 FFmpeg 的项目或模板。视频放在 `Assets/Videos`，并打包正确 runtime 变体。Windows 与 macOS 的 FFmpeg 构建使用共享库或动态库；iOS、HarmonyOS 与 Android 视频需要 C++ Source + FFmpeg，并使用 `Sample/cmake/FFmpeg` 构建的静态 `.a` 库。下游发行必须满足 `Licenses/FFmpeg/README.md` 所述的适用 LGPL 重链接材料要求。Android 裁剪构建保留 file protocol、MOV demuxer、H.264/AAC decoder 与 parser、swscale 和 swresample，不启用 network、JNI、MediaCodec 或硬件加速。资源存在并不表示非 FFmpeg 模板能够播放。

## 限制

Shader 可用性由运行时图形环境决定；编辑器预览成功不代表目标硬件具备同等支持。

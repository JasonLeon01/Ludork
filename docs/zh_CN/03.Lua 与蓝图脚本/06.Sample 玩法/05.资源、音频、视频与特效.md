# 资源、音频、视频与效果

## 适用范围

本页说明 Sample 的运行时资源路径约定、媒体模板边界，以及可选渲染能力不可用时的 fallback 要求。

## 资源路径

使用 `Assets/System/Icon.png` 这类不带前导 `./` 的项目相对资源路径和 metadata 驱动的选择器。C++ manager 会缓存 texture、shader 和 audio 资源；Lua 中不要自行拼接操作系统路径分隔符。Android 会把最终化资源作为 APK assets 保存，并在原生启动前镜像到内部 runtime 目录，因此 SFML 与普通文件系统调用都使用同一个 `Assets/...` key。只有行为确实因平台而异时才读取 `PLATFORM`。

## 音频

音乐、音效和语音在 `Main.ini` 中拥有独立开关与音量。GlobalFunctions 的 Manager 分组提供玩法侧辅助函数。缺失的可选音效路径应显式处理；用不同拼写重复加载同一资源会破坏缓存效果。

音频 Effect 是登记在 `Source.AudioEffects.EFFECTS` 中的项目 Lua 处理器；该字典把 preset 名称映射到处理器工厂函数。Sample 默认提供带脚本默认参数的 `Echo`、`Distortion`、`Underwater` 和 `BehindWall` 四个 preset。`BehindWall` 使用两级低通滤波和音量衰减，产生声音隔着实体障碍物传来的沉闷效果。`NodeFunctions.System.SetEffect(audioType, effect)` 可以分别为 `Sound`、`Voice` 或 `Music` 选择当前 preset，metadata 会把两个参数都显示为下拉框。选择后会立即应用到该通道正在播放的声源，并成为之后新播放声源的默认 Effect。选择字面量 `nil` 可清除该通道当前和后续播放的 Effect。新 preset 应加入脚本 registry，并把 key 同步到 `SetEffect` metadata 的下拉列表。Effect 选择不再属于 `SoundFilter` 或 `MusicFilter`。

SFML 在每个声源上只保存一个 Effect processor。选择另一个 preset 会替换当前 processor；preset 不会自动串联或混合。

## Shader、雾与转场

图层 shader、屏幕转场、雾、闪烁、色调和震动由 runtime 实现。请通过 `sf.Shader.isAvailable()` 与 `sf.Shader.isGeometryAvailable()` 检测可选能力，保留可玩的 fallback，并测试关闭可选效果后的相同地图。

## 视频

视频播放需要启用 FFmpeg 的项目或模板。视频放在 `Assets/Videos`，并打包正确 runtime 变体。Windows 与 macOS 的 FFmpeg 构建使用共享库或动态库；iOS、HarmonyOS 与 Android 视频需要 C++ Source + FFmpeg，并使用 `Sample/cmake/FFmpeg` 构建的静态 `.a` 库。下游发行必须满足 `Licenses/FFmpeg/README.md` 所述的适用 LGPL 重链接材料要求。Android 裁剪构建保留 file protocol、MOV demuxer、H.264/AAC decoder 与 parser、swscale 和 swresample，不启用 network、JNI、MediaCodec 或硬件加速。资源存在并不表示非 FFmpeg 模板能够播放。

## 验证

测试资源缺失、不支持的 shader、静音通道、音量边界、重复场景切换和打包相对路径。必须检查最终包，不能只检查开发目录。

## 限制

不提供 Standalone iOS、HarmonyOS 或 Android 模板，因此这些目标的视频都必须使用 C++ Source + FFmpeg 路径，并遵守其静态链接分发义务。Shader 可用性由运行时图形环境决定；编辑器预览成功不代表目标硬件具备同等支持。

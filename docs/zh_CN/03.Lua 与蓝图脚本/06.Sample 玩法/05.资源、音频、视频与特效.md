# 资源、音频、视频与效果

## 适用范围

本页说明 Sample 的运行时资源路径约定、媒体模板边界，以及可选渲染能力不可用时的 fallback 要求。

## 资源路径

使用项目相对资源路径和 metadata 驱动的选择器。C++ manager 会缓存 texture、shader 和 audio 资源；Lua 中不要自行拼接操作系统路径分隔符。只有行为确实因平台而异时才读取 `PLATFORM`。

## 音频

音乐、音效和语音在 `Main.ini` 中拥有独立开关与音量。GlobalFunctions 的 Manager 分组提供玩法侧辅助函数。缺失的可选音效路径应显式处理；用不同拼写重复加载同一资源会破坏缓存效果。

## Shader、雾与转场

图层 shader、屏幕转场、雾、闪烁、色调和震动由 runtime 实现。请通过 `sf.Shader.isAvailable()` 与 `sf.Shader.isGeometryAvailable()` 检测可选能力，保留可玩的 fallback，并测试关闭可选效果后的相同地图。

## 视频

视频播放需要启用 FFmpeg 的项目或模板。视频放在 `Assets/Videos`，并打包正确 runtime 变体。Windows 与 macOS 的 FFmpeg 构建使用共享库或动态库；iOS 视频需要 C++ Source + FFmpeg，并使用 `Sample/cmake/FFmpeg` 构建的静态 `.a` 库。下游发行必须满足 `Licenses/FFmpeg/README.md` 所述的适用 LGPL 重链接材料要求。资源存在并不表示非 FFmpeg 模板能够播放。

## 验证

测试资源缺失、不支持的 shader、静音通道、音量边界、重复场景切换和打包相对路径。必须检查最终包，不能只检查开发目录。

## 限制

不提供 Standalone iOS 模板，因此 iOS 视频必须使用 C++ Source + FFmpeg 路径，并遵守其静态链接分发义务。Shader 可用性由运行时图形环境决定；编辑器预览成功不代表目标硬件具备同等支持。

# Actor、敌人、物品与装备

## Actor 与 Character

`Actor` 提供地图所有权、位置、生命周期和碰撞相关行为。Character 类增加移动和朝向。公开类默认值必须写在 Lua 类表上；`init` 只用于构造参数和私有运行时状态。

### 组合式大地图中的 Actor

`WorldGameMap` 维护一份大地图坐标 Actor registry。跨越已就绪的子地图边界时迁移同一实例；空洞仍属于大地图。启用碰撞的 Actor 不能进入未加载 placement，无碰撞 root 则休眠并异步请求目标。

只有 Active 32×32 格 chunk 中的 root 参与模拟和绘制。离开时调用 `onWorldSleep()`，返回时调用 `onWorldWake(elapsedSeconds)`，但不替代 `onCreate` 或 `onDestroy`。从未 Active 的 Prepared root 不接收生命周期，也不会被玩法查询返回。

Tile 与 Actor 按清单 `layerOrder` 绘制；运行时专用图层按首次出现顺序追加。Player 在所属图层保持最后。隐藏子地图 Tile 图层时，该层 Actor 也不会参与颜色与光照 surface 绘制。

`getActorByTag` 在不加载子地图的情况下查找 Active Actor 和已激活后休眠的驻留 root；被淘汰 Actor 在重载前保持缺失。

`SceneMap:recordDestroyedActorTag` 会屏蔽驻留及未来 payload 中的该身份，不会为缺失子地图产生 I/O。被屏蔽 Actor 不能执行生命周期、被查询或在淘汰后重现。接收 Actor 的 `recordDestroyedActor` API 仍然只负责记录。

## 移动、寻路与动画

`GameMap` 会缓存地块可通行性和动态 Actor 占用。Actor 列表或地形变化时会重建相应缓存，普通移动只更新单个 Actor 的占用；执行 A* 前，寻路会核对并更新占用格发生变化的 Actor。A* 与实际移动使用相同的 Dir4 边规则：Actor 每个新进入的前沿格都必须允许从来源地块向该方向离开，并允许从目标地块的反方向进入。点击移动对普通目标与单格阻挡目标会复用直接 A* 结果；若移动 Actor 的完整占用范围使该直接结果不可用，则回退为搜索目标的相邻格。碰撞目标仍作为最后一次尝试移动，以继续触发其碰撞交互。回退到相邻格时，若不可通行的目标格已无碰撞体，则停在相邻格而不再向目标格 bump。普通无碰撞 `onOverlap` Actor 仍会令移动停在邻格；显式点击 Teleporter 时则会进入所选占用格，以触发 overlap 传送。

大地图寻路可跨越已加载的子地图边界，但把未加载子地图视为不可用，且不产生隐式 I/O。空洞仍可通行，top material 为 nil。

`GameMap.MapViewRect` 定义逻辑屏幕中的地图画布，默认值为 `sf.IntRect.new(192, 32, 416, 416)`。其 position 决定画布位置，size 同时决定裁剪绘制范围与 Camera 视野尺寸。地图某轴小于画布时在该轴内居中，大于画布时限制在可滚动范围内。地图绘制、指针坐标转换、世界/UI 定位、动画、光照、雾与天气统一使用该矩形，画布外的指针输入会被忽略。

`PathRouteState` 持有路线副本，并公开随路线变化的 revision。预览渲染器只在 revision 变化后刷新缓存路线，复用矩形图形，并在玩家进入另一个地图格时裁剪可见路线。若 texture rectangle 尺寸不变，仅修改图集帧源位置不会刷新 Actor 边界；帧尺寸变化时仍会刷新缓存边界与占用格。

实时地图缓存移动危险：领域使用小于配置范围的曼哈顿距离，夹击要求敌人位于两侧，阻击影响相邻格，同格正伤害会累加。取得怪物手册后，`EnemyDamageHintLevel` 的 `NONE`（`0`）不显示提示，`BATTLE`（`1`，默认）显示敌人读数，`MAP`（`2`）再显示危险格总伤害。提示不产生玩法副作用。

点击寻路始终排除正伤害格，即使提示尚未显示；明确点击的目标格例外。点击领域或阻击敌人时，只移除该目标的贡献，包括它在夹击中的一侧；玩家不会占用的碰撞或 overlap 目标忽略目标格危险。

新进入 Active 的大地图 chunk 会刷新缓存。危险 revision 只在影响剩余路线或可进入敌人目标时使移动失效；失效路线退回最后完整格并重算。

## 敌人

Enemy Blueprint 把类默认值与 Enemy General Data 成员组合。运行时数据提供战斗数值、奖励、掉落、动画和特殊效果配置。`onDefeat` graph 可选，只在存在时执行。

`MAXHP` 是 Enemy 与 Player 共用的 Battler 耐久属性。当前 `HP` 只属于 `PlayerInfoComponent`：敌人战斗与预览直接根据 Enemy 的 `MAXHP` 计算致命一击前的轮数，Enemy 不保存可变的当前生命值。

Enemy `special` 以 JSON literal 保存 integer 参数、boolean flag 和 `Reborn` Blueprint 类路径 string。

`drops` 把每个 Item Blueprint 类路径映射到一个 `sf.Vector2i` offset。`onDefeat` 完成后，所有配置的 Item 会在敌人移除前完成校验，再在同一图层以“敌人地图坐标 + offset”作为目标位置生成。地图持久化 tag 按地图编辑器约定由 Blueprint 路径和绝对目标坐标组成。已有相同 tag 时，Sample 只跳过该掉落并记录 warning；否则 Item 正常执行 `onCreate`、记录为 added Actor，并执行一次 `onDrop`。无效路径或未继承 `Source.Item` 的 Blueprint 属于必需数据错误。

`Enemy.DefeatShatterEffectEnabled` 是全局类设置，默认值为 `true`；它不是 Blueprint 字段，不能逐个敌人覆盖。击败流程收尾时，Sample 会立即把敌人记录为 destroyed 并调用 `destroy()`，因此敌人不再阻挡移动，其所在格可立即通行。该设置开启且 Shader 可用时，视觉快照会保留约 0.65 秒，并以世界空间逻辑像素碎片从中心径向向外消散。快照只参与绘制，不参与碰撞或遮光。关闭该设置或运行环境不支持 Shader 时，继续使用立即消失的表现。

带 `Reborn` special 的敌人会把该 special 的非空字符串值作为 Blueprint 类路径。原敌人记录并销毁后，替代 Actor 会以新的地图持久化 tag 在相同格子和图层生成，正常执行 `onCreate`，并记录为 added Actor。因此地图切换和存读档会继续移除原放置对象，并且只恢复一个替代 Actor。无效 Reborn 路径属于必需数据错误。

`afterBattleVarChanges` 默认为空 dictionary，每项战后更新保存为 `variableName = { operator, operand }`。新增条目时先从尚未使用的已声明 `int` 或 `float` 游戏变量中选择。运算符默认为 `=`，可从 `=`、`+`、`-`、`*`、`/`、`//`、`%`、`**` 中选择；操作数默认为 `0` 或 `0.0`，并使用已选变量对应的整数或浮点编辑器。在整数变量与浮点变量之间切换时，操作数会重置为相应类型的零值。这些类型只约束编辑器创作：`GameInstance` 不在运行时强制游戏变量类型，保存值仍是 object key 加双元素 array。

伤害预览只计算攻击者打出致命一击之前发生的反击。防守方最大生命为 `H`、每轮受到的正伤害为 `D` 时，反击次数为 `max(ceil(H / D) - 1, 0)`。

累计的领域、夹击、阻击伤害导致玩家战败时，Sample 会立即结算该伤害，但只在同时开始的攻击动画中最长者播放完毕后进入 Game Over 场景，与普通敌人战斗的时序一致。

## 物品

Item 记录定义显示、可用性、价格、图标和使用后是否消耗。成员 graph 实现背包 `onUse` 与敌人掉落 `onDrop`；Item 不存在 `onGet` 事件或 `kwargs` 数据字段。可复用算法应放入 Lua 或 Common Function，不要在多个成员中复制大型图。

最高占用图层内的碰撞回调会从视觉最上方 Actor 向最下方 Actor 执行；同一图层中，Actor 列表里越靠后的对象越晚绘制、越先触发。多个可拾取 Item 占据同一格时，一次受阻的移动尝试因此只会拾取视觉最上方 Item；该对象销毁后结束本次碰撞派发，下一件 Item 由之后的移动尝试拾取。持续按住方向键时，后续 fixed update 可以继续拾取，而不要求先松开按键。

`NodeFunctions.Mota.CenterSymmetricTeleport`、`GoUpstairsSamePos` 与 `GoDownstairsSamePos` 提供中心对称飞行器、上楼器与下楼器的可复用逻辑。相邻楼层节点遵循当前区域的地图顺序，并在切换地图前，以玩家当前的零基坐标检查应用了持久状态的目标地图；中心对称节点在当前地图上使用 `(width - 1 - x, height - 1 - y)` 作为目标。每个节点都公开 `Success` 与 `Failed` 执行分支；失败时会解析 `FLY_FAIL` 并显示 CommonTip，且不会扣除物品。配置消耗型物品 graph 时，只把 `Success` 连接到 `NodeFunctions.Player.RemoveItem`。

## 装备

Equip 记录定义槽位和整数属性增量。`onEquip` 与 `onUnequip` graph 在普通数值变化前后实现特殊行为。槽位名必须与选择的 Class 数据一致。

## 运行时引用

General Data 标识符应作为稳定 key。Runtime 应用会保持每个 string 的原值，因此 class、animation 与装备槽位 key 不依赖当前语言。显示名称和说明可以使用花括号本地化标识符；仅在展示时通过 `LOC` 解析，并在语言变化后重新解析。查找表由[游戏本地化工作流](<../../05.插件开发与安装/06.游戏本地化工作流.md>)管理。重命名标识符时必须更新所有引用。

Sample 的精确 schema 与成员列表见“General Data 参考”；Bottle、Gem、门和敌人范例见“用法范例”。

## 限制

General Data 标识符属于项目契约，重命名时不会自动修复全部引用。Sample 中的战斗和库存规则仅为示例，不是引擎强制行为。

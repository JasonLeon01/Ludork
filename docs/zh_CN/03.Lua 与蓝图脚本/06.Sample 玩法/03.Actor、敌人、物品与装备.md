# Actor、敌人、物品与装备

## Actor 与 Character

`Actor` 提供地图所有权、位置、生命周期和碰撞相关行为。Character 类增加移动和朝向。公开类默认值必须写在 Lua 类表上；`init` 只用于构造参数和私有运行时状态。

### 组合式大地图中的 Actor

`WorldGameMap` 维护一份大地图坐标 Actor registry。跨越已就绪的子地图边界时迁移同一实例；空洞仍属于大地图。启用碰撞的 Actor 不能进入未加载的摆放（placement）；无碰撞的 root 会休眠，并异步请求这些摆放。

只有 Active 32×32 格 chunk 中的 root 参与模拟和绘制。离开时调用 `onWorldSleep()`，返回时调用 `onWorldWake(elapsedSeconds)`，但不替代 `onCreate` 或 `onDestroy`。从未 Active 的 Prepared root 不接收生命周期，也不会被玩法查询返回。

Tile 与 Actor 按清单 `layerOrder` 绘制；运行时专用图层按首次出现顺序追加。Player 在所属图层保持最后。隐藏子地图 Tile 图层时，该层 Actor 也不会参与颜色与光照 surface 绘制。

`getActorByTag` 在不加载子地图的情况下查找 Active Actor 和已激活后休眠的驻留 root；被淘汰 Actor 在重载前保持缺失。

地图索引与流送使用原生 root-first BFS 遍历 Actor 树并保持 child 顺序；重复 Actor 和环会报错。

`SceneMap:recordDestroyedActorTag` 会屏蔽驻留及未来 payload 中的该身份，不会为缺失子地图产生 I/O。被屏蔽 Actor 不能执行生命周期、被查询或在淘汰后重现。接收 Actor 的 `recordDestroyedActor` API 仍然只负责记录。

## 移动、寻路与动画

`GameMap` 会缓存地块可通行性和动态 Actor 占用。Actor 列表或地形变化时会重建相应缓存，普通移动只更新单个 Actor 的占用；执行 A* 前，寻路会核对并更新占用格发生变化的 Actor。A* 与实际移动使用相同的 Dir4 边规则：Actor 每个新进入的前沿格都必须允许从来源地块向该方向离开，并允许从目标地块的反方向进入。点击移动对普通目标与单格阻挡目标会复用直接 A* 结果；若移动 Actor 的完整占用范围使该直接结果不可用，则回退为搜索目标的相邻格。碰撞目标仍作为最后一次尝试移动，以继续触发其碰撞交互。回退到相邻格时，若不可通行的目标格已无碰撞体，则会停在相邻格，而不再向目标格顶撞（bump）。普通无碰撞 `onOverlap` Actor 仍会令移动停在邻格；显式点击 Teleporter 时则会进入所选占用格，以触发 overlap 传送。

大地图寻路可跨越已加载的子地图边界，但把未加载子地图视为不可用，且不产生隐式 I/O。空洞仍可通行，其顶层材质（top material）为 nil。

稀疏大地图的就绪、通行、Dir4 与 top material 查询均在原生层完成。prepared 范围限制移动；材质查询仍使用独立的就绪规则。

`GameMap.MapViewRect` 定义逻辑屏幕中的地图画布，默认值为 `sf.IntRect.new(192, 32, 416, 416)`。其 position 决定画布位置，size 同时决定裁剪绘制范围与 Camera 视野尺寸。地图某轴小于画布时在该轴内居中，大于画布时限制在可滚动范围内。地图绘制、指针坐标转换、世界/UI 定位、动画、光照、雾与天气统一使用该矩形，画布外的指针输入会被忽略。

`PathRouteState` 持有路线副本，并公开随路线变化的 revision。预览渲染器只在 revision 变化后刷新缓存路线，复用矩形图形，并在玩家进入另一个地图格时裁剪可见路线。若 texture rectangle 尺寸不变，仅修改图集帧源位置不会刷新 Actor 边界；帧尺寸变化时仍会刷新缓存边界与占用格。

Domain（领域）、Flank（夹击）与 Blockade（封锁）Effect 授予 `Gameplay.Movement.Hazard`。移动与 `MovementDangerGrid` 都调用 `MovementSpecials.Preview`，由它派发 `Event.Movement.QueryHazard`；空间规则只放在这条路径中。Domain 使用曼哈顿范围，Flank 要求敌人位于相邻两侧，Blockade 影响相邻格，正伤害累加。取得怪物手册后，`EnemyDamageHintLevel` 可选择不显示（`NONE`，`0`）、显示敌人读数（`BATTLE`，`1`，默认）或再显示危险格读数（`MAP`，`2`）。提示没有玩法副作用。

点击寻路始终排除正伤害格，即使提示尚未显示；明确点击的目标格例外。点击 Domain 或 Blockade 敌人时，只移除该目标的贡献（包括它在 Flank 中的一侧）；玩家不会占用的碰撞或 overlap 目标，会忽略目标格的危险。

新进入 Active 的大地图 chunk 会使危险缓存失效。完整网格仅供地图提示或点击寻路按需生成；单格查询只计算该格。危险 revision 只在影响剩余路线或可进入敌人目标时使移动失效；失效路线退回最后完整格并重算。

## 敌人

Enemy Blueprint 会选择一个 Enemy General Data 成员。`GeneralDataTypes.Create` 将其复制为 `EnemyAttributeSet`；`Battler` 通过 `attributes` 公开该集合，并持有对应的 `AbilitySystemComponent`。Enemy General Data 不声明成员事件，战斗行为使用显式 Gameplay Ability 与 Effect。

`MAXHP` 是 Enemy 的虚拟耐久，Enemy 不保存可变 `HP`。Player `HP` 属于 `PlayerAttributeSet`，初值 `1000` 来自 Player General Data，不作为 attribute override 写进 Blueprint JSON。

Player HP Current 在 modifier 之后钳制到 `0..MAXHP`。永久 MAXHP 与 LEVEL 成长只响应 Base 变化，因此临时 Infinite Effect 不会改变永久成长。

Enemy 的 `special` 保留整数次数/范围、仅表存在的 `""`、`Vampire` 比例、`FixDmg` 数值/表达式与 `Reborn` 类路径。每一项都会转换为 Infinite `Special.<id>` Effect，并带有同名 tag 与聚焦用途的 ability。战斗类 special 修改战斗 Gameplay Event；移动类 special 使用 `Event.Movement.QueryHazard` 与 `Gameplay.Movement.Hazard`。

每个 Enemy 都授予 `Ability.Combat.MotaBattle`。无副作用的计算返回伤害明细与数值 `BattleResult`（`WIN`、`CANNOT_DAMAGE` 或 `LETHAL_COUNTER_DAMAGE`）。碰撞会在 `CommitResult(result)` 前校验伤害、Game Over、奖励和 State Effect Spec；预览复用同一计算且不修改状态。

`drops` 把 Item Blueprint 路径映射到 `sf.Vector2i` offset。有效掉落会在敌人图层上生成、记录为 added Actor，并通过 `GeneralDataGraphAbility` 激活 `onDrop` graph。重复的放置 tag（placement tag）会跳过该掉落；无效路径或非 Item Blueprint 会报错。

`Enemy.DefeatShatterEffectEnabled` 是全局类设置，默认值为 `true`；它不是 Blueprint 字段，不能逐个敌人覆盖。击败流程收尾时，Sample 会立即把敌人记录为 destroyed 并调用 `destroy()`，因此敌人不再阻挡移动，其所在格可立即通行。该设置开启且 Shader 可用时，视觉快照会保留约 0.65 秒，并以世界空间逻辑像素碎片从中心径向向外消散。快照只参与绘制，不参与碰撞或遮光。关闭该设置或运行环境不支持 Shader 时，继续使用立即消失的表现。

胜利且双方攻击动画结束后，执行 Enemy Actor Blueprint 的 `onDefeat` 事件；它完成后进入固定结算：应用游戏变量变化、记录并销毁 Enemy、生成掉落或 Reborn，然后应用奖励与 State。Enemy General Data 没有 `onDefeat` graph。

带 `Reborn` special 的敌人会把该 special 的非空字符串值当作 Blueprint 类路径。原敌人被记录并销毁后，替代 Actor 会以新的地图放置 tag（map-placement tag），在相同的格子和图层生成，正常执行 `onCreate`，并记录为 added Actor。因此地图切换与存读档会继续移除原放置对象，而且只会恢复一个替代 Actor。无效的 Reborn 路径属于必需数据错误。

`afterBattleVarChanges` 为已声明的 `int` 或 `float` 变量保存 `variableName = { operator, operand }`。运算符支持 `=`、`+`、`-`、`*`、`/`、`//`、`%` 与 `**`；存储形状仍是 value 为双元素 array 的 object。

击败准备会在造成战斗伤害之前，校验已配置的运算。`onDefeat` 之后，固定结算会通过固定的 `Engine.Eval` 表达式与新的局部变量，按当前变量再次求值这些运算；存储的 operator 永远不会作为源码执行。

伤害预览只计算致命一击前的反击。无回复时，最大生命 `H` 与每轮正伤害 `D` 产生 `max(ceil(H / D) - 1, 0)` 次反击。`Vampire = R` 在每次非终结反击后回复 `floor(counterDamage * R)`；非一击伤害不大于回复量时无法取胜，否则次数为 `ceil((H - D) / (D - 回复量))`。`First` 在玩家首次攻击前增加一次攻击，敌人满血时不产生有效回复。`FixDmg` 直接使用数值，或在替换当前 `{m<属性>}` / `{e<属性>}` 值之后对字符串求值；有限非负的结果会向下取整，并加在回合伤害与先攻伤害之后。

当累计的 Domain、Flank 或 Blockade 伤害导致玩家战败时，Sample 会立即结算该伤害，但会等到同时开始的所有攻击动画中耗时最长者播放完毕，才进入 Game Over 场景，与普通敌人战斗的时序一致。

## 物品

Item 的成员图把 `onUse` 与 `onDrop` 实现为显式激活的 `GeneralDataGraphAbility`，而不是 Actor 事件。`onUse` 以 Player 为 target；`onDrop` 以新生成的 Item Actor 为 target。因此，绑定 target 的节点应使用 `GameplayEventData.target`，Player State 相关节点应放在 `onUse` 里。

最高占用图层内的碰撞回调会从视觉最上方 Actor 向最下方 Actor 执行；同一图层中，Actor 列表里越靠后的对象越晚绘制、越先触发。多个可拾取 Item 占据同一格时，一次受阻的移动尝试因此只会拾取视觉最上方 Item；该对象销毁后结束本次碰撞派发，下一件 Item 由之后的移动尝试拾取。持续按住方向键时，后续 fixed update 可以继续拾取，而不要求先松开按键。

`NodeFunctions.Mota.CenterSymmetricTeleport`、`GoUpstairsSamePos` 与 `GoDownstairsSamePos` 提供中心对称飞行器、上楼器与下楼器的可复用逻辑。相邻楼层节点遵循当前区域的地图顺序，并在切换地图前，以玩家当前的零基坐标检查应用了持久状态的目标地图；中心对称节点在当前地图上使用 `(width - 1 - x, height - 1 - y)` 作为目标。每个节点都公开 `Success` 与 `Failed` 执行分支；失败时会解析 `FLY_FAIL` 并显示 CommonTip，且不会扣除物品。配置消耗型物品 graph 时，只把 `Success` 连接到 `NodeFunctions.Player.RemoveItem`。

## 装备

装备 `attrPlus` 会转换为以 slot 为 source 的 Infinite Effect。它在显式 `onEquip` graph 前应用，在 `onUnequip` 前移除；slot 名必须匹配 Class 数据。

State 是带 `State.<id>`、stack、modifier 与 ability 的 Infinite Effect。Weak 每 stack 减少 1 ATK/DEF，最小为零；HUD 显示 Ability System 的 Current 值与 Weak stack 数，因此 Base 为 10、两层 Weak 时显示 `8 (-2)`。Poisoned 通过 `Event.Combat.ResolveIncomingDamage` 增加伤害。State graph 分别监听 `Event.Movement.Step`（`onWalk`）与 `Event.State.Trigger.<id>`（显式 hook）。

## 运行时引用

General Data 标识符应作为稳定 key 使用。运行时应用会原样保留每个 string，因此 class、animation 与装备槽位 key 不依赖当前语言。显示名称和说明可以使用花括号本地化标识符；仅在展示时通过 `LOC` 解析，并在语言变化后重新解析。查找表由[游戏本地化工作流](<../../05.插件开发与安装/06.游戏本地化工作流.md>)管理。重命名标识符时必须更新所有引用。

Sample 的精确 schema 与成员列表见“General Data 参考”；Bottle、Gem、门和敌人范例见“用法范例”。

## 限制

General Data 标识符属于项目契约，重命名时不会自动修复全部引用。Sample 中的战斗和库存规则仅为示例，不是引擎强制行为。

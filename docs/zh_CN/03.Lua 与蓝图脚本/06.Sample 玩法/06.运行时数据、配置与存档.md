# 运行时数据、配置与存档

## 配置

`Data/Configs` 保存游戏配置 JSON，`Main.ini` 保存可变启动和用户设置。应使用配置 API 与编辑器字段，让未知的 section/key 在一次读写往返（round trip）后仍然保留。

资源型 Config `file` 字段保存完整 `/Game/Assets/...` 路径，`base` 与 `ext` 只约束选择器。Data 引用独立处理：`System.json` 的 `startPlayerBlueprint` 使用 `root = "Data"`，相对 `Data/Blueprints` 保存并转换为 `Data.Blueprints.*`；`startRegion` 指定初始区域。两者仅影响新游戏，存档保留自身的玩家类与区域。

格子尺寸由编译后的引擎固定，默认 `32`，通过 `Engine.GetCellSize()` 查询。`System.json` 与系统配置编辑器不再配置该值；遗留的 `System/cellSize` 字段不会被使用或编辑，也不会转换为运行时设置。

Sample 的 Lua 配置模块位于 `Scripts/Source/Configs`，通过 `Source.Configs.*` 加载。

编辑器模式下，`LUDORK_EDITOR=1` 选择项目内 `Main.ini`。普通打包运行使用平台用户数据目录，并在适用时以打包配置作为初始来源。

Android 发行包会在原生运行时启动前，把不可变运行时资源镜像到 `filesDir/ludork/runtime/<runtime-hash>`。可变配置与存档使用 `filesDir/ludork/user-data`；它们不会写回带版本的运行时目录，也不需要外部存储权限。

## 运行时状态

不可变定义放在 Blueprint、Config 或 General Data 文件中；可变游戏状态放在游戏实例、Actor 或组件上。不要把临时状态写回源码 JSON。

`Data.GetClassData(path)` 暴露的共享会话定义遵循 [类定义与会话生命周期](<../04.蓝图脚本/01.执行流、事件与变量.md#类定义与会话生命周期>)。

使用 `Source.Configs.GeneralDataTypes.Create` 从通用数据创建属性集。值转换与默认值规则见[通用数据](<../../02.编辑器用户指南/05.General Data 与 Text Config.md>)。

### 玩家

`GameInstance` 使用 `_playerKeys` 保存玩家顺序，使用 `_players` 保存以 `Player.ID` 中稳定 Player General Data key 为键的玩家对象。Player key 必须非空且唯一。`getPlayers()` 返回实际的 key 字典（非副本），`getPlayerKeys()` 返回实际的有序 key 数组（非副本）。首个 key 标识 `getPlayer()` 使用的主 Player；`getPlayerByIndex()` 通过同一顺序解析零基索引，`setPlayer(playerKey)` 则把已存在的 key 移到首位。

存档使用同级的 `playerKeys` 和 `players` 字段保留这一结构。顺序以 `playerKeys` 为准，其中每个键必须在 `players` 中恰好对应一项，且与恢复后的 `Player.ID` 一致。

每个 Player 在 `attr` 下保存数值 Attribute Set Base：`LEVEL`、`HP`、`MAXHP`、`ATK`、`DEF`、`EXP` 与 `GOLD`。派生 Current 不会保存；非数值 attribute 从 Player General Data 重建。数值必须有限，并符合生成的 `int` 或 `float` schema。

存档保留物品/装备数量、已装备 ID 与 State stack。读取时先恢复全部 Base，再重建 Item ability、装备 Effect 与 State Effect，不执行初始装备或成员图。Handle、派生 Current、临时 Effect、ability spec 与 tag 不保存；新增持久效果需要独立的稳定记录与重建步骤。

玩家存档要求与 `attr` 同级的字符串 `customName`。`""` 表示 General Data 的本地化默认名；非空值必须已去除首尾空白，并符合 [Player 名字规则](<../07.API 参考/02.源码类/12.Player.md>)。

### 游戏变量

运行时从生成的 `Scripts/Source/Configs/GameVariables.lua` 读取初始值；启动前须保存 [Game Variable Manager](<../../02.编辑器用户指南/05.General Data 与 Text Config.md#game-variable-manager>) 中的修改。list 和 dict 初始值使用普通 Lua table，不使用 Standard 容器；空 table 经过 JSON 序列化后不保证保留 array 与 object 的区别。

`GameInstance:init` 会 `deepcopy` 生成的运行时映射，因此每个新游戏都会获得彼此独立的可变初始值。Sample 声明了 `MTExample = 0` 与 `ShopPrice = 20`。运行时系统仍可创建动态名称，但只有编辑器中声明的名称会出现在 `InstVar` 选择器中。

读取存档时，会以该存档保存的变量 table 覆盖新建实例上的变量 table。因此生成初始值只用于新游戏：增加、删除或修改声明不会迁移或合并已有 slot。修改声明类型同样只会重置项目初始值，不会改变存档中已保存的值。

变量快照包含被监听字段的当前逻辑值。`deepcopy` 不复制 monitor 代理和订阅，因此 ConditionalActor 的监听只存在于当前游戏实例。恢复记录后，`onCreate` 监听恢复后的变量并重新计算可见性，无需新增存档字段。

### 地图 Actor 身份

地图 JSON 的放置 `tag` 会成为 Actor 的地图持久化 tag。`GameMap:getActorByTag` 与 `GameInstance` 持久化记录仅以 `Actor:getMapTag()` 识别 Actor；`Actor.tag` 与其独立。没有地图持久化 tag 的 Actor 不会被记录，相关地图路径统一规范化。

需要跨地图重建保留的运行时生成 Actor 使用自身新生成的地图持久化 tag 写入 added-Actor 记录；该 Actor 后续销毁时，其 destroyed 记录会屏蔽这条新增记录。Reborn 敌人复用这组既有记录，而不复用原放置对象的 tag。

大地图的运行时 tag 在摆放（placement）内使用 `<子地图文件 stem>.runtime_default_<N>`，在空洞中使用 `<大地图目录>.runtime_default_<N>`。所有 tag 在大地图生命周期内都会保留，冲突会失败；编辑器 tag 在整个大地图范围内唯一，地图重命名时保持稳定。

### 组合式大地图持久化

即使从子地图进入，当前 `map` 也保存清单路径。Player、added、moved 与 destroyed 记录使用该身份、大地图坐标和全局 tag；added/moved 记录冲突时拒绝加载。

added Actor 优先恢复到 `actorPositions[tag]`，否则使用原始位置；destroyed tag 会跳过。placement Actor 随子地图 payload 重建，不产生远处子地图 I/O；空洞 Actor 可立即恢复。

`worldMovedActors` 管理离开定义子地图的 authored root，保存身份、owner、图层 override 和大地图位置，并只在该 owner 重建。返回或销毁会移除 moved 记录。

销毁 tag 会移除其 moved 记录，并在不加载缺失子地图的情况下屏蔽 authored、added、驻留和进行中实例。被屏蔽 tag 保持保留；非法记录和冲突会失败。

地形记录使用子地图路径和局部坐标，在构造子地图时应用，实时修改只更新受影响图层。空洞不能拥有地形修改。

大地图存档必须包含 `worldMovedActors`。moved 快照只保存重建身份、类变量 override、图层和位置；任意实例字段、Lua 私有状态或计时进度需单独持久化，或通过 `onWorldWake` 补算时间。

## 存档

Sample 的存档格式版本为 `1`，仅支持当前的数据结构和版本。`SaveCodec` 会拒绝不兼容的存档，不自动迁移。开发期间修改数据结构可以不变更版本号。

`telepoints` 按规范化地图路径保存有序的 `{ position = {x, y}, tag = "原始 tag" }` 记录。运行时位置使用 `sf.Vector2u`，tag 保留未本地化的字符串。`GameInstance:recordTelepoint(mapPath, position, tag)` 为每组地图与坐标保留第一次记录；`getTelepoints(mapPath)` 返回这些记录。世界地图记录使用清单身份和世界坐标。

`GameInstance:getCurrentMapPath()` 返回当前地图或 nil；`getVisitedMapPaths()` 返回已记录传送点的地图路径并排序；`getTelepointsForMap(key)` 忽略扩展名匹配。两个集合查询均返回副本。`restoreFromData(data)` 将验证后的存档恢复到实例。

`SAVE_AS_LDC` 为 `false`（默认）时使用普通 `.json` 存档，为 `true` 时使用加密 `.ldc` 存档。**加密存档内容**设置 C++ Source 包的原生默认值。包括 Standalone 在内的项目均可在 `Scripts/Entry.lua` 顶部、所有 `require` 之前，通过全局赋值 `SAVE_AS_LDC = true` 或 `false` 覆盖。`Source.Save` 首次加载时确定格式，之后赋值不再生效。

`GetSavePath(slot)` 为从 1 开始的 slot 编号选择扩展名。应使用稳定的编号，在序列化前校验数据，显式处理文件缺失，避免硬编码存档目录。

存档加密与项目 JSON 加密相互独立，但 Pack Options 将两者归入**加密游戏数据**。

## 数据边界上的原生容器

将 Standard 的 `list`、`tuple` 或 `dict` 保存为 JSON 前，先转换为 Lua 表：

```lua
local cjson = require("cjson")
local encoded = cjson.encode(payload:toTable())
```

JSON decode 的结果是普通 Lua table。tuple-key string、nil 槽位上的 `cjson.null` 以及 record array 的重建，见 [Ludork Lua进阶](<../../01.快速入门/04.Ludork Lua进阶.md>)。不得持久化内部 tuple hash。

## 限制

切换存档格式不会重命名或迁移已有存档槽。应在发行前确定格式，或自行提供迁移流程。存档升级、原子写入、备份、云同步以及元组键的记录格式均由项目负责。

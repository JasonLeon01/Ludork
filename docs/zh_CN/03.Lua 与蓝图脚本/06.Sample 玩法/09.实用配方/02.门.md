# 门

## 目标

创建通过背包钥匙或命名游戏状态条件开启的门。

## 前置条件

- 有效的 `Source.DoorBase.DoorBase` Blueprint 父类与门 Sprite Sheet。
- 与所选工作流匹配的 Item 或游戏变量标识符。

## 步骤

Door Blueprint 组合碰撞行为、开门动画/状态，以及可选钥匙或条件。

开门完成后，`DoorBase` 会把非空地图放置 tag 记录为已销毁。地图重建时会跳过该放置实例，因此门在跨地图及存档读写后仍保持消失。

### 钥匙门

1. 从 `Source.DoorBase.DoorBase` 派生通用门，配置纹理、矩形、碰撞和开门默认值。
2. 再派生颜色专用门。Sample 的 `BP_Door_Y.json` 继承 `BP_Door_General`，保存 `needKeyID = "KEY_Y"`。
3. 在 `onCollision` 中排除已经开门的状态，并要求 `MeetPlayer`。
4. 读取 `needKeyID`，调用 `GetItemCount`，并与一比较。
5. 成功时通过 `SUPER` 调用继承碰撞流程，再移除一把钥匙；失败分支可保持未连接或连接明确反馈。

钥匙 ID 必须同时匹配 Item 成员及其拾取 Blueprint，例如 `KEY_Y` 与 `BP_Item_Key_Y.json`。

### 条件门

`BP_Door_Condition.json` 保存 `openConditionName` 与 `openConditionVal`，实际行为由 `Mixins/Doors/ConditionDoor.lua` 承担。创建时，Mixin 把门标记为 pending；若配置变量不存在，则把它初始化为零。每次 tick 先执行普通继承行为，再在当前变量大于或等于配置阈值时只开门一次。销毁时会取消门的 event-bus handler 注册。

`openConditionName` 使用仅限数值类型的 `InstVar` 选择器，因此只列 Game Variable Manager 中的 `int` 与 `float` 声明。`openConditionVal` 使用 `InstVarValue`，并采用已选声明对应的通用数值编辑器。Sample 生成声明中包含供此流程使用的 `MTExample = 0`。

应测试无钥匙、一把钥匙、开门中重复碰撞、钥匙缺失/重命名、数值选择器过滤、条件低于/等于/高于阈值、存档变量恢复和地图重载。开启多扇已放置的门，离开并重新进入地图，再执行存档读档；确认每扇门都能独立保持消失。重命名 ID 前先检查引用。

## 限制

Door 逻辑不负责场景移动。跨地图应使用 Teleporter；重命名钥匙或条件 ID 时必须更新全部存储引用。

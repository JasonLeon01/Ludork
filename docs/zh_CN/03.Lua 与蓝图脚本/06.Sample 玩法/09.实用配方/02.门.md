# 门

## 目标

创建通过背包钥匙或命名游戏状态条件开启的门。

## 前置条件

- 有效的 `Source.DoorBase.DoorBase` Blueprint 父类与门 Sprite Sheet。
- 与所选工作流匹配的 Item 或游戏变量标识符。

## 步骤

Door Blueprint 组合碰撞行为、开门动画/状态，以及可选钥匙或条件。跨地图移动属于 Teleporter，不是 Door 字段。

### 钥匙门

1. 从 `Source.DoorBase.DoorBase` 派生通用门，配置纹理、矩形、碰撞和开门默认值。
2. 再派生颜色专用门。Sample 的 `BP_Door_Y.json` 继承 `BP_Door_General`，保存 `needKeyID = "KEY_Y"`。
3. 在 `onCollision` 中排除已经开门的状态，并要求 `MeetPlayer`。
4. 读取 `needKeyID`，调用 `GetItemCount`，并与一比较。
5. 成功时通过 `SUPER` 调用继承碰撞流程，再移除一把钥匙；失败分支可保持未连接或连接明确反馈。

钥匙 ID 必须同时匹配 Item 成员及其拾取 Blueprint，例如 `KEY_Y` 与 `BP_Item_Key_Y.json`。

### 条件门

`BP_Door_Condition.json` 保存 `openConditionName` 与 `openConditionVal`。它的 graph 会初始化变量、通过 `SUPER` 执行普通 tick、比较游戏变量、确保只开门一次并调用 `openDoor`；销毁时还会取消 event-bus 注册。

应测试无钥匙、一把钥匙、开门中重复碰撞、钥匙缺失/重命名、条件低于/等于/高于阈值、存档变量恢复和地图重载。重命名 ID 前先检查引用。

## 预期结果

钥匙或条件成功时门只开启一次；适用时只消耗已配置钥匙，并保持生命周期清理。

## 验证

在编辑器与打包版本中执行上列全部情况，包括地图重载与游戏变量恢复。

## 限制

Door 逻辑不负责场景移动。跨地图应使用 Teleporter；重命名钥匙或条件 ID 时必须更新全部存储引用。

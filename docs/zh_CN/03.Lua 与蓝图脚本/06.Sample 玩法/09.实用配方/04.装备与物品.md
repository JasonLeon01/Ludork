# 装备与物品

## 目标

创建具有稳定背包 ID、有效槽位与聚焦成员 graph 行为的物品和装备记录。

## 前置条件

- 包含所需背包与槽位标识符的 Item、Equip 与 Class General Data。
- 从 `Source.Item` 或 `Source.Equip` 派生的 Blueprint 父类。

## 步骤

Item 与 Equip schema 把可复用定义和背包实例分离。

- 使用 Item 的 `usable` 与 `cost` 控制菜单可用性和是否消耗。
- 背包使用放在 `onUse`，敌人掉落行为放在 `onDrop`。Runtime 将两者作为 `GeneralDataGraphAbility` 激活；前者 target 是 Player，后者是生成的 Item Actor。
- Equip 的 `slot` 必须匹配所选 Class 的 slot 字典。
- 属性变化放在 `attrPlus`；`onEquip` 与 `onUnequip` graph 只处理特殊行为。
- 图标放在 `Assets/Icons`，并使用资源选择器。

## Sample 装备

`BP_Equip_Sword_A.json` 继承 `Source.Equip` 并设置 `ID = "Sword_A"`，该 ID 会解析 Equip 成员。

`attrPlus` 会转换为以 slot 为 source 的 Infinite Gameplay Effect。装备时先应用它再执行 `onEquip`；卸下时先移除它再执行 `onUnequip`，因此替换不会残留旧 modifier。

## Sample 物品

`BP_Item_Key_Y.json` 继承 `Source.Item` 并设置 `ID = "KEY_Y"`，同时匹配 Item 成员和黄门的 `needKeyID`。

持有 Item 时授予其 `onUse` ability，移除最后一件时撤销。`Player:activateItem` 以该 Player 为 target，graph 决定何时消耗 Item；`cost` 是菜单策略，不是 Ability System cost。

应测试购买、出售、掉落、使用、装备替换与存档恢复。读取时重建保存的 Item ability 与装备 Effect，不重放成员 graph。还要测试图标缺失、未知 ID、非法 slot 与成员重命名。

## 限制

重命名成员不会自动修复已存储引用。Class slot 不匹配和未知记录 ID 仍是明确数据错误。

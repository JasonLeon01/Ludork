# 装备与物品

## 目标

创建具有稳定背包 ID、有效槽位与聚焦成员 graph 行为的物品和装备记录。

## 前置条件

- 包含所需背包与槽位标识符的 Item、Equip 与 Class General Data。
- 从 `Source.Item` 或 `Source.Equip` 派生的 Blueprint 父类。

## 步骤

Item 与 Equip schema 把可复用定义和背包实例分离。

- 使用 Item 的 `usable` 与 `cost` 控制菜单可用性和是否消耗。
- 物品特有的使用/获得流程放在 `onUse` 与 `onGet`。
- Equip 的 `slot` 必须匹配所选 Class 的 slot 字典。
- 普通属性变化放在 `attrPlus`；`onEquip` 与 `onUnequip` 只处理特殊效果。
- 图标放在 `Assets/Icons`，并使用资源选择器。

## Sample 装备

`BP_Equip_Sword_A.json` 继承 `Source.Equip` 并设置 `ID = "Sword_A"`。该 ID 解析 Equip 成员，其 `slot` 必须是当前 Class 成员 `slot` 字典中存在的 key。普通加成放在 `attrPlus`；只有装备需要超出普通加成的行为时，才实现 `onEquip`/`onUnequip`。

## Sample 物品

`BP_Item_Key_Y.json` 继承 `Source.Item` 并设置 `ID = "KEY_Y"`，同时匹配 Item 成员和黄门的 `needKeyID`。主动物品应明确设置 `usable` 与 `cost`，并实现 `onUse`；运行时授予物品时的行为放在 `onGet`。

应测试购买、出售、获得、使用、获得回调、装备、替换、卸下、门消耗，以及从存档恢复背包/装备。还要测试图标缺失、未知 ID、非法 slot 和成员重命名，使引用错误能够被发现。

## 预期结果

背包实例解析稳定记录，装备只应用有效槽位与属性变化，成员 graph 只执行记录特有行为。

## 验证

执行上列全部背包、装备与故障情况，包括存档恢复和打包资产查找。

## 限制

重命名成员不会自动修复已存储引用。Class slot 不匹配和未知记录 ID 仍是明确数据错误。

# 敌人

## 目标

创建物理 Blueprint 与 General Data 战斗定义可独立复用的敌人。

## 前置条件

- 有效的 Enemy General Data 文件与 Actor 兼容敌人父类。
- 新记录所引用的已有 Item Blueprint 路径、特殊效果标识符与动画标识符。

## 步骤

在 General Data 中创建敌人定义，在 Blueprint 中创建敌人实体。

1. 添加 Enemy 成员，设置战斗数值、奖励、掉落、特殊效果和 animation key。
2. 创建或派生 Enemy Blueprint，并指向该数据成员。
3. 配置移动、碰撞和表现默认值。
4. 自定义击败编排放在 Enemy Actor `onDefeat` hook 或子类授予的 Gameplay Ability 中。Enemy General Data 不声明 event；固定结算会等待 `onDefeat`。
5. 放置 Blueprint，测试战斗、奖励、掉落、存读档和地图重置。

共享战斗算法放在 Gameplay Ability、Gameplay Effect 或 Lua 模块中。

## Sample 操作

`BP_Enemy_Slime.json` 继承 `Source.Enemy` 并设置 `ID = "Slime"`；该 ID 会解析 `Data/General/Enemy.json` 中的 `Slime` 成员。Blueprint 保存纹理、源矩形、material speed 等物理/表现默认值；General Data 成员保存 `MAXHP`、`ATK`、`DEF`、`EXP`、`GOLD`、`drops`、`special` 与 `ANIMATION_KEY`。

内置击败粉碎特效由项目级的 `Enemy.DefeatShatterEffectEnabled` 选择；它是全局类设置而不是 Blueprint 字段，默认值为 `true`。开启时，敌人会立即按玩法逻辑记录并销毁，同时由不参与碰撞和遮光的视觉快照以世界空间逻辑像素碎片从中心径向向外消散，持续约 0.65 秒。把该类设置设为 `false`，或在不支持 Shader 的环境运行时，会保留立即消失的表现。

每个 `drops` key 都是 `Source.Item` Blueprint 路径，而不是 General Data ID；`sf.Vector2i` value 是格子 offset。掉落会在敌人图层生成、持久化，并激活 `onDrop` `GeneralDataGraphAbility`。持久化 tag 重复时跳过该掉落。

`GhostSoldier` 演示了 `special.Reborn = "Data.Blueprints.Enemies.BP_Enemy_Skeleton_01"`。击败结算期间，原敌人先被记录并销毁，目标 Blueprint 再以新的地图持久化 tag 在同一格子和图层生成，并记录为 added Actor。不得复用被击败 Actor 的 tag，否则地图重建时 destroyed 记录会同时删除替代 Actor。

创建变体时，复制现有 Enemy Blueprint，创建或选择匹配的 Enemy 成员，更新 Blueprint `ID`，再单独调整表现。

## 限制

未知 ID 与缺失引用记录都是错误。Runtime 不会合成替代战斗定义。

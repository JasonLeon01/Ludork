# 默认模板概览

Sample 既是可运行参考，也是可复用模板的来源。它展示推荐项目结构，而不是最小空白程序。它适合用来学习所有权与数据流；复制某个模式前，先弄清它的依赖。

Sample 提供可参考的源码，但其中的玩法行为不等于引擎保证。在其他项目中使用前，应先通过元数据、LuaLS 声明和 API 参考确认公开行为。

## 入口与模块

`Scripts/Entry.lua` 负责初始化游戏并进入原生主循环，按以下顺序加载 Core 模块：

```lua
local Engine = require("Engine")
local GlobalCore = require("GlobalCore")
local GlobalFunctions = require("GlobalFunctions")

local Components = GlobalFunctions.Components
local UI = GlobalFunctions.UI
local NodeGraph = GlobalFunctions.NodeGraph
local Manager = GlobalFunctions.Manager
```

启动时需要显式调用以下函数；仅加载模块不会初始化服务：

| 调用 | 职责 |
|---|---|
| `Source.Locale.Core.Init()` | 在读取配置、选择语言前加载语言字典。 |
| `Source.Configs.Main.LoadOrCreate()` | 读取 `Main.ini`；文件不存在时，使用默认设置创建。 |
| `Source.Data.InitializeRuntime()` | 初始化数据服务，并在首个场景创建前注册数据与蓝图服务。 |
| `Source.System.InstallRuntimeProviders()` | 在首个场景创建前注册配置服务。 |
| `Source.System.Init()` | 应用 System 和 Audio 配置，并在进入原生主循环前准备显示资源。 |

入口还会在创建 `SceneInit` 前初始化延迟执行图和原生 System。每个会话只注册一次服务；[Lua 热更新](<../01.Lua 运行时与模块.md#lua-热更新>)不会重新执行启动流程。配置与存档位置见[运行时数据、配置与存档](<06.运行时数据、配置与存档.md>)。

## 玩法布局

- `Scripts/Source` 保存可复用 Lua 类、场景、窗口、组件和节点函数。
- `Scripts/Source/UI` 保存由 `Data/UI/Assets` 生成的 View；手写基础模块位于 `Source.UIBase`，业务窗口位于 `Source.Windows`。详见 [UI 编写工作流](<../05.声明式 UI/01.编写工作流.md>)。
- `Scripts/Mixins` 保存可直接挂载的 Lua 行为。
- `Data/Blueprints` 保存游戏专用 Actor 类。
- `Data/General` 提供物品、敌人、装备、职业、玩家、状态和特殊效果。
- `Data/Maps` 与 `Data/Tilesets` 提供可玩世界。
- `Engine/` 包含原生运行时、模块与依赖。

其他公开 Lua 模块将私有实现服务归入同名子目录；这些服务不 require 或扩展宿主。具有独立 `.d.lua` 契约的模块保持独立。

原生源码归属与依赖关系见 [构建与模块布局](<../../04.C++ 原生开发/01.构建与模块布局.md>)。

`Source.Data.Blueprints` 将 Blueprint、公共函数及 General Data 图定义编译为原生 `Engine.Graph` 模板，再通过 `instantiate` 创建实例。

## 模板变体

`Cpp` 保留原生源码并按项目构建；`Cpp-ffmpeg` 增加视频支持；Standalone 变体包含已构建好的运行时，供打包使用。iOS、HarmonyOS 与 Android 发行包只从 C++ Source 变体构建，并在启用视频时使用 C++ Source + FFmpeg 变体。修改 Sample 不会自动更新已经创建的项目，应重新生成模板或明确地把所需改动应用到该项目。

运行时 Lua、`Scripts/stub` 声明与 `_meta.lua` 文件分层规则见 [Lua 运行时与模块](../01.Lua 运行时与模块.md)。

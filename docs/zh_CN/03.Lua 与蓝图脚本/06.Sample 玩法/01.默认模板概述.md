# 默认模板概览

Sample 既是可运行参考，也是可复用模板的来源。它展示推荐项目结构，而不是最小空白程序。

## 入口与模块

`Scripts/Entry.lua` 加载 Core 模块，通过 `Source.Config.Main` 读取或首次创建 `Main.ini`，初始化语言表和 latent 图支持、创建首个场景并进入 C++ 主循环。模板还在入口中声明全局 `SAVE_AS_LDC = false`：保持默认值时标准存档使用 `.json`，改为 `true` 时使用包含 JSON 序列化数据的加密 `.ldc`。这个运行时存档开关独立于打包选项 **Encrypt Data**。Core 模块必须按以下顺序加载：

```lua
local Engine = require("Engine")
local GlobalCore = require("GlobalCore")
local GlobalFunctions = require("GlobalFunctions")

local Components = GlobalFunctions.Components
local UI = GlobalFunctions.UI
local NodeGraph = GlobalFunctions.NodeGraph
local Manager = GlobalFunctions.Manager
```

## 玩法布局

- `Scripts/Source` 保存可复用 Lua 类、场景、窗口、组件和节点函数。
- `Scripts/Mixins` 保存可直接挂载的 Lua 行为。
- `Data/Blueprints` 保存游戏专用 Actor 类。
- `Data/General` 提供物品、敌人、装备、职业、玩家、状态和特殊效果。
- `Data/Maps` 与 `Data/Tilesets` 提供可玩世界。
- `Core` 提供原生模块和生成绑定。

## 模板变体

`Cpp` 保留原生源码并按项目构建；`Cpp-ffmpeg` 增加视频支持；Standalone 变体包含已构建 runtime，用于打包。iOS、HarmonyOS 与 Android 发行包只从 C++ Source 变体构建，并在启用视频时使用 C++ Source + FFmpeg 变体。修改 Sample 不会自动更新已经创建的项目，应重新生成模板或明确地把所需改动应用到该项目。

运行时 Lua、`Scripts/stub` 声明与 `_meta.lua` 文件分层规则见 [Lua 运行时与模块](../01.Lua 运行时与模块.md)。

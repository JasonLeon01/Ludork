# 声明式 UI 校验与打包

## 目标

校验基于路径的 UI 声明，对比原生 Preview 与 Runtime，并在不包含编辑器 preview 数据的情况下打包资产。

## 外部修改后校验

UI JSON 在编辑器外发生变更时运行：

```text
ScriptTools ui-assets validate <project-root>
ScriptTools ui-adapter-check <repo-root>
```

两项检查都只读，不生成索引文件。原生构建会执行相同的资产与 adapter 检查，并在 schema、路径或 descriptor 无效时停止。

## 校验层

保存、原生预览、Run 与 Pack 执行同一组核心契约：

- 精确资产字段集合与规范相对资产 key；
- 项目唯一节点 UUID，以及资产内唯一节点名；
- 已知控件 ID、子项策略、属性类型与上级 Slot 类型；
- 大小写精确的资源 key 与匹配 Text Config/Curve 种类；
- exposed 嵌套目标、无缺失项目资产且无嵌套循环；
- 匹配的系统 adapter fingerprint。

校验会拒绝资产 schema 之外的字段、资产 UUID 字段、UUID 项目引用与别名路径。

## 原生预览与打包

Preview 需要匹配的协议和系统 adapter fingerprint。Render 请求发送根资产 key 与以逻辑 key 索引的 dependency snapshot，不发送或读取 Catalog。

Packaging 在 staging 副本中校验资产，递归删除每个 `editor` 对象，按配置编译/加密数据，并保持源码资产不变。开发态 JSON 与发布态 `.ldc` 使用同一个不带扩展名的逻辑 key。

## 发布验证

1. 在源码无变更的情况下运行两项只读检查。
2. 在原生 Preview 中打开每个顶层资产。
3. 运行每个所属 Scene/窗口，对比布局、文本刷新与输入。
4. 打包，然后在每个受支持逻辑尺寸下运行打包结果。
5. 确认包内没有生成 UI 索引，也不依赖开发机路径。

Fallback preview 与构建成功都不能证明 live runtime 一致；应分别报告 Preview、Run 与 Pack 验收。

# 声明式 UI 校验与打包

## 目标

校验基于路径的 UI 声明，对比原生 Preview 与运行时，并在不包含编辑器 preview 数据的情况下打包资产。

## 外部修改后校验

UI JSON 在编辑器外发生变更时运行：

```text
ScriptTools ui-assets validate <project-root>
ScriptTools ui-adapter-check <project-root>
```

`ui-assets validate` 使用项目 Registry 校验资产。`ui-adapter-check` 和 `ui-preview validate` 为只读检查；Adapter 校验比较项目 JSON 与配套 Host 的编译描述。

源码工程尚无预览产物时，以及编译前保存时，只进行不依赖控件描述的结构校验，原生校验仍未就绪。命令行可用 `ScriptTools ui-assets validate <project-root> --structure-only` 执行。构建先生成预览产物，再执行完整 UI 校验；资产无效会使构建失败，但已生成的预览仍可用于编辑。已有 Registry 的普通保存执行完整校验。

Standalone 可通过 `ScriptTools ui-preview ensure <project-root>`、常规 UI 校验或 `ui-preview registry`，从随附 Host 恢复缺失的预览 JSON。元数据损坏、不匹配或二进制缺失仍会报错。源码工程的预览产物不可用时必须重编；未完成或失败的原生构建不能自动恢复。

## 校验层

保存、原生预览、Run 与 Pack 都执行[资产 Schema](<04.资产 Schema 与 Control Registry.md>)，并拒绝未知字段、资产内重复节点名和别名路径。

## 原生预览与打包

Preview 需要匹配的协议、系统 Adapter fingerprint 和完整 Registry 摘要。

Packaging 校验 staging 副本、移除 `editor` 数据，并按配置编译、加密或归档，不改动源工程的游戏资产。JSON、`.ldc` 与 packed Data 保持相同的无扩展名 UI key；packed Controller 保持原逻辑模块路径。

staging 校验通过 `--registry <source-project>/Temp/UiPreview.registry.json` 使用源项目 Registry。Registry 属于开发产物，不进入玩家包。

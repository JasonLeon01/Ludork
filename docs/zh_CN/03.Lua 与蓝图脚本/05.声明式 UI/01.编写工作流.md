# 声明式 UI 编写工作流

## 目标

创建逻辑 key 匹配的 View/Controller 对，保持稳定资产所有权，并由所在 Scene 或窗口拥有其生命周期。

## 步骤

### 文件布局

资产根目录固定为 `Data/UI/Assets`：

```text
Data/UI/Assets/
    ├── Inventory.json
    └── Parts/
        ├── Inventory/ItemRow.json
        └── Shared/KeyPrompt.json
```

完整屏幕、窗口、HUD 与 Overlay 直接位于 `Assets`。某个大型 UI 所有的部件放在 `Parts/<Owner>`，真正共享的部件放在 `Parts/Shared`。不得新建仅按控件形态组织的目录。

Lua owner 层级与资产层级一致：

```text
Scripts/Source/UI/
├── Inventory.lua
└── Parts/
    ├── Inventory/ItemRow.lua
    └── Shared/KeyPrompt.lua
```

`Ui.lua`、`UiController.lua`、`UiControlFactory.lua` 与真正跨 UI 的 helper 可保留在共享位置。

### 创建 View 与 Controller

1. 在 UI 资产编辑器中创建 JSON 资产。
2. 为每个运行时会访问的控件选择稳定、有意义的节点名。
3. 决定资产是否已完整到足以暴露到 Project Palette。
4. 保存并解决所有校验问题。
5. 在 `Scripts/Source/UI` 下创建匹配 Lua 文件。
6. 返回 `Ui.define(logicalKey, definition)`；key 是资产相对于 `Data/UI/Assets` 的路径，使用正斜杠且不含扩展名。
7. 在 `bind` 中完成一次性回调/控件获取，在 `refresh` 中完成可重复的 Model-to-View 更新。
8. 从所属 Scene 或窗口创建、准备并挂载 Controller。

`Inventory.json` 的逻辑 key 为 `Inventory`；`Parts/Inventory/ItemRow.json` 的 key 为 `Parts/Inventory/ItemRow`。Key 不是文件系统路径，不得包含空段、`.` 或 `..`。

## 验证

- 保存资产并运行 `ScriptTools ui-assets validate <project-root>`。
- 从真实 owner 构造、prepare、mount 并 dispose Controller。
- 通过编辑器重命名或移动后，同步更新 `Ui.define` key 与 `require` 路径。

## 限制

有意义的复合件、具有独立生命周期的 UI 或可复用嵌套部件应分别建立资产。与上级 View 固有关联的系统控件直接放在上级资产内。动态生成的内部 Row 使用 `palette.exposed = false`。永久且与语言无关的符号可使用字面 `text`；本地化或 Model 派生文本保持为空，由 Controller 赋值。

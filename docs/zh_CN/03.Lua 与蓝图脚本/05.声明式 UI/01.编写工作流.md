# 声明式 UI 编写工作流

## 目标

Ludork 声明式 UI 从 JSON 资产生成 Lua View，业务行为保留在手写 Controller 中。可视化编辑操作见 [UI 资产编辑器](<../../02.编辑器用户指南/07.UI 资产编辑器.md>)。

| 层 | 拥有内容 |
|---|---|
| JSON View | Hierarchy、资产内节点名、静态控件属性、Slot、动画 Timeline 与纯设计预览数据 |
| 自动生成的 Lua View | 完整的类型化控件与子 View 树、资产身份、挂载与所拥有对象的生命周期 |
| Lua Controller | Model 访问、回调、本地化/格式化文本、状态刷新与动态组合 |
| 窗口 UI | 原生窗口与输入状态，以及它持有的生成 View 和私有 Controller |
| 原生控件 | 渲染、测量、命中测试、焦点与原子交互状态 |
| UIManager | 挂载和移除已准备根控件 |

不要在 UI 资产中存储 Controller 函数、表达式、事件处理器或 `LOC(...)` 调用。

## 步骤

### 文件布局

资产根目录固定为 `Data/UI/Assets`：

```text
Data/UI/Assets/
    ├── Inventory.json
    └── Parts/
        ├── Inventory/ItemRow.json
        └── Shared/KeyPrompt.json
```

完整屏幕、窗口、HUD 与 Overlay 直接位于 `Assets`。某个大型 UI 所有的部件放在 `Parts/<Owner>`，真正共享的部件放在 `Parts/Shared`。不得新建仅按控件形态组织的目录。

自动生成的 Lua View 与资产层级一致。`Scripts/Source/UI` 与 `Scripts/stub/Source/UI` 中的文件全部由生成器维护：

```text
Scripts/Source/UI/
├── Inventory.lua
└── Parts/
    ├── Inventory/ItemRow.lua
    └── Shared/KeyPrompt.lua
```

手写基础模块放在 `Scripts/Source/UIBase`。窗口模块如 `Scripts/Source/Windows/WindowInventory.lua` 在文件内定义私有 Controller，并通过 `Ui.DefineWindow` 返回 UI 类。独立行与 Scene Controller 使用各自模块，例如 `Source.Windows.WindowInventory.ItemRow.Controller` 和 `Source.Scenes.SceneTitle.Controller`。

对应窗口 stub 只声明私有 Controller，使用不带模块名的 `---@meta`。公开窗口声明生成到 `Scripts/stub/Source/UIWindows`，不得手工修改。声明格式见 [Controller 示例](<03.Controller 示例.md#业务成员只声明一次>)。

### 创建 UI 并添加业务行为

1. 在 UI 资产编辑器中创建 JSON 资产，为运行时访问的节点设置稳定名称。
2. 需要在 Project Palette 中使用时，启用 **Exposed**。
3. 保存并解决校验问题，在窗口模块中 require 生成 View。
4. 定义局部 Controller，并返回 `Ui.DefineWindow(ViewClass, Controller, nativeBase?)`。在 `init` 中初始化业务，在 `bind` 中绑定回调，通过 `watch` 或 `refresh` 更新状态。
5. 用 `windowOptions` 配置初始窗口行为，用 `createChild` 绑定已有子窗格，用集合管理数量随模型变化的行。详见[运行时契约](<02.运行时契约.md>)与 [Controller 示例](<03.Controller 示例.md>)。
6. 维护私有 Controller 声明并重新生成。由拥有者创建、挂载窗口，不再使用时释放。

### 资产变更后重新生成

移动资产或重命名节点后，更新手写 `require` 路径和节点引用，再运行 `ScriptTools ui-assets generate <project-root>`。自动生成与只读检查见[校验与打包](<05.校验与打包.md>)。

### 可滚动内容

可能溢出的内容放入 `Engine.ScrollBox`，不得由 Controller 移动 Canvas。`size` 是 viewport，空 `windowSkin` 使用系统皮肤。ScrollBox 统一负责裁剪、偏移和滚轮/触摸输入，且只在布局内容超出时滚动对应轴。提示图集细节见 [布局与图像控件](<../07.API 参考/04.Core 模块/02.Engine/10.布局与图像控件.md>)。

## 限制

每个可见界面使用一个顶层资产。多窗格界面从 `Parts/<顶层名称>/` 嵌套 owner 专用资产；嵌套 part 使用 `palette.exposed = true`，纯运行时 helper 可不暴露。

用有代表性的 `#TAB`/`#ITEM` 子项与 Sample 视觉资源提供预览，但不得把它们当作游戏数据的回退（fallback）。显示前由业务代码本地化 Tab 标签并填充动态集合；固定控件和行复用 JSON 创建的实例。只有永久且与语言无关的符号使用字面 `text`。

逐帧角色或敌人使用 `Engine.CharacterView`。资产只提供预览值；运行时通过 `setCharacter` 传入真实纹理、Rect、缩放、动画、Shader 与 Hue。Lua 不再裁帧或合成 Actor 视觉。

# UI 资产 Schema 与 Control Registry

## 范围

本参考定义 UI 资产规范 key、资产结构、节点、Slot、资源 key 与编辑器实时控件 Registry。

## 资产 key 与结构

UI 资产使用 `type = "uiAsset"` 并遵循下述字段契约，不保存 schema 版本字段。资产唯一身份是相对 `Data/UI/Assets`、大小写精确、使用正斜杠且不含扩展名的路径。`Title.json` 的 key 为 `Title`；`Parts/Shared/WindowBase.json` 的 key 为 `Parts/Shared/WindowBase`。

Key 不得是绝对路径，不得包含反斜杠、空段、`.`、`..`、扩展名或 `Assets/`、`UI/Assets/` 等重复前缀。资产对象包含 `designSize`、`palette` 与一个 `root` 节点，不包含资产 UUID。

每个节点包含：

| 字段 | 契约 |
|---|---|
| `id` | 编辑器管理的项目唯一 UUID。 |
| `name` | Controller 查找名，在当前资产内唯一。 |
| `controlId` | 系统控件的规范模块根原生类路径，或 `Project:<相对路径>`。 |
| `properties` | 控件 schema 拥有的值。 |
| `slot` | 上级拥有的布局；根节点没有该字段。 |
| `editor` | `previewText` 等纯设计数据。 |
| `children` | 有序子节点；当 z-order 相同时，顺序是稳定 tie-breaker。 |

嵌套项目资产是黑盒。节点只声明项目 `controlId`、自身节点身份/名称与上级 Slot，不存储内部覆盖或子节点。目标资产必须 exposed，直接或间接嵌套循环无效。

系统 ID 使用绑定类唯一的 runtime 路径，例如 `Engine.Canvas` 或
`Engine.FunctionalPlainText`。不匹配其绑定类唯一 runtime 路径的系统 ID 属于未知控件。

## Slot 与资源 key

Canvas 上级提供锚点、偏移、对齐、自动尺寸与 z-order。List 上级提供 List 排布，不接受 Canvas Slot 字段。上级 adapter 声明决定子项策略与 Slot 类型。

- 文件资源使用大小写精确、以 `Assets/` 开头、带扩展名的项目相对路径，并使用正斜杠。
- `textConfig` 相对于 `Data/TextConfigs`，不含目录前缀或扩展名。
- `opacityCurve` 相对于 `Data/Curves`，不含目录前缀或扩展名，并解析为标量曲线。
- 绝对路径、反斜杠、越界与别名前缀均无效。

## 实时控件 Registry

编辑器从原生系统 descriptor 与项目 UI 资产实时构建内存 Registry。只有 `palette.exposed = true` 的资产会作为项目控件出现。Runtime 不生成、保存或读取任何 Registry/Catalog 文件。

Adapter fingerprint 只由系统 descriptor 推导，编辑器与 PreviewHost 用它拒绝不匹配的原生 adapter。Runtime 与 Preview 都按规范相对 key 直接解析项目资产。

## 验证

- 校验节点 UUID 与节点名唯一性。
- 让每个子 Slot 匹配父 descriptor 与 child policy。
- 按精确大小写解析项目引用与资源 key。
- 原生构建前运行 `ScriptTools ui-assets validate <project-root>` 与 `ScriptTools ui-adapter-check <repo-root>`。

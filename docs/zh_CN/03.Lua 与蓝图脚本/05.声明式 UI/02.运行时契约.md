# 声明式 UI 运行时契约

生成的 View 创建并拥有完整的 UI 对象树；需要业务行为时，再为它绑定 Controller。

## 创建 View

```lua
local InventoryView = require("Source.UI.Inventory")

local inventory = InventoryView.new()
inventory:mount(uiManager, logicalSize)
```

`View.new()` 实例化 JSON 资产，递归为每个嵌套资产创建对应的生成 View，并填充全部类型化引用，无需任何 Controller。创建 View 不会把它挂到屏幕上；需要显式调用 `mount` 或 `attachTo`。

每个 View 提供 `assetKey`、`designSize: sf.Vector2f`、原生 `instance: Engine.AssetInstance`、精确类型的 `root`、保存原生系统控件的 `controls`，以及保存精确类型子 View 的 `assets`。例如通过 `inventory.assets.ItemRow.controls.Label` 访问子项控件。名称保留原始资产内 key；不是 Lua 标识符的名称使用方括号访问。

每个嵌套节点都有独立的 View 和原生实例，同一资产被多个节点引用时也如此。为子节点绑定 Controller 时，传入已有的子 View。

## 绑定业务行为

窗口模块在文件内定义私有 Controller，并返回 `Ui.DefineWindow(viewClass, Controller, nativeBase?)`。`nativeBase` 默认为 `Engine.Canvas`。返回的 UI 继承该原生基类；Controller 是独立的 `UiController` 对象，生成 View 也独立于两者。`Window.new(...businessArgs):mount(uiManager)` 创建并注册完整窗口。空 Controller 无需 `init`，即可按模板尺寸显示原始内容。

构造过程先创建原生宿主和生成 View，完成与 Controller 的绑定并挂接 View，再调用可选的业务 `init(...)`。此时 `self.ui` 是强类型生成树，`self.view` 是其原生 `Engine.AssetInstance`，`self.root` 是原生根，`self.host` 是 UI。UI 通过 `window.ui` 提供同一个 View，私有地持有 Controller。`init` 后，框架调用 `prepare` 完成绑定、刷新和布局，再调用可选的 `ready`，最后应用配置的初始隐藏状态。必须等待首次准备好布局的业务操作才放入 `ready`。

工厂向窗口 API 暴露 Controller 实例方法（`camelCase`）、静态辅助函数（`PascalCase`）、`SCREAMING_SNAKE_CASE` 常量与 `Publish`；构造钩子保持私有。声明文件布局见[编写工作流](<01.编写工作流.md#文件布局>)。

`Controller.windowOptions` 配置可选宿主行为。`position`、`centered` 与 `screen` 控制根位置或全屏范围；`hidden`、`returnButton` 与 `focusable` 控制初始交互。窗口基类通过 `frame` 与 `content` 指定节点名，默认分别为 `WindowFrame` 和 `Content`；选择窗口还可指定 `list`、`scroll` 及 `itemWidth`、`itemHeight`、`hitWidth`、`hitHeight`。`transitionTarget` 选择节点动画目标。除请求全屏范围外，宿主尺寸来自生成模板；这些选项不会复制 JSON 层级或执行业务表达式。

Controller 负责回调、本地化、模型查询、命令与显示状态。独立行与 Scene Controller 保留 `Ui.Define(viewClass, definition, baseClass?)` 和 `Controller.new(model, ui?)`。传入的 View 必须匹配生成类型，且只能绑定一个 Controller。纯声明式显示仍可直接创建和挂载生成 View。

## 观察模型字段与绑定回调

`Controller:watch(target, field, method, immediate?)` 通过原生 `Class.monitor` 观察表或 userdata 字段。传入未绑定的 Controller 方法，它接收 `(controller, newValue, oldValue)`。默认还会立即执行一次，此次使用当前值，并以 `Class.MISSING` 表示旧值；`immediate` 传 `false` 则等待字段变化后再执行。返回的 `stop()` 只取消当前订阅；Controller 释放时自动取消它拥有的所有观察。

字段观察是浅层的；字段所保存表的内部变化需要单独观察或显式刷新事件。相等值、`nil` 赋值与通知错误遵循[原生字段观察契约](<../../01.快速入门/04.Ludork Lua进阶.md#class-工具>)。

`Controller:bindCallback(method)` 通过弱引用绑定类方法，例如 `self:bindCallback(Controller.confirm)`。回调自动提供 `self`，原样传递参数和返回值；Controller 释放或被垃圾回收后停止调用。输入含义与执行动作仍属于 Controller。

## 准备、子窗口与挂载

`Window.new(...)` 自动准备 View 并挂到宿主。`window:mount(uiManager)` 将宿主注册一次；`window:unmount()` 移除该注册，但保留可复用窗口。终止生命周期时调用 `window:dispose()`。

`self:createChild("AssetName", ChildWindow, ...businessArgs)` 将 `self.ui.assets.AssetName` 传给子类的 `FromView`；`ChildWindow.FromView(ui, ...)` 也可以直接接收指定的子 View。两者复用已有控件及其原始父级，绑定独立输入宿主并准备子 Controller。位置、尺寸和层级顺序跟随生成布局；移动子宿主也会更新对应窗格。父 View 释放时自动释放子窗口。框架不会从 JSON 猜测 Controller 模块或隐式创建业务依赖。

直接使用 View 时，`View:prepare(logicalSize?)` 对已有对象树重新布局并返回根。`View:mount(uiManager, logicalSize?)` 准备并注册该根一次。`View:attachTo(parent, logicalSize?)` 准备并将根挂到 Canvas 或 ListView，必要时先移除原有挂接。直接挂载 View 不会执行 Controller 的业务准备。

`Controller:prepare(logicalSize?)` 调用一次 `bind`，订阅声明的刷新事件，注册资产更新通道，调用 `refresh`，最后准备 View。后续准备重复刷新与布局。同一资产的 Controller 共享更新通道，首次准备时才创建；仅加载模块或创建 View 不会订阅。

模型决定 Canvas 尺寸时，使用 `Source.UIBase.UiLayout.ResizeCanvas(canvas, width, height)` 调整尺寸并恢复对应默认视图，宽高为整数。静态布局仍留在 JSON；仅购买商店隐藏标签栏等依赖内容的排布仍属于业务行为。

## 动态集合

`view:createCollection(container, RowControllerClass)` 为 Canvas 或 ListView 创建一个受其拥有的 `UiCollection`；Controller 通过 `self:createCollection(...)` 提供相同方法。创建集合时会从容器移除已编写的预览子项。

`collection:add(model, logicalSize?)` 创建行 Controller，准备它，把生成根挂到容器，并返回该 Controller。`collection.items` 按插入顺序保存这些 Controller。批量修改后调用 `collection:layout()`，重新计算 ListView 的位置。`collection:clear()` 释放行 Controller 及其 View、移除根并清空 `items`；集合本身保留，可继续添加下一批。拥有它的 View 释放时，也会释放集合。

固定的 JSON 子项通过 `assets` 绑定；行数由模型决定时使用集合。

## 命名空间与属性值

生成的 `controls` 只包含当前资产的系统节点；`assets` 包含当前资产的嵌套 View 边界，通过子 View 自身的 `controls` 与 `assets` 继续访问。`Controller:requireAsset(name)` 返回该生成子 View。原生 `instance:requireControl(name)` 与 `instance:requireAsset(name)` 保持资产内命名空间并返回原生对象。`instance:getNodeByName(name)` 搜索实际控件子树，名称不唯一时拒绝查询；生成引用直接确定边界，无需这种搜索。

`AssetInstance:setProperty(name, propertyId, value)` 和 `UiController:setProperty` 要求符合属性声明类型的运行时值。类型及可选值清除方式见 [AssetInstance API](<../07.API 参考/04.Core 模块/02.Engine/13.交互与声明式 UI 控件.md#assetinstance>)。父级嵌套 JSON 不能覆盖子资产的内部属性或层级。

## 动画播放

原生实例、生成 View 和 Controller 都提供 `hasAnimation(name, target?)`、`playAnimation(name, target?, onFinished?)` 与 `stopAnimation(name, target?)`，操作 Global 或资产内节点动画。播放采用线性插值并立即应用 0 秒采样。自然完成保持末帧并调用一次完成回调。

不同 target 独立运行。同 target 替换动画会清除旧效果和回调，并从零开始。`stopAnimation` 只清除名称匹配的动画效果及待执行回调，也可清除已完成动画保持的末帧。隐藏 root 和释放实例会清除动画效果及待执行回调。

动画缺失时会输出包含 asset、target 与 name 的警告，返回 false，并同步调用完成回调。嵌套资产只在边界及其子树导出 Global 动画；父资产在该节点上的同名动画只覆盖当前实例。父 Global 动画不会启动 override，子节点动画也不会导出。

## 释放

`View:dispose()` 释放绑定的 Controller、嵌套 View 和动态集合，停止动画，卸载根并将其从父级移除。`View:own(child)` 可接管其他具有 `dispose` 方法的对象。

`window:dispose()` 与 `Controller:dispose()` 也会释放所拥有的 UI 树。重复释放是安全的；释放时会清理更新订阅、字段观察和生成控件上的原生回调。Controller 只需为该对象树之外的资源或回调补充清理逻辑。

`UIManager` 销毁时会清除注册到其生命周期的回调，包括已脱离的控件。`removeUI` 保留回调供之后 `loadUI`；加载或重新挂接子树会转移回调所有权。因此，从管理器移除根不等于释放 View 或 Controller。

释放是终端操作，不能再复用已释放 UI。[Lua 热更新](<../01.Lua 运行时与模块.md#lua-热更新>) 可以更新兼容方法并保留界面状态与订阅，但不会重新调用 `bind`、挂载控件或重建 JSON 对象树。

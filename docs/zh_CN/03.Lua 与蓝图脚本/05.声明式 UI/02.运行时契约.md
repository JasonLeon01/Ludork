# 声明式 UI 运行时契约

## 范围

本契约定义所有声明式 UI Controller 的类创建、prepare、mount、namespace 查找、refresh 与终止性 dispose。

## 类定义

`Ui.define(assetKey, definition, baseClass)` 设置资产 key，创建资产专属更新通道，并使用 `class(definition, baseClass or UiController)` 完成类定义。调用者 require 模块后使用 Model 构造：

```lua
local InventoryUI = require("Source.UI.Inventory")

local inventoryUI = InventoryUI.new(inventoryModel)
```

未提供资产实例时，`UiController:init` 只按规范逻辑 key 创建资产。

## 准备与挂载

`prepare(logicalSize)` 按以下顺序执行：

1. 调用一次 `bind`；
2. 订阅已声明刷新事件，并注册 UI 更新通道；
3. 调用 `refresh`；
4. 使用当前逻辑尺寸对 View 重新布局；
5. 返回根控件。

`mount(uiManager, logicalSize)` 先准备，再调用一次 `UIManager:loadUI`。`attachTo` 把已准备根节点添加到上级控件；`attachWindowView` 替换已有窗口宿主的兼容 View 区域。

Controller 只会在 `_bound` 变为 true 前调用 `bind`，因此它在该生命周期内只执行一次。`refresh` 与 reflow 可以重复执行。

## 查找边界

`requireControl(name)` 与 `getNodeByName(name)` 查找当前资产命名空间。`requireAsset(name)` 获取嵌套资产实例。上级不能通过子节点名穿透嵌套资产；应用该嵌套实例构造子 Controller。

## 释放

`dispose()` 是终止操作。它会卸载根、注销资产更新通道，并取消通过 `subscribe` 注册的每个事件。调用继承释放前，Controller 必须清除原生控件保持的回调，避免它们继续持有 Lua 闭包。

## 限制

已 dispose 的 Controller 不能再次 prepare 或 mount；上级不能覆盖嵌套资产实例内部。

# Lua 运行时与模块

Ludork 使用 Lua 5.5.0 运行时。项目脚本使用显式模块，以及 Ludork、LuaSF 和项目原生模块注册的 API。

## 范围

本页定义所有生产 Lua 模块遵循的 runtime 级规则：加载顺序、原生值、平台选择、真值语义、复制、日志与声明分离。

## 入口与模块顺序

`Main.ini` 选择入口脚本，通常为 `Scripts/Entry.lua`。按以下顺序加载根原生模块；同一作用域内先完成所有直接 `require`，空一行后再声明成员别名：

```lua
local Engine = require("Engine")
local GlobalCore = require("GlobalCore")
local GlobalFunctions = require("GlobalFunctions")
local Logging = require("Global.Utils.Logging")

local Input = Engine.Input
local System = GlobalCore.System
local ManagerFunctions = GlobalFunctions.Manager
```

`GlobalFunctions` 暴露 `Components`、`UI`、`NodeGraph` 与 `Manager` 分组。其他项目模块使用完整点分路径。不要创建目录级 `init.lua` 聚合入口。只有解决真实循环依赖时，才在函数内延迟 `require`。

## 原生值与平台

`sf` 是运行时全局对象。直接使用 `sf.Vector2i.new(...)`、`sf.Vector2f.new(...)`、`sf.Color.new(...)` 等已注册值，并向 API 传入它明确要求的原生值。

构建会注入全局字符串 `PLATFORM`。已定义值包括 `win32`、`darwin`、`ios` 与 `android`；其他 CMake 系统使用小写系统名。平台代码读取 `PLATFORM`，不得通过路径分隔符、文件或环境变量推测操作系统。

## 原生容器

Standard 注册小写的全局可调用对象 `list`、`tuple` 与 `dict`。它们在普通 Lua table 之外提供原生容器，但不会替代资产、metadata、Blueprint 值或原生 API 使用的 table，也不是 vector 适配器。metadata 或 binding 声明 `sf.Vector2i`、`sf.Vector2f` 等 SFML 类型时，必须传入完全对应的原生类型；持久化 raw data 应在读取边界完成转换，不得让接收 API 猜测 table、string 或 tuple 的形状。

```lua
local route = list("north", nil, "east")
local position = tuple(4, 7)
local cache = dict {
    [position] = "visited",
}
cache[1] = nil
```

`list(value1, value2, ...)` 与 `tuple(value1, value2, ...)` 会把参数依次保存为有序槽位。只有在恰好传入一个 raw table、原生 list 或原生 tuple 时，才改为把该值作为序列浅复制。因此，`list { ... }` 与 `tuple { ... }` 是 Lua 对单 sequence 调用 `list({ ... })` 与 `tuple({ ... })` 的简写。dict 只接受零个参数，或一个 raw table/原生 dict mapping；`dict { ... }` 是 `dict({ ... })` 的对应简写。因此，`dict { [1] = 2 }` 表示创建包含数值 key `1` 的字典，不是特殊的列表构造语法。list 与 tuple 的数值索引从 1 开始，不接受负索引，list 写入与插入只能指向已有槽位或 `#value + 1`。

list 可变，支持 `append`、`extend`、`insert`、`pop`、`remove`、`clear`、`index`、`count`、`contains`、`reverse`、`sort`、`copy`、`unpack` 与 `toTable`。tuple 不可变，支持 `index`、`count`、`contains`、`unpack` 与 `toTable`。dict 支持直接 key 访问，以及 `get`、`setdefault`、`update`、`pop`、`remove`、`clear`、`contains`、`keys`、`values`、`items`、`copy` 与 `toTable`。除 `pop` 外，list 的修改方法不返回值；`pop()` 默认移除最后一槽，`remove` 在值缺失时抛错。`sort(compare?)` 是稳定排序，使用传入的 `compare(left, right)` 回调或 Lua `<`。dict 的 `remove` 返回是否移除了 key，`pop` 返回被移除的值，且 key 缺失又未提供 default 时抛错。dict 的 keys、values 与 items 均按插入顺序返回原生 list；每个 item 是二槽原生 list，因此可以保留 nil value。直接读取时方法名优先于同名字符串 key：执行 `value["get"] = stored` 后，应通过 `value:get("get")` 或 `dict.get(value, "get")` 读取该项。

list 与 dict 可以保存 nil；`dictionary[key] = nil` 表示保存一个存在的 nil value，应通过 `remove` 或 `pop` 删除。其长度包含 nil 槽位或 nil value。原生容器感知的 `ipairs(list)` 与 `ipairs(tuple)` 会访问每个从 1 开始的序列槽位，并且不会在 list 的 nil 槽停止；`pairs(dict)` 按插入顺序访问所有字典项。在这些迭代期间改变容器结构会抛错。`get(key, default)` 对存在的 nil 返回 nil，只在 key 缺失时使用 default；使用 `contains(key)` 区分两种情况。tuple 禁止 nil 元素。list 与 dict 按内容做结构相等比较，并安全处理 list/dict 循环引用；tuple 根据下述按值或按身份规则比较有序元素。

tuple 是不可变、可 hash 的原生 dict key。布尔值、有限数值、字符串与嵌套 tuple 按值参与 hash；table、function、thread、list、dict 与其他 userdata 按身份参与。nil、NaN 与正负无穷都不能作为原生 dict key，嵌套在 tuple 中也不例外。hash 仅供当前 Lua State 内部使用，不是公开的持久化格式。普通 Lua table 仍按 userdata 身份 hash：只有复用同一个 tuple 对象才能命中其 key；重新构造的相等 tuple 不会命中该项。

`toTable` 会把嵌套的原生容器递归转换为普通 Lua table，并保留共享引用与循环。list 与 tuple 生成的 table 即使为空或处于嵌套位置，也会保留 JSON array 形状。list 的 nil 槽位与 dict 的 nil value 会变为 `cjson.null`，从而保留位置或 key。dict 的 tuple key 会变成 `(1,2)`、`(1,)`、`()` 这类无空格固定字符串；如果该字符串与已有字符串 key 冲突，转换会抛错。JSON encoder 与 Core binding 不会隐式转换原生容器；应在边界显式调用 `toTable`。其他非 JSON key 仍需显式转换成 record array；如果读取后必须重建 tuple 语义，也应使用 record array。

## 真值与类型检查

普通条件使用全局 `bool(value)`，使零、空字符串、空 table 与空原生容器遵循 Ludork 项目语义。只有必须区分“未提供”与 `false`、`0`、`""`、`{}` 或空原生容器，或协议把 nil 作为哨兵时，才显式比较 `nil`。

脚本类与原生类关系使用 `Class.isInstance(value, Type)` 和 `Class.isSubclass(Type, Base)`。Lua `type` 仅用于真实序列化边界、已声明基础类型联合、底层反射与 callable 分类。

## 复制与状态

全局 `copy` 与 `deepcopy` 是统一复制原语，并分别按浅复制与递归复制语义保留原生容器类型。实例需要独立可变值时使用它们。不要为向量、矩形或其他已由通用复制协议支持的值增加按类型区分的 clone helper。`asizeof` 会计入原生容器持有的值。

## 日志与错误

运行时代码通过 `Global.Utils.Logging` 输出：`debug` 用于诊断细节，`info` 用于重要阶段，`warning` 用于可恢复数据问题，`error` 用于不可恢复错误。记录错误不会抛出错误；执行必须停止时使用 `error` 或 `assert`。不要为了隐藏项目或资源错误而增加保护调用。

## 运行时、声明与 Metadata

Lua 文件分为三层，职责不得混用：

- 普通 `.lua` 承载运行时行为，只保留局部变量、局部/私有函数等实现必需注解，以及 `---@cast` 等控制流类型收窄；
- `Scripts/stub/**/*.d.lua` 按运行时模块路径镜像，承载公开文档与 LuaLS API 声明，不得包含 `require`、初始化副作用或玩法逻辑；每个可 `require` 的文件都声明与相对路径严格对应的 EmmyLua 模块名，例如 `Global/Pool.d.lua` 以 `---@meta Global.Pool` 开头；只声明全局 API 的 `Standard.d.lua`、`Class.d.lua` 与 `LuaSF.d.lua` 使用裸 `---@meta`；
- 运行时脚本旁同名 `_meta.lua` 返回固定名称的 `_METADATA` 纯数据 table，仅供编辑器发现。

EmmyLua 工作区只把 `Scripts/stub` 设为显式模块根；运行时文件仍参与工作区分析并通过后缀解析，而精确的 `require` 路径优先命中声明模块，从而提供其中的文档和类型。声明注释中的 Doxygen 命令使用 `@brief`、`@param`、`@return` 等 `@` 前缀，避免 Lua 工具把反斜杠视为转义。项目模板保留完整 `Scripts/stub` 供开发使用；游戏打包删除该目录，Lua 编译忽略所有 `.d.lua`，其他位置仍有声明文件时必须拒绝出包。

## 验证

- 从 `Scripts/Entry.lua` 开始，确认三个根模块按文档顺序加载。
- 在每个支持目标上运行平台分支，并直接检查 `PLATFORM`。
- 通过 `bool` 测试零、空字符串、空 table 与空原生容器条件。
- 验证原生 dict 可以通过分别构造的相等 tuple key 命中、普通 table 按身份命中、nil 保留迭代以及显式 `toTable` 转换。
- 确认生产脚本通过 `Global.Utils.Logging` 输出，声明文件不包含运行时逻辑，metadata 文件只包含纯数据。

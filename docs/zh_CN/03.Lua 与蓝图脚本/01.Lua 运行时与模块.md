# Lua 运行时与模块

Ludork 使用 Lua 5.5，并提供 Standard 扩展、LuaSF 和项目原生模块。

第一次接触 Lua 的读者应先阅读 [Lua 基础语法](<../01.快速入门/03.Lua 基础语法.md>)。`class`、`bool`、`list`、`dict`、复制、文件系统辅助函数与 `asyncio` 等 Ludork 原生语言扩展见 [Ludork Lua进阶](<../01.快速入门/04.Ludork Lua进阶.md>)。本节只描述项目脚本架构，不重复语言语法。

| 模型 | 适合场景 | 主要来源 |
|---|---|---|
| Blueprint graph | 可视化事件与执行流 | `Data/Blueprints/*.json` |
| Lua class | 可复用系统与玩法类型 | `Scripts/**/*.lua` |
| Script Mixin | 直接附加到 Blueprint class 的 Lua 行为 | `Scripts/Mixins/**/*.lua` 与同名 `_meta.lua` |
| 声明式 UI | JSON 资产与生成的类型化 View 树 | `Data/UI/Assets/**/*.json`、生成的 `Scripts/Source/UI/**/*.lua` 及对应 stub |
| UI 行为 | 手写基础模块与业务 Controller | `Scripts/Source/UIBase`；窗口模块内的私有 Controller；独立行与 Scene 的 `Controller.lua` 模块 |

一条 Blueprint 继承链只能使用 graph 或 Script Mixin 模式，不得中途切换。

## 入口与模块顺序

`Main.ini` 选择入口脚本，通常为 `Scripts/Entry.lua`。按以下顺序加载根原生模块；先完成直接 `require`，再声明别名：

```lua
local Engine = require("Engine")
local GlobalCore = require("GlobalCore")
local GlobalFunctions = require("GlobalFunctions")
local Logging = require("Global.Utils.Logging")

local Input = Engine.Input
local System = GlobalCore.System
local ManagerFunctions = GlobalFunctions.Manager
```

`GlobalFunctions` 提供 `Components`、`UI`、`NodeGraph` 与 `Manager`。其他模块使用完整点分路径。不要添加目录级 `init.lua` 聚合模块；只有解决真实依赖环时才延迟 `require`。

静态依赖从根原生模块流向 `Scripts/Global`，再流向 `Scripts/Source`；Global 不得 require Source。通用设施可解析数据提供的不透明模块名，但不得硬编码高层业务模块。

运行时严格使用一种脚本存储形态：开发期使用 loose `Scripts`，打包发行版使用根级 `Scripts.ldpak`。两种形态并存、缺失或无效时启动失败；逻辑模块与入口路径保持不变。

每个 Lua state 都通过 `package.preload` 暴露项目模块，且不覆盖原生模块。Script Mixin 仍在每次执行时重新加载；Standard 文件系统 API 不暴露归档内容。

packed Data 仍通过相同的逻辑 `Data/...` 路径访问，并保留加密 `.ldc` 替代规则。这是只读运行时边界，不是通用归档文件系统。

每个独立可复用类使用自己的模块，并返回该类。窗口模块可以包含自身的私有 Controller，并通过 `Ui.DefineWindow` 导出 UI，详见 [UI 编写工作流](<05.声明式 UI/01.编写工作流.md>)。工具模块可以组合相关辅助函数。

私有实现需要独立模块时，由公开模块作为宿主，将实现放在同名子目录中，例如 `Global/GameMap.lua` 与 `Global/GameMap/*.lua`。宿主保留公开方法并委托给实现模块，后者不得 require 或扩展宿主。具有独立镜像 `.d.lua` 声明的辅助模块仍视为独立模块。

私有成员只通过 `self` 或同实例 `super(..., self)` 分派访问；其他对象使用公开查询、操作方法或数据，链式访问和动态索引同样遵守此规则。

## 原生模块与值

`os.createDirectories`、`os.removeFile`、`zlib`、`base64` 等 Standard 全局由宿主安装，无需 require。宿主还会从 `LUDORK_SAVE_AS_LDC` 设置 `SAVE_AS_LDC` 默认值；项目覆盖方式见[存档](<06.Sample 玩法/06.运行时数据、配置与存档.md#存档>)。`LudorkRuntime` 是原生库而非 Lua 模块；Core binding 只通过 `Engine`、`GlobalCore` 与 `GlobalFunctions` 加载，不提供 `Runtime` 或 `CoreSystem` 别名。

LuaSF 注册全局 `sf`。API 声明 `sf.Vector2i`、`sf.Vector2f`、`sf.Color` 等类型时，应传入完全对应的原生值；原生容器和普通 table 不会隐式适配为 vector。

## 会话生命周期

同一 Lua VM 的主线程与协程共享原生会话。捕获的回调与不透明值可以跨 yield 存活，但不能跨 VM；会话关闭后失效。原生宿主接入见 [会话与模块生命周期](<../04.C++ 原生开发/01.构建与模块布局.md#会话与模块生命周期>)。

## Lua 热更新

从编辑器启动游戏，且 `Scripts` 中使用未打包的 Lua 源码时，保存修改后可在控制台输入 `$r`。运行时会在下一次控制台更新、玩法回调之间，更新已加载的项目模块与已使用的 Script Mixin，并保留当前场景、对象和 Lua 虚拟机。Debug 和 Release 构建均支持该命令；已打包或仅含编译字节码的脚本不支持。

热更新替换已有的具名函数，保留模块与类的身份、实例字段、模块数据、常量、默认值及捕获的非函数值。修改函数体会生效，修改类默认值则需要重启。已缓存的匹配函数引用（包括原生回调）会指向新的函数对象。已有匿名回调和挂起的协程执行帧继续使用原函数体，但其中引用的匹配辅助函数会更新。构造函数和生命周期回调不会重新执行。

已加载模块与已使用的 Mixin 必须保留导出名称、基类、字段与函数的种类、原生回调成员，并维持捕获状态的兼容性。删除这些模块或进行不兼容的结构变更，需要重启。普通全局变量访问可以增删；自定义 `_ENV` 无法与原环境匹配时需要重启。

更新前会编译全部运行时 Lua 源码。入口脚本只做检查，不重新执行；新增和尚未加载的模块仍由 `require` 按需加载。元数据、声明文件、JSON 数据、UI 资产和原生代码不参与更新。已有[音频处理器](<06.Sample 玩法/05.资源、音频、视频与特效.md#音频>)继续使用原代码，重新播放时才会采用新代码。

语法检查、兼容性检查或候选代码执行失败时，原有定义保持不变，控制台会报告错误。但候选代码产生的外部副作用无法回滚；若错误可能影响原生资源或共享对象，应重启游戏。模块顶层只放定义与依赖加载，资源创建和事件订阅放在显式启动函数或生命周期回调中，参见 [Sample 入口顺序](<06.Sample 玩法/01.默认模板概述.md#入口与模块>)。

## 日志与错误

运行时 Lua 通过 `Global.Utils.Logging` 记录日志：`debug` 用于诊断细节，`info` 用于关键阶段，`warning` 用于可恢复数据问题，`error` 用于不可恢复失败。记录日志不会抛错；必须停止时使用 `error` 或 `assert`。

引擎服务需要在[启动时](<06.Sample 玩法/01.默认模板概述.md#入口与模块>)显式注册，`require` 不会自动注册。服务缺失或重复注册、会话已停止、返回值数量或类型错误时均会报错；不返回值与返回一个 `nil` 含义不同。

## 运行时、声明与 Metadata

Lua 文件分工如下：

- `.lua` 保存运行时行为与仅实现所需的注解（annotation）；
- 镜像路径下的 `Scripts/stub/**/*.d.lua` 保存公开文档与 LuaLS 声明，不含运行时副作用或 `require`；
- 同名 `_meta.lua` 保存纯编辑器 metadata，不作为玩法脚本运行。

可 require 的声明使用带模块路径的 `---@meta`，例如 `Global/Pool.d.lua` 声明 `---@meta Global.Pool`。只声明全局 API 的 `Standard.d.lua`、`Class.d.lua` 与 `LuaSF.d.lua` 使用裸 `---@meta`。

EmmyLua 工作区索引 `Scripts/stub`。模板保留完整声明树供开发使用；打包会删除它，Lua 编译忽略 `.d.lua`，发行包不得残留声明文件。

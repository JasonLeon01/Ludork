# Lua 运行时与模块

Ludork 运行 Lua 5.5，并提供 Standard 扩展、LuaSF 与项目原生模块。

初次接触 Lua 的读者可以从 [Lua 基础语法](<../01.快速入门/03.Lua 基础语法.md>) 入手。`class`、`bool`、`list`、`dict`、复制、文件系统辅助函数与 `asyncio` 等 Ludork 原生语言扩展见 [Ludork Lua进阶](<../01.快速入门/04.Ludork Lua进阶.md>)。本节讲项目脚本架构，不涉及语言语法。

| 模型 | 适合场景 | 主要来源 |
|---|---|---|
| 蓝图 graph | 可视化事件与执行流 | `Data/Blueprints/*.json` |
| Lua 类 | 可复用系统与玩法类型 | `Scripts/**/*.lua` |
| Script Mixin | 直接挂到蓝图类上的 Lua 行为 | `Scripts/Mixins/**/*.lua` 与同名 `_meta.lua` |
| 声明式 UI | JSON 资产与生成的类型化 View 树 | `Data/UI/Assets/**/*.json`、生成的 `Scripts/Source/UI/**/*.lua` 及对应 stub |
| UI 行为 | 手写基础模块与业务 Controller | `Scripts/Source/UIBase`；窗口模块内的私有 Controller；独立的行与 Scene `Controller.lua` 模块 |

同一条蓝图继承链只能使用图模式或 Script Mixin 模式，不得中途切换。

## 入口与模块顺序

`Main.ini` 指定入口脚本，通常为 `Scripts/Entry.lua`。按下面的顺序加载根原生模块，先完成全部直接 `require`，再声明别名：

```lua
local Engine = require("Engine")
local GlobalCore = require("GlobalCore")
local GlobalFunctions = require("GlobalFunctions")
local Logging = require("Global.Utils.Logging")

local Input = Engine.Input
local System = GlobalCore.System
local ManagerFunctions = GlobalFunctions.Manager
```

`GlobalFunctions` 暴露 `Components`、`UI`、`NodeGraph` 与 `Manager`。其他模块一律使用完整点分路径。不要添加目录级的 `init.lua` 聚合模块。只有确实存在依赖环时，才延迟 `require`。

静态依赖从根原生模块流向 `Scripts/Global`，再流向 `Scripts/Source`。Global 模块不得 `require` Source。通用设施可以解析数据给出的不透明模块名，但不得硬编码更高层的业务模块。

运行时脚本只采用一种存储形态：开发期用未打包的 `Scripts`，打包发行版用根级 `Scripts.ldpak`。两种形态混用、缺失或无效都会在启动阶段失败。两种形态下的逻辑模块路径与入口路径完全一致。

每个 Lua state 都通过 `package.preload` 暴露项目模块，同时不覆盖原生模块。Script Mixin 仍在每次执行时重新加载。Standard 文件系统 API 不会暴露归档内容。

打包后的 Data 仍通过相同的逻辑 `Data/...` 路径访问，加密的 `.ldc` 替代文件同样如此。这是只读的运行时边界，不是通用归档文件系统。

每个可独立复用的类都有自己的模块，由该模块返回类本身。窗口模块可以内含私有 Controller，并通过 `Ui.DefineWindow` 导出 UI，详见[声明式 UI 编写工作流](<04.声明式 UI/01.编写工作流.md>)。工具模块可以收拢相关的辅助函数。

私有实现需要拆成多个模块时，由公开模块充当宿主，把它们放进同名目录，例如 `Global/GameMap.lua` 与 `Global/GameMap/*.lua`。宿主负责自己的公开方法，并委托给实现模块。实现模块不得 `require` 宿主，也不得扩展宿主。带有独立镜像 `.d.lua` 声明的辅助模块仍是独立模块。

私有成员只能通过 `self` 或同实例的 `super(..., self)` 分派访问。访问其他对象时改用公开的读取方法、命令或数据，链式访问与动态索引同样如此。

## 原生模块与值

`os.createDirectories`、`os.removeFile`、`zlib`、`base64` 等 Standard 全局由宿主安装，不需要 `require`。宿主还会根据 `LUDORK_SAVE_AS_LDC` 安装 `SAVE_AS_LDC` 默认值，项目覆盖方式见[存档](<05.Sample 玩法/06.运行时数据、配置与存档.md#存档>)。`LudorkRuntime` 是原生库，不是 Lua 模块。Core 绑定只通过 `Engine`、`GlobalCore` 与 `GlobalFunctions` 加载，也没有 `Runtime` 或 `CoreSystem` 别名。

LuaSF 注册全局 `sf`。API 声明 `sf.Vector2i`、`sf.Vector2f`、`sf.Color` 等类型时，必须传入对应的原生值，例如 `sf.Vector2i.new(...)`、`sf.Vector2f.new(...)`、`sf.Color.new(...)`。原生容器与普通 table 不会隐式充当 vector。

## 会话生命周期

同一个 Lua VM 中的主线程与协程共享一个原生会话。被捕获的回调与不透明值可以跨 yield 存活，但不能跨越 VM，会话关闭后即告失效。原生宿主接入见[会话与模块生命周期](<../04.C++ 原生开发/01.构建与模块布局.md#会话与模块生命周期>)。

## Lua 热更新

从编辑器启动游戏，且 `Scripts` 下是未打包的 Lua 源码时，保存改动后在控制台输入 `$r`。运行时会在下一次控制台更新时、玩法回调之间，更新已加载的项目模块与已使用的 Script Mixin，同时保留当前场景、对象与 Lua VM。Debug 与 Release 构建都支持该命令。已打包脚本或仅有编译产物的脚本不支持。

热更新替换已有的具名函数，同时保留模块与类的身份、实例字段、模块数据、常量、默认值以及已捕获的非函数值。修改函数体会生效，修改类默认值则需要重启。已缓存的匹配函数引用（含原生回调）会转向新的函数对象。已有的匿名回调与挂起的协程帧继续使用原函数体，但其中引用的匹配辅助函数会更新。构造函数与生命周期回调不会重新执行。

已加载模块与已使用的 Script Mixin 必须保留导出名称、类基类、字段与函数的种类、原生回调成员，以及兼容的捕获状态。删除这些模块或做出不兼容的结构改动都需要重启。增删普通全局访问是允许的。自定义 `_ENV` 无法匹配时同样需要重启。

应用改动前，运行时会编译全部 Lua 源码。入口脚本只做检查，不会重新执行。新增模块与尚未加载的模块仍可由 `require` 按需加载。Metadata、声明文件、JSON 数据、UI 资产与原生代码都不参与热更新。已有的[音频处理器](<05.Sample 玩法/05.资源、音频、视频与特效.md#音频>)继续使用原代码，直到开始新的播放。

语法、兼容性或候选代码执行失败时，原有定义保持不变，控制台会报告错误。候选执行造成的外部副作用无法回滚。错误一旦可能改动过原生资源或共享对象，就应重启。模块顶层只放定义与依赖加载，资源创建与订阅放进显式的启动函数或生命周期回调，参见 [Sample 入口顺序](<05.Sample 玩法/01.默认模板概述.md#入口与模块>)。

## 日志与错误

运行时 Lua 通过 `Global.Utils.Logging` 写日志：`debug` 记录诊断细节，`info` 记录关键阶段，`warning` 记录可恢复的数据问题，`error` 记录不可恢复的失败。写日志不会抛错。必须中止执行时使用 `error` 或 `assert`。

Engine 提供程序在[启动](<05.Sample 玩法/01.默认模板概述.md#入口与模块>)时显式安装，`require` 不会安装它们。提供程序缺失或重复、会话已停止、返回值数量或类型无效都会抛错。不返回值与返回一个 `nil` 含义不同。

## 运行时、声明与 Metadata

Lua 文件分工如下：

- `.lua` 文件保存运行时行为，以及仅供实现使用的注解。
- 镜像路径 `Scripts/stub/**/*.d.lua` 保存公开文档与 LuaLS 声明，不含运行时副作用，也不含 `require`。
- 同名 `_meta.lua` 文件保存纯编辑器 metadata，绝不作为玩法脚本运行。

可 `require` 的声明用 `---@meta` 写出模块路径，例如 `Global/Pool.d.lua` 声明 `---@meta Global.Pool`。只声明全局 API 的 `Standard.d.lua`、`Class.d.lua` 与 `LuaSF.d.lua` 使用裸 `---@meta`。

EmmyLua 工作区索引 `Scripts/stub`。模板保留整套声明树供开发使用。打包会删除它，Lua 编译忽略 `.d.lua`，发行包中不得残留任何声明文件。

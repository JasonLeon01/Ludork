# 声明式 UI 运行时契约

生成的 View 创建并拥有完整的 UI 对象树。需要业务行为时，再由 Controller 补上。

## 创建 View

```lua
local InventoryView = require("Source.UI.Inventory")

local inventory = InventoryView.new()
inventory:mount(uiManager, logicalSize)
```

`View.new()` 实例化 JSON 资产，为每个嵌套资产套上它对应的生成 View 类，并递归填满所有类型化引用，不需要 Controller。创建 View 并不会把界面挂到屏幕上，因此必须显式调用 `mount` 或 `attachTo`。

每个 View 都暴露 `assetKey`、`designSize: sf.Vector2f`、原生 `instance: Engine.AssetInstance`、类型化的 `root`、保存原生系统控件的 `controls`，以及保存类型化子 View 的 `assets`。访问子项的具名控件可以写 `inventory.assets.ItemRow.controls.Label`。名称始终是资产内的原始 key，所以不是 Lua 标识符的名称要用方括号访问。

每个嵌套节点都有自己的 View 与原生实例，即使多个节点引用同一个资产也如此。为子节点绑定 Controller 时，直接传入已有的子 View。

## 绑定业务行为

窗口模块在文件内定义一个私有 Controller，并返回 `Ui.DefineWindow(viewClass, Controller, nativeBase?)`。`nativeBase` 默认为 `Engine.Canvas`，返回的 UI 继承该原生基类。Controller 是独立的 `UiController` 对象，生成的 View 则独立于这两者。`Window.new(...businessArgs):mount(uiManager)` 创建并注册完整窗口。Controller 为空时不需要 `init`，窗口按模板原有的内容与尺寸显示。

构造过程先创建原生宿主与生成的 View，把它们绑定到 Controller，并挂接 View，之后才调用可选的业务 `init(...)`。此时 `self.ui` 是类型化的生成树，`self.view` 是它的原生 `Engine.AssetInstance`，`self.root` 是原生根，`self.host` 是 UI。UI 通过 `window.ui` 暴露同一个 View，并让 Controller 保持私有。`init` 结束后，框架调用 `prepare` 完成绑定、刷新与重新布局，接着调用可选的 `ready`，再应用配置好的初始隐藏状态。需要首次准备好的布局才能开展的业务工作放在 `ready` 中。

工厂通过窗口 API 暴露 Controller 实例方法（`camelCase`）、静态辅助函数（`PascalCase`）、`SCREAMING_SNAKE_CASE` 常量与 `Publish`，构造钩子保持私有。声明布局见[声明式 UI 编写工作流](<01.编写工作流.md#文件布局>)。

`Controller.windowOptions` 提供可选的宿主行为。`position`、`centered` 与 `screen` 控制根节点的位置或全屏范围，`hidden`、`returnButton` 与 `focusable` 控制初始交互状态。窗口基类使用 `frame` 与 `content` 节点名，默认分别为 `WindowFrame` 与 `Content`。可选择项的基类可以命名 `list` 与 `scroll`，并设置 `itemWidth`、`itemHeight`、`hitWidth` 或 `hitHeight`。`transitionTarget` 指定节点动画目标。宿主尺寸取自生成模板，除非请求全屏行为。这些选项不会复现 JSON 层级，也不会执行业务表达式。

回调、本地化、模型查询、命令与显示状态都由 Controller 拥有。独立行 Controller 与 Scene Controller 保留 `Ui.Define(viewClass, definition, baseClass?)` 与 `Controller.new(model, ui?)`。传入的 View 必须与生成类型一致，并且只能接受一个 Controller。纯声明式的显示仍然可以直接创建并挂载生成的 View。

## 观察模型字段与绑定回调

`Controller:watch(target, field, method, immediate?)` 通过原生 `Class.monitor` 观察表或 userdata 的字段。传入未绑定的 Controller 方法，回调收到 `(controller, newValue, oldValue)`。默认还会立即执行一次，此时收到当前值与作为旧值的 `Class.MISSING`；把 `immediate` 传为 `false` 则等字段变化后再执行。返回的 `stop()` 只取消这一个订阅，Controller 释放时会自动取消它拥有的全部观察。

观察是浅层的，表字段内部的变化需要另行观察，或者显式触发刷新事件。相等判断、`nil` 赋值与通知错误的规则见 [Ludork Lua进阶](<../../01.快速入门/04.Ludork Lua进阶.md#class-工具>)。

`Controller:bindCallback(method)` 通过弱引用绑定类方法，例如 `self:bindCallback(Controller.confirm)`。回调自带 `self`，并原样传入参数、原样返回结果。Controller 释放或被回收之后调用随即停止。输入的解释与动作的执行仍留在 Controller 中。

## 准备、子窗口与挂载

把已有 View 挂接到窗口宿主时，保留窗口背景在资产中定义的 `windowSkin` 与 `repeated` 属性，宿主默认值不会覆盖它们；显式调用 `applyWindowSkin()` 仍会应用宿主的皮肤与平铺设置。

`Window.new(...)` 自动准备 View 并把它挂接到宿主。`window:mount(uiManager)` 注册宿主一次，`window:unmount()` 取消这次注册，同时保留可复用的窗口。彻底释放请调用 `window:dispose()`。

`self:createChild("AssetName", ChildWindow, ...businessArgs)` 用 `self.ui.assets.AssetName` 调用子类的 `FromView`；`ChildWindow.FromView(ui, ...)` 也接受显式传入的子 View。两种写法都复用子 View 已有的控件与已编写的父级，绑定独立的输入宿主，并准备子 Controller。位置、尺寸与层叠顺序遵循生成布局，移动子宿主会同步更新它的窗格。父 View 释放时自动释放子窗口。框架不会从 JSON 中发现 Controller 模块，也不会隐式构造业务依赖。

直接使用 View 时，`View:prepare(logicalSize?)` 重新布局已有的树并返回根节点；`View:mount(uiManager, logicalSize?)` 准备并注册该根一次；`View:attachTo(parent, logicalSize?)` 准备根，并把它挂接到 Canvas 或 ListView，必要时先解除原有的挂接。直接挂载 View 不会执行 Controller 的业务准备。

`Controller:attachTo` 和 `Controller:mount` 只准备一次 Controller，之后通过 `View:attachPreparedTo(parent)` 或 `View:mountPrepared(uiManager)` 挂接，以保留 Controller 在基类准备之后应用的几何调整。

`Controller:prepare(logicalSize?)` 调用一次 `bind`，订阅声明的刷新事件，注册资产更新通道，调用 `refresh`，然后准备 View。之后的每次准备都重复刷新与重新布局。同一资产的 Controller 共享一个更新通道，通道在首次准备时创建。仅加载模块或创建 View 不会订阅该通道。省略 `logicalSize` 会继续使用上次由持有者传入的尺寸。行 Controller 使用该尺寸完成动态布局和语言刷新。

Canvas 尺寸由模型决定时，用 `Source.UIBase.UiLayout.ResizeCanvas(canvas, width, height)` 调整尺寸，并为这组整数宽高恢复默认视图。静态布局仍留在 JSON 中。依赖内容的排布，例如在仅购买模式下隐藏商店标签页，仍由 Controller 负责。

## 首次使用时创建可选窗口

`Source.UIBase.LazyWindow` 是可选窗口的泛型拥有者。`LazyWindow.new(factory)` 只保存工厂，不创建 UI。`handle:get()` 首次使用时调用工厂，缓存完整窗口，后续调用返回同一实例。`handle:peek()` 返回已有窗口或 `nil`，不会调用工厂。

工厂依次 require 窗口模块、调用 `Window.new(...)`、配置回调与焦点，再将窗口挂载到已有的 UI 管理器。把 `require` 留在工厂内，也会将窗口类定义的加载推迟到首次使用。显示入口随后调用 `handle:get():open(...)`。工厂运行时读取当前玩家、游戏实例与配置。拥有者可以预先建立空焦点组及其相邻关系，再在挂载和激活新窗口之前填入实际控件。可见性、输入阻塞、关闭、语言刷新与玩家重绑定使用 `peek()`，避免创建尚未使用的 UI。

每个独立弹窗分别持有句柄，包括从菜单打开的窗口。窗口内已编写的子 View 仍随父窗口一起构造。`Window.new(...)` 与生成的 `View.new()` 始终构造完整的树，懒加载只推迟这次调用。重新打开会保留已有窗口、Controller 与 View，并沿用窗口正常的刷新和动画行为。

拥有者生命周期结束时，`handle:dispose()` 释放已创建的窗口与工厂；尚未使用的句柄只释放工厂。释放是终态，绝不会调用工厂。

## 动态集合

`view:createCollection(container, RowControllerClass)` 为 Canvas 或 ListView 创建一个由其拥有的 `UiCollection`；Controller 通过 `self:createCollection(...)` 使用同一方法。创建集合会把已编写的预览子项从容器上摘除。

`collection:add(model, logicalSize?)` 创建行 Controller、准备它、把它的生成根挂接到容器，并返回该 Controller。`collection.items` 按插入顺序保存这些 Controller。批量添加之后调用 `collection:layout()` 重新计算 ListView 位置。`collection:clear()` 释放行 Controller 及其 View，移除它们的根，清空 `items`，集合本身留给下一批使用。拥有集合的 View 释放时，集合一并释放。

固定的 JSON 子项通过 `assets` 绑定；行数随模型变化时改用集合。

## 重复模板控件

已编写的 `Engine.WrapBox` 持有一个模板，创建 `count` 个独立的原生子树。生成 View 在 `controls` 中暴露 WrapBox，不会将模板后代展开到外层 View 的 `controls` 或 `assets` 中。使用 `wrapBox:get(i)` 按从 1 开始的下标获取实例的原生根控件，再使用普通子控件 API 访问内部控件。将 `Engine.ControlBase` 引用缩窄到具体原生类之前，先通过 `Class.isInstance` 检查。

`getCount()` 与 `setCount(count)` 读写非负重复数量。数量为零或没有模板时控件为空，`get(i)` 在下标无效时会报错。重新布局以及修改尺寸或间距都会保留已有实例；增大数量时追加实例，减小时只释放移除的尾部实例。每份子树具有独立的运行时状态，由 WrapBox 拥有更新、输入与释放生命周期。这种固定视觉重复不需要创建 `UiCollection`。

## 命名空间与属性值

生成的 `controls` 只包含本资产的系统节点，`assets` 只包含本资产的嵌套 View 边界；每个边界各自暴露自己的 `controls` 与 `assets`，供继续访问。`Controller:requireAsset(name)` 返回对应的生成子 View。原生 `instance:requireControl(name)` 与 `instance:requireAsset(name)` 保留本资产的命名空间并返回原生对象。`instance:getNodeByName(name)` 搜索真实的控件子树，名称有歧义时拒绝返回。生成引用直接给出准确边界，无需这种搜索。

`AssetInstance:setProperty(name, propertyId, value)` 与 `UiController:setProperty` 接受属性声明的运行时类型。属性类型与可选值的清除方式见 [Engine：交互与声明式 UI 控件](<../08.全局与 Core 模块/02.Core Modules/01.Engine/13.交互与声明式 UI 控件.md#assetinstance>)。嵌套 JSON 不能覆盖子资产的内部属性或层级。

## 动画播放

`hasAnimation(name, target?)`、`playAnimation(name, target?, onFinished?)` 与 `stopAnimation(name, target?)` 在原生实例、生成的 View 和 Controller 上都可用，作用于 Global 动画或资产内节点动画。播放是线性的，并立即应用时间零点。自然播放结束时保持末帧，并调用一次完成回调。

各 target 彼此独立。替换同一 target 会先清除旧效果与旧回调，再从零开始。`stopAnimation` 只清除名称匹配的动画效果与待执行回调，也包括已完成动画保持的末帧。隐藏根节点与释放实例都会清除动画效果与待执行回调。

动画不存在时会输出警告，其中包含所属资产、target 与名称，返回 `false`，并同步调用完成回调。嵌套资产只在自身边界及其子树上导出 Global 动画。父资产针对该节点的同名动画只覆盖这一个实例。父资产的 Global 动画不会启动该覆盖，子节点动画也不会导出。

## 释放

`View:dispose()` 释放绑定的 Controller、嵌套 View 与动态集合，停止动画，卸载根节点并解除挂接。`View:own(child)` 接管另一个带 `dispose` 方法的对象。

`window:dispose()` 与 `Controller:dispose()` 同样释放所拥有的 UI 树。释放可以安全重复执行，并清除更新订阅、拥有的观察以及生成控件上的原生回调。只有当资源或回调位于这棵树之外时，Controller 才需要额外清理。

`UIManager` 销毁会清除注册到它生命周期上的回调，已脱离的控件也不例外。`removeUI` 会保留这些回调，供之后的 `loadUI` 使用；加载或改变子树父级会转移回调所有权。因此，从管理器移除根节点不能替代 View 或 Controller 的释放。

已释放的 UI 是终态，不得复用。热更新（见 [Lua 运行时与模块](<../01.Lua 运行时与模块.md#lua-热更新>)）更新兼容的方法，同时保留界面状态与订阅；它不会重新执行 `bind`，不会重新挂载控件，也不会重建 JSON 树。

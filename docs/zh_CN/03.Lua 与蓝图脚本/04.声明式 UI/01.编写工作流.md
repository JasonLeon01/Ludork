# 声明式 UI 编写工作流

## 目标

Ludork 的声明式 UI 由 JSON 资产生成 Lua View，业务行为则写在手写 Controller 中。可视化编辑请使用 [UI 资产编辑器](<../../02.编辑器用户指南/07.UI 资产编辑器.md>)。

| 层 | 拥有内容 |
|---|---|
| JSON View | 层级结构、资产内节点名、静态控件属性、Slot、动画 Timeline 与仅用于设计的预览数据 |
| 生成的 Lua View | 完整的类型化控件与子 View 树、资产身份、挂载与所拥有对象的生命周期 |
| Lua Controller | 模型访问、回调、本地化与格式化文本、状态刷新与动态组合 |
| 窗口 UI | 原生窗口与输入状态，以及该窗口持有的生成 View 与私有 Controller |
| 原生控件 | 渲染、测量、命中测试、焦点与基础交互状态 |
| UIManager | 挂载和移除已准备的根控件 |

Controller 函数、表达式、事件处理器与 `LOC(...)` 调用一律不得写入 UI 资产。

## 步骤

### 文件布局

资产根目录固定为 `Data/UI/Assets`：

```text
Data/UI/Assets/
    ├── Inventory.json
    └── Parts/
        ├── Inventory/ItemRow.json
        └── Shared/KeyPrompt.json
```

完整的屏幕、窗口、HUD 与浮层直接放在 `Assets` 下。某个大型 UI 自有的部件放入 `Parts/<Owner>`，多个 UI 共用的部件放入 `Parts/Shared`。不得创建只按控件形态划分的目录。

生成的 Lua View 与资产层级一一对应。`Scripts/Source/UI` 与 `Scripts/stub/Source/UI` 下的每个文件都由生成器维护：

```text
Scripts/Source/UI/
├── Inventory.lua
└── Parts/
    ├── Inventory/ItemRow.lua
    └── Shared/KeyPrompt.lua
```

手写基础模块放在 `Scripts/Source/UIBase` 下。窗口模块（例如 `Scripts/Source/Windows/WindowInventory.lua`）在文件内定义私有 Controller，并通过 `Ui.DefineWindow` 返回 UI 类。独立行 Controller 与 Scene Controller 各自单独成模块，例如 `Source.Windows.WindowInventory.ItemRow.Controller` 与 `Source.Scenes.SceneTitle.Controller`。

配套的窗口 stub 只声明私有 Controller，使用不带模块名的 `---@meta`。公开窗口声明生成到 `Scripts/stub/Source/UIWindows`，不得手工修改。声明格式见[声明式 UI Controller 示例](<03.Controller 示例.md#业务成员只声明一次>)。

### 创建 UI 并添加业务行为

1. 在 UI 资产编辑器中创建 JSON 资产，为运行时访问的节点取稳定的名称。
2. 启用 **Exposed**，资产才会出现在 Project Palette 中。
3. 保存资产并处理所有校验诊断，再点击 **导出** 生成 View，然后在窗口模块中 require 该 View。
4. 定义局部 Controller，返回 `Ui.DefineWindow(ViewClass, Controller, nativeBase?)`。业务初始化写在 `init` 中，回调写在 `bind` 中，状态更新交给 `watch` 或 `refresh`。
5. 窗口的初始行为用 `windowOptions`，已编写的子窗格用 `createChild`，行数随模型变化的行用集合。参见[声明式 UI 运行时契约](<02.运行时契约.md>)与[声明式 UI Controller 示例](<03.Controller 示例.md>)。
6. 维护私有 Controller 声明并重新生成。由拥有者创建并挂载窗口，不再需要时将其释放。可选弹窗各自持有 `Source.UIBase.LazyWindow` 句柄，由其工厂完成完整构造、回调与焦点配置以及挂载；显示入口使用 `get()`，查询使用 `peek()`，详见[首次使用时创建窗口](<02.运行时契约.md#首次使用时创建可选窗口>)。

### 资产变更后重新生成

移动资产或重命名节点之后，先更新手写的 `require` 调用与节点引用，再点击 **导出**；也可运行 `ScriptTools ui-assets generate <project-root>`，仅生成 UI 文件。导出归属与只读检查见[声明式 UI 校验与打包](<05.校验与打包.md>)。

### 平铺图像与重复控件

制作重复背景时，添加 `Engine.Image`，将 **Draw As** 选择为 **Tile**，并通过 Canvas Slot 拉伸到目标区域。区域增大时，纹理像素保持原有逻辑尺寸。需要拉伸图片时保留默认的 **Image**。

重复显示气息火苗等视觉单元时，添加一个 `Engine.WrapBox`，只在下面放一个子模板，然后设置 `count`、`size` 与 `spacing`。模板可以是完整的 Canvas 子树，所有实例都由原生控件创建和排布；Controller 使用 `wrapBox:get(i)` 访问各个单元，无需逐行构造。如果每行都需要独立的模型和 Controller，则使用动态集合。运行时访问与生命周期见[声明式 UI 运行时契约](<02.运行时契约.md#重复模板控件>)。

### 可滚动内容

容易溢出的内容一律放入 `Engine.ScrollBox`，不要用 Controller 代码移动 Canvas。`size` 定义视口，`windowSkin` 为空时使用系统皮肤。裁剪、偏移以及滚轮和触摸输入都由 ScrollBox 负责：只有排布后的内容超出某个轴，它才滚动该轴。提示图集细节见 [Engine：布局与图像控件](<../08.全局与 Core 模块/02.Core Modules/01.Engine/10.布局与图像控件.md>)。

## 限制

每个可见界面只有一个顶层资产。多窗格界面从 `Parts/<TopLevelName>/` 嵌套属于该所有者的资产。嵌套部件设置 `palette.exposed = true`，只供运行时使用的辅助资产可以不暴露。

`#TAB`、`#ITEM` 子项与 Game 视觉资源只取有代表性的样例，仅作预览数据，绝不能当作游戏数据的回退。显示之前，业务代码负责本地化 Tab 标签并填充动态集合。固定控件与固定行始终是 JSON 创建的那一份实例。字面 `text` 只留给永久且与语言无关的符号。

逐帧动画的角色与敌人使用 `Engine.CharacterView`。资产提供预览值，运行时把真实的纹理、Rect、缩放、动画、Shader 与 Hue 传给 `setCharacter`。Lua 不负责裁剪或合成 Actor 视觉。

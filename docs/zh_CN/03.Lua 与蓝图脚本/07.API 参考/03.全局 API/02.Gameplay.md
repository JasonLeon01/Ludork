# GlobalCore Gameplay API

通过 `require("GlobalCore")` 可使用原生能力系统，包括 `AttributeSet`、`AbilitySystemComponent`，以及能力、结果、事件和效果相关类型。

## AttributeSet

`AttributeSet` 子类在 `ATTRIBUTE_NAMES` 中声明有序的属性名，并在 `SCHEMA` 中为各属性定义 `{ type, default }`；`ID` 对应 General Data 成员的键。缺失字段使用默认值，显式保存的 nil 分支则覆盖默认值。使用 `Source.Configs.GeneralDataTypes.Create` 加载已保存的 General Data。

| 成员 | 签名 | 行为 |
|---|---|---|
| `init` | `(values?)` | 初始化全部已声明属性和 `ID` |
| `initialize` | `(values)` | 校验并复制运行时值 |
| `initializeStored` | `(values)` | 按类型规则还原存储值，再复制到属性中 |
| `getAttributeNames` | `() -> string[]` | 返回有序属性名列表的副本 |
| `getAttributeSchema` | `(name) -> AttributeSchema?` | 返回属性的类型规则 `type` 和默认值 `default` |

只有 `int` 和 `float` 字段区分基础值（Base）与当前值（Current），并支持修饰项。值必须为有限数；`int` 要求 Lua 整数，`float` 接受任意有限数值。其他字段按声明类型直接存储。

## AbilitySystemComponent

`AbilitySystemComponent.new(owner, attributeSet)` 管理属性、能力、生效中的效果和带计数的标签。

### 属性

| 成员 | 签名 | 行为 |
|---|---|---|
| `getOwner` | `() -> any` | 返回所属的玩法对象 |
| `getAttributeSet` | `() -> AttributeSet` | 返回正在使用的属性集 |
| `getNumericAttribute` | `(name) -> number` | 返回应用修饰项后的当前值 |
| `getNumericAttributeBase` | `(name) -> number` | 返回未经修饰的基础值 |
| `setNumericAttributeBase` | `(name, value)` | 修改一个基础值，并重算所有数值属性的当前值 |
| `setNumericAttributeBases` | `(values)` | 修改多个基础值，再重算所有数值属性 |
| `getNumericAttributeBases` | `() -> table<string, number>` | 返回可用于持久化的基础值副本 |
| `addAttributeChangeListener` | `(name, callback, params?)` | 相关当前值或基础值变化后，调用 `callback(oldValue, newValue, change, ...)` |
| `setNumericAttributeConstraint` | `(name, callback?)` | 设置或移除当前值的最终约束，并立即重算 |
| `getRevision` | `() -> integer` | 返回随属性、能力或效果变化而递增的版本号 |

基础值写入前会校验完整的候选 Base/Current 状态；属性名未知、数值非有限或类型不匹配时，不会留下部分修改。直接给数值字段赋值也视为修改基础值。

监听回调中的 `oldValue` 和 `newValue` 始终是当前值，第三个参数是 `AttributeChange` 上下文：

| 字段 | 类型 | 含义 |
|---|---|---|
| `source` | `"Base" \| "Effect" \| "Constraint"` | 触发本次重算的操作 |
| `force` | `boolean` | 为 true 时，即使当前值未变，基础值写入仍会触发通知 |
| `oldBase` | `number \| Class.MissingValue \| nil` | 来源为 `Base` 时的旧基础值；其他来源为 nil |
| `newBase` | `number \| nil` | 来源为 `Base` 时的新基础值；其他来源为 nil |

附加参数 `params` 在 `change` 之后传入回调。批量写入只通知最终状态；基础值写入即使未改变当前值也会通知，效果和约束则仅在当前值变化时通知。

约束在修饰项聚合后接收 `(value, abilitySystem, resolvedValues)`，必须恰好返回一个符合属性类型的有限数值，且不修改基础值。传入 nil 可移除约束。属性按 `ATTRIBUTE_NAMES` 顺序计算，HP 最后；`resolvedValues` 包含本轮已算出的字段。

### 能力与事件

| 成员 | 签名 | 行为 |
|---|---|---|
| `giveAbility` | `(ability, sourceKey?) -> GameplayAbilitySpec` | 授予能力并记录来源 |
| `removeAbilitiesBySource` | `(sourceKey)` | 移除由指定来源授予的全部能力 |
| `tryActivateAbility` | `(abilityID, eventData?) -> GameplayAbilityResult` | 激活该 ID 下优先级最高且满足激活条件的能力 |
| `handleGameplayEvent` | `(eventData) -> GameplayAbilityResult[]` | 执行触发标签与事件匹配的全部能力 |

能力按 `priority` 从高到低执行，同优先级按授予顺序执行。标签支持层级匹配。直接激活时，ID 不存在则返回 `AbilityNotFound`，所有匹配能力均未满足激活条件则返回 `AbilityNotActivated`。

### 效果与标签

| 成员 | 签名 | 行为 |
|---|---|---|
| `applyGameplayEffectSpec` | `(spec) -> integer?` | 应用 `Instant` 效果，或返回 `Infinite` 效果的句柄 |
| `validateGameplayEffectSpec` | `(spec) -> bool` | 校验并预演效果，不改变能力系统状态 |
| `removeActiveGameplayEffect` | `(handle, stacks?) -> bool` | 移除指定层数或整个生效中的效果 |
| `getActiveEffectStacks` | `(effectID) -> integer` | 汇总该 ID 下所有生效中效果的层数 |
| `getActiveGameplayEffects` | `() -> ActiveGameplayEffect[]` | 按应用顺序返回生效中的效果 |
| `hasMatchingGameplayTag` | `(tag) -> bool` | 检查已拥有的标签是否与指定标签相同或属于其子级 |

`Instant` 修饰项按顺序更新基础值，每项更新后立即应用其 `minimum`，不返回句柄。`Infinite` 修饰项持续参与当前值计算，直到效果被移除：`Add` 求和，`Multiply` 相乘，最后一个 `Override` 生效，最后再取匹配修饰项中最大的 `minimum` 作为当前值下限。`Aggregate` 叠层对 `Add` 按层数相乘，对 `Multiply` 按层数求幂。`None` 按非空 ID 与来源的组合去重。

修饰量、下限、基础值和当前值都必须为有限数且符合属性类型。`Instant` 效果不能授予标签或能力。`None` 只允许一层；采用 `Aggregate` 的 `Infinite` 效果要求非空 ID。移除 `Infinite` 效果时，也会移除它的标签和授予的能力。

效果的应用、叠加和移除都会先预演完整结果，再修改能力系统状态。`validateGameplayEffectSpec` 仅预演，不修改状态；正式应用时会再次校验。修饰量函数和约束会在预演时执行，不得产生外部副作用。提交后的监听回调出错不会回滚已完成的修改。

## GameplayAbility

`GameplayAbility` 定义能力的激活策略与行为。

| 字段 | 类型 | 默认值 |
|---|---|---|
| `id` | `string` | `""` |
| `priority` | `integer` | `0` |
| `abilityTags` | `string[]` | `{}` |
| `requiredTags` | `string[]` | `{}` |
| `blockedTags` | `string[]` | `{}` |
| `triggerTags` | `string[]` | `{}` |

| 成员 | 签名 | 行为 |
|---|---|---|
| `canActivate` | `(abilitySystem, eventData) -> GameplayAbilityResult` | 检查是否拥有必要标签、是否存在阻止激活的标签 |
| `calculate` | `(abilitySystem, eventData) -> GameplayAbilityResult` | 默认只计算结果，不提交修改 |
| `activate` | `(abilitySystem, eventData) -> GameplayAbilityResult` | 调用 `calculate`；子类可覆盖此方法以提交修改 |

授予能力时要求非空 ID；覆盖上述方法时必须返回 `GameplayAbilityResult`。

## GameplayAbilityResult

`GameplayAbilityResult` 包含 `ok`、字符串或整数 `code`（默认为 `""`），以及任意类型的 `data`。

| 静态成员 | 签名 | 行为 |
|---|---|---|
| `Success` | `(code?, data?) -> GameplayAbilityResult` | 创建成功结果；默认结果码为 `Success` |
| `Failure` | `(code, data?) -> GameplayAbilityResult` | 创建失败结果；结果码必须是非空字符串或非零整数 |

## GameplayEventData

`GameplayEventData.new(instigator?, target?, eventTag?, payload?)` 携带一次能力激活或事件的数据。

| 字段 | 类型 | 默认值 |
|---|---|---|
| `instigator` | `any` | `nil` |
| `target` | `any` | `nil` |
| `eventTag` | `string` | `""` |
| `payload` | `table<string, any>` | `{}` |

事件处理函数可修改 `payload`。`handleGameplayEvent` 要求非空标签，直接激活能力则无此要求。

## GameplayEffect 与 GameplayEffectSpec

`GameplayEffect` 描述修饰项及授予的标签和能力；`GameplayEffectSpec` 将效果与事件数据、层数和来源关联起来。

| GameplayEffect 字段 | 类型 | 取值/默认值 |
|---|---|---|
| `id` | `string` | `""` |
| `durationPolicy` | `string` | `Instant` 或 `Infinite`；默认 `Instant` |
| `stackingPolicy` | `string` | `None` 或 `Aggregate`；默认 `None` |
| `modifiers` | `GameplayModifier[]` | `{}` |
| `grantedTags` | `string[]` | `{}`；仅限 `Infinite` |
| `grantedAbilities` | `GameplayAbility[]` | `{}`；仅限 `Infinite` |
| `data` | `table<string, any>` | `{}` |

| GameplayModifier 字段 | 类型 | 取值/默认值 |
|---|---|---|
| `attribute` | `string` | 目标数值属性 |
| `operation` | `string` | `Add`、`Multiply` 或 `Override` |
| `magnitude` | `number` 或 `function` | 校验时必填：有限数值，或接收 `(spec, stacks)` 并恰好返回一个有限数值的函数 |
| `minimum` | `number?` | 可选的有限下限 |

能力系统不解析 `data` 的内容。`GameplayEffectSpec.new(effect, eventData?, stacks?, sourceKey?)` 要求层数为正整数。`Infinite` 效果按效果 ID 和 Lua 相等的 `sourceKey` 去重或叠加；调用方须确保同一组合对应的效果定义一致。`Aggregate` 保留首次应用的效果参数。

## 运行时记录

`GameplayAbilitySpec` 保存 `ability`、`sourceKey` 和 `grantOrder`。`ActiveGameplayEffect` 保存 `handle`、`spec`、`stacks`、`applicationOrder` 和已授予能力的记录。

## 支持范围

支持即时效果（`Instant`）、持续效果（`Infinite`）、`Add`/`Multiply`/`Override` 运算、聚合叠层、层级标签和同步能力。不支持计时器、周期效果、预测、复制同步、异步任务或内建持久化。

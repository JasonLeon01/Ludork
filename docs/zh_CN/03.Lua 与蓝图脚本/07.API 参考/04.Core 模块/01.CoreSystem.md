# CoreSystem Lua API

`CoreSystem` 是提供文件系统检查、目录创建、zlib 压缩与 Base64 转换的原生 Lua 模块。本参考以 `Scripts/stub/CoreSystem.d.lua` 和 `Core/System/include/CoreSystem.hpp` 为依据。

`Scripts/CoreSystem_meta.lua` 为空，因此这些函数不会生成 Blueprint 节点。Metadata 为空不代表 Lua 模块为空。

## 加载

```lua
local CoreSystem = require("CoreSystem")
```

`CoreSystem` 独立于固定的 `Engine` → `GlobalCore` → `GlobalFunctions` 玩法根序列。

## 函数

| 名称 | 参数 | 返回 | 用途 |
|---|---|---|---|
| `exists` | path: string | bool | 检查文件系统路径是否存在。 |
| `currentPath` | — | string | 返回进程当前工作目录。 |
| `createDirectories` | path: string | — | 创建目录及缺失的上级目录。 |
| `compress` | value: string | string | 使用 zlib 压缩可包含二进制数据的 Lua 字符串。 |
| `decompress` | value: string | string | 解压 zlib 压缩的二进制安全 Lua 字符串。 |
| `encodeBase64` | value: string | string | 将二进制安全 Lua 字符串编码为 Base64。 |
| `decodeBase64` | value: string | string | 将 Base64 解码为二进制安全 Lua 字符串。 |

## 验证

在原生 runtime 构建中 require 模块，用代表性二进制数据分别执行 `compress`/`decompress` 与 `encodeBase64`/`decodeBase64` 往返，并只在项目拥有的临时目录内测试文件系统操作。

## 限制

这些函数使用 runtime 进程的文件系统权限，不提供编辑器 sandbox。无效压缩数据或 Base64 输入会报告 runtime 错误。不得用 `currentPath` 代替项目相对资产路径。

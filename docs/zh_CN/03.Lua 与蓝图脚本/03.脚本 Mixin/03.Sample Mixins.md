# Sample Script Mixins

Sample 项目包含五个职责各异的 Mixin。可把它们用作行为模式与验证夹具（fixture）；只有当新的 Blueprint 父类与数据依赖一致时，才复制其契约结构。

| 脚本 | 父类能力 | 行为 |
|---|---|---|
| `Consumables/Bottle.lua` | 可碰撞 Actor | 检测 Player、恢复 HP、播放已配置声音并销毁拾取物。 |
| `Consumables/Gem.lua` | 可碰撞 Actor | 向 Player 直接字段或匹配组件字段增加数值。 |
| `Doors/Door.lua` | `DoorBase` | 碰撞时开门，并防止重复开启。 |
| `Doors/KeyDoor.lua` | Script Mixin 门 Blueprint | 继续执行父碰撞方法前，要求并消耗已配置的 General Data 物品。 |
| `Doors/ConditionDoor.lua` | `DoorBase` | 仅为已配置的游戏变量启用轮询，达到阈值时开门。 |

## 消耗品模式

`Bottle` 与 `Gem` 在处理碰撞前检查 `self:isDestroyed()`，从 Scene 中查找活动 Player，执行数据变更，调用继承碰撞行为，记录已销毁 Actor，并销毁拾取物。声音字段为空时，使用项目配置中的回退值（fallback）。

## 门模式

`Door` 负责碰撞开门。`KeyDoor` 要求 `MeetPlayer`、持有钥匙且未重入，随后消耗钥匙。`ConditionDoor` 仅在配置 `openConditionName` 后轮询，并在达到阈值时调用 `openDoor`。

## 限制

Sample ID、声音与 General Data 记录都属于具体项目。复制来的 Mixin 仍需要与之匹配的 metadata、父类能力与运行时引用。

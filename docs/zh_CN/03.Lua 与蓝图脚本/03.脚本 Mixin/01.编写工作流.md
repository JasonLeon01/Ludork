# Script Mixin 编写工作流

Script Mixin 把 Lua 行为 table 直接挂载到 Blueprint 类。当 Blueprint 需要保留编辑器默认值与继承，但事件逻辑用 Lua 表达更清晰时，应使用该模式。

同一条 Blueprint 继承链中，图模式与 Script Mixin 模式互斥。第一个 Script Mixin Blueprint 提供脚本；后代可以继承该脚本或提供另一个兼容 Mixin，但不能把继承链切回图模式。

Script Mixin Blueprint 可以省略 `graph`，因为其事件来自 Lua。若仍保存 `graph` 字段，该字段必须是结构合法的 graph object，尽管运行时不会执行它。图模式 Blueprint 则必须始终保存 graph object。

## 目标

把新 Lua 行为挂载到编辑器创建的 Blueprint。

## 前置条件

- Blueprint 父类提供 Mixin 使用的全部生命周期 callback 与原生成员。
- 已为 runtime 文件、metadata 类型与暴露字段确定稳定名称。
- 同一继承链中不存在图模式祖先或后代。

## 步骤

1. 在 `Scripts/Mixins` 下创建 Lua 文件，例如 `Doors/KeyDoor.lua`。
2. 从文件返回一个普通定义 table。可编辑默认值放在 table 上，行为放在方法中。
3. 在旁边创建 `KeyDoor_meta.lua`，并返回仅含一个 `KeyDoor` 类型的 `_METADATA`。
4. 创建或打开 Blueprint，其父类应提供 Mixin 使用的生命周期与原生成员。
5. 在继承链的第一个 Blueprint 上启用 **Script Mixin**。
6. 为 **Script Path** 选择 `Doors/KeyDoor.lua`。保存路径相对于 `Scripts/Mixins`。
7. 刷新或重新打开 Blueprint，编辑暴露字段，然后校验并保存。
8. 在地图上放置实例，并在运行中游戏验证行为。

## 文件对

```text
Scripts/
└── Mixins/
    └── Doors/
        ├── KeyDoor.lua
        └── KeyDoor_meta.lua
```

Metadata 文件是编辑器声明，不提供运行时方法。运行时文件是行为来源，不得加载其 metadata 伴生文件。

## 继承脚本

子 Blueprint 可以省略 `scriptPath` 以继承当前 Mixin。提供另一个路径时，兼容的子 Mixin 会合并到继承成员之上。替换脚本前，应检查字段/函数种类是否兼容，并移除不再属于已解析类的过期保存属性。

## 验证

- 放置两个具有不同覆盖值的实例，并运行所有生命周期/事件路径。
- 在 Console 中检查模块、保留名称或成员种类错误。

## 限制

Script Mixin 不能声明 `init`、metadata bases 或第二个 metadata 类型。

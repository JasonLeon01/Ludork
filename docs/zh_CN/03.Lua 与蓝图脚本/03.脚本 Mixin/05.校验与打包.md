# Script Mixin 校验与打包

## 目标

保存前校验挂载脚本及其 metadata，并证明打包游戏能够加载每个被引用 Mixin。

## 前置条件

- 已配置为 Script Mixin 模式的 Blueprint 继承链。
- `Scripts/Mixins` 下的 runtime/metadata 文件对。
- 包含每个受影响 Blueprint 的代表性地图。

## 步骤

1. 校验相对脚本路径与同名 metadata 文件。
2. 按报告顺序解决保存时 Blueprint 与字段诊断。
3. 在编辑器模式中运行所有生命周期/事件路径。
4. 使用预期 Lua 编译设置打包，并重复 runtime 检查。

## 路径校验

`scriptPath` 必须是 `Scripts/Mixins` 下非空、相对的 `.lua` 路径。路径使用正斜杠，不得包含空段、`.`、`..`、驱动器前缀、绝对根或 `_meta.lua` 后缀。

继承链中第一个 Script Mixin Blueprint 必须设置 `scriptPath`。子类可以继承该值或提供另一个有效路径。本地路径指向缺失文件时，校验失败。

## 保存时校验

保存前，编辑器检查：

- Blueprint 父类与模式继承链；
- 必需 `attrs` 与 graph 容器形状；
- 脚本路径与同名 metadata 文件；
- 单类型规则、有序字段、类型、默认值与空基类；
- 已解析继承字段与过期属性冲突。

应先解决第一个路径或 metadata 错误，再检查后续字段错误。

## 运行时验证

Metadata 校验不执行行为模块。请运行会创建该 Blueprint 的地图，并遍历每个生命周期与事件路径。模块加载、保留名、metatable 与成员种类违规会由运行时连同 Blueprint 类与脚本路径报告。

## 打包

Pack 会把项目 `Scripts` 树复制到 staging。**Use luac** 只编译 staging 中的 Lua 文件，不会改写项目源文件。发布前，应用每个已引用 Script Mixin Blueprint 至少运行一次打包结果，并确认 Console 没有模块解析错误。

## 预期结果

Blueprint 在没有路径或 metadata 错误的情况下保存；编辑器模式加载行为模块；无论是否启用 **Use luac**，发行包都解析相同 Mixin 路径。

## 验证

- 保存后重新打开每个已变更 Blueprint。
- 在 Console 可见时执行生命周期、继承与失败分支。
- 在 staging/output 而非源码树中检查 luac 结果。
- 从最终目录启动打包游戏。

## 限制

编辑器 metadata 校验不能证明所有父方法存在。打包会保留有效源码路径，但不能修复过期 Blueprint attribute。

# Sample Script Mixin

Sample 项目包含五个职责不同的 Mixin。 这些实现用于展示行为模式和验证 fixture。只有新的 Blueprint 父类与数据依赖一致时，才应复用其契约结构。

| 脚本 | 父类能力 | 行为 |
|---|---|---|
| `Consumables/Bottle.lua` | 可碰撞 Actor | 检测 Player、恢复 HP、播放已配置声音并销毁拾取物。 |
| `Consumables/Gem.lua` | 可碰撞 Actor | 向 Player 直接字段或匹配组件字段增加数值。 |
| `Doors/Door.lua` | `DoorBase` | 碰撞时开门，并防止重复开启。 |
| `Doors/KeyDoor.lua` | Script Mixin 门 Blueprint | 继续执行父碰撞方法前，要求并消耗已配置的 General Data 物品。 |
| `Doors/ConditionDoor.lua` | `DoorBase` | Tick 期间监视命名游戏变量，达到配置阈值时开门。 |

## 消耗品模式

`Bottle` 与 `Gem` 在处理碰撞前检查 `self:isDestroyed()`，从 Scene 中查找活动 Player，执行数据变更，调用继承碰撞行为，记录已销毁 Actor，并销毁拾取物。声音字段为空时，使用项目配置 fallback。

## 门模式

`Door` 实现公共碰撞方法。`KeyDoor` 仅在 `MeetPlayer`、物品数量与重入检查通过后调用该方法，然后移除钥匙。`ConditionDoor` 具有独立的 `onCreate`、`onTick` 和 `onDestroy` 生命周期工作，并使用门已有的 `openDoor` API。

## 限制

Sample ID、声音与 General Data 记录都属于具体项目。复制 Mixin 后仍需匹配 metadata、父类能力与 runtime 引用。

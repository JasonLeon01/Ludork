# 安装与管理插件

## 目标

使用发行版提供的官方插件，或引入、启用、检查、更新和卸载第三方源码插件，并明确区分插件程序文件与保留的可写数据。

## 前置条件

- 对必须独立保留的插件数据完成备份。

编辑器插件是可信代码，以编辑器进程权限运行且不受 sandbox 隔离。只能引入你信任的目录。

![插件完全信任确认](../../_images/plugins/trust-confirmation.png)

*只有用户确认所选源码将以编辑器进程权限运行后，引入流程才会继续。*

## 引入第三方插件

1. 关闭不应暴露给所选代码的工作，并检查插件源码、manifest 与来源。
2. 选择 **Plugins → Import Plugin**，选择完整源码目录，并接受信任确认。
3. 阅读引入结果；继续前先解决所有 manifest 或编译错误。
4. 重启 Ludork；引入的源码不会热加载。
5. 打开 **Plugins → Manage Plugins**，确认插件状态为 **Loaded**。

![Import Plugin 源码目录选择](../../_images/plugins/import-plugin.png)

*选择包含 `plugin.json` 的目录，不要选择单个源码文件或 build 输出。*

编辑器会验证目录和 manifest，在受管理插件根目录内创建安全 staging 副本，使用 Roslyn 动态编译副本并验证入口类型；成功后才移动到最终位置、写入注册表，并标记为下次重启生效。目标目录保留所选目录的名称；编译失败、重复 ID 和已存在的目标目录都会被拒绝。

目录根部必须包含 `plugin.json` 和至少一个参与编译的 `.cs` 文件。链接、reparse point、内嵌 `.data`、宿主共享 DLL、F#/VB 工程以及松散 XAML/Avalonia 源码都会在安装前被拒绝。C# 工程文件可以保留供 IDE 使用，但插件编译不执行工程文件；`bin`、`obj`、`.git` 和 `.vs` 下的 `.cs` 不参与编译。

仓库 checkout 生成的编辑器 build 会携带显式开发标记，并使用 `./Plugins` 作为插件根目录。Windows 发布版使用编辑器程序目录：源码位于 `<编辑器目录>/Plugins`，注册表位于 `<编辑器目录>/plugins.json`。macOS 发布版使用 `~/Ludork/Plugins`，注册表位于 `~/Ludork/plugins.json`。publish 输出即使位于 checkout 内也不带开发标记；Windows 不会回退到 `~/Ludork`，也不会与其合并。

Windows 编辑器目录必须保持可写，因为注册表更新和 `Plugins/.data` 都保存在该目录。per-user MSI 使用的 `%LocalAppData%\Ludork` 满足该要求；只读介质中的便携副本不支持插件管理或插件可写数据。

## 发行版官方插件

Official Blueprint AI、Official Locale Tools 与 Official Random Map 随编辑器一起发行。Windows 发行包把三个插件安装到程序目录的 `Plugins` 文件夹，并包含根据各插件 manifest 自动生成的 `plugins.json`。它们已经登记并启用，因此发行包安装这些插件时不会显示第三方插件的信任确认。

macOS DMG 不把插件嵌入 `Ludork.app`。Finder 中可见 `Ludork.app`、`Applications` 链接与 **Install Official Plugins**；安装器的 `.command` 扩展名和插件载荷会隐藏。先把应用拖到 Applications，保持 Ludork 关闭，再双击安装器。用户接受明确警告后，安装器会校验隐藏载荷，并以事务方式把 `~/Ludork/Plugins` 与 `~/Ludork/plugins.json` 作为一组整体替换。

不要把插件文件拖到 Applications。macOS 的这个操作会替换完整插件安装，不会合并。普通失败会回滚到原安装；如果连回滚也无法完成，应按安装器显示的恢复信息处理。成功后不会留下备份，并会删除全部现有第三方插件源码、登记和 `Plugins/.data`。选择 **Replace and Install** 前，请自行保留需要的内容。应用与安装器仍未经签名和公证。

## 重启与状态

导入时的动态编译用于阻止无效源码被登记；编辑器启动时会再次从已登记目录编译并加载插件。因为不支持热重载，引入、卸载或直接修改插件源码后都需要重启。**Plugins → Manage Plugins** 显示 Loaded、manifest 无效、编译失败、初始化失败及等待重启/删除状态，并提供诊断。

已注册插件会在下次启动时启用；不提供热启用/禁用开关，可把 **Loaded** 视为实际启用状态。

![Manage Plugins 状态与操作](../../_images/plugins/manage-plugins.png)

*替换或移除已安装源码前，先查看这里显示的状态与诊断。*

## 验证

- 在可丢弃项目中实际执行每项声明的命令或 hook。
- 更新后核对显示的插件版本，并重复 smoke test。
- 卸载后重启，确认插件入口已经消失；如需保留数据，也要确认其仍然存在。

## 数据与卸载

可写状态必须放在 `Plugins/.data/<插件 ID>`，插件通过 `PluginDataDirectory` 获得该路径。仓库 checkout 对应 `./Plugins/.data/<插件 ID>`；Windows 发布版对应 `<编辑器目录>/Plugins/.data/<插件 ID>`；macOS 发布版对应 `~/Ludork/Plugins/.data/<插件 ID>`。官方 Blueprint AI 使用对应根目录下的 `Plugins/.data/Ludork.OfficialBlueprintAI`。设置和历史必须通过 `PluginDataDirectory` 保存，不要写入插件源码目录。

卸载会取消注册，并可安排安全删除已安装插件文件。已加载程序集仍在使用时，目录可能保留到重启。仅取消注册的插件可通过重新选择插件根目录下现存的直接子目录恢复注册。两种卸载方式都会保留插件数据；删除数据必须是另一个显式操作。编辑器运行期间不要手改注册表。

## 限制

源码编译可引用 .NET runtime、`Ludork.Plugin.Abstractions`、`Ludork.Plugin.Avalonia` 与编辑器共享的 Avalonia 程序集；插件不能引用编辑器实现程序集。

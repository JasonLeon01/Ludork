# Official Locale Tools 演练

`Plugins/OfficialLocaleTools` 是普通菜单命令、文本提示 provider，以及复用 before-Run/before-Pack 操作逻辑的参考实现。它不注册地图项右键命令。

Official Locale Tools 已在 Windows 发行版中预置并登记。上述路径是仓库检出（checkout）中的对应源码目录；macOS 上需按[安装与管理插件](<01.安装与管理插件.md>)的说明运行 DMG 中的 **Install Official Plugins**。

## 注册

公开入口类型加载插件自己的 `locale.json`，构造一个 `LocaleTextHintProvider` 和一个共享 `LocaleExportHook`，然后注册：

- 在 Database（数据库）菜单注册一条 order 为 900 的命令，用于打开 `Data/Locale/Locale.xlsx`；
- 文本提示 provider；
- Run 前导出 hook；
- Pack 前复用同一个导出 hook。

复用 hook 可确保 Run 与 Pack 生成相同游戏语言文件。每次导出尝试后，它都会使自身缓存和编辑器文本提示失效。

工作簿保留在 `Data/Locale/Locale.xlsx`，生成的语言模块写入 `Scripts/Source/Locale`。Pack 时，hook 调用 `Packaging.ExcludeFile("Data/Locale/Locale.xlsx")`，因此发行包不会包含创作用的本地化工作簿。插件不参与 luac 转换；打包器会递归编译 `Scripts`。

## 菜单行为

菜单 handler 要求已打开项目，检查工作簿是否存在，并请求操作系统打开它。已处理警告/错误通过 `IPluginUserInterface` 显示。

## 语言分离

`Plugins/OfficialLocaleTools/locale.json` 使用 `EditorLanguage` 本地化插件自己的菜单与诊断；它不是游戏语言表。

作为结构示例：入口小而明确、显式注册、操作放入专用类、错误返回 `PluginResult`，并且不依赖编辑器实现类型。

## 限制

该插件只负责项目游戏文本导出。它不会本地化编辑器、提供通用的电子表格（spreadsheet）编辑器、注册 Random Map 功能或编译指定的 Lua 目录。

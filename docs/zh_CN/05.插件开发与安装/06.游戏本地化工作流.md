# 游戏本地化工作流

游戏本地化由 Official Locale Tools 负责，并与通用数据和存档数据刻意分开。

## 目标

只用一份工作簿编写文本，在 Run 与 Pack 之前导出结果一致的 Lua 语言表，并在游戏运行时解析出所选语言。

## 前置条件

- 项目包含 `Scripts/Source/Locale/Core.lua`，且 `Scripts/Entry.lua` 中有常规的语言初始化代码。
- 使用公式时，所用电子表格软件必须能保留公式的缓存计算结果。

## 步骤

1. 安装编辑器发行版。macOS 上还要运行 DMG 中的 **Install Official Plugins**。重启后确认 Official Locale Tools 状态为 **已加载**。
2. 在 Game 工作簿中添加一个 ID 和对应翻译。
3. 运行项目，确认导出消息。
4. 检查生成的 Lua 语言表。
5. 使用 `LOC("ID")`，或在需要格式解析的位置存放 `{ID}`。
6. 切换游戏语言，确认可见 UI 就地更新，隐藏 UI 在下次打开时使用新语言。
7. 打包，确认生成的语言表同样存在。

## 工作簿

创建 `Data/Locale/Locale.xlsx`。每个参与导出的工作表都以第 1 行作为表头。A 列必须是 `ID`（不区分大小写），B 列起是 `en_GB`、`zh_CN` 之类的语言名。语言表头为空会被忽略，并且至少需要一个语言列。

ID 为空的行会被忽略。ID 会去除首尾空白，并且区分大小写。多个工作表的内容会合并。ID 重复时会报告首次与重复出现的单元格位置；同一语言下，后出现的单元格值会覆盖先前的值。

公式单元格存在缓存值时使用缓存值。没有缓存值时，导出去掉开头等号的公式文本。字面量 `=` 或 `==` 可以写成 `'=` 或 `'==`。

## 导出

在 Run 与 Pack 之前，插件为每种语言写出一个 UTF-8 编码的 Lua 表：

```lua
return {
    ["TITLE_START"] = "Start",
    ["TITLE_EXIT"] = "Exit",
}
```

输出文件经由临时文件写入，并替换 `Scripts/Source/Locale/<language>.lua`。语言名不能为空，不能是根路径，也不能包含分隔符或非法文件名字符。工作簿缺失属于成功的跳过导出，工作簿格式错误则会使操作失败。

## 编辑器提示

字段去除首尾空白后的完整文本为 `{TITLE_START}` 时，可以获得提示。provider 从 `Scripts/Source/Locale` 中读取与 `EditorLanguage` 匹配的文件，找不到时回退到 `en_GB.lua`。含空格或嵌套花括号的标记无效。

## 运行时

`Scripts/Entry.lua` 先调用 `Source.Locale.Core.Init()` 加载语言表，再用 `Source.Configs.Main.LoadOrCreate()` 读取语言设置。只 require Core 不会加载语言表。使用方先把格式化函数绑定为局部 `LOC`：

```lua
local Locale = require("Source.Locale.Core")

local LOC = Locale.ApplyStringLocaleFormat

local buttonText = LOC("TITLE_START")
local tabLabels = Locale.ApplyListLocaleFormat({ "MENU_LOAD", "MENU_SAVE" })
local message = LOC(
    "{ITEM_NEW}: {ITEM_NAME}"
)
```

`ApplyStringLocaleFormat` 既能解析单独的语言键，也能解析字符串中的每个 `{ID}`。找不到的键保持原样；语言不可用时尽可能使用 `en_GB`。双写的 `{{` 和 `}}` 输出字面花括号。通用数据中的字符串不会自动翻译，显示时必须调用 `LOC`。

`Locale.ApplyListLocaleFormat(values: string[]): string[]` 按顺序对数组的每个元素应用 `ApplyStringLocaleFormat`，返回新数组且不修改输入。页签标签与选项列表都应使用它；语言变化需要刷新时再次调用。

`Locale.SetLanguage` 切换当前语言，并同步发布 `LocaleChanged`。配置窗口负责保存所选语言。订阅该事件的 UI 从原始语言键刷新文本，不会重置选中项、焦点或当前对话。

`Source.Configs.Main` 只在目标 `Main.ini` 不存在时写入默认配置。新文件的默认语言为 `en_GB`，只有当平台语言与支持列表完全匹配时才改用该语言。创建文件时已启用自由窗口模式的 HarmonyOS Mobile 平板会写入 Scale 默认值 `0`，其他宿主（包括 HarmonyOS 2in1）写入 `1`。启动时不会为补齐缺失的键而改写已有文件，也不会覆盖已经选择的语言。

Lua 编译与 **将 Assets、Data 和 Scripts 打包为 .ldpak** 这两项设置，都会把 Core 和生成的语言文件随其余 Scripts 目录树一起处理。Official Locale Tools 既不检查这两个选项，也不单独处理语言目录。

翻译改动导出后要重启游戏。[Lua 热更新](<../03.Lua 与蓝图脚本/01.Lua 运行时与模块.md#lua-热更新>)会保留已加载的语言表。

## 限制

工作簿属于项目创作源文件，不是运行时数据库，也不是存档格式。插件菜单的本地化独立于这些游戏语言表。

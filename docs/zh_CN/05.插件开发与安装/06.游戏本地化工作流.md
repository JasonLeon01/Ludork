# 游戏本地化工作流

游戏本地化由 Official Locale Tools 管理，独立于 General Data 和存档数据。

## 目标

用一份工作簿编写文本，在运行和打包前按固定规则导出 Lua 语言表，并在游戏中使用所选语言。

## 前置条件

- 项目包含 `Scripts/Source/Locale/Core.lua`，且 `Scripts/Entry.lua` 按标准流程初始化语言设置。
- 如果使用公式，所用的电子表格软件须能保留公式计算结果的缓存。

## 工作簿

创建 `Data/Locale/Locale.xlsx`。每个参与导出的工作表均以第 1 行为表头：A 列必须是 `ID`（不区分大小写），B 列起填写 `en_GB`、`zh_CN` 等语言名。表头为空的语言列会被忽略，且至少需要一个语言列。

ID 会去除首尾空白，并区分大小写；ID 为空的行会被忽略。多个工作表的内容会合并。ID 重复时会报告首次和重复出现的单元格位置；对于同一语言，后出现的有效单元格值会覆盖先前的值。

公式单元格优先使用缓存值；没有缓存时导出去掉开头等号后的公式文本。字面 `=` 或 `==` 可以写成 `'=` 或 `'==`。

## 导出

运行和打包前，插件为每种语言生成一个 UTF-8 编码的 Lua 表：

```lua
return {
    ["TITLE_START"] = "Start",
    ["TITLE_EXIT"] = "Exit",
}
```

输出先写入临时文件，再替换 `Scripts/Source/Locale/<language>.lua`。语言名不能为空、不能是根路径、不能包含分隔符或非法文件名字符。工作簿不存在时会成功跳过；格式错误会使操作失败。

## 编辑器提示

当字段去掉首尾空白后的完整文本为 `{TITLE_START}` 时，可显示翻译提示。提示内容来自 `Scripts/Source/Locale` 中与 `EditorLanguage` 匹配的文件，找不到时使用 `en_GB.lua`。占位符中不能包含空格或嵌套花括号。

## 运行时

`Scripts/Entry.lua` 先调用 `Source.Locale.Core.Init()` 加载语言表，再通过 `Source.Configs.Main.LoadOrCreate()` 读取语言设置。仅导入 Core 模块不会加载语言表。使用时，将格式化函数保存为局部变量 `LOC`：

```lua
local Locale = require("Source.Locale.Core")

local LOC = Locale.ApplyStringLocaleFormat

local buttonText = LOC("TITLE_START")
local message = LOC(
    "{ITEM_NEW}: {ITEM_NAME}"
)
```

`ApplyStringLocaleFormat` 可以解析单独的语言键，也可以替换字符串中的每个 `{ID}`。找不到的键保持原样；所选语言不可用时，优先使用 `en_GB`。双写 `{{` 和 `}}` 可显示花括号本身。General Data 中的字符串不会自动翻译，显示时需调用 `LOC`。

`Locale.SetLanguage` 切换当前语言并同步发布 `LocaleChanged` 事件。配置窗口会保存所选语言；订阅该事件的 UI 根据保留的语言键刷新文本，不会重置选中项、焦点或当前对话。

`Source.Configs.Main` 仅在目标 `Main.ini` 不存在时写入默认配置。新建文件默认使用 `en_GB`，并在平台语言精确匹配支持列表时改用该语言。HarmonyOS Mobile 平板在创建文件时若已启用自由多窗模式，会写入缩放默认值 `0`；其他宿主（包括 HarmonyOS 2in1）写入 `1`。已有文件在启动时不会因字段缺失而被回写，也不会覆盖已选择语言。

Lua 编译与**使用 .ldpak**会将 Core 和生成的语言文件随其余 Scripts 一起处理。Official Locale Tools 不读取这两个选项，也不单独处理语言目录。

修改翻译并导出后，需要重启游戏；[Lua 热更新](<../03.Lua 与蓝图脚本/01.Lua 运行时与模块.md#lua-热更新>)会保留已加载的语言表。

## 步骤

1. 安装编辑器发行版；macOS 还需运行 DMG 中的 **Install Official Plugins**。重启并确认 Official Locale Tools 状态为 **已加载**。
2. 在 Sample 工作簿中添加 ID 与翻译。
3. 运行项目并确认导出消息。
4. 检查生成的 Lua 语言表。
5. 使用 `LOC("ID")`，或在需要格式解析的位置保存 `{ID}`。
6. 切换游戏语言，确认可见界面立即更新，隐藏界面在下次打开时使用新语言。
7. 打包并确认生成的语言表已包含在包中。

## 限制

工作簿用于编写项目文本，不用于保存运行时数据或存档。插件菜单的翻译独立于游戏语言表。

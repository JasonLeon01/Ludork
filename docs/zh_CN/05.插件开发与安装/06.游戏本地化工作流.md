# 游戏本地化工作流

游戏本地化由 Official Locale Tools 管理，与 General Data 和存档数据明确分离。

## 目标

使用一份 workbook 创作文本，在 Run 与 Pack 前导出确定性的 Lua 语言表，并在玩法中解析所选语言。

## 前置条件

- 项目包含 `Scripts/Source/Locale/Core.lua`，且 `Scripts/Entry.lua` 使用正常 locale 初始化流程。
- 如果使用公式，需要 spreadsheet 应用能保留公式缓存值。

## Workbook

创建 `Data/Locale/Locale.xlsx`。每个参与导出的 worksheet 使用第 1 行作为表头；A 列必须是 `ID`（不区分大小写），B 列及以后是 `en_GB`、`zh_CN` 等语言名。空语言表头会忽略，并且至少需要一个语言列。

空 ID 行会忽略。ID 会 trim，且区分大小写。多个 worksheet 会合并。重复 ID 会报告首次与重复单元格位置；同一语言后出现且实际存在的单元格值会覆盖先前值。

公式单元格优先使用缓存值；没有缓存时导出去掉开头等号后的公式文本。字面 `=` 或 `==` 可以写成 `'=` 或 `'==`。

## 导出

Run 与 Pack 前，插件为每种语言写一个 UTF-8 Lua table：

```lua
return {
    ["TITLE_START"] = "Start",
    ["TITLE_EXIT"] = "Exit",
}
```

输出先写临时文件，再替换 `Scripts/Source/Locale/<language>.lua`。语言名不能为空、不能是根路径、不能包含分隔符或非法文件名字符。workbook 不存在会成功跳过；格式错误会使操作失败。

## 编辑器提示

字段完整 trim 文本为 `{TITLE_START}` 时可获得提示。provider 从 `Scripts/Source/Locale` 读取匹配 `EditorLanguage` 的文件，并 fallback 到 `en_GB.lua`。包含空格或嵌套花括号的 token 无效。

## Runtime

项目自带的 `Scripts/Source/Locale/Core.lua` 会 require 同目录下的全部语言模块并导出本地化函数。`Scripts/Entry.lua` require Core 并选择语言；每个使用方直接从 `ApplyStringLocaleFormat` 绑定自己的局部 `LOC`。目录内没有语言模块或 key 不存在时，`LOC("KEY")` 直接返回原 key；所选语言不可用时尽可能 fallback 到 `en_GB`。

```lua
local LOC = require("Source.Locale.Core").ApplyStringLocaleFormat

local buttonText = LOC("TITLE_START")
local message = LOC(
    "{ITEM_NEW}: {ITEM_NAME}"
)
```

`ApplyStringLocaleFormat` 既可解析裸 locale key，也会把字符串内每个 `{ID}` 替换为当前语言表的值。未知 key 保持原样；双写 `{{` 和 `}}` 会产生字面花括号。`Locale.setLanguage` 会切换当前语言表并同步发布 `LocaleChanged`。默认 Config 窗口保存所选语言，订阅该事件的 UI owner 会使用保留的 locale source 原位重新解析，且不重置选择、焦点或活动对话状态。General Data string 应用到 runtime object 时保持原值；展示 owner 在渲染花括号值时调用 `LOC`。

`Source.Config.Main` 仅在目标 `Main.ini` 不存在时写入完整默认配置。新建文件默认使用 `en_GB`，并在平台语言精确匹配支持列表时改用该语言；已有文件只读取，启动流程不会补写缺失字段或覆盖已选择的语言。

启用 Lua 编译打包时，打包器会递归处理整个 `Scripts`，因此 Core 与插件生成的语言文件会一起转换为 luac；Official Locale Tools 不读取打包选项，也不单独编译语言目录。

## 步骤

1. 安装编辑器发行版；macOS 还需运行 DMG 中的 **Install Official Plugins**。重启并确认 Official Locale Tools 状态为 **Loaded**。
2. 在 Sample workbook 中添加 ID 与翻译。
3. 运行项目并确认导出消息。
4. 检查生成 Lua table。
5. 使用 `LOC("ID")`，或在需要格式解析的位置保存 `{ID}`。
6. 修改游戏语言，确认可见 UI 原位更新，隐藏 UI 在下次打开时使用新语言。
7. 打包并确认相同生成语言表存在。

## 验证

测试受支持语言、不受支持的平台语言、缺失 `en_GB`、缺失 key、嵌入式格式化、双花括号、API 即时切换、选择/焦点/对话状态保持，以及打包后的语言文件。

## 限制

Workbook 是项目创作源，不是 runtime 数据库或存档格式。插件菜单本地化与这些游戏语言表互相独立。

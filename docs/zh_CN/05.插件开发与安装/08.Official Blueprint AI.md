# Official Blueprint AI

## 目标

使用随 Ludork 发行的官方源码插件，安全配置 provider，并通过编辑器的审查边界应用一份经过校验的单蓝图提案。

插件 ID 为 `Ludork.OfficialBlueprintAI`，在仓库中固定位于 `Plugins/OfficialBlueprintAI`。重启后，编辑器会再次编译已安装的源码，并通过 **游戏 → Blueprint AI** 暴露该插件。

## 工作流

1. 按当前环境安装插件，见下文“目录与职责”。
2. 打开项目，选择 **游戏 → Blueprint AI**。
3. 在 **Blueprint AI 设置** 中配置 provider、模型、endpoint 与密钥。
4. 为一个已有蓝图新建会话，检查暂存的提案与生成的差异。
5. 只有校验成功后才能选择 **应用**；改动准备写入磁盘时，再执行普通的项目保存命令。

## 目录与职责

| 环境 | 程序或源码位置 | 可写数据位置 |
|---|---|---|
| 仓库检出 | `./Plugins/OfficialBlueprintAI` 源码；引入的目录按所选名称直接复制到 `./Plugins` 下 | `./Plugins/.data/Ludork.OfficialBlueprintAI` |
| Windows 发布版 | `<安装根目录>/Plugins/OfficialBlueprintAI` | `<安装根目录>/Plugins/.data/Ludork.OfficialBlueprintAI` |
| macOS 发布版 | 由 DMG 的隐藏载荷安装到 `~/Ludork/Plugins/OfficialBlueprintAI` | `~/Ludork/Plugins/.data/Ludork.OfficialBlueprintAI` |

Windows 上，`<安装根目录>` 是根 `Ludork.exe` 启动器所在目录，编辑器本体位于其 `Binaries` 子目录。

macOS DMG 安装器以事务方式把现有 `~/Ludork/Plugins` 与 `~/Ludork/plugins.json` 作为一个完整集合替换。普通失败会回滚到上一个集合；一旦成功，就会删除现有第三方插件源码、注册记录以及 `Plugins/.data` 下的全部数据。整个过程既不合并，也不保留备份，因此确认前先留存需要的文件。

菜单命令、Avalonia 窗口、设置界面、本地化、provider 客户端与会话历史都由插件自己负责，编辑器不包含 Blueprint AI 窗口。编辑器只为插件窗口提供一个可选的 `IAvaloniaPluginUserInterface` 所有者，并在项目打开期间提供受限的 `IBlueprintAssistantHost` 桥。该桥创建的会话固定绑定一个蓝图，并暴露本工作流需要的读取、提案、校验、应用与放弃能力。

删除插件源码目录不会删除 `Plugins/.data/Ludork.OfficialBlueprintAI`。删除设置或历史属于另一个显式操作。

## 范围与权限

每个会话绑定一个项目和一个已有蓝图。助手可以查看其他蓝图、Lua metadata 以及白名单内的 Lua/C/C++ 源码文件，以理解可用 API。它不能创建、重命名或删除蓝图，不能一次修改多个蓝图，不能编写源码，不能运行 shell，也不能启动进程。

模型只能暂存一份蓝图提案。编辑器校验候选内容并显示生成的差异。用户选择 **应用** 之前不会有任何改动。应用时会重新读取编辑器的工作副本，并把它的 revision 与提案基准比较。应用成功只产生一个普通 Undo 步骤，项目保持脏状态，并刷新该蓝图所有已打开的编辑器。只有执行普通的项目保存操作，蓝图才会写入磁盘。

插件是进程内的可信代码，不是操作系统沙箱。上述限制由官方助手面向模型的能力面，以及编辑器的会话边界与 Apply 边界共同保证。

## Provider 设置与凭据

在 Blueprint AI 窗口中打开 **Blueprint AI 设置**，选择 provider、模型与 endpoint。OpenAI 使用 Responses API。DeepSeek、Google OpenAI-compatible 与 Custom profile 使用 OpenAI-compatible Chat endpoint。模型与 endpoint 字段始终可编辑，因此不必为每次模型发布更新插件。

endpoint 必须是绝对 HTTPS URL。纯 HTTP 只允许本地开发使用的 loopback 地址。endpoint URL 中不接受凭据、query 字符串或 fragment。

API key 不会写入 `settings.json`。在 Windows 上它们存放在凭据管理器（Credential Manager），在 macOS 上存放在 Keychain。其他平台读取按插件隔离的环境变量，不持久化密钥。设置窗口把已保存的 key 显示为前三个字符、一段固定掩码和最后三个字符。较短的 key 完全隐藏。只有输入新值或明确选择移除时，凭据才会变化。provider 是否可用由外部决定，与 Ludork 无关。

## 本地会话与 provider 状态

插件数据目录下的本地索引与只追加 JSONL 记录是会话历史的权威数据。它们保存消息、模型快照、精简的工具活动与提案决定，从不保存 API key，也不保存完整的源码读取内容。

OpenAI Responses 请求使用 `store:false`，插件不依赖 provider 端的会话存储。会话较长时，下一次 provider 请求只放入滚动摘要与最近的消息。这种请求上下文压缩不会删除或替换完整的本地历史。

未完成的请求会被记录为 interrupted。它已完成的本地记录在重启后仍可查看，但进行中的请求不会自动续传。

## 安全读取代码

项目搜索与文件读取只接受项目相对路径，且这些路径必须位于所配置的运行时与 API 源码根目录之下，扩展名也必须在支持列表内。构建输出、日志、版本控制数据、INI 文件、插件数据、凭据以及项目之外的路径都会被拒绝。文件内容按数据处理，不能当作扩大助手权限的指令。

## 故障排查

- **游戏菜单中没有 Blueprint AI：** 确认 Windows 预装插件已经就位，或 macOS DMG 安装器已经完成，然后重启编辑器，并在 **插件 → 插件管理** 中检查等待重启、manifest、依赖或初始化方面的诊断。插件未安装时不提供菜单项，这是预期行为。
- **没有项目或蓝图可用：** 先打开项目。项目窗口之外不提供宿主桥。项目还必须至少包含一个已有蓝图。打开插件不会自动选择目标，只有选择 **新会话** 后才会出现目标选择器。
- **目标被重命名或删除：** 旧会话仍可读取，但目标无法静默切换。为已有蓝图新建会话。
- **API key 缺失或服务器返回 401：** 在设置中更换 key，并确认它属于所选 provider 或 profile。同时检查 endpoint，以及 OpenAI organization 或 project 取值。界面只显示掩码值，从不显示完整的已存 key。
- **连接或 endpoint 错误：** 使用不含内嵌凭据、query 或 fragment 的绝对 HTTPS 基础地址。检查 DNS、代理、防火墙与 TLS 设置。纯 HTTP 有意限制为 loopback 开发地址。
- **应用时报告 revision 冲突：** 提案记录基准 revision 之后蓝图发生了变化，编辑器会拒绝覆盖。放弃该提案，检查当前蓝图，然后新建会话或重新发起请求。
- **历史显示 interrupted：** 编辑器、窗口或请求在完成前被停止。本地历史仍然是权威数据。准备好后发送新请求，不要指望上一次网络流自动恢复。

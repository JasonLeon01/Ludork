# Official Resource Cleanup

## 目标

检查未发现静态引用的项目资源，保护通过动态路径加载的资源，并把确认后的候选移到操作系统回收站或垃圾篓。

## 前置条件

- 随编辑器官方插件安装 Official Resource Cleanup。仓库源码位于 `Plugins/OfficialResourceCleanup`。
- 打开项目，停止游戏，并在扫描前保存当前改动。

## 操作步骤

1. 选择 **插件 → 资源清理**。窗口分别显示内置固定保留清单和当前项目的追加保留路径。
2. 查看内置清单。`NativeResources.list` 随插件分发，保护 C++ 直接使用的资源，包括 shader、UI 默认资源、文本配置和曲线；同时保留发行所需的标准应用图标及随附资源许可证。窗口中的这些条目只读。
3. 把动态 Lua 路径需要的文件或目录加入追加保留清单，每行一个项目相对路径，例如 `Assets/Characters/Dynamic` 或 `Data/Animations/GeneratedEffect.json`。目录会保护其全部内容。静态扫描无法识别字符串拼接或运行时计算的路径，必须自行补充。
4. 点击 **扫描**。扫描在后台运行，显示阶段、进度和当前路径。点击 **取消** 会停止操作，不会开始清理。
5. 查看 **Data** 和 **Assets** 两个页签。候选显示完整的项目相对路径与体积，页签显示文件数量和总体积。候选表示在受支持的静态规则下未发现引用，不代表已经证明运行时不会使用它。
6. 如需保留候选，选中条目后点击 **保留选中项并重扫**，或编辑清单后重新扫描。修改保留清单会使原报告失效。存在扫描问题时，必须先处理问题，才能执行回收。
7. 点击 **移到回收站／垃圾篓**，核对最终文件数量和总体积后确认。操作会处理当前报告中的全部候选。宿主先检查报告是否仍与当前项目文件一致，再移动文件。
8. 查看已回收条目、发生的错误与未处理文件。取消或失败会停止后续处理，已经移走的文件仍在系统回收站／垃圾篓中。再次清理前必须重新扫描。

追加保留路径由宿主保存在当前项目的 `EditorCache/ResourceCleanupKeep.list`，扫描、保存清单或关闭窗口时写入。初始列表为空时，仅打开窗口不会创建该文件。清空追加项后保存会移除文件。内置固定条目不会混入这个文件。保存失败时，窗口保持打开并显示错误。

## 扫描范围

扫描覆盖所有普通地图、世界子地图、Lua 源码与受支持的 Data 结构引用。先沿 Data 引用关系计算保留内容，再判断哪些 Assets 仍被使用。无人引用的 Data 不会继续保活它自己的资源依赖。蓝图字段及地图实例覆盖值会按元数据递归扫描，包括组件和有类型的容器内部的资源引用。

地图、`Data/General`、`Data/UI`、`Data/Configs` 和 `Data/Locale` 固定保留，它们通过受支持规则引用的内容也会保留。Data 候选只包括 Tilesets、AutoTiles、Blueprints、CommonFunctions、Animations、Particles、Curves 和 TextConfigs。未知 Data 格式不进入清理候选。Lua 只用于扫描引用，不会被删除。生成的 UI 镜像和声明 stub 不作为独立的使用依据。

已知资源 API 的参数支持字符串常量、括号、常量别名和 `and`/`or` 条件分支。扫描器保守保留所有分支中的常量路径，并继续追踪其 Data 依赖。

此功能只做静态分析，不执行 Lua、不记录游玩轨迹，也不推断运行时拼接出的值。这些资源需要通过保留清单明确保护。即使扫描没有报错，也应检查结果后再确认。

## 回收与编辑器状态

受支持的 Windows 和 macOS 编辑器使用系统回收站或垃圾篓。回收位置不可用、卷不支持回收或移动失败时，不会退回永久删除。恢复文件请使用操作系统，再重新打开项目以载入恢复内容。

成功回收的 Data 会从编辑器托管文档和资源列表中移除，之后保存不会重新生成这些文件。编辑器撤销不会恢复已回收的文件。回收后的报告不能重复使用，项目输入发生变化时也必须重新扫描。

## 插件契约

插件注册一个普通菜单命令，并拥有自己的 Avalonia 窗口、内置清单和翻译。`PluginMenuContext.ResourceCleanupHost` 提供受限的 `IResourceCleanupHost` 边界：读取和保存追加保留项、带进度与取消的扫描，以及凭返回的报告 ID 回收资源。不暴露可变编辑器文档或任意文件删除能力。

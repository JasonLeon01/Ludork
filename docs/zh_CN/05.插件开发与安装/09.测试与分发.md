# 测试与分发

## 目标

准备一个源码插件目录，使其他 Ludork 1.0.0 用户无需依赖作者 build tree，即可检查、引入、重启并验证。

## 前置条件

- 有效 manifest，包含全局唯一 ID，且 `minimumEditorVersion` 至少为 `1.0.0`。
- 能通过 **Import Plugin** 编译的源码。
- 插件许可，以及所有再分发第三方组件或资产的声明。

## 步骤

1. 从分发目录移除 build 输出、本地设置、密钥、凭据、测试项目与 `.data`。
2. 保留 `plugin.json`、所有必需 `.cs` 文件、插件自有资源、许可文件和简明的安装/重启说明。
3. 使用 .NET 9 构建可选 IDE 工程。这可以发现普通编译诊断，但不能替代宿主编译。
4. 把干净目录引入新的开发版编辑器，重启并检查 **Manage Plugins**。
5. 在 `en_GB` 与 `zh_CN` 下测试每个已注册命令、文本 provider 与操作 hook；覆盖未打开项目、取消、无效输入和已处理失败路径。
6. 对 before-Run 与 before-Pack hook，测试顺序、失败阻断和输出。只在 Pack 时读取 `Packaging`，并在最终发行包中核对每个编译目录与排除文件。
7. 对地图或 Blueprint bridge，强制制造 revision conflict，确认插件拒绝覆盖更新的编辑器状态。
8. 把同一目录引入干净的正式发行编辑器，并重复面向用户的 smoke test。
9. 归档完全相同的源码目录，并发布 checksum、版本历史、支持的编辑器范围、许可与支持联系方式。

## 预期结果

接收者可以检查完整源码，在没有 manifest 或编译诊断的情况下完成引入，重启一次后看到 **Loaded**，并复现文档描述的行为。归档不含作者凭据或开发机专用路径。

## 验证

- 比较归档内容与已安装源码目录。
- 确认 `plugin.json` ID、version 与 `entryType` 匹配代码。
- 搜索归档中的 token、password、私有 URL、用户路径与生成的 `.data`。
- 检查最终 Run/Pack 输出，不要只假设 hook 改动了正确文件。
- 卸载并重启，验证文档描述的程序文件与保留数据行为。

## 限制

Ludork 不提供插件 marketplace、签名机构、依赖解析器、NuGet restore 或预构建二进制插件格式。分发信任、发行签名、更新通知和第三方法律合规均由发布者负责。

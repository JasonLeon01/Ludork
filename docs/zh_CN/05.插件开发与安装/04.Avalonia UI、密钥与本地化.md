# Avalonia UI、密钥与本地化

## 目标

打开插件自带的 Avalonia 窗口，通过宿主凭据服务保存密钥，并按当前编辑器语言显示文本，同时不依赖编辑器实现类型。

## 前置条件

- 有效源码插件，引用 `Ludork.Plugin.Avalonia` 与宿主共享 Avalonia 程序集。
- 已注册菜单命令或地图项右键命令。
- 插件目录内包含自身的本地化字符串资源。

## 步骤

### 1. 获取真实 Owner

```csharp
if (context.UserInterface is not IAvaloniaPluginUserInterface avaloniaUi)
{
    return PluginResult.Failed("Avalonia UI is unavailable.");
}

MyPluginWindow window = new();
await window.ShowDialog(avaloniaUi.Owner);
return PluginResult.Completed();
```

适用时把 `WindowStartupLocation` 设为 `CenterOwner`。插件拥有窗口、控件、view state、cancellation，以及图片等资源的释放职责。不得通过 `Application.Current` 搜索编辑器窗口，也不得向编辑器拥有的 view 注入控件。

### 2. 分离程序与数据路径

`PluginDirectory` 保存引入的程序内容，必须按只读目录处理。设置、缓存与历史应写入 `PluginDataDirectory`。不得从当前工作目录推导任何一条路径。

### 3. 保存密钥

使用命令 context 中按插件隔离的 `SecretStore`：

```csharp
await context.SecretStore.WriteAsync(
    "api-key",
    apiKey,
    context.CancellationToken);
string? stored = await context.SecretStore.ReadAsync(
    "api-key",
    context.CancellationToken);
```

`ContainsAsync`、`ReadAsync`、`WriteAsync` 与 `DeleteAsync` 使用宿主提供的操作系统凭据服务。不得把返回的密钥复制到普通设置、诊断、URL 或会话日志。逻辑 key 应保持稳定，并且只用于一个明确目的。

### 4. 本地化插件 UI

注册时读取 `IPluginRegistrar.EditorLanguage`，加载匹配的插件资源，并提供明确 fallback，例如 `en_GB`。注册时，`PluginMenuCommand.Label` 与 `PluginMapContextMenuCommand.Label` 必须已经本地化。窗口标题、按钮、校验与诊断都由插件自行本地化；宿主不会翻译插件字符串。

游戏本地化是另一套数据工作流。不得把插件自身的 locale 资源当成项目 runtime 文本目录。

## 预期结果

窗口正确从属于编辑器窗口，可写文件保存在 data 目录，密钥留在凭据存储中，并且所有插件可见文本都遵循启动前选择的编辑器语言。

## 验证

- 如果命令支持两种 context，应分别在打开和未打开项目时执行。
- 关闭窗口，确认 cancellation 与 disposable 资源均被释放。
- 重启 Ludork，分别验证设置与密钥。
- 在 `en_GB` 与 `zh_CN` 间切换并重启，检查所有插件拥有的界面。
- 卸载插件，确认保留数据按文档约定处理。

## 限制

`IAvaloniaPluginUserInterface` 只暴露 owner window，不暴露编辑器控件、服务或样式。源码插件引入器不接受松散 XAML 源码。宿主不支持对已经加载的插件实时切换语言。

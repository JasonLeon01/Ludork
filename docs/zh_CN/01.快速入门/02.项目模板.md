# 项目模板

## 目标

根据项目对原生代码、视频与目标平台的需求选择模板。

## 模板参考

模板决定项目基线；之后更换模板属于源码与资产管理任务，不是编辑器开关。

| 模板 | 原生源码 | 普通 Run 是否需要编译器 | 适用场景 |
|---|---:|---:|---|
| Standalone | 无 | 否 | 使用随附运行时编辑 Lua、Blueprint、数据与资产。 |
| C++ Source | 有 | 是 | 修改原生服务、绑定，或构建 iOS/HarmonyOS/Android 目标。 |
| Standalone + FFmpeg | 无 | 否 | 预构建运行时必须支持视频播放。 |
| C++ Source + FFmpeg | 有 | 是 | 同时需要原生开发与视频播放。 |

## FFmpeg 选项

FFmpeg 会增加构建体积、第三方许可义务与平台准备步骤，只有项目使用视频时才应启用。Windows 与 macOS 的 FFmpeg 构建使用共享库或动态库；iOS、HarmonyOS 与 Android 的 C++ Source + FFmpeg 路径通过 `Sample/cmake/FFmpeg` 构建静态 `.a` 库。下游发行者分发其中任一静态链接应用时，都必须满足适用的 LGPL 重链接材料要求；发行前请查阅 `Licenses/FFmpeg/README.md`。在 macOS 上，选中 FFmpeg 后新建项目窗口会显示额外的兼容性提示。

## 打包目标

- Windows 10 或更高版本的 x64 编辑器提供 Windows x64 目标。
- macOS 13.3 或更高版本的 Apple Silicon 编辑器提供 macOS arm64 与 iOS arm64 目标；安装对应 IDE 后显示 HarmonyOS Mobile/2in1 arm64-v8a 与 Android arm64-v8a 目标。
- 不提供 Standalone iOS 模板。所有 iOS 输出都需要 C++ Source 项目、Xcode、开发团队、Bundle 设置与签名资源。
- 不提供 Standalone HarmonyOS 模板。HarmonyOS 输出需要 C++ Source 项目，以及包含 OpenHarmony native SDK 的 DevEco Studio。所有 HAP 均面向 API 22：Mobile 使用 OpenGL ES，2in1 默认使用 OpenGL，也可选择 OpenGL ES。
- 不提供 Standalone Android 模板。Android 输出需要 C++ Source 项目、Android Studio、SDK Platform 36、Build Tools 36.0.0、NDK r27 或更高版本，以及本机 CMake 3.28 或更高版本。它面向 API 24 或更高版本并默认生成未签名 APK；也可勾选**签名 APK**，使用已有 JKS 或 PKCS12 keystore 完成签名。两种模式都不会安装或启动 APK。
- **Use luac**、Shader 加密与数据加密属于打包选项，不是模板类型。

四种模板都包含完整 `Scripts/stub/**/*.d.lua` 声明目录，供编辑器与 Lua 语言工具使用。这些文件只属于开发资产：打包会删除整个 `Scripts/stub`，Lua 编译会忽略 `.d.lua`，游戏发行包不携带任何声明文件。

`Sample` 单独保留 Ludork 许可证，以及包含原生运行时、可选 FFmpeg 与随包资产材料的游戏运行时法律材料集。编辑器、托管运行时、预览宿主与构建工具声明只保留在编辑器发行包中。生成模板时会把 Sample 法律材料集刷新到每个 C++ Source 模板，再由其派生 Standalone 变体。打包会保留已有材料，但不会把它们设为技术前置条件；最终发行法律材料是否完整仍由发行者负责。

## 决策检查

如果所有计划内功能都能通过可用的 Lua、Blueprint、资产和数据 API 实现，请使用 Standalone。只要有一项需求必须修改原生代码，就应使用 C++ Source，并确保开发主机提供目标所需的编译器、SDK 与签名资源。只有明确需要视频播放时才加入 FFmpeg。

# 项目模板

## 目标

根据项目对原生代码、视频播放与目标平台的要求，选出合适的模板。

## 模板参考

新建项目窗口提供两张模板卡片 **Standalone** 与 **C++ Source**，以及一个独立的 **启用视频播放（FFmpeg）** 开关。

| 模板 | 原生源码 | 常规运行是否需要编译器 | 适用场景 |
|---|---|---|---|
| Standalone | 无 | 否 | 用随附的运行时编写 Lua、蓝图、数据与资产。 |
| C++ Source | 有 | 是 | 修改原生服务、绑定，或构建 iOS、HarmonyOS、Android 目标。 |

卡片与开关的每种组合都有自己的生成模板目录：`Standalone`、`Cpp`、`Standalone-ffmpeg` 与 `Cpp-ffmpeg`。模板决定项目的基线。事后更换模板属于源码管理工作，编辑器里没有对应的开关。

C++ Source 模板在项目根目录附带 `.clang-format`，用于格式化原生源码，并且要先完成一次构建，才会生成预览二进制与元数据。Standalone 模板把预览运行时放进 `Binaries`，元数据放在 `Temp/UiPreview.json` 与 `Temp/UiPreview.registry.json`。

## FFmpeg 选项

**启用视频播放（FFmpeg）** 为所选模板加入本地 MOV 与 MP4 播放能力，同时增大构建体积。随附的构建启用了 FFmpeg 的 file 协议、MOV/MP4 demuxer、H.264 与 AAC 解码器及 parser、libswscale 与 libswresample，不提供网络协议，不提供硬件加速，也不提供其他编解码器。

平台准备工作也因平台而异：Windows 与 macOS 使用 FFmpeg 动态库，iOS、HarmonyOS 与 Android 使用静态库。发行要求（包括静态构建所需的 LGPL 重链接材料）见 `Licenses/FFmpeg/README.md`。在 macOS 上选择 FFmpeg 还会显示兼容性提示。

## 模板目标

- 没有 Standalone 版 iOS 模板。任何 iOS 产物都要求 C++ Source 项目、Xcode、开发团队、Bundle 设置与签名资源。
- 没有 Standalone 版 HarmonyOS 模板。产出 HarmonyOS 版本要求 C++ Source 项目，以及带 OpenHarmony native SDK 的 DevEco Studio。所有 HAP 都以 API 22 为目标。Mobile 使用 OpenGL ES，2in1 默认使用 OpenGL，也可以改选 OpenGL ES。
- 没有 Standalone 版 Android 模板。产出 Android 版本要求 C++ Source 项目、Android Studio、SDK Platform 36、Build Tools 36.0.0、NDK r27 或更高版本，以及本机 CMake 3.28 或更高版本。APK 声明的最低版本为 API 24（Android 7.0），因此可安装在 Android 7.0 及更高版本上。编译级别与目标级别同为 API 36。默认打包结果为未签名 APK，勾选 **签名 APK** 后可用已有的 JKS 或 PKCS12 keystore 为它签名。两种模式都不会安装或启动 APK。
- 脚本编译、Shader 加密、数据加密、存档加密，以及 **将 Assets、Data 和 Scripts 打包为 .ldpak** 都属于打包选项，不是模板类型。完整的选项行为见[运行、调试与打包](<../02.编辑器用户指南/08.运行、调试与打包.md>)。

四种模板都包含完整的 `Scripts/stub/**/*.d.lua` 声明目录，供编辑器与 Lua 语言工具使用。这些文件属于开发期资产：打包时会删除整个 `Scripts/stub` 目录，Lua 编译会忽略 `.d.lua`，游戏发行包中不会附带任何声明文件。

顶层 `Licenses` 是许可证文本的唯一来源。生成模板时，先把公共的运行时材料复制进每个 C++ Source 模板，再由此派生 Standalone；只有 FFmpeg 变体才会得到 `Licenses/FFmpeg`。编辑器与工具的声明留在编辑器发行包内，资产声明留在对应资产旁边。打包会保留现有的许可证文本，但不强制要求它们存在，因此法律材料是否完整仍由发行者负责。

## 选择要点

计划中的全部功能都能用现有的 Lua、蓝图、资产与数据 API 实现时，就选 Standalone。只要有一项必需功能要改动原生代码，就应选 C++ Source；它的各个目标还要求开发主机具备对应的编译器、SDK 与签名资源。只有视频播放是明确需求时，才加入 FFmpeg。

# 项目模板

## 目标

根据项目对原生代码、视频与目标平台的需求，选择合适的模板。

## 模板参考

模板决定了项目的基础形态；事后要更换模板，属于源码与资产管理层面的工作，编辑器里没有可切换的开关。

| 模板 | 原生源码 | 常规运行是否需要编译器 | 适用场景 |
|---|---:|---:|---|
| Standalone | 无 | 否 | 使用随附运行时编辑 Lua、Blueprint、数据与资产。 |
| C++ Source | 有 | 是 | 需要修改原生服务或绑定，或构建 iOS/HarmonyOS/Android 目标。 |
| Standalone + FFmpeg | 无 | 否 | 要求随附的预构建运行时支持视频播放。 |
| C++ Source + FFmpeg | 有 | 是 | 同时需要原生开发与视频播放。 |

## FFmpeg 选项

启用 FFmpeg 会增大构建体积、带来第三方许可义务，并增加平台准备步骤，因此只在项目确实使用视频时才应开启。Windows 与 macOS 上，FFmpeg 以共享库或动态库的形式提供；iOS、HarmonyOS 与 Android 的 C++ Source + FFmpeg 则通过 `Sample/cmake/FFmpeg` 构建静态 `.a` 库。要把这类静态链接应用分发给他人时，你需要满足适用的 LGPL 重链接材料要求，发行前请查阅 `Licenses/FFmpeg/README.md`。另外在 macOS 上，勾选 FFmpeg 后，新建项目窗口会额外显示一条兼容性提示。

## 打包目标

- 运行于 Windows 10 或更高版本（x64）的编辑器，提供 Windows x64 打包目标。
- Apple Silicon Mac（macOS 13.3 或更高版本）上的编辑器提供 macOS arm64 与 iOS arm64 目标；安装对应的 IDE 后，还会出现 HarmonyOS Mobile/2in1 arm64-v8a 与 Android arm64-v8a 目标。
- 不存在 Standalone iOS 模板。所有 iOS 产物都要求 C++ Source 项目、Xcode、开发团队、Bundle 设置与签名资源。
- 不存在 Standalone HarmonyOS 模板。HarmonyOS 产物需要 C++ Source 项目，以及带 OpenHarmony native SDK 的 DevEco Studio。所有 HAP 都以 API 22 为目标：Mobile 使用 OpenGL ES；2in1 默认使用 OpenGL，也可以改用 OpenGL ES。
- 不存在 Standalone Android 模板。Android 产物需要 C++ Source 项目、Android Studio、SDK Platform 36、Build Tools 36.0.0、NDK r27 或更高版本，以及本机安装的 CMake 3.28 或更高版本。产物面向 API 24 或更高版本，默认生成未签名 APK；也可以勾选 **签名 APK**，用已有的 JKS 或 PKCS12 keystore 完成签名。两种模式都不会安装或启动 APK。
- **Use luac**、Shader 加密、数据加密与 `.ldpak` 资源打包都属于打包选项，而不是模板类型。

四种模板都带有完整的 `Scripts/stub/**/*.d.lua` 声明目录，供编辑器与 Lua 语言工具使用。这些文件只是开发期资产：打包时会删除整个 `Scripts/stub` 目录，Lua 编译会忽略 `.d.lua` 文件，因此游戏发行包不会包含任何声明文件。

根目录的 `Licenses` 是许可证文本的唯一来源。生成模板时，会先把公共的运行时材料复制到各个 C++ Source 模板，再从中派生 Standalone；只有 FFmpeg 变体带 `Licenses/FFmpeg`。编辑器与工具的声明随编辑器发行包分发，资产声明则放在对应资产旁边。打包会保留已有的许可证文本，但不会强制要求它们必须存在——保证法律材料完整仍是发行者的责任。

## 选择要点

如果计划内的功能都能通过现有的 Lua、Blueprint、资产与数据 API 实现，就选 Standalone。只要有一项需求必须改动原生代码，就应选 C++ Source，并确保开发主机备有所需的编译器、SDK 与签名资源。只有明确需要视频播放时，才考虑加入 FFmpeg。

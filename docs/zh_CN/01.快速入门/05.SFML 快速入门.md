# SFML 快速入门

SFML 是 Ludork 运行时底层的多媒体库，提供图形、音频、窗口与输入能力。项目里的位置、尺寸、颜色和矩形也用它的值类型表示。

Ludork 通过 LuaSF 内嵌 SFML，由它注册全局的 `sf` 表。任何项目脚本都能直接使用，无需 `require`。

本仓库内置的是 **SFML 3.1.0**。网上仍有大量 SFML 2 的资料，它们的构造方式与 3.x 不同，请优先查阅上面的 3.1 页面。

## Ludork 与 SFML 的分工

Ludork 并不包装或隐藏 SFML，而是在它之上构建。两者职责不同。

| 层 | 负责内容 |
|---|---|
| Ludork | 项目数据、地图、Actor、蓝图、场景、声明式 UI 资产体系、资源管理器与打包。 |
| SFML | 图形、音频、窗口、输入设备，以及这些子系统之间交换的几何与值类型。 |

当一个值或行为本质上是图形或数值时，用 `sf`；当它属于项目本身时，用 `Engine`、`GlobalCore` 与 `GlobalFunctions`。`sf` 里没有地图、Actor、蓝图或数据的概念。

项目里的绘制大多走 Engine 控件与场景，而不是自己新建 `sf.RenderWindow`——窗口、帧循环与 UI 树都由运行时持有。SFML 层的价值在于提供底层的值与资源。

## sf 表

`sf` 是一张普通的全局表，装着类、枚举和辅助函数。完整声明在 `Scripts/stub/LuaSF.d.lua`，EmmyLua 工作区会索引它，因此在编辑器里能获得补全与悬浮提示。

| sf 分组 | 成员 |
|---|---|
| 向量与矩阵 | `sf.Vector2i`、`sf.Vector2u`、`sf.Vector2f`、`sf.Vector2b`、`sf.Vector3i`、`sf.Vector3u`、`sf.Vector3f`、`sf.Vector3b`、`sf.Vector4i`、`sf.Vector4f`、`sf.Vector4b`、`sf.Mat3`、`sf.Mat4`，以及 GLSL 别名 `sf.Vec2`、`sf.Vec3`、`sf.Vec4`、`sf.Ivec2`、`sf.Ivec3`、`sf.Ivec4`、`sf.Bvec2`、`sf.Bvec3`、`sf.Bvec4` |
| 几何 | `sf.Color`、`sf.IntRect`、`sf.FloatRect`、`sf.Angle`、`sf.Time`、`sf.Transform` |
| 图形 | `sf.Texture`、`sf.Image`、`sf.Font`、`sf.Text`、`sf.Shader`、`sf.RenderStates`、`sf.RenderTarget`、`sf.RenderTexture`、`sf.RenderWindow`、`sf.VertexArray`、`sf.VertexBuffer`、`sf.Vertex`、`sf.Shape`、`sf.CircleShape`、`sf.ConvexShape`、`sf.RectangleShape`、`sf.Sprite`、`sf.View` |
| 音频 | `sf.SoundBuffer`、`sf.Sound`、`sf.Music`、`sf.SoundStream`、`sf.SoundSource`、`sf.Listener`、`sf.SoundRecorder`、`sf.SoundChannel`、`sf.PlaybackDevice` |
| 窗口与输入 | `sf.Keyboard`、`sf.Mouse`、`sf.Joystick`、`sf.Touch`、`sf.Sensor`、`sf.Clipboard`、`sf.Cursor`、`sf.VideoMode`、`sf.Event` 及其 `sf.Event_*` 变体 |
| 系统 | `sf.Clock`、`sf.sleep`、`sf.Version`、`sf.InputStream`、`sf.FileInputStream`、`sf.MemoryInputStream` |
| 网络 | `sf.IpAddress`、`sf.Dns`、`sf.Http`、`sf.Ftp`、`sf.Sftp`、`sf.TcpSocket`、`sf.TcpListener`、`sf.UdpSocket`、`sf.SocketSelector`、`sf.Packet` |

一些辅助函数直接挂在 `sf` 上：`sf.seconds`、`sf.milliseconds` 与 `sf.microseconds` 构造 `sf.Time`，`sf.degrees` 与 `sf.radians` 构造 `sf.Angle`。`sf.BlendAlpha`、`sf.BlendAdd` 之类的混合模式也是 `sf` 的字段。

## 值类型

几何值是原生 userdata，不是 Lua table。它们与 Standard 的 `list`、`tuple`、`dict` 是两套互不相通的体系。

用 `new` 构造：

```lua
local cell = sf.Vector2i.new(4, 7)
local speed = sf.Vector2f.new(1.5, -2.5)
local limit = sf.Vector2u.new(640, 480)
local tint = sf.Color.new(255, 255, 255, 128)
local area = sf.IntRect.new(0, 0, 32, 32)
```

`x` 与 `y` 是可读可写的字段，`Vector3*` 与 `Vector4*` 另加 `z` 和 `w`：

```lua
local position = sf.Vector2i.new(0, 0)
position.x = position.x + 1
position.y = 4

local amount = sf.Vector3f.new(1.0, 0.5, 0.0)
local offset = sf.Vector4f.new(0.0, 0.0, 0.5, 1.0)
```

二维向量支持算术运算符，位移与居中的写法因此很直观：

```lua
local start = sf.Vector2f.new(64.0, 64.0)
local step = sf.Vector2f.new(16.0, 0.0)

local moved = start + step * 2.0   -- Vector2f(96, 64)
local back = moved - step
local mirrored = -moved
local half = moved / 2.0

local isSame = moved == back + step -- true
```

可用的运算符是 `+`、`-`、一元 `-`、与标量数字的 `*` 和 `/`，以及 `==`。仅定义了 `==`，因此 `<` 之类的比较不能用于向量。两个向量相乘是方法而不是运算符。三种 `Vector2` 都提供 `lengthSquared`、`perpendicular`、`dot`、`cross`、`componentWiseMul`、`componentWiseDiv` 与 `unpack`，其中 `unpack` 把各分量作为多个返回值返回。浮点类型另有 `length`、`normalized`、`angle`、`angleTo`、`rotatedBy` 与 `projectedOnto`，它们使用 `sf.Angle` 而不是角度值。

`sf.Vector2f.new` 还接受一个长度和一个 `sf.Angle`，用于按极坐标构造向量：

```lua
local forward = sf.Vector2f.new(1.0, sf.degrees(90)) -- Vector2f(0, 1)
```

### 颜色、矩形与时间

`sf.Color` 的 `r`、`g`、`b`、`a` 取值范围是 0 到 255。四参数构造函数依次接收红、绿、蓝、透明度，参数更少的写法会为缺省分量取默认值：

```lua
local solid = sf.Color.new(32, 96, 160)
local veil = sf.Color.new(0, 0, 0, 160)
```

预设颜色是 `sf.Color` 的字段：`Black`、`White`、`Red`、`Green`、`Blue`、`Yellow`、`Cyan`、`Magenta` 与 `Transparent`。`toInteger` 返回打包后的 32 位整数。`sf.Color` 没有任何运算符，不能相加也不能比较；需要时应读取并比较它的各个分量。

`sf.IntRect.new` 与 `sf.FloatRect.new` 接收一个位置和一个尺寸，也接受四个数字。后两个数字是宽和高，不是右下角坐标——这是这个构造函数最容易踩的坑：

```lua
local tile = sf.IntRect.new(sf.Vector2i.new(0, 0), sf.Vector2i.new(32, 32))
local same = sf.IntRect.new(0, 0, 32, 32)
local sub = sf.IntRect.new(32, 0, 32, 32)

local origin = tile.position      -- Vector2i(0, 0)
local height = tile.size.y        -- 32
local inside = tile.contains(sf.Vector2i.new(16, 16)) -- true
local overlap = tile.findIntersection(sub) -- 一个 sf.IntRect；不相交时为 nil
```

`sf.Angle` 表示旋转角度。它不是数字，因此角度值必须经 `sf.degrees` 或 `sf.radians` 构造，不能直接把度数当参数传。

```lua
local facing = sf.degrees(90)
local radians = sf.radians(math.pi / 2)

local degrees = facing.asDegrees()
local wrapped = sf.degrees(450).wrapSigned().asDegrees() -- 90
```

`wrapSigned` 把角度约束到 `[-180°, 180°)`，`wrapUnsigned` 约束到 `[0°, 360°)`。两者都是可选的：超出这两个范围的角度依然有效，只有需要比较或需要规范化的显示值时才用它们。`sf.Angle.new()` 与 `sf.Angle.Zero` 都是零。

`sf.Time` 表示时长，由 `sf.seconds`、`sf.milliseconds` 与 `sf.microseconds` 构造：

```lua
local cooldown = sf.seconds(0.75)

local milliseconds = cooldown.asMilliseconds() -- 750
```

`sf.Time.new()` 同样是零值；`sf.sleep` 会让当前线程暂停指定时长。

## 对象类型

图形对象遵循 SFML 的继承结构，Lua 中看到的也是同一套关系：

```text
sf.Drawable
sf.Transformable
sf.Shape : sf.Drawable, sf.Transformable
sf.CircleShape, sf.ConvexShape, sf.RectangleShape : sf.Shape
sf.Sprite : sf.Drawable, sf.Transformable
sf.Text : sf.Drawable, sf.Transformable
```

所有 `sf.Transformable` 都提供：`setPosition`、`getPosition`（`sf.Vector2f`）、`setRotation`、`getRotation`（`sf.Angle`）、`setScale`、`getScale`、`setOrigin`、`getOrigin`（`sf.Vector2f`），以及 `move`、`rotate`、`scale` 和 `getTransform`。Sprite、Shape 与 Text 的位移操作就靠这一套方法。

```lua
local cell = sf.RectangleShape.new(sf.Vector2f.new(32.0, 32.0))

cell:setPosition(sf.Vector2f.new(64.0, 64.0))
cell:setOrigin(sf.Vector2f.new(16.0, 16.0))
cell:setRotation(sf.degrees(45))
cell:setScale(sf.Vector2f.new(2.0, 2.0))
cell:move(sf.Vector2f.new(8.0, 0.0))

local bounds = cell:getGlobalBounds()
```

`sf.RectangleShape.new` 接收尺寸，`sf.CircleShape.new` 接收半径与顶点数，`sf.ConvexShape.new` 接收顶点数，`sf.Text.new` 接收字体、字符串与字号。Shape 还提供 `setFillColor` 与 `setOutlineColor`（接收 `sf.Color`）以及 `setOutlineThickness`（接收数字）。

上面列出的抽象基类都以表的形式存在，但没有 `new`：`sf.Drawable`、`sf.Shape`、`sf.RenderTarget`、`sf.InputStream`、`sf.SoundSource`、`sf.SoundStream`、`sf.SoundRecorder`、`sf.SoundFileReader`、`sf.SoundFileWriter` 与 `sf.Socket` 都无法构造。请改为构造具体的子类，并把基类当作参数或返回值所声明的类型来用。唯一的例外是 `sf.Drawable`：Lua 可以通过 `sf.LuaDrawable.new(drawCallback)` 实现它，`draw` 会在 Lua 中执行。

事件的构造方向正好相反：`sf.Event_Closed`、`sf.Event_Resized` 这类载荷类型可以构造，而 `sf.Event.new` 要求传入其中一个作为参数。项目代码通常是接收事件，而不是自己构造。

## 在项目中使用 SFML

位置、尺寸与矩形在 Engine API 中都以 `sf` 值传递，因此格坐标与世界坐标之间的换算就是普通的向量运算：

```lua
local Player = require("GlobalFunctions.Player")

local CELL_SIZE = Engine.GetCellSize()

local function cellToWorld(cellX, cellY)
    return sf.Vector2f.new(cellX * CELL_SIZE, cellY * CELL_SIZE)
end

local player = Player.GetPlayer()
if player ~= nil then
    local position = player:getPosition()
    local cell = sf.Vector2i.new(
        math.floor(position.x / CELL_SIZE),
        math.floor(position.y / CELL_SIZE)
    )
end
```

传值之前先看声明的类型。声明为 `sf.Vector2f` 的接口不会接受 `sf.Vector2i`，也不会接受 Standard 的 `tuple` 或普通 table，运行时更不会替你转换。

JSON 与 metadata 只保存纯数据，而 `sf` 值是原生 userdata，因此两种形式之间的转换是显式的。Game 项目的存档编解码器把 `sf.Vector2i` 写成 `{ x, y }`，读取时再重建；它的记录归一化会把 `sf.Vector2i`、`sf.Vector3i`、`sf.IntRect`、`sf.FloatRect` 与 `sf.Color` 转成数字数组。只要目标是数据，就存分量，用到时再构造 `sf` 值。

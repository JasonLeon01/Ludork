# Ludork Lua进阶

Ludork 的 Standard 运行时在 Lua 之上提供原生 class、容器与工具函数。这些 API 在 `Scripts/Entry.lua` 加载之前就已可用，无需 `require("Standard")`；它们与 API 参考中的 `Engine`、`GlobalCore`、`GlobalFunctions` 与 LuaSF 绑定不是同一套。

开发时使用的精确签名，声明在 `Scripts/stub/Standard.d.lua` 与 `Scripts/stub/Class.d.lua` 中。

## Ludork 的类（class）

先创建一张没有 metatable 的普通定义表，把默认值和方法写上去，最后返回 `class(definition, ...)`。定义表不能是已经定型（finalise）过的；每个基类都必须是已定型的 Ludork class 或已注册的原生类型，基类不能重复，声明顺序决定 C3 方法解析顺序。

```lua
local Engine = require("Engine")

local Actor = Engine.Actor

local Pickup = {}

Pickup.count = 1
Pickup.sound = ""

function Pickup:init(texture, tag)
    Actor.init(self, texture, tag)
    self._collected = false
end

return class(Pickup, Actor)
```

### 默认值与实例状态

凡是允许编辑或继承的默认值，都要在定型之前写进定义表：包括 metadata 字段、component 默认值、`default*` spawn 值，以及允许 Blueprint 覆写（override）的标识符。

`init` 负责应用构造参数，并初始化每个实例各自的状态。实例需要一份独立可变的值时，应复制 class 上的默认值：

```lua
local RouteFollower = {}

RouteFollower.speed = 96.0
RouteFollower.defaultRoute = {}

function RouteFollower:init()
    self._route = deepcopy(self.defaultRoute)
    self._routeIndex = 1
end

return class(RouteFollower)
```

公开的默认值不能只在 `init` 里初始化——子类与 Blueprint 的字段发现都要从 class 上读取这个值。

### 构造、生命周期与继承

`Type.new(...)` 创建实例并调用 `init`；定型后的 class 也可以直接调用，但项目代码应跟随相邻模块的写法。没有 `init` 的 class 不接受参数，除非它唯一的原生根类型定义了构造契约。必需的原生基类初始化器要显式调用。`onCreate`、`onTick`、`onDestroy` 这类生命周期方法，只在所属运行时契约调用它们时才执行。`instance:dispose()` 最多执行一次解析得到的实现，负责释放原生所有权与实例字段；垃圾回收不会重复调用它。

方法内写 `super()`，会从定义该方法的 class 开始解析下一个实现。当间接回调让归属（owner）不明确时，请改用 `super(ClassName, self)`。支持多重继承，但声明的基类顺序必须保持稳定。

Direct Script Mixin 遵循独立的生命周期，不能声明 `init`。

### Class 工具

| API | 用途 |
|---|---|
| `Class.isInstance(value, target)` | 判断原始 Lua 类型，或按 class 的完整 MRO 判断是否为实例。 |
| `Class.isSubclass(value, target)` | 按完整 MRO 判断是否为子类。 |
| `Class.type(value)` | 返回其 Ludork class 或原生回退（fallback）类型。 |
| `Class.hasOwnField(value, key)` | 判断字段是否直接存储在该值上。 |
| `Class.getMro(value)` | 返回一份独立的 MRO 数组。 |
| `Class.getParameterNames(callable)` | 返回声明的参数名列表（不含 `self`）。 |
| `Class.constructNamed(type, values)` | 按名称把值对应到 `init` 参数上并构造实例。 |
| `Class.super(cls?, self?)` / `super(...)` | 在当前 MRO 中解析下一个实现。 |
| `Class.monitor` / `Class.unmonitor` | 添加或移除一个字段监听。 |
| `Class.MISSING` | 被监听的字段此前不存在时使用的哨兵值。 |

`Class.monitor(target, name, callback, params?, notifyEqualWrites?)` 不接受 `nil`。它通常在赋值改变了可见值之后发出通知；传入 `true` 后，等值写入也会通知。重入赋值仍然生效，但同一 callback 的递归通知会被抑制；callback 报错不会回滚已完成的赋值。

### 类型判断

所有类型判断都通过 `Class.isInstance` 完成。target 可以是已定型的 Ludork class、已注册的原生 class，也可以是准确的 Lua 类型名字符串：`nil`、`boolean`、`number`、`string`、`function`、`userdata`、`thread`、`table`。

```lua
if Class.isInstance(value, "string") then
    print(string.upper(value))
end

local isActor = Class.isInstance(actor, Actor)
local isNativeVector = Class.isInstance(position, sf.Vector2f)
local isInteger = Class.isInstance(value, "number") and math.type(value) == "integer"
```

以字符串作 target 时，判断保持 Lua `type` 的语义：原生容器是 userdata，可调用的 table 仍是 table。未知的类型名返回 false；target 既不是 string 也不是 table 时抛出参数错误。`math.type` 只在确认值为 number 之后使用；`Class.type` 只在确需解析后的类型值时使用。不要拿 Lua `type` 的结果与 `==`、`~=` 比较。

## 真值与复制（Truth Value）

Lua 本身只把 `nil` 与 `false` 当作假。Ludork 的 `bool(value)` 进一步把 `0`、空字符串、空 table 和空的原生容器也判为假。只有当“缺失”本身是独立的协议值时，才需要显式比较 nil。

| API | 行为 |
|---|---|
| `copy(value)` | 浅复制 table 以及支持该操作的原生值。 |
| `deepcopy(value)` | 递归复制键与值，同时保留别名引用与循环结构。 |
| `asizeof(value)` | 估算某个 Lua/原生值图占用的字节数。 |

可复制的原生值类型会得到一份独立的值；没有定义复制策略的资源则保持原身份。

## 原生容器

`list`、`tuple` 与 `dict` 是原生容器，不能取代 JSON、metadata、Blueprint 值或 Core binding 所要求的 Lua table。

```lua
local route = list("north", nil, "east")
local position = tuple(4, 7)
local visited = dict {
    [position] = true,
}
```

`list(...)` 与 `tuple(...)` 把参数放进从 1 开始的槽位；只传一个 table/list/tuple 时，会按序列浅复制它。`dict(mapping?)` 复制传入的映射。tuple 不允许 nil；list 与 dict 可以保留 nil 槽位或 nil 值。序列不接受负索引；对 list 的写入或插入只能指向已有槽位或 `#value + 1`。

| 类型 | 主要操作 |
|---|---|
| `list` | `append`、`extend`、`insert`、`pop`、`remove`、`clear`、`index`、`count`、`contains`、`reverse`、`sort`、`copy`、`unpack`、`toTable` |
| `tuple` | `index`、`count`、`contains`、`unpack`、`toTable` |
| `dict` | `get`、`setdefault`、`update`、`pop`、`remove`、`clear`、`contains`、`keys`、`values`、`items`、`copy`、`toTable` |

原生 `ipairs` 会照常访问 list 里的 nil 槽位；dict 的迭代保持插入顺序，迭代期间修改结构会失败。`dict:get(key, default)` 只在 key 不存在时返回 default；`dict:contains(key)` 则能区分“key 不存在”与“存了 nil”这两种情形。删除条目要用 `remove` 或 `pop`，不能赋 nil：`remove` 返回是否找到了 key；`pop` 在 key 不存在且未提供 default 时报错。

`list:pop()` 默认删除最后一个槽位；`list:remove` 在值不存在时报错；`list:sort(compare?)` 是稳定排序。dict 的 `keys` 与 `values` 返回按插入顺序排列的 list 快照；`items` 是惰性迭代器。当 string key 与 dict 方法同名时，方法名优先于键的直接查找，因此这类条目要改用 `value:get("get")` 或 `dict.get(value, "get")` 读取。

list 与 dict 按结构进行比较，包含循环的图也不例外。tuple 不可变，可以用作原生 dict 的 key：boolean、有限 number、string 与嵌套 tuple 按值比较；可变/引用值按身份比较。nil 与非有限 number 不能作为 tuple key。普通 Lua table 作 key 时，仍按 tuple userdata 的身份进行哈希。

### 转换边界

`toTable` 会递归转换原生容器，同时保留别名与循环。转换出的 list 与 tuple 即使为空或被嵌套，也仍是 JSON array 的形状。list 的 nil 槽位与 dict 的 nil 值会变成 `cjson.null`；tuple key 转成 `(1,2)` 这样的紧凑字符串，若与已有的 string key 撞名则失败。JSON encoder、metadata、Blueprint 值与 Core binding 都不会自动做这种转换。

如果加载之后必须重建 key 的身份，请改用 record array。

## string 与 table 扩展

Standard 在 Lua 自带库的基础上补充了下列辅助函数：

| API | 用途 |
|---|---|
| `string.pformat` | 用 `{}` 依次填充位置字段，或用末尾的映射表填充 `{name}`；`{{` 与 `}}` 转义花括号。 |
| `string.contains`、`string.startsWith`、`string.endsWith` | 判断是否包含某文本，或以某文本开头/结尾。 |
| `string.isEmpty`、`string.isBlank` | 判断文本是否为空，或只含空白。 |
| `string.strip`、`string.stripLeading`、`string.stripTrailing` | 移除开头/结尾处的 Unicode 空白。 |
| `string.replace`、`string.split` | 替换子串，或按分隔符拆分。 |
| `string.utf8Length`、`string.utf8Slice` | 按 UTF-8 码点统计长度或切片。 |
| `table.contains`、`table.index` | 用 Lua 相等语义在稠密数组中查找，遇到第一个 nil 槽位即停。 |
| `table.orderedStringKeys` | 先返回优先键（preferred keys），再输出其余按序排列的字符串键。 |

## 平台、配置与文件

`PLATFORM` 是目标平台的小写名称（`win32`、`darwin`、`ios`、`android`、`ohos`，或 CMake 系统名）。`LUDORK_MOBILE` 与 `LUDORK_DESKTOP` 标明运行时的宿主类别。不要通过路径或环境变量去猜测平台。

`configparser.ConfigParser()` 用于读写 INI 文件，提供 `read`、`write`、`has_section`、`add_section`、`get`、`getfloat`、`getint`、`getboolean` 与 `set` 等方法。`locale.getdefaultlocale()` 返回宿主的 locale 对。

文件系统扩展如下：

| API | 用途 |
|---|---|
| `os.getcwd`、`os.listdir` | 读取当前目录，或列出其中已排序的直接条目。 |
| `os.createDirectories` | 按 UTF-8 路径创建目录（含缺失的父目录）；目录已存在也算成功。 |
| `os.removeFile` | 按 UTF-8 路径删除一个文件；文件不存在或删除失败都会报错。它不取代 `os.remove`。 |
| `os.path.join`、`os.path.splitext`、`os.path.basename`、`os.path.dirname`、`os.path.abspath` | 拼接或解析路径。 |
| `os.path.isdir`、`os.path.isfile` | 判断路径是否指向已有目录/文件；路径不存在时返回 false，检查过程中的错误仍会抛出。 |
| `os.path.getmtime` | 返回文件的修改时间。 |

`os.listdir` 返回的是条目名，检查之前要先把名称与父目录拼成完整路径。

Standard 还提供以下二进制安全的编解码（codec）全局函数：

| API | 用途 |
|---|---|
| `zlib.compress`、`zlib.decompress` | 将数据压缩成 zlib 格式，或解压 zlib/gzip 数据。 |
| `base64.encode`、`base64.decode` | 对 Base64 做编码/解码；解码容忍空白，接受合法 padding，并拒绝畸形数据。 |

## 协作任务与文件批次

`asyncio.create_task(callback, ...)` 启动一个协作式任务；`asyncio.sleep(seconds)` 让出执行；`asyncio.cancel_task(task)` 请求取消该任务。

较大的读取可交给 `asyncio.start_file_batch(specs)` 批量完成：最多并发读取四个文件，交付时仍保持清单（manifest）顺序。`asyncio.poll_file_batch(job, maxItems?)` 返回进度、已交付条目与结构化错误；`asyncio.cancel_file_batch(job)` 取消整批任务。

设置 `parseJson = true` 后，所选文件必须都是 `.json`。轮询会返回 `FileBatchJsonConversion`，解析失败时 `operation = "parse"`。在 Lua 逻辑线程上用 `asyncio.step_file_batch_json(conversion, maxNodes, maxMilliseconds)` 推进转换，两个预算值都必须为正；它返回 `completed, processed, data`，完成时只交付一次 data。解码出的数组用 `n` 记录逻辑长度；JSON 中的 null 项表现为缺失的 key。`asyncio.clear_file_batch_json` 可以安全地重复释放转换；取消、回收或 shutdown 也会使转换失效。转换不能跨 Lua VM 或线程。

未设置 `parseJson` 时，文件字节放在 `item.content` 中。

## 时间与内存诊断

`perfCounter()` 返回单调递增的高精度时间，单位为秒。`processMemoryMB()` 返回当前进程占用的内存（MiB）。估算单个值图请用 `asizeof`，不要拿进程内存来代替。

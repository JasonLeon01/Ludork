# Ludork Lua进阶

Ludork 的 Standard runtime 为 Lua 增加原生 class、容器和工具函数。这些 API 在 `Scripts/Entry.lua` 之前已可用，无需 `require("Standard")`；它们不同于 API 参考中的 `Engine`、`GlobalCore`、`GlobalFunctions` 与 LuaSF binding。

开发期精确签名位于 `Scripts/stub/Standard.d.lua` 与 `Scripts/stub/Class.d.lua`。

## Ludork Class

先创建没有 metatable 的普通 definition table，添加默认值与方法，再返回 `class(definition, ...)`。definition 不得已被 finalise；每个 base 必须是已 finalise 的 Ludork class 或已注册原生类型，不允许重复 base，base 顺序决定 C3 方法解析顺序。

```lua
local Engine = require("Engine")

local Actor = Engine.Actor

local Pickup = {}

Pickup.count = 1
Pickup.sound = ""

function Pickup:init(texture, tag)
    Actor.init(self, texture, tag)
    self._collected = false
end

return class(Pickup, Actor)
```

### 默认值与实例状态

可编辑或可继承的默认值必须在 finalise 前写在 definition table 上，包括 metadata 字段、component 默认值、`default*` spawn 值和允许 Blueprint override 的标识符。

`init` 负责构造参数和每实例状态。实例需要独立可变值时，应复制 class 默认值：

```lua
local RouteFollower = {}

RouteFollower.speed = 96.0
RouteFollower.defaultRoute = {}

function RouteFollower:init()
    self._route = deepcopy(self.defaultRoute)
    self._routeIndex = 1
end

return class(RouteFollower)
```

公开默认值不能只在 `init` 中初始化；subclass 和 Blueprint 字段发现会从 class 读取它。

### 构造、生命周期与继承

`Type.new(...)` 创建实例并调用 `init`；finalise 后的 class 也可直接调用，但项目代码应遵循相邻模块风格。没有 `init` 的 class 不接受参数，除非它唯一的原生 root 定义了构造 contract。必需的原生 base initialiser 应显式调用。`onCreate`、`onTick`、`onDestroy`、`dispose` 等生命周期方法只在所属 runtime contract 调用时执行。

方法内的 `super()` 从定义该方法的 class 解析下一实现。间接 callback 使 owner 不明确时，使用 `super(ClassName, self)`。支持多继承，声明的 base 顺序必须保持稳定。

Direct Script Mixin 使用独立生命周期，不得声明 `init`。

### Class 工具

| API | 用途 |
|---|---|
| `Class.isInstance(value, target)` | 按完整 MRO 判断实例。 |
| `Class.isSubclass(value, target)` | 按完整 MRO 判断 subclass。 |
| `Class.type(value)` | 返回 Ludork class 或原生 fallback 类型。 |
| `Class.hasOwnField(value, key)` | 判断字段是否直接存储。 |
| `Class.getMro(value)` | 返回独立 MRO 数组。 |
| `Class.getParameterNames(callable)` | 返回不含 `self` 的声明参数名。 |
| `Class.constructNamed(type, values)` | 按名称匹配 `init` 参数并构造。 |
| `Class.super(cls?, self?)` / `super(...)` | 在当前 MRO 中解析下一实现。 |
| `Class.monitor` / `Class.unmonitor` | 添加或移除字段 monitor。 |
| `Class.registerService` / `Class.unregisterService` | 管理 fail-fast runtime 集成 service。 |
| `Class.MISSING` | monitor 字段此前不存在时使用的 sentinel。 |

## 项目 Truth Value 与复制

Lua 自身只有 `nil` 和 `false` 为假。Ludork 的 `bool(value)` 还会把 `0`、空字符串、空 table 和空原生容器视为假。只有缺失是独立协议值时才显式比较 nil。

| API | 行为 |
|---|---|
| `copy(value)` | 浅复制 table 与支持的原生值。 |
| `deepcopy(value)` | 递归复制 key/value，并保留 alias 与循环。 |
| `asizeof(value)` | 估算 Lua/原生值图拥有的字节数。 |

支持值复制的原生类型会生成独立值；没有值复制策略的资源保持身份。

## 原生容器

`list`、`tuple` 与 `dict` 是原生容器，不替代 JSON、metadata、Blueprint 值或 Core binding 要求的 Lua table。

```lua
local route = list("north", nil, "east")
local position = tuple(4, 7)
local visited = dict {
    [position] = true,
}
```

`list(...)` 与 `tuple(...)` 按从 1 开始的槽保存参数；只传一个 table/list/tuple 时会按序列浅复制。`dict(mapping?)` 复制 mapping。tuple 禁止 nil，list 与 dict 可保留 nil 槽或值。序列不接受负索引，list 写入或插入只能指向已有槽或 `#value + 1`。

| 类型 | 主要操作 |
|---|---|
| `list` | `append`、`extend`、`insert`、`pop`、`remove`、`clear`、`index`、`count`、`contains`、`reverse`、`sort`、`copy`、`unpack`、`toTable` |
| `tuple` | `index`、`count`、`contains`、`unpack`、`toTable` |
| `dict` | `get`、`setdefault`、`update`、`pop`、`remove`、`clear`、`contains`、`keys`、`values`、`items`、`copy`、`toTable` |

原生 `ipairs` 会访问 list 的 nil 槽，dict 迭代保持插入顺序；迭代期间修改结构会失败。`dict:get(key, default)` 只在 key 缺失时使用 default，`dict:contains(key)` 可区分该情况与“保存了 nil”。删除应使用 `remove` 或 `pop`，不能赋 nil；`remove` 返回是否找到 key，`pop` 在 key 缺失且没有 default 时抛错。

`list:pop()` 默认删除最后一槽，`list:remove` 在值不存在时抛错，`list:sort(compare?)` 保持稳定。dict 的 `keys` 与 `values` 返回按插入顺序排列的 list snapshot，`items` 是惰性 iterator。dict 方法名优先于同名 string key 的直接查找，因此这类条目应通过 `value:get("get")` 或 `dict.get(value, "get")` 读取。

list 与 dict 按结构比较，包括循环图。tuple 不可变，可作为原生 dict key：boolean、有限 number、string 和嵌套 tuple 按值比较，可变/引用值按身份比较；nil 和非有限 number 不能作为 tuple key。普通 Lua table 仍按 tuple userdata 身份进行 hash。

### 转换边界

`toTable` 递归转换原生容器，并保留 alias 与循环。转换后的 list 与 tuple 在为空或嵌套时仍保持 JSON array 形状。list nil 槽和 dict nil 值转换为 `cjson.null`。tuple key 转换为 `(1,2)` 形式的紧凑 string，与已有 string key 冲突时失败。JSON encoder、metadata、Blueprint 值和 Core binding 不会自动转换。

若加载后必须重建 key 身份，应改用 record array。

## String 与 Table 扩展

Standard 在 Lua 既有库上增加以下 helper：

| API | 用途 |
|---|---|
| `string.pformat` | 格式化 `{}` 位置字段，或用末尾 mapping table 格式化 `{name}`；`{{` 与 `}}` 转义花括号。 |
| `string.contains`、`string.startsWith`、`string.endsWith` | 检查内容或首尾。 |
| `string.isEmpty`、`string.isBlank` | 检查空文本或纯空白文本。 |
| `string.strip`、`string.stripLeading`、`string.stripTrailing` | 移除 Unicode 空白。 |
| `string.replace`、`string.split` | 替换或拆分文本。 |
| `string.utf8Length`、`string.utf8Slice` | 按 UTF-8 codepoint 计数或切片。 |
| `table.contains`、`table.index` | 按 Lua 相等语义搜索稠密数组，并在首个 nil 槽停止。 |
| `table.orderedStringKeys` | 先返回 preferred key，再排序其余 string key。 |

## 平台、配置与文件

`PLATFORM` 是小写目标名（`win32`、`darwin`、`ios`、`android`、`ohos` 或 CMake 系统名）。`LUDORK_MOBILE` 与 `LUDORK_DESKTOP` 表示 runtime 宿主类别。不得通过路径或环境变量推测平台。

`configparser.ConfigParser()` 读写 INI，提供 `read`、`write`、`has_section`、`add_section`、`get`、`getfloat`、`getint`、`getboolean` 与 `set`。`locale.getdefaultlocale()` 返回宿主 locale pair。

文件系统扩展如下：

| API | 用途 |
|---|---|
| `os.getcwd`、`os.listdir` | 读取当前目录或排序后的直接条目。 |
| `os.path.join`、`os.path.splitext`、`os.path.basename`、`os.path.dirname`、`os.path.abspath` | 构造或检查路径。 |
| `os.path.isdir`、`os.path.isfile` | 检查已有目录/文件；缺失路径返回 false，检查错误继续抛出。 |
| `os.path.getmtime` | 返回文件修改时间。 |

检查 `os.listdir` 返回项前，应先把名称与父目录拼合。

## 协作式任务与文件批次

`asyncio.create_task(callback, ...)` 启动协作式任务，`asyncio.sleep(seconds)` 让出执行，`asyncio.cancel_task(task)` 请求取消。

批量读取使用 `asyncio.start_file_batch(specs)`，最多并发读取四个文件并保持 manifest 顺序。`asyncio.poll_file_batch(job, maxItems?)` 返回进度、已交付项目和结构化错误；`asyncio.cancel_file_batch(job)` 取消任务。

设置 `parseJson = true` 时，所有文件必须为 `.json`。poll 返回 `FileBatchJsonConversion`，解析失败的 `operation = "parse"`。在 Lua 逻辑线程通过 `asyncio.step_file_batch_json(conversion, maxNodes, maxMilliseconds)` 推进，两个 budget 都必须为正；它返回 `completed, processed, data`，完成时只交付一次 data。解码数组以 `n` 保存逻辑长度，JSON null 项表现为缺失 key。`asyncio.clear_file_batch_json` 可重复安全地释放转换；取消、回收或 shutdown 同样使其失效。转换不能跨 Lua VM 或线程。

不设置 `parseJson` 时，文件字节位于 `item.content`。

## 时间与内存诊断

`perfCounter()` 返回以秒为单位的单调高精度时间。`processMemoryMB()` 返回当前进程内存 MiB。单个值图使用 `asizeof`，不要用进程内存代替。

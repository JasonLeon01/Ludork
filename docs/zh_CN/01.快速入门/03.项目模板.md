# 项目模板

## 目标

根据项目对原生代码、视频与目标平台的需求选择模板。

## 前置条件

- 已列出需要支持的目标平台。
- 已确定项目是否会修改原生 C++ 代码。
- 已确定发行游戏是否必须播放视频。

## 步骤

1. 需要原生代码、iOS 目标或 HarmonyOS 目标时选择 C++ Source，否则选择 Standalone。
2. 只有明确需要视频播放时才加入 FFmpeg。
3. 确认开发主机具备目标所需的编译器、SDK 与签名资源。

## 模板参考

应根据项目的长期技术需求选择模板。后续更换模板属于源码与资产管理任务，不是一个编辑器开关。

| 模板 | 原生源码 | 普通 Run 是否需要编译器 | 适用场景 |
|---|---:|---:|---|
| Standalone | 无 | 否 | 使用随附运行时编辑 Lua、Blueprint、数据与资产。 |
| C++ Source | 有 | 是 | 修改原生服务、绑定，或构建 iOS/HarmonyOS 目标。 |
| Standalone + FFmpeg | 无 | 否 | 预构建运行时必须支持视频播放。 |
| C++ Source + FFmpeg | 有 | 是 | 同时需要原生开发与视频播放。 |

## FFmpeg 选项

FFmpeg 会增加构建体积、第三方许可义务与平台准备步骤。只有项目使用视频时才应启用。Windows 与 macOS 的 FFmpeg 构建使用共享库或动态库；iOS 的 C++ Source + FFmpeg 路径通过 `Sample/cmake/FFmpeg` 构建静态 `.a` 库。下游发行者分发该静态链接 iOS 应用时，必须满足适用的 LGPL 重链接材料要求；发行前请查阅 `Licenses/FFmpeg/README.md`。在 macOS 上，选中 FFmpeg 后新建项目窗口会显示额外的兼容性提示。

## 打包目标

- Windows 10 或更高版本的 x64 编辑器提供 Windows x64 目标。
- macOS 13.3 或更高版本的 Apple Silicon 编辑器提供 macOS arm64、iOS arm64 与 HarmonyOS Mobile arm64-v8a 目标。
- 不提供 Standalone iOS 模板。所有 iOS 输出都需要 C++ Source 项目、Xcode、开发团队、Bundle 设置与签名资源。
- 不提供 Standalone HarmonyOS 模板。HarmonyOS Mobile 输出需要 C++ Source 项目，以及包含 OpenHarmony native SDK 的 DevEco Studio。
- **Use luac**、Shader 加密与数据加密属于打包选项，不是模板类型。

四种模板都包含完整 `Scripts/stub/**/*.d.lua` 声明目录，供编辑器与 Lua 语言工具使用。这些文件只属于开发资产：打包会删除整个 `Scripts/stub`，Lua 编译会忽略 `.d.lua`，游戏发行包不携带任何声明文件。

## 决策检查

如果所有计划内功能都能通过当前 Lua、Blueprint、资产和数据 API 实现，请使用 Standalone。只要有一项需求必须修改原生代码，就应使用 C++ Source。只有明确需要视频播放时才加入 FFmpeg。

## 预期结果

新项目包含目标发行所需的正确原生源码/runtime 与视频能力，同时不引入无关构建和许可义务。

## 验证

打开 `Main.proj`，确认记录的 capability 与完整声明目录，运行项目并打开 Pack Options。检查一次发行包，确认不包含 `Scripts/stub` 或任何 `.d.lua`。确认已配置的 macOS 主机将 iOS 目标设置为 iOS 15.0 或更高版本的 arm64，并将 HarmonyOS Mobile 目标设置为 HarmonyOS 6.0.1 / API 21 或更高版本的 arm64-v8a。

## 限制

模板用于建立项目基线；编辑器不会在已有项目上自动转换 Standalone 与 C++ Source。FFmpeg 还会增加第三方分发义务，且动态链接桌面包与静态链接 iOS 包的要求不同。

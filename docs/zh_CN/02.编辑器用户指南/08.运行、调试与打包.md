# 运行、测试与打包

## 目标

运行项目并获得可操作的诊断信息，测试原生可执行文件，并为受支持的目标平台生成完整发行包。

## 运行模式

点击 Play 控件，会按当前选择的开发模式启动项目。启用 **独立窗口** 时游戏运行在独立窗口中；嵌入模式则在 Windows 上把运行时托管在编辑器内，不支持的平台会改用相应的独立运行方式。修改原生二进制之前，先停止当前进程。

运行前，编辑器会先执行 before-run 插件 hook，在需要时构建 C++ 目标，用编辑器启动参数拉起运行时，并建立命令通道。hook、构建或协议握手失败时，错误都会显示在控制台。

## 测试层次

- 保存前校验改动过的 Blueprint。
- 在编辑器里运行地图，并让控制台保持可见。
- 用性能监视器检查主帧与逻辑线程耗时。
- 在编辑器之外直接运行原生可执行文件，以发现对工作目录的错误假设。
- 测试最终打包产物——它的可写设置目录与资产布局都和编辑器模式不同。

## 打包

选择 **文件 → 打包项目**，选定目标平台并关注打包日志。项目必须包含合法的入口脚本与兼容的模板。打包之前，把 `Scripts/Entry.lua` 中 Sample 的 `APP_NAME = "LudorkSample"` 改成游戏专用的名称——打包脚本会拒绝默认值。Official Locale Tools 通过 before-pack hook 导出 `Locale.xlsx`；底层的打包脚本本身不会执行这个导出。

**加密游戏数据**控制脚本编译以及 Shader、JSON 和存档加密；只选择部分子项时显示三态中的部分选中状态。存档加密会改变原生构建设置，因此仅适用于 C++ Source 项目。**使用 .ldpak**是单独的选项。

桌面包复制运行时文件、`Assets`、`Data` 与运行时 `Scripts`。**使用 .ldpak**默认不勾选；勾选后，每个 Asset 和 Data 一级分组成为归档，裁剪后的运行时脚本成为根级 `Scripts.ldpak`。加密与 Lua 编译先于归档执行；归档本身不等于加密内容。

最终化流程会校验 staging 副本、应用插件排除、删除开发文件，并按选择执行编译、加密与归档；源工程始终不变。

打包会拒绝符号链接、大小写冲突、非法路径与输出冲突。Runtime 会拒绝损坏归档、Asset/Data 分组的 loose/packed 混用，以及不满足唯一有效 loose 或 packed 布局的脚本根目录。

仅供开发使用的 `Scripts/stub` 与所有 `.d.lua` 都会排除。桌面 Standalone 在根部保留启动器，把运行时二进制放入平台包目录（Windows 为 `Binaries`，macOS `.app` 为 `Contents/Frameworks`）。适用时携带 FFmpeg 声明与源码提供材料，发行要求见 [FFmpeg 选项](<../01.快速入门/02.项目模板.md#ffmpeg-选项>)；macOS 签名与公证由发行者负责。

在 macOS 上选择 iOS 15.0 或更高版本目标，需要 C++ Source 项目、完整版 Xcode，以及可用的 Apple Development 签名身份。

iOS 打包默认只生成 `dist/<游戏名>.ipa`，不需要连接 iPhone。勾选 **导出到 iPhone** 后，打包器还会把应用安装到设备上并自动启动；该模式要求恰好连接一台可用的 iPhone，且设备已解锁、信任这台 Mac，并开启了开发者模式。

HarmonyOS 打包需要 C++ Source 项目、Apple Silicon macOS，以及带 OpenHarmony native SDK 的 DevEco Studio。所有 HarmonyOS 变体都基于 HarmonyOS 6.0.2 / API 22。选择 **Mobile** 面向使用 OpenGL ES 的手机/平板宿主；选择 **2in1** 后再选 OpenGL（默认）或 OpenGL ES。

不导出到设备时，打包器会在 `dist` 中生成一个 arm64-v8a 的未签名 HAP，文件名形如 `<游戏名>-harmony-mobile-unsigned.hap`、`<游戏名>-harmony-2in1-opengl-unsigned.hap` 或 `<游戏名>-harmony-2in1-opengl-es-unsigned.hap`。勾选 **导出到匹配的 HarmonyOS 设备** 后，改为生成对应的 `-signed.hap`，安装到设备并启动游戏。Mobile 导出接受上报为 `default`、`phone` 或 `tablet` 的已连接设备；2in1 导出只接受 `2in1`。必须恰好有一台已连接设备与所选形态匹配，另一形态的设备可以保持连接。2in1 OpenGL 包要求设备装有 `libGLv4.so`；部分模拟器没有这个库，应用会报告模块缺失而不会回退到 OpenGL ES，这种情况下应改用 OpenGL ES 包。

`Licenses` 及根目录的许可证/声明文件并不是 HAP 格式的前置条件：存在时打包器会一并包含，缺失时也不会拒绝项目。

只有在 macOS 上、且编辑器检测到 Android Studio 已安装到 `/Applications` 或当前用户的 `Applications` 目录时，C++ Source 项目才会显示 Android 打包。它要求 SDK Platform 36、Build Tools 36.0.0、本机 SDK 下完整且稳定的 NDK r27 或更高版本工具链，以及本机 CMake 3.28 或更高版本。打包器只会从该 SDK 的 `ndk` 目录里挑选满足要求且版本最高的 NDK；项目与编辑器发行包都不会携带 SDK 或 NDK。打包先用本机 CMake 与选定的 toolchain 构建，再走 Android Studio 自带的 JBR 与 Gradle。APK 声明的最低版本为 API 24，因此覆盖 Android 12 与 12L。打包器还会把应用标记为游戏，并请求由传感器决定方向的横屏，所以两个横屏方向都受支持。Android 打包不会调用 SDK Manager、AVD 或 `adb`；无论是否签名，都不会安装或启动 APK。

选择 Android 后会出现默认不勾选的**签名 APK**。不勾选时发布 `dist/<游戏名>-android-arm64-v8a-unsigned.apk`；勾选后可选择 JKS 或 PKCS12 keystore、填写 alias 与密码，并选择是否在本机保存。Key 密码默认与 Keystore 密码相同，选择有记录的 keystore 会自动填写已保存值。取消签名窗口会返回 Pack Options；签名成功时只发布 `dist/<游戏名>-android-arm64-v8a-signed.apk`。

保存记录只属于当前编辑器安装：引用保存在编辑器设置中，密码保存在操作系统凭据库。密码不会写入项目、Gradle 文件或日志。后续版本若要更新同一个已安装应用，必须复用相同的签名密钥。

Android 资源以带 SHA-256 manifest 的 APK assets 保存到版本化运行时目录。移动端包执行与桌面相同的 Scripts loose/packed 二选一协议，同时保留各平台的原生二进制布局；Android 与 HarmonyOS 不会再次压缩 `.ldpak`。生成工程只使用顶层 `Licenses` 的运行时文本，不携带编辑器声明。

## 失败排查

Run 或 Pack 中途停止时，先看控制台或打包日志中第一个可操作的错误。按顺序检查插件 hook、`Main.proj`、入口脚本、JSON 语法、Blueprint 校验、生成的原生模块与缺失的资源。Android 签名失败时，还要确认 keystore 路径可读、alias 存在且密码正确；保存记录失效时，在签名窗口修正自动填写的值。打包无法修复无效的项目引用，也不能替代针对目标平台的测试。

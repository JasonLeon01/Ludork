# Blueprint 与 Actor

Blueprint 是位于 `Data/Blueprints` 下的 JSON 类定义。它选择一个原生或 Lua 父类，保存可编辑属性，并在图模式下包含事件图。地图中的 Actor 实例引用这些类。

## 目标

创建图模式 Blueprint，设置类默认值，添加有效事件图并放置实例，同时不混用图模式与 Script Mixin 继承模式。

## 前置条件

- 已打开并保存的项目，以及有效父类。
- 已生成或加载将使用的所有字段与节点的当前 metadata。
- 如需把 Blueprint 放置为 Actor，还需要一张地图。

## 步骤

1. 按 F3 创建 Blueprint，选择父类和路径。
2. 设置类默认值与组件值。
3. 添加受支持事件，连接执行/数据 pin，并设置未连接输入默认值。
4. 校验并保存 Blueprint。
5. 在 Actor 模式中放置实例，只设置必要实例覆盖，然后运行地图。

## 创建 Blueprint

使用 **Game → New Blueprint**（F3）或文件浏览器命令。选择最终继承 `BPBase` 的父类，再选择 `Data/Blueprints` 下的保存路径。编辑器打开类时会解析父类默认值和支持的事件。

## 类值与实例值

类属性为所有实例提供默认值。地图 Actor 可以覆盖单独字段。组件由 metadata 声明，并显示为结构化字段。`InvalidVars` 隐藏的字段不会作为普通属性编辑。

## 图模式

每个事件拥有节点列表和连接。通过选择器添加节点，连接执行 pin 与类型兼容的数据 pin，并为未连接输入设置字面默认值。Pure 节点只有数据 pin；执行节点必须从事件起点可达。

Common Functions 提供可复用图。多个 Blueprint 需要相同节点序列时，应优先使用 Common Function，而不是复制图。

## 继承

子 Blueprint 继承字段与行为。不要随意修改已保存的父类路径，因为继承字段、事件和兼容组件数据可能改变。同一 Blueprint 继承链必须统一使用图模式或 Script Mixin 模式；参见“直接脚本挂载（Script Mixin）”。

## 校验

校验会检查父类解析、循环继承、graph 结构、事件起点、节点函数、link、pin 和已保存默认值。空的可选事件有效；错误或越界的连接无效。修复所有报告后保存，并运行代表性地图验证。

## 预期结果

Blueprint 解析为一条有效继承链，在没有校验错误的情况下保存；已放置 Actor 除显式实例覆盖外均继承类默认值。

## 验证

- 重新打开 Blueprint，确认父类、字段、事件与 graph link。
- 每次结构性修改 graph 后重新校验。
- 放置两个实例，确认修改一个实例覆盖不会改变类或另一个实例。
- 保持 Console 可见并运行事件路径。

## 限制

同一 Blueprint 继承链不能在图模式与 Script Mixin 模式间切换。校验不能修复已重命名 runtime 成员的引用，也不能证明每个可达玩法状态都正确。

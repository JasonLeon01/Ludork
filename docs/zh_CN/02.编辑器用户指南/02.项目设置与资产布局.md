# 项目设置与资产布局

```text
MyGame/
├── Main.proj
├── Main.ini
├── Assets/
├── Data/
│ ├── Animations/
│ ├── AutoTiles/
│ ├── Blueprints/
│ ├── CommonFunctions/
│ ├── Configs/
│ ├── Curves/
│ ├── General/
│ ├── Locale/
│ ├── Maps/
│ │ ├── Map_01.json
│ │ └── World_01/
│ │   ├── _world.json
│ │   ├── Map_01.json
│ │   └── Map_02.json
│ ├── TextConfigs/
│ ├── Tilesets/
│ └── UI/
├── Scripts/
│ ├── Entry.lua
│ ├── Global/
│ ├── Mixins/
│ ├── Source/
│ │ ├── Configs/
│ │ ├── Locale/
│ │ └── UI/
│ ├── stub/
│ ├── Engine_meta.lua
│ ├── GlobalCore_meta.lua
│ └── GlobalFunctions_meta.lua
└── Engine/
```

C++ Source 模板在项目顶层保留 `CMakeLists.txt`、`src/` 与 `include/`。`Engine/` 集中存放 `Runtime/`、`Standard/`、`Source/{Core,Global,GlobalFunctions}/`、第三方依赖 `ThirdParty/`、平台宿主 `PlatformHosts/` 与构建支持 `cmake/`。FFmpeg 源码归档位于顶层 `ThirdPartySource/`。Standalone 模板包含资源、许可证与打包运行时。见 [构建与模块布局](<../04.C++ 原生开发/01.构建与模块布局.md>)。

## Main.proj

`Main.proj` 声明编辑器和打包所需的能力。Sample 项目启用了 C++ 运行时与 FFmpeg，并保存了首选的运行窗口模式：

```json
{
 "Cpp": true,
 "ffmpeg": true,
 "IndividualWindow": true,
 "lastFileExplorerPath": "Data/Blueprints/Actors"
}
```

未知键可能是编辑器自己维护的状态，应原样保留。选择模板时，FFmpeg 模板要与 `ffmpeg` 设置保持一致。

## Main.ini

`Main.ini` 保存面向游戏的设置。打开 **游戏 → 游戏配置**（F3），可修改语言、缩放、渲染上限、光照渲染倍率、帧时间与音频值；入口脚本是只读的。点击 **确认** 会把项目标记为已修改，随后由普通保存操作写入 `Main.ini`。

![包含显示与音频设置的 Game Config](../../_images/editor/game-config.png)

*调整三个音频通道前，先核对入口脚本、语言和显示设置。*

“缩放”项只在运行时宿主支持时才显示。在编辑器里运行时读取项目内的 `Main.ini`；打包后的游戏则把可变设置存到平台用户数据目录。各项字段、选项、默认值与生效时机的说明，见 [游戏设置参考](<../03.Lua 与蓝图脚本/06.Sample 玩法/07.游戏设置参考.md>)。

## Assets

创作文件位于物理 `Assets` 目录，保存时使用大小写精确、带扩展名且以 `/` 分隔的 `/Game/Assets/...` 路径；`Assets/...`、类别相对路径、原生绝对路径和路径穿越均无效。`PathVars` 与 Config 的 `base` 只约束选择器。`/Game` 仅用于 Ludork 资源 API，Standard 文件 API 与 LuaSF 直接文件构造仍使用原生路径。

建议使用以下一级目录，便于选择器过滤：`Tilesets`、`Autotiles`、`Characters`、`Animations`、`Icons`、`Fonts`、`Musics`、`Sounds`、`Voices`、`Shaders`、`Fogs`、`Transitions`、`System` 和 `Videos`。自定义分组名不能以 `.ldpak` 结尾。勾选**使用 .ldpak**后每组生成一个归档，`Assets` 根部不能含普通文件。

移动资产不会自动修复所有已保存的引用。移动或删除之前，先打开它的引用树，再手工更新受影响的引用。

## Data 与 Scripts

`Data` 保存编辑器生成的 JSON；`Data/Locale/Locale.xlsx` 是 Official Locale Tools 的本地化工作簿。声明式 UI 资产放在 `Data/UI/Assets`；共享或特殊文本样式放在 `Data/TextConfigs`，普通 UI 文本的样式则直接保存在各自的 UI 节点上。`Scripts` 保存运行时 Lua、生成的 Core metadata 与 LuaLS 声明：`Scripts/Global` 放 `GameMap`、`Pool` 等共享运行时模块，`Scripts/Source` 放玩法类与 UI Controller，生成的语言模块位于 `Scripts/Source/Locale`。`.lua`、`stub/**/*.d.lua`、`_meta.lua` 的文件分层说明见 [Lua 运行时与模块](<../03.Lua 与蓝图脚本/01.Lua 运行时与模块.md>)。

Game Variable Manager 负责管理 `Scripts/Source/Configs/GameVariables.lua` 与 `GameVariables_meta.lua`；General Data 保存流程管理 `Scripts/Source/Configs/GeneralEnum.lua` 与 `Scripts/stub/Source/Configs/GeneralEnum.d.lua`。这四个都是生成文件，不得手工修改；其重新生成规则见 [General Data 与 Text Config](<05.General Data 与 Text Config.md>)。

`Engine_meta.lua`、`GlobalCore_meta.lua`、`GlobalFunctions_meta.lua` 以及生成的 Core/LuaSF 声明，都不得手工修改。打包会删除 `Scripts/stub`，并拒绝出现在其他位置的 `.d.lua` 文件。

项目在创作期保留 loose `Data` 与 `Scripts`。**使用 .ldpak**只改变 staging：每个 Data 一级分组成为归档，裁剪后的运行时脚本成为 `Scripts.ldpak`，开发声明不会进入发行包。校验规则见[运行、调试与打包](<08.运行、调试与打包.md>)。

### 地图与大地图资产

普通地图是 `Data/Maps/<名称>.json`。大地图是 `Data/Maps/<大地图文件夹>/`：其中必须恰好有一个 `_world.json`，以及若干直接放在该目录下的子地图 `.json` 文件，不允许继续嵌套。加载大地图时只读取这些直接的 `.json` 文件，像 `.DS_Store` 之类的其他普通文件会被忽略。文件夹名是大地图的路径身份；独立的 `worldName` 则存放在 `_world.json` 里。每张直接子地图都保留一个可编辑的 `mapName`，这样即使文件被移出大地图，它仍是一张完整的地图；子地图的文件名则继续充当其路径与摆放（placement）身份。清单是大地图在选择器与存档中的身份，在地图列表中保持隐藏。

清单采用以下由编辑器管理的封闭结构：

```json
{
  "type": "worldMap",
  "worldName": "{WORLD_01}",
  "width": 256,
  "height": 192,
  "fog": "",
  "fogPower": 0,
  "fogOx": 0.0,
  "fogOy": 0.0,
  "fogDistort": 0,
  "layerOrder": ["floor", "default"],
  "placements": [
    {
      "map": "Map_01.json",
      "rect": [0, 0, 64, 64]
    }
  ]
}
```

`width`、`height` 以及 `[x, y, width, height]` 形式的摆放矩形（placement rect）都使用从零开始的格子坐标。矩形必须与子地图的尺寸一致；每张子地图最多摆放一次，摆放矩形之间可以相邻，但不能重叠或越界，未被覆盖的格子属于合法的空洞。

`worldName` 是必填的非空显示名称。`layerOrder` 由已摆放的子地图推导而来，出现矛盾环时会报错。清单承载大地图的显示名称、尺寸、拼合关系与全局雾；音频、滤镜（filter）与环境光仍然属于各子地图。

## 限制

地图重命名或移动时，只会改写可识别的结构化地图引用：一类是 Config 设置，其 `type` 以 `file` 开头，且选择根目录恰好为 `root = Data`、`base = Maps`；另一类是 graph 节点的 `params[0]`，其 `nodeFunction` 以 `.GotoMap` 或 `.RecordTelepoint` 结尾。其他基于字符串的运行时引用不会被推断或改写。

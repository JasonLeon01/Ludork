C++ Source 模板还会在上述目录旁携带原生构建脚手架：`CMakeLists.txt`、`src/`、`include/`、`cmake/`、`PlatformHosts/`、`Standard/`、`LuaSF/`、`lua-cjson/`、`zlib/`，FFmpeg 变体另有 `ffmpeg/` 与 `ThirdPartySource/`。Standalone 模板只包含 `Assets`、`Data`、`Scripts`、`Licenses` 与打包好的运行时。见[构建与模块布局](<../04.C++ 原生开发/01.构建与模块布局.md>)。

## Main.proj

`Main.proj` 描述编辑器与打包能力。Sample 启用了 C++ runtime 和 FFmpeg，并保存首选运行窗口模式：

```json
{
 "Cpp": true,
 "ffmpeg": true,
 "IndividualWindow": true,
 "lastFileExplorerPath": "Data/Blueprints/Actors"
}
```

未知键可能属于编辑器状态，应予以保留。FFmpeg 模板必须与 `ffmpeg` 设置保持一致。

## Main.ini

`Main.ini` 保存面向游戏的设置。打开 **游戏 → 游戏配置**（F3）可修改语言、缩放、渲染上限、光照渲染倍率、帧时间与音频值；入口脚本只读。点击**确认**会把项目标记为已修改，再由普通保存操作写入 `Main.ini`。

![包含显示与音频设置的 Game Config](../../_images/editor/game-config.png)

*调整三个音频通道前，先核对入口脚本、语言和显示设置。*

仅在运行时宿主支持时显示“缩放”。编辑器运行读取项目内的 `Main.ini`；打包游戏在平台用户数据目录保存可变设置。字段、选项、默认值与生效时机见[游戏设置参考](<../03.Lua 与蓝图脚本/06.Sample 玩法/07.游戏设置参考.md>)。

## Assets

资源路径相对于 `Assets`。建议使用约定目录，以便选择器和 metadata 提示正确过滤：`Tilesets`、`Autotiles`、`Characters`、`Animations`、`Icons`、`Fonts`、`Musics`、`Sounds`、`Voices`、`Shaders`、`Fogs`、`Transitions`、`System` 和 `Videos`。

移动资源不会自动修复所有已保存引用。移动或删除前先打开引用树，再手工更新受影响的数据。

## Data 与 Scripts

`Data` 保存编辑器生成的 JSON；`Data/Locale/Locale.xlsx` 是 Official Locale Tools 的本地化工作簿。声明式 UI 资产位于 `Data/UI/Assets`；UI 控件引用的文本配置位于 `Data/TextConfigs`。`Scripts` 保存运行时 Lua、生成的 Core metadata 与 LuaLS 声明。`Scripts/Global` 保存 `GameMap`、`Pool` 等共享运行时模块，`Scripts/Source` 保存玩法类与 UI Controller，生成的语言模块位于 `Scripts/Source/Locale`。文件分层（`.lua`、`stub/**/*.d.lua`、`_meta.lua`）见 [Lua 运行时与模块](<../03.Lua 与蓝图脚本/01.Lua 运行时与模块.md>)。

Game Variable Manager 管理 `Scripts/Source/Configs/GameVariables.lua` 与 `GameVariables_meta.lua`；General Data 保存流程管理 `Scripts/Source/Configs/GeneralEnum.lua` 与 `Scripts/stub/Source/Configs/GeneralEnum.d.lua`。四者都是生成文件，不得手工修改。重新生成规则见 [General Data 与 Text Config](<05.General Data 与 Text Config.md>)。

不得手改 `CoreSystem_meta.lua`、`Engine_meta.lua`、`GlobalCore_meta.lua`、`GlobalFunctions_meta.lua` 或生成的 Core/LuaSF 声明。打包会删除 `Scripts/stub` 并拒绝其他位置的 `.d.lua`。

### 地图与大地图资产

普通地图是 `Data/Maps/<名称>.json`。大地图是 `Data/Maps/<大地图名称>/`，其中必须恰有一个 `_world.json` 和若干直接子地图 `.json`，不得继续嵌套。清单是大地图的选择器/存档身份，在地图列表中保持隐藏。

清单采用以下由编辑器管理的封闭结构：

```json
{
  "type": "worldMap",
  "width": 256,
  "height": 192,
  "fog": "",
  "fogPower": 0,
  "fogOx": 0.0,
  "fogOy": 0.0,
  "fogDistort": 0,
  "layerOrder": ["floor", "default"],
  "placements": [
    {
      "map": "Map_01.json",
      "rect": [0, 0, 64, 64]
    }
  ]
}
```

`width`、`height` 和 `[x, y, width, height]` placement rect 使用从零开始的格坐标。rect 必须匹配子地图尺寸；每张子地图最多摆放一次，placement 可相接但不能重叠或越界，未覆盖格是合法空洞。

`layerOrder` 从已摆放子地图派生，矛盾环非法。清单只拥有大地图尺寸、拼合关系和全局雾；音频、filter 与环境光仍属于子地图。

## 限制

地图重命名或移动只会改写可识别的结构化地图引用：一类是 `type` 以 `file` 开头、且选择根目录严格为 `root = Data`、`base = Maps` 的 Config 设置；另一类是 `nodeFunction` 以 `.GotoMap` 或 `.RecordTelepoint` 结尾的 graph node 的 `params[0]`。其他基于字符串的 runtime 引用不会被推断或改写。

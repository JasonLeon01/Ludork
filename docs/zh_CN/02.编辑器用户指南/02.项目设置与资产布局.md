# 项目设置与资产布局

项目由几部分组成：`Main.proj` 声明编辑器与打包能力，`Main.ini` 保存面向游戏的运行时设置，文件资源放在 `Assets`，编辑产出的数据放在 `Data`，运行时代码放在 `Scripts`。C++ Source 模板把 `CMakeLists.txt` 放在项目根目录，游戏宿主放在 `Application/include/` 与 `Application/src/`。`Engine/` 下集中了 `Runtime/`、`Standard/`、`Source/{Core,Global,GlobalFunctions}/` 与 `UiPreviewHost/`，第三方依赖放在 `ThirdParty/`，平台宿主放在 `PlatformHosts/`，构建支持放在 `cmake/`。FFmpeg 源码归档位于顶层 `ThirdPartySource/`。Standalone 模板包含资源、许可证和打包后的运行时。见 [构建与模块布局](<../04.C++ 原生开发/01.构建与模块布局.md>)。

## Main.proj

`Main.proj` 声明编辑器和打包所需的能力。Game 项目启用了 C++ 运行时与 FFmpeg，并保存首选的运行窗口模式：

```json
{
  "Cpp": true,
  "ffmpeg": true,
  "IndividualWindow": true,
  "lastFileExplorerPath": "Data/UI/Assets"
}
```

未知的键属于编辑器自身的状态，原样保留即可。选择模板时，FFmpeg 模板要与 `ffmpeg` 设置保持一致。

编辑器将上次选中的地图键保存在 `lastOpenedMapKey`，编辑时切换地图即保存该偏好，不会保存地图内容。重新打开项目时恢复选中项，支持世界地图及其子地图。记录缺失或失效时选择第一项；空项目不选地图。实时调试触发的切图不会覆盖此偏好。

## Main.ini

`Main.ini` 保存面向游戏的设置。打开 **游戏 → 游戏配置**（`F3`）即可编辑。对话框按以下顺序列出 14 行：脚本（只读）、语言、缩放、渲染上限、光照渲染倍率、帧率、抗锯齿级别、垂直同步、音乐开关、音效开关、语音开关、音乐音量、音效音量与语音音量。

只有当取值与已存配置不同时，**确认** 才会以原子方式写入 `Main.ini`，取值未变时确认不会写入任何内容。写入成功后才会更新当前配置。写入失败会显示错误并保持对话框打开，**取消** 则不写入任何内容。游戏配置不参与文档撤销，也不计入未保存状态。

![包含显示与音频设置的 Game Config](../../_images/editor/game-config.png)

*调整三个音频通道之前，先核对入口脚本、语言和显示设置。*

在编辑器中，游戏配置始终显示缩放一行。游戏内的 Config 窗口只有在 `Display.isDisplayScaleConfigurable()` 报告宿主支持显示缩放时才显示该行。

在编辑器中运行时使用项目内的 `Main.ini`。打包后的 Windows 桌面游戏把 `Main.ini` 与 `Save/` 写入运行时根目录，与 `Assets`、`Data`、`Scripts` 并列，因为 Windows 把用户数据解析到进程工作目录。macOS 与 Linux 桌面版使用 `$HOME/<AppName>`，iOS 使用 `~/Library/Application Support/<AppName>`，HarmonyOS 与 Android 使用应用私有的用户数据根目录。各项键名、可选项、默认值与生效时机见 [游戏设置参考](<../03.Lua 与蓝图脚本/05.Game 玩法/07.游戏设置参考.md>)。

## 系统配置

打开 **数据库 → 系统配置**（`F4`）编辑 `Data/Configs` 下的配置文件。左侧列表按相对键名列出各项配置；选择 **Audio**、**System** 等条目后，右侧只显示当前配置的字段。

发现规则沿用原有逻辑：递归读取 `Data/Configs` 下的 `*.json` 文件，按路径排序，以去掉扩展名的相对路径作为键名。接受 `type: "system"` 或未填写 `type` 的 JSON 对象；其他类型、无法解析的 JSON 和动画缓存文件不会成为配置条目。文件选择器的根目录与扩展名过滤仍由各字段原有的 `root`、`base` 和 `ext` 设置决定。

切换配置会保留尚未保存的编辑，不会自动保存。列表和窗口标题中的星号表示修改状态。Windows 使用 Ctrl+S、macOS 使用 Command+S 执行全局保存；撤销/重做针对列表中当前选中的配置。

![左侧为配置列表、右侧为当前表单的系统配置窗口](../../_images/editor/system-config.png)

*选择 System 编辑游戏标题、尺寸和启动设置；选择 Audio 编辑音效与音乐资源。*

## Assets

创作期的文件放在物理目录 `Assets` 下。存储的资源使用大小写精确的 `/Game/Assets/...` 路径，以 `/` 分隔并带文件扩展名。`Assets/...`、类别相对路径、原生绝对路径和路径穿越都无效。`PathVars` 把字段标记为经过校验的规范 `/Game/Assets/...` 引用，`PathRoot = "Project"` 的字段可以豁免。Config 的 `base` 只决定选择器的根目录。`/Game` 通过 Ludork 资源 API 生效；Standard 文件系统 API 与直接使用 LuaSF 文件构造函数时仍需原生路径。

保留约定的一级目录，选择器才能正确过滤：`Tilesets`、`Autotiles`、`Characters`、`Animations`、`Particles`、`Icons`、`Fonts`、`Musics`、`Sounds`、`Voices`、`Shaders`、`Fogs`、`Panoramas`、`Transitions`、`System` 和 `Videos`。`.ldpak` 选项把完整的 `Assets` 树归档为根级 `Assets.ldpak`，直接位于 `Assets` 下的普通文件也包含在内，逻辑资源路径保持不变。

移动资产不会自动修复所有已保存的引用。移动或删除之前先打开它的引用树，再手工更新受影响的数据。

## Data 与 Scripts

`Data/Particles` 保存 [通用粒子](<10.通用粒子.md>) 定义。粒子引用使用不带扩展名的相对键；粒子纹理使用完整逻辑路径，通常位于 `/Game/Assets/Particles`。

`Data` 保存编辑器生成的 JSON；`Data/Locale/Locale.xlsx` 是由 Official Locale Tools 管理的本地化工作簿。声明式 UI 资产放在 `Data/UI/Assets`；`Data/TextConfigs` 保存共享或专用文本样式，普通 UI 文本的样式直接保存在各自的 UI 节点上。

`Scripts` 保存运行时 Lua、生成的 Core metadata 与 LuaLS 声明。`Scripts/Global` 放 `GameMap`、`Pool` 等共享运行时模块；`Scripts/Source` 放玩法类与 UI Controller。生成的语言模块位于 `Scripts/Source/Locale`。`Scripts/Source/UI` 及其镜像 stub 由 UI JSON 生成，手写的基础模块放在 `Source.UIBase`。UI 文件的归属见 [声明式 UI 编写工作流](<../03.Lua 与蓝图脚本/04.声明式 UI/01.编写工作流.md>)；`.lua`、`stub/**/*.d.lua`、`_meta.lua` 三层的归属见 [Lua 运行时与模块](<../03.Lua 与蓝图脚本/01.Lua 运行时与模块.md>)。

`Scripts/Source` 下包含 `Configs/`、`Locale/`、`UI/`、`UIBase/`、`Windows/`、`Scenes/`、`SceneComponents/`、`Components/`、`Data/`、`Enemy/`、`GameInstance/`、`Gameplay/`、`NodeFunctions/` 与 `Utils/`。

游戏变量管理器拥有两个文件：`Scripts/Source/Configs/GameVariables.lua` 与 `GameVariables_meta.lua`。通用数据的保存流程拥有四个文件：`Scripts/Source/Configs/GeneralEnum.lua`、`Scripts/stub/Source/Configs/GeneralEnum.d.lua`、`Scripts/Source/Configs/GeneralDataTypes.lua` 与 `Scripts/stub/Source/Configs/GeneralDataTypes.d.lua`。这六个文件都是生成的，不得手工修改。重新生成规则见 [通用数据与文本配置](<05.通用数据与文本配置.md>)。

`Engine_meta.lua`、`GlobalCore_meta.lua`、`GlobalFunctions_meta.lua` 以及生成的 Core/LuaSF 声明都不得手工修改。打包会移除 `Scripts/stub`，并拒绝任何位置不正确的 `.d.lua`。

创作期的项目保留散放的 `Data` 与 `Scripts`。`.ldpak` 选项只改变暂存方式：完整的 Data 树成为根级 `Data.ldpak`，裁剪后的运行时脚本成为根级 `Scripts.ldpak`，开发用的声明永远不会包含在内。校验规则见 [运行、调试与打包](<08.运行、调试与打包.md>)。

### 地图与大地图资产

普通地图是 `Data/Maps/<Name>.json`。大地图是 `Data/Maps/<WorldFolder>/`，其中恰好有一个 `_world.json` 和若干直接子地图 `.json` 文件，不允许继续嵌套。加载大地图时只读取这些直接的 `.json` 文件，`.DS_Store` 等其他普通文件一律忽略。目录名是大地图的路径身份，`_world.json` 另存一份独立的 `worldName`。每张直接子地图都保留可编辑的 `mapName`，因此文件被移出大地图后仍是一张完整的地图；子地图的文件名继续充当它的路径身份与摆放身份。清单是大地图在选择器和存档中的身份，在地图列表中始终隐藏。

清单采用以下由编辑器管理的封闭结构：

```json
{
  "type": "worldMap",
  "worldName": "{WORLD_01}",
  "width": 256,
  "height": 192,
  "fog": "",
  "fogPower": 0,
  "fogOx": 0.0,
  "fogOy": 0.0,
  "fogDistort": 0,
  "panorama": "",
  "layerOrder": ["floor", "default"],
  "placements": [
    {
      "map": "Map_01.json",
      "rect": [0, 0, 64, 64]
    }
  ]
}
```

`width`、`height` 与 `[x, y, width, height]` 形式的摆放矩形都使用从零开始的格子坐标。矩形必须与对应子地图的尺寸一致，每张子地图只能出现一次。摆放之间可以相邻，但不能重叠，也不能越出大地图边界；未被覆盖的格子属于合法空洞。

`worldName` 是必填的非空显示名称。`layerOrder` 由已摆放的子地图推导而来，出现矛盾环时会报错。清单持有大地图的显示名称、尺寸、拼合关系、全局雾与全局远景；音频、滤镜和环境光仍属于各子地图的数据。

## 限制

地图重命名或移动时，只改写可识别的结构化地图引用：一类是 Config 设置，其 `type` 以 `file` 开头，且选择根目录恰好为 `root = Data`、`base = Maps`；另一类是 graph 节点的 `params[0]`，其 `nodeFunction` 以 `.GotoMap` 或 `.RecordTelepoint` 结尾。其他基于字符串的运行时引用不会被推断或改写。

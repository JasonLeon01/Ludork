# UI 资产编辑器

## 目标

在不编写运行时 Controller 的前提下，创建并排布一个声明式 UI 资产。

## 前置条件

- 已保存项目，且 `Data/UI/Assets` 下的 UI 资产有效。
- 已规划资产所有权：完整 UI、owner 专用 part 或 shared part。
- 已准备纹理、Text Config 或嵌套资产使用的项目资源 key。

## 打开或创建资产

选择 **Game → New UI Asset**，或从项目文件浏览器创建、打开 `Data/UI/Assets` 下的 JSON 资产。完整屏幕和窗口直接放在 `Assets`；归属于某个 UI 的部件放在 `Assets/Parts/<Owner>`；真正跨 UI 共用的部件放在 `Assets/Parts/Shared`。

![显示 Palette、Hierarchy、Designer 和 Inspector 的 UI 资产编辑器](../../_images/editor/ui-asset-editor.png)

*UI 资产编辑器将可用控件、树结构、可视化布局与选中节点属性分开显示。*

## 步骤

1. 设置资产的设计宽度与高度。
2. 添加根控件。新屏幕通常以 `Engine.Canvas` 开始。
3. 将系统控件或已暴露的项目资产从 Palette 拖入 Hierarchy。
4. 逐个选择节点，并在 Inspector 中编辑控件属性。
5. 配置子节点 Slot。Canvas 子项使用锚点、偏移、对齐、自动尺寸与 z-order；List 子项使用 List 自有排布。
6. 为每个节点设置在当前资产内唯一的有意义名称。运行时 Controller 使用名称查找节点。
7. 只有资产是完整、可复用且应出现在 Project Palette 中时，才启用 **Exposed**。
8. 保存并检查校验结果。

## 资产路径与节点身份

资产相对 `Data/UI/Assets`、使用正斜杠且不含扩展名的路径是唯一资产身份。节点 `id` 是编辑器管理的项目唯一 UUID。移动或重命名资产会自动改写受管 JSON 嵌套引用；匹配的 `Ui.define`、`require` 与 LuaDoc 路径由调用方手工更新。通过编辑器复制资产时会生成新的节点身份。

## 预览行为

当匹配的 `UiPreviewHost` 与 adapter fingerprint 可用时，Designer 使用原生预览。原生预览不可用时，编辑器会报告原因并使用受支持的 fallback。纯设计数据 `previewText` 用于排布本地化或运行时生成文本；运行时忽略所有 `editor` 对象。

## 验证

- Hierarchy 不包含重复节点名或 ID。
- 每个非根节点都有上级控件允许的 Slot。
- 资源属性使用项目键，而不是绝对路径。
- 保存时没有路径、嵌套循环或 adapter 错误。
- 原生预览与运行中游戏的布局边界一致。

## 预期结果

资产以唯一规范相对路径、稳定节点 UUID、有效嵌套与 Slot 保存，只在 exposed 时出现在 palette，并且在 preview 与 runtime 中产生相同布局契约。

## 限制

编辑器只设计静态结构与 preview 值；runtime 数据、callback 与生命周期属于 Lua Controller。外部复制 JSON 可能制造编辑器会拒绝的节点身份冲突。

# General Data

General Data 是编辑器管理的 `Data/General` 数据库。每个 JSON 文件定义一个类型 schema 和一组命名成员，适合保存被多个地图或 Blueprint 共用的敌人、物品、装备、玩家预设、状态等数据。

## 目标

定义可复用数据 schema、录入经过校验的 member，并创建 Text Config，同时不破坏已有 runtime 引用。

## 类型结构

| 键 | 含义 |
|---|---|
| `params` | 有序字段定义，包含 `type`、`defaultValue`，以及可选说明和引用选择器 |
| `members` | 保存字段值的命名记录 |
| `linkedType` | 可选的运行时 metadata 类型，用于图事件和转换 |
| `events` | 可选的有序事件名；每个成员可以保存对应 graph |

编辑器字段包括字符串、布尔、整数、浮点、文件、列表和字典。reference 声明可以把值限定到另一个 General Data 类型、animation 或其他受支持资源。空引用显示为 **— 不选择 —**，JSON 中仍保存空字符串。新增带 reference 的 dict 行时，在选中真实 key 前只保留待选 UI，不会保存 `key` 等占位键。

## 步骤

1. 打开 **数据库 → 通用数据**（F12）。
2. 选择或创建类型。
3. 在大量创建成员前先定义字段。
4. 添加成员并填写字段值。
5. 对带 events 的类型编辑每个成员的事件图。
6. 重命名或删除类型/成员前查看引用。
7. 保存，并实际运行读取该数据的路径。

保存 General Data 时还会重新生成 `Scripts/Source/Configs/GeneralEnum.lua` 及其 LuaLS 声明 `Scripts/stub/Source/Configs/GeneralEnum.d.lua`。二者按稳定顺序包含所有 General Data 类型和成员常量，不得手工修改。

已有数据后修改字段类型可能使保存值失效。删除字段会移除其含义，但不会自动修复读取该字段的脚本。

## 搜索与视图

成员搜索不区分大小写，会匹配成员 ID，以及名称、数字、布尔值等直接标量值；不会递归搜索 list、dict、tuple 或 graph 内容。General Data 窗口保持打开期间，每种数据类型会保留自己的搜索内容、选中成员和 Form/Table 选择，Undo 或 Redo 重建页面后也会恢复；这些会话状态不会写入项目。

Form 为单个成员提供完整编辑器。Table 按 schema 声明顺序显示 ID 与字段，并可直接编辑 bool、int、float 和 string；带 reference 的 string 仍使用 selector。file、list、dict、tuple 与未知结构字段只显示摘要和 **编辑** 按钮；点击后会选中对应成员并返回 Form，避免把结构化 JSON 替换为显示字符串。Table 行使用纵向虚拟化，固定宽度的列可横向滚动。

同一字段获得焦点期间的连续文本和数字修改形成一个 Undo 步骤。复选框、selector、成员操作和 schema 操作仍各自形成独立步骤。保存、Undo 与 Redo 会先切分当前焦点编辑，之后继续输入会开始新的步骤。

![General Data 编辑器](../../_images/editor/general-data.png)

*先定义 schema，再录入记录，确保所有 member 使用预期字段类型。*

## Game Variable Manager

打开 **数据库 → 游戏变量**（F11），声明由 Blueprint 与当前游戏实例共享的可变值。左侧列出已声明的变量名；选中一项后，可在右侧编辑类型、初始值和可选备注。备注只供编辑器查看，不影响运行时。变量名是运行时标识符，因此 graph、地图或脚本开始引用后应保持稳定。

创建变量时必须选择类型。Manager 提供 `bool`、`int`、`float`、`string`、`list` 与 `dict`，写入 metadata 时分别映射为 `bool`、`int`、`float`、`string`、`any[]` 与 `Dict[string, any]`。list 与 dict 使用普通 Lua table，而不是 Standard 的原生 `list` 或 `dict`。修改已有变量的类型会清空初始值，并替换成新类型的空默认值。

打开 Manager 会在需要时创建 `Scripts/Source/Configs/GameVariables.lua` 与 `GameVariables_meta.lua`，每次成功修改都会重新生成这一对文件。runtime 文件把每个名称映射到其初始值；metadata 文件保存有序名称、声明类型，并且只在备注非空时写入 `Meta.Remark`。两个文件都是生成输出，均带有“不得手工修改”的警告。

带 `InstVar` 的 Blueprint 字段或节点参数使用可搜索选择器，而不是自由输入文本框。对应的 `InstVarValue` 字段会读取已选声明的类型，并切换为该类型的通用编辑器。带类型过滤的选择器（例如 Sample 条件门）只列兼容变量。

## Text Config

使用 **游戏 → 新建文字配置**（F6）创建结构化文本配置。脚本或资产开始引用后应保持 key 稳定；每次改变 schema 后都要校验保存的 JSON，并验证实际运行时读取路径。

![Text Config 编辑器](../../_images/editor/text-config.png)

*Text Config 为项目使用的结构化文本数据提供专用编辑界面。*

General Data member 应用到 Info 对象或通过 `BPBase.ApplyGeneralData` 应用时，每个 string 都会保持存储原值。string 字段不会自动本地化，因为同一字段类型还用于 class、animation、装备槽位等语义标识符。类似 `{ITEM_NAME}` 的花括号显示值只应在展示边界传给 `LOC`，长生命周期 UI 响应语言变化时应重新解析。Catalogue 格式与 runtime formatter 见[游戏本地化工作流](<../../05.插件开发与安装/06.游戏本地化工作流.md>)。

Sample 的精确 schema 参见“General Data 参考”。

## 验证

- 重新打开类型，对照 schema 检查 member 值。
- 分别按 ID 和直接标量值搜索，再切换 Form 与 Table，确认选择保持同步。
- 在 Table 编辑简单字段、通过 Form 编辑结构字段，然后在两种视图中验证 Undo 与 Redo。
- 让带 reference 的 string 和新建 reference dict 行保持未选择，确认 string 保存为 `""`，dict 不会新增占位键。
- 新增、重命名和删除一个 General Data 成员，保存后检查两个生成的 `GeneralEnum` 文件。
- 创建每种游戏变量类型，修改一项声明的类型并重新打开 Manager，再检查生成的 runtime/metadata 文件对。
- 运行每个读取已变更字段的事件或脚本。
- 把本地化提示与保存的标识符分别校验。

## 限制

修改 schema 或游戏变量声明不能自动修复脚本、graph、存档或字符串引用。General Data 与生成的游戏变量声明属于项目定义数据，不用于保存可变游戏会话状态。

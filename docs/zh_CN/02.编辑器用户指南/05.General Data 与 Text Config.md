# General Data

General Data 是编辑器管理的 `Data/General` 数据库。每个 JSON 文件定义一个类型 schema 和一组命名成员，适合保存被多个地图或 Blueprint 共用的敌人、物品、装备、玩家预设、状态等数据。

## 目标

定义可复用数据 schema、录入经过校验的 member，并创建 Text Config，同时不破坏已有 runtime 引用。

## 前置条件

- 已保存项目，并为每个类型和 member 规划稳定名称。
- 已明确 runtime consumer 需要的字段类型、默认值与引用目标。
- 修改已有 member 的 schema 前已经备份。

## 类型结构

| 键 | 含义 |
|---|---|
| `params` | 有序字段定义，包含 `type`、`defaultValue`，以及可选说明和引用选择器 |
| `members` | 保存字段值的命名记录 |
| `linkedType` | 可选的运行时 metadata 类型，用于图事件和转换 |
| `events` | 可选的有序事件名；每个成员可以保存对应 graph |

编辑器字段包括字符串、布尔、整数、浮点、文件、列表和字典。reference 声明可以把值限定到另一个 General Data 类型、animation 或其他受支持资源。

## 步骤

1. 打开 **Database → General Data**（F11）。
2. 选择或创建类型。
3. 在大量创建成员前先定义字段。
4. 添加成员并填写字段值。
5. 对带 events 的类型编辑每个成员的事件图。
6. 重命名或删除类型/成员前查看引用。
7. 保存，并实际运行读取该数据的路径。

已有数据后修改字段类型可能使保存值失效。删除字段会移除其含义，但不会自动修复读取该字段的脚本。

![General Data 编辑器](../../_images/editor/general-data.png)

*先定义 schema，再录入记录，确保所有 member 使用预期字段类型。*

## Text Config

使用 **Game → New Text Config**（F6）创建结构化文本配置。脚本或资产开始引用后应保持 key 稳定；每次改变 schema 后都要校验保存的 JSON，并验证实际运行时读取路径。

![Text Config 编辑器](../../_images/editor/text-config.png)

*Text Config 为项目使用的结构化文本数据提供专用编辑界面。*

类似 `{ITEM_NAME}` 的花括号显示值由游戏本地化流程消费；表格格式和运行时解析只在“插件系统与本地化”专题说明。

Sample 的精确 schema 参见“General Data 参考”。

## 预期结果

所有 member 遵循声明的字段顺序与类型，selector 解析有效目标，Text Config 保存有效结构化数据，runtime consumer 读取预期值。

## 验证

- 重新打开类型，对照 schema 检查 member 值。
- 重命名或删除标识符前检查引用树。
- 运行每个读取已变更字段的事件或脚本。
- 把本地化提示与保存的标识符分别校验。

## 限制

改变 schema 不能自动修复脚本、graph 或字符串引用。General Data 是项目定义数据，不用于保存可变游戏会话状态。

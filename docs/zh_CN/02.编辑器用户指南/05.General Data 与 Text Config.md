# General Data

General Data 是编辑器管理的数据库，位于 `Data/General`。每个 JSON 文件定义一个类型的 schema 和一组命名成员，适合存放会被多张地图或多个 Blueprint 共用的数据，例如敌人、物品、装备、玩家预设与状态。

## 目标

定义可复用的数据 schema、录入通过校验的成员并创建 Text Config，同时不破坏已有的运行时引用。

## 类型结构

| 键 | 含义 |
|---|---|
| `params` | 有序字段定义，包含 `type`、`defaultValue`、可选 `comment`、容器必需的 `itemType`/`valueType` 和引用选择器 |
| `members` | 保存字段值的命名记录 |
| `events` | 可选的有序事件名；每个成员可分别为各事件保存独立的 graph |

支持的字段类型有 string、bool、int、float、file、list、dict，以及 `sf.Vector2f/i/u`、`sf.Vector3f/i/u`、`sf.Color` 与 `sf.IntRect`。list 必须声明 `itemType`；以 string 为 key 的 dict 必须声明 `valueType`。容器可以用 `any` 保存异构的 JSON 值，但不能嵌套。缺少子类型、成员缺少字段、出现未知的非下划线字段，或者值与 schema 不符时，加载会直接失败。SFML 数组在这一边界上构造；`any` 保留 JSON 字面量的类型，且不会执行字符串。运行时直接使用加载出来的 typed member。

`linkedType` 已不受支持，一旦出现就会直接报错。

每个字段定义都可以附带一段可选的英文 `comment`。新增或编辑字段时，在 **注释** 一栏填写；注释为空则不会写入。悬停 Form 的字段名或 Table 的表头时，会显示这条注释。这个 schema 注释与业务上恰好叫 `desc` 的成员字段值不是一回事：它只是项目中的普通文本，不是 locale key。

reference 声明可以把 string 值限定到另一个 General Data 类型、animation 或其他受支持的资源：list 的 reference 作用于 string 条目，dict 的 reference 作用于 string key。空引用显示为 **— 不选择 —**，JSON 里仍然保存空字符串。给带 reference 的 dict 新增行时，在选中真实 key 之前只保留一个待选界面，不会保存 `key` 之类的占位键。

## 步骤

1. 打开 **数据库 → 通用数据**（F9）。
2. 选择或创建类型。
3. 在批量创建成员之前先定义好字段；在 Form 中右键点击字段名即可编辑该字段的定义。
4. 添加成员并填写字段值。
5. 从类型的右键菜单管理事件，再通过 **编辑 Ability Graph** 打开成员的图（member graph）。重命名或删除事件会更新所有成员的图；运行时必须显式激活它们。
6. 重命名或删除类型/成员前，先查看其引用。
7. 保存后，实际运行一遍读取这些数据的路径。

保存时会重新生成 `Source.Configs.GeneralEnum` 与 `Source.Configs.GeneralDataTypes` 对应的运行时/LuaLS 文件：`GeneralEnum` 保存有序的 type/member 常量；`GeneralDataTypes` 定义各 `<TypeName>AttributeSet` 以及 `Create(typeName, memberID, memberData)`，用于复制带类型的成员（typed member）及其 ID。生成的文件不得手工编辑。

编辑字段时，可以修改它的名称、类型、容器元素/值类型、默认值与注释。重命名字段会保留每个成员中该字段的现有值。修改字段类型、list 的元素类型或 dict 的值类型时，编辑器会先请求确认；确认后，会用新默认值重置所有已有成员中该字段的值。只改默认值不会覆盖已有成员。删除字段会移除其含义，但不会自动修复读取该字段的脚本。

## 搜索与视图

成员搜索不区分大小写，能匹配成员 ID，以及名称、数字、布尔值等直接标量值；不会递归搜索 list、dict、tuple 或 graph 的内容。General Data 窗口保持打开期间，每种数据类型都会记住各自的搜索内容、选中成员与 Form/Table 选择，Undo 或 Redo 重建页面后也会恢复；这些会话状态不会写入项目。

Form 提供单个成员的完整编辑器；Table 按 schema 声明顺序显示 ID 与各字段，其中 bool、int、float 与 string 可直接编辑，带 reference 的 string 仍用 selector 选择。file、list、dict、tuple 及未知结构字段只显示摘要和一个 **编辑** 按钮；点击后选中对应成员并回到 Form，这样就不会把结构化 JSON 替换成显示用的字符串。Table 行做了纵向虚拟化，固定宽度的列可以横向滚动。

焦点停留在同一字段期间，连续的文本与数字修改只形成一个 Undo 步骤；复选框、selector、成员操作和 schema 操作则各自成一步。保存、撤销或重做会先切分当前处于焦点状态的编辑，之后的输入会另起新步骤。

![General Data 编辑器](../../_images/editor/general-data.png)

*先定义好 schema 再录入记录，确保所有成员都使用预期的字段类型。*

## Game Variable Manager

打开 **数据库 → 游戏变量**（F8），可以声明由 Blueprint 与当前游戏实例共享的可变值。左侧列出已声明的变量名；选中某项后，可在右侧编辑它的类型、初始值与可选备注。备注仅供编辑器查看，不影响运行时。变量名是运行时标识符，因此一旦 graph、地图或脚本开始引用它，就应保持稳定。

搜索框按变量名做不区分大小写的过滤。**新建变量** 会先要求输入名称并选择类型，然后添加声明；**删除变量** 在确认后移除当前选中的声明。

![选中整数变量的 Game Variable Manager](../../_images/editor/game-variables.png)

*在右侧详情区修改当前声明的类型、初始值和仅供编辑器查看的备注。*

创建变量时必须先选择类型。Manager 提供 `bool`、`int`、`float`、`string`、`list` 与 `dict`，写入 metadata 时分别映射为 `bool`、`int`、`float`、`string`、`any[]` 与 `Dict[string, any]`。list 与 dict 使用普通 Lua table，而不是 Standard 的原生 `list` 或 `dict`。修改已有变量的类型会清空它的初始值，换成新类型的空默认值。

打开 Manager 时，如需要会创建 `Scripts/Source/Configs/GameVariables.lua` 与 `GameVariables_meta.lua`，此后每次成功修改都会重新生成这一对文件。运行时文件把每个名称映射到它的初始值；metadata 文件保存有序的名称与声明类型，且只在备注非空时写入 `Meta.Remark`。两个文件都是生成产物，都带有“不得手工修改”的警告。

带 `InstVar` 的 Blueprint 字段或节点参数使用可搜索的选择器，而不是自由输入的文本框。对应的 `InstVarValue` 字段会读取已选声明的类型，并切换为该类型的通用编辑器。带类型过滤的选择器（例如 Sample 的条件门）只会列出兼容的变量。

## Text Config

普通 UI 文本的样式直接设置在 UI 节点上；只有共享文本、特殊文本或富文本标签样式，才使用 **游戏 → 新建文字配置**。已被引用的 key 应保持稳定；修改 schema 后，要验证运行时读取是否正常。

![Text Config 编辑器](../../_images/editor/text-config.png)

*Text Config 为项目使用的结构化文本数据提供专用编辑界面。*

General Data 会原样保存每个 string。string 字段不会自动本地化，因为同一字段类型还会承载 class、animation、装备槽位等语义标识符。`{ITEM_NAME}` 这类带花括号的显示值，只应在展示边界交给 `LOC`；生命周期较长的 UI 在响应语言切换时，需要重新解析这些值。Catalogue 格式与运行时 formatter 的说明见 [游戏本地化工作流](<../05.插件开发与安装/06.游戏本地化工作流.md>)。

`Source.Gameplay.GeneralDataGraphAbility` 负责以 `GameplayEventData` 作为 context 显式激活成员图。这类图不提供伪 parent/self 节点，请使用全局节点与这个 context。start 为 `null` 时返回 `NoGraph`；图必须同步执行，不允许 latent node，错误会直接向外传播。

纯 graph 编辑器从类型的 `events` 读取事件列表，不提供 class attribute，也没有 Blueprint 继承。保存项目时会拒绝未声明的事件与 latent node。

Sample 各类型的精确 schema，见“General Data 参考”章节。

## 限制

修改 schema 或游戏变量声明，不会自动修复脚本、graph、存档或字符串中的引用。General Data 与生成的游戏变量声明属于项目定义数据，不应用来保存可变的对局会话状态。

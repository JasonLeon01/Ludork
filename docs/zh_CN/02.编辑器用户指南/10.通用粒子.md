# 通用粒子

通用粒子资源由有序的 GPU 发射轨道组成。Actor 通过 `EmitterComponent` 使用，UI 通过 `Engine.EmitterView` 节点使用，两者共享同一个 `Emitter` 播放实现。原有 `Particle`、`TextParticle` 与 `ParticleSystem` 继续独立存在。

## 编辑与预览

选择 **游戏 → 新建通用粒子**，或在项目文件浏览器中新建粒子。**数据库 → 通用粒子总览**（`F6`）列出 `Data/Particles` 下的资源。选中资源后编辑轨道、属性和生命周期曲线。轨道支持新增、复制、删除、调整顺序，预览可以单独显示选中轨道。轨道顺序也是同一发射器内的绘制顺序。

预览支持播放/暂停、停止、重播、单步、输入时间、拖动时间轴、播放速度与缩放。单步推进 `1 / simulationRate` 秒。跳转时间会暂停播放，再从起点重新运行 GPU 模拟以还原目标时刻，不把粒子状态读回 CPU，因此长距离跳转比相邻帧播放开销更大。预览控制不会修改保存的资源。

资源编辑遵循现有内存文档工作流：手动保存，同一文件的视图共享数据，当前文件保留最近 100 步撤销/重做。修改资源会刷新预览。项目原生预览运行时必须就绪并匹配其注册表；缺少 GPU 能力或资源时会报告错误。

## 资源标识与 Schema

定义保存在 `Data/Particles/<key>.json`。引用使用大小写精确、以 `/` 分隔、不带目录前缀和扩展名的键，例如 `Combat/Hit`。纹理使用完整的 `/Game/Assets/...` 逻辑路径。定义不包含 version 字段。

这里的 Schema 是资源文件和编辑器的 JSON 格式。运行时代码通过 `setConfiguration`、`getConfiguration` 使用 `EmitterConfiguration`、`EmitterTrack`、`EmitterCurves`、`EmitterBurst` 的固定字段。加载器将字符串选项转换为布尔/整数属性，将 RGBA 分量除以 255，构造 SFML 向量/矩形，并把曲线资源键解析成 `CurveData`。[Emitter 配置 API](<../03.Lua 与蓝图脚本/08.全局与 Core 模块/02.Core Modules/01.Engine/08.时间、渲染与粒子.md#emittertrack>)列出了映射。编写文件时仍使用 JSON 字段名和 0–255 颜色单位；编辑器沿用该格式与已有预览消息。

```json
{
  "type": "particle",
  "simulationRate": 60,
  "seed": 1,
  "tracks": [
    {
      "name": "Glow",
      "mode": "resident",
      "capacity": 64,
      "count": 32,
      "loop": true,
      "shape": "disk",
      "radius": 24,
      "lifetime": [0.8, 1.6],
      "speed": [4, 12],
      "texture": "/Game/Assets/Particles/Glow.png",
      "blend": "add",
      "curves": {
        "alpha": {
          "keys": [
            { "time": 0, "value": 0 },
            { "time": 0.2, "value": 1 },
            { "time": 1, "value": 0 }
          ]
        }
      }
    }
  ]
}
```

此例需要项目内存在所引用的纹理。空纹理透明。`simulationRate` 是 1–240 的整数，默认 60；`seed` 是 0–16,777,215 的整数，默认 1。`tracks` 为有序数组，轨道名称唯一。固定种子便于在同一运行时和 GPU 上重复编辑结果，但 GPU 浮点模拟不保证跨设备确定性。

| 轨道字段 | 默认值与含义 |
|---|---|
| `name`、`enabled` | `"Track"`、`true`；手动发射通过名称指定轨道。 |
| `mode` | `"emission"` 或 `"resident"`，生命周期规则见下文。 |
| `duration`、`delay`、`loop`、`prewarm` | `2`、`0`、`true`、`false`；时间单位为秒，`duration` 为正数，`delay` 非负。 |
| `capacity`、`count` | `1024`、`min(32, capacity)`；容量为 1–1,000,000，常驻初始数量为 0–capacity。 |
| `rate`、`distanceRate`、`bursts` | `30`、`0`、`[]`；分别为每秒粒子数、宿主每移动一个逻辑像素的粒子数，以及定时爆发。 |
| `shape`、`extent`、`radius`、`innerRadius` | `"point"`、`[32,32]`、`16`、`8`；形状支持 `point`、`line`、`rectangle`、`disk`、`ring`。线段使用 `extent.x`，矩形使用两个分量。半径非负，圆环内半径不超过外半径。 |
| `direction`、`spread` | `-90`、`30` 度；初始方向在 `direction ± spread` 内采样，Y 轴正方向向下。 |
| `lifetime`、`speed` | `[1,2]` 秒、`[20,40]` 逻辑像素/秒；数组给出最小值和最大值，寿命为正数。 |
| `sizeMin`、`sizeMax` | `[8,8]`、`[16,16]` 逻辑像素；每轴非负的尺寸最小值和最大值。 |
| `rotation`、`angularVelocity` | `[0,360]` 度、`[0,0]` 度/秒。 |
| `colourMin`、`colourMax` | 均为 `[255,255,255,255]`；RGBA 各分量的最小值和最大值，范围 0–255。 |
| `gravity`、`radialAcceleration`、`tangentialAcceleration`、`damping` | `[0,0]`、`0`、`0`、`0`；加速度单位为逻辑像素/秒²，非负阻尼按指数衰减速度。 |
| `texture`、`textureRect` | `""`、`[0,0,0,0]`；裁剪矩形为整数 `[x,y,width,height]`。宽高均为零时使用整图，否则宽高必须为正且位于图片内部。 |
| `columns`、`rows`、`frameCount`、`frameRate` | `1`、`1`、`1`、`0`；网格行列为 1–4096，帧数为 1–`columns × rows`，帧率为非负帧/秒。 |
| `randomStartFrame`、`frameLoop` | `false`、`true`；帧从左向右、再从上向下排列。零帧率保持初始帧，不循环的序列停在最后一帧。 |
| `space`、`scaleMode`、`blend` | `"local"`、`"hierarchy"`、`"alpha"`，其他选项见下文；混合还支持 `"add"`。 |
| `offset`、`rotationOffset`、`scale` | `[0,0]`、`0` 度、`[1,1]`；轨道相对于宿主的变换。 |
| `curves` | 可选生命周期通道 `speed`、`sizeX`、`sizeY`、`rotation`、`red`、`green`、`blue`、`alpha`。 |

每个爆发条目的格式为 `{ "time": 0, "count": 16, "cycles": 1, "interval": 0 }`。首次时间位于 `[0,duration)`，数量为 0–1,000,000，重复次数为 1–10,000，间隔为非负秒数，多次重复时必须大于零。数值必须有限，最小值与最大值范围必须有序。

曲线可使用内联标量 [Curve](<06.动画与曲线.md>)，或 `Data/Curves` 下不带扩展名的键。键时间使用粒子归一化年龄 `[0,1]`。速度、尺寸和 RGBA 通道乘以初始值，默认值为 1；旋转通道追加角度，默认值为 0。内联曲线支持 `defaultValue`、`preInfinity`、`postInfinity`，以及包含 `time`、`value`、`interpolation`、`arriveTangent`、`leaveTangent` 的 `keys`。运行时把每个通道采样成 256 项 GPU 查找表，因此渲染结果是原始曲线的近似。

## 发射、空间与所有权

`emission` 组合时间发射、宿主距离发射、爆发和 `emit(trackName, count)`。`loop` 重复轨道时长；关闭循环后，自动发射在时长结束时停止，已有粒子继续完成生命周期。固定 GPU 槽位按环形使用，新粒子占用后续槽位，容量耗尽时覆盖最旧槽位。容量是模拟预算，不保证每次发射都保留到寿命结束。

`resident` 在延迟后创建 `count` 个粒子。`loop = true` 时每个粒子重复自己的生命周期，无需继续发射；关闭循环时初始粒子只播放一次。时间/距离发射、爆发和手动 `emit` 不用于常驻轨道。图集序列播放独立于这个生命周期模式。

`prewarm` 只作用于循环轨道。正常播放前，GPU 在宿主当前位置重演足以覆盖最大粒子寿命的完整发射周期，每帧最多执行 120 个固定步。预热期间公开播放时间保持为零，重播时重新执行预热。

`local` 空间中已有粒子跟随当前宿主变换；`world` 空间中粒子在宿主移动后仍保留出生时的位置和变换。Actor 使用地图坐标域，`EmitterView` 使用所属 Canvas 的逻辑坐标域，UI 粒子不使用地图 View。Canvas 缩放只在 UI 合成时应用一次。控件转移到另一个 Canvas 时坐标域发生变化，粒子会重置。

`hierarchy` 把完整宿主和轨道缩放应用于形状、运动和粒子尺寸。`local` 缩放模式移除宿主缩放，保留轨道缩放。`shape` 只把组合缩放应用于出生形状，粒子尺寸与运动保持不缩放。

通过正常 Component 配置为 Actor 的 `emitterComp` 指定 `EmitterComponent`。其归一化边界锚点默认 `[0.5,0.5]`，偏移、旋转和缩放相对于 Actor。`beforeActor = false` 紧接宿主之后绘制，`true` 紧接宿主之前绘制。普通地图和大地图都保留既有 Actor 列表与层顺序，不新增 Y 排序。

把 `Engine.EmitterView` 作为可视化 UI 节点放在现有 Canvas 或 List 容器下，也可以通过代码构造。配置 `particle`、`size`、`anchor`、`autoPlay`，用 `getEmitter()` 取得播放对象。UI 节点继续通过 `ControlBase` 和父节点管理布局与裁剪，不需要 Actor。

每个 Scene 在 UI 更新和布局之后收集活动 Actor 与已挂载可见 UI 的发射器，在渲染前由图形线程对每个实例推进一次。不可见 Actor、休眠大地图 Actor、隐藏 UI 子树和未挂载控件不进入当前帧集合，保留粒子与播放状态。恢复后继续已有状态，不把隐藏期间的移动累计为距离发射；用户手动暂停仍然有效。Actor 销毁、世界区域逐出、地图替换、UI 控件 dispose 或 Scene 结束时，会清空并释放对应发射器。GPU 状态是瞬态数据，不进入地图持久化。

播放控制与原生宿主接入见 [Emitter、EmitterComponent 与 EmitterView API](<../03.Lua 与蓝图脚本/08.全局与 Core 模块/02.Core Modules/01.Engine/08.时间、渲染与粒子.md#emitter>)。

## GPU 支持与性能验收

模拟使用 transform feedback 将粒子状态保留在 GPU 缓冲中，绘制使用实例化纹理四边形。CPU 处理轨道、发射数量、宿主变换与命令，不进行逐粒子 CPU 模拟或同步存活数回读。后端要求 transform feedback、实例化绘制与顶点属性、顶点纹理采样，以及浮点曲线纹理。缺少能力会报运行时错误，不提供 CPU 回退。

桌面构建使用兼容 OpenGL 着色器路径并查询核心/扩展入口。macOS Legacy OpenGL 提供 `EXT_transform_feedback`，但运行时仍需找到其余必要能力，不能据此强制切换 Core Profile。移动 GLES 构建在创建图形资源前请求 OpenGL ES 3。OHOS 使用的 SFML 依赖必须在上下文规范化、EGL 配置选择和上下文创建三处保留 ES 3 请求；强制 ES 2 的依赖无法满足粒子后端。源码联调可通过 [LUDORK_SFML_SOURCE_DIR](<../04.C++ 原生开发/01.构建与模块布局.md#2-构建项目>) 选择外部源码树。

原生宿主必须在 Tick 或绘制前激活兼容的共享 SFML 上下文。游戏与预览使用各自的宿主和上下文，GPU 资源由所在运行时宿主管理。销毁发射器可以把资源放入待释放队列，再由图形线程在有效上下文中回收。渲染器在 SFML 绘制前后保护自身涉及的原生 OpenGL 状态。这些要求参考 [SFML OpenGL 互操作说明](https://www.sfml-dev.org/tutorials/3.1/window/opengl/)、[Khronos OpenGL ES 3.0](https://registry.khronos.org/OpenGL/specs/es/3.0/es_spec_3.0.pdf) 和 [Apple Legacy 着色器扩展文档](https://developer.apple.com/library/archive/documentation/GraphicsImaging/Conceptual/OpenGL-MacProgGuide/opengl_shaders/opengl_shaders.html)。

本机验收目标为 RTX 5080、1920×1080、60 Hz、100,000 个活动粒子：CPU P95 ≤ 1 ms，GPU 模拟加绘制 P95 ≤ 4 ms；另做 1,000,000 粒子的压力测试。这些是验收门槛，不代表未经测量的性能结论。结果应记录硬件/驱动、构建配置、模拟频率、种子、预热与采样时长、轨道、容量、素材尺寸、屏幕覆盖率与混合方式。大面积半透明重叠可能独立于粒子数量成为主要开销。

CPU 提交耗时与异步 GPU 时间分别测量。`getStatistics()` 在 C++ 中返回 `EmitterStatistics` 结构体，在 Lua 中返回固定字段的快照表。`capacity`、`time` 必有；`renderer`、存活数和计时字段为可选值，不可用时在 Lua 中读作 `nil`。`getCapacity()` 和统计中的 `capacity` 表示已启用轨道的容量，不是精确存活数；可用的 `aliveCount` 是以 `sampledTime` 标识时刻的延迟采样。GPU 时间为延迟返回的采样，计时查询不受支持或发生 disjoint 时可能缺失，缺失不等于零。通过 `simulationSample` 和 `drawSample` 确保每个计时结果只统计一次。被测循环不能使用阻塞查询或 `glFinish`。编译通过或 Windows 基准不代表 macOS、iOS、Android、OHOS 真机验收通过。

[2026-09-11 实现与验收报告](../../../Verification/Emitter/2026-09-11/Report.md)记录了 Windows 实测、原始证据及尚待完成的平台/设备检查。

本次粒子功能不包含碰撞、拖尾、噪声与子发射器。

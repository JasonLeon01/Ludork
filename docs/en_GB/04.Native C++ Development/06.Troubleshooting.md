# C++ Binding Troubleshooting

## Scope

Start with the first bindgen or compiler diagnostic. Resolve declaration, generation and runtime-path failures in that order, then rebuild before investigating a later symptom.

## The declaration is not generated

Confirm that the marker is on a public declaration parsed by the module, the header is included by its CMake binding input and the annotation syntax matches an existing example. Rebuild and read the first bindgen diagnostic.

## C++ compiles but Lua cannot find the member

Check the Lua module or canonical function-group path, generated registration
and require order. Classes, ungrouped functions and module properties exist
only at the module root; a grouped function exists only in its group table.

## LuaLS sees a member but Blueprint does not

Check whether the method is intentionally marked `metadata = false`, as used for internal helpers and secondary adapter overloads. Otherwise every logical public `BIND_METHOD` should appear in the generated root `*_meta.lua`; read the bindgen diagnostics and do not add a handwritten duplicate.

## Bindgen reports a duplicate metadata method

Keep the logical Blueprint-facing overload and mark secondary conversion or adapter overloads `metadata = false`. Do not add overload-specific generator branches or allow one declaration to silently replace another.

## Type conversion fails

Use supported primitive, STL, SFML and declared Core types. Include complete cross-module declarations. Add reusable conversion through generic adapters/traits; never make bindgen branch on one business class or member name.

## Metadata default is wrong

Put property/method `Meta` inside its own annotation and use an annotation-native `default` (see [Macro Reference](<04.Macro Reference.md>) and [Generated Metadata and Stubs](<05.Generated Metadata and Stubs.md>)). Rebuild all generated outputs and recheck Blueprint API Reference coverage.

A top-level method/function `default`, `success` or `fail` is rejected with a validation diagnostic that requires `outpins(...)`; the `outpins`/`defaults` distinction and lowercase-token rules follow [Functions, Events and Execution](<03.Functions Events and Execution.md>) and [Macro Reference](<04.Macro Reference.md>).

## Verification

After the correction, rebuild from a clean configuration, compare registration, stub and metadata, and exercise the member through its public Lua path and, where applicable, a Blueprint node.

## Limitations

This page covers declaration and generation faults. Crashes or incorrect behaviour after a member is called require ordinary C++ runtime debugging.

# Native UI Adapters

## Goal

Add a native control to Ludork's declarative UI contract so the runtime, preview host and editor's live control registry describe the same control.

## Prerequisites

- A C++ Source project.
- A native control type and generic adapter operations for construction, property assignment, measurement, arrangement and child attachment.
- Familiarity with the [Declarative UI Runtime Contract](<../03.Lua and Blueprint Scripting/04.Declarative UI/02.Runtime Contract.md>).

## Descriptor contract

System control descriptors are defined in `Engine/Source/Core/include/UI/UiControlAdapterDescriptors.hpp` using the private `BIND_UI_CONTROL` X-macro, not a Core bindgen annotation. Its logical signature is:

```cpp
BIND_UI_CONTROL(TAG, CONTROL_ID, ADAPTER, DISPLAY_NAME, CATEGORY,
                CHILD_POLICY, SLOT_TYPE, ...PROPERTIES)
```

| Argument | Meaning |
|---|---|
| `TAG` | Unique C++ tag used to specialise `UiControlAdapterTraits` |
| `CONTROL_ID` | Stable serialised system-control identifier; use the native class's canonical module-root path |
| `ADAPTER` | Runtime adapter identifier; use the same canonical module-root path |
| `DISPLAY_NAME` | Palette label |
| `CATEGORY` | Palette category |
| `CHILD_POLICY` | `UiChildPolicy::None`, `Single` or `Multiple` |
| `SLOT_TYPE` | `UiControlSlotType::None`, `Canvas` or `List` |
| `...PROPERTIES` | One or more property descriptors |

Properties use one of three descriptor macros. `UI_CONTROL_COMMON_PROPERTY` applies to every control. `UI_CONTROL_PROPERTY` is written to and consumed by the runtime adapter. `UI_CONTROL_EDITOR_PROPERTY` is available only to the editor or preview. Each macro takes `(ID, DISPLAY_NAME, TYPE, REQUIRED, DEFAULT_JSON)`. Plain-text controls use `UI_CONTROL_PLAIN_TEXT_PROPERTIES(DEFAULT_SIZE)`, and rich-text controls use `UI_CONTROL_RICH_TEXT_PROPERTIES`. These groups also determine the expected TextConfig type for editor and packaging validation.

Before exporting descriptors, the native registry validates IDs, property types and defaults, property responsibilities and adapter registration.

For a system control the two path fields must be identical. A bound `Canvas` in Engine therefore uses `Engine.Canvas` for both `CONTROL_ID` and `ADAPTER`. Nested or abbreviated identifiers are invalid.

Read asset JSON as `RuntimeData` and decode each property through its descriptor into `UiControlPropertyValue`. Factories receive the resulting `UiControlProperties` dictionary. Setters receive one typed property value.

Image `drawAs` uses the bound C++ `Image::DrawAs` enum, exported as `Engine.ImageDrawAs`. JSON stores the member name, but native decoding and runtime setters carry the enum itself. A runtime `AssetInstance:setProperty` call therefore passes `Engine.ImageDrawAs.Tile`. Keep the decoder, property-value variant, Inspector enum selector, ScriptTools validation and generated declarations in agreement.

`Engine.WrapBox` declares `UiChildPolicy::Single` and List Slots. Its one authored child is an instantiation template, not a single shared child object. Native asset construction owns each repeated subtree behind an independent instance boundary; generated Views stop at that boundary. Count changes append or release tail instances, and ordinary arrangement preserves them. Preview emits every repetition with the identity of its authored template node, so selecting or editing a repetition still targets the one template.

## Steps

1. Implement the native control.
2. Add one `BIND_UI_CONTROL` entry to `LUDORK_UI_CONTROL_DEFINITIONS`. Choose a stable control ID and specify the exact child policy and Slot type.
3. Declare properties using the existing supported types and resource handling. A new property type also requires changes to the native decoder, editor and ScriptTools.
4. Register the tag in `UiControlAdapterRegistry`. Supply the factory, setter, arranger and child functions required by the descriptor. The registry copies adapter-property IDs from the descriptor.
5. Build the C++ project with the platform `tools/build_cpp` entry point to update the Host and registry and validate UI assets. Controls using supported property types do not require rebuilding the editor or ScriptTools.
6. To validate separately, run:

   ```bash
   ScriptTools ui-adapter-check <project-root>
   ScriptTools ui-assets validate <project-root>
   ```

   `ui-adapter-check` compares the registry with its Host's compiled description without modifying files.

7. Open a representative asset in the UI Asset Editor and verify rendering and interaction.

`Engine.TabView` is the childless Input example: serialise construction and visual resources only, and bind labels and callbacks at runtime. Details are in the [UI Asset Schema and Control Registry](<../03.Lua and Blueprint Scripting/04.Declarative UI/04.Asset Schema and Control Registry.md>) and [Engine: Interactive and Declarative UI Controls](<../03.Lua and Blueprint Scripting/08.Global and Core Modules/02.Core Modules/01.Engine/13.Interactive and Declarative UI Controls.md>).

`Engine.CharacterView` is the childless animated Visual example. Its adapter constructs the native preview state from `size`, texture/Rect, actor scale, animation, Shader and Hue properties. Its class owns cropping, frame advancement and effect composition, while the adapter owns resource-path conversion and property assignment.

## Project preview artifacts

Each project uses its own Host. `EditorCache/UiPreview.json` selects its project-relative runtime directory: `bin/<configuration>` for source builds or `Binaries` for Standalone. The compiled `UiPreviewHost --describe` supplies `EditorCache/UiPreview.registry.json`, shared by the editor and ScriptTools.

Source builds stop existing preview connections before compilation. Preview remains unavailable until the matching Host and registry are published successfully, so C++ UI changes require a rebuild. Later UI asset validation failures leave the new preview available for fixing assets. Standalone can restore missing JSON from its included Host through `ui-preview ensure`. Corrupt or mismatched artifacts are rejected.

## Limitations

Native controls must be added through the project's Core UI source and adapter registration, and they must satisfy the preview runtime's dependency boundary. Editor plug-ins cannot register them through the palette. A control with `UiChildPolicy::None` cannot contain children, and `Single` accepts at most one child.

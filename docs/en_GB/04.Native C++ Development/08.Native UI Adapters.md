# Native UI Adapters

## Goal

Add a native control to Ludork's declarative UI contract so the runtime, preview host and editor's live control registry describe the same control.

## Prerequisites

- A C++ Source project.
- A native control type and generic adapter operations for construction, property assignment, measurement, arrangement and child attachment.
- An understanding of the [Declarative UI runtime contract](<../03.Lua and Blueprint Scripting/05.Declarative UI/02.Runtime Contract.md>).

## Descriptor contract

`BIND_UI_CONTROL` is a private X-macro declared and consumed only in `Engine/Source/Core/include/UI/UiControlAdapterDescriptors.hpp`; it is not a Core bindgen annotation. It has this logical signature:

```cpp
BIND_UI_CONTROL(TAG, CONTROL_ID, ADAPTER, DISPLAY_NAME, CATEGORY,
                CHILD_POLICY, SLOT_TYPE, ...PROPERTIES)
```

| Argument | Meaning |
|---|---|
| `TAG` | Unique C++ tag used to specialise `UiControlAdapterTraits` |
| `CONTROL_ID` | Stable serialised system-control identifier; use the native class's canonical module-root path |
| `ADAPTER` | Runtime adapter identifier; use the same canonical module-root path |
| `DISPLAY_NAME` | Palette label |
| `CATEGORY` | Palette category |
| `CHILD_POLICY` | `UiChildPolicy::None`, `Single` or `Multiple` |
| `SLOT_TYPE` | `UiControlSlotType::None`, `Canvas` or `List` |
| `...PROPERTIES` | One or more property descriptors |

Properties use one of three descriptor macros. `UI_CONTROL_COMMON_PROPERTY` applies to every control, `UI_CONTROL_PROPERTY` is written to and consumed by the runtime adapter, and `UI_CONTROL_EDITOR_PROPERTY` is available only to the editor or preview. Each declaration provides an ID, schema type, required flag and JSON default.

For a system control the two path fields must be identical. A bound `Canvas`
in Engine therefore uses `Engine.Canvas` for both `CONTROL_ID` and `ADAPTER`;
nested or abbreviated identifiers are invalid.

Read asset JSON as `RuntimeData` and decode each property through its descriptor into `UiControlPropertyValue`. Factories receive the resulting `UiControlProperties` dictionary; setters receive one typed property value.

## Steps

1. Implement the native control.
2. Add one `BIND_UI_CONTROL` entry to `LUDORK_UI_CONTROL_DEFINITIONS`. Choose a stable control ID and specify the exact child policy and Slot type.
3. Declare supported properties using the existing property conversion and resource handling. Extend the decoder and `UiControlPropertyValue` when adding a new reusable property type.
4. Register the tag in `UiControlAdapterRegistry`. Supply the factory, setter, arranger and child functions required by the descriptor. The registry copies adapter-property IDs from the descriptor.
5. If the control adds an editor-facing adapter, update the matching editor descriptor through the shared contract.
6. Validate descriptors and UI assets:

   ```sh
   ScriptTools ui-adapter-check .
   ScriptTools ui-assets validate Sample
   ```

7. Build the project and open a representative asset in the UI Asset Editor and preview host.

`Engine.TabView` is the childless Input example: serialise construction and visual resources only, and bind labels and callbacks at runtime. Details are in [Asset Schema and Control Registry](<../03.Lua and Blueprint Scripting/05.Declarative UI/04.Asset Schema and Control Registry.md>) and [Interactive and Declarative UI Controls](<../03.Lua and Blueprint Scripting/07.API Reference/04.Core Modules/02.Engine/13.Interactive and Declarative UI Controls.md>).

`Engine.CharacterView` is the childless animated Visual example. Its adapter constructs the native preview state from `size`, texture/Rect, actor scale, animation, Shader and Hue properties; its class owns cropping, frame advancement and effect composition, while the adapter owns resource-path conversion and property assignment.

## Limitations

`BIND_UI_CONTROL` describes native runtime controls; it is not an editor plug-in extension point. Editor plug-ins cannot add controls to the host-owned UI Asset Editor palette. A control with `UiChildPolicy::None` cannot contain children, and `Single` accepts at most one child.

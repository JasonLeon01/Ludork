# Binding a Class

## Goal

Expose one C++20 class consistently to native Lua, LuaLS and the Blueprint metadata catalogue.

## Prerequisites

- The owning module and dependency direction are already selected.
- The class has a public header and implementation under that module.

## Steps

### 1. Declare the class

```cpp
#pragma once
#include <BindAnnotations.hpp>
#include <string>

BIND_CLASS()
class Counter {
public:
  BIND_INIT()
  explicit Counter(int initial = 0);

  BIND_PROPERTY()
  int value = 0;

  BIND_METHOD(Pure = true)
  int getValue() const;

  BIND_METHOD()
  void add(int amount);
};
```

Place the header under the owning module's `include/` tree and the implementation under its `src/` tree:

```cpp
#include "Counter.hpp"

Counter::Counter(int initial) : value(initial) {}

int Counter::getValue() const {
  return value;
}

void Counter::add(int amount) {
  value += amount;
}
```

The module CMake files discover `include/**/*.hpp` and `src/**/*.cpp`; no per-file source-list edit is required. Reconfigure or rebuild so bindgen can emit the registration source, `Scripts/stub/<Module>.d.lua` and the applicable root metadata. For a class placed in `Engine`, Lua can then use:

```lua
local Engine = require("Engine")
local Logging = require("Global.Utils.Logging")

local counter = Engine.Counter.new(4)
counter:add(3)
Logging.info(counter:getValue())
```

The module root is the class's only public runtime location. `name` selects the
Lua identifier for that root field. Do not create a second table path for the
same native class.

Every logical public `BIND_METHOD` enters editor metadata by default. Mark an internal method or a secondary adapter overload as `metadata = false` when it must remain available to native Lua and LuaLS without creating another Blueprint node:

```cpp
BIND_METHOD(metadata = false)
void _updateCache();
```

The flag does not remove runtime registration or the LuaLS stub. Two non-excluded methods in the same type cannot expose the same metadata name.

### 2. Declare properties

`BIND_PROPERTY()` exposes a data member. Safe boolean, numeric, string and `{}` initialisers can become metadata defaults. Use annotation-native pure data for an explicit default. Put property editor semantics that cannot be inferred from the type inside `BIND_PROPERTY(meta(...))`.

```cpp
BIND_PROPERTY(
    default = {0.0, 0.0})
sf::Vector2f defaultOrigin{0.0f, 0.0f};
```

Positional entries form arrays and named entries form objects. This is annotation syntax read by bindgen, so it does not need to be a valid C++ expression. The same singular `default` syntax applies to a getter-backed property declared with `BIND_METHOD(property = ...)`.

Structured pure-data values inside `meta(...)` use the same brace DSL. Either form may be nested:

```cpp
BIND_PROPERTY(
    meta(Rely = {source = "autoSound", op = "!=", value = ""}))
float autoSoundInterval = 0.0f;

BIND_METHOD(defaults = {{}},
            meta(MoveRouteVars = {"route"}),
            outpins(default = nil))
void setRoute(
    const std::optional<std::vector<sf::Vector2i>>& route = {});
```

Use lowercase `true` and `false` in this data. Structured metadata cannot contain `nil`, because a Lua table cannot preserve a nil field or array slot; `nil` remains valid only for protocol tokens such as `defaults`, `outpins(...)` and `latent(...)`. Arrays and objects in `meta(...)` must use the brace DSL and must not quote the complete value. Scalar string values such as `meta(PathVars = "Sounds")` and property defaults such as `default = "true"` remain strings. Property defaults do not accept stringified JSON arrays or objects.

Ordinary properties and methods do not declare `DisplayName` or `DisplayDesc`. The editor formats identifiers automatically, so `defaultOrigin` is displayed as `Default Origin` while the C++ and Lua member name remains `defaultOrigin`. A true operator alias may use a direct literal display name such as `+`; it must not use `LOC(...)` or a default description.

A no-argument getter can expose a property:

```cpp
BIND_METHOD(property = "volume", setter = "setVolume")
float getVolume() const;

void setVolume(float value);
```

The getter return type becomes the property type unless `type` overrides it. This form exposes one property and does not also expose getter/setter nodes.

### 3. Review constructors and exclusions

`BIND_INIT` marks constructors. `BIND_IGNORE` excludes declarations from binding entirely; `BIND_METHOD(metadata = false)` excludes only method metadata. Use `BIND_CLASS_PROPERTY` for class-level values and `BIND_MODULE_PROPERTY` for module-level values.

## Expected result

The class is registered at one stable Lua path, appears in the generated stub, and exposes exactly its intended Blueprint properties and methods.

## Verification

Rebuild, instantiate the class from Lua, inspect `Scripts/stub/<Module>.d.lua` and the applicable root `*_meta.lua`, then confirm no generated output changes on a second unchanged build.

## Limitations

Bindgen does not infer project-specific conversion rules or resolve incomplete cross-module types. Getter-backed properties expose one property, not separate getter and setter nodes.

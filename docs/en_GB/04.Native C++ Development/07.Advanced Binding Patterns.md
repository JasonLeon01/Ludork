# Advanced Binding Patterns

For engine infrastructure that cannot be represented by the ordinary class, property, method and free-function workflow.

## Class metadata decorators

Class decorators are nested in the owning class annotation:

```cpp
BIND_CLASS(callbacks = true,
           invalid_vars(defaultRect, internalState),
           rect_range_vars(defaultRect = texturePath))
class Character : public Actor {
public:
  BIND_METHOD(metadata = false)
  virtual void _applyDirection(float x, float y);
};
```

`invalid_vars(...)` hides fields and `rect_range_vars(...)` links rectangles to resource/range fields. Both accept ordered identifiers only inside `BIND_CLASS`; property-specific rectangle semantics remain `meta(RectRangeVars = "texturePath")` in `BIND_PROPERTY`. `metadata = false` does not disable a callback; use `callback = false`. See [Binding a Class](<02.Binding a Class.md>).

Member-level editor decorators stay inside their owning annotation. Structured values use brace data rather than a complete JSON string:

```cpp
BIND_PROPERTY(
    meta(Rely = {source = "autoSound", op = "!=", value = ""}))
float autoSoundInterval = 0.0f;

BIND_METHOD(defaults = {{}},
            meta(MoveRouteVars = {"route"}),
            outpins(default = nil))
void setRoute(
    const std::optional<std::vector<sf::Vector2i>>& route = {});
```

The first value is an object because it has named entries; the second is an array because its entries are positional. Full brace syntax and quoted-JSON rejection follow [Macro Reference](<04.Macro Reference.md>).

## Events, latent work and loops

```cpp
BIND_REGISTER_EVENT()
BIND_METHOD()
virtual void onCreate();

BIND_METHOD(latent(TimeUp = true),
            defaults = {nil, nil, {}, false},
            parameter_types = {float, function, any[], bool})
TimerHandle addTimer(float interval,
                     RuntimeIdentityPtr task = {},
                     RuntimeValue::Array params = {},
                     bool blocking = false);

BIND_METHOD(loop_node(ForEach))
void forEach(const RuntimeValue::Array &values);
```

Event, inline latent and loop annotations generate execution metadata; the C++/Lua implementation must still carry out the promised runtime protocol (see [Functions, Events and Execution](<03.Functions Events and Execution.md>)).

## Values, reverse maps and helpers

```cpp
BIND_MODULE_PROPERTY()
extern std::string LANGUAGE;

class FocusTransition {
public:
  BIND_CLASS_PROPERTY(readonly = true)
  static const std::string DIRECTIONAL;
};

BIND_LUA_REVERSE(path = "Input.KeyName", source = "sf.Keyboard.Key")
BIND_LUA_HELPER(kind = "cast", path = "Cast")
```

Module properties are exposed at the module root and class properties on their
own class. Bindgen does not duplicate an existing Lua value under another
runtime path. Reverse declarations create a new reverse-name lookup at their
declared canonical path; helpers use generic native support. The `eval` helper
evaluates only its caller's expression, with optional locals taking precedence
over runtime globals. A missing or empty expression returns `nil`; non-empty
evaluation is synchronous and raises when called from a yieldable coroutine.

## Initialisation, injection and value traits

```cpp
BIND_MODULE_INIT()
void initialiseRuntimeServices(lua_State *state);

BIND_INJECT(global = "_LUDORK_BLUEPRINT_EVENT_VALIDATOR")
void setBlueprintEventValidator(BlueprintEventValidator validator);

BIND_CLASS(opaque_identity = true)
class RuntimeIdentity {};

BIND_CLASS(dynamic_value = true)
class RuntimeValue {};
```

`BIND_MODULE_INIT` runs while opening the module. `BIND_INJECT` connects a Lua global callback to a C++ setter and is valid only while that Lua state remains available. With `variadic = true`, the setter must accept `std::function<std::vector<T>(Fixed..., const std::vector<T>&)>`; zero returns and interior or trailing `nil` remain distinct without envelope tables. The two `BIND_CLASS` flags select conversion/identity traits and cannot combine with incompatible table-value modes. Engine subsystems use typed runtime façades and fixed provider slots, not a generic string operation dispatcher.

## Limitations

Bindgen must remain declaration-driven. Do not introduce generator branches keyed to a gameplay module, class or member name, and do not use an infrastructure marker to bypass an unsupported conversion.

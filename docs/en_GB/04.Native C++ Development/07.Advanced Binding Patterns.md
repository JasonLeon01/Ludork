# Advanced Binding Patterns

## Scope

Use these patterns only for engine infrastructure that cannot be represented by the ordinary class, property, method and free-function workflow.

These declarations are mainly for engine infrastructure. Prefer ordinary class, property, method and function annotations until a lower-level pattern is actually required.

## Class metadata decorators

Decorators immediately before a class or member are folded into the same generated metadata entry:

```cpp
BIND_INVALID_VARS(vars = "defaultRect,internalState")
BIND_RECT_RANGE_VARS(defaultRect = texturePath)
BIND_CLASS(callbacks = "MapMove,_animate")
class Character : public Actor {
  // ...
};
```

`BIND_INVALID_VARS` lists fields hidden from ordinary Blueprint editing. `BIND_RECT_RANGE_VARS` relates rectangle fields to the resource/range fields used by the editor. Callback and base options belong on `BIND_CLASS`; the class itself has only its module-root path.

Member-level editor decorators stay inside their owning annotation. Structured values use brace data rather than a complete JSON string:

```cpp
BIND_PROPERTY(
    meta(Rely = {source = "autoSound", op = "!=", value = ""}))
float autoSoundInterval = 0.0f;

BIND_METHOD(defaults = {{}},
            meta(MoveRouteVars = {"route"}),
            outpins(default = nil))
void setRoute(
    const std::optional<std::vector<sf::Vector2i>>& route = {});
```

The first value is an object because it has named entries; the second is an array because its entries are positional. The forms may be nested. All `meta(...)` arrays and objects use this brace DSL. Complex property defaults use the same DSL in `BIND_PROPERTY(default = {...})` or a getter-property `default`; quoted JSON arrays and objects are rejected there.

## Events, latent work and loops

```cpp
BIND_REGISTER_EVENT()
BIND_METHOD()
virtual void onCreate();

BIND_METHOD(latent(TimeUp = true),
            defaults = {nil, nil, {}, false},
            parameter_types = {float, function, any[], bool})
TimerHandle addTimer(float interval,
                     RuntimeIdentityPtr task = {},
                     RuntimeValue::Array params = {},
                     bool blocking = false);

BIND_LOOP_NODE(ForEach)
BIND_METHOD()
void forEach(const RuntimeValue::Array &values);
```

Event, inline latent and loop annotations generate execution metadata; the C++/Lua implementation must still implement the promised runtime protocol. Execution protocol values use lowercase `nil`, `true` and `false`.

## Values, reverse maps and helpers

```cpp
BIND_MODULE_PROPERTY()
extern std::string LANGUAGE;

class FocusTransition {
public:
  BIND_CLASS_PROPERTY(readonly = true)
  static const std::string DIRECTIONAL;
};

BIND_LUA_REVERSE(path = "Input.KeyName", source = "sf.Keyboard.Key")
BIND_LUA_HELPER(kind = "cast", path = "Cast")
```

Module properties are exposed at the module root and class properties on their
own class. Bindgen does not duplicate an existing Lua value under another
runtime path. Reverse declarations create a new reverse-name lookup at their
declared canonical path; helpers create one of bindgen's generic helper kinds.

## Initialisation, injection and value traits

```cpp
BIND_MODULE_INIT()
void initialiseRuntimeServices(lua_State *state);

BIND_INJECT(global = "_LUDORK_RUNTIME_RESOLVER")
void setRuntimeResolver(RuntimeResolver resolver);

class RuntimeIdentity {
public:
  BIND_OPAQUE_IDENTITY_TYPE();
};

class RuntimeValue {
public:
  BIND_DYNAMIC_VALUE_TYPE();
};
```

`BIND_MODULE_INIT` runs a declared initialiser while opening the module. `BIND_INJECT` connects a supported Lua global callback to a C++ setter. Dynamic-value and opaque-identity traits select generic conversion/identity rules; they are not ordinary usertypes and cannot be combined with incompatible table-value modes.

## Verification

Build every module that consumes the declaration, inspect the generated registration and stub path, and add a focused runtime test for the generic adapter or identity rule.

## Limitations

Bindgen must remain declaration-driven. Do not introduce generator branches keyed to a gameplay module, class or member name, and do not use an infrastructure marker to bypass an unsupported conversion.

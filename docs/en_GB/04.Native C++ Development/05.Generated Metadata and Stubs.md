# Generated Metadata and Stubs

## Scope

Use this page to understand and verify the outputs produced from public binding declarations. Generated files are build artefacts and must not be edited by hand.

One declaration feeds three consumers:

1. generated sol2 registration used by the native Lua module;
2. `Scripts/stub/<Module>.d.lua` used by Lua language tooling;
3. `Scripts/<Module>_meta.lua` used by the editor, including the generated Engine, GlobalCore and GlobalFunctions catalogues (the CoreSystem metadata catalogue is empty).

These outputs must agree on the one canonical module path, class name, function group and parameter order. Metadata additionally carries Blueprint execution and editor information.

Every logical public `BIND_METHOD` is included in metadata. `metadata = false` is reserved for internal helpers and secondary adapter overloads; it leaves the native registration and LuaLS stub intact. Bindgen rejects duplicate exposed method names within one type instead of silently overwriting an entry.

Generated stubs declare each bound class, ungrouped function and module property
only at its module-root path. A class such as `ListView` is therefore available
as `Engine.ListView`, with no generated nested field, duplicate value assignment
or runtime-path type alias. A file-level `BIND_FUNCTION_GROUP` declaration owns
the group table, and grouped functions appear only in that table. Do not add
handwritten duplicate paths.

Core bindgen preserves complete multiline `///` documentation, including blank paragraphs and command lines, for ordinary and `Pure = true` members. It converts recognised Doxygen commands such as `\brief`, `\param`, `\return`, `\see`, `\code`/`\endcode`, warnings and inline formatting commands to the corresponding `@` form in `.d.lua`; unrelated backslashes, including path content, remain unchanged. LuaSF uses the same rule when it emits `Scripts/stub/LuaSF.d.lua`.

## Defaults and types

Bindgen may derive defaults only from safe boolean, numeric, string or empty-table member initialisers. Explicit complex defaults use annotation-native brace data; quoted JSON arrays and objects are rejected. Core object references use the full module/type pair. Arrays append `[]` to the type item.

LuaSF exports an absolute `LUASF_CALLBACK_CODECS_FILE` CMake path. Core bindgen consumes that schema-versioned manifest for callback aliases whose Lua calling convention differs from their canonical `std::function` type. Selection uses the declared semantic alias before canonical expansion; an unrelated alias with the same C++ signature does not inherit the codec. The manifest supplies the codec, named Lua type and exact Lua signature, so neither Core binding code nor ScriptTools contains an SFML callback-signature table. Codec-aware conversion composes recursively through `vector`, `array`, `optional`, `variant`, `pair`, `map` and `tuple` parameters and returns while preserving the callback policy at each leaf. A missing manifest or adjacent `sfml_api.json`, unsupported schema, duplicate selector, direction mismatch or disallowed `nil` stops generation. The generated codec use also asserts the alias against both the manifest and LuaSF API canonical types, so a stale canonical type stops compilation before the binding is available.

## Regeneration

Run the normal CMake build. If output appears stale, confirm that the annotated header belongs to the module's configured public-header set, inspect generator diagnostics and rebuild from the project's build directory. Do not patch an emitted file: the next build will replace it.

The pages in Blueprint API Reference are an inventory of metadata, not a replacement for LuaLS stubs. Members explicitly marked `metadata = false` remain available to scripts but absent from the node catalogue.

## Expected result

Registration, stubs and metadata agree on paths and signatures, and an unchanged rebuild produces no tracked generated differences.

## Verification

Compare the runtime path, LuaLS declaration and metadata entry for every changed public member. For a manifest-selected callback, also compare the alias at the C++ use site, generated codec call and named type from `LuaSF.d.lua`; do not accept an inlined `fun(...: any): any` substitute. Confirm that multiline documentation remains intact and no recognised Doxygen command retains its backslash prefix. Run the module's bindgen validation and then perform a second unchanged build.

## Limitations

Blueprint metadata intentionally omits members marked `metadata = false`; this is not generation drift. Generated references document declarations, not the runtime correctness of their implementations.

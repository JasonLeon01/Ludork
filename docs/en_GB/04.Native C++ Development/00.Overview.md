# Native C++ Development

Use C++ Source projects when Lua and Blueprint APIs are insufficient, when a new native UI adapter is required, or when producing an iOS, HarmonyOS or Android build. The runtime uses C++20, CMake and declaration-driven bindings.

## Development sequence

1. [Build and Module Layout](<01.Build and Module Layout.md>)
2. [Binding a Class](<02.Binding a Class.md>)
3. [Functions, Events and Execution](<03.Functions Events and Execution.md>)
4. [Macro Reference](<04.Macro Reference.md>)
5. [Generated Metadata and Stubs](<05.Generated Metadata and Stubs.md>)
6. [Troubleshooting](<06.Troubleshooting.md>) and [Advanced Binding Patterns](<07.Advanced Binding Patterns.md>)
7. [Native UI Adapters](<08.Native UI Adapters.md>)

One public declaration must drive C++ registration, LuaLS stubs and editor metadata. Never patch generated outputs or add generator branches keyed to a gameplay module, type or member name.

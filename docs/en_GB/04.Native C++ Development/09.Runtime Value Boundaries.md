# Runtime Value Boundaries

Choose a type from the values the API accepts and the ownership it requires.

| Requirement | Type |
|---|---|
| Fixed fields or a fixed set of named choices | A struct, enum or concrete C++/SFML type |
| A finite choice of value types | `std::variant<T...>` |
| A value that may be absent | `std::optional<T>`; use `std::monostate` when nil is a variant alternative |
| Recursive JSON-compatible data without a VM | `RuntimeData` |
| Ownership of a known native object | A typed pointer, with shared or weak ownership as required |
| Open script values, including native objects and references | `RuntimeValue` |
| Lua identity for equality, subscriptions or later calls | `RuntimeHandle` or `RuntimeIdentityPtr`, tied to one session |

Use `RuntimeValue` for open script boundaries such as event payloads, Blueprint pins and shared gameplay contexts. Convert to a concrete type before entering an algorithm with a fixed contract. Keep absence distinct from zero and from empty containers.

## Lua value conversion

Direct Lua calls pass a `std::variant` alternative as its actual value, without a wrapper. Lua integers prefer integer alternatives, and floating-point numbers prefer floating-point alternatives. Fractional numbers are never truncated into integers. Strings and booleans require their actual Lua types. Native SFML types remain distinct even when their values have the same shape.

Pure-data conversion, used by `RuntimeData` and `BIND_CLASS(pure_data = true)`, accepts nil, the registered JSON-null sentinel, booleans, finite numbers, strings, acyclic arrays and string-keyed maps. It rejects functions, native objects, cycles, invalid keys and unrecognised metatables.

An empty Lua `{}` is a map, while `{ n = 0 }` is an empty array. A non-negative integer `n` preserves array length and nil holes, and emitted arrays include it. Registered JSON array metatables are accepted. Map null entries use the registered JSON-null sentinel to preserve their keys.

## Native object wrappers

Returning a shared native object first reuses its existing Lua owner. After that wrapper is collected, sources exposing the [native Cast protocol](<04.Macro Reference.md#native-cast-declarations>) select a registered writer through `ludorkDynamicTypeKey()`. The writer receives the source's static type key and an aliasing shared pointer to its subobject. Generated conversion bases permit statically checked pointer recovery, including nonzero multiple-inheritance offsets, while preserving the original control block.

A missing writer or unsupported source uses an ordinary static-type wrapper. This includes an external base such as `sf::Drawable` with neither a Cast protocol nor an existing Lua owner. Non-polymorphic value types use their declared static type without dynamic-writer registration.

The wrapper registers the exposed type and all conversion-base subobject addresses to preserve repeated Lua object identity. Lua callback adapters release captured references through the Cast protocol. Opaque Lua references retain their original value and follow the [session lifetime rules](<#lua-references-and-session-lifetime>).

## Containers and views

`RuntimeData` owns VM-independent data, and copies detach on mutation. `RuntimeValue` can also own native objects without a VM or hold session-bound Lua handles. Its `Array` is `std::vector<RuntimeValue>`, and `Map` is `std::unordered_map<std::string, RuntimeValue>`. Construction from `RuntimeData` shares its containers, while the Array and Map constructors take ownership.

Read containers through `value.view().array()` or `.map()`, which return optional borrowed views. Array indexing and iteration yield `RuntimeValueView`, and Map `find` distinguishes a missing key from a stored nil. The source must remain alive and unmodified while a view or borrowed string is in use. Views cannot be acquired from temporary owning values. Use `toValue()`, `toArray()` or `toMap()` when ownership is required.

`getMutableIf<Array/Map>()` materialises or detaches the container being modified. `toData()` shares an existing Data branch or converts bridge containers recursively, rejecting native objects and handles.

## Lua references and session lifetime

Ordinary argument and result passing preserves `RuntimeValue` directly. Use `<Runtime/RuntimeReference.hpp>` for explicit conversion and Lua-reference operations:

| Operation | Behaviour |
|---|---|
| `intern` | Obtains the handle required by `get`, `set` and `invoke`; reuses an existing handle or creates a new Lua table from an owning container |
| `retain` | Keeps scalars and existing non-scalar handles; converts owning containers to new Lua tables |
| `snapshot` | Copies ordinary acyclic arrays or string-keyed maps, preserving nested function/object references; other tables and opaque-identity bindings keep their identity |
| `data` | Converts to pure data, rejecting native objects and references that cannot be converted |

Snapshot conversion preserves array length through `n`, and nil map fields are omitted. It is separate from class and instance default cloning.

Calls preserve all return values, including intermediate and trailing nil, and propagate errors. Handles cannot cross VMs and become invalid when their session closes. An empty handle or identity pointer becomes nil when wrapped in `RuntimeValue`.

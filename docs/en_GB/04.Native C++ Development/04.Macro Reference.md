# Macro Reference

Select the declaration marker for a supported binding or native UI adapter. Detailed option syntax is on the task and advanced-pattern pages.

| Macro | Purpose |
|---|---|
| `BIND_CLASS` | Declare a bound class and its unique module-root name; `callbacks = true` selects this class's non-static virtual bound methods for C++-to-Lua dispatch |
| `BIND_ENUM` | Expose a scoped C++ enum as one module-root Lua table and LuaLS type |
| `BIND_FUNCTION` | Bind a free function; `outpins(...)` and `latent(...)` are inline options |
| `BIND_FUNCTION_GROUP` | Put all bound free functions in a header into one table |
| `BIND_METHOD` | Bind a method or getter-backed property; methods enter metadata unless `metadata = false`, and `callback = false` excludes a virtual method from its class's automatic callback selection |
| `BIND_PROPERTY` | Bind an instance data property |
| `BIND_INIT` | Bind a constructor |
| `BIND_REGISTER_EVENT` | Register a Blueprint event entry |
| `BIND_INJECT` | Inject declaration-driven binding code at a supported point |
| `BIND_MODULE_PROPERTY` | Expose a module-level property |
| `BIND_CLASS_PROPERTY` | Expose a class-level property |
| `BIND_LUA_REVERSE` | Describe reverse Lua/C++ adaptation |
| `BIND_LUA_HELPER` | Declare a reusable Lua binding helper |
| `BIND_MODULE_INIT` | Add module initialisation behaviour |

Leave unexposed declarations unmarked. `BIND_CLASS(dynamic_value = true)` and `BIND_CLASS(opaque_identity = true)` select the generated conversion traits. Class decorators such as `invalid_vars(...)` and `rect_range_vars(...)` belong inside `BIND_CLASS`; loop protocols use inline `loop_node(...)`, while `BIND_REGISTER_EVENT()` remains standalone.

`BIND_METHOD(...)` and the other variadic annotation markers expand to nothing in the C++ compiler. Bindgen reads their raw token sequences, so annotation-only tokens such as `outpins(...)`, `loop_node(...)`, `nil`, `function` and `{nil, false}` do not need C++ expression or type meaning and must not be quoted merely to satisfy C++ parsing. Named execution branches use `outpins(...)`, latent states use `latent(...)`, and protocol values use lowercase `nil`, `true` and `false`. Ordered `defaults` and `parameter_types` values use brace-enclosed token lists for methods and free functions, and constructor `defaults` uses the same form. Structured `meta(...)` data and singular property `default` values also use braces: positional entries form arrays such as `default = {0.0, 0.0}`, and named entries form objects such as `meta(Rely = {source = "autoSound", op = "!=", value = ""})`; nesting is allowed. Complete arrays and objects must not be quoted as JSON. Use the annotation form already established by neighbouring declarations. Extra conversion capability belongs in the self-contained feature headers under `LudorkCoreBinding/`; bindgen selects those headers from the generated signatures and must not add business-name special cases.

`BIND_CLASS` infers declared bases; `cast_bases = {"BaseA", "BaseB"}` supplies ordered extra ancestors, not a comma-separated string.

`BIND_ENUM` binds an `enum class` to one module-root table. LuaLS retains the enum type, while Lua values and Blueprint metadata signatures use integers; `name` may replace the table identifier.

Bound classes, ungrouped functions and module properties use exactly one
module-root path; grouped functions use their group table.
`BIND_INJECT(global = ...)` uses `global` as the injection-source identifier. `variadic = true` is restricted to matching vector-in/vector-out `std::function` injection and maps the trailing vector directly to Lua stack arguments and results.

## Limitations

The table identifies supported markers, not every permitted option combination. `Pure`, execution protocols and property declarations remain subject to the validation rules on their dedicated pages.

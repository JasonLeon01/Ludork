# Classes, Defaults and Lifecycle

## Goal

Define a Ludork class whose public defaults are discoverable and inheritable, while keeping mutable runtime state independent for every instance.

## Prerequisites

- The required root modules loaded in their documented order.
- Every base already finalised as a Ludork class or registered native type.

## Steps

1. Create a plain definition table and place public defaults and methods on it.
2. Implement `init` only for constructor inputs and per-instance state.
3. Call required native-base initialisers and use `copy` or `deepcopy` for mutable defaults.
4. Return `class(definition, ...)` with bases in the intended C3 order.
5. Construct multiple instances and verify inheritance and state isolation.

## Define a class

Create a plain definition table, place class defaults and methods on it, then finalise it with `class(definition, ...)`:

```lua
local Engine = require("Engine")

local Actor = Engine.Actor

local Pickup = {}

Pickup.count = 1
Pickup.sound = ""

function Pickup:init(texture, tag)
    Actor.init(self, texture, tag)
    self._collected = false
end

return class(Pickup, Actor)
```

The definition must be a plain table without a metatable and must not already be finalised. Each additional argument is a finalised Ludork class or a registered native type. Duplicate bases are rejected. The runtime computes a C3 method-resolution order, so base order is significant.

## Class defaults and instance state

Editable, inheritable values form the Class Default Object and must exist on the definition table before finalisation. This includes metadata fields, component defaults, `default*` spawn values and identifiers intended for class or Blueprint override.

`init` is for constructor arguments and state that must belong to one instance. Initialise mutable private tables and lifecycle flags there. Use `copy` or `deepcopy` when an instance needs an independent copy of a mutable class default.

```lua
local RouteFollower = {}

RouteFollower.speed = 96.0
RouteFollower.defaultRoute = {}

function RouteFollower:init()
    self._route = deepcopy(self.defaultRoute)
    self._routeIndex = 1
end

return class(RouteFollower)
```

Do not move a public default into `init`: subclasses and Blueprint discovery must be able to read it from the class.

## Construction and lifecycle

Call `Type.new(...)` to create an instance. Finalised classes are also callable, but project code should follow the style used by neighbouring modules. `init` receives the new instance as `self`. A class with no `init` accepts no arguments unless its single native root supplies the constructor contract.

For a native base, invoke the required base initialiser explicitly from `init`. Implement lifecycle callbacks such as `onCreate`, `onTick`, `onDestroy` or `dispose` only when the owning runtime contract calls them.

## Inheritance and super calls

Use `super()` inside a method to resolve the next implementation from the defining class. When a callback or indirect call makes the owner ambiguous, use `super(ClassName, self)`. Explicit base calls, such as `Actor.init(self, ...)`, remain appropriate for constructors and deliberate composition.

Multiple inheritance is supported. The Sample `Player` finalises its definition with native `Character` and script `PlayerInfo` and `Battler` bases. Keep the declared base order stable because it determines method resolution.

## Class utilities

| API | Purpose |
|---|---|
| `Class.isInstance(value, targetClass)` | Test an instance against its complete MRO. |
| `Class.isSubclass(value, targetClass)` | Test a class against its complete MRO. |
| `Class.type(value)` | Return the Ludork class or native type fallback. |
| `Class.hasOwnField(value, key)` | Check whether a field is stored directly. |
| `Class.getMro(value)` | Return a detached MRO array. |
| `Class.constructNamed(type, arguments)` | Match named values to `init` parameters and construct. |
| `Class.monitor` / `Class.unmonitor` | Observe and remove field monitoring. |

## Verification

- Every public default is visible on the class table before construction.
- Every private mutable state value is independently initialised per instance.
- Base calls execute in the intended C3 order.
- `Class.isInstance` and `Class.isSubclass` succeed for all declared bases.

## Limitations

Duplicate bases, unfinalised bases and ambiguous class ownership are rejected. A Direct Script Mixin follows its own lifecycle contract and must not declare `init`.

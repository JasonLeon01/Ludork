# Declarative UI Validation and Packaging

## Goal

Validate path-based UI declarations, compare native preview with runtime, and package assets without editor-only preview data.

## Validate after external changes

When UI JSON changes outside the editor, run:

```text
ScriptTools ui-assets validate <project-root>
ScriptTools ui-adapter-check <repo-root>
```

Both checks are read-only. No index file is generated. Native builds run the same asset and adapter checks and stop on invalid schema, paths or descriptors.

## Validation layers

Save, native preview, Run and Pack enforce the same core contracts described on the [Asset Schema and Control Registry](<04.Asset Schema and Control Registry.md>) page, and reject fields outside the asset schema, asset UUID fields, UUID project references and alias paths.

## Native preview and packaging

Preview requires a compatible protocol and system adapter fingerprint. The render request sends the root asset key and logical-keyed dependency snapshots; it does not send or read a catalogue.

Packaging works in a staging copy. It validates the staged assets, recursively removes every `editor` object, compiles/encrypts data as configured and leaves source assets unchanged. JSON development data and packaged `.ldc` data use the same extension-free logical key.

## Release verification

1. Run both read-only checks without source changes.
2. Open every top-level asset in native preview.
3. Run each owning Scene/window and compare layout, text refresh and input.
4. Package, then run the packaged result at every supported logical size.
5. Confirm the package contains no generated UI index and no development-machine path.

Fallback preview and a successful build are not proof of live runtime parity; report Preview, Run and Pack acceptance separately.

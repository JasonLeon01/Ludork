# Declarative UI Validation and Packaging

## Goal

Validate path-based UI declarations, compare native preview with runtime, and package assets without editor-only preview data.

## Validate after external changes

When UI JSON changes outside the editor, run:

```text
ScriptTools ui-assets validate <project-root>
ScriptTools ui-adapter-check <repo-root>
```

Both checks are read-only. No index file is generated. Native builds run the same asset and adapter checks and stop on invalid schema, paths or descriptors.

## Validation layers

Save, native preview, Run and Pack enforce the [asset schema](<04.Asset Schema and Control Registry.md>), rejecting unknown fields, duplicate asset-local node names and alias paths.

## Native preview and packaging

Preview requires a compatible protocol and system adapter fingerprint. The render request sends the root asset key and logical-keyed dependency snapshots; it does not send or read a catalogue.

Packaging validates a staging copy, removes `editor` data and applies configured compilation, encryption or archiving without changing the source project. JSON, `.ldc` and packed Data keep the same extension-free UI keys; packed controllers keep their logical module paths.

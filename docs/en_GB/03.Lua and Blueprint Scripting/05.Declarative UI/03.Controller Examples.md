# Declarative UI Controller Examples

A window module contains one private business Controller and exports its UI class. The framework constructs and binds the generated View; developers add the behaviour they need.

## Start with the unchanged template

Put this in `Scripts/Source/Windows/WindowInventory.lua` for an existing `Inventory.json`:

```lua
local Ui = require("Source.UIBase.Ui")
local InventoryView = require("Source.UI.Inventory")

local Controller = {}

return Ui.DefineWindow(InventoryView, Controller)
```

The Scene creates and registers it:

```lua
local WindowInventory = require("Source.Windows.WindowInventory")

local window = WindowInventory.new():mount(uiManager)
```

The window displays the template's content and dimensions. Keep it on its owner and call `window:dispose()` when no longer needed.

## Replace content and react to a field

Assume `Inventory.json` contains `WindowFrame`, `Content`, and `Engine.PlainText` nodes named `Title` and `Count`. Extend the same window module with its business behaviour:

```lua
local LocaleCore = require("Source.Locale.Core")
local Ui = require("Source.UIBase.Ui")
local InventoryView = require("Source.UI.Inventory")
local WindowBase = require("Source.Windows.Base.WindowBase")

---@class Source.Windows.WindowInventory.Controller
local Controller = {}

Controller.windowOptions = { centered = true, returnButton = true }

function Controller:init(inventory)
    self.model = inventory
    self.view:setText("Title", LocaleCore.ApplyStringLocaleFormat("INVENTORY_TITLE"))
    self:watch(inventory, "count", Controller.updateCount)
end

function Controller:updateCount(count)
    self.ui.controls.Count:setString(tostring(count or 0))
end

function Controller:onReturn()
    self.host:hideImmediate()
end

return Ui.DefineWindow(InventoryView, Controller, WindowBase)
```

`watch` renders the current count immediately and updates it when the field changes:

```lua
local WindowInventory = require("Source.Windows.WindowInventory")

local inventoryModel = { count = 3 }
local window = WindowInventory.new(inventoryModel):mount(uiManager)
inventoryModel.count = 4
```

The display changes to `4` without calling `refresh`. To react to language changes, move the title update into `refresh` and add the locale event to `refreshEvents`.

### Declare business members once

The handwritten `Scripts/stub/Source/Windows/WindowInventory.d.lua` contains only the Controller and its business types:

```lua
---@meta

---@class InventoryModel
---@field count integer

---@class Source.Windows.WindowInventory.Controller: Source.UIBase.UiController
---@field host Source.Windows.WindowInventory
---@field ui Source.UI.Inventory
---@field model InventoryModel
local Controller = {}

---@param inventory InventoryModel
function Controller:init(inventory) end

---@param count integer | nil
function Controller:updateCount(count) end

function Controller:onReturn() end
```

Run `ScriptTools ui-assets generate <project-root>` to derive the public window declaration. Require `Source.Windows.WindowInventory`; `Source.Windows.WindowInventory.Controller` is a private type, not a module.

## Bind a native callback

Independent row Controllers retain `Ui.Define(RowView, RowController)` and `RowController.new(model, ui?)`. A setting row can bind its existing DropBox:

```lua
function SettingRowController:bind()
    self.ui.controls.DropBox:setItems(self.model.items)
    self.ui.controls.DropBox:setOnSelectedIndexChanged(self:bindCallback(SettingRowController.onSelectedIndexChanged))
end

function SettingRowController:onSelectedIndexChanged(index)
    self.model:setSelectedIndex(index)
end
```

Pass the unbound class method to `bindCallback`; it supplies `self` and becomes inactive after Controller disposal. See the [callback contract](<02.Runtime Contract.md#observe-model-fields-and-bind-callbacks>).

## Add behaviour to existing child Views

If the parent JSON contains `DetailsAsset`, create its business window in the parent Controller:

```lua
local WindowDetails = require("Source.Windows.WindowDetails")

function Controller:init(inventory)
    self.details = self:createChild("DetailsAsset", WindowDetails, inventory)
end
```

`createChild` reuses `self.ui.assets.DetailsAsset` and its authored layout. The parent View owns the child window.

Independent fixed rows keep their existing Controller path:

```lua
local ItemRowController = require("Source.Windows.WindowInventory.ItemRow.Controller")

local row = ItemRowController.new(itemModel, self.ui.assets.ItemRow)
row:prepare()
```

## Populate model-dependent rows

Populate `ItemList` from `self.model.items`:

```lua
function Controller:bind()
    self.rows = self:createCollection(self.ui.controls.ItemList, ItemRowController)
end

function Controller:refresh()
    self.rows:clear()
    for _, item in ipairs(self.model.items) do
        self.rows:add(item)
    end
    self.rows:layout()
end
```

Require `ItemRowController` alongside the other dependencies. The collection replaces preview children and owns the row lifetimes; see [Dynamic collections](<02.Runtime Contract.md#dynamic-collections>).

## Publish updates

`WindowInventory.Publish(payload)` updates every live, prepared Controller through the asset's EventBus channel. Override `onViewUpdate(payload)` to store state before refresh and reflow. Add events such as locale changes to `refreshEvents` when needed. Independent row and Scene Controllers expose `Publish` through `Ui.Define`. View instances without Controllers do not subscribe.

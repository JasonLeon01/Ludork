# Declarative UI Runtime Contract

## Scope

This contract defines class creation, preparation, mounting, namespace lookup, refresh and terminal disposal for every declarative UI Controller.

## Class definition

`Ui.define(assetKey, definition, baseClass)` sets the asset key, creates a per-asset update channel and finalises the definition with `class(definition, baseClass or UiController)`. Callers require the module and construct it with a Model:

```lua
local InventoryUI = require("Source.UI.Inventory")

local inventoryUI = InventoryUI.new(inventoryModel)
```

When no asset instance is supplied, `UiController:init` instantiates the asset using its canonical logical key.

## Preparation and mounting

`prepare(logicalSize)` performs this sequence:

1. call `bind` once;
2. subscribe declared refresh events and register the UI update channel;
3. call `refresh`;
4. reflow the View with the current logical size;
5. return the root control.

`mount(uiManager, logicalSize)` prepares first, then calls `UIManager:loadUI` once. `attachTo` adds the prepared root to a parent control; `attachWindowView` replaces the compatible View area of an existing window host.

`bind` must be idempotent under this lifecycle because the Controller invokes it only before `_bound` becomes true. `refresh` and reflow may run repeatedly.

## Lookup boundary

`requireControl(name)` and `getNodeByName(name)` search the current asset namespace. `requireAsset(name)` obtains a nested asset instance. A parent cannot reach through a nested asset by child node name; construct the child Controller with that nested instance instead.

## Disposal

`dispose()` is terminal. It unmounts the root, unregisters the asset update channel and unsubscribes every event registered through `subscribe`. Before calling inherited disposal, a Controller must clear callbacks held by native controls so they no longer retain Lua closures.

## Verification

- Count one `bind` call and allow repeated `refresh` and reflow calls.
- Test `mount`, `attachTo` and `attachWindowView` only with compatible owners.
- Confirm nested controls are accessed through their child Controller, not by crossing asset namespaces.
- Dispose the owner and verify EventBus subscriptions and native callbacks are released.

## Limitations

Lookup is intentionally scoped to one asset namespace. A disposed Controller cannot be prepared or mounted again, and a parent cannot override the internals of a nested asset instance.

# Declarative UI Runtime Contract

Covers class creation, preparation, mounting, namespace lookup, refresh and terminal disposal for every declarative UI Controller.

## Class definition

`Ui.Define(assetKey, definition, baseClass)` sets the asset key, creates a per-asset update channel and finalises the definition with `class(definition, baseClass or UiController)`. Callers require the module and construct it with a Model:

```lua
local InventoryUI = require("Source.UI.Inventory")

local inventoryUI = InventoryUI.new(inventoryModel)
```

When no asset instance is supplied, `UiController:init` instantiates the asset using its canonical logical key.

## Preparation and mounting

`prepare(logicalSize)` performs this sequence:

1. call `bind` once;
2. subscribe declared refresh events and register the UI update channel;
3. call `refresh`;
4. reflow the View with the current logical size;
5. return the root control.

`mount(uiManager, logicalSize)` prepares, then calls `UIManager:loadUI` once; `attachTo` adds the prepared root to a parent. A `deferView = true` window uses `attachWindowView` for its full root. `attachNestedWindowView` binds an input host to a pane already inside a loaded top-level asset without reparenting it; the host retains focus, selection, scrolling and return-button behaviour. Programmatic and overlay-only windows keep the ordinary base-view path.

`bind` must be idempotent under this lifecycle because the Controller invokes it only before `_bound` becomes true. `refresh` and reflow may run repeatedly.

## Lookup boundary

`requireControl(name)` and `getNodeByName(name)` search the current asset namespace. `requireAsset(name)` obtains a nested asset instance. A parent cannot reach through a nested asset by child node name; construct the child Controller with that nested instance instead.

## Disposal

`dispose()` is terminal and runs at most once, including during later garbage collection. It unmounts the root, unregisters the asset update channel and unsubscribes every event registered through `subscribe`. Before inherited disposal, a Controller must clear native-control callbacks that retain Lua closures.

`UIManager` destruction clears callbacks registered to its lifetime, including on detached controls. `removeUI` preserves them for a later `loadUI`; loading or reparenting a subtree transfers callback ownership. Controllers must still call `dispose()` to unsubscribe events and release owned resources.

## Limitations

A disposed Controller cannot be prepared or mounted again, and a parent cannot override the internals of a nested asset instance.

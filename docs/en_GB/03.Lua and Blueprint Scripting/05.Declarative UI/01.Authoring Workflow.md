# Declarative UI Authoring Workflow

## Goal

Create a View/Controller pair with matching logical keys, stable asset ownership and a lifecycle owned by the containing Scene or window.

## Prerequisites

- An asset location chosen from the owner-based directory rules.
- Stable node names for every control the Controller will access.
- A Model and owning Scene/window that can construct and dispose the Controller.

## Steps

### File layout

The asset root is fixed at `Data/UI/Assets`:

```text
Data/UI/Assets/
    ├── Inventory.json
    └── Parts/
        ├── Inventory/ItemRow.json
        └── Shared/KeyPrompt.json
```

Complete screens, windows, HUDs and overlays live directly below `Assets`. Put parts owned by one large UI in `Parts/<Owner>` and genuinely shared parts in `Parts/Shared`. Do not create directories organised only by control shape.

The Lua owner hierarchy mirrors the asset hierarchy:

```text
Scripts/Source/UI/
├── Inventory.lua
└── Parts/
    ├── Inventory/ItemRow.lua
    └── Shared/KeyPrompt.lua
```

`Ui.lua`, `UiController.lua`, `UiControlFactory.lua` and genuine cross-UI helpers may remain at shared locations.

### Create a View and Controller

1. Create the JSON asset in the UI Asset Editor.
2. Choose a stable, descriptive node name for every runtime-accessed control.
3. Decide whether the asset is complete enough to expose in the Project Palette.
4. Save and resolve all identity, Slot, property and resource diagnostics.
5. Create the matching Lua file under `Scripts/Source/UI`.
6. Return `Ui.define(logicalKey, definition)`, where the key is the asset path relative to `Data/UI/Assets`, with forward slashes and no extension.
7. Implement `bind` for one-time callback/control acquisition and `refresh` for repeatable Model-to-View updates.
8. Instantiate, prepare and mount the Controller from the owning Scene or window.

`Inventory.json` uses logical key `Inventory`; `Parts/Inventory/ItemRow.json` uses `Parts/Inventory/ItemRow`. A key is not a filesystem path and cannot contain an empty segment, `.` or `..`.

## Expected result

The JSON View owns only serialisable structure and static properties, while the matching Lua module uses the same logical key and controls runtime data, callbacks and lifecycle.

## Verification

- Save the asset and run `ScriptTools ui-assets validate <project-root>`.
- Construct, prepare, mount and dispose the Controller from its real owner.
- Rename or move through the editor, then update the matching `Ui.define` key and `require` paths.

## Limitations

Create a separate asset for a meaningful composite, a UI with its own lifecycle or a reusable nested part. Keep an inherent system control directly inside its parent asset. Use `palette.exposed = false` for internal rows created dynamically. A permanent language-independent symbol may use literal `text`; localised or Model-derived text remains empty and is assigned by the Controller.

# Declarative UI Authoring Workflow

## Goal

Create a View/Controller pair with matching logical keys, stable asset ownership and a lifecycle owned by the containing Scene or window.

Ludork declarative UI separates a JSON View from a Lua Controller. Use the [UI Asset Editor](<../../02.Editor User Guide/07.UI Asset Editor.md>) for visual editing.

| Layer | Owns |
|---|---|
| JSON View | Hierarchy, asset-local node names, static control properties, Slots and design-only preview data |
| Lua Controller | Model access, callbacks, localised/formatted text, state refresh and dynamic composition |
| Native control | Rendering, measurement, hit testing, focus and primitive interaction state |
| UIManager | Mounting and removing prepared root controls |

Do not store Controller functions, expressions, event handlers or `LOC(...)` calls in a UI asset.

## Steps

### File layout

The asset root is fixed at `Data/UI/Assets`:

```text
Data/UI/Assets/
    ├── Inventory.json
    └── Parts/
        ├── Inventory/ItemRow.json
        └── Shared/KeyPrompt.json
```

Complete screens, windows, HUDs and overlays live directly below `Assets`. Put parts owned by one large UI in `Parts/<Owner>` and genuinely shared parts in `Parts/Shared`. Do not create directories organised only by control shape.

The Lua owner hierarchy mirrors the asset hierarchy:

```text
Scripts/Source/UI/
├── Inventory.lua
└── Parts/
    ├── Inventory/ItemRow.lua
    └── Shared/KeyPrompt.lua
```

`Ui.lua`, `UiController.lua`, `UiControlFactory.lua` and genuine cross-UI helpers may remain at shared locations.

### Create a View and Controller

1. Create the JSON asset in the UI Asset Editor.
2. Choose a stable, descriptive node name for every runtime-accessed control.
3. Decide whether the asset is complete enough to expose in the Project Palette.
4. Save and resolve all validation diagnostics.
5. Create the matching Lua file under `Scripts/Source/UI`.
6. Return `Ui.Define(logicalKey, definition)`, where the key is the asset path relative to `Data/UI/Assets`, with forward slashes and no extension.
7. Implement `bind` for one-time callback/control acquisition and `refresh` for repeatable Model-to-View updates.
8. Instantiate, prepare and mount the Controller from the owning Scene or window.

`Inventory.json` uses logical key `Inventory`; `Parts/Inventory/ItemRow.json` uses `Parts/Inventory/ItemRow`. A key is not a filesystem path and cannot contain an empty segment, `.` or `..`.

### Scrollable content

Put overflow-prone content in `Engine.ScrollBox`; do not move a Canvas from Controller code. `size` is the viewport, and an empty `windowSkin` uses the system skin. ScrollBox owns clipping, offsets and wheel/touch input, and scrolls an axis only when laid-out content exceeds it. Indicator-atlas details are in [Layout and Image Controls](<../07.API Reference/04.Core Modules/02.Engine/10.Layout and Image Controls.md>).

## Limitations

Give every visible screen one top-level asset. Multi-pane screens nest owner-specific assets from `Parts/<TopLevelName>/`; nested parts use `palette.exposed = true`, while runtime-only helpers may remain unexposed.

Use representative `#TAB`/`#ITEM` children and Sample visuals as preview data, never fallback game data. Before display, the Controller replaces tab labels and authored list children. Only permanent language-independent symbols use literal `text`.

Use `Engine.CharacterView` for frame-animated characters or enemies. Assets provide preview values; runtime passes the real texture, Rect, scale, animation, Shader and Hue to `setCharacter`. Lua does not crop or compose the actor visual.

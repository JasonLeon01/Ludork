# UI Asset Schema and Control Registry

## Scope

This reference defines canonical UI asset keys, the current asset structure, nodes, Slots, resource keys and the live editor control registry.

## Asset key and structure

A UI asset uses `type = "uiAsset"` and follows the current field contract directly; it does not carry a schema-version field. Its only asset identity is the exact-case path relative to `Data/UI/Assets`, with forward slashes and no extension. `Title.json` has key `Title`; `Parts/Shared/WindowBase.json` has key `Parts/Shared/WindowBase`.

Keys cannot be absolute, contain backslashes, empty segments, `.` or `..`, include an extension, or repeat prefixes such as `Assets/` or `UI/Assets/`. The asset object contains `designSize`, `palette` and one `root` node; it does not contain an asset UUID.

Each node contains:

| Field | Contract |
|---|---|
| `id` | Project-unique UUID managed by the editor. |
| `name` | Controller lookup name, unique within the asset. |
| `controlId` | Canonical module-root native class path for a system control, or `Project:<relative-key>`. |
| `properties` | Values owned by the control schema. |
| `slot` | Layout owned by the parent; absent on the root. |
| `editor` | Design-only values such as `previewText`. |
| `children` | Ordered child nodes; order is the stable tie-breaker for equal z-order. |

Nested project assets are black boxes. Their node declares the project `controlId`, its own node identity/name and parent Slot, with no internal overrides or children. The target must be exposed, and direct or indirect nesting cycles are invalid.

System IDs use the bound class's sole runtime path, for example
`Engine.Canvas` or `Engine.FunctionalPlainText`. Retired nested IDs are unknown
controls; the registry does not alias or migrate them.

## Slots and resource keys

A Canvas parent supplies anchors, offsets, alignment, auto-size and z-order. A List parent supplies list placement and does not accept Canvas Slot fields. The parent's adapter declaration determines child policy and Slot type.

- File resources use exact-case project-relative paths beginning `Assets/`, with forward slashes and extensions.
- `textConfig` is relative to `Data/TextConfigs`, with no directory prefix or extension.
- `opacityCurve` is relative to `Data/Curves`, with no directory prefix or extension, and resolves to a scalar curve.
- Absolute paths, backslashes, traversal and alias prefixes are invalid.

## Live control registry

The editor builds its control registry in memory from native system descriptors and the current UI assets. Only assets with `palette.exposed = true` appear as project controls. No registry or catalogue file is generated, saved or read by the runtime.

The adapter fingerprint is derived only from system descriptors and is used by the editor and preview host to reject mismatched native adapters. Runtime and preview resolve every project asset directly by its canonical relative key.

## Verification

- Validate node UUID and node-name uniqueness.
- Match every child Slot to its parent's descriptor and child policy.
- Resolve project references and resource keys with exact case.
- Run `ScriptTools ui-assets validate <project-root>` and `ScriptTools ui-adapter-check <repo-root>` before native builds.

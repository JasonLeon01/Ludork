# Declarative UI Validation and Packaging

## Goal

Validate path-based UI declarations, compare the native preview with the runtime, and package assets without editor-only preview data.

## Validate after external changes

When UI JSON changes outside the editor, run:

```text
ScriptTools ui-assets generate <project-root>
ScriptTools ui-assets validate <project-root>
ScriptTools ui-adapter-check <project-root>
```

`ui-assets generate` synchronises generated Views and declarations and removes obsolete outputs. It needs no Preview Host or registry. Use `--check` instead to report missing, stale or obsolete outputs without writing. Generated file locations are listed in [Declarative UI Authoring Workflow](<01.Authoring Workflow.md#file-layout>).

`ui-assets validate` checks assets against the project registry. Both `ui-adapter-check` and `ui-preview validate` are read-only. Adapter validation compares the project JSON with its Host's compiled descriptors.

Before a source project's first preview build, and when saving before compilation, only descriptor-independent structure is checked, so native validation remains pending. Use `ScriptTools ui-assets validate <project-root> --structure-only` for this check. Builds generate preview artefacts before full UI validation. Invalid assets fail the build but leave the generated preview available for editing. Ordinary saves with an available registry perform full validation.

Standalone restores missing preview JSON from its included Host through `ScriptTools ui-preview ensure <project-root>`, normal UI validation or `ui-preview registry`. Corrupt or mismatched metadata and missing binaries remain errors. Source projects must rebuild unavailable preview artefacts, because incomplete or failed native builds cannot be recovered automatically.

## Automatic synchronisation

Save, build, Play, Pack and template creation synchronise generated UI files automatically, including when reusing existing binaries. Generation failures stop the operation. Mobile packaging with `--check` only performs preflight checks.

Templates retain generated declarations, while game packages exclude `Scripts/stub`.

## Validation layers

Save, native preview, Play and Pack validate assets against [UI Asset Schema and Control Registry](<04.Asset Schema and Control Registry.md>) and reject unknown fields, duplicate asset-local node names and alias paths.

## Native preview and packaging

Preview requires a compatible protocol, system adapter fingerprint and complete registry hash. Mobile packaging builds the local desktop Preview for native validation, and that Preview is not included in the device package.

Packaging validates a staging copy, removes `editor` data and applies configured compilation, encryption or archiving without modifying the project's gameplay assets. JSON, `.ldc` and packed Data keep the same extension-free UI keys, and packed controllers keep their logical module paths.

Staging validation uses the source project registry through `--registry <source-project>/Temp/UiPreview.registry.json`. The registry is a development artefact and is excluded from player packages.

# Lua and Blueprint Scripting

## Choose a scripting model

| Model | Best suited to | Primary source |
|---|---|---|
| Blueprint graph | Visual event and execution flow | `Data/Blueprints/*.json` |
| Lua class | Reusable systems and gameplay types | `Scripts/**/*.lua` |
| Script Mixin | Lua behaviour attached directly to a Blueprint class | `Scripts/Mixins/**/*.lua` plus same-name `_meta.lua` |
| Declarative UI | JSON View with a Lua Controller | `Data/UI/Assets/**/*.json` and `Scripts/Source/UI/**/*.lua` |

A Blueprint inheritance chain uses either graph mode or Script Mixin mode. Do not switch mode within the chain.

Runtime code, public declarations and editor metadata are separate files. A normal `.lua` module owns behaviour, its mirrored `Scripts/stub/**/*.d.lua` owns public documentation and LuaLS types, and its same-name `_meta.lua`, when present, contains pure data for editor discovery. Declaration files are development-only and are excluded from game packages.

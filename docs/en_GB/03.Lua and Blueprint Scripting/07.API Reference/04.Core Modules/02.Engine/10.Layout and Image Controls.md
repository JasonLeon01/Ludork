## CharacterView

Direct metadata bases: `{ "Engine", "FunctionalImage" }`

`CharacterView` renders frame-animated character and enemy sheets inside fixed `size` bounds. `textureRect` selects the initial frame; `characterScale` is applied before centred, no-enlargement fitting. Positive `switchInterval` advances equal-width horizontal frames when `animatable` is true; a non-positive value pauses animation.

`shader` is empty or a complete `/Game/Assets/Shaders/...` logical path. The control uses actor uniforms (`texture`, `time`, `textureSize`, `textureRect`) and the world-actor Hue pass; Shader failure renders magenta. `setFrameRect` changes the reset frame, and changing declarative `texture` resets it to the full texture. Asset properties (`size`, `texture`, optional `textureRect`, `characterScale`, `animatable`, `switchInterval`, `shader`, `hue`, `colour`) are preview data; runtime calls `setCharacter` with the real snapshot.

## ScrollBox

Direct metadata bases: `{ "Engine", "Canvas" }`

`ScrollBox` is a clipped multi-child layout viewport. Declarative assets set `size` and `windowSkin`; an empty `windowSkin` loads the current system window skin. It inherits the standard Canvas child functions. Its own methods are:

| Name | Kind | Parameters | Returns | Execution and metadata |
|---|---|---|---|---|
| `getSize` | `function` | — | return: sf.Vector2f | Pure |
| `resize` | `function` | size: sf.Vector2f | — | — |
| `setWindowSkin` | `function` | windowSkin: sf.Image | — | — |
| `getScrollOffset` | `function` | — | return: sf.Vector2f | Pure |
| `setScrollOffset` | `function` | offset: sf.Vector2f | — | — |
| `getMaxScrollOffset` | `function` | — | return: sf.Vector2f | Pure |
| `getScrollingEnabled` | `function` | — | return: bool | Pure |
| `setScrollingEnabled` | `function` | enabled: bool | — | — |
| `scrollDescendantIntoView` | `function` | descendant: { "Engine", "ControlBase" } | — | — |

Each axis uses visible direct-child content bounds and is enabled only when they exceed the viewport; otherwise offset and maximum are zero. Writes, resize and content shrink clamp offsets. Rendering and descendant hits are clipped, and `scrollDescendantIntoView` rejects controls outside this ScrollBox.

Ordinary wheel input uses 32-logical-pixel steps; precise deltas apply directly to the matching axis. Touch drag starts after the input threshold and has no inertia. Selectable-list taps, Config Slider direction ownership and DropBox popup input remain unchanged.

### Window-skin overflow indicators

The system window skin must contain the complete standard 32 × 32 indicator atlas at `(144, 16)`. A smaller skin is an error. ScrollBox never samples the centre `(156, 28, 8, 8)` or the four corners; it extracts only these nearest-neighbour regions:

| Direction | Source rectangle | Viewport position | Visible when |
|---|---|---|---|
| Up | `(156, 16, 8, 12)` | centred on the top edge | `offset.y > 0` |
| Down | `(156, 36, 8, 12)` | centred on the bottom edge | `offset.y < maximum.y` |
| Left | `(144, 28, 12, 8)` | centred on the left edge | `offset.x > 0` |
| Right | `(164, 28, 12, 8)` | centred on the right edge | `offset.x < maximum.x` |

Indicators scale with global UI `Scale`, use nearest-neighbour sampling, render above content and do not affect scrolling, bounds or hits. `setWindowSkin` rebuilds them immediately.

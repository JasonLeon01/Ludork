### Display scale semantics

`getConfiguredScale()` returns the configured preference, including `0`; `getScale()` returns the positive scale currently used for rendering and input. The default preference is `1.0`. `setScale` applies and saves, `applyScale` only applies and `saveScale` only saves; non-finite or negative values normalise to `1`, while `0` selects borderless desktop fullscreen without changing display mode. At positive scales, standalone windows are resizable, preserve aspect ratio with centred black bars and do not persist manual resizing. On macOS, scale is measured in Cocoa client points independently of Retina backing scale. Embedded hosts retain their size; mobile remains platform-fullscreen, although the preference may be saved.

`getMaximumWindowedScale(gameSize)` returns the largest scale at which a normally decorated window of logical `gameSize` fits the current window's display work area, or the primary display when no window exists. It returns `nil` if either dimension is zero, on embedded or mobile hosts, or when the work area is unavailable.

### iOS graphics context

On iOS, startup requires an OpenGL ES 3.0 or later context.

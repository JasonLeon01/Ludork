### Display scale semantics

`getConfiguredScale()` returns the configured display preference, including `0`; `getScale()` returns the positive effective scale currently used for rendering and input after applying Maximum Render Scale. The default configured preference is `1.0`. `setScale` applies and saves, `applyScale` only applies and `saveScale` only saves; non-finite or negative values normalise to `1`. On desktop, `0` selects borderless fullscreen without changing display mode. At positive values, standalone desktop windows are resizable, preserve aspect ratio with centred black bars and do not persist manual resizing. On macOS, display scale is measured in Cocoa client points independently of Retina backing scale.

`isDisplayScaleConfigurable()` returns false for embedded displays. It returns true for standalone desktop windows and for a mobile native host that explicitly registers a display-scale request handler; ordinary mobile hosts return false. The HarmonyOS tablet host maps a positive value to a freeform Stage window-size request of `round(gameSize * scale)` and maps `0` to the platform maximised/fullscreen state. Rendering uses the actual surface received after that operation, which may be smaller than the Stage window because of platform decorations, and a manual platform resize does not change the stored preference.

`getMaximumWindowedScale(gameSize)` returns the largest scale at which logical `gameSize` fits the available window dimensions. Desktop uses the current window's decorated work area, or the primary display when no window exists. A configurable mobile host uses the maximum windowed dimensions reported by that host; embedded and non-configurable mobile hosts return `nil`. It also returns `nil` if either logical dimension is zero or the available size is unknown.

### Maximum render scale semantics

`getMaximumRenderScale()` returns the configured cap. A positive value limits the effective internal scale to the smaller of the surface-fit scale and the cap; `0` leaves it uncapped. The default is `2.0`, and negative or non-finite values normalise to `2`. `setMaximumRenderScale` applies and saves the cap, rebuilding render targets between complete frames without changing the native window size; `saveMaximumRenderScale` saves without applying.

### Anti-aliasing semantics

The anti-aliasing methods read or save the requested non-negative SFML context level. The initial default comes from `sf::ContextSettings`. `setAntiAliasingLevel` saves the value but does not recreate the current graphics context; it takes effect on the next display initialisation, and SFML may negotiate a different supported level.

### iOS graphics context

On iOS, startup requires an OpenGL ES 3.0 or later context.

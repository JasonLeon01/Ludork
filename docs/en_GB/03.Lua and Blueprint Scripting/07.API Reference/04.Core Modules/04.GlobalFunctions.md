# GlobalFunctions Lua API

`GlobalFunctions` exposes native free functions through the `Components`, `Manager`, `NodeGraph` and `UI` group tables. Derived from `Scripts/stub/GlobalFunctions.d.lua` and `Engine/Source/GlobalFunctions/include/GlobalFunctions`. `Scripts/GlobalFunctions_meta.lua` is empty, so functions here are Lua APIs rather than Blueprint nodes. Grouped functions appear only in their group tables.

## Loading

```lua
local Engine = require("Engine")
local GlobalCore = require("GlobalCore")
local GlobalFunctions = require("GlobalFunctions")

local Components = GlobalFunctions.Components
local Manager = GlobalFunctions.Manager
local NodeGraph = GlobalFunctions.NodeGraph
local UI = GlobalFunctions.UI
```

Load the three gameplay roots in the displayed order.

## Components

These component utilities support class metadata, serialisation and attachment. Names beginning with `_` and functions declared `metadata = false` are runtime infrastructure; project gameplay should prefer the public class/component workflow.

`getComponentFieldValue` and `setComponentFieldValue` require the declared component instance. A missing or wrong-type component raises instead of being rebuilt.

## Limitations

Category helpers accept only category-relative paths and add their `/Game/Assets/...` prefix; for example, `loadCharacter("actors/Hero.png")` and `playSE("cursor.ogg")`. Stored data and `getSoundBuffer(filePath)` instead require complete logical paths. Loading failures follow the native manager contract. Infrastructure Component functions are not gameplay APIs.

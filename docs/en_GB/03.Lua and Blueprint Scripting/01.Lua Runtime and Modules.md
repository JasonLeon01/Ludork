# Lua Runtime and Modules

Ludork uses the Lua 5.5.0 runtime. Project scripts use explicit modules and the APIs registered by Ludork, LuaSF and project-native modules.

| Model | Best suited to | Primary source |
|---|---|---|
| Blueprint graph | Visual event and execution flow | `Data/Blueprints/*.json` |
| Lua class | Reusable systems and gameplay types | `Scripts/**/*.lua` |
| Script Mixin | Lua behaviour attached directly to a Blueprint class | `Scripts/Mixins/**/*.lua` plus same-name `_meta.lua` |
| Declarative UI | JSON View with a Lua Controller | `Data/UI/Assets/**/*.json` and `Scripts/Source/UI/**/*.lua` |

A Blueprint inheritance chain uses either graph mode or Script Mixin mode. Do not switch mode within the chain.

Runtime code, public declarations and editor metadata are separate files. A normal `.lua` module owns behaviour, its mirrored `Scripts/stub/**/*.d.lua` owns public documentation and LuaLS types, and its same-name `_meta.lua`, when present, contains pure data for editor discovery. Declaration files are development-only and are excluded from game packages.

## Entry and module order

`Main.ini` selects the entry script, normally `Scripts/Entry.lua`. Load the root native modules in this order, complete all direct `require` calls, then declare member aliases after a blank line:

```lua
local Engine = require("Engine")
local GlobalCore = require("GlobalCore")
local GlobalFunctions = require("GlobalFunctions")
local Logging = require("Global.Utils.Logging")

local Input = Engine.Input
local System = GlobalCore.System
local ManagerFunctions = GlobalFunctions.Manager
```

`GlobalFunctions` exposes the `Components`, `UI`, `NodeGraph` and `Manager` groups. Other project modules use their full dotted path. Do not create a directory-level `init.lua` aggregator. A delayed `require` is appropriate only when resolving a genuine dependency cycle.

## Native values and platform

`sf` is a runtime global. Use `sf.Vector2i.new(...)`, `sf.Vector2f.new(...)`, `sf.Color.new(...)` and other registered values directly. Pass the exact native value required by an API.

The build injects the global string `PLATFORM`. Defined values include `win32`, `darwin`, `ios`, `android` and `ohos`; another CMake system uses its lower-case system name. Platform-specific code reads `PLATFORM` and must not infer the operating system from path separators, files or environment variables.

## Native containers

Standard registers the lower-case callable globals `list`, `tuple` and `dict`. They create native containers alongside ordinary Lua tables; they do not replace tables used by assets, metadata, Blueprint values or native APIs. They are not vector adapters: when metadata or a binding declares `sf.Vector2i`, `sf.Vector2f` or another SFML type, pass exactly that native type. Convert persisted raw data at its loading boundary instead of making the receiving API guess a table, string or tuple shape.

```lua
local route = list("north", nil, "east")
local position = tuple(4, 7)
local cache = dict {
    [position] = "visited",
}
cache[1] = nil
```

`list(value1, value2, ...)` and `tuple(value1, value2, ...)` store their arguments as ordered slots. When either receives exactly one raw table, native list or native tuple, it instead shallow-copies that value as a sequence. Therefore `list { ... }` and `tuple { ... }` are Lua shorthand for the single-sequence calls `list({ ... })` and `tuple({ ... })`. A dictionary accepts no argument or one raw table/native dictionary mapping; `dict { ... }` is the corresponding shorthand for `dict({ ... })`. Consequently, `dict { [1] = 2 }` creates a dictionary containing the numeric key `1`; it is not a special list constructor. Numeric list and tuple access is 1-based, negative indices are not accepted, and list writes and inserts are limited to an existing slot or `#value + 1`.

A list is mutable and supports `append`, `extend`, `insert`, `pop`, `remove`, `clear`, `index`, `count`, `contains`, `reverse`, `sort`, `copy`, `unpack` and `toTable`. A tuple is immutable and supports `index`, `count`, `contains`, `unpack` and `toTable`. A dictionary supports direct key access plus `get`, `setdefault`, `update`, `pop`, `remove`, `clear`, `contains`, `keys`, `values`, `items`, `copy` and `toTable`. Mutating list methods return no value except `pop`; `pop()` removes the last slot by default, and `remove` raises when its value is absent. `sort(compare?)` is stable, using a supplied `compare(left, right)` callback or Lua `<`. Dictionary `remove` reports whether it removed a key, while `pop` returns the removed value and raises for an absent key when no default is supplied. Dictionary `keys()` and `values()` return insertion-ordered native-list snapshots. `items()` returns a lazy iterator and is consumed directly as `for key, value in dictionary:items() do`; it retains the dictionary and yields each key/value pair without constructing an intermediate list or pair container, including when the value is nil. Method names take priority over string keys during direct lookup: after `value["get"] = stored`, use `value:get("get")` or `dict.get(value, "get")` to read that entry.

Lists and dictionaries can store nil. Assigning `dictionary[key] = nil` stores a present nil value; remove it with `remove` or `pop`. Their length includes nil slots or values, native-aware `ipairs(list)` and `ipairs(tuple)` visit every 1-based sequence slot without stopping at a list nil, and both `pairs(dict)` and `dict:items()` visit every dictionary entry in insertion order. Structural mutation during one of these iterations raises an error. `get(key, default)` returns nil for a present nil and uses the default only when the key is absent; use `contains(key)` to distinguish those cases. Tuples reject nil elements. Lists and dictionaries compare their contents structurally, including cyclic list/dictionary graphs; tuples compare ordered elements under the value-or-identity rules below.

Tuples are immutable, hashable native-dictionary keys. Booleans, finite numbers, strings and nested tuples participate by value. Tables, functions, threads, lists, dictionaries and other userdata participate by identity. Nil, NaN and positive or negative infinity are invalid native-dictionary keys, including when nested in a tuple. Hashes are internal, local to the Lua state and are not a public persistence format. An ordinary Lua table still hashes userdata by identity: it can use a tuple as a key only when lookup reuses that exact tuple object; a separately constructed equal tuple does not hit the entry.

`toTable` recursively converts nested native containers to ordinary Lua tables while preserving shared references and cycles. Tables produced from lists and tuples retain JSON-array shape even when empty or nested. Nil list slots and dictionary values become `cjson.null` so their positions or keys survive conversion. A tuple dictionary key becomes a fixed, space-free string such as `(1,2)`, `(1,)` or `()`; conversion raises if that string collides with an existing string key. JSON encoders and Core bindings do not convert native containers implicitly: call `toTable` at the boundary. Other non-JSON key types still require an explicit record-array representation, and use a record array whenever tuple identity must be reconstructed after loading.

## Truth values and type checks

Use the global `bool(value)` for ordinary conditions so zero, empty strings, empty tables and empty native containers follow Ludork's project semantics. Use an explicit `nil` comparison only when the code must distinguish absence from `false`, `0`, `""`, `{}` or an empty native container, or when a protocol uses nil as a sentinel.

Use `Class.isInstance(value, Type)` and `Class.isSubclass(Type, Base)` for script and native class relationships. Lua `type` is reserved for real serialisation boundaries, declared primitive unions, low-level reflection and callable classification.

## Copying and state

The global `copy` and `deepcopy` functions are the shared copying primitives. They preserve native container types, with shallow and recursive semantics respectively. Use them when an instance requires an independent mutable value. Do not add per-type cloning helpers for vectors, rectangles or other values supported by the common copy protocol. `asizeof` includes the values owned by native containers.

## Logging and errors

Runtime code writes through `Global.Utils.Logging`: `debug` for diagnostic detail, `info` for significant stages, `warning` for recoverable data issues and `error` for unrecoverable failures. Logging an error does not raise it; use `error` or `assert` when execution must stop. Do not add protected calls merely to hide project or resource errors.

Runtime-service infrastructure is fail-fast. A missing resolver, a stopping Lua session, an unregistered service or an unsupported operation raises an error instead of behaving like an empty result. A successful service returning no values is distinct from one returning a single `nil`; fixed-result callers also require the exact result count and type. Register every required service before exposing the feature that uses it, and do not translate service-lifecycle or registration failures into `false`, an empty value or fallback behaviour.

## Runtime, declarations and metadata

The three Lua file layers have separate owners:

- ordinary `.lua` files own runtime behaviour and keep only implementation annotations needed by local variables, local/private functions or control-flow narrowing such as `---@cast`;
- `Scripts/stub/**/*.d.lua` mirrors the runtime module path and owns public documentation and LuaLS API declarations without `require`, initialisation side effects or gameplay logic; each requireable file declares its exact EmmyLua module name, for example `Global/Pool.d.lua` starts with `---@meta Global.Pool`, while the global-only `Standard.d.lua`, `Class.d.lua` and `LuaSF.d.lua` use bare `---@meta`;
- same-name `_meta.lua` files beside runtime scripts return a fixed `_METADATA` pure-data table for editor discovery.

The EmmyLua workspace uses `Scripts/stub` as its explicit module root. Runtime files remain in the main workspace and resolve by suffix, while an exact `require` path selects the declaration module and exposes its documentation and types. Write Doxygen-style commands in declaration comments with an `@` prefix, such as `@brief`, `@param` and `@return`, so Lua tooling does not interpret a backslash as an escape. Templates retain the complete `Scripts/stub` tree for development. Game packaging removes that tree, Lua compilation ignores every `.d.lua`, and a package is rejected if any declaration file remains elsewhere.

## Button

Direct metadata bases: `{ "Engine", "Image" }`, `{ "Engine", "FunctionalBase" }`

A declarative Button with an empty `texture` uses the current window skin's selection-Rect image. While a gamepad is connected, that default background is hidden; size, global bounds, hit area and separate text controls stay unchanged. A custom texture stays visible, and disconnecting the gamepad restores the default background.

`gamepadButton` and `gamepadLongPress` add a gamepad binding. JSON stores a logical name such as `"X"`; `""` means unbound and long press defaults to `false`. Lua uses `button:setGamepadButton(Engine.JoystickButton.getX())` and `button:setGamepadLongPress(true)`; pass `nil` to clear the binding.

With a gamepad connected, the bound key is a 16 logical-pixel circle inside the button's right edge, vertically centred and independent of background stretching. It shares the white key glyph and green clockwise long-press progress with [`GamepadHintBar`](<13.Interactive and Declarative UI Controls.md#gamepadhintbar>). A short press invokes `onConfirm` / `addConfirmCallback` once; a long press invokes it once at one second and needs a release before another trigger. The button need not have focus, but it and its owning window must be visible and interactive. Disabling or hiding either, deactivating the window or disconnecting the gamepad clears progress. A disabled button's visible hint is grey.

### Properties

Declarative properties include `gamepadButton` (empty by default) and `gamepadLongPress` (`false` by default), alongside the existing texture and colour settings.

## FunctionalBase

Direct metadata bases: `{ "Engine", "FocusableMixin" }`

### Input event data

Input methods and callbacks receive `Engine.UiInputEventArguments`. Pointer events provide `position: sf.Vector2f`. Mouse-button events also provide `button: sf.Mouse.Button`, and wheel events also provide `delta: number`. All fields are optional and absent from keyboard events. Use `Engine.UiInputEventArguments.new({})` for programmatic confirmation or cancellation.

### Interaction eligibility

A `FunctionalBase` accepts focus and input only while it and every `FunctionalBase` ancestor are active, and while it and every `ControlBase` ancestor are visible. `getActive` and `getVisible` remain local-state queries. Losing eligibility clears pointer and touch capture throughout the subtree and keeps the cancelled gesture consumed until release, while ticking and rendering continue.

### Touch capture

`setTouchHitBounds` sets an optional touch-only hit rectangle in the control's local logical coordinates. The rectangle must have finite coordinates and a non-negative size, and passing `nil` restores the default. `getAbsoluteTouchHitBounds` returns its axis-aligned screen rectangle after the runtime display scale and control hierarchy transforms are applied. A `FunctionalBase` mixed into a `ControlBase` defaults to the control's absolute bounds. A standalone `FunctionalBase` has no control coordinate space, so the getter returns `nil`.

An effectively enabled functional control captures a primary touch whose beginning position is inside its absolute touch hit bounds. The capturing control continues to receive movement and the final release even after the pointer leaves those bounds. Releasing outside clears the pressed state without invoking click or confirm, but any tap belonging to that capture is still consumed so it cannot activate a control underneath. Multi-touch cancellation also releases capture, and touch hit bounds do not affect mouse hit testing.

### Pointer click

A mouse press begins pointer capture but does not invoke `onClick`. The click fires only when the pressed button is released while the pointer is still hovering the same control; a release after the pointer leaves the control clears the pressed state without a click. The click arguments carry the released `button`, so callbacks that only handle the left button can filter on it. A touch tap follows the touch-capture rules above and prefers `onConfirm` when a confirm callback is present.

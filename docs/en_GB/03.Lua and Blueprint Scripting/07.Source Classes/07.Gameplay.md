# Source Gameplay API

`Source.Gameplay` contains the Sample-specific abilities and Effects built on `GlobalCore`.

## GameplayScene

Module: `Source.Gameplay.GameplayScene`, derived from `GlobalCore.SceneBase`. `SceneMap` implements this contract, and Actors reach it through their owning map.

| Member | Signature | Behaviour |
|---|---|---|
| `getGameMap` | `() -> GameMap` | Returns the scene's loaded map |
| `getGameInstance` | `() -> GameInstance` | Returns the game instance owning variable and persistence state |
| `recordAddedActor`, `recordDestroyedActor` | `(actor)` | Records the corresponding persistence change |
| `recordActorPosition` | `(actor, position)` | Records the Actor's map position |
| `requestFloorStep` | `(teleporter, step) -> boolean` | Accepts one adjacent-floor request; `step` must be `1` or `-1` |
| `requestGameOver` | `(player, delay)` | Waits for a finite non-negative animation delay and navigates without applying damage or Effects |

Combat and movement hazards require a `GameplayScene` before they change state. Unavailable or rejected floor requests preserve movement. Game Over uses the longest remaining animation duration. Duplicate requests are ignored, and replacing the scene, map or player cancels pending navigation.

## GeneralDataGraphAbility

Module: `Source.Gameplay.GeneralDataGraphAbility`

Direct base: `GlobalCore.GameplayAbility`

| Field | Type |
|---|---|
| `generalType` | `string` |
| `memberID` | `string` |
| `graphEvent` | `string` |

| Member | Signature | Behaviour |
|---|---|---|
| `init` | `(generalType, memberID, graphEvent, triggerTags?)` | Creates ability ID `GeneralData.<type>.<member>.<event>` |
| `calculate` | `(abilitySystem, eventData) -> GameplayAbilityResult` | Returns `ExecutableGraph` with graph data or successful `NoGraph` |
| `activate` | `(abilitySystem, eventData) -> GameplayAbilityResult` | Builds and synchronously executes the selected event; returns `GraphExecuted` or `NoGraph` |

The graph parent and the `eventData` argument are the same `GameplayEventData`. Its payload receives the three fields above and, for State graphs, `activeEffect`. Execution uses `Engine.BPBase.ExecuteGraph`. General Data graphs have no Actor dispatch or inheritance, cannot be latent, and propagate errors.

## Effects

Module: `Source.Gameplay.Effects`

| Function | Signature | Result |
|---|---|---|
| `CreateInstantModifierSpec` | `(effectID, attribute, operation, magnitude, eventData?) -> GameplayEffectSpec` | Creates, but does not apply, one Instant modifier spec |
| `ApplyInstantModifier` | `(target, effectID, attribute, operation, magnitude, eventData?)` | Applies one Instant modifier |
| `CreateEquipmentEffect` | `(equipID, slot, attrPlus) -> GameplayEffect` | Creates an Infinite equipment effect and `Equipment.Slot.<slot>` tag |
| `CreateStateEffect` | `(stateID) -> GameplayEffect` | Creates an Infinite state effect, tag and granted state abilities |
| `CreateStateSpec` | `(stateID, stacks?, eventData?) -> GameplayEffectSpec` | Creates, but does not apply, a State spec with a positive stack count |
| `ApplyState` | `(target, stateID, stacks?, eventData?) -> integer` | Applies or stacks the State effect and returns its handle |
| `RemoveState` | `(target, stateID) -> bool` | Removes the complete State effect |
| `ReduceState` | `(target, stateID, stacks?) -> bool` | Removes only the requested stacks when supported |
| `ClearStates` | `(target)` | Removes every effect whose ID begins with `State.` |
| `GetStateStacks` | `(target) -> table<string, integer>` | Returns State ID to stack count |
| `GetStateIDs` | `(target) -> string[]` | Returns active State IDs in stable order |
| `FindActiveEffectHandle` | `(abilitySystem, effectID) -> integer?` | Returns the first matching active handle |

Equipment uses `attrPlus` in stable attribute order. Weak applies `-1 ATK` and `-1 DEF` per stack, with a minimum of `0`. Poisoned grants its damage ability. States may grant `onWalk` and `onHookTriggered` graph abilities.

## MotaBattleAbility

Module: `Source.Gameplay.MotaBattleAbility`

Direct base: `GlobalCore.GameplayAbility`

Ability ID: `Ability.Combat.MotaBattle`

| Enum | Members |
|---|---|
| `BattleResult` | `WIN = 1`, `CANNOT_DAMAGE = 2`, `LETHAL_COUNTER_DAMAGE = 3` |
| `CriticalResult` | `VALUE = 1`, `NOT_NEEDED = 2`, `UNKNOWN = 3` |

| Member | Signature | Behaviour |
|---|---|---|
| `calculate` | `(abilitySystem, eventData) -> GameplayAbilityResult` | Produces a `BattleResult` code and prevalidated damage/Game Over specs without mutation |
| `activate` | `(abilitySystem, eventData) -> GameplayAbilityResult` | Calculates and optionally commits when `eventData.payload.commit` is true |
| `CalculateDamagePerRound` | `(attacker, defender) -> damage, details` | Runs the attack, defence, damage, hit-count and incoming-damage event pipeline |
| `CommitResult` | `(result)` | Applies the prevalidated counter-damage Effect exactly once |
| `CalculateCriticalValue` | `(enemy, player) -> GameplayAbilityResult` | Returns a `CriticalResult` code |

The owner is the enemy, and `eventData.target` is the player. Calculation validates without applying counter-damage or Game Over Specs. Its `BattleResult` data includes per-round damage, counter rounds, Vampire healing, first-strike and fixed damage, both Battlers, prepared Specs and `committed`. `CommitResult` applies the combined damage once. The Enemy handles Game Over after the animation. Critical calculation includes Vampire healing and the unchanged First round threshold, but it ignores FixDmg expressions.

## SpecialAbilities

Module: `Source.Gameplay.SpecialAbilities`

Concrete ability classes can also be loaded from `Source.Gameplay.SpecialAbilities.<ClassName>`, for example `require("Source.Gameplay.SpecialAbilities.MultiHitAbility").new(magnitude)`.

| Member | Signature/value | Behaviour |
|---|---|---|
| `MOVEMENT_HAZARD_TAG` | `"Gameplay.Movement.Hazard"` | Shared owned tag granted by every movement-hazard special |
| `BATTLE_RULES_EVENT` | `"Event.Combat.ResolveBattleRules"` | Collects order-independent Vampire, First and FixDmg battle fields |
| `CreateEffect` | `(specialID, magnitude) -> GameplayEffect` | Creates one Infinite `Special.<id>` effect, tag and ability |
| `CreatePoisonedAbility` | `() -> GameplayAbility` | Creates the State Poisoned incoming-damage ability |
| `GetMagnitude` | `(abilitySystem, specialID) -> any` | Reads the magnitude stored on the active special effect |

Compete, Hard, Magic, MultiHit and Poisoned use their combat resolution events. `BATTLE_RULES_EVENT` gathers Vampire healing, First damage and FixDmg. Numeric FixDmg is direct, while strings substitute the current numeric attributes of the player and enemy before evaluation. Domain, Flank and Blockade handle `Event.Movement.QueryHazard` and grant `Gameplay.Movement.Hazard`. Other IDs grant queryable passive tags.

## MovementSpecials and movement danger

Module: `Source.MovementSpecials`

| Function | Signature | Behaviour |
|---|---|---|
| `CreatePreviewContext` | `(enemies, player) -> PreviewContext` | Caches position-independent combat damage for one unchanged player/enemy snapshot |
| `Preview` | `(enemies, player, playerPosition, ignoredEnemies?, previewContext?) -> GameplayAbilityResult` | Resolves movement-hazard damage and contributing sources |
| `Commit` | `(player, pathPositions) -> GameplayAbilityResult` | Reuses `Preview` for every traversed cell, applies total damage and performs Blockade retreat |
| `NotifyPlayerMovementFinished` | `(player, pathPositions?) -> GameplayAbilityResult` | Commits a completed movement path or the current cell |

`Preview` owns movement-hazard geometry. It dispatches `Event.Movement.QueryHazard`, resolves Flank and ignored enemies, and returns ordered sources and total damage. Danger grids filter by `Gameplay.Movement.Hazard` and materialise on demand. `PreviewContext` caches position-independent damage for an unchanged snapshot without skipping per-cell events. Ignored Flank enemies count for geometry, not for damage. Preview handlers must not mutate gameplay state.

## Generated GeneralDataTypes

Module: `Source.Configs.GeneralDataTypes`

The General Data generator owns this module and its stub. `Types` and named fields expose each generated `<TypeName>AttributeSet`.

`Create(typeName, memberID, memberData) -> AttributeSet` deep-copies schema fields and sets `ID`. Use `Source.Data.CreateGeneralAttributeSet(typeName, memberID)` when starting from IDs.

# Resources, Audio, Video and Effects

## Scope

This page covers the Sample's runtime resource-path conventions, media template boundary and fallback expectations for optional rendering features.

## Resource paths

Use project-relative asset paths such as `Assets/System/Icon.png`, without a leading `./`, and the metadata-driven selectors. The C++ managers cache textures, shaders and audio resources; do not invent operating-system-specific separators in Lua. Android keeps finalised resources as APK assets and mirrors them into an internal runtime directory before native startup, so the same `Assets/...` key works for SFML and ordinary filesystem consumers. Use `PLATFORM` when behaviour genuinely differs by platform.

## Audio

Music, sound effects and voices have independent enable flags and volumes in `Main.ini`. The GlobalFunctions Manager group provides the gameplay-facing helpers. Missing optional sound paths should be handled deliberately; repeatedly loading the same resource under different path spellings defeats caching.

Audio effects used by the gameplay Manager and Blueprint nodes are native C++ processors selected through the `GlobalCore.AudioEffects` string-token table. The Sample provides the case-sensitive `Echo`, `Distortion`, `Underwater` and `BehindWall` presets. Their defaults remain a 0.3-second/0.5-decay echo, 2.0-drive/0.7-threshold distortion, 0.7-depth/0.3-bubble underwater effect, and 900-Hz/0.35-transmission behind-wall filter. `BehindWall` uses a two-stage low-pass filter and level reduction to create a muffled sound behind a solid barrier.

`NodeFunctions.System.SetEffect(audioType, effect)` stores the selected preset independently for the `Sound`, `Voice` or `Music` category; metadata presents both parameters as drop-downs. Selection does not create a processor and does not modify a source that is already playing. Each later source receives a newly created processor before playback, so delay lines, filter history, random state and fault state are isolated per source. Select the literal string `nil` to clear the preset for future playback. The C++ registry is authoritative and validates every string even though the Lua token table itself is a discovery snapshot. Runtime preset implementations and registration live together in the native audio-effects file; mirror any added or removed key into the hand-authored `SetEffect` metadata drop-down and the matching documentation and tests. Effect selection is not part of `SoundFilter` or `MusicFilter`.

For a non-empty preset, source creation obtains and validates the current playback-device sample rate before attaching the processor and calling `play`. The processor retains that rate for its lifetime. An active source keeps its original coefficients after device rerouting; stop and replay it to use the new device rate. SFML stores one processor per source, and presets are not automatically chained or mixed.

The Manager effect path executes only bounded native DSP on the audio thread and never enters gameplay Lua. Preset state is allocated before playback; sources with more than eight output channels are rejected by the stateful native processors. Failure to allocate that state aborts playback synchronously. Invalid callback buffers or processing failures produce silence rather than unprocessed audio; the source is stopped and the first fault is reported from the main-thread manager update. `Echo` drains its buffered tail after natural end of stream. An explicit Manager stop, dialogue skip or shutdown cancels the processor first and discards any remaining tail; scene code stops the sources it owns during scene teardown. Direct LuaSF `sf.SoundSource:setEffectProcessor` use is a separate low-level callback API: it is not part of this preset registry and retains LuaSF's best-effort state-entry and fallback behaviour.

`NodeFunctions.Scene.ShowVoiceMessageByTag` and `ShowVoiceMessage` own the current Voice for the lifetime of their dialogue. When the dialogue finishes, their latent condition stops that Voice before `FinishedDialogue` resumes downstream Blueprint execution. A following `SetEffect` therefore configures the next Voice instead of mutating the clip whose dialogue just closed. Ordinary message nodes do not change Voice playback.

## Shaders, fog and transitions

Layer shaders, screen transitions, fog, flash, tone and shake are runtime effects. Detect optional capabilities with `sf.Shader.isAvailable()` and `sf.Shader.isGeometryAvailable()`, keep a playable fallback, and test the same map without optional effects.

## Video

Video playback requires an FFmpeg-enabled project or template. Keep video files beneath `Assets/Videos` and package the correct runtime variant. Windows and macOS FFmpeg builds use shared or dynamic libraries. iOS, HarmonyOS and Android video require C++ Source + FFmpeg and use static `.a` libraries built through `Sample/cmake/FFmpeg`; downstream distribution must satisfy the applicable LGPL relinking-material requirements described in `Licenses/FFmpeg/README.md`. Android's trimmed build keeps the file protocol, MOV demuxer, H.264/AAC decoders and parsers, swscale and swresample; it does not enable network, JNI, MediaCodec or hardware acceleration. Do not assume a non-FFmpeg template can play a video merely because the asset exists.

## Verification

Test missing assets, unsupported shaders, muted channels, volume boundaries, repeated scene changes and package-relative paths. Check the final package rather than only the development tree.

## Limitations

There is no Standalone iOS, HarmonyOS or Android template. Video on those targets therefore requires the C++ Source + FFmpeg path and its static-link distribution obligations. Shader availability is determined by the runtime graphics environment, and a successful editor preview does not guarantee equivalent target hardware support.

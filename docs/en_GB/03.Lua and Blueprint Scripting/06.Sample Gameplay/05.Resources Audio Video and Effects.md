# Resources, Audio, Video and Effects

## Resource paths

Use project-relative asset paths such as `Assets/System/Icon.png`, without a leading `./`, and the metadata-driven selectors. The C++ managers cache textures, shaders and audio resources; do not invent operating-system-specific separators in Lua. Android keeps finalised resources as APK assets and mirrors them into an internal runtime directory before native startup, so the same `Assets/...` key works for SFML and ordinary filesystem consumers. Use `PLATFORM` when behaviour genuinely differs by platform.

## Audio

Music, sound effects and voices have independent enable flags and volumes in `Main.ini`. The GlobalFunctions Manager group provides the gameplay-facing helpers. Missing optional sound paths should be handled deliberately; repeatedly loading the same resource under different path spellings defeats caching.

Audio effects used by the gameplay Manager and Blueprint nodes are Lua DSP processors defined by `Source.AudioEffects`. The Sample provides the case-sensitive `Echo`, `Distortion`, `Underwater` and `BehindWall` presets. Their defaults remain a 0.3-second/0.5-decay echo, 2.0-drive/0.7-threshold distortion, 0.7-depth/0.3-bubble underwater effect, and 900-Hz/0.35-transmission behind-wall filter.

`NodeFunctions.System.SetEffect(audioType, effect)` resolves the name with `AudioEffects.Get` and stores the resulting attacher independently for the `Sound`, `Voice` or `Music` category; metadata presents both parameters as drop-downs. Selection does not create a processor and does not modify a source that is already playing. Each later source invokes the attacher, which creates an isolated audio Lua state and a fresh processor for that source. Select the literal string `nil` to clear the preset for future playback; any other unknown name raises immediately. `Source.AudioEffects` is the sole preset registry. Mirror any added or removed key into the hand-authored `SetEffect` metadata drop-down and the matching documentation and tests. Effect selection is not part of `SoundFilter` or `MusicFilter`.

For a non-empty preset, source creation captures the current playback-device sample rate before play. An active source keeps those coefficients after device rerouting; start a new Manager playback to use the new rate. The attacher must install exactly one non-empty processor, so a selected preset cannot play dry. SFML stores one processor per source; presets are not chained or mixed.

`Echo` drains its buffered tail after natural end of stream. Explicit Manager stop, dialogue skip or shutdown discards remaining tail. Direct `sf.SoundSource:setEffectProcessor` use is a separate low-level API and does not receive the Manager isolation, EOS or cancellation protocol.

`NodeFunctions.Scene.ShowVoiceMessageByTag` and `ShowVoiceMessage` capture the exact Voice handle started by that call for the lifetime of their dialogue. When the dialogue finishes, their latent condition stops that handle before `FinishedDialogue` resumes downstream Blueprint execution. A following `SetEffect` therefore configures the next Voice. Leaving or destroying a map scene also stops the current global Voice. Ordinary message nodes do not change Voice playback.

## Shaders, fog and transitions

Layer shaders, screen transitions, fog, flash, tone and shake are runtime effects. Detect optional capabilities with `sf.Shader.isAvailable()` and `sf.Shader.isGeometryAvailable()`, keep a playable fallback, and test the same map without optional effects. HarmonyOS OpenGL ES compiles an unversioned shader explicitly as ESSL 1.00. On that path, a legacy `sampler2D` uniform named `texture` is aliased internally while the public `setUniform("texture", ...)` name remains unchanged. An explicit shader version directive must match the selected backend and is not rewritten.

Fog textures use ordinary RGBA semantics: RGB supplies the fog colour, alpha supplies per-pixel density, and the map's `fogPower` scales the resulting opacity. The shader path and sprite fallback use the same colour and alpha interpretation.

Map fog data uses a strict optional-field protocol. `fog` is a string; when it is missing, `nil` or blank, fog is disabled. `fogPower`, `fogOx`, `fogOy` and `fogDistort` are finite numbers within the float range and default to `0` only when missing or `nil`. A `fogPower` at or below `0` also disables fog. Power and distortion are floored and clamped to `0..100`, while the two offset fields control scrolling. Numeric strings and other scalar coercions are not accepted.

The Sample's advanced enemy-defeat effect is controlled by the global class setting `Enemy.DefeatShatterEffectEnabled`, which defaults to `true` and is not a Blueprint field. Its shader renders a snapshot as world-space logical-pixel fragments scattering radially outward from the centre for about 0.65 seconds. The defeated enemy has already been recorded and destroyed, so the snapshot does not affect passability, collision or light blocking. When the setting is `false` or `sf.Shader.isAvailable()` is false, the enemy disappears immediately instead.

## Video

Video playback requires an FFmpeg-enabled project or template. Keep video files beneath `Assets/Videos` and package the correct runtime variant. Windows and macOS FFmpeg builds use shared or dynamic libraries. iOS, HarmonyOS and Android video require C++ Source + FFmpeg and use static `.a` libraries built through `Sample/cmake/FFmpeg`. Downstream distribution must satisfy the applicable LGPL relinking-material requirements described in `Licenses/FFmpeg/README.md`. Android's trimmed build keeps the file protocol, MOV demuxer, H.264/AAC decoders and parsers, swscale and swresample; it does not enable network, JNI, MediaCodec or hardware acceleration. Do not assume a non-FFmpeg template can play a video merely because the asset exists.

## Limitations

Shader availability is determined by the runtime graphics environment, and a successful editor preview does not guarantee equivalent target hardware support.

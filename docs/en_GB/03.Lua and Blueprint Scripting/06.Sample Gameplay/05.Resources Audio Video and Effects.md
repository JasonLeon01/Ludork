# Resources, Audio, Video and Effects

## Scope

This page covers the Sample's runtime resource-path conventions, media template boundary and fallback expectations for optional rendering features.

## Resource paths

Use project-relative asset paths such as `Assets/System/Icon.png`, without a leading `./`, and the metadata-driven selectors. The C++ managers cache textures, shaders and audio resources; do not invent operating-system-specific separators in Lua. Android keeps finalised resources as APK assets and mirrors them into an internal runtime directory before native startup, so the same `Assets/...` key works for SFML and ordinary filesystem consumers. Use `PLATFORM` when behaviour genuinely differs by platform.

## Audio

Music, sound effects and voices have independent enable flags and volumes in `Main.ini`. The GlobalFunctions Manager group provides the gameplay-facing helpers. Missing optional sound paths should be handled deliberately; repeatedly loading the same resource under different path spellings defeats caching.

Audio effects are project-authored Lua processors registered in `Source.AudioEffects.EFFECTS`, a dictionary from preset name to processor factory. The Sample provides the `Echo`, `Distortion`, `Underwater` and `BehindWall` presets with their script-defined default parameters. `BehindWall` applies a two-stage low-pass filter and level reduction to create a muffled sound behind a solid barrier. `NodeFunctions.System.SetEffect(audioType, effect)` selects the active preset independently for `Sound`, `Voice` or `Music`; metadata presents both parameters as drop-downs. A selection is applied immediately to sources already playing on that channel and becomes the default for sources played later. Select the literal `nil` entry to clear the channel effect for both current and future playback. Add new presets to the script registry and mirror their keys into the `SetEffect` metadata drop-down. Effect selection is no longer part of `SoundFilter` or `MusicFilter`.

SFML stores only one effect processor on each sound source. Selecting another preset replaces the current processor; presets are not automatically chained or mixed.

## Shaders, fog and transitions

Layer shaders, screen transitions, fog, flash, tone and shake are runtime effects. Detect optional capabilities with `sf.Shader.isAvailable()` and `sf.Shader.isGeometryAvailable()`, keep a playable fallback, and test the same map without optional effects.

## Video

Video playback requires an FFmpeg-enabled project or template. Keep video files beneath `Assets/Videos` and package the correct runtime variant. Windows and macOS FFmpeg builds use shared or dynamic libraries. iOS, HarmonyOS and Android video require C++ Source + FFmpeg and use static `.a` libraries built through `Sample/cmake/FFmpeg`; downstream distribution must satisfy the applicable LGPL relinking-material requirements described in `Licenses/FFmpeg/README.md`. Android's trimmed build keeps the file protocol, MOV demuxer, H.264/AAC decoders and parsers, swscale and swresample; it does not enable network, JNI, MediaCodec or hardware acceleration. Do not assume a non-FFmpeg template can play a video merely because the asset exists.

## Verification

Test missing assets, unsupported shaders, muted channels, volume boundaries, repeated scene changes and package-relative paths. Check the final package rather than only the development tree.

## Limitations

There is no Standalone iOS, HarmonyOS or Android template. Video on those targets therefore requires the C++ Source + FFmpeg path and its static-link distribution obligations. Shader availability is determined by the runtime graphics environment, and a successful editor preview does not guarantee equivalent target hardware support.

# Resources, Audio, Video and Effects

## Resource paths

Use project-relative asset paths such as `Assets/System/Icon.png`, without a leading `./`, and the metadata-driven selectors. The C++ managers cache textures, shaders and audio resources; do not invent operating-system-specific separators in Lua. Android keeps finalised resources as APK assets and mirrors them into an internal runtime directory before native startup, so the same `Assets/...` key works for SFML and ordinary filesystem consumers. Use `PLATFORM` when behaviour genuinely differs by platform.

## Audio

Music, sound effects and voices have independent enable flags and volumes in `Main.ini`. The GlobalFunctions Manager group provides the gameplay-facing helpers. Missing optional sound paths should be handled deliberately; repeatedly loading the same resource under different path spellings defeats caching.

Audio effects used by the gameplay Manager and Blueprint nodes are Lua DSP processors defined by `Source.AudioEffects`. The Sample provides the case-sensitive `Echo`, `Distortion`, `Underwater` and `BehindWall` presets. Their defaults remain a 0.3-second/0.5-decay echo, 2.0-drive/0.7-threshold distortion, 0.7-depth/0.3-bubble underwater effect, and 900-Hz/0.35-transmission behind-wall filter. `BehindWall` uses a two-stage low-pass filter and level reduction to create a muffled sound behind a solid barrier. `Underwater` schedules its deterministic bubble density in seconds rather than per sample and renders each event as an eight-millisecond Hann-windowed tone with a fixed per-event channel spread. This replaces the retired implementation's one-sample bubble pulses, which were audible as broadband clicks, while retaining the preset's LCG, frequency/amplitude ranges, intensity and output clamp.

`NodeFunctions.System.SetEffect(audioType, effect)` resolves the name with `AudioEffects.Get` and stores the resulting attacher independently for the `Sound`, `Voice` or `Music` category; metadata presents both parameters as drop-downs. Selection does not create a processor and does not modify a source that is already playing. Each later source invokes the attacher before playback. The attacher delegates to the source control, which creates one isolated audio Lua state and resolves the same preset there to obtain a fresh closure. Delay lines, filter history, phase, envelope and deterministic random state are therefore isolated per source and never contend with the gameplay Lua VM or another active source. Select the literal string `nil` to clear the preset for future playback; any other unknown name raises immediately. `Source.AudioEffects` is the sole preset registry and implementation. Mirror any added or removed key into the hand-authored `SetEffect` metadata drop-down and the matching documentation and tests. Effect selection is not part of `SoundFilter` or `MusicFilter`.

For a non-empty preset, source creation obtains and validates the current playback-device sample rate before attaching the processor and calling `play`. The processor retains that rate for its lifetime. An active source keeps its original coefficients after device rerouting; start a new playback through the Manager to create a source using the new device rate. The attacher must install exactly one non-empty processor. Installing none, installing an empty processor or installing more than one fails source creation synchronously, so a selected preset cannot silently play dry. SFML stores one processor per source, and presets are not automatically chained or mixed.

The effect callback uses LuaSF's copying contract. Input and output are flat, dense, 1-based arrays of interleaved samples; their array lengths are measured in samples while `inputFrameCount` and `outputFrameCount` are measured in frames. End of stream is exactly `nil` input plus a zero input-frame count. LuaSF reuses callback-scoped input/output scratch tables, overwrites or zeroes their complete current ranges and removes stale entries when a block becomes shorter; processors must not retain those tables after returning. Each preset likewise reuses one result table. The old `.value` and `.capacity` callback shapes are not accepted. Stateful presets reject more than eight output channels and reset their histories when the channel count changes or the source reaches end of stream.

Each active preset processor owns its isolated Lua state. Its collector is stopped after processor construction, and the copying bridge plus first-party processors reuse all callback tables, so steady-state blocks create no collectible Lua garbage. The audio thread uses LuaSF's non-blocking try-enter; the isolated state has no competing gameplay or source work, while shutdown/quiesce simply receives the copying fallback instead of waiting. LuaSF's GC guard still preserves the state found on entry across scratch-table population, the protected Lua call and result parsing. Finalizers run only when the isolated state is closed on the logic thread after its callback generation has quiesced. A Lua or callback-protocol error is latched and consumed from that state by the Manager update on the logic thread. A processor installed directly on a raw source and backed by a shared Lua VM instead follows LuaSF's generic try-enter contract, so contention may dry-bypass an individual block; it does not receive the Manager's isolation guarantee.

SFML can report a source as `Stopped` while the first effect callback observed in that state still contains the final real input block; later calls may contain positive-frame silence instead of a null EOS input. The first-party trampoline on Manager-returned handles processes that first real block once, moves through an atomic natural-ending stage, and only then normalises later calls to `nil` plus zero input frames. The Manager waits one logic update before its no-callback fallback so it cannot pre-empt that final block. Managed preset generations keep EOS pending until Lua acknowledges it. Once EOS is complete, the trampoline returns native `0/0` without entering Lua until the source is replayed. A processor installed directly on a raw `sf.Sound` or `sf.Music` follows SFML's callback stream and does not receive this managed EOS/control protocol. This bridge does not modify SFML.

`Echo` marks its control tail-pending whenever it processes input. It remains pending after producing the final non-empty tail block and becomes drained only when the next empty EOS callback returns `0/0`, so the last tail block is not truncated. Every managed preset finishes the EOS acknowledgement barrier only after its Lua processor has actually received EOS and reset its state. SFML's `Stopped` status can therefore be visible before managed EOS and the tail have drained; it is not a safe immediate-replay signal. A retained handle resets its preset state when replayed after EOS completion. To restart immediately, create a new source through the Manager.

Explicit Manager stop, direct stop through a Manager-returned `sf.Sound` or `sf.Music` handle, processor replacement, dialogue skip and shutdown cancel first and discard any remaining tail. Each managed source installs one stable native trampoline before playback; processor replacement or clearing atomically changes the trampoline target instead of rewriting SFML's callback while the audio thread may be using it. A lock-free generation gate rejects new activity after cancellation and lets an already-started processor call leave before replacement or clearing returns. The cancelled generation remains owned by the managed source until every callback that observed it has quiesced; its Lua callback reference and isolated state are then destroyed on the calling thread outside the audio locks, never by the audio thread. An effect processor is not a lifecycle callback: calling managed `play`, `pause`, `stop`, processor replacement or clearing, or the equivalent Manager operations from inside that audio callback is rejected and reported through LuaSF's deferred-error path. A cancelled real-input block is consumed as silence and cancelled EOS returns `0/0`. Manager attachment, playback publication, stop and shutdown never hold the Manager audio mutex while calling Lua, waiting for audio, or destroying callback references. Shutdown rejects new playback and moves out Manager records/attachers, cancels and stops the sources, waits for any in-flight source attachment, destroys their isolated states, shuts down the audio-effect runtime, and only later allows the gameplay LuaSF state and Lua VM to close. Raw sources do not provide this generation gate, cancellation protocol or self-wait rejection, so a raw effect callback must never invoke a producer-waiting lifecycle operation on its own source.

`NodeFunctions.Scene.ShowVoiceMessageByTag` and `ShowVoiceMessage` capture the exact Voice handle started by that call for the lifetime of their dialogue. When the dialogue finishes, their latent condition stops that handle before `FinishedDialogue` resumes downstream Blueprint execution, so an older latent condition cannot stop a newer Voice. A following `SetEffect` therefore configures the next Voice instead of mutating the clip whose dialogue just closed. Leaving or destroying a map scene also stops the current global Voice. Ordinary message nodes do not change Voice playback.

## Shaders, fog and transitions

Layer shaders, screen transitions, fog, flash, tone and shake are runtime effects. Detect optional capabilities with `sf.Shader.isAvailable()` and `sf.Shader.isGeometryAvailable()`, keep a playable fallback, and test the same map without optional effects. HarmonyOS OpenGL ES compiles an unversioned shader explicitly as ESSL 1.00. On the ESSL 1.00 compatibility path, a legacy `sampler2D` uniform named `texture` is aliased internally while the public `setUniform("texture", ...)` name remains unchanged, avoiding conflicts in PC shader translation layers. An explicit shader version directive must match the selected backend and the directive is not rewritten.

Fog textures use ordinary RGBA semantics: RGB supplies the fog colour, alpha supplies per-pixel density, and the map's `fogPower` scales the resulting opacity. The shader path and sprite fallback use the same colour and alpha interpretation.

Map fog data uses a strict optional-field protocol. `fog` is a string; when it is missing, `nil` or blank, fog is disabled. `fogPower`, `fogOx`, `fogOy` and `fogDistort` are finite numbers within the float range and default to `0` only when missing or `nil`. A `fogPower` at or below `0` also disables fog. Power and distortion are floored and clamped to `0..100`, while the two offset fields control scrolling. Numeric strings and other scalar coercions are not accepted.

The Sample's advanced enemy-defeat effect is controlled by the global class setting `Enemy.DefeatShatterEffectEnabled`, which defaults to `true` and is not a Blueprint field. Its shader renders a snapshot as world-space logical-pixel fragments scattering radially outward from the centre for about 0.65 seconds. The defeated enemy has already been recorded and destroyed, so the snapshot does not affect passability, collision or light blocking. When the setting is `false` or `sf.Shader.isAvailable()` is false, the enemy disappears immediately instead.

## Video

Video playback requires an FFmpeg-enabled project or template. Keep video files beneath `Assets/Videos` and package the correct runtime variant. Windows and macOS FFmpeg builds use shared or dynamic libraries. iOS, HarmonyOS and Android video require C++ Source + FFmpeg and use static `.a` libraries built through `Sample/cmake/FFmpeg`; every HarmonyOS Mobile and 2in1 FFmpeg build compiles and links for the API 22 native target. Downstream distribution must satisfy the applicable LGPL relinking-material requirements described in `Licenses/FFmpeg/README.md`. Android's trimmed build keeps the file protocol, MOV demuxer, H.264/AAC decoders and parsers, swscale and swresample; it does not enable network, JNI, MediaCodec or hardware acceleration. Do not assume a non-FFmpeg template can play a video merely because the asset exists.

## Limitations

Shader availability is determined by the runtime graphics environment, and a successful editor preview does not guarantee equivalent target hardware support.

# Troubleshooting

## Scope

Use this page after reproducing a Sample or project failure and preserving the first relevant Console message. Resolve errors from the earliest failing stage: project load, validation, native build, runtime start, resource access, then packaging.

## The project will not open

Check `Main.proj` and every loaded file beneath `Data` for valid JSON. Paths must remain inside the project. Restore required directories rather than pointing the editor at a partial package.

## A Blueprint will not save

Run Blueprint validation and address the first parent, cycle, graph, node, link, pin or default-value error. For Script Mixins, also check the relative path, returned table and same-name metadata.

## The game will not start

Read the Console from the first failure. A before-run plug-in hook may fail before compilation. Otherwise check the C++ build, generated modules, `Main.ini` entry script, Core module order and runtime protocol diagnostics.

## A node is missing

Confirm that its metadata file is pure data, returns `_METADATA`, names the member `type = "function"` or `"event"`, and is outside `Scripts/Mixins`. For C++ declarations, rebuild so bindgen regenerates metadata.

## An asset or data reference is broken

Open the reference tree, find the invalid stored key or path and update it manually. Rename and delete do not promise automatic reference repair.

## Localised text is missing

Use the Official Locale Tools checks in Plugin System and Localisation: workbook headers, ID, exported language file, selected language, fallback and `LOC`/brace format.

## Packaged behaviour differs

Check the package's assets, scripts, native modules, FFmpeg variant, writable `Main.ini` location and platform-specific path handling. Never infer the platform from path separators; use the injected `PLATFORM` value.

## Verification

Repeat the exact failing action after each correction, then run the relevant validation or package on a clean start. A later warning does not prove that the original error was resolved; confirm the first failure has disappeared.

## Limitations

This page covers common project and Sample failures. Native crashes, binding-generation failures and plug-in load failures require the specialised diagnostics in their respective development sections.

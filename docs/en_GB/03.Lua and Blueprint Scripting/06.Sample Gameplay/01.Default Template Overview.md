# Default Template Overview

The Sample is both a playable reference and the source of the reusable templates. It demonstrates the expected project shape rather than a minimal empty application. Use it to learn ownership and data flow; copy a pattern only after identifying its dependencies.

The Sample is source material, not an implicit engine contract. Confirm public behaviour in metadata, LuaLS stubs and the API reference before depending on it in another project.

## Entry and modules

`Scripts/Entry.lua` loads Core modules, reads or creates `Main.ini` through `Source.Configs.Main`, initialises localisation and latent graphs, creates the first scene and enters the C++ loop. A new config uses Medium: Render Limit `1`, 60 FPS, anti-aliasing `2` and 75% lighting resolution. The native runtime also selects plain or encrypted saves; see [Runtime Data, Configuration and Saves](<06.Runtime Data Configuration and Saves.md>). Load Core modules in this order:

```lua
local Engine = require("Engine")
local GlobalCore = require("GlobalCore")
local GlobalFunctions = require("GlobalFunctions")

local Components = GlobalFunctions.Components
local UI = GlobalFunctions.UI
local NodeGraph = GlobalFunctions.NodeGraph
local Manager = GlobalFunctions.Manager
```

## Gameplay layout

- `Scripts/Source` contains reusable Lua classes, scenes, windows, components and node functions.
- `Scripts/Mixins` contains directly attachable Lua behaviour.
- `Data/Blueprints` contains game-specific Actor classes.
- `Data/General` provides items, enemies, equipment, classes, players, states and special effects.
- `Data/Maps` and `Data/Tilesets` provide the playable world.
- `Engine/` contains the native runtime, modules and dependencies.

Public Lua modules group private implementation services under same-name directories; those services do not require or extend their host. Modules with their own `.d.lua` contract remain independent.

Native source ownership and dependencies are described in [Build and Module Layout](<../../04.Native C++ Development/01.Build and Module Layout.md>).

`Source.Data.Blueprints` compiles Blueprint, Common Function and General Data graph definitions into native `Engine.Graph` templates, then creates instances with `instantiate`.

## Template variants

`Cpp` keeps native sources and builds per project. `Cpp-ffmpeg` adds video support. Standalone variants contain a built runtime for packaging. iOS, HarmonyOS and Android packages are built only from a C++ Source variant and use the C++ Source + FFmpeg variant when video is enabled. Changing the Sample does not update an existing project; regenerate the template or apply the required changes to that project explicitly.

Runtime Lua, `Scripts/stub` declarations and `_meta.lua` file-layer rules are in [Lua Runtime and Modules](../01.Lua Runtime and Modules.md).

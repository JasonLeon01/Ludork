# Default Template Overview

The Sample is both a playable reference and the source of the reusable templates. It demonstrates the expected project shape rather than a minimal empty application.

## Entry and modules

`Scripts/Entry.lua` loads Core modules, uses `Source.Config.Main` to read or initially create `Main.ini`, initialises locale catalogues and latent graph support, creates the first scene and enters the C++ main loop. The template also declares the global `SAVE_AS_LDC = false` in the entry point. Standard saves use `.json` while it remains false; setting it to `true` selects encrypted `.ldc` files containing JSON-serialised data. This runtime save setting is independent of the packaging option **Encrypt Data**. Core modules must be loaded in this order:

```lua
local Engine = require("Engine")
local GlobalCore = require("GlobalCore")
local GlobalFunctions = require("GlobalFunctions")

local Components = GlobalFunctions.Components
local UI = GlobalFunctions.UI
local NodeGraph = GlobalFunctions.NodeGraph
local Manager = GlobalFunctions.Manager
```

## Gameplay layout

- `Scripts/Source` contains reusable Lua classes, scenes, windows, components and node functions.
- `Scripts/Mixins` contains directly attachable Lua behaviour.
- `Data/Blueprints` contains game-specific Actor classes.
- `Data/General` provides items, enemies, equipment, classes, players, states and special effects.
- `Data/Maps` and `Data/Tilesets` provide the playable world.
- `Core` provides native modules and generated bindings.

## Template variants

`Cpp` keeps native sources and builds per project. `Cpp-ffmpeg` adds video support. Standalone variants contain a built runtime for packaging. iOS, HarmonyOS and Android packages are built only from a C++ Source variant and use the C++ Source + FFmpeg variant when video is enabled. Changing the Sample does not update an existing project; regenerate the template or apply the required changes to that project explicitly.

When learning an API, inspect the documented Sample file, its mirrored `.d.lua` declaration and its same-name metadata together. Runtime Lua shows behaviour, `Scripts/stub` shows public documentation and LuaLS types, and `_meta.lua` shows what the editor can expose.

## Verification

Create a project from the selected template, confirm that `Scripts/Entry.lua` requires the three Core modules in the documented order and that `SAVE_AS_LDC` is disabled by default, then run the project and reach its initial scene without a module-loading error.

## Limitations

The Sample is an integrated reference project, not a minimal dependency list. Its content is copied when a project is created; later changes to the installed Sample do not update that project.

# Actors, Enemies, Items and Equipment

## Scope

This page explains how the Sample combines script classes, Blueprints and General Data to define world actors, enemies, items and equipment. It identifies ownership boundaries rather than duplicating each schema field.

## Actors and characters

`Actor` supplies map ownership, position, lifecycle and collision-facing behaviour. Character-style classes add movement and direction. Public class defaults belong on the Lua class table; `init` is reserved for constructor arguments and private runtime state.

## Enemies

Enemy Blueprints combine class defaults with an Enemy General Data member. Runtime data supplies combat values, rewards, drops, animation and special-effect configuration. The `onDefeat` graph is optional and is executed only when present.

## Items

Item records define presentation, usability, price, icon and whether use consumes the item. Member graphs implement `onUse` and `onGet`. Keep reusable algorithms in Lua or Common Functions rather than duplicating large member graphs.

## Equipment

Equipment records define slot and attribute additions. `onEquip` and `onUnequip` graphs apply special behaviour around the ordinary stat changes. Slot names must match the selected Class data.

## Runtime references

Use General Data identifiers as stable keys. Display names and descriptions may be brace-wrapped localisation identifiers; the lookup table is managed by Plug-in Development and Installation. Renaming an identifier requires updating every reference.

The exact Sample schemas and member lists are in General Data Reference. Practical Bottle, Gem, door and enemy examples are in Usage Recipes.

## Verification

Create one actor of each relevant kind, run the map, and verify its Blueprint defaults, referenced General Data record and member graphs. For equipment, test both equip and unequip paths; for consumables, test use and inventory removal independently.

## Limitations

General Data identifiers are project contracts and are not repaired automatically when renamed. The Sample's combat and inventory rules are examples, not mandatory engine behaviour.

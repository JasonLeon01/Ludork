# New Game, Title and Scene Flow

The default entry creates `Source.Scenes.SceneInit`, then hands control to the native System loop. SceneInit prepares shared data and advances to the title flow. Its logic tick performs loading and transition checks, while its render-thread late tick publishes progress to the declarative UI. Keeping the UI update on the render thread prevents GPU-backed controls from being mutated by the logic thread. The title scene builds menu windows for Start Game, Continue, Config and Exit Game.

## Goal

Adapt the Sample title flow while preserving deterministic project initialisation, explicit save handling and safe scene transitions.

## Prerequisites

- A known initial map and player definition for the New Game path.

## Steps

### Configure New Game

A new-game action creates or resets the game instance, selects the initial map and player data, and changes to the map scene. `Data/Configs/System.json` stores the player Blueprint under `startPlayerBlueprint` as a path relative to `Data/Blueprints`, and stores the initial region under `startRegion`. These values initialise new games only; Continue restores the player class and current region saved in the selected slot.

`startMap` may identify an ordinary map, a composite-world manifest such as `World_01/_world.json`, or a placed world child such as `World_01/Map_03.json`. `startPos` is a world coordinate for a manifest target and a child-local coordinate for a child target. The editor presents all three forms through one map tree and stores the selected string path.

### Enter maps and composite worlds

`NodeFunctions.Scene.GotoMap` follows the same path and coordinate rules. Entering another child of the current world keeps its `WorldGameMap` facade; unplaced children are invalid destinations.

For a world, `Scene:getGameMap()` and `Actor:getMap()` expose one world-coordinate GameMap facade. Child placements provide passability, Dir4, materials and terrain; uncovered cells are passable holes. Missing or inconsistent child data is an error.

World placements are indexed natively. Installing, rebuilding or evicting a child updates the index; Actor publication and Tile-chunk readiness gate gameplay access. Navigation and material queries neither call Lua per cell nor load absent children.

On entry, runtime revalidates the flat world directory, exact `_world.json`, child files, placements and layer order; invalid data fails.

Children progress through `Unloaded`, `Reading`, `Prepared`, `Active` and `Dormant`. Streaming prioritises the Camera neighbourhood and cancels obsolete reads. Only Active Actors simulate; until every visible placement and Tile chunk is ready, the Camera retains its last complete frame and colliding movement cannot enter the unprepared area.

Active Actors outside the Camera's conservative world-space bounds continue to simulate but are omitted from the colour and lighting-surface render passes. Region-layer visibility is still applied before this viewport test. World scenes keep the ordinary automatic Lua garbage collector active; streaming releases region references through its normal lifecycle instead of stopping the global collector and advancing it with one manual step per tick.

With transitions enabled, world entry freezes the outgoing frame until the target viewport and required Actors, lights and Tile chunks are ready. Required-data failures propagate before release. `blockTransition = true` skips the mask but keeps this readiness barrier; surrounding preparation remains asynchronous.

Non-Active payloads use a 32-region or estimated 256-MiB LRU. Dormant regions are evicted before Prepared ones; Active and pending destinations are pinned and may temporarily exceed the soft limit.

The Performance Monitor exposes streaming state and logs one warning per world session when an asynchronous publish tick reaches 4 ms, including its slowest measured stage. See [Start Page, Workspace and Shortcuts](<../../02.Editor User Guide/01.Start Page Workspace and Shortcuts.md>).

`RegionDict` remains floor-transfer data and does not define world composition or streaming.

### Configure Continue

Continue uses `GetSavePath(slot)` to read the standard save selected by the current `SAVE_AS_LDC` setting: `.json` by default, or an encrypted `.ldc` containing JSON-serialised data when enabled. It restores game state and opens the appropriate scene. A missing, malformed or unsupported save must follow the explicit not-found/error path instead of silently constructing partial state.

### Preserve scene transitions

Use the System and scene APIs documented in Blueprint API Reference. Scene changes are scheduled by the C++ runtime so that active updates are not destroyed midway through a frame. Windows and temporary resources owned by the outgoing scene should be released through its normal lifecycle.

### Customise the title

Edit the Lua scene/window composition and corresponding data, then keep all text identifiers compatible with [Game Localisation Workflow](<../../05.Plug-in Development and Installation/06.Game Localisation Workflow.md>). Test Start Game, Continue with and without a save, Config, Exit Game and return-to-title from a running map.

## Limitations

The Sample does not define a universal save upgrade policy or title-screen design. A released game must define the versions it supports and provide its own presentation and recovery messages.

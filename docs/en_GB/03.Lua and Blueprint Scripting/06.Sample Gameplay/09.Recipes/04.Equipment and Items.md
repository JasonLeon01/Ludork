# Equipment and Items

## Goal

Create item and equipment records with stable inventory IDs, valid slots and focused member-graph behaviour.

## Prerequisites

- Item, Equip and Class General Data with the required inventory and slot identifiers.
- Blueprint parents derived from `Source.Item` or `Source.Equip`.

## Steps

Item and Equip schemas separate reusable definitions from inventory instances.

- Use Item `usable` and `cost` to control menu availability and consumption.
- Put inventory use in `onUse` and enemy drop behaviour in `onDrop`. Runtime activates both as `GeneralDataGraphAbility`; `onUse` targets the Player and `onDrop` the spawned Item Actor.
- Match Equip `slot` to the selected Class slot dictionary.
- Store stat changes in `attrPlus`; reserve `onEquip` and `onUnequip` graphs for special behaviour.
- Keep icons under `Assets/Icons` and use the resource selector.

## Sample equipment

`BP_Equip_Sword_A.json` derives from `Source.Equip` and sets `ID = "Sword_A"`, which resolves the Equip member.

`attrPlus` becomes a slot-sourced Infinite Gameplay Effect. Equipping applies it before `onEquip`; unequipping removes it before `onUnequip`, so replacement cannot leave old modifiers behind.

## Sample item

`BP_Item_Key_Y.json` derives from `Source.Item` and sets `ID = "KEY_Y"`, matching both the Item member and the yellow door's `needKeyID`.

Owning an Item grants its `onUse` ability; removing the last copy revokes it. `Player:activateItem` targets that Player, and the graph decides when to consume the Item. `cost` remains menu policy, not an Ability System cost.

Test buying, selling, drops, use, equipment replacement and save restore. Loading rebuilds saved Item abilities and equipment Effects without replaying member graphs. Also test missing icons, unknown IDs, invalid slots and renamed members.

## Limitations

Renaming a member does not repair stored references automatically. A Class slot mismatch and an unknown record ID remain explicit data errors.

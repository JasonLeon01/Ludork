# Consumables

## Goal

Create a collision-driven healing or attribute pickup with a Script Mixin.

## Prerequisites

- A saved Actor-derived Blueprint with collision enabled.
- Matching Player fields or components and a valid Audio configuration fallback.

## Steps

Use a Script Mixin when the item's behaviour is naturally expressed as an Actor collision method.

1. Create an Actor-derived Blueprint and enable Script Mixin.
2. Attach `Consumables/Bottle.lua` or `Consumables/Gem.lua`.
3. Set `HP_plus` for a healing bottle, or `ATTR_key` and `plus` for a gem.
4. Select a sound or leave the value empty to use the Audio config fallback.
5. Place the Blueprint on a map and test collision with and without a player.

The mixin checks destroyed state, identifies the player in the collision list, applies the value, calls inherited collision behaviour, records the destroyed actor and destroys itself. Keep editable defaults in the returned table and expose them in the same-name metadata.

## Sample walkthrough

- `Bottle_200.json` derives directly from `Engine.Actor`, enables `scriptMixin`, selects `Consumables/Bottle.lua`, sets `HP_plus = 200`, enables collision and selects the potion texture.
- `Gem_1_1.json` selects `Consumables/Gem.lua`, sets `ATTR_key = "ATK"` and `plus = 1`, and selects the gem texture.
- Both leave `getSE` at its metadata default, so the script resolves `Audio.getSE`.

## Verification

Test a player collision, a non-player collision and an already-destroyed instance, then repeat after packaging.

## Limitations

The Sample scripts depend on their declared parent capabilities, metadata fields and General Data/configuration keys; they are not universal inventory components.

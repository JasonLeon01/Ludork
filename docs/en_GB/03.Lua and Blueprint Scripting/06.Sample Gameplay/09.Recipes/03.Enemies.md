# Enemies

## Goal

Create an enemy whose physical Blueprint and General Data combat definition remain independently reusable.

## Prerequisites

- A valid Enemy General Data file and an Actor-compatible enemy parent.
- Existing Item Blueprint paths, special-effect identifiers and animation identifiers referenced by the new record.

## Steps

Create enemy definitions in General Data and enemy bodies as Blueprints.

1. Add an Enemy member with combat values, rewards, drops, special effects and animation key.
2. Create or derive an Enemy Blueprint and point it at the data member.
3. Configure movement, collision and presentation defaults.
4. Add an `onDefeat` member graph only for data-specific behaviour.
5. Place the Blueprint and test combat, rewards, drops, save/load and map reset.

Shared combat algorithms belong in Lua or Common Functions. General Data member graphs should remain focused on differences between records.

## Sample walkthrough

`BP_Enemy_Slime.json` derives from `Source.Enemy` and sets `ID = "Slime"`; that ID resolves the `Slime` member in `Data/General/Enemy.json`. The Blueprint owns physical/presentation defaults such as texture, source rectangle and material speed. The General Data member owns `MAXHP`, `ATK`, `DEF`, `EXP`, `GOLD`, `drops`, `special` and `ANIMATION_KEY`.

The built-in defeat shatter is selected project-wide through `Enemy.DefeatShatterEffectEnabled`, which defaults to `true`; it is a global class setting, not a Blueprint field. Enabled enemies are recorded and destroyed immediately for gameplay, while a non-colliding, non-light-blocking snapshot scatters radially outward from the centre as world-space logical-pixel fragments for about 0.65 seconds. Set the class setting to `false`, or run without shader support, to retain immediate disappearance.

Each `drops` key is a Blueprint class path derived from `Source.Item`, not an Item General Data ID, and its `sf.Vector2i` value is the offset from the enemy's cell. On defeat the Item is spawned at that target on the same layer, persisted as an added Actor and sent its `onDrop` event. The persistent tag combines the Blueprint path with the absolute target coordinates; an existing identical tag skips that drop and writes a warning.

`GhostSoldier` demonstrates `special.Reborn = "Data.Blueprints.Enemies.BP_Enemy_Skeleton_01"`. Once its optional `onDefeat` graph finishes, the original is recorded and destroyed, then the target Blueprint is spawned on the same cell and layer with a new map-placement tag and recorded as an added Actor. Do not reuse the defeated Actor's tag: the destroyed record would remove the replacement when the map is rebuilt.

To make a variant, duplicate an existing enemy Blueprint, create or select the matching Enemy member, update the Blueprint `ID`, and then change presentation separately.

## Limitations

Unknown IDs and missing referenced records are errors. The runtime does not synthesise replacement combat definitions.

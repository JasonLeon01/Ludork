# Enemies

## Goal

Create an enemy whose physical Blueprint and General Data combat definition remain independently reusable.

## Prerequisites

- A valid Enemy General Data file and an Actor-compatible enemy parent.
- Existing drop, special-effect and animation identifiers referenced by the new record.

## Steps

Create enemy definitions in General Data and enemy bodies as Blueprints.

1. Add an Enemy member with combat values, rewards, drops, special effects and animation key.
2. Create or derive an Enemy Blueprint and point it at the data member.
3. Configure movement, collision and presentation defaults.
4. Add an `onDefeat` member graph only for data-specific behaviour.
5. Place the Blueprint and test combat, rewards, drops, save/load and map reset.

Shared combat algorithms belong in Lua or Common Functions. General Data member graphs should remain focused on differences between records.

## Sample walkthrough

`BP_Enemy_Slime.json` derives from `Source.Enemy` and sets `ID = "Slime"`; that ID resolves the `Slime` member in `Data/General/Enemy.json`. The Blueprint owns physical/presentation defaults such as texture, source rectangle and material speed. The General Data member owns `MAXHP`, `ATK`, `DEF`, `EXP`, `GOLD`, `drops`, `special` and `ANIMATION_KEY`.

To make a variant, duplicate an existing enemy Blueprint, create or select the matching Enemy member, update the Blueprint `ID`, and then change presentation separately. Run the same map against a normal enemy and the variant. Verify damage, defeat, rewards, every referenced drop/special/animation, optional `onEncounter`/`onDefeat` graphs, save/load and map reset. An unknown ID is a broken data reference, not a request to invent default combat data.

## Expected result

The Blueprint supplies presentation and placement while its stable Enemy ID resolves all combat data and record-specific graphs.

## Verification

Run the normal enemy and variant in the same map, then verify combat, rewards, references, optional graphs, save/load and map reset as described above.

## Limitations

Unknown IDs and missing referenced records are errors. The runtime does not synthesise replacement combat definitions.

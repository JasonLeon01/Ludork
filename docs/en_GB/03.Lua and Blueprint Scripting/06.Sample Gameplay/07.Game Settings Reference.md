# Game Settings Reference

Game Config edits supported `[Main]` values in `Main.ini`.

## Supported keys

| Key | Type | Meaning |
|---|---|---|
| `script` | path | Lua entry script; normally `Scripts/Entry.lua` |
| `language` | string | Game catalogue key; see Game Localisation Workflow |
| `scale` | float | Display-scale preference; desktop and HarmonyOS 2in1 default to `1.0`, while a HarmonyOS Mobile tablet with free-window mode enabled defaults a missing value to `0` in memory |
| `maxrenderscale` | float | Maximum internal render scale, default `2.0`; Unlimited (`0`) removes the cap |
| `lightingrenderscale` | discrete float | Direct-light render scale: `0.5`, `0.75` or `1.0`; missing or invalid values use `1.0` |
| `framerate` | integer | Target frame rate, default `30` |
| `antialiasinglevel` | non-negative integer | Requested SFML anti-aliasing level; defaults to `sf::ContextSettings`' own default |
| `verticalsync` | boolean | Vertical synchronisation |
| `musicon`, `soundon`, `voiceon` | boolean | Channel enable switches |
| `musicvolume`, `soundvolume`, `voicevolume` | float | Channel volume, clamped to 0–100 |

The editor preserves unknown sections and keys. Invalid supported values fall back to safe defaults in the applicable reader; correct the source rather than relying on fallback.

`Main.proj` contains project/tooling flags rather than mutable game preferences. `Cpp` selects native-project behaviour, `ffmpeg` selects video-capable packaging, and `IndividualWindow` stores the preferred editor run mode.

Settings changed while a project is open participate in the combined dirty state and are written by the normal Save action. Existing files keep their stored frame rate; changing the default to `30` does not overwrite a previous value.

Scale applies immediately where `System.isDisplayScaleConfigurable()` is true. On desktop, including HarmonyOS 2in1, positive values resize the window, `0` selects borderless fullscreen, manual resizing is not saved, and unmatched aspect ratios are letterboxed. A HarmonyOS Mobile API 22-or-newer tablet exposes Scale only in free-window mode: positive values request a freeform window and `0` requests maximised/fullscreen. A config created there writes `scale = 0`; a missing key uses `0` in memory only. Config updates the row when that mode changes and rechecks it before saving. Other mobile hosts omit Scale. Invalid negative or non-finite values resolve to `1`. See [Scenes and System](<../07.API Reference/04.Core Modules/03.GlobalCore/06.Scenes and System.md>) for host mapping.

`maxrenderscale`, shown as Render Limit, caps the internal System canvas and dependent render targets without changing the window, logical game size or configured Scale. It applies immediately on every platform. Config offers `0.5`, `0.75`, `1`, `1.5`, `2`, `3`, `4` and Unlimited (`0`), retains another finite non-negative value, and resolves a negative or non-finite value to `2`.

Lighting Render Scale applies immediately without rebuilding the System canvas. The dynamic direct-light target uses the current logical camera view, while the static target always uses the complete map logical view; each target axis is `floor(logicalPixels * lightingrenderscale)` with a minimum of one pixel. The surface mask and static/dynamic transmission and occupancy targets stay full-resolution. Values below `1.0` use smooth upsampling; `1.0` preserves the full-resolution sampling path. A scale change rebuilds the two direct-light targets, invalidates the static-light cache and affects the next map frame. Other numbers, non-finite values and a missing key resolve to `1.0`.

Config lists Low, Medium, High, Extra High, Original and Custom in that order. It derives the current Quality Preset from (`maxrenderscale`, `framerate`, `antialiasinglevel`, `lightingrenderscale`):

| Preset | Values |
|---|---|
| Low | (`0.75`, `30`, `0`, `0.5`) |
| Medium | (`1`, `60`, `2`, `0.75`) |
| High | (`2`, `60`, `8`, `1`) |
| Extra High | (`3`, `90`, `8`, `1`) |
| Original | (Unlimited (`0`), `120`, `8`, `1`) |

Any other tuple displays the final, display-only Custom option; selecting it applies no values. No preset key is stored, and `scale` and `verticalsync` do not participate.

The anti-aliasing level is a requested multisample level. SFML may create the closest context supported by the platform. `0` is SFML's default and disables anti-aliasing. Because it is a context-creation setting, changing it saves the preference but affects rendering only after the display is initialised again, normally on the next game start. Negative or out-of-range values resolve to the SFML default.

Standalone desktop startup, including HarmonyOS 2in1, filters positive Scale presets `1`, `1.25`, `1.5`, `1.75`, `2`, `3` and `4` against the primary display work area; Config rechecks the window's current display when opened. HarmonyOS Mobile free-window mode uses the smaller of the display's available area and the Stage maximum. Fullscreen (`0`) and a fitting non-preset value remain available. An over-limit value becomes the highest fitting preset, or Fullscreen if none fits, and moving to a larger display does not raise it automatically. A failed size query leaves the choices and value unchanged.

## Limitations

Supported keys are interpreted by the current Sample readers. Adding a project-specific key requires corresponding runtime handling; merely adding it to `Main.ini` does not create behaviour.

A configurable HarmonyOS Mobile host samples its maximum windowed dimensions when the native host is initialised and whenever free-window mode becomes enabled. Moving the running window to another display or changing the display's available area without a free-window mode transition requires a host rebuild or restart before the Scale choices use the new capacity. HarmonyOS 2in1 instead follows the ordinary desktop window and display queries.

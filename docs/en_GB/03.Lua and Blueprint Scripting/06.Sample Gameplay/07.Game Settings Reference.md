# Game Settings Reference

Game Config edits supported `[Main]` values in `Main.ini`.

## Supported keys

| Key | Type | Meaning |
|---|---|---|
| `script` | path | Lua entry script; normally `Scripts/Entry.lua` |
| `language` | string | Game catalogue key; see Game Localisation Workflow |
| `scale` | float | Display-scale preference; desktop defaults to `1.0`, while a configurable HarmonyOS tablet defaults a missing value to `0` in memory |
| `maxrenderscale` | float | Maximum internal render scale, default `2.0`; Unlimited (`0`) removes the cap |
| `framerate` | integer | Target frame rate, default `30` |
| `antialiasinglevel` | non-negative integer | Requested SFML anti-aliasing level; defaults to `sf::ContextSettings`' own default |
| `verticalsync` | boolean | Vertical synchronisation |
| `musicon`, `soundon`, `voiceon` | boolean | Channel enable switches |
| `musicvolume`, `soundvolume`, `voicevolume` | float | Channel volume, clamped to 0–100 |

The editor preserves unknown sections and keys. Invalid supported values fall back to safe defaults in the applicable reader; correct the source rather than relying on fallback.

`Main.proj` contains project/tooling flags rather than mutable game preferences. `Cpp` selects native-project behaviour, `ffmpeg` selects video-capable packaging, and `IndividualWindow` stores the preferred editor run mode.

Settings changed while a project is open participate in the combined dirty state and are written by the normal Save action. Existing files keep their stored frame rate; changing the default to `30` does not overwrite a previous value.

The running Sample applies Scale immediately when `System.isDisplayScaleConfigurable()` is true. On desktop, a positive value sizes a resizable window; manual resizing changes only the current run and does not overwrite `Main.ini`. A manually chosen non-game aspect ratio is letterboxed rather than stretched, and `0` selects borderless desktop fullscreen. On a configurable HarmonyOS tablet, a positive Scale requests a freeform window and `0` requests maximised/fullscreen; new configs write `scale = 0`, and a missing key defaults to `0` in memory only. Other mobile hosts keep their platform-controlled scale and do not expose the row. Invalid negative or non-finite Scale values resolve to `1`. Host window mapping is in [Scenes and System](<../07.API Reference/04.Core Modules/03.GlobalCore/06.Scenes and System.md>).

Maximum Render Scale caps the internal System canvas and its dependent render targets without changing the native window, logical game size or configured Scale. It applies immediately on every platform. A negative or non-finite value resolves to `2`.

The anti-aliasing level is a requested multisample level. SFML may create the closest context supported by the platform. `0` is SFML's default and disables anti-aliasing. Because it is a context-creation setting, changing it saves the preference but affects rendering only after the display is initialised again, normally on the next game start. Negative or out-of-range values resolve to the SFML default.

Standalone desktop startup filters positive Scale presets `1`, `1.25`, `1.5`, `1.75`, `2`, `3` and `4` against the primary display's work area; Config rechecks the window's current display when opened. A configurable HarmonyOS tablet filters the same presets against the smaller of its current display's available area and the Stage window's maximum dimensions. Fullscreen (`0`) and a fitting configured non-preset value are retained. An over-limit value is saved as the highest fitting preset, or as Fullscreen if none fits; moving to a larger display does not raise it. A failed display-size query leaves the choices and configured value unchanged.

## Limitations

Supported keys are interpreted by the current Sample readers. Adding a project-specific key requires corresponding runtime handling; merely adding it to `Main.ini` does not create behaviour.

A configurable HarmonyOS host samples its maximum windowed dimensions when the native host is initialised. Moving the running window to another display or changing the display's available area requires a host rebuild or restart before the Scale choices use the new capacity.

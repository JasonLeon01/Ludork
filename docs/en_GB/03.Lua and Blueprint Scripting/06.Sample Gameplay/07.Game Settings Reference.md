# Game Settings Reference

Game Config edits supported `[Main]` values in `Main.ini`.

## Scope

This reference lists settings presented by the Sample Game Config workflow. It distinguishes mutable runtime preferences in `Main.ini` from project and tool flags in `Main.proj`.

## Supported keys

| Key | Type | Meaning |
|---|---|---|
| `script` | path | Lua entry script; normally `Scripts/Entry.lua` |
| `language` | string | Game catalogue key; see Game Localisation Workflow |
| `scale` | float | Preferred canvas-to-window scale; `0` selects borderless desktop fullscreen |
| `framerate` | integer | Target frame rate |
| `verticalsync` | boolean | Vertical synchronisation |
| `musicon`, `soundon`, `voiceon` | boolean | Channel enable switches |
| `musicvolume`, `soundvolume`, `voicevolume` | float | Channel volume, clamped to 0–100 |

The editor preserves unknown sections and keys. Invalid supported values fall back to safe defaults in the applicable reader; correct the source rather than relying on fallback.

`Main.proj` contains project/tooling flags rather than mutable game preferences. `Cpp` selects native-project behaviour, `ffmpeg` selects video-capable packaging, and `IndividualWindow` stores the preferred editor run mode.

Settings changed while a project is open participate in the combined dirty state and are written by the normal Save action. The running Sample applies scale immediately. A positive scale sizes a resizable desktop window; manual resizing changes only the current run and does not overwrite `Main.ini`. Invalid negative or non-finite scale values resolve to `1`.

## Verification

Change one supported value at a time, save, close and reopen the project, then run the game and confirm the effective value. Inspect `Main.ini` to ensure unrelated sections and keys were preserved.

## Limitations

Supported keys are interpreted by the current Sample readers. Adding a project-specific key requires corresponding runtime handling; merely adding it to `Main.ini` does not create behaviour.

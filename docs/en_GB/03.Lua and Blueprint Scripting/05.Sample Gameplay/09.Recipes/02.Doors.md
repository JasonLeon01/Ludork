# Doors

## Goal

Create a door that opens through an inventory key or a named game-state condition.

## Prerequisites

- A valid `Source.DoorBase.DoorBase` Blueprint parent and door sprite sheet.
- Matching Item or Game Variable identifiers for the selected workflow.

## Steps

A door Blueprint combines collision behaviour, an opening animation, door state and an optional key or condition.

When the opening animation finishes, `DoorBase` records its map-placement tag as destroyed, provided the tag is not empty. Rebuilt maps omit that placement, so the door remains absent across map transfers and save and load.

`DoorBase` inherits `tickable = false` and enables ticks only while opening or reversing.

### Key door

1. Derive a general door from `Source.DoorBase.DoorBase` and configure its texture, rectangle, collision and opening defaults.
2. Derive a colour-specific door. The Sample's `BP_Door_Y.json` derives from `BP_Door_General` and stores `needKeyID = "KEY_Y"`.
3. In `onCollision`, reject a door that is already opening and require `MeetPlayer`.
4. Read `needKeyID`, call `GetItemCount` and compare the count with one.
5. On success, call the inherited collision flow through `SUPER`, then remove one key. Leave the failure branch disconnected, or connect explicit feedback.

The key ID must match an Item member and its pickup Blueprint, such as `KEY_Y` and `BP_Item_Key_Y.json`.

### Conditional door

`Mixins/Doors/ConditionDoor.lua` polls `openConditionName` against `openConditionVal`. An empty name disables polling. A configured name with no variable starts at zero. Reaching the threshold calls `openDoor`.

`openConditionName` uses a numeric-only `InstVar` selector, so it lists `int` and `float` declarations from the Game Variable Manager. `openConditionVal` uses `InstVarValue`, so it adopts the numeric editor of the selected declaration. The Sample's generated declarations include `MTExample = 0` for this workflow.

Test the door with no key, with one key and with repeated collision while it opens. Also test a missing or renamed key, numeric selector filtering, a condition below, equal to and above the threshold, saved variable restoration and map reload. Open multiple placed doors, revisit the map, then save and load. Confirm that each door remains absent independently. Inspect references before renaming IDs.

## Limitations

Door logic does not perform scene travel. Use Teleporter for map-to-map movement. Update every stored reference when a key or condition identifier is renamed.

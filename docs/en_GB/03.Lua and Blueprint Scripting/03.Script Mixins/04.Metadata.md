# Script Mixin Metadata

The same-name `_meta.lua` file must return `_METADATA` and contain exactly one type whose name matches the script file name.

## Scope

Script Mixin metadata exposes editable fields for one attached behaviour. It does not declare runtime methods, Blueprint node entries or an inheritance hierarchy.

```lua
local _METADATA = {
    KeyDoor = {
        attrs = {
            "needKeyID",
            "needKeyCount",
        },
        needKeyID = {
            type = "string",
            default = "",
            Meta = {
                GeneralDataVars = "Item",
            },
        },
        needKeyCount = {
            type = "int",
            default = 1,
        },
    },
}

return _METADATA
```

## Rules

- `attrs` is a dense, ordered array of unique, non-empty field names.
- Every listed field is a table with a valid `type`.
- `default`, when present, is finite, acyclic, JSON-convertible pure data.
- `bases` is absent or an empty table. Blueprint inheritance supplies the base.
- The root contains no second type, function, userdata, coroutine or external-state access.
- Decorators such as `Meta.GeneralDataVars`, `Meta.PathVars` and `Meta.ConfigVars` refine the editor control without changing runtime values.

Mixin metadata participates in attached-script field discovery and is excluded from the ordinary Blueprint node catalogue.

## Verification

Open the attached Blueprint, compare its Inspector field order with `attrs`, and validate every default and decorator-driven selector. Run the behaviour separately because loading metadata never executes it.

## Limitations

The root may contain only one matching type and cannot contain functions, runtime objects, side effects or metadata bases. A field omitted from both saved attributes and `default` is schema-only.

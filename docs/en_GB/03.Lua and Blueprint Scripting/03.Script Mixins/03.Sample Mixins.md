# Sample Script Mixins

The Sample project contains five mixins that demonstrate distinct responsibilities. Use them as behaviour patterns and verification fixtures; copy their contract shape only when the new Blueprint parent and data dependencies match.

| Script | Parent capability | Behaviour |
|---|---|---|
| `Consumables/Bottle.lua` | Collidable Actor | Detects the Player, restores HP, plays a configured sound and destroys the pickup. |
| `Consumables/Gem.lua` | Collidable Actor | Adds a value to a direct Player field or matching component field. |
| `Doors/Door.lua` | `DoorBase` | Opens on collision and guards against repeated opening. |
| `Doors/KeyDoor.lua` | Script Mixin door Blueprint | Requires and consumes a configured General Data item before continuing the parent collision method. |
| `Doors/ConditionDoor.lua` | `DoorBase` | Watches a named game variable during ticks and opens when it reaches the configured threshold. |

## Consumable pattern

`Bottle` and `Gem` check `self:isDestroyed()` before processing collision, find the active Player from the Scene, perform their data change, call inherited collision behaviour, record the destroyed Actor and destroy the pickup. Their sound field uses a project configuration fallback when it is empty.

## Door pattern

`Door` owns the common collision method. `KeyDoor` calls that method only after `MeetPlayer`, item-count and re-entry checks pass, then removes the key. `ConditionDoor` has independent `onCreate`, `onTick` and `onDestroy` lifecycle work and uses the door's existing `openDoor` API.

## Verification

- Test each mixin with the parent type used by the matching Sample Blueprint.
- Confirm configurable IDs resolve to current General Data.
- Trigger collision more than once and confirm the opening/destruction guard prevents duplicate work.
- For `ConditionDoor`, test below, at and above the configured threshold.

## Limitations

The Sample IDs, sounds and General Data records are project-specific. A copied Mixin still requires matching metadata, parent capabilities and runtime references.

# Script Mixin Validation and Packaging

## Goal

Validate an attached script and its metadata before saving, then prove that the packaged game loads every referenced Mixin.

## Prerequisites

- A Blueprint chain configured for Script Mixin mode.
- A runtime/metadata file pair beneath `Scripts/Mixins`.
- A representative map containing each affected Blueprint.

## Steps

1. Validate the relative script path and same-name metadata file.
2. Resolve save-time Blueprint and field diagnostics in reported order.
3. Run every lifecycle/event path in editor mode.
4. Package with the intended Lua compilation setting and repeat the runtime checks.

## Path validation

`scriptPath` must be a non-empty relative `.lua` path beneath `Scripts/Mixins`. It uses forward slashes and cannot contain an empty segment, `.`, `..`, a drive prefix, an absolute root or an `_meta.lua` suffix.

The first Script Mixin Blueprint in a chain must set `scriptPath`. A child may inherit it or provide another valid path. A local path that names a missing file fails validation.

## Save-time validation

Before saving, the editor verifies parent and mode-chain validity, the script path and same-name metadata file, and the metadata rules in [Script Mixin Metadata](<04.Metadata.md>). Resolve the first reported path or metadata error before examining downstream field errors.

## Packaging

Pack copies the project's `Scripts` tree into staging. **Use luac** compiles Lua files in staging and never rewrites project source. Before distributing, perform one package run with each referenced Script Mixin Blueprint and confirm the Console contains no module-resolution error.

## Limitations

Editor metadata validation does not prove that all parent methods exist. Packaging preserves valid source paths but cannot repair stale Blueprint attributes.

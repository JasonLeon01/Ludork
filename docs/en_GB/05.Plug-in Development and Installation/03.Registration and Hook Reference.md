# Registration and Hook Reference

Registration occurs only inside `IEditorPlugin.Register`. The API exposes six registration methods.

## Menu commands

`RegisterMenuCommand(PluginMenuCommand)` inserts a command into `File`, `Edit`, `Game`, `Database`, `Help` or `Plugins`. IDs must be non-empty and globally unique. `Order` sorts the commands within a location.

The handler receives an optional project path, the editor language, the read-only plug-in directory, the writable plug-in data directory, the message UI, text-hint invalidation, a plug-in-scoped secret store, an optional Blueprint assistant host bridge and cancellation. An Avalonia source plug-in that references `Ludork.Plugin.Avalonia` can cast the message UI to `IAvaloniaPluginUserInterface` to obtain the real owner for a plug-in-owned window. Return `PluginResult.Completed()` on success or `PluginResult.Failed(error)` on a handled failure.

| `PluginMenuCommand` field | Meaning |
|---|---|
| `Id` | Non-empty global command ID |
| `Location` | One of the six menu locations |
| `Order` | Numeric ordering key |
| `Label` | Displayed command text |
| `Handler` | Asynchronous `PluginMenuHandler` |

## Map item context-menu commands

`RegisterMapContextMenuCommand(PluginMapContextMenuCommand)` adds a plug-in command after the built-in commands in the context menu for an actual map item. It is never offered when the user right-clicks blank space in the map list. Command IDs are non-empty and globally unique across ordinary menu and map context-menu commands. `Order` sorts the plug-in commands, and `Label` is the already-localised displayed text.

| `PluginMapContextMenuCommand` field | Meaning |
|---|---|
| `Id` | Non-empty global command ID |
| `Order` | Numeric ordering key |
| `Label` | Displayed command text |
| `Handler` | Asynchronous `PluginMapContextMenuHandler` |

The handler receives `PluginMapContextMenuContext`. `MapKey` is the right-clicked map. The remaining fields provide the project path, the editor language, the plug-in directories, the message UI, text-hint invalidation, the secret store, cancellation and `MapEditorHost`. The handler returns `PluginResult` in the same way as an ordinary menu command.

`IMapEditorHost` is a narrow contract boundary. A plug-in does not receive `GameDataService`, editor view models, `MapPanel`, host controls or mutable JSON.

| `IMapEditorHost` member | Meaning |
|---|---|
| `ProjectPath` | Open project root |
| `CellSize` | Read-only source cell size from the compiled engine declaration; independent of preview zoom |
| `SuggestedMapKey` | Map that opened the plug-in, when available |
| `ListMaps()` | Ordered map summaries containing key and display name |
| `ReadMap(mapKey)` | Immutable snapshot of the current in-memory map |
| `ReadTileset(tilesetKey)` | Immutable tileset snapshot |
| `ResolveAssetFile(assetPath)` | Resolve a logical path at final editor file I/O; empty if unavailable |
| `ReplaceLayerAndSaveAsync(request, cancellationToken)` | Revision-checked layer replacement and direct single-map save |

`PluginMapSnapshot` contains identity, dimensions, an opaque `Revision` and ordered layers with rectangular `Tiles` and `AutoTiles`. Tileset and actor `AssetPath` values remain exact-case `/Game/Assets/...` paths. Call `ResolveAssetFile` only at final native file I/O, never for snapshots or intermediate caches. Tileset snapshots also contain tile dimensions, count and passability. Copy revisions unchanged into write requests.

`PluginMapLayerWriteRequest` identifies the map and layer, echoes `BaseRevision` and `ExpectedTilesetKey`, and supplies both matrices with exactly the snapshot's `Height × Width` shape. `PluginMapWriteResult` distinguishes success, a revision or tileset conflict, and a failure with an error. It also returns the current revision. Validation and write errors do not change editor memory, the Undo state or the UI.

On success, the host replaces only that layer in the current in-memory map and atomically saves only `Data/Maps/<mapKey>.json`. It records one Undo step in that map's history, advances the saved revision and refreshes the target map and layer. Existing unsaved edits already present in that same map are included in this direct save. Other maps and project data are not saved, and their Dirty state is not cleared. Undo restores the pre-write in-memory state and marks the map as needing a save. Undo does not save automatically.

Writes are refused while the target has an unsaved related path change. Complete a global Save first.

## Text hints

`RegisterTextHintProvider(ITextHintProvider)` registers synchronous text resolution. `TextHintContext` contains the project path, the editor language and the current text. Providers run in plug-in order, and the first non-empty result wins. Exceptions are recorded as plug-in diagnostics.

## Before Export, Before Run and Before Pack

`RegisterBeforeExportHook(IProjectExportHook)` registers an export step. `IProjectExportHook` extends `IProjectOperationHook` with `ProjectExportFiles GetFiles(string projectPath)`. The returned record contains `IReadOnlyList<string> InputPaths` and `IReadOnlyList<string> OutputPaths`: concrete project-relative file paths, with no repeated paths or overlap between inputs and outputs. Declare missing input files as well so the editor can detect their later creation. `GetFiles` describes the current inputs and generated outputs without modifying them; `ExecuteAsync` performs the export.

Export saves and validates the project, executes Export hooks sequentially, generates UI files and records success. The editor fingerprints the declared files and export plug-in identity to check whether another export is required. Export hooks run for the Export button, confirmed **Export and Play**, and every editor Pack. A before-Run hook that changes export inputs makes Play require another Export before launch. See [Construct, Export and Play](<../02.Editor User Guide/08.Run Debug and Package.md#construct-export-and-play>).

`RegisterBeforeRunHook` and `RegisterBeforePackHook` accept `IProjectOperationHook`. These hooks run sequentially before their requested operation; editor Pack runs its complete Export before the before-Pack hooks. All hooks receive the project path, language, operation kind, output writer, text-hint invalidation and cancellation. A failed result or exception stops the remaining hooks and blocks the operation. Honour cancellation and write progress through `IPluginOutput`.

| Operation context field | Meaning |
|---|---|
| `ProjectPath` | Open project root |
| `EditorLanguage` | Current editor language key |
| `Operation` | `ProjectOperationKind.Export`, `Run` or `Pack` |
| `Packaging` | Non-null only for a before-Pack hook; null for Export and before-Run |
| `Output` | Append-only operation output |
| `TextHints` | Request text-hint refresh |
| `CancellationToken` | Cancellation for the current operation |

When `Packaging` is available, it exposes only the packaging decisions below:

| `IProjectPackaging` member | Meaning |
|---|---|
| `UseLuac` | Whether Pack is compiling supported Lua source |
| `UseLdPak` | Whether Pack writes the complete `Assets`, `Data` and pruned `Scripts` trees as root `Assets.ldpak`, `Data.ldpak` and `Scripts.ldpak` |
| `CompileLuaDirectory(relativePath)` | Include a project-relative Lua directory in the Pack compilation set |
| `ExcludeFile(relativePath)` | Omit a project-relative file from the package |

Official Locale Tools calls `ExcludeFile("Data/Locale/Locale.xlsx")` during Pack, so the authoring workbook is not distributed. Its Export hook writes language files separately; `Packaging` is null during Export and Run.

## Blueprint assistants

A Blueprint assistant registers an ordinary `PluginMenuCommand` and owns its UI, settings and conversation history. The host contributes no assistant window and no controls. `IAvaloniaPluginUserInterface` only supplies an optional owner for a plug-in-owned window. In a project window, the optional `PluginMenuContext.BlueprintAssistantHost` exposes the project path, the suggested current Blueprint, available Blueprint keys and `CreateSession`.

An `IBlueprintAssistantSession` fixes one existing Blueprint and exposes its base revision plus an `IBlueprintAssistantWorkspace`. The workspace can list and read Blueprints, query the API catalogue, search or read allowlisted project source, validate candidates and create proposals. It cannot apply changes or reach arbitrary editor services. The plug-in UI retains the session and explicitly calls its apply or discard methods after user approval. Apply rechecks the base revision and the candidate validity, records one editor Undo snapshot, marks project data dirty and refreshes an open Blueprint editor without saving to disk.

Use `PluginMenuContext.SecretStore` for API keys. It is scoped by plug-in ID and uses the operating-system credential store. It does not fall back to plaintext files.

## Resource cleanup

`PluginMenuContext.ResourceCleanupHost` is available in a project window and supplies `IResourceCleanupHost`. The plug-in owns the scan window, the fixed native-resource list and the final user confirmation; the host owns analysis, report validation, project keep-list storage and system recycling.

| Member | Meaning |
|---|---|
| `ProjectPath` | Open project root |
| `ReadKeepPathsAsync` / `SaveKeepPathsAsync` | Read or replace project additions in `EditorCache/ResourceCleanupKeep.list`; empty additions remove the file |
| `ScanAsync(nativeKeepPaths, userKeepPaths, progress, cancellationToken)` | Analyse static references and return an immutable report with candidate paths, categories, sizes and issues |
| `TrashAsync(reportId, progress, cancellationToken)` | Revalidate and recycle all candidates in that report, returning moved paths, remaining paths and any error |

`ResourceCleanupProgress` describes the stage, completed and total counts, and current path. Reports with scan issues cannot be recycled. Changed project inputs invalidate the report. The host never replaces an unavailable Recycle Bin or Trash operation with permanent deletion. See [Official Resource Cleanup](<10.Official Resource Cleanup.md>) for scan boundaries and the review workflow.

## Unsupported extension points

There are no public hooks for host-docked panels, toolbars, arbitrary context menus, data types or editor events. The map-item command described above is the only context-menu extension point. A plug-in can carry and open its own Avalonia window from a command, but it cannot inject arbitrary controls into editor-owned views.

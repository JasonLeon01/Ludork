# Hook Reference

Registration occurs only inside `IEditorPlugin.Register`. The API exposes five registration methods.

## Menu commands

`RegisterMenuCommand(PluginMenuCommand)` inserts a command into `File`, `Edit`, `Game`, `Database`, `Help` or `Plugins`. IDs must be non-empty and globally unique. `Order` sorts commands within a location.

The handler receives optional project path, editor language, read-only plug-in directory, writable plug-in data directory, message UI, text-hint invalidation, a plug-in-scoped secret store, an optional Blueprint assistant host bridge and cancellation. An Avalonia source plug-in that references `Ludork.Plugin.Avalonia` can cast the message UI to `IAvaloniaPluginUserInterface` to obtain the real owner for a plug-in-owned window. Return `PluginResult.Completed()` on success or `PluginResult.Failed(error)` on a handled failure.

| `PluginMenuCommand` field | Meaning |
|---|---|
| `Id` | Non-empty global command ID |
| `Location` | One of the six menu locations |
| `Order` | Numeric ordering key |
| `Label` | Displayed command text |
| `Handler` | Asynchronous `PluginMenuHandler` |

## Map item context-menu commands

`RegisterMapContextMenuCommand(PluginMapContextMenuCommand)` adds a plug-in command after the built-in commands in the context menu for an actual map item. It is never offered when the user right-clicks blank space in the map list. Command IDs are non-empty and globally unique across ordinary menu and map context-menu commands. `Order` sorts the plug-in commands, and `Label` is the already-localised displayed text.

| `PluginMapContextMenuCommand` field | Meaning |
|---|---|
| `Id` | Non-empty global command ID |
| `Order` | Numeric ordering key |
| `Label` | Displayed command text |
| `Handler` | Asynchronous `PluginMapContextMenuHandler` |

The handler receives `PluginMapContextMenuContext`. `MapKey` is the right-clicked map; the remaining fields provide the project path, editor language, plug-in directories, message UI, text-hint invalidation, secret store, cancellation and `MapEditorHost`. The handler returns `PluginResult` in the same way as an ordinary menu command.

`IMapEditorHost` is a narrow contract boundary. A plug-in does not receive `GameDataService`, editor view models, `MapPanel`, host controls or mutable JSON.

| `IMapEditorHost` member | Meaning |
|---|---|
| `ProjectPath` | Open project root |
| `SuggestedMapKey` | Map that opened the plug-in, when available |
| `ListMaps()` | Ordered map summaries containing key and display name |
| `ReadMap(mapKey)` | Immutable snapshot of the current in-memory map |
| `ReadTileset(tilesetKey)` | Immutable tileset snapshot |
| `ReplaceLayerAndSaveAsync(request, cancellationToken)` | Revision-checked layer replacement and direct single-map save |

`ListMaps()` returns `PluginMapSummary` values. A `PluginMapSnapshot` contains key, display name, dimensions, an opaque `Revision`, and `PluginMapLayerSnapshot` values in declaration order. Each layer contains its name, tileset key and rectangular `Tiles` and `AutoTiles` matrices. `PluginTilesetSnapshot` contains its key, image path, tile dimensions, tile count and tile-indexed passability values. Treat revisions as opaque values and only copy them into a later write request.

`PluginMapLayerWriteRequest` identifies the map and layer, echoes `BaseRevision` and `ExpectedTilesetKey`, and supplies both matrices with exactly the snapshot's `Height × Width` shape. `PluginMapWriteResult` distinguishes success, revision or tileset conflict, and failure with an error, and returns the current revision. Validation or write errors do not change editor memory, Undo state or the UI.

On success, the host replaces only that layer in the current in-memory map, atomically saves only `Data/Maps/<mapKey>.json`, records one Undo snapshot, advances the saved revision and refreshes the target map and layer. Existing unsaved edits already in that same map are included in this direct save; other maps and project data are neither saved nor have their Dirty state cleared. Undo restores the pre-write in-memory state and marks the map as needing a save; it does not save automatically.

## Text hints

`RegisterTextHintProvider(ITextHintProvider)` registers synchronous text resolution. `TextHintContext` contains project path, editor language and current text. Providers run in plug-in order; the first non-empty result wins. Exceptions are recorded as plug-in diagnostics.

## Before Run and Before Pack

`RegisterBeforeRunHook` and `RegisterBeforePackHook` accept `IProjectOperationHook`. Hooks run sequentially before the requested operation. The context supplies project path, language, operation kind, output writer, text-hint invalidation and cancellation.

A failed result or exception stops the remaining hooks and blocks Run or Pack. Honour cancellation and write progress through `IPluginOutput`.

| Operation context field | Meaning |
|---|---|
| `ProjectPath` | Open project root |
| `EditorLanguage` | Current editor language key |
| `Operation` | `Run` or `Pack` |
| `Packaging` | Non-null only for a before-Pack hook; null for before-Run |
| `Output` | Append-only operation output |
| `TextHints` | Request text-hint refresh |
| `CancellationToken` | Cancellation for the current operation |

When `Packaging` is available, it exposes only the packaging decisions below:

| `IProjectPackaging` member | Meaning |
|---|---|
| `UseLuac` | Whether Pack is compiling supported Lua source |
| `CompileLuaDirectory(relativePath)` | Include a project-relative Lua directory in the Pack compilation set |
| `ExcludeFile(relativePath)` | Omit a project-relative file from the package |

Official Locale Tools calls `ExcludeFile("Data/Locale/Locale.xlsx")` during Pack so the authoring workbook is not distributed. It does not call this method during Run because `Packaging` is null.

## Blueprint assistants

A Blueprint assistant registers an ordinary `PluginMenuCommand` and owns its UI, settings and conversation history. The host contributes no assistant window or controls; `IAvaloniaPluginUserInterface` only supplies an optional owner for a plug-in-owned window. In a project window, the optional `PluginMenuContext.BlueprintAssistantHost` exposes the project path, suggested current Blueprint, available Blueprint keys and `CreateSession`.

An `IBlueprintAssistantSession` fixes one existing Blueprint and exposes its base revision plus an `IBlueprintAssistantWorkspace`. The workspace can list and read Blueprints, query the API catalogue, search or read allowlisted project source, validate candidates and create proposals. It cannot apply changes or reach arbitrary editor services. The plug-in UI retains the session and explicitly calls its apply or discard methods after user approval. Apply rechecks the base revision and candidate validity, records one editor Undo snapshot, marks project data dirty and refreshes an open Blueprint editor without saving to disk.

Use `PluginMenuContext.SecretStore` for API keys. It is scoped by plug-in ID and uses the operating-system credential store; it does not fall back to plaintext files.

## Unsupported extension points

There are no public hooks for host-docked panels, toolbars, arbitrary context menus, data types or editor events. The map-item command described above is the only context-menu extension point. A plug-in can carry and open its own Avalonia window from a command, but it cannot inject arbitrary controls into editor-owned views.

# Manifest and Minimal Plug-in

## Goal

Create a C# 13 source plug-in that adds one Help menu command and can be imported by Ludork 1.0.0.

## Prerequisites

- .NET 9 SDK for IDE diagnostics and local compilation.
- Access to `Ludork.Plugin.Abstractions` from this repository or the editor development kit.
- A unique plug-in ID and CLR namespace.

## Source directory

```text
MyPlugin/
├── plugin.json
├── MyPlugin.cs
└── MyPlugin.csproj
```

There is one source-directory plug-in format. The directory must contain `plugin.json` and at least one participating `.cs` file. Sources are compiled in relative-path order with C# 13, nullable enabled, unsafe allowed and release optimisation. Import compiles and validates a staging copy; editor startup compiles and loads the installed registered source again.

Sources below `bin`, `obj`, `.git` and `.vs` are ignored. A `.csproj` may remain for IDE use, but the host does not execute project files, restore NuGet packages or load a prebuilt entry assembly. Plug-in source can reference the .NET runtime, `Ludork.Plugin.Abstractions`, `Ludork.Plugin.Avalonia` and the editor's shared Avalonia assemblies.

## Steps

### 1. Write `plugin.json`

```json
{
  "schemaVersion": 1,
  "id": "Example.MyPlugin",
  "name": "My Plugin",
  "version": "1.0.0",
  "minimumEditorVersion": "1.0.0",
  "entryType": "Example.MyPlugin.Plugin"
}
```

| Field | Contract |
|---|---|
| `schemaVersion` | Manifest schema; must equal `1` |
| `id` | Identifier containing only letters, digits, dots, hyphens or underscores |
| `name` | Non-empty display name |
| `version` | Version accepted by .NET `Version` parsing |
| `minimumEditorVersion` | Minimum editor version parsed as a .NET `Version` |
| `entryType` | Case-sensitive namespace-qualified CLR type name |

JSON property names are case-sensitive.

### 2. Add the entry type

```csharp
using Ludork.Plugin.Abstractions;
using System;
using System.Threading.Tasks;

namespace Example.MyPlugin;

public sealed class Plugin : IEditorPlugin
{
    public void Register(IPluginRegistrar registrar)
    {
        ArgumentNullException.ThrowIfNull(registrar);
        PluginMenuCommand command = new(
            "Example.MyPlugin.About",
            PluginMenuLocation.Help,
            500,
            "My Plug-in",
            ShowMessageAsync);
        registrar.RegisterMenuCommand(command);
    }

    private static async Task<PluginResult> ShowMessageAsync(
        PluginMenuContext context)
    {
        await context.UserInterface.ShowMessageAsync(
            "My Plug-in",
            "The plug-in is loaded.",
            PluginMessageKind.Information,
            context.CancellationToken);
        return PluginResult.Completed();
    }
}
```

The entry type must be public, non-abstract, implement `IEditorPlugin` and have a public parameterless constructor. Command IDs must be globally unique.

### 3. Add an optional IDE project

```xml
<Project Sdk="Microsoft.NET.Sdk">
  <PropertyGroup>
    <TargetFramework>net9.0</TargetFramework>
    <LangVersion>13.0</LangVersion>
    <Nullable>enable</Nullable>
    <ImplicitUsings>disable</ImplicitUsings>
  </PropertyGroup>
  <ItemGroup>
    <ProjectReference Include="..\..\Ludork.Plugin.Abstractions\Ludork.Plugin.Abstractions.csproj">
      <Private>false</Private>
    </ProjectReference>
  </ItemGroup>
</Project>
```

Adjust the reference for your source layout. The project is for IDE analysis only; every source needed at runtime must remain in the imported directory and use host-provided dependencies.

### 4. Import and restart

Choose **Plugins → Import Plugin**, select `MyPlugin`, accept the full-trust confirmation, then restart Ludork.

## Expected result

**Help → My Plug-in** appears after restart and opens the message supplied by the plug-in.

## Verification

- **Manage Plugins** reports **Loaded** and version `1.0.0`.
- Selecting the command returns a completed result without a diagnostic.
- Re-importing the same ID or selecting a source directory with a manifest error is rejected.

## Limitations

Host-shared DLLs, symbolic links, reparse points, plug-in-local `.data`, F#/VB projects and loose XAML/Avalonia source are rejected. The source compiler does not restore plug-in-specific packages and plug-ins cannot reference editor implementation assemblies.

`IPluginRegistrar.PluginDirectory` is read-only program content. Settings, history and caches belong in `PluginDataDirectory`. For a plug-in-owned Avalonia window, obtain the owner through `IAvaloniaPluginUserInterface`; do not infer it from `Application.Current`.

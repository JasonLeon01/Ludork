# Game Localisation Workflow

Game localisation is owned by Official Locale Tools. It is deliberately separate from General Data and save data.

## Goal

Author one workbook, export deterministic Lua catalogues before Run and Pack, and resolve the selected language in gameplay.

## Prerequisites

- A project with `Scripts/Source/Locale/Core.lua` and the normal locale initialisation in `Scripts/Entry.lua`.
- A spreadsheet application capable of preserving cached formula values when formulas are used.

## Workbook

Create `Data/Locale/Locale.xlsx`. Every included worksheet must use row 1 as a header. Column A must be `ID` (case-insensitive); columns B onwards are language names such as `en_GB` and `zh_CN`. Blank language headers are ignored, and at least one language is required.

Rows with a blank ID are ignored. IDs are trimmed and are case-sensitive. Multiple worksheets are merged. Duplicate IDs are reported with first and duplicate cell locations; a later present cell value overwrites the earlier value for the same language.

Formula cells use their cached value when present. Without a cached value, the formula text without the leading equals sign is exported. A literal `=` or `==` may be entered as `'=` or `'==`.

## Export

Before Run and Pack, the plug-in writes one UTF-8 Lua table per language:

```lua
return {
    ["TITLE_START"] = "Start",
    ["TITLE_EXIT"] = "Exit",
}
```

Output files are written through temporary files and replace `Scripts/Source/Locale/<language>.lua`. Language names may not be blank, rooted, contain separators or contain invalid filename characters. A missing workbook is a successful skipped export; malformed workbooks fail the operation.

## Editor hints

A field whose complete trimmed text is `{TITLE_START}` can receive a hint. The provider reads the file matching `EditorLanguage` from `Scripts/Source/Locale` and falls back to `en_GB.lua`. Spaces or nested braces invalidate the token.

## Runtime

The built-in `Scripts/Source/Locale/Core.lua` requires every language module in the same directory and exposes the locale functions. `Scripts/Entry.lua` requires the Core and selects a language; each consumer binds its own local `LOC` directly from `ApplyStringLocaleFormat`. If the directory contains no language module, or if a key is missing, `LOC("KEY")` returns the original key; an unavailable selected language falls back to `en_GB` where possible.

```lua
local LOC = require("Source.Locale.Core").ApplyStringLocaleFormat

local buttonText = LOC("TITLE_START")
local message = LOC(
    "{ITEM_NEW}: {ITEM_NAME}"
)
```

`ApplyStringLocaleFormat` resolves a bare locale key or replaces every `{ID}` embedded in a string from the active catalogue. Unknown keys are preserved; doubled `{{` and `}}` produce literal braces. `Locale.setLanguage` changes the active catalogue and synchronously publishes `LocaleChanged`. The default Config window saves the selected language, and subscribed UI owners resolve their retained locale sources again in place without resetting selection, focus or active dialogue state. General Data string fields remain unchanged when applied to runtime objects; a display owner calls `LOC` when it renders a brace-wrapped value.

`Source.Configs.Main` writes default configuration only when the target `Main.ini` does not exist. A new file defaults to `en_GB` and uses the platform language only when it exactly matches the supported list. A HarmonyOS tablet with free-window mode enabled when the file is created writes the Scale default `0`; other hosts write `1`. Existing files are not rewritten to fill missing keys or overwrite the selected language during startup.

When Lua compilation is enabled for packaging, the packer processes the complete `Scripts` tree recursively, so Core and generated language files are converted to luac together. Official Locale Tools does not inspect the packaging option or compile the locale directory separately.

## Steps

1. Install the editor release; on macOS also run **Install Official Plugins** from the DMG. Restart and verify that Official Locale Tools is **Loaded**.
2. Add an ID and translations to the Sample workbook.
3. Run the project and confirm the export message.
4. Verify the generated Lua tables.
5. Use `LOC("ID")` or store `{ID}` where format resolution is expected.
6. Change the game language and verify that visible UI updates in place and hidden UI uses the new language when next opened.
7. Pack and verify the same generated catalogues are present.

## Limitations

The workbook is a project authoring source, not a runtime database or save format. Plug-in menu localisation is independent from these game catalogues.

# Official Blueprint AI

## Goal

Use the official source plug-in distributed with Ludork, configure a provider securely and apply a validated one-Blueprint proposal through the editor's review boundary.

The plug-in ID is `Ludork.OfficialBlueprintAI`, fixed at `Plugins/OfficialBlueprintAI` in the repository. After restart, the editor compiles the installed source again and exposes the plug-in through **Game → Blueprint AI**.

## Workflow

1. Install the plug-in for your environment; see Locations and ownership below.
2. Open a project and select **Game → Blueprint AI**.
3. Configure the provider, model, endpoint and secret from **Settings**.
4. Create a conversation for one existing Blueprint and review the staged proposal and generated diff.
5. Select **Apply** only after validation succeeds, then use the normal project Save command when the change is ready for disk.

## Locations and ownership

| Environment | Program or source location | Writable data location |
|---|---|---|
| Repository checkout | `./Plugins/OfficialBlueprintAI` source; imported directories are copied directly below `./Plugins` using the selected directory name | `./Plugins/.data/Ludork.OfficialBlueprintAI` |
| Published Windows editor | `<editor-directory>/Plugins/OfficialBlueprintAI` | `<editor-directory>/Plugins/.data/Ludork.OfficialBlueprintAI` |
| Published macOS editor | `~/Ludork/Plugins/OfficialBlueprintAI` installed from the DMG's hidden payload | `~/Ludork/Plugins/.data/Ludork.OfficialBlueprintAI` |

The macOS DMG installer transactionally replaces the existing `~/Ludork/Plugins` and `~/Ludork/plugins.json` as a complete set. An ordinary failure rolls back to the previous set, but success deletes existing third-party plug-in source, registrations and all data below `Plugins/.data`. There is no merge or retained backup; preserve required files before confirming.

The plug-in owns the menu command, Avalonia windows, settings UI, localisation, provider clients and conversation history. The editor does not contain a Blueprint AI window. It only supplies an optional `IAvaloniaPluginUserInterface` owner for the plug-in window and, while a project is open, a restricted `IBlueprintAssistantHost` bridge. That bridge creates a session bound to one Blueprint and exposes the read, proposal, validation, Apply and Discard capabilities required by the workflow.

Removing the executable directory does not remove `Plugins/.data/Ludork.OfficialBlueprintAI`. Deleting settings or history is a separate explicit operation.

## Scope and permissions

Each conversation is bound to one project and one existing Blueprint. The assistant can inspect other Blueprints, Lua metadata and allow-listed Lua/C/C++ source files to understand available APIs. It cannot create, rename or delete Blueprints, modify more than one Blueprint, write source code, run a shell or start processes.

The model can only stage a Blueprint proposal. The editor validates the candidate and shows a generated diff. Nothing changes until the user selects **Apply**. Apply re-reads the editor working copy and compares its revision with the proposal base. A successful Apply creates one normal Undo step, leaves the project dirty and refreshes every open editor for that Blueprint. The Blueprint is not written to disk until the normal project Save operation.

Plug-ins are trusted in-process code and are not an operating-system sandbox. The official assistant's model-facing capability surface and the editor's session/Apply boundary enforce the restrictions above.

## Provider settings and credentials

Open **Settings** in the Blueprint AI window to choose a provider, model and endpoint. OpenAI uses the Responses API. DeepSeek, Google OpenAI-compatible and Custom profiles use an OpenAI-compatible Chat endpoint. Model and endpoint fields remain editable so a plug-in update is not required for every model release.

An endpoint must be an absolute HTTPS URL. Plain HTTP is accepted only for a loopback address used during local development. Credentials, query strings and fragments are not accepted in endpoint URLs.

API keys are not written to `settings.json`. On Windows they are stored in Credential Manager and on macOS in Keychain. Other platforms read a plug-in-scoped environment variable and do not persist the secret. The settings window displays a stored key as its first three characters, a fixed mask, and its final three characters; short keys are fully hidden. The credential changes only when a new value is entered or removal is explicitly selected. Provider availability is external to Ludork.

## Local conversations and provider state

The local index and append-only JSONL records under the plug-in data directory are the authoritative conversation history. They contain messages, model snapshots, compact tool activity and proposal decisions. They never contain the API key or complete source-file reads.

OpenAI Responses requests use `store:false`; the plug-in does not rely on provider-side conversation storage. For a long conversation, only a rolling summary and recent messages are placed in the next provider request. This request-context compaction does not delete or replace the complete local history.

An unfinished request is recorded as interrupted. Its completed local records remain available after restart, but the in-flight request is not resumed automatically.

## Safe code inspection

Project search and file reading only accept project-relative paths under the configured runtime/API source roots and supported text extensions. Build outputs, logs, VCS data, INI files, plug-in data, credentials and paths outside the project are rejected. File contents are treated as data, not as instructions that can expand assistant permissions.

## Troubleshooting

- **Blueprint AI is missing from Game:** confirm that the preinstalled Windows plug-in or the macOS DMG installer completed, restart the editor, then inspect **Plugins → Manage Plugins** for pending-restart, manifest, dependency or initialisation diagnostics. An uninstalled plug-in intentionally contributes no menu item.
- **No project or Blueprint is available:** open a project first. The host bridge is unavailable outside a project window. A project also needs at least one existing Blueprint. Opening the plug-in does not choose a target; the selector appears only after selecting **New**.
- **The target was renamed or deleted:** the old conversation remains readable, but its target cannot be switched silently. Create a new conversation for an existing Blueprint.
- **The API key is missing or the server returns 401:** replace the key in Settings and check that it belongs to the selected provider/profile. Also verify the endpoint and any OpenAI organisation/project values. The UI shows only a masked value, never the complete stored key.
- **Connection or endpoint errors:** use an absolute HTTPS base endpoint without embedded credentials, a query or a fragment. Check DNS, proxy, firewall and TLS settings. Plain HTTP is intentionally limited to loopback development endpoints.
- **Apply reports a revision conflict:** the Blueprint changed after the proposal was based. The editor refuses to overwrite it. Discard the proposal, review the current Blueprint and start a new conversation/request.
- **History shows interrupted:** the editor, window or request was stopped before completion. The local history remains authoritative; send a new request when ready rather than expecting the previous network stream to resume.

## Verification

Confirm the plug-in loads after restart, secrets remain absent from `settings.json` and history, a proposal cannot apply after a revision conflict, Discard leaves the project unchanged, and a successful Apply remains unsaved until the normal Save command.

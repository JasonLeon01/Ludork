# Project Settings and Asset Layout

## Scope

This page defines the project-root settings and directory ownership that editor users must preserve when moving, reviewing or packaging project content.

```text
MyGame/
├── Main.proj
├── Main.ini
├── Assets/
├── Data/
│   ├── Animations/
│   ├── AutoTiles/
│   ├── Blueprints/
│   ├── CommonFunctions/
│   ├── Configs/
│   ├── Curves/
│   ├── General/
│   ├── Locale/
│   ├── Maps/
│   └── Tilesets/
├── Scripts/
│   ├── Entry.lua
│   ├── Mixins/
│   ├── Source/
│   │   ├── Configs/
│   │   │   ├── GameVariables.lua
│   │   │   └── GameVariables_meta.lua
│   │   └── Locale/
│   └── stub/
│       ├── Mixins/**/*.d.lua
│       └── Source/**/*.d.lua
└── Core/
```

## Main.proj

`Main.proj` describes editor and packaging capabilities. The Sample enables the C++ runtime and FFmpeg and stores the preferred run-window mode:

```json
{
  "Cpp": true,
  "ffmpeg": true,
  "IndividualWindow": true,
  "lastFileExplorerPath": "Data/Blueprints/Actors"
}
```

Treat unknown keys as editor-owned state and preserve them. Select the FFmpeg template consistently with the `ffmpeg` setting.

## Main.ini

`Main.ini` contains game-facing settings such as `script`, `language`, scale, frame rate, vertical synchronisation and audio switches/volumes. Display scale defaults to `1.0`; desktop Config offers borderless fullscreen (`0`) and filters its positive presets to those that fit the display work area, while mobile omits scale. Use Game Config to edit supported values. In editor mode the project copy is used; packaged games keep mutable settings in their platform user-data location.

## Assets

Asset paths are relative to `Assets`. Keep content in the conventional folders so selectors and metadata hints can filter correctly: `Tilesets`, `Autotiles`, `Characters`, `Animations`, `Icons`, `Fonts`, `Musics`, `Sounds`, `Voices`, `Shaders`, `Fogs`, `Transitions`, `System` and `Videos`.

Moving an asset does not automatically repair every stored reference. Open its reference tree before moving or deleting it, then update affected data manually.

## Data and Scripts

`Data` contains JSON authored by the editor; `Data/Locale/Locale.xlsx` is the localisation workbook managed by Official Locale Tools. `Scripts` contains runtime Lua, generated Core metadata and LuaLS declarations; generated language modules live under `Scripts/Source/Locale`. Ordinary `.lua` files own runtime logic, mirrored `stub/**/*.d.lua` files own public documentation and types, and `_meta.lua` files beside runtime scripts are editor pure-data declarations. Neither `_meta.lua` nor `.d.lua` is a gameplay module.

The Game Variable Manager owns `Scripts/Source/Configs/GameVariables.lua` and `GameVariables_meta.lua`. The first file is the runtime name-to-initial-value map; the second preserves declaration order, metadata types and optional remarks. Both begin with `-- AUTO-GENERATED by Ludork Game Variable Manager. DO NOT EDIT.` and must not be edited manually. Opening the manager creates the pair when needed, and each successful manager change regenerates both files together.

Handwritten declarations are versioned with their runtime module. Do not edit `Engine_meta.lua`, `GlobalCore_meta.lua`, `GlobalFunctions_meta.lua` or generated Core/LuaSF declarations by hand. Templates retain the declaration tree, while packaging removes `Scripts/stub` and rejects any misplaced `.d.lua`.

## Verification

- Open the project after every external move and resolve missing references before saving further changes.
- Confirm that `Main.proj` capabilities match the selected template.
- Edit a game variable and confirm that both generated files contain the same ordered names.
- Run and package once after changing `Main.ini`, asset locations or entry scripts.

## Limitations

The file explorer cannot guarantee that every string-based runtime reference is rewritten.

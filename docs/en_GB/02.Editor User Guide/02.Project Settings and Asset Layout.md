## Main.proj

`Main.proj` describes editor and packaging capabilities. The Sample enables the C++ runtime and FFmpeg and stores the preferred run-window mode:

```json
{
  "Cpp": true,
  "ffmpeg": true,
  "IndividualWindow": true,
  "lastFileExplorerPath": "Data/Blueprints/Actors"
}
```

Treat unknown keys as editor-owned state and preserve them. Select the FFmpeg template consistently with the `ffmpeg` setting.

## Main.ini

`Main.ini` contains game-facing settings such as `script`, Language, Scale, Frame Rate, Anti-Aliasing Level, Vertical Sync and audio switches/volumes (Sound, Voice, Music). Anti-aliasing defaults to SFML's own context default and applies on the next display initialisation. Scale defaults to `1.0`; desktop Config offers Fullscreen (`0`) and filters its positive presets to those that fit the display work area, while mobile omits Scale. Use Game Config to edit supported values. In editor mode the project copy is used; packaged games keep mutable settings in their platform user-data location.

## Assets

Asset paths are relative to `Assets`. Keep content in the conventional folders so selectors and metadata hints can filter correctly: `Tilesets`, `Autotiles`, `Characters`, `Animations`, `Icons`, `Fonts`, `Musics`, `Sounds`, `Voices`, `Shaders`, `Fogs`, `Transitions`, `System` and `Videos`.

Moving an asset does not automatically repair every stored reference. Open its reference tree before moving or deleting it, then update affected data manually.

## Data and Scripts

`Data` contains JSON authored by the editor; `Data/Locale/Locale.xlsx` is the localisation workbook managed by Official Locale Tools. `Scripts` contains runtime Lua, generated Core metadata and LuaLS declarations; generated language modules live under `Scripts/Source/Locale`. File-layer ownership (`.lua`, `stub/**/*.d.lua`, `_meta.lua`) is in [Lua Runtime and Modules](<../03.Lua and Blueprint Scripting/01.Lua Runtime and Modules.md>).

The Game Variable Manager owns `Scripts/Source/Configs/GameVariables.lua` and `GameVariables_meta.lua`. General Data Save owns `Scripts/Source/Configs/GeneralEnum.lua` and `Scripts/stub/Source/Configs/GeneralEnum.d.lua`. All four are generated; do not edit them by hand. Their regeneration is described in [General Data and Text Config](<05.General Data and Text Config.md>).

Do not edit `Engine_meta.lua`, `GlobalCore_meta.lua`, `GlobalFunctions_meta.lua` or generated Core/LuaSF declarations by hand. Packaging removes `Scripts/stub` and rejects any misplaced `.d.lua`.

## Verification

- Open the project after every external move and resolve missing references before saving further changes.
- Confirm that `Main.proj` capabilities match the selected template.
- Edit a game variable and one General Data member, then confirm that each generated file pair contains the same ordered names.
- Run and package once after changing `Main.ini`, asset locations or entry scripts.

## Limitations

The file explorer cannot guarantee that every string-based runtime reference is rewritten.

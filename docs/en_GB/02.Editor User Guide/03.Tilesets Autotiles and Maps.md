# Tilesets, Autotiles and Maps

## Goal

Create a map with verified tilesets, ordered layers, lights and placed Actor instances, then save and run it without invalid references.

## Prerequisites

- A saved project and source images beneath the intended `Assets` directories.
- Known tile dimensions and at least one Blueprint for any Actor to be placed.
- A backup before changing an established map's dimensions or tileset identity.

## Tilesets and autotiles

Open **Database → Tilesets** (F9) to define a tileset image and its tile properties. Autotile data describes animated or connected tiles assembled from an autotile source. Keep images beneath `Assets/Tilesets` or `Assets/Autotiles`; JSON definitions are stored beneath the corresponding `Data` directory.

Verify tile size and source regions before painting. Changing a tileset definition after maps have been authored can change the meaning of existing tile indices.

![Tile palette and layer list in the map editor](../../_images/editor/tile-layers.png)

*Use the tile palette together with the active layer; the selected layer receives every paint operation.*

## Map list

Use the map-list context menu to create, edit, copy, paste or delete a map. Map properties include dimensions, tileset, audio, fog and ambient-light settings. A map rename changes its data path but does not promise to rewrite every gameplay reference.

![Map properties window](../../_images/editor/map-properties.png)

*Review dimensions and the selected tileset before authoring layers.*

## Layers and painting

Tile mode supports layer creation, rename, reorder, copy, paste and deletion. A layer may have a shader. Select a tile or autotile in the palette, paint on the active layer, and use erase for removal. Zoom and pan do not alter map data.

## Lights and actors

Switch to Light mode to place and edit lights, including position, colour and radius. Switch to Actor mode to place a Blueprint instance, move it and edit its exposed attributes. The selected instance may override class defaults without changing the Blueprint itself.

![Light editing mode](../../_images/editor/light-mode.png)

*Light mode visualises the selected emitter and its radius over the map.*

![Actor editing mode](../../_images/editor/actor-mode.png)

*Actor mode edits a placed Blueprint instance without changing its class defaults.*

An Actor light uses `LightComponent.lightOffset` relative to the centre of the Actor's local bounds. The complete Actor transform is applied to the offset, so the emitter follows rotation and scale. For a wall-mounted torch, place the offset at the visible flame on the room side of the wall; the renderer does not move an emitter to a nearby passable cell.

`Material.lightBlock` is an opacity in the inclusive range `[0, 1]` for one `CellSize` of penetration. `0` is fully transmissive, `1` blocks direct light completely, and intermediate values compound by physical path length. For example, a value of `0.5` transmits approximately `0.707`, `0.5`, and `0.25` through half, one, and two cells respectively.

An emitting Actor is excluded only from the dynamic occluders of its own light. It still blocks every other light, while tiles and other Actors at the same position remain occluders. Do not combine a wall and its torch emitter into one Actor: use a wall occluder Actor and a separate torch Actor, otherwise excluding the emitter would also exclude the wall.

## Steps

1. Create and verify tilesets.
2. Create the map and set its dimensions.
3. Build visual layers from background to foreground.
4. Add lights.
5. Add Actor instances and configure per-instance values.
6. Save, run and inspect collisions, draw order and transitions.

Large changes to map dimensions, layer order or tileset identity should be tested immediately.

## Expected result

The saved map renders its layers in the intended order, uses valid tileset indices, applies light and occlusion settings, and instantiates Actors with the selected per-instance overrides.

## Verification

- Reopen the map and confirm dimensions, tileset and layer order.
- Inspect Tile, Light and Actor modes for the same saved selections and values.
- Run the map and test collision, transitions, light occlusion and Actor lifecycle.
- Use the reference tree before renaming or deleting a referenced asset.

## Limitations

Renaming a map or moving a tileset does not guarantee that string-based gameplay references are rewritten. A placed Actor can override declared fields but cannot change its Blueprint class definition.

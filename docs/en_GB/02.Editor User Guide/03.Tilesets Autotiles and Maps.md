# Tilesets, Autotiles and Maps

## Goal

Create a map with verified tilesets, ordered layers, lights and placed Actor instances, then save and run it without invalid references.

## Tilesets and autotiles

Open **Database → Tilesets** (`F6`) to define a tileset image and its tile properties. Autotile data describes animated or connected tiles assembled from an autotile source. Keep images under `Assets/Tilesets` or `Assets/Autotiles`, and store the JSON definitions under the corresponding `Data` directory.

The window separates ordinary definitions and autotiles into the **Tilesets Data** and **AutoTiles** tabs. Select a definition from the list and edit its name. Then use the browse button beside **File Name** to choose its source image from the corresponding asset directory.

The map palette labels tileset tabs with `name`, while the JSON file name is the internal key. Changing the display name leaves references unchanged. Renaming the key updates every affected map's `layerTileset`, including unopened maps, following the shared [save and Undo rules](<01.Start Page Workspace and Shortcuts.md#editing-and-saving>).

![Tilesets Data tab showing per-tile passability](../../_images/editor/tilesets-data.png)

*In Passable mode, a circle marks a passable tile and a cross marks a blocked tile.*

![AutoTiles tab showing whole-asset passability](../../_images/editor/auto-tile.png)

*Autotile properties apply to the complete source rather than to each displayed source cell.*

Verify tile size and source regions before painting. Changing a tileset definition after maps have been authored can change the meaning of existing tile indices. Test large changes to map dimensions, layer order or tileset identity immediately.

Map JSON requires a `layerOrder` string array, which is the authoritative draw and Actor-processing sequence. `layers` and `actors` remain dictionaries keyed by those names, and the editor keeps the array synchronised. Runtime loading rejects missing, duplicate or unlisted layers. It never infers order from JSON object keys.

An ordinary tileset provides the **Passable**, **Material** and **Dir4** modes. Left-click toggles one tile's passability, opens its material editor or toggles the direction nearest the clicked edge. Shift+left-drag copies the pressed source tile's property through every crossed cell. The current mode chooses the copied value: Passable copies the boolean, Material deep-copies the complete material, and Dir4 copies all four directions. Sparse pointer movement is joined without gaps, and one drag is one Undo step. Autotiles provide **Passable** and **Material** for the whole asset and do not support this batch brush.

![Tile palette and layer list in the map editor](../../_images/editor/tile-layers.png)

*Use the tile palette together with the active layer; the selected layer receives every paint operation.*

## Map list and composite worlds

The Map List contains ordinary maps and worlds. A world row displays the `worldName` from `_world.json`. Expanding the row shows direct children by their editable `mapName`, while `_world.json` stays hidden. **World Map Properties** edits the world display name, whereas **Rename World Map** changes the folder and the runtime paths. A child keeps the ordinary **Map Name** field, so its file remains usable as a standalone map. Selecting a world opens its composition panel, and the context menus create each asset type. Copying a child assigns fresh Actor map tags without placing the copy.

Drag an unplaced child onto the world canvas, and drag a placed child to move it. Delete, Backspace or the context menu of the placement removes it. Each placement edit is one Undo/Redo step, and it rejects overlap, bounds or layer-order violations.

Scroll or pan the canvas. Use Ctrl+wheel on Windows/Linux or Command+wheel/pinch on macOS to zoom. The read-only preview shows tiles, the first autotile frame and static Actor images at time zero. It does not animate Actors or render lights, fog, panorama or map-layer shaders.

Validation covers the manifest, the flat directory shape, direct JSON maps, placements, layer order and world-wide Actor-tag uniqueness. Non-JSON regular files are ignored. An invalidating resize is rejected rather than moving or cropping a placement. Before deleting a placed child file, remove its placement and save, because the manifest's reference otherwise blocks deletion.

A rename updates the recognised references listed in [Project Settings and Asset Layout](<02.Project Settings and Asset Layout.md>). The world manifest and its child maps have separate histories, and automatic reference, placement and layer-order corrections create Undo barriers. The file explorer preserves the `Data/Maps` hierarchy, so root maps, world folders and children cannot move between levels or worlds. Create and delete them through the Map List.

![Map properties window](../../_images/editor/map-properties.png)

*Review dimensions and the selected tileset before authoring layers.*

Map Properties also selects an optional **Panorama** image from `Assets/Panoramas`. The runtime Cover-scales that image to fill `GameMap.MapViewRect`, then crops any overflow using the Camera's position as a fraction of the map's scrollable range. The left edge of the map shows the left of the panorama, and the right edge shows the right. An axis that cannot scroll uses the centre of that overflow. Ambient light tints the image, and point lights do not. A blank path disables the panorama. A world manifest may set a global panorama that covers the world Camera, while a child's `panorama` applies only when that child is loaded as a standalone map.

## Layers and painting

Tile mode supports layer creation, rename, reorder, copy, paste and deletion. A layer may have a shader. Selecting a tileset tab changes the active layer's tileset immediately, and its existing tile indices are then interpreted against that tileset. Select a tile or autotile in the palette, paint on the active layer, and use erase for removal. Zoom and pan do not alter map data.

Each layer tab shows its name on the left and its visibility control on the right. Visibility is authored map data, so hidden layers are not rendered and are read-only.

The map uses one tile brush. Left-drag paints the selected tile or autotile continuously, Shift+left-drag paints a filled rectangle, and right-click samples the clicked cell. One brush stroke or rectangle is recorded as one map edit for Undo. Hidden layers reject every editing route and show read-only feedback.

Saving during a stroke starts a new Undo step for subsequent movement. Undo and Redo end the active stroke, and pressing again resumes painting.

## Lights and actors

Switch to Light mode to place and edit lights, including their position, colour and radius. Switch to Actor mode to place a Blueprint instance, move it and edit its exposed attributes. The selected instance may override class defaults without changing the Blueprint itself.

Ordinary maps and world previews draw an Actor whose resolved `visible` value is `false` at 25% opacity, including inherited defaults and instance overrides. Texture alpha and the 50% dimming of non-current layers on an ordinary map still multiply this opacity. Selection outlines and error markers stay clear, and the Actor remains selectable and movable. Hidden layers remain invisible, while placement ghosts and missing-texture placeholders retain their normal appearance. This behaviour is an editor preview aid, and invisible Actors remain hidden at runtime.

![Light editing mode](../../_images/editor/light-mode.png)

*Light mode visualises the selected emitter and its radius over the map.*

![Actor editing mode](../../_images/editor/actor-mode.png)

*Actor mode edits a placed Blueprint instance without changing its class defaults.*

An Actor light uses `LightComponent.lightOffset` relative to the centre of the Actor's local bounds. The complete Actor transform is applied to the offset, so the emitter follows rotation and scale. For a wall-mounted torch, place the offset at the visible flame on the room side of the wall, because the renderer does not move an emitter to a nearby passable cell.

`Material.lightBlock` is an opacity in the inclusive range `[0, 1]` for one `CellSize` of penetration. `0` is fully transmissive, `1` blocks direct light completely, and intermediate values compound by physical path length. For example, a value of `0.5` transmits approximately `0.707`, `0.5`, and `0.25` through half, one and two cells respectively.

An emitting Actor is excluded only from the dynamic occluders of its own light. It still blocks every other light, while tiles and other Actors at the same position remain occluders. Do not combine a wall and its torch emitter into one Actor. Use a wall occluder Actor and a separate torch Actor, because excluding the emitter also excludes the wall.

### Map tags in a world

Creating or pasting an Actor in a world child prefixes its default tag with the child file stem, and the editor enforces uniqueness across the world. Renaming a child or a world does not rewrite existing or custom tags. Copying a child rewrites the copied tags to `<new-child-stem>.<old-tag-body>` and updates their matching `BPClassVarChanged` keys.

## Map targets

The `startMap` file field and the Blueprint Transfer picker use the same map tree. Selecting a world stores `<WorldFolder>/_world.json`, and its position is a world-cell coordinate. Selecting a placed child stores `<WorldFolder>/<ChildFile>.json`, and its position is local to that child and is converted to world coordinates at runtime. Unplaced children remain visible in the tree but cannot be selected as runtime destinations.

## Limitations

Arbitrary strings, custom protocols and dynamically constructed paths are not rewritten. Moving a tileset likewise does not repair gameplay strings.

# Start Page, Workspace and Shortcuts

## Goal

Open a project, identify the primary workspace regions, use the current global shortcuts and locate diagnostics before editing project data.

## Safe editing

- Save before Run or Pack, and resolve validation errors at their source.
- Create, rename, copy and move data-aware assets through the editor so stable identifiers and tracked paths remain valid.
- Use the reference tree to inspect indexed references; map operations protect only recognised structured references, not arbitrary strings.
- Keep file resources below `Assets`, authored project data below `Data`, and runtime code below `Scripts`.
- Review the Console whenever an operation invokes plug-in hooks, native builds or the game process.

## Start page

The Start page lists up to three recently opened projects and provides **New Project** and **Open Project**. A validated `.proj` file moves to the top of the list when opened; unavailable entries are removed when the Start page loads. Opening `Main.proj` replaces the current project only after unsaved-work checks succeed.

## Main workspace

The main window contains the map list, map canvas, editing-mode inspector, Actor outliner, project file explorer and Console. The toolbar switches between Tile, Light and Actor modes and controls the game process.

The workspace window and the map list, Actor Library, inspector and lower area can be resized; the editor saves those sizes after resizing.

Animation Overview, Tilesets, General Data, Common Functions, Blueprint and UI Asset windows first show a Loading view and initialize at background UI priority. General Data pages, Tileset tabs and Animation content are constructed only when selected for the first time.

## Global shortcuts

The primary modifier is Ctrl on Windows and Command on macOS.

| Shortcut | Action |
|---|---|
| Ctrl/Command+N | New Project |
| Ctrl/Command+O | Open Project |
| Ctrl/Command+S | Save |
| Ctrl/Command+Z | Undo |
| Ctrl/Command+Y | Redo |
| Ctrl/Command+W | Exit or close the project window |
| Ctrl/Command+1 | Tile mode |
| Ctrl/Command+2 | Light mode |
| Ctrl/Command+3 | Actor mode |
| F1 | Ludork Documentation |
| F3 | Game Config |
| F4 | System Config |
| F5 | Animation Overview |
| F6 | Tilesets Data |
| F7 | Common Functions |
| F8 | Game Variables |
| F9 | General Data |

Some document windows add context-specific shortcuts. For example, F2 renames a selected Blueprint graph or Common Function where that window advertises the action.

Single-button hint and error dialogs close with Enter, Return, Space or Escape. In confirmation dialogs, Enter, Return and Space confirm the action, while Escape cancels it.

## Editing and saving

Changes remain in the editor model until saved. Undo and Redo cover supported data mutations. Closing or replacing a modified project prompts before discarding work. A normal save validates changed Blueprints; use forced saving only when deliberately retaining an unfinished graph.

Undo and Redo retain the latest 100 project-data steps. Continuous text or numeric editing in one focused field is merged into one step; moving to another control ends that step. Saving, Undo and Redo split the current focused edit so further input can be undone independently. Buttons, check boxes and selections remain discrete steps.

## File explorer and reference tree

The file explorer manages project files and creates Blueprint, Animation, Curve, Text Config and UI assets. The reference tree shows incoming and outgoing references. Map operations atomically update or guard recognised indexed references; arbitrary strings remain unmanaged.

The open menu at the upper right always provides the system file manager and lists VS Code or Cursor only when the corresponding application is installed. C++ Source projects additionally list an installed CLion, plus Visual Studio 2022 on Windows. Opening CLion or Visual Studio for the first time prompts before running the project-provided environment generator when the local `.idea` or `.vs` configuration is absent; cancelling leaves the project unchanged. Visual Studio opens the generated `Main.sln`.

## Console and performance monitor

The Console collects plug-in, build and runtime output. Input can be sent only while a compatible runtime connection is ready. **Edit → Development Tools → Performance Monitor** displays recent frame, logic and memory samples while the game is running.

### World-streaming samples

When profiling a composite world, the Performance Monitor includes an optional `worldStreaming` snapshot. Ordinary-map and unprofiled ticks do not include it.

| Field | Meaning |
|---|---|
| `queueDepth` | Child regions waiting in the streaming queue. |
| `reading` | Regions currently in `Reading`. |
| `prepared` | Loaded regions in `Prepared`. |
| `active` | Regions in `Active`. |
| `dormant` | Loaded regions in `Dormant`. |
| `cacheBytes` | Conservative estimate used by the non-Active region cache; it is not exact process, Lua, native or GPU memory. |
| `publishMilliseconds` | Time spent converting and publishing regions during the logic tick. |
| `visibleTileChunks` | Unique 32×32-cell TileLayer chunks submitted by visible child layers in the latest draw. |
| `activeActors` | Actors currently present in the world's Active update/render batches. |

## Limitations

Context-specific windows can assign additional shortcuts, but they do not change the global F3–F9 mapping.

# Blueprints and Actors

A Blueprint is a JSON class definition beneath `Data/Blueprints`. It selects a native or Lua parent, stores editable attributes and, in graph mode, contains event graphs. Actor instances placed on maps refer to these classes.

## Goal

Create a graph-mode Blueprint, set class defaults, add a valid event graph and place an instance without mixing graph and Script Mixin inheritance modes.

## Prerequisites

- Current metadata generated or loaded for every field and node to be used.

## Create a Blueprint

Use **Game → New Blueprint** (F3) or the file-explorer command. Choose a parent that ultimately inherits `BPBase`, then choose a path beneath `Data/Blueprints`. Parent defaults and supported events are resolved when the editor opens the class.

## Class and instance values

Class attributes provide defaults for all instances. A map Actor may override individual values. Components are declared by metadata and appear as structured fields. Hidden fields from `InvalidVars` are not ordinary editable properties.

## Actor Library and Inspector

The Actor Library lists every Actor Blueprint and can be filtered by text, top-level folder category and scope. **All** shows the complete catalog, **Favourites** shows starred entries, and **Recent** keeps the 20 most recently selected or placed entries. Favourites are stored under `editor.actorFavorites` in `Main.proj`, follow Blueprint moves and renames performed in the file explorer, and are removed when the Blueprint no longer exists. Right-click an entry to open or locate its Blueprint, change its favourite state, or remove a recent entry. Animated previews run only for rows currently visible in the library viewport.

For a selected map Actor, the Inspector shows its Blueprint reference with **Open** and **Locate** actions, grid position X/Y, tag and exposed class fields. Position and text edits merge into one undo step for a continuous focused edit. A reset button beside an overridden field removes that instance override; **Reset All** removes every class-field override for the instance and reveals inherited Blueprint defaults again. When the Actor's layer is hidden, the Inspector stays available for inspection and Blueprint navigation but its tag, position, reset actions and class fields are read-only.

## Graph mode

Each event owns a node list and links. Add nodes from the picker, connect execution pins and data pins with compatible types, and set literal defaults for unconnected input pins. Pure nodes have data pins only; execution nodes must be reachable from the event start.

New nodes, pasted nodes and duplicated selections use the current pointer position in the graph. The editor converts that visible position through the current pan and zoom when the action begins; if the pointer is outside the graph, it uses the viewport centre. A duplicated selection keeps its relative layout and internal links, with the selection's top-left bound placed at the target position.

The primary modifier is Ctrl on Windows and Command on macOS.

| Shortcut | Action |
|---|---|
| Ctrl/Command+N | Open the node picker at the pointer position |
| Ctrl/Command+A | Select all editable nodes in the current graph |
| Ctrl/Command+C | Copy the selected nodes and their internal links |
| Ctrl/Command+V | Paste at the pointer position |
| Ctrl/Command+D | Duplicate the selection at the pointer position |
| Arrow keys | Move selected editable nodes by one graph unit |
| Delete | Delete selected editable nodes |

Inherited and event-parameter nodes are virtual and are excluded from select-all, movement, duplication and deletion. Graph shortcuts do not replace keyboard input while a parameter editor or another input control has focus, and mutating shortcuts are disabled for read-only graphs.

Common Functions provide reusable graphs. They are preferable to copying identical node sequences into many Blueprints.

## Inheritance

A child Blueprint inherits fields and behaviour. Avoid changing a saved parent path casually: inherited fields, events and compatible component data may change. A Blueprint inheritance chain must use either graph mode or Script Mixin mode throughout; see [Script Mixins](<../03.Lua and Blueprint Scripting/03.Script Mixins/00.Overview.md>).

## Validation

Validation checks parent resolution, cycles, graph shape, event start nodes, node functions, links, pins and stored defaults. An empty optional event is valid; a malformed or out-of-range link is not. Save after correcting all reported errors, then run a representative map.

## Verification

- Reopen the Blueprint and confirm parent, fields, events and graph links.
- Run validation after every structural graph change.
- Place two instances and verify that changing one instance override does not alter the class or the other instance.
- Run the event path with Console visible.

## Limitations

Validation cannot repair references to renamed runtime members or prove that every reachable gameplay state is correct.

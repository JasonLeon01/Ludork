# Ludork Documentation

Ludork is a game-development environment for building map-driven 2D games with a visual editor, Blueprint graphs, Lua scripts and an extensible C++20 runtime. The editor provides one workflow for project configuration, maps, actors, data, animation, user interfaces, testing and packaging.

![The Ludork editor workspace with a Sample map open](../_images/overview/editor-workspace.png)

*The main workspace combines the map canvas, editing modes, project data and runtime tools.*

## Supported platforms

| Product or output | Minimum supported system | Notes |
|---|---|---|
| Ludork editor for Windows | Windows 10 or newer, x64 | Use the Windows release package. |
| Ludork editor for macOS | Apple Silicon macOS 13.3 or newer | Use the macOS arm64 release package. |
| Desktop game | Windows 10 or newer, x64; or Apple Silicon macOS 13.3 or newer | Package for the current host platform. |
| iOS game | iOS 15.0 or newer, arm64 | Packaging requires a C++ Source project on Apple Silicon macOS, full Xcode and Apple development signing. |
| HarmonyOS game | HarmonyOS 6.0.2 / API 22 or newer, arm64-v8a | Mobile uses OpenGL ES; 2in1 uses OpenGL by default and can select OpenGL ES. HAP packaging requires a C++ Source project on Apple Silicon macOS with DevEco Studio. |
| Android game | Android 7.0 / API 24 or newer, arm64-v8a | APK packaging requires a C++ Source project on Apple Silicon macOS with Android Studio, SDK Platform 36, Build Tools 36.0.0, NDK r27 or newer, and host CMake 3.28 or newer. Output is unsigned by default, with optional signing from an existing JKS or PKCS12 keystore. |

Other CMake platforms are not release-qualified. A Standalone project uses the prebuilt runtime for the editor's host platform; choose C++ Source when you must change native code or produce an iOS, HarmonyOS, or Android target.

## Documentation conventions

- Paths are relative to the project root unless a page states otherwise.
- Menu commands and field labels are written as they appear in the English editor.
- `Code`, file names and API identifiers are case-sensitive where the underlying platform is case-sensitive.
- A **Note** provides context; a **Warning** identifies a condition that can block, corrupt or expose project data.
- Task pages state a goal, prerequisites, procedure and expected result where those distinctions are useful.

Use **Help → Ludork Documentation** or F1 to open these pages inside the editor. Six role-based tabs organise the pages: Ludork Documentation is a standalone tab, while the others use top-level folder names without numeric prefixes. A tab with only one document hides the navigation tree and gives the page the full content width. Each tab remembers its last selection; search covers all tabs, local links switch tabs automatically, and the strip scrolls on narrow windows. Change the documentation language from the Help menu, then restart when prompted; HTTPS links open in the system browser.

## Product and content licences

Ludork's software licence, third-party notices and Sample asset terms are separate. Review all three before redistributing an editor package or a game made from Sample content. Installing a plug-in also executes trusted code with the editor process's permissions; inspect its source and origin before import.

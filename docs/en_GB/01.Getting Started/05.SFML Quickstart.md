# SFML Quickstart

SFML is the multimedia library behind the Ludork runtime. It supplies the graphics, audio, window and input layer, and Ludork projects use its value types for positions, sizes, colours and rectangles.

Ludork embeds SFML through LuaSF, which registers the global `sf` table. Every project script can use it without a `require`.

The repository vendors **SFML 3.1.0**. Online material for SFML 2 is still common and uses a different constructor style, so prefer the 3.1 pages above.

## What Ludork provides and what SFML provides

Ludork does not hide SFML; it builds on top of it. The two layers have different jobs.

| Layer | Responsibility |
|---|---|
| Ludork | Project data, maps, Actors, Blueprints, Scenes, the declarative UI asset system, resource managers and packaging. |
| SFML | Graphics, audio, windowing, input devices and the geometry and value types those subsystems exchange. |

Reach for `sf` when a value or a behaviour is genuinely graphical or numeric. Reach for `Engine`, `GlobalCore` and `GlobalFunctions` when it is about the project. `sf` contains no map, Actor, Blueprint or data concept.

Most drawing in a project goes through Engine controls and Scenes rather than a hand-built `sf.RenderWindow`, because the runtime owns the window, the frame loop and the UI tree. The SFML layer is where the underlying values and resources come from.

## The sf table

`sf` is a plain global table of classes, enums and helper functions. The full declaration is in `Scripts/stub/LuaSF.d.lua`, which the EmmyLua workspace indexes, so completion and hover work inside the editor.

| Vector and matrix | `sf.Vector2i`, `sf.Vector2u`, `sf.Vector2f`, `sf.Vector2b`, `sf.Vector3i`, `sf.Vector3u`, `sf.Vector3f`, `sf.Vector3b`, `sf.Vector4i`, `sf.Vector4f`, `sf.Vector4b`, `sf.Mat3`, `sf.Mat4`, and the GLSL aliases `sf.Vec2`, `sf.Vec3`, `sf.Vec4`, `sf.Ivec2`, `sf.Ivec3`, `sf.Ivec4`, `sf.Bvec2`, `sf.Bvec3`, `sf.Bvec4` |

| Audio | `sf.SoundBuffer`, `sf.Sound`, `sf.Music`, `sf.SoundStream`, `sf.SoundSource`, `sf.Listener`, `sf.SoundRecorder`, `sf.SoundChannel`, `sf.PlaybackDevice` |

Helpers sit directly on `sf`: `sf.seconds`, `sf.milliseconds` and `sf.microseconds` build an `sf.Time`, while `sf.degrees` and `sf.radians` build an `sf.Angle`. Named blend modes such as `sf.BlendAlpha` and `sf.BlendAdd` are also `sf` fields.

## Value types

Geometry values are native userdata, not Lua tables. Compare them with the Standard `list`, `tuple` and `dict` containers, which are a separate system and are not SFML values.

Construct them with `new`:

```lua
local cell = sf.Vector2i.new(4, 7)
local speed = sf.Vector2f.new(1.5, -2.5)
local limit = sf.Vector2u.new(640, 480)
local tint = sf.Color.new(255, 255, 255, 128)
local area = sf.IntRect.new(0, 0, 32, 32)
```

`x` and `y` are readable and writable fields, and `Vector3*` and `Vector4*` add `z` and `w`:

```lua
local position = sf.Vector2i.new(0, 0)
position.x = position.x + 1
position.y = 4

local amount = sf.Vector3f.new(1.0, 0.5, 0.0)
local offset = sf.Vector4f.new(0.0, 0.0, 0.5, 1.0)
```

Two-dimensional vectors support arithmetic operators, so movement and centring read naturally:

```lua
local start = sf.Vector2f.new(64.0, 64.0)
local step = sf.Vector2f.new(16.0, 0.0)

local moved = start + step * 2.0   -- Vector2f(96, 64)
local back = moved - step
local mirrored = -moved
local half = moved / 2.0

local isSame = moved == back + step -- true
```

Operators are `+`, `-`, unary `-`, `*` and `/` by a scalar number, and `==`. Only `==` is defined, so ordering comparisons such as `<` are not available on vectors. Multiplication between two vectors is a method rather than an operator. `lengthSquared`, `perpendicular`, `dot`, `cross`, `componentWiseMul`, `componentWiseDiv` and `unpack` exist on all three `Vector2` types, and `unpack` returns the components as separate values. The floating-point type adds `length`, `normalized`, `angle`, `angleTo`, `rotatedBy` and `projectedOnto`, which works in `sf.Angle` rather than degrees.

`sf.Vector2f.new` also accepts a length and an `sf.Angle`, which builds the vector from polar coordinates:

```lua
local forward = sf.Vector2f.new(1.0, sf.degrees(90)) -- Vector2f(0, 1)
```

### Colour, rectangles and time

`sf.Color` holds `r`, `g`, `b` and `a` in the range 0 to 255. The four-argument constructor takes red, green, blue and alpha, and shorter forms default the missing components:

```lua
local solid = sf.Color.new(32, 96, 160)
local veil = sf.Color.new(0, 0, 0, 160)
```

Predefined colours are fields of `sf.Color`: `Black`, `White`, `Red`, `Green`, `Blue`, `Yellow`, `Cyan`, `Magenta` and `Transparent`. `toInteger` returns the packed 32-bit value. `sf.Color` has no operators, so it cannot be added or compared; read and compare its components if that is needed.

`sf.IntRect.new` and `sf.FloatRect.new` take a position and a size, and both also accept four numbers. The last two numbers are width and height, not the bottom-right corner, which is the mistake this constructor invites most often:

```lua
local tile = sf.IntRect.new(sf.Vector2i.new(0, 0), sf.Vector2i.new(32, 32))
local same = sf.IntRect.new(0, 0, 32, 32)
local sub = sf.IntRect.new(32, 0, 32, 32)

local origin = tile.position      -- Vector2i(0, 0)
local height = tile.size.y        -- 32
local inside = tile.contains(sf.Vector2i.new(16, 16)) -- true
local overlap = tile.findIntersection(sub) -- an sf.IntRect, or nil, when the rectangles do not overlap
```

`sf.Angle` carries a rotation. It is not a number, so an angle value has to go through `sf.degrees` or `sf.radians` rather than being passed as degrees:

```lua
local facing = sf.degrees(90)
local radians = sf.radians(math.pi / 2)

local degrees = facing.asDegrees()
local wrapped = sf.degrees(450).wrapSigned().asDegrees() -- 90
```

`wrapSigned` constrains an angle to `[-180°, 180°)` and `wrapUnsigned` to `[0°, 360°)`. Both are optional: an angle outside those ranges is still valid, so use them only when a comparison or a normalised display value needs the constrained form. `sf.Angle.new()` and `sf.Angle.Zero` are both zero.

`sf.Time` carries a duration, and `sf.seconds`, `sf.milliseconds` and `sf.microseconds` build one:

```lua
local cooldown = sf.seconds(0.75)

local milliseconds = cooldown.asMilliseconds() -- 750
```

`sf.Time.new()` is zero as well; `sf.sleep` pauses the calling thread for a duration.

## Object types

The graphics objects follow the SFML hierarchy, and Lua sees the same relationships:

```text
sf.Drawable
sf.Transformable
sf.Shape : sf.Drawable, sf.Transformable
sf.CircleShape, sf.ConvexShape, sf.RectangleShape : sf.Shape
sf.Sprite : sf.Drawable, sf.Transformable
sf.Text : sf.Drawable, sf.Transformable
```

Every `sf.Transformable` exposes `setPosition` and `getPosition` with `sf.Vector2f`, `setRotation` and `getRotation` with `sf.Angle`, `setScale`, `getScale`, `setOrigin` and `getOrigin` with `sf.Vector2f`, plus `move`, `rotate`, `scale` and `getTransform`. That is the whole movement vocabulary for a sprite, a shape or a text object.

```lua
local cell = sf.RectangleShape.new(sf.Vector2f.new(32.0, 32.0))

cell:setPosition(sf.Vector2f.new(64.0, 64.0))
cell:setOrigin(sf.Vector2f.new(16.0, 16.0))
cell:setRotation(sf.degrees(45))
cell:setScale(sf.Vector2f.new(2.0, 2.0))
cell:move(sf.Vector2f.new(8.0, 0.0))

local bounds = cell:getGlobalBounds()
```

`sf.RectangleShape.new` takes a size, `sf.CircleShape.new` takes a radius and a point count, `sf.ConvexShape.new` takes a point count, and `sf.Text.new` takes a font, a string and a character size. Shapes also carry `setFillColor` and `setOutlineColor` with an `sf.Color`, and `setOutlineThickness` with a number.

The abstract bases above are present as tables but have no `new`: `sf.Drawable`, `sf.Shape`, `sf.RenderTarget`, `sf.InputStream`, `sf.SoundSource`, `sf.SoundStream`, `sf.SoundRecorder`, `sf.SoundFileReader`, `sf.SoundFileWriter` and `sf.Socket` cannot be constructed. Create a concrete subclass instead, and treat the base as the type a parameter or a return value declares. `sf.Drawable` is the one exception that Lua can implement: `sf.LuaDrawable.new(drawCallback)` produces a drawable whose `draw` runs in Lua.

Events follow the same pattern in reverse. The payload types such as `sf.Event_Closed` and `sf.Event_Resized` are constructible, while `sf.Event.new` requires one of them as its argument. Project code normally receives events instead of building them.

## Using SFML in a project

Positions, sizes and rectangles travel across the Engine API as `sf` values, so converting between cell coordinates and world positions is ordinary vector arithmetic:

```lua
local Player = require("Source.NodeFunctions.Player")

local CELL_SIZE = Engine.GetCellSize()

local function cellToWorld(cellX, cellY)
    return sf.Vector2f.new(cellX * CELL_SIZE, cellY * CELL_SIZE)
end

local player = Player.GetPlayer()
if player ~= nil then
    local position = player:getPosition()
    local cell = sf.Vector2i.new(
        math.floor(position.x / CELL_SIZE),
        math.floor(position.y / CELL_SIZE)
    )
end
```

Check the declared type before passing a value. An API that declares `sf.Vector2f` does not accept a `sf.Vector2i`, a Standard `tuple` or a plain table, and it does not convert one for you.

JSON and metadata hold pure data, while `sf` values are native userdata, so converting between the two forms is explicit rather than automatic. The Game project's save codec writes a `sf.Vector2i` as `{ x, y }` and rebuilds it on load, and its record normaliser turns `sf.Vector2i`, `sf.Vector3i`, `sf.IntRect`, `sf.FloatRect` and `sf.Color` into numeric arrays. Store the components whenever the destination is data, and build the `sf` value again where it is used.

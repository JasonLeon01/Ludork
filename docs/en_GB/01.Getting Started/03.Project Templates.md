# Project Templates

## Goal

Select the template that matches the project's native-code, video and target-platform requirements.

## Prerequisites

- A list of required target platforms.
- A decision on whether the project will change native C++ code.
- A decision on whether the shipped game must play video.

## Steps

1. Choose C++ Source if native code, an iOS target or a HarmonyOS target is required; otherwise choose Standalone.
2. Add FFmpeg only if video playback is an explicit requirement.
3. Confirm that the development host provides every compiler, SDK and signing resource required by the target.

## Template reference

Choose the template from the project's long-term technical requirements. Changing template later is a source-management task, not an editor toggle.

| Template | Native source | Compiler needed for normal Run | Use when |
|---|---:|---:|---|
| Standalone | No | No | Authoring Lua, Blueprint, data and assets with the supplied runtime. |
| C++ Source | Yes | Yes | Changing native services, bindings or building an iOS or HarmonyOS target. |
| Standalone + FFmpeg | No | No | The supplied runtime must support video playback. |
| C++ Source + FFmpeg | Yes | Yes | Native development and video playback are both required. |

## FFmpeg option

FFmpeg adds build size, third-party licence obligations and platform-specific preparation. Enable it only for projects that use video. Windows and macOS FFmpeg builds use shared or dynamic libraries. The iOS C++ Source + FFmpeg path builds static `.a` libraries through `Sample/cmake/FFmpeg`; a downstream distributor of that statically linked iOS application must satisfy the applicable LGPL relinking-material requirements. Consult `Licenses/FFmpeg/README.md` before distribution. On macOS, the New Project window displays an additional compatibility notice when FFmpeg is selected.

## Packaging targets

- Windows 10-or-newer x64 editors expose the Windows x64 target.
- Apple Silicon macOS 13.3-or-newer editors expose macOS arm64, iOS arm64 and HarmonyOS Mobile arm64-v8a targets.
- There is no Standalone iOS template. Every iOS output requires a C++ Source project, Xcode, a development team, bundle settings and signing resources.
- There is no Standalone HarmonyOS template. HarmonyOS Mobile output requires a C++ Source project and DevEco Studio with the OpenHarmony native SDK.
- **Use luac**, shader encryption and data encryption are packaging options, not template types.

All four templates include the complete `Scripts/stub/**/*.d.lua` declaration tree for editors and Lua language tooling. These files are development assets: packaging removes the entire `Scripts/stub` directory, Lua compilation ignores `.d.lua`, and no declaration file is shipped with a game.

## Decision check

Use Standalone if every planned feature is expressible through the available Lua, Blueprint, asset and data APIs. Use C++ Source when even one required feature changes native code. Add FFmpeg only when video playback is an explicit requirement.

## Expected result

The new project contains the correct native source/runtime and video capability for its intended releases, without unnecessary build or licence obligations.

## Verification

Open `Main.proj`, confirm the recorded capabilities, verify that its declaration tree is present, run the project, and open Pack Options. Inspect a package to confirm that neither `Scripts/stub` nor any `.d.lua` remains. Confirm that iOS targets iOS 15.0 or newer on arm64 and that HarmonyOS Mobile targets HarmonyOS 6.0.1 / API 21 or newer on arm64-v8a from a configured macOS host.

## Limitations

A template establishes the project baseline; the editor does not convert an established project between Standalone and C++ Source. FFmpeg also adds third-party distribution obligations that differ between dynamically linked desktop packages and statically linked iOS packages.

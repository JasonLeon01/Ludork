# Lua Basics

Ludork runs Lua 5.5. This page introduces the language itself for readers new to Lua. Ludork's native additions are described separately in [Ludork Lua Advanced](<04.Ludork Lua Advanced.md>).

## Files, comments and local variables

Lua files use the `.lua` extension. `--` starts a line comment and `--[[ ... ]]` encloses a block comment. Declare working values with `local`; an uninitialised variable is `nil`.

```lua
-- One line
local playerName = "Hero"
local level = 1
local alive = true
local target = nil
```

Lua values include `nil`, booleans, numbers, strings, functions, tables, userdata and threads. `type(value)` returns one of these built-in categories; application objects represented by tables or userdata keep that underlying category.

## Operators

Common operators are:

| Kind | Operators |
|---|---|
| Arithmetic | `+`, `-`, `*`, `/`, `//`, `%`, `^` |
| Comparison | `==`, `~=`, `<`, `<=`, `>`, `>=` |
| Logic | `and`, `or`, `not` |
| Strings | `..` for concatenation |
| Length | `#value` |

Lua treats only `nil` and `false` as false. Values such as `0`, an empty string and an empty table are true in a condition.

## Conditions

```lua
if health <= 0 then
    state = "defeated"
elseif health < maxHealth then
    state = "hurt"
else
    state = "healthy"
end
```

Use explicit `nil` comparisons when absence must differ from `false`, `0` or an empty value.

## Tables

A table can act as an array, dictionary or record. Array indices start at 1.

```lua
local items = { "Key", "Potion" }
local player = {
    name = "Hero",
    hp = 100,
}

items[#items + 1] = "Gem"
player.hp = player.hp - 10
```

Assigning `nil` removes an ordinary table key. Avoid nil holes in arrays because `#`, `ipairs` and array helpers stop at the first missing slot.

## Loops

```lua
for index, item in ipairs(items) do
    useItem(index, item)
end

for key, value in pairs(player) do
    inspectValue(key, value)
end

local count = 3
while count > 0 do
    count = count - 1
end
```

Use `ipairs` for dense arrays and `pairs` for dictionaries. Numeric `for` loops include both endpoints unless the step skips the last value.

## Functions and methods

Functions are values and may return multiple results. Use colon syntax for instance methods; it passes the receiver as `self`.

```lua
local function clampHealth(value, maximum)
    return math.max(0, math.min(value, maximum))
end

local Character = {}

function Character:setHealth(value)
    self.health = clampHealth(value, self.maxHealth)
end

local value, found = findItem("Key")
```

`object:method(value)` is equivalent to `object.method(object, value)`. Define and call instance methods consistently with the colon form.

## Modules

A module is a Lua file that returns its public value. Require it by its path below `Scripts`, using dots and no extension.

```lua
-- Scripts/Source/Score.lua
local Score = {}

function Score.Add(current, amount)
    return current + amount
end

return Score
```

```lua
local Score = require("Source.Score")

local total = Score.Add(10, 5)
```

Finish direct `require` calls before declaring aliases. Do not create directory-level `init.lua` aggregators.

## Errors

Use `assert(condition, message)` for required conditions and `error(message)` for an explicit failure. Required project data should fail at its source rather than silently produce partial state.

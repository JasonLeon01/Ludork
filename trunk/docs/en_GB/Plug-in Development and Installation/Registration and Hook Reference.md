# Registration and Hook Reference

Reference for every registration method, command context, host bridge and lifecycle hook exposed on `IPluginRegistrar`. All registrations occur exclusively inside `IEditorPlugin.Register`; an empty `Register` method (as generated by the creation templates) is valid.

## Scope and execution order

- **Active scope:** The start page loads global plug-ins only. A project window combines global plug-ins with that project's plug-ins across menus, map context menus, text hints, Export/Run/Pack hooks and export-participant fingerprints. Switching projects deactivates the previous project's registrations.
- **Source precedence:** Within each scope, working-directory and user registrations merge by plug-in ID with the working-directory copy winning; only the selected copy contributes commands, providers and hooks.
- **Ordering and uniqueness:** Global plug-ins run before project plug-ins for providers and hooks. Menu items sort by menu location and `Order` (global commands win ties). Plug-in IDs and command IDs must be unique within the effective global-plus-current-project set — ordinary menu commands and map context-menu commands share one command-ID namespace. Conflicting registrations fail rather than overwriting earlier ones. Independent project scopes may reuse IDs, and one project's load failure never blocks global or other-project plug-ins.

## Menu commands

`RegisterMenuCommand(PluginMenuCommand)` adds a command to `File`, `Edit`, `Game`, `Database`, `Help` or `Plugins`. Command IDs must be non-empty and unique in the effective set, and `Order` determines placement within the menu.

| `PluginMenuCommand` field | Meaning |
|---|---|
| `Id` | Non-empty command ID, unique in the effective set |
| `Location` | One of the six supported menu locations |
| `Order` | Numeric sort key within the menu |
| `Label` | Already-localised displayed text |
| `Handler` | Asynchronous `PluginMenuHandler` |

The `PluginMenuContext` passed to `Handler` supplies the optional project path, editor language, read-only plug-in directory, writable plug-in data directory, message UI, text-hint invalidation, plug-in-scoped secret store, optional Blueprint assistant and resource-cleanup host bridges, and a `CancellationToken`. Avalonia source plug-ins referencing `Ludork.Plugin.Avalonia` can cast `UserInterface` to `IAvaloniaPluginUserInterface` to obtain the real owner window. Return `PluginResult.Completed()` on success or `PluginResult.Failed(error)` on a handled failure.

## Map item context-menu commands

`RegisterMapContextMenuCommand(PluginMapContextMenuCommand)` appends a command after built-in actions when the user right-clicks a map item (never when right-clicking empty space in the map list). Command IDs share the unique namespace with ordinary menu commands, `Order` sorts plug-in commands, and `Label` is the already-localised displayed text.

| `PluginMapContextMenuCommand` field | Meaning |
|---|---|
| `Id` | Non-empty command ID, unique in the effective set |
| `Order` | Numeric sort key |
| `Label` | Already-localised displayed text |
| `Handler` | Asynchronous `PluginMapContextMenuHandler` |

`PluginMapContextMenuContext` provides `MapKey` (the right-clicked map), the project path, editor language, plug-in directories, message UI, text-hint invalidation, secret store, `CancellationToken` and `MapEditorHost`, returning `PluginResult` like an ordinary menu command.

### `IMapEditorHost` contract

`IMapEditorHost` is a narrow read/write boundary — plug-ins never receive `ProjectDataStore`, editor view models, `MapPanel`, host controls or mutable editor JSON.

| `IMapEditorHost` member | Meaning |
|---|---|
| `ProjectPath` | Open project root |
| `CellSize` | Read-only source cell size from the compiled engine declaration, independent of preview zoom |
| `SuggestedMapKey` | Map that opened the plug-in, when available |
| `ListMaps()` | Ordered map summaries containing key and display name |
| `ReadMap(mapKey)` | Immutable snapshot of the current in-memory map |
| `ReadTileset(tilesetKey)` | Immutable tileset snapshot |
| `ListActorBlueprints()` | Actor Blueprint summaries (`Key` is the canonical class reference; `DisplayName` is the project Blueprint key) |
| `ReadActorBlueprintPreview(blueprintReference)` | Resolved default Actor appearance at cell `(0, 0)` for an existing Actor Blueprint |
| `AcquireActorPreview(snapshot)` | Native material preview handle (`IPluginActorPreview`) for a resolved Actor snapshot |
| `ResolveAssetFile(assetPath)` | Resolve a logical path at final editor file I/O; empty if unavailable |
| `GetSaveDirectoryAsync(cancellationToken)` | Return the project's absolute user save directory without creating it |
| `ReplaceLayerAndSaveAsync(request, cancellationToken)` | Revision-checked layer replacement and direct single-map save |
| `ReplaceActorsInRegionAndSaveAsync(request, cancellationToken)` | Revision-checked replacement of Actor placements in one layer's rectangular region |
| `RunProjectScriptAsync(scriptPath, request, cancellationToken)` | Execute a Lua entry with the current project's game runtime and return its JSON object result |

`GetSaveDirectoryAsync` reads the static `APP_NAME` from the saved `Scripts/Entry.lua` and follows the [desktop game directory rules](<../Editor User Guide/Project Settings and Asset Layout.md#game-configuration>). It never executes Lua or creates directories; unreadable or invalid names, unavailable home directories or cancellation fail the call.

### Map, tileset and Actor snapshots

- **Map and passage snapshots (`PluginMapSnapshot`):** Exposes identity, dimensions, an opaque `Revision` (copy unchanged into write requests), ordered layers with `Visible`, rectangular `Tiles` and `AutoTiles`, and a map-sized `Passage` matrix. Each `PluginMapPassage` gives terrain `Passable` plus resolved `Up`, `Right`, `Down` and `Left` movement permissions across visible terrain layers, AutoTiles, map edges and both ends' directional flags; Actor occupancy is separate.
- **Tilesets and asset paths:** Tileset snapshots include tile dimensions, count and passability. Tileset and Actor `AssetPath` values stay exact-case `/Game/Assets/...` paths — call `ResolveAssetFile` only at final native file I/O, never for snapshots or intermediate caches.
- **Actor snapshots (`PluginMapActorSnapshot`):** Each layer exposes immutable Actor snapshots carrying `Tag`, `BlueprintReference` and visuals resolved via the map editor's own Blueprint/script and instance-override resolver. `SourceRect` is the resolved static texture rectangle (including the character direction's first frame — do not re-derive character sheet layouts).
- **Actor transforms and placeholders:** Translation, scale, origin, rotation, `Material`, `MaterialParameters` and `PreviewOpacity` (`0.25` for invisible Actors, `1.0` for visible) are pre-resolved. Missing visuals have an empty `AssetPath` and null `SourceRect` for cell placeholders. Scale rendering by `CellSize`, not tileset tile dimensions.
- **Native Actor material preview:** Call `IMapEditorHost.AcquireActorPreview(snapshot)` for native material rendering of the resolved source frame. The returned `IPluginActorPreview` exposes `Changed` and a `Frame` with premultiplied BGRA pixels, dimensions, `OffsetX`/`OffsetY` and any material error. Apply `OffsetX`/`OffsetY` relative to the source-frame origin before the Actor transform (displaced materials can expand the frame). Set `IsActive = false` while hidden and dispose the handle when finished; source-frame animation remains the plug-in's responsibility.

### Layer and Actor-region writes

- **Tile layer replacement (`PluginMapLayerWriteRequest`):** Identifies the map and layer, echoes `BaseRevision` and `ExpectedTilesetKey`, and provides full `Height × Width` `Tiles` and `AutoTiles` matrices. For regional tile edits, copy the snapshot matrices and modify only the target rectangle (there is no separate regional tile write API). `PluginMapWriteResult` distinguishes success, revision/tileset conflict and error, and returns the current revision. Validation or write failures leave editor memory, Undo history and UI untouched.
- **Actor region replacement (`PluginMapActorRegionWriteRequest`):** Identifies `MapKey`, `LayerName`, `BaseRevision`, a zero-based `PluginMapRegion(X, Y, Width, Height)`, a required `PreserveBaseClassReference`, and a non-empty list of `PluginMapActorPlacement(BlueprintReference, X, Y)`. The host preserves Actors outside the rectangle and Actors inside whose resolved class derives from `PreserveBaseClassReference`, removing other inside Actors and their instance overrides while keeping preserved records intact.
- **Actor placement validation:** New placements must reference valid Actor Blueprints on distinct passable cells inside the rectangle without colliding with preserved Actors or Actors on other layers; the host assigns map-unique tags. Hidden layers, invalid bounds, unresolved classes, invalid or duplicate existing tags, empty placement lists and revision conflicts fail before writing. Tiles and AutoTiles are untouched.
- **Direct save and Undo semantics:** Either successful write updates the in-memory map, atomically saves only `Data/Maps/<mapKey>.json`, pushes one Undo step onto that map's history, advances its revision and refreshes the target map and layer. Any existing unsaved edits on that same map are included in this save; other maps and project documents are neither saved nor cleared of their dirty state. Undo restores the pre-write in-memory state and marks the map dirty without auto-saving.
- **Pending path-change guard:** Writes are refused while the target map has an unsaved related path change; complete a global Save first.

### Project script execution

`RunProjectScriptAsync` launches the project's own game executable against an existing absolute `.lua` or `.luac` entry file and an independent `JsonObject` request, using the project root as working directory (without invoking normal `Entry` or saving project documents).

- **Preconditions:** Unsaved non-map project documents are rejected, and C++ Source projects require a current native build. Execution also fails if `APP_NAME` cannot be resolved from `Scripts/Entry.lua`.
- **Arguments and initialisation:** The entry receives the temporary request JSON path in `arg[1]`, the required output JSON path in `arg[2]`, and the resolved `APP_NAME` in `arg[3]`. Call `Engine.setAppName(arg[3])` before loading project modules so user data and resource overrides resolve properly. Scripts creating Actors or material-dependent graphics must also run [material cache preparation](<../Lua and Blueprint Scripting/Global and Core Modules/Core Modules/Engine/Maps and Materials.md#material-cache-preparation>) first.
- **Result contract and limits:** Write one JSON object to `arg[2]` before exiting. `PluginProjectScriptResult.Success` confirms clean execution and decoding, `Data` holds the JSON object and `Error` describes host failures (plug-in payload fields are the plug-in's responsibility). Results exceeding 32 MiB, missing or invalid JSON objects, non-zero exit codes and detected project input changes during execution all fail the request.
- **Process lifecycle:** The host captures stdout and stderr, terminates the process on cancellation or after 60 seconds, and removes the temporary request/result directory. Because the script runs as a full child process rather than a restricted sandbox, it controls what it loads; [Official Mota Map Fill](<Official Plug-ins/Mota Map Fill.md>) uses this entry point to decode saves and compute battle previews without starting a scene.

## Text hints

`RegisterTextHintProvider(ITextHintProvider)` registers synchronous text-hint resolution. `TextHintContext` supplies the project path, editor language and current field text. Providers run in plug-in order and the first non-empty result wins; thrown exceptions are recorded as plug-in diagnostics.

## Before Export, Before Run and Before Pack

- **Before Export (`RegisterBeforeExportHook`):** Accepts `IProjectExportHook` (extending `IProjectOperationHook` with `ProjectExportFiles GetFiles(string projectPath)`). `GetFiles` inspects without modifying files and returns concrete project-relative `InputPaths` and `OutputPaths` with no duplicates or input/output overlap (declare missing input files too so later creation is detected); `ExecuteAsync` performs the work.
- **Export sequencing and fingerprinting:** Export saves and validates the project, runs Export hooks sequentially, generates UI runtime files and records success. The editor fingerprints declared files plus export plug-in identity (including project scope for project plug-ins) to decide whether another Export is needed. Export hooks run for **Export**, confirmed **Export and Play**, and every editor **Pack**; a before-Run hook modifying export inputs forces another Export before launch. See [Construct, Export and Play](<../Editor User Guide/Run Debug and Package.md#construct-export-and-play>).
- **Before Run and Before Pack (`RegisterBeforeRunHook`, `RegisterBeforePackHook`):** Accept `IProjectOperationHook` and run sequentially prior to their operation. Editor game packaging runs a complete Export before running before-Pack hooks. [Standalone project conversion](<../Editor User Guide/Run Debug and Package.md#convert-source-to-a-standalone-project>) runs Export hooks only — it skips before-Pack hooks and their packaging exclusions. Any failed result or exception aborts subsequent hooks and blocks the operation. Honour `CancellationToken` and report progress via `IPluginOutput`.

| Operation context field | Meaning |
|---|---|
| `ProjectPath` | Open project root |
| `EditorLanguage` | Current editor language key |
| `Operation` | `ProjectOperationKind.Export`, `Run` or `Pack` |
| `Packaging` | Non-null only during before-Pack hooks; null during Export and before-Run |
| `Output` | Append-only operation output |
| `TextHints` | Request text-hint refresh |
| `CancellationToken` | Cancellation token for the current operation |

When `Packaging` is non-null, `IProjectPackaging` exposes the following controls:

| `IProjectPackaging` member | Meaning |
|---|---|
| `UseLuac` | Whether Pack compiles supported Lua sources |
| `UseLdPak` | Whether Pack writes complete `Assets`, `Data` and pruned `Scripts` trees into root `Assets.ldpak`, `Data.ldpak` and `Scripts.ldpak` |
| `CompileLuaDirectory(relativePath)` | Include a project-relative Lua directory in Pack compilation |
| `ExcludeFile(relativePath)` | Omit a project-relative file from the final package |

For example, Official Locale Tools calls `ExcludeFile("Data/Locale/Locale.xlsx")` in its before-Pack hook to omit the authoring workbook from final game packages while keeping it in Standalone conversions; its Export hook writes the Lua language catalogues separately.

## Blueprint assistants

A Blueprint assistant registers an ordinary `PluginMenuCommand` and owns its UI, settings and conversation history (the host supplies no assistant window or controls; `IAvaloniaPluginUserInterface` provides only an optional owner window). Inside a project window, `PluginMenuContext.BlueprintAssistantHost` provides the project path, suggested current Blueprint, available Blueprint keys and `CreateSession`.

- **Session and workspace boundaries:** `IBlueprintAssistantSession` binds to one existing Blueprint, exposing its base revision and an `IBlueprintAssistantWorkspace`. The workspace can list and read Blueprints, query the API catalogue, search or read allowlisted project source, query official documentation, validate candidates and stage proposals — it cannot mutate Blueprints directly or access arbitrary editor services.
- **Approval and apply:** The plug-in retains the session and calls apply or discard explicitly after user approval. Apply rechecks the base revision and candidate validity, records one Undo snapshot, marks project data dirty and refreshes open editors for that Blueprint without saving to disk.
- **Secrets:** Store API keys in the scoped `PluginMenuContext.SecretStore`; see [Store secrets](<Avalonia UI Secrets and Localisation.md#store-secrets>).

### Official documentation queries

| Documentation member | Result |
|---|---|
| `SearchDocumentationAsync(query, maxResults, cancellationToken)` | Keyword matches across titles, paths and full Markdown with document keys, excerpts and official page URLs |
| `ReadDocumentationAsync(documentKey, startLine, lineCount, cancellationToken)` | Numbered Markdown lines from a document key and one-based line range, with its official page URL |

These methods fetch the fixed website's search index on demand for the editor-selected documentation version and language (matching [online documentation](<../Editor User Guide/Start Page Workspace and Shortcuts.md#online-documentation>)), sharing one cached snapshot per request workspace. They accept queries and document keys only (never project paths or arbitrary URLs). Missing or invalid indexes and network failures return tool errors without switching version or language.

Documentation results are capped at 12,000 characters: continue reads from `nextLine` when present, and inspect `truncatedLine` when an oversized line's tail was omitted (continuation resumes at the following line). API catalogue metadata remains authoritative for concrete Blueprint APIs; see [Official Blueprint AI](<Official Plug-ins/Blueprint AI.md#official-documentation>).

## Resource cleanup

Inside a project window, `PluginMenuContext.ResourceCleanupHost` exposes `IResourceCleanupHost`. The plug-in owns its scan UI, built-in native keep list and final confirmation; the host owns static reference analysis, report validation, project keep-list storage and system Trash recycling.

| Member | Meaning |
|---|---|
| `ProjectPath` | Open project root |
| `ReadKeepPathsAsync` / `SaveKeepPathsAsync` | Read or replace project additions in `EditorCache/ResourceCleanupKeep.list` (an empty list deletes the file) |
| `ScanAsync(nativeKeepPaths, userKeepPaths, progress, cancellationToken)` | Analyse static references and return an immutable report of candidates, categories, sizes and issues |
| `TrashAsync(reportId, progress, cancellationToken)` | Revalidate and recycle all candidates in the report, returning moved paths, remaining paths and any error |

`ResourceCleanupProgress` reports stage, completed/total counts and current path. Reports containing scan issues cannot be recycled, and modified project inputs invalidate existing reports. The host never falls back to permanent deletion when the system Recycle Bin or Trash is unavailable. See [Official Resource Cleanup](<Official Plug-ins/Resource Cleanup.md>) for scan boundaries and the review workflow.

## Unsupported extension points

There are no public hooks for host-docked panels, toolbars, arbitrary context menus, custom data types or editor events. `RegisterMapContextMenuCommand` is the sole context-menu extension point. Plug-ins may open their own Avalonia windows from a command, but cannot inject controls into editor-owned views.

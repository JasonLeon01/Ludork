# Mota Map Fill

官方插件 Mota Map Fill（源码位于 `Plugins/OfficialMotaMapFill`）通过分析当前地形连通性并结合存档玩家状态评估怪物战斗伤害，在已有地图区域中自动填充门、怪物与奖励。安装方式见[发行版官方插件](<../安装与管理插件.md#发行版官方插件>)。

项目须保留默认玩法的 `Player`、`Enemy`、`DoorBase`、`Teleporter` 与 `MotaBattleAbility` 契约。插件会启动当前项目的游戏程序以还原玩家状态、自动准备项目的用户材质缓存（若准备失败会在状态区报告错误）并计算战斗伤害。打开参考存档前请先保存蓝图、脚本与其他非地图文档；C++ Source 项目还须具备最新的**编译**产物。插件不会代为保存这些文档。

## 选择范围与参考玩家

1. 在地图列表中右键点击地图，选择**魔塔 Actor 填充**。
2. 选择一个可见图层，在地图预览中拖动框选矩形范围，或点击**恢复全图**。坐标从 0 开始，包含拖动起点与终点格。
3. 选择 `.json` 或 `.ldc` 游戏存档。文件选择器优先定位至上次选择的目录，首次打开时默认定位至当前项目的用户存档目录 `~/<APP_NAME>/Save`（目录不存在时回退至最近的已有父目录且不创建目录；若无法从 `Scripts/Entry.lua` 解析 `APP_NAME`，错误会显示在状态区）。
4. 从**参考玩家**下拉框中选择玩家（按 `playerKeys` 顺序排列，默认选中第一位玩家）。显示的 HP、ATK 与 DEF 已计入还原后的装备、道具能力与状态效果。切换玩家会自动重算怪物伤害；点击**重新读取**可重新加载存档与项目定义。

参考存档仅提供玩家状态——地形始终取自编辑器当前打开的地图，存档内记录的地图变动会被忽略。

## 选择 Actor 蓝图

点击**下一步**，再点击**选择蓝图…** 以选取项目 `Data/Blueprints` 目录下一个或多个 `.json` 蓝图文件。列表初始为空，后续选择会去重追加，取消操作不改变原列表。若单次多选中包含无效文件或不受支持的 Actor 类型，整批选择均会被拒绝，原有列表保持不变。

**门**、**怪物**与**道具**页签仅显示已添加的蓝图，选中或悬停条目时在下方展示预览。右键条目选择**移除**，或选中后按 **Delete**／**Backspace** 即可将其移出候选列表。伤害评估覆盖已选蓝图与当前地图上已有的 Actor 引用：

- **门**：显示继承后的钥匙 ID 与所需数量。支持黄门（`KEY_Y`）与蓝门（`KEY_B`）；其他门类型不参与摆放。
- **怪物**：显示由项目 `MotaBattleAbility` 计算的单场战斗伤害（含战斗特殊能力）。无法击败或伤害超过参考玩家当前 HP 一半的怪物，会被标记为仅用于最大房间守卫。不造成伤害的怪物可正常显示 `0`；无法击败的怪物即使伤害字段为 `0` 仍保持不可击败标记。
- **道具**：包括 Item 与 Equip 蓝图、消耗品（如宝石、药瓶）以及其他既非玩家、门、怪物也非传送点的 Actor 蓝图。请仅勾选希望作为奖励摆放的拾取物；传送点及其子类自动排除。

## 摆放规则

### 地形与房间分析

插件综合读取所有可见图层的地形通行数据（含自动图块与方向通行限制），并基于整张地图进行分析以避免将选区边界误判为墙体，而实际摆放严格限定在所选图层与矩形范围内。其他图层上已有的 Actor 与被保留的传送点会继续占用其所在格。

宽房间内部由至少属于一个完整可通行 2 × 2 区块的格子组成，并按四方向可通行关系归为独立房间；单格宽直通道、弯道与交叉口不计入宽房间面积。

### 房间守卫与门

- **每房一怪**：只要存在合适的怪物候选与空闲格，每个房间在室内与直属入口合计配置一只怪物（优先放在靠近入口的室内格）。共享入口若已有怪物，相邻房间共用该守卫而不再叠加第二只；直属入口外的独立主通道仍可配置各自守卫。没有可用门口的房间也可在室内空格摆放普通怪物。
- **独立摆门**：门独立放置在可用入口处，不占用房间的单怪名额。
- **房间规模与怪物分级**：大房间（室内不少于 9 格）优先配置蓝门与较强怪物；小房间优先配置黄门与较弱怪物。在可击败且伤害不超过玩家半血的怪物中，按伤害排序后前半部分（向上取整）作为弱怪、后半部分作为强怪；若仅有一种合格怪物，则兼任两类角色。

### 高危守卫

每次生成最多摆放一只高危怪物，守卫一个完整位于选区内且具有可用入口的最大大房间（并列最大时随机选取）。高危候选包括伤害超过玩家半血、无法击败以及反击伤害致死的怪物。高危怪物绝不会放入普通房间、口袋或无守卫走廊。

### 终端口袋

- **定义**：终端口袋包含 1–8 格，由单个狭窄入口与主路隔开（支持 L 形与 T 形内部），不含宽房间或传送点，且入口外侧连通至宽房间、传送点或主路分叉。终端口袋不计入大房间面积。
- **守卫、门与奖励**：口袋同样遵循室内与入口合计一怪的原则，入口已有守卫时直接复用。室内空间充足时，口袋优先在内部配置弱怪与奖励，入口可摆放黄门；室内仅余一格用于奖励时，守卫可放在入口处。普通走廊不摆放道具。

### 奖励与回退处理

- **保底与目标数量**：只要存在道具候选与合法位置，房间与口袋均优先保证至少一件奖励（已有保留道具即可满足保底；否则先预留一个奖励格再放置守卫，口袋的首件奖励优先位于内部较深处）。新增奖励的目标数量为剩余可用室内格的 40%（向上取整）。
- **空间分布**：摆放优先采用随机选定的棋盘格奇偶（如 `1010`／`0101`），并禁止横向或纵向连续三格出现道具（保留道具与已预留奖励均计入），因此实际数量可能低于目标。
- **候选缺失与报告**：缺失某类候选时仅独立跳过该类（例如未选蓝门不影响摆放强怪）。结果会报告未能配置怪物、守卫或奖励的房间与口袋，绝不违反已有占位、选区边界或高危规则。结果同时列出各类摆放数量、房间与口袋合计数量以及随机种子；点击**再次生成**可沿用当前选择生成新分布。

## 替换与保存

> **警告**：点击**生成并保存**会移除选定图层与矩形范围内除 `Source.MapActors.Teleporter` 实例及其子类以外的所有既有 Actor（包括事件、装饰、门、怪物与道具）及其实例覆盖。被保留的传送点维持原有标签与实例覆盖；Tile、自动图块、其他图层及矩形范围外的 Actor 保持不变。若无法生成任何合法摆放，地图既不会被清空也不会被保存。

保存操作执行一次带 revision 校验的单地图直接保存，并压入一步撤销记录（该地图上已有的未保存改动会一并保存）。遇到冲突编辑、无法解析的 Actor 类或保存失败时，地图保持原样；若发生 revision 冲突，编辑器会重新载入地图并要求重新读取参考存档。完整写入与撤销规则见[地图项右键菜单命令](<../注册点与 Hook 参考.md#地图项右键菜单命令>)。

> **注意**：伤害数值仅基于所选存档状态的单场战斗估算。生成过程不模拟拾取奖励、消耗钥匙、多场连续战斗消耗或领域、夹击等空间移动伤害，也不保证生成的地图一定可通关。

# 游戏本地化工作流

在 Excel 工作簿（`Data/Locale/Locale.xlsx`）中维护游戏文本，并借助官方插件 Locale Tools 导出 Lua 语言目录，供编辑器文本提示与游戏运行时格式化使用。

## 工作流

开始前，请确认项目包含 `Scripts/Source/Locale/Core.lua` 并在 `Scripts/Entry.lua` 中保留常规的本地化初始化；如果工作簿中使用了公式，所用电子表格软件必须能保存公式缓存值。

1. 通过[发行版官方插件](<../安装与管理插件.md#发行版官方插件>)安装 Locale Tools。
2. 在 `Data/Locale/Locale.xlsx` 中填写文本 ID 与对应翻译。
3. 运行或打包项目前执行**导出**。
4. 在脚本与数据中使用 `LOC("ID")` 或 `{ID}` 格式化文本。

## 工作簿

按以下结构规则创建并维护 `Data/Locale/Locale.xlsx`：

- **表头**：每个参与导出的工作表均以第 1 行为表头。A 列必须为 `ID`（不区分大小写），B 列起为目标语言名称（如 `en_GB`、`zh_CN`）。空白语言表头会被忽略，且至少需要一列有效语言。
- **数据行与合并**：ID 为空的行会被跳过。ID 自动去除首尾空白且区分大小写。多张工作表合并至同一语言目录：出现重复 ID 时会同时报告首次与重复单元格坐标，同一语言下后出现的非空值覆盖先前的值。
- **公式与前导等号**：公式单元格存在缓存值时导出缓存值；无缓存值时导出移除前导 `=` 后的公式文本。如需导出字面量 `=` 或 `==`，请写作 `'=` 或 `'==`。

## 导出

在编辑器统一**导出**流程中，Locale Tools 为每种语言在 `Scripts/Source/Locale/<language>.lua` 生成一份 UTF-8 编码的 Lua 表：

```lua
return {
    ["TITLE_START"] = "Start",
    ["TITLE_EXIT"] = "Exit",
}
```

- **校验规则**：语言名必须非空、非根路径，且不得包含路径分隔符或非法文件名字符。工作簿缺失时跳过导出且不报告错误；工作簿格式损坏时会中止导出。
- **字符编码**：导出以 UTF-8 原样保留 Unicode 文本（含 C1 控制字符），并将引号、反斜杠与 ASCII 控制字符转义为 Lua 转义序列，确保编辑器提示与游戏运行时读到一致的字符串。
- **变更检测与打包**：工作簿与生成的语言文件均参与[导出变更检测](<../../编辑器用户指南/运行、调试与打包.md#编译导出与运行>)。游戏打包会先执行导出并在成品中排除 `Locale.xlsx`，而[将 Source 转换为 Standalone 项目](<../../编辑器用户指南/运行、调试与打包.md#将-source-转换为-standalone-项目>)会同时保留工作簿与生成的语言目录。通过命令行运行或打包前须先执行导出。生成的语言文件被版本控制忽略且不随项目模板分发，手写的 `Core.lua` 则保留。

## 编辑器提示

编辑器中任意输入框的文本去除首尾空白后若恰好为单个 `{TITLE_START}` 标记，即可显示实时提示。提供器读取 `Scripts/Source/Locale/<EditorLanguage>.lua`，缺失时回退至 `en_GB.lua`。包含空格或嵌套花括号的标记均视为无效。

## 运行时

`Scripts/Entry.lua` 先调用 `Source.Locale.Core.Init()` 加载语言目录，再通过 `Source.Configs.Main.LoadOrCreate()` 读取当前语言设置（仅 `require` `Core` 不会加载语言目录）。在玩法模块中可将格式化函数绑定为局部 `LOC`：

```lua
local Locale = require("Source.Locale.Core")

local LOC = Locale.ApplyStringLocaleFormat

local buttonText = LOC("TITLE_START")
local tabLabels = Locale.ApplyListLocaleFormat({ "MENU_LOAD", "MENU_SAVE" })
local message = LOC(
    "{ITEM_NEW}: {ITEM_NAME}"
)
```

- **字符串格式化（`ApplyStringLocaleFormat`）**：既支持解析裸键名，也支持替换字符串中的全部 `{ID}` 占位符。未命中的键原样保留，当前语言不可用时尽可能回退至 `en_GB`，双写 `{{`／`}}` 输出字面花括号。通用数据中的字符串不会自动翻译，显示前须经 `LOC` 处理。
- **列表格式化（`ApplyListLocaleFormat`）**：`Locale.ApplyListLocaleFormat(values: string[]): string[]` 按顺序格式化每个元素并返回新数组，不修改原输入；适用于页签标签与选项列表，语言切换时重新调用即可。
- **语言切换**：`Locale.SetLanguage` 切换当前活动语言并同步广播 `LocaleChanged`，配置窗口负责持久化选择。已订阅该事件的 UI 会依据原始语言键刷新文本，而不会重置当前选项、焦点或正在进行的对话。
- **初始语言与打包**：新建游戏配置时，若平台语言与可用语言目录精确匹配则采用该语言，否则采用 `en_GB`，同时不覆盖已有保存配置；详见[运行时配置](<../../Lua 与蓝图脚本/默认玩法/运行时数据、配置与存档.md#配置>)。Lua 编译与**将 Assets、Data 和 Scripts 打包为 .ldpak** 会将 `Core.lua` 与生成的语言表随其余 `Scripts` 一同处理。
- **重载规则**：导出更新后的翻译后需重启游戏。[Lua 热重载](<../../Lua 与蓝图脚本/Lua 运行时与模块.md#lua-热重载>)会保留已加载的语言表。

> **注意**：`Data/Locale/Locale.xlsx` 仅是项目创作源文件，而非运行时数据库或存档格式。插件界面自身的本地化与游戏语言目录彼此独立。

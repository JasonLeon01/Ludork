# Resource Cleanup

官方插件 Resource Cleanup（源码位于 `Plugins/OfficialResourceCleanup`）用于扫描已保存项目中未检测到静态引用的资源，保护通过动态路径加载的资源，并将经用户确认的候选文件移至操作系统回收站或垃圾篓。

## 工作流

请先通过[发行版官方插件](<../安装与管理插件.md#发行版官方插件>)安装 Resource Cleanup；扫描前打开项目、停止运行中的游戏并保存全部未保存编辑。

1. 选择**插件 → 资源清理…**（窗口标题为**资源清理**），界面分别展示只读的内置固定保留清单与当前项目的追加保留路径。
2. 检查内置保留清单，其中涵盖编辑器的[固定资源目录](<../../编辑器用户指南/项目设置与资产布局.md#固定资源目录>)以及插件附带的 UI 默认资源、应用图标与资产许可证；被这些保护目录内文件引用的资产同样受到保护。
3. 将通过动态 Lua 路径加载的项目相对文件或目录逐行添加到追加保留清单（例如 `Assets/Characters/Dynamic` 或 `Data/Animations/GeneratedEffect.json`）；填写目录即可保护其下全部内容。
4. 点击**扫描**。扫描在后台执行并实时展示阶段、进度与当前路径；点击**取消**可立即中止且不回收任何文件。
5. 审阅 **Data** 与 **Assets** 两个页签，查看各候选文件的项目相对路径、大小、总数与总体积。进入候选列表仅代表未检测到受支持的静态引用，并不等同于证明运行时不会使用该文件。
6. 如需保留某个候选文件，选中对应行并点击**保留选中项并重扫**，或修改保留清单后重新扫描。修改保留清单会使旧报告失效；若存在任何扫描问题，须先解决并重扫后才允许回收。
7. 点击**移到回收站／垃圾篓**，核对最终文件数量与总体积后确认执行。宿主会先依据当前项目文件重新校验报告，随后将当前报告中的全部候选移至系统回收站／垃圾篓。
8. 检查已回收文件、可能出现的错误与未处理文件。取消或发生错误都会中止后续移动，已移走的文件仍保留在系统回收站／垃圾篓中；再次清理前必须重新扫描。

追加保留路径会在点击扫描、点击**保存保留清单**或关闭窗口时写入 `EditorCache/ResourceCleanupKeep.list`。初始列表为空时仅打开窗口不会创建该文件，清空后保存会删除该文件，且内置固定条目不会写入其中。若保存失败，窗口会保持打开并显示错误。

## 扫描范围

> **重要**：Resource Cleanup 仅执行静态分析——不会运行 Lua、追踪游玩流程，也不会推断字符串拼接或运行时计算的路径。请务必将动态加载路径加入保留清单，即便扫描报告零问题，也应在回收前逐项复核候选列表。

- **扫描来源**：读取全部普通地图与世界子地图、全部 Lua 源码以及全部受支持的结构化 Data 文件。系统先沿 Data 依赖链判定保留范围再评估 Assets，因此未被引用的 Data 文件不会使其依赖的资产被连带保留。蓝图字段与地图实例覆盖会依据元数据递归遍历，包括组件与类型化容器内部的资源引用。
- **保护项与候选类型**：地图、`Data/General`、`Data/UI`、`Data/Configs`、`Data/Locale` 及其受支持引用始终受到保护。Data 清理候选仅限于 `Materials`、`Tilesets`、`AutoTiles`、`Blueprints`、`CommonFunctions`、`Animations`、`Particles`、`Curves` 与 `TextConfigs`（未知 Data 格式绝不列入候选）。Lua 脚本仅用于提取引用而不会被删除，生成的 UI 镜像与声明 Stub 不计作独立使用依据，材质缓存位于用户数据目录并由[运行时生成](<../../编辑器用户指南/材质.md#运行时生成>)管理。
- **Lua 表达式支持**：在已知资源 API 参数中可识别字符串字面量、括号、常量别名以及 `and`／`or` 条件分支，保守保留每个分支的常量路径并继续追踪其 Data 依赖。
- **文件系统安全检查**：符号链接、失效链接、重解析点与不可访问路径（含项目根目录本身）会产生扫描问题并阻断回收，且在移动文件前再次复检。保留条目允许填写尚未创建的路径，但无法绕过已有父目录的安全检查。

## 回收与编辑器状态

回收操作遵循与[编辑器文件删除](<../../编辑器用户指南/启动页、工作区与快捷键.md#文件浏览器与引用树>)相同的系统回收站／垃圾篓、错误处理与恢复规则。扫描前项目必须已保存，已完成回收的报告不可复用，且项目输入发生任何修改都会使当前报告失效。

## 插件契约

Resource Cleanup 注册一条普通菜单命令，自行管理其 Avalonia 窗口、内置保护清单与本地化文本。`PluginMenuContext.ResourceCleanupHost` 提供严格受限的 `IResourceCleanupHost` 桥接，负责读写项目保留路径、支持进度与取消的扫描以及按报告 ID 回收，不暴露可变编辑器文档或任意文件删除能力。

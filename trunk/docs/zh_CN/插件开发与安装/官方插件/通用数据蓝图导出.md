# 通用数据蓝图导出

官方插件通用数据蓝图导出（源码位于 `Plugins/OfficialGeneralDataBlueprintExport`）用于为尚未建立蓝图的[通用数据成员](<../../编辑器用户指南/通用数据与文本配置.md#类型结构>)批量创建 Actor 蓝图。在项目窗口选择**插件 → 导出通用数据到蓝图…**即可打开；Game 项目默认声明了 `Enemy`、`Equip`、`Item` 与 `Player` 四种导出类型。

勾选要导出的类型，在保存目录中输入项目相对路径或点击**浏览…**选择（须位于 `Data/Blueprints` 或其子目录下）。默认目录按 `Data/Blueprints/<类型键>s` 生成，例如 `Data/Blueprints/Enemys`，可按需改为 `Data/Blueprints/Enemies`。

点击**导出**后，插件会为每个尚无对应蓝图的成员创建 `BP_<成员 ID>.json`。新蓝图继承声明的 Lua 父类，将成员 ID 写入指定字段，并将 `texturePath` 留空以便在蓝图编辑器中配置贴图；图标、本地化显示名称与其他字段仍由通用数据维护。

导出前，插件会扫描整个 `Data` 目录下的已有蓝图（包括子蓝图及项目窗口中当前的未保存编辑）。只要某份蓝图继承自声明的父类，且指定字段的生效值等于该成员 ID（例如位于其他目录、手工命名的 `Slime` 蓝图），该成员即视为已有蓝图，重复导出时会自动跳过。若目标路径无效、已被占用或与同批次其他成员重名，结果中会列出冲突，其余可导出的蓝图仍正常创建。

## 声明可导出的类型

在 `Scripts` 下的 Lua 类实现文件中添加一条独占一行的单行注释，写入 `@general-data-blueprint` 标记与 JSON 对象（以 `Scripts/Source/MapActors/Enemy.lua` 为例）：

```lua
-- @general-data-blueprint {"type":"Enemy","parent":"Source.MapActors.Enemy","memberField":"ID"}
```

- **`type`**：与通用数据类型键完全一致（区分大小写），同一项目内每种类型只能声明一次。
- **`parent`**：新蓝图继承的运行时类引用，须能解析为 `Engine.Actor` 的派生类。模块直接返回类或通过具名成员导出类的写法见 [Lua 父类引用规则](<../../Lua 与蓝图脚本/蓝图脚本/元数据结构与 Decorator.md#继承>)。
- **`memberField`**：接收成员 ID 的蓝图可编辑字段，类型须为 `string` 或该通用数据类型的成员枚举；`texturePath` 保留用于 Actor 贴图，不可用作此字段。

扫描会跳过 `Scripts/stub`、`.d.lua` 与 `_meta.lua`。未声明的类型（如 Game 项目中的 `State`）不会出现在列表中；无效或重复的声明会在窗口中显示诊断信息。

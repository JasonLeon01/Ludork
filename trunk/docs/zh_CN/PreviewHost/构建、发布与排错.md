# 构建、发布与排错

PreviewHost 属于可编辑项目。请保持其可执行文件、专用运行库与 UI 控件注册表与项目的原生控件及编辑器协议一致。

## 准备 Source 与 Standalone 项目

对于 **C++ Source** 项目，点击**编译**即可构建 Debug 游戏程序与预览运行时（不会启动玩法）；执行完整的桌面端 `tools/build_cpp` 构建同样会生成预览产物。**Standalone** 项目直接使用 `Binaries` 中随附的配套预览运行时。地图修改在每次变更后立即刷新预览，无需点击**运行**或**导出**。

Windows x64 预览支持与游戏构建相同的 MSVC、MinGW-w64 与 LLVM Clang 工具链。工具链配置以及可编辑项目与发行包随附的运行时 DLL 请参阅[构建项目](<../C++ 原生开发/构建与模块布局.md#构建项目>)。

仅构建预览宿主时，Windows 执行：

```text
tools\build_preview_host.bat Game Debug
```

macOS 执行：

```sh
sh tools/build_preview_host.sh Game Debug
```

底层工具命令为 `ludork-build preview`。执行 `ludork-build preview validate Game` 可校验项目已发布的预览产物（按需将 `Game` 替换为实际项目根目录）。

修改原生 UI 控件后，必须重新构建项目并发布更新后的注册表。控件注册流程请参阅[原生 UI Adapter](<../C++ 原生开发/原生 UI Adapter.md>)，资产与生成代码归属请参阅[声明式 UI 编写工作流](<../Lua 与蓝图脚本/声明式 UI/编写工作流.md>)。

## 构建配置

| 构建类型 | `LUDORK_BUILD_PREVIEW_HOST` | `LUDORK_BUILD_GAME_APPLICATION` | UI 校验 |
|---|---|---|---|
| 完整桌面开发 | `ON` | `ON` | 配套桌面注册表 |
| 仅预览 | `ON` | `OFF` | 由宿主发布项目注册表 |
| 仅游戏 | `OFF` | `ON` | 通过 `LUDORK_UI_REGISTRY_PATH` 提供配套桌面注册表 |

移动平台交叉构建必须显式提供桌面端生成的 UI 注册表。原生构建不生成 UI Lua View 或声明文件，需单独执行 [UI 导出流程](<../Lua 与蓝图脚本/声明式 UI/编写工作流.md>)。有关**运行**与**打包**所需的构建和导出记录，请参阅[运行、调试与打包](<../编辑器用户指南/运行、调试与打包.md>)。

## 发布文件与重建

桌面端原生构建会生成以下产物：

| 产物 | 用途 |
|---|---|
| `PreviewHost` | 负责地图、Actor、粒子、字幕与 UI 的原生预览进程 |
| `PreviewHostRuntime` | 专用预览运行库 |
| `EditorCache/Preview.json` | 描述配套二进制与注册表的清单文件 |
| `EditorCache/UiPreview.registry.json` | UI 专用控件注册表 |
| `EditorCache/Preview.building` | 重建期间暂停预览连接的临时标记文件 |

- **二进制布局与重连**：**C++ Source** 项目的预览与游戏二进制共用 `bin/<configuration>`，**Standalone** 项目则使用 `Binaries`。更新后的产物发布完成后，编辑器会自动重连。
- **构建失败与 UI 校验**：编译、链接、描述导出或发布阶段失败时，预览保持不可用状态，直至下一次成功发布清除 `EditorCache/Preview.building`。完整 UI 资产校验在发布之后执行，因此资产校验错误可使构建失败，同时保留已新发布的预览供编辑器继续修改。
- **运行时标识符**：通用预览服务使用 `PreviewRuntimeService` 与 `PreviewRuntimeSnapshot`；UI 专用组件使用 `UiPreviewClient`、`UiPreviewSession` 与 `UiPreview.registry.json`。

若 **Standalone** 项目的预览 JSON 缺失、损坏或不匹配，预览准备、**保存**、**导出**或 `ludork-build preview ensure <project-root>` 会基于当前 `Binaries/PreviewHost` 重新生成。恢复流程仅替换这两份预览 JSON，并保留其余缓存文件。

若存在有效的 `Preview.building` 标记，恢复操作会被阻止；若宿主二进制或依赖缺失，则会报告错误。**C++ Source** 项目在其所选预览元数据不可用时必须重新构建。

## 可编辑模板与游戏成品

[Source 转换为 Standalone 项目](<../编辑器用户指南/运行、调试与打包.md#将-source-转换为-standalone-项目>)会一并构建并发布配套的 Release 预览与可编辑项目。在 macOS 上，签名流程会刷新预览构建标识并在发布前验证宿主。`EditorCache` 仅写入预览元数据，不会复制源项目的导出记录。

**C++ Source** 与 **Standalone** 可编辑项目及模板均包含预览支持。最终游戏打包会使用有效的项目 UI 注册表校验资产，随后排除预览可执行文件、专用运行库（含带版本号的动态库）、清单文件、构建标记、临时帧文件以及 `Engine/PreviewHost` 源码树。游戏可执行文件与运行库从不链接 `PreviewHostRuntime`。

上述排除规则同时适用于未归档目录与 `.ldpak` 归档布局，以及各平台二进制与资源目录（含 macOS 应用包）。打包仅操作暂存副本，不会移除可编辑项目中的预览支持。有关分发、加密与签名选项，请参阅[运行、调试与打包](<../编辑器用户指南/运行、调试与打包.md#打包>)。

## 排错

| 现象 | 处理方式 |
|---|---|
| 宿主、清单或注册表缺失 | 对 **C++ Source** 项目执行**编译**。对 **Standalone** 项目重新生成预览元数据；若二进制或依赖缺失，请更新配套运行时，然后校验已发布的产物。 |
| 协议或能力不兼容 | 重新构建或更新宿主以提供[所需的预览能力](<架构与数据流.md#能力与耗时>)。地图预览不提供回退渲染器。 |
| 构建期间预览暂停 | 等待发布完成并自动重连。若构建失败，请先修复构建错误并重新构建，再重试预览。 |
| Windows 构建报告运行时文件正被占用 | 关闭构建日志列出的进程（含从外部启动的游戏或测试进程）后重新构建。Windows 可识别占用进程时，日志会列出对应进程 ID。 |
| 新增的原生控件不可用 | 一并重新构建对应的 Adapter 与注册表；仅向编辑器 Palette 添加条目不会注册原生控件。 |
| 打包拒绝 UI 资产或注册表 | 使用配套桌面构建修复报告的资产/注册表不匹配；切勿使用无关项目的注册表替代。 |
| 地图拖拽或动画延迟 | 按实际输出尺寸检查[架构与数据流](<架构与数据流.md#能力与耗时>)中的各阶段耗时。原生绘制、GPU 回读、像素复制与 UI 发布各自存在独立开销。 |

各视图的占位内容与不支持项请参阅 [UI、Actor、粒子与字幕预览](<UI、Actor、粒子与字幕预览.md>)；地图显示控制请参阅[地图与世界预览](<地图与世界预览.md>)。

# 架构与数据流

PreviewHost 使用项目的原生实现渲染编辑器内容：编辑器负责内容创作、输入与叠加层，PreviewHost 负责原生预览会话与像素传输。各视图层面的操作说明请参阅[地图与世界预览](<地图与世界预览.md>)及 [UI、Actor、粒子与字幕预览](<UI、Actor、粒子与字幕预览.md>)。

## 共用渲染器与模块边界

- **共用地图渲染器（`Engine/Source/Core/include/Graphics/MapRenderer.hpp`）**：Engine 与 `PreviewHostRuntime` 编译 Core Graphics 下的同一份渲染器实现。`Scene` 保存有序图层、图块地图区域、精灵、光源、环境光、远景与雾；`View` 与 `Options` 提供摄像机、输出尺寸、时间与显示开关。渲染器输出 `sf::RenderTexture`，不解析编辑器请求，也不向 CPU 回读像素。
- **地图与大地图图层**：普通地图包含单个区域；大地图在每个权威图层内跨区域绘制，保留摆放优先级以及跨区域光照与遮挡。`GlobalCore.GameMapRenderer` 负责适配玩法状态，并提供 Emitter、Billboard、图层特效及普通地图玩家遮挡钩子。
- **图块更新与动画**：`TileLayer::updateBlock` 重建受影响的区块与自动图块邻接区域，并使材质与遮挡缓存失效；流式加载使用 `writeBlock` 及常规构建阶段，动画则使用显式传入的帧时间。
- **宿主隔离（`Engine/PreviewHost`）**：`Engine/PreviewHost` 独立于 Core 的递归源码收集范围之外，负责请求解析、编辑器会话、IPC、BGRA 回读与临时帧传输。游戏模块从不包含该目录或链接 `PreviewHostRuntime`，`LudorkRuntime` 也保持向下依赖边界而不依赖地图玩法对象。详见[构建与模块布局](<../C++ 原生开发/构建与模块布局.md>)与[构建、发布与排错](<构建、发布与排错.md>)。

## 场景更新

- **实时内存快照**：编辑器在[预览与游戏运行的边界](<概述.md#预览与游戏运行>)内提交实时内存地图数据，涵盖未保存修改、蓝图实例覆盖、带已解析曲线的引用粒子资源以及材质文档快照。即使 Actor 没有纹理，其光源与 Emitter 效果仍可正常预览。材质节点与参数 Schema 由原生注册表提供，编辑器不另行维护着色器模型。
- **地图材质版本**：地图请求携带 `materialRevision`。首次请求、材质修改、撤销、重命名、删除及资源刷新时会附带完整 `materials` 快照，其余帧与地图切换均复用该快照及已解析资源（缺少请求版本对应快照时返回错误）。材质覆盖仅在所属预览请求内生效，不影响其他预览类型。
- **材质窗口请求（`renderMaterial`）**：每次请求均携带当前材质的 `materialRevision`。首次请求、内容或路径变更以及新连接建立时会附带该材质的 `asset` 与 `materialPath`（排除节点图布局与无关材质）；后续帧仅发送时间与预览设置。
- **材质窗口缓存**：会话缓存已解析的材质、生成的 GLSL 与编译错误，并在预览设置或源纹理变化时更新场景。重发相同版本与路径会直接返回缓存的源码与诊断信息而无需重新编译，同时在帧间检测纹理文件变化。
- **材质诊断（`diagnosticsRevision`）**：纹理或帧裁剪错误可能独立于材质编辑出现或消除。普通帧仅在诊断发生变化时携带诊断信息（空数组用于清除旧错误），快照响应则始终附带诊断信息与生成的源码。
- **诊断保留与错误恢复**：即便后续编辑导致同一响应中的预览图像过期，客户端仍保留诊断结果。编译失败的材质会显示错误画面而非沿用旧的有效渲染；修复节点图或缺失纹理后预览即恢复正常。
- **增量地图更新**：完整地图场景用于初始化会话；后续编辑仅更新场景字段、区域及带标识的精灵/光源记录，摄像机与动画帧则复用已安装场景。仅涉及 Actor 的编辑会刷新缓存的视觉记录与光照，无需重新扫描地形或重建 Tilemap；结构变更与资源刷新则在普通地图、大地图与缩略图上统一重建所需状态。

### 渲染器缓存与统计

- **静态光源缓存**：Core 渲染器在帧间复用渲染目标与光照缓存。静态光源结果按位置、颜色、半径、强度与纹理尺寸建立索引，不依赖距离排序；静态遮挡变化会使受影响的缓存条目失效，同时保留可复用的纹理存储。
- **动态占用与透光率**：动态透光率纹理与占用纹理分别按精确尺寸缓存，保持光照分辨率与采样坐标一致。静态与动态占用共享一块可复用的 CPU 像素缓冲区：尺寸未变时直接更新像素，动态遮挡则每帧重绘并上传当前像素。
- **动态池预算**：每类动态纹理池最多保留着色器光源上限数量的条目（默认配置为 64），各池在每个渲染器实例内共享 64 MiB RGBA 像素预算并按最近最少使用（LRU）策略淘汰。当前活跃光源所需纹理会保留至绘制结束；超预算请求会临时分配存储并在绘制后回收。
- **静态缓存与 CPU 缓冲**：64 MiB 动态预算不含驱动与帧缓冲开销、静态光源缓存及 CPU 缓冲区。静态光源缓存上限为着色器光源数量上限，CPU 缓冲区则保留峰值容量；在双上限范围内的稳定工作集经预热后可持续复用，超出范围时可能发生重新分配。

`MapRenderer::statistics()` 与预览响应报告以下帧级指标：

| 指标 | 含义 |
|---|---|
| `renderTextureAllocations` | 最近一帧创建的渲染目标数量。 |
| `occupancyTextureAllocations` | 最近一帧创建的静态或动态占用纹理数量。 |
| `occupancyBufferGrowths` | 最近一帧 CPU 占用缓冲区扩容次数。 |
| `staticLightRedraws` | 最近一帧执行的静态光源重绘次数。 |
| `residentRenderTextures` | 帧结束时常驻的渲染目标数量（含已缓存的光照目标）。 |
| `dynamicLightingCacheBytes` | 帧结束时动态光照池持有的估算 RGBA 像素字节数。 |

地图切换与场景关闭会保留可复用纹理、CPU 缓冲区容量、着色器与材质程序，同时使场景相关的遮挡与光照缓存失效（通过 `MapRenderer::invalidateScene()` 触发；调用 `reset()` 可释放全部渲染器资源）。资源刷新与连接关闭会释放预览资源。仅当可见材质需要反射时才会渲染表面遮罩。

渲染器仅消费纯数据形式的场景、区域、精灵、光源与视图记录，不依赖 Actor 或 Lua。视图模式、雾效与远景选项各自独立生效（见[地图与世界预览](<地图与世界预览.md>)）；运行时雾效配置与静态楼层预览 API 请参阅 [GlobalCore：地图与雾效](<../Lua 与蓝图脚本/全局与 Core 模块/Core Modules/GlobalCore/地图与雾效.md>)。

## 调度与帧所有权

- **宿主进程**：项目地图预览服务按需为地图/大地图视口及串行缩略图渲染启动独立的 PreviewHost 进程；其他预览视图可建立各自连接。在 macOS 上，宿主进程运行且不在 Dock 显示图标，并将键盘焦点保留在当前活动应用。缩略图数量不会触发额外进程创建。
- **前台请求合并**：前台同时至多运行一个请求，仅保留最新待处理状态，动画帧率上限为 30 FPS。连接空闲时，新选中地图的首帧会跳过动画间隔立即提交；若已有在途请求，则待其完成后再提交新地图。
- **隐藏视图与缩略图**：隐藏视图会停止刷新，活跃交互期间会暂停新的缩略图任务。缩略图在时间 `0` 渲染，并按场景/资源、尺寸与显示选项缓存。
- **渐进式地图帧发布**：连续编辑地图期间允许发布已完成的兼容帧，避免新的待处理修改长期阻塞画面刷新；场景标识、资源及显示选项变化会使不兼容结果失效。每张已发布位图均附带该帧的摄像机变换，交互结束后会渲染最终编辑状态。
- **材质窗口调度**：材质窗口每 100 ms 调度一次 `640 × 300` 预览，同时至多有一个在途请求；窗口隐藏、最小化或禁用时不提交帧。其 `generation` 用于标识当前材质与预览设置，从而独立于缓存的 `materialRevision` 丢弃过期图像；仅调整节点布局不会替换材质快照。
- **共享内存像素传输**：每条连接持有两块可复用的 BGRA 帧文件映射，仅在容量不足时扩容。宿主直接写入映射存储并保持像素有效直至客户端复制完全部页面（含 Actor 批量预览）；编辑器复用映射视图。关闭或重建连接会释放映射与临时文件。
- **线程归属**：UI 线程捕获独立的地图请求后，将序列化、IPC、像素读取与位图创建交由后台线程执行（后台任务从不读取可编辑场景），最后向 UI 发布不可变位图及其摄像机变换。上述职责完全属于 PreviewHost 与编辑器，不属于游戏运行时。

## 能力与耗时

编辑器在提交请求前会校验宿主协议与声明的能力：

| 预览视图 | 所需能力 |
|---|---|
| 所有预览（传输层） | `persistentFrames` |
| 地图编辑 | `map`、`mapActorChanges`、`mapEmitters`、`mapMaterialSnapshots` |
| 材质窗口 | `material`、`materialSnapshots` |

不兼容的宿主必须重新构建或更新；地图预览不提供 Avalonia 回退渲染器。排错步骤请参阅[构建、发布与排错](<构建、发布与排错.md#排错>)。

`MapPreviewLease.LastFrameTiming` 暴露从变更到发布的端到端延迟以及各阶段耗时：场景更新、序列化、原生场景应用、渲染、回读、传输、客户端像素读取与位图创建。其中可为空的 `SelectionToPublishMilliseconds` 度量从选中地图（早于文档准备）到首个兼容帧发布的耗时；被丢弃的帧不消耗该指标，后续动画帧不填写此值。

两项发布耗时均截止于编辑器发布帧的时刻，而非显示器实际呈现的时刻。将延迟归因于原生绘制前，请先在相同场景、摄像机与输出尺寸下对比各阶段耗时：一张 `3840 × 2160` 输出帧在计入传输开销前即包含超过 33 MB 的 BGRA 像素数据，与地图图块尺寸无关。

# 简易服务器：部署与编辑器设置

Ludork 服务器是带有 Lua 逻辑层的可选 Node.js 服务，通过 WebSocket 提供显式数据快照、无返回值 RPC 与在线事件。账号数据存储在纯数据 `.ldata` 分类文件中，并可通过只读管理网站查看；游戏玩法代码自行决定拉取、刷新或写入哪些数据，该服务不会自动同步多人状态，也不会替代本地存档。

请将后端与管理前端部署在服务器或独立测试实例上；游戏客户端仅需服务器 URL 与项目密钥，无需在本机安装 Node.js。配置客户端集成需要 **C++ Source** 项目。转换后的 **Standalone** 项目可使用已编译进运行时的服务器配置，但会隐藏两处服务器配置菜单。

## 获取服务器包

打开 [Ludork Releases](https://github.com/JasonLeon01/Ludork/releases)，在对应版本的 **Assets** 中下载 `LudorkServer-<版本号>.tar.gz`。其版本号与同一 Release 中的编辑器包一致（例如 `1.0.0` 版本编辑器对应 `LudorkServer-1.0.0.tar.gz`）。临时 CI 产物命名为 `LudorkServer-<40位Server提交SHA>.tar.gz`。

服务器独立分发：开发版与正式版编辑器安装包均不含 Server 目录或归档，需单独下载并解压至专用部署目录。安装或运行编辑器不会启动服务器。

归档内的 `LudorkServer/` 目录包含编译后的后端 JavaScript、生产版管理网站、Lua 模块与声明、部署与启动脚本以及锁定的生产依赖清单，不含已安装的 `node_modules`、项目凭据或用户数据。在 Linux 上解压并进入目录：

```sh
tar -xzf LudorkServer-1.0.0.tar.gz
cd LudorkServer
```

如需自行从 `Server` 分支构建，请安装 Node.js 24，在该源码签出目录运行 `npm ci` 与 `npm run build`，再将 `dist/LudorkServer` 复制到独立的部署目录。构建流程会编译后端并使用 Vite 打包管理网站。源码开发说明详见 [Server README](https://github.com/JasonLeon01/Ludork/blob/Server/README.md)。

> **重要**：部署脚本与启动脚本在源码签出目录中会拒绝运行，且重新构建会拒绝覆盖包含 `config/`、`data/`、`projects/` 或 `logs/` 的输出目录。请始终将部署实例置于 `dist/LudorkServer` 之外。

## 部署与启动

在服务器安装 **Node.js 24 及 npm** 后，在解压目录中执行：

```sh
sh deploy.sh MyGame 'project-key' 'management-password'
sh start.sh
```

Windows 命令提示符下使用对应的批处理脚本：

```bat
deploy.bat MyGame "project-key" "management-password"
start.bat
```

三个参数依次为项目名、项目密钥与管理密码。请按当前 Shell 的语法正确加引号与转义，尤其注意 `$`、`%`、`!`、`&` 与引号。命令行参数可能留存于 Shell 历史记录或进程列表中，切勿将真实凭据写入纳入版本控制的脚本。

- **依赖与运行时**：部署脚本运行 `npm ci --omit=dev` 安装锁定的生产依赖、保存凭据哈希并创建项目 Lua 入口，不会重新编译后端或构建网站。锁定的 Wasmoon 依赖内置基于 WebAssembly 的 Lua 5.4.5，因此无需安装系统 Lua 或原生编译器。
- **端口与生命周期**：Node.js 在端口 `6666` 运行编译后的后端，并在端口 `3333` 托管生产管理网站。启动脚本会同时拉起两个服务：任一端口被占用即启动失败，任一子进程异常退出时会停止另一个服务；按 `Ctrl+C` 可同时停止两者。部署不会安装系统服务，也不会配置开机自启。

| 用途 | 地址 |
|---|---|
| 管理网站 | `http://IP:3333/MyGame/` |
| 游戏客户端 URL | `http://IP:6666/MyGame` |
| 派生的 WebSocket 端点 | `ws://IP:6666/MyGame/api/v1/net` |

同一服务器实例中的所有项目共用端口 **3333** 与 **6666**，但各自拥有独立的密钥、密码、数据、Lua 进程与管理会话。使用新的项目名再次执行部署可添加项目；使用已有项目名重新部署则会轮换凭据，同时保留原有数据、Lua 源码与项目设置。

请按顺序执行部署，重新安装依赖前先停止实例，完成后重启以加载新的配置或 Lua 源码变更。

IP 地址、`localhost` 及其子域名均可直接访问，[已绑定的项目域名](#绑定项目域名)同样自动生效。如需通过其他域名访问管理网站，请在启动前设置 `LUDORK_ALLOWED_HOSTS=games.example.com`（多个允许的主机名以逗号分隔，精确匹配且不含协议与端口）。DNS 与防火墙规则需另行配置。

| 字段 | 约束 |
|---|---|
| 项目名 | 1–64 个 UTF-8 字节；不含控制字符、`/`、`\`，且不能恰好为 `.` 或 `..`。在 URL 中编码为单个路径段，支持中文项目名。 |
| 项目密钥 | 1–4096 个不含空格的可见 ASCII 字符；无默认值。 |
| 管理密码 | 1–4096 个不含控制字符的 UTF-8 字节；无默认值。 |

## 项目 Lua 入口

部署会自动创建 `projects/<项目名十六进制>/Main.lua`（默认注册 `Modules.Storage`）。目录名为项目名 UTF-8 字节的小写十六进制编码（部署时会打印完整路径）。请将项目自有的 Lua 模块放入该目录：服务器从 `lua/` 加载框架模块、从此私有目录加载项目模块，且从不向游戏客户端下发项目源码或通过管理网站对外提供。

`config/projects.json` 中的每个项目对象可设置 `luaEntry`（默认为 `Main.lua`），指定该项目目录内使用 `/` 分隔的相对 `.lua` 路径。绝对路径、空路径段、`.` 或 `..`、反斜杠、冒号、控制字符以及超过 512 个 UTF-8 字节的路径均会被拒绝。重新部署会保留 `luaEntry` 及现有入口文件。修改源码或 `luaEntry` 后须重启服务器。

服务端 Lua 运行标准 Lua 5.4，不含客户端的 Standard、`Engine` 或 `GlobalCore` 模块。公开声明位于 `lua/stub` 并配有服务端专用 `.emmyrc.json`；声明文件与 `stub` 目录在运行时会被排除。模块注册、context 服务与执行限制详见[服务端 Lua 模块](<HTTP 协议.md#服务端-lua-模块>)。

## 配置写入间隔

每个项目在 `config/projects.json` 中均包含 `ipWriteIntervalSeconds` 字段（示例项目位于 `projects["MyGame"]` 下）。新部署默认将其设为 **180 秒**，省略该字段时同样采用 180 秒。修改时请在现有项目对象内调整该字段，保留凭据哈希及其他项目配置：

```json
{"ipWriteIntervalSeconds":180}
```

上述示例仅为项目对象片段，而非完整配置文件。设为 `0` 可禁用写入间隔，或设为不超过 `9007199254740991` 的非负整数以自定义时长；小数、字符串、`null` 与负数均会被拒绝。重新部署项目会保留已有的间隔与数据。**编辑配置后必须重启服务器**，运行中的进程不会自动重载。

该间隔仅作用于随附的 `Storage.WriteField` RPC，并在同一 TCP 客户端 IP 向同一项目发起写入时共享（位于同一 NAT 或反向代理后的用户共享同一额度）。自定义 RPC 需自行实现业务规则，不会继承该限制；不同项目之间的额度相互独立。

有关准入、失败与重启行为请参阅[写入限频](<HTTP 协议.md#写入限频>)，不确定结果的处理请参阅 [RPC 生命周期](<原生客户端 API.md#调用-rpc-与接收事件>)。

## 绑定项目域名

在 `config/projects.json` 的项目对象中配置 `hosts` 数组，可让 `mygame.example.com` 等域名直接映射至对应项目，无需在 URL 中携带项目路径段：

```json
{"hosts":["mygame.example.com"]}
```

该示例与 `ipWriteIntervalSeconds` 一样为项目对象片段。每项必须是精确的小写主机名，不含协议与端口，且同一主机名只能绑定至一个项目；无效或重复条目会导致服务器无法启动。省略 `hosts` 表示不绑定域名。重新部署会保留已有列表。**编辑后必须重启服务器。**

当请求的 `Host` 头匹配已绑定主机名时，后端会将 `/api/v1/...`（含 WebSocket 端点）路由为该项目的 `/<项目名>/api/v1/...`，使游戏客户端可直接使用 `http://mygame.example.com:6666`。带显式项目路径的地址在所有主机名下依然有效，而未绑定主机名不会在 `/api/v1` 下暴露任何项目。

管理网站接受已绑定的主机名，入口路径仍为 `http://mygame.example.com:3333/MyGame/`。域名的 DNS 解析记录需自行配置至服务器，域名绑定不会更改服务端口。

## 配置开发环境客户端

在 **C++ Source** 项目中打开**游戏 → 测试服务器设置**，启用 Ludork 服务器并填写测试 URL 与密钥。默认 URL 为 `http://localhost:6666/<项目目录名>`（目录名经 URL 编码）。点击**确认**保存更改，点击**取消**则放弃更改。该对话框仅配置客户端；测试服务器仍需自行部署并启动。

本机配置保存在 Windows 与 macOS 的 `~/Ludork/.localserver/<项目目录名>/test.json`（从源码仓库运行时路径相同，其中 `~` 为当前用户主目录）：

```json
{
  "enabled": true,
  "url": "http://localhost:6666/MyGame",
  "key": "test-project-key"
}
```

这些本机配置（含明文测试密钥）已被 Git 忽略，不会写入 `Main.proj` 或 Lua 脚本。同名目录的项目共用同一本机配置文件；文件缺失或 `"enabled": false` 时禁用集成。

**编译**构建 Debug 版本，**运行**启动该 Debug 版本。有效配置发生变化后需重新编译原生代码，可再次点击**编译**或选择**编译后运行**。Debug 构建通过 `LUDORK_SERVER_CONFIG_FILE` 读取本机配置文件。

## 配置发行客户端

在**文件 → 打包项目**中勾选**启用 Ludork 服务器**，填写生产 URL 与密钥。每次新打开打包窗口时该选项默认关闭且输入框为空，生产配置不会被缓存，也不会从测试配置复制。

URL 格式为 `http://主机:6666/项目名`（主机名已[绑定到该项目](#绑定项目域名)时可写为 `http://主机:6666`），不得包含 `/api/v1`、凭据、查询参数或片段。原生客户端使用 HTTP/WS；WebGL 目标额外支持 HTTPS 并自动派生 WSS 地址。

HTTPS 游戏页面必须连接 HTTPS/WSS 服务器端点；客户端在发送请求前即会拒绝 HTTP/WS（含 `localhost`）。请在 HTTP 服务器前部署反向代理以终结 TLS，并同时转发项目路由与 WebSocket 升级请求。

浏览器健康检测属于无凭据的公开请求，允许跨域访问；管理 API 仅限同源管理网站访问。原生与浏览器客户端均遵循 [WebSocket 消息](<HTTP 协议.md#websocket-消息>)的首帧认证流程，请保持客户端与服务端协议版本一致。

[Standalone 项目转换](<../编辑器用户指南/运行、调试与打包.md#将-source-转换为-standalone-项目>)提供相同的可选 Release 配置。生成的可编辑项目会使用该编译内嵌的连接配置，如需更改必须基于 **C++ Source** 重新构建。

打包流程始终构建 **Release**（包括标记为 dev 的内部测试包），且忽略 `LUDORK_SERVER_CONFIG_FILE`。通过命令行或 CI 打包时，请在进程环境中提供 `LUDORK_SERVER_ENABLED=1`、`LUDORK_SERVER_URL` 与 `LUDORK_SERVER_KEY`；省略 `LUDORK_SERVER_ENABLED` 或设为 `0` 即可禁用集成。生产配置应从密钥管理服务读取，切勿将字面量写入版本控制命令中。

例如，在 Windows 的 GitHub Actions 打包步骤中使用仓库 Secret 传入环境变量（切勿打印 Secret 值）：

```yaml
- name: Package game
  shell: cmd
  env:
    LUDORK_SERVER_ENABLED: '1'
    LUDORK_SERVER_URL: ${{ secrets.LUDORK_SERVER_URL }}
    LUDORK_SERVER_KEY: ${{ secrets.LUDORK_SERVER_KEY }}
  run: tools\pack_project.bat --release Game
```

启用集成的构建会定义 `LUDORK_SERVER_AVAILABLE`，并将传输代码、URL 与密钥编译进二进制文件。禁用集成时，所有服务器调用仅输出诊断日志并立即返回；返回值与禁用状态下仍可用的本地操作详见[禁用服务器集成](<原生客户端 API.md#禁用服务器集成>)。

## 管理与运行边界

打开管理网站后，需同时输入项目密钥与管理密码登录。页面支持账号筛选、分类选择、带类型的 Lua 值查看（含精确整数与转义字节字符串）、刷新与退出登录。Cookie 作用域与会话有效期详见[只读管理](<HTTP 协议.md#http-健康检测与只读管理>)。

运行生成的 `config/`、私有 `projects/` Lua 源码、用户 `data/`、日志与已安装依赖均不包含在分发的服务器包中。请自行做好 `config/`、`projects/` 与 `data/` 的备份并限制本机访问权限。

后端会持有数据目录实例锁。已退出进程残留的旧锁会自动恢复；若遇到不完整的锁文件或 PID 被复用，请先确认无正在运行的实例，再手动删除 `data/.server.lock`。

> **警告**：HTTP 与 WebSocket 以明文传输凭据与数据，且分发二进制中内嵌的密钥可能被提取。共享项目密钥拥有访问该项目全部已注册模块的权限；账号 ID 仅作为存储命名空间，而非经过认证的用户。请在项目 Lua 中自行实施账号授权与业务规则，并通过反向代理或可信网络在外部配置 TLS 与网络访问控制。

继续阅读[原生客户端 API](<原生客户端 API.md>)与[服务端 Lua 与协议](<HTTP 协议.md>)。

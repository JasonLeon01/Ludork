# C++ 绑定故障排除

诊断并解决常见的 Core bindgen、编译与 Lua 运行时路径错误。排查时应优先查看第一条 Bindgen 或编译器诊断信息，按“声明 → 生成 → 运行时路径”的顺序逐层修复，并在每次修正后重新构建，再处理后续症状。

## 声明没有生成

确认 `BIND_*` 标记位于模块会解析的 `public` 声明上，该头文件已包含在所属模块的 CMake 绑定输入集合中，且注解语法符合[宏参考](<宏参考.md>)。

## C++ 编译成功但 Lua 找不到成员

检查生成的注册单元、[模块加载顺序](<构建与模块布局.md#加载运行时模块>)与规范 Lua 路径：类和未分组自由函数注册在模块根，分组函数注册在对应的[函数组](<函数、事件与执行.md#指定函数组>)下。

## LuaLS 可见但蓝图不可见

检查该方法是否有意标记了 `metadata = false`（常见于内部辅助函数与次要 Adapter 重载）。除此之外，生成的根 `*_meta.lua` 会收录每一个逻辑公开的 `BIND_METHOD`。如缺失，请查阅 Bindgen 诊断输出，切勿手写重复声明。

## Bindgen 报告元数据方法重名

在元数据中仅保留主要面向蓝图的重载，将其余次要转换或 Adapter 重载标记为 `metadata = false`。不要在生成器中为单个重载添加特判分支，也不要让一条声明静默覆盖另一条声明。

## 类型转换失败

请使用受支持的基础类型、STL 类型、SFML 类型以及已声明的 Core 类型，并确保跨模块类型带有完整声明。如需新增可复用类型转换，请通过通用 Adapter 或转换特征实现——切勿在 Bindgen 内针对特定玩法类或成员名称编写分支。

## 元数据默认值错误

请将 `meta(...)` 写在对应属性或方法自身的绑定注解内，并提供注解原生支持的 `default`（见[宏参考](<宏参考.md>)与[生成元数据与 Stub](<生成元数据与 Stub.md>)），随后重新构建以重新生成输出。

在方法或自由函数顶层直接填写 `default`、`success` 或 `fail` 会导致校验失败，必须改用 `outpins(...)`。关于 `outpins(...)` 与 `defaults` 的区别以及小写关键字规则，请参阅[函数、事件与执行](<函数、事件与执行.md>)与[宏参考](<宏参考.md>)。

# 运行时值边界

根据接口可接受的值范围、所需的所有权语义以及是否跨越 Lua VM 边界，合理选择原生 C++ API 类型。

## 类型选择

| 需求 | 类型 |
|---|---|
| 字段固定或取值限于一组具名选项 | 结构体、枚举或具体的 C++/SFML 类型 |
| 值仅限有限几种类型之一 | `std::variant<T...>` |
| 值可能缺失 | `std::optional<T>`；当 `nil` 作为 `std::variant` 分支时使用 `std::monostate` |
| 不依赖 VM 的递归 JSON 兼容数据 | `RuntimeData` |
| 持有已知原生对象的所有权 | 按需选择共享或弱所有权的类型化指针 |
| 开放脚本值（含原生对象与引用） | `RuntimeValue` |
| 保留 Lua 身份用于相等比较、订阅或后续调用 | 绑定至单个会话的 `RuntimeHandle` 或 `RuntimeIdentityPtr` |

事件载荷、蓝图引脚与共享玩法上下文等开放脚本边界应使用 `RuntimeValue`。进入具有固定契约的算法前须先转换为具体类型，并保持“值缺失”与零值、空容器之间的严格区分。

## 原生编译契约

- **已编译类型 Schema**：`<Runtime/TypeSchema.hpp>` 定义了递归原生类型描述。`TypedDataService::compileType` 负责解析脚本描述，`resolveTypedDataValue` 与 `resolveRuntimeTypedValue` 的类型化重载可直接复用已编译 Schema。编译后的 `NodeDefinition` 保存有序参数描述，供 `DataNode`、模板与实例共享，并在各参数首次需要校验时按需编译其 Schema。接受可变类型表的公开入口则在每次调用时解析传入描述。
- **蓝图与 Actor 记录**：蓝图事件描述符、生成类初始化计划与组件字段映射均采用原生记录，原生图服务传递 `std::shared_ptr<Graph>`。固定 Actor 事件在分发前保持类型化参数直至需要脚本值，而开放图引脚、默认值、多返回值、共享局部上下文与用户字段仍保持动态值语义。复制原生组件时会先按声明类型重建记录值再执行校验；调用方对组件字段的写入会受到严格校验。
- **数值契约**：`RuntimeNumber` 定义为 `std::variant<std::int64_t, double>`，`GameplayNumber` 同样基于该类型。`AttributeSet` 数值访问在 Lua 字段边界完成转换，`AbilitySystem` 快照与通知则在内部保持 `RuntimeNumber`。`Current` 值存储在 Lua 字段中，涵盖直接写入与监听器通知。
- **缓存所有权与 `ClassDict`**：组件与事件描述符缓存使用 Lua 弱键索引。私有 userdata 持有原生记录，关联的 Lua 值存放在 userdata 的 uservalue 中，使 GC 与热重载能够正确追踪（C++ 弱指针不等同于 Lua 弱引用）。会话级类记录保留显式引用并在关闭时释放。`ClassDict:getData` 返回原始共享定义表；修改该表不会改变已编译的默认值或图模板。

## Lua 值转换

- **联合类型与基础类型**：Lua 直接调用时，`std::variant` 分支以实际值传入，无需任何包装。Lua 整数优先匹配整数分支，浮点数优先匹配浮点分支，小数绝不会被截断为整数。字符串与布尔值必须匹配其精确 Lua 类型；即使数值结构相同，不同原生 SFML 类型之间仍保持独立。
- **枚举 Schema**：`{ enum = "Enums.Engine.Direction" }` 等枚举 Schema 会解析常量模块并按底层标量类型校验取值。调用与保存值均直接携带标量；只要标量类型匹配，未列在具名选项中的取值同样有效。字典可选的枚举 `key` 必须显式声明 `valueType = "string"`，运行时仍以字符串为键。联合类型存储常规分支包装，但运行时仅传递还原后的值。详见[枚举 Schema](<../Lua 与蓝图脚本/蓝图脚本/元数据结构与 Decorator.md#枚举-schema>)。
- **纯数据转换**：适用于 `RuntimeData` 与 `BIND_CLASS(pure_data = true)`，接受 `nil`、已注册的 JSON null 哨兵值、布尔值、有限数值、字符串、无环数组与字符串键映射；拒绝函数、原生对象、循环引用、非法键与未识别元表。
- **数组与映射**：空的 Lua 表 `{}` 按映射转换，而 `{ n = 0 }` 按空数组转换。非负整数 `n` 用于保留数组长度与 `nil` 空洞，输出的数组同样携带 `n`。已注册的 JSON 数组元表会被正常识别；映射中的 null 项使用已注册的 JSON null 哨兵值，从而保留其键。

## 原生对象包装

返回共享原生对象时，系统会优先复用其已有的 Lua 宿主包装。若原包装已被垃圾回收，实现了[原生转换协议](<宏参考.md#原生转换声明>)的来源会通过 `ludorkDynamicTypeKey()` 查找已注册的 writer。writer 接收来源的静态类型键与指向子对象的别名 `std::shared_ptr`；生成的转换基类可支持静态检查的指针还原（含非零多重继承偏移），同时保留原始控制块。

- **回退行为**：若缺失 writer 或来源类型不受支持，系统会回退为常规静态类型包装，包括既无转换协议也无现存 Lua 宿主的外部基类（如 `sf::Drawable`）。非多态值类型直接使用其声明的静态类型，不注册动态 writer。
- **对象身份与清理**：包装器会登记公开类型及所有转换基类的子对象地址，确保重复返回时保持 Lua 对象身份一致。Lua 回调 Adapter 通过转换协议释放捕获的引用。不透明 Lua 引用保留原始值，并遵循 [Lua 引用与会话生命周期](#lua-引用与会话生命周期)。

## 容器与视图

- **持有型容器**：`RuntimeData` 持有独立于 VM 的数据，副本在修改时执行写时分离。未绑定的 C++ 方法 `RuntimeData::equals` 按精确值类型递归比较：数组按顺序逐项比对，映射按键值比对而与 JSON 对象迭代顺序无关。`RuntimeValue` 既可在无 VM 状态下持有原生对象，也可持有绑定至会话的 Lua 句柄；其 `Array` 为 `std::vector<RuntimeValue>`，`Map` 为 `std::unordered_map<std::string, RuntimeValue>`。从 `RuntimeData` 构造会共享其底层容器，而 `Array` 与 `Map` 构造函数会接管所有权。
- **借用视图**：通过 `value.view().array()` 或 `.map()` 读取容器，返回可选的借用视图。数组索引与遍历返回 `RuntimeValueView`，`Map::find` 可区分键不存在与键对应值为 `nil`。在使用任何视图或借用字符串期间，所属源对象必须保持存活且不被修改。无法从临时持有型值获取视图；需要独立所有权时，请调用 `toValue()`、`toArray()` 或 `toMap()`。
- **修改与纯数据转换**：`getMutableIf<Array/Map>()` 会物化或分离待修改的容器。`toData()` 会直接共享已有的 `RuntimeData` 分支或递归转换桥接容器，遇到原生对象与句柄时拒绝转换。

## Lua 引用与会话生命周期

常规参数与返回值传递直接保留 `RuntimeValue`。如需执行显式转换或 Lua 引用操作，请包含 `<Runtime/RuntimeReference.hpp>`：

| 操作 | 行为 |
|---|---|
| `intern` | 获取 `get`、`set` 与 `invoke` 所需的句柄；复用已有句柄，或将持有型容器转换为新的 Lua 表 |
| `retain` | 保留标量与已有的非标量句柄；将持有型容器转换为新的 Lua 表 |
| `snapshot` | 复制普通的无环数组或字符串键映射并保留嵌套函数与对象引用；其他表与 `opaque_identity` 绑定保持原身份 |
| `data` | 转换为纯数据，拒绝原生对象与不可转换的引用 |

`snapshot` 通过 `n` 保留数组长度，忽略映射中值为 `nil` 的字段，且独立于类与实例的默认值克隆流程。

Lua 调用会完整保留全部返回值（包括中间及末尾的 `nil`）并将错误传播给调用方。句柄不可跨 Lua VM 使用，所属会话关闭后即失效。空的句柄或身份指针在 `RuntimeValue` 中包装为 `nil`。

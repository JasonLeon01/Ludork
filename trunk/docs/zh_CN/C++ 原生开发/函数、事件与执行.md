# 函数、事件与执行

在绑定类或公开自由函数头文件内，可通过同一份声明统一暴露 C++ 类方法、分组自由函数、事件与蓝图执行协议。

## 绑定方法与自由函数

`BIND_METHOD` 将类方法暴露给原生 Lua 与 LuaLS，逻辑上公开的方法默认纳入蓝图元数据。`BIND_FUNCTION` 按既定的元数据筛选规则暴露自由函数。仅当蓝图节点确实没有执行输入与执行输出引脚时才声明 `Pure = true`；非 `void` 返回值并不等同于纯函数。

```cpp
BIND_FUNCTION(name = "clampValue", Pure = true)
float clampValue(float value, float minimum, float maximum);
```

- **模块根路径与分组路径**：未分组的自由函数仅暴露在模块根（例如 `Engine.clampValue`），其 `name` 规则见[声明类](<绑定类.md#声明类>)。当某张分组表是函数的规范归属位置时，请使用 `BIND_FUNCTION_GROUP`。
- **返回引脚与 `self` 接收者**：非 `void` 函数生成名为 `return` 的单个元数据输出引脚，`void` 函数生成空返回值表。普通实例方法会获得一个始终可见、带类型的首个 `self` 输入参数，默认指向图所有者；静态方法、自由函数与注册事件入口不添加此参数。参数与默认值对齐规则见[默认值与类型](<生成元数据与 Stub.md#默认值与类型>)。

## 仅覆盖元数据签名

`metadata_parameters` 将业务参数名映射到蓝图 Schema，`metadata_returns` 将返回引脚名映射到蓝图 Schema（单个常规结果的引脚名为 `return`）。两者均不修改 C++ 签名、LuaLS 声明或元数据可见性。

```cpp
BIND_METHOD(
    Pure = true,
    metadata_parameters = {direction = {enum = "Enums.Engine.Direction"}},
    metadata_returns = {return = {enum = "Enums.Engine.Direction"}})
int oppositeDirection(int direction) const;
```

此处采用注解花括号语法（包括上例中不加引号的 `return` 标识符），Bindgen 在输出 Lua 代码时会自动生成带引号的键名。引用不存在的引脚名会导致生成失败。由于实例 `self` 单独生成，覆盖项直接填写业务参数名，无需计算接收者偏移。

属性覆盖请使用 `metadata_type`。递归枚举 Schema 与容器、联合类型的组合方式详见[枚举 Schema](<../Lua 与蓝图脚本/蓝图脚本/元数据结构与 Decorator.md#枚举-schema>)。

## 指定函数组

在仅包含自由函数的头文件顶部声明 `BIND_FUNCTION_GROUP`：

```cpp
BIND_FUNCTION_GROUP(name = "Manager")

BIND_FUNCTION(name = "playSE")
void playSE(const std::string &path);
```

该头文件中的所有绑定函数在原生 Lua、LuaLS Stub 与蓝图元数据中都仅注册在所声明的分组表下。未分组的函数仍保留在模块根。

## 声明执行行为

非纯方法默认采用常规单执行流，无需添加执行注解：

```cpp
BIND_METHOD()
void refresh();
```

### 分支执行（`outpins`）

当调用结果需要选择某个具名执行分支时，在内联 `outpins(...)` 块中列出各分支；Bindgen 会保留声明顺序：

```cpp
BIND_METHOD(outpins(default = nil))
void setCollisionEnabled(bool enabled);

BIND_METHOD(outpins(success = true, fail = false))
bool tryMove();
```

### Latent 操作（`latent`）

对于 Latent 异步工作，在 `latent(...)` 中声明恢复状态，并返回来自 `<Runtime/Async/AsyncOperation.hpp>` 的 `std::shared_ptr<AsyncOperation>`：

```cpp
BIND_METHOD(nonnull_return = true, latent(TimeUp = true),
            defaults = {nil, nil, {}, false},
            parameter_types = {float, function, any[], bool})
std::shared_ptr<AsyncOperation> addTimer(
    float interval,
    RuntimeIdentityPtr task = {},
    RuntimeValue::Array params = {},
    bool blocking = false);
```

原生 Latent 操作通过 `AsyncOperation::create(poll?)` 创建，通过 `emit` 发布中间状态，并通过 `complete` 或 `cancel` 结束。

### 执行选项规则

- **`defaults` 与 `outpins`**：`defaults` 用于指定参数默认值（同样适用于构造函数与自由函数），与 `outpins(default = nil)` 无关。小写关键字与花括号选项列表规则见[宏参考](<宏参考.md>)。
- **互斥约束**：`Pure = true` 不能与任何执行协议共存。基于 Getter 的属性也不能声明执行协议，其顶层单数 `default` 仅用于设置属性默认值。
- **循环与事件**：内联 `loop_node(ForEach)` 用于声明循环节点；独立的 `BIND_REGISTER_EVENT()` 用于注册事件入口（未指定显式输出的事件默认获得分支值 `nil`）。
- **仅限内联元数据**：显示信息、编辑器选项与执行选项均须写在 `BIND_METHOD(...)` 或对应的函数／属性注解内部，不支持另写独立的元数据、纯函数、分支或 Latent 标记。
- **非空共享指针**：`nonnull_return = true` 声明方法或自由函数返回非空的 `std::shared_ptr`。Bindgen 会从其 LuaLS 声明中移除最外层的 `nil` 分支，且若原生代码实际返回空指针则抛出绑定错误；该选项不改变 C++ 类型或蓝图执行引脚。

> **重要**：注解仅描述执行协议，不会自动实现运行时行为。C++ 实现与运行时调度器必须实际触发每一个已声明的分支、Latent 状态或循环转换。

## 声明严格回调

如需强制约束回调的返回值数量，请使用 `<Runtime/StrictFunction.hpp>` 中的 `ludork::runtime::StrictFunction<Return(Arguments...)>`：非 `void` 签名要求 Lua 恰好返回一个值，`void` 签名要求不返回任何值。返回值会按声明类型执行转换与校验。

```cpp
using Number = std::variant<std::int64_t, double>;
using Constraint = ludork::runtime::StrictFunction<Number(Number)>;

BIND_METHOD()
void setConstraint(Constraint constraint);
```

当回调嵌套在 `std::variant` 或容器内时同样生效。`nil` 表示空回调。由 Lua 持有的回调会保留函数身份并绑定至原会话，Lua 错误与转换失败均会传播给调用方。引用规则详见 [Lua 引用与会话生命周期](<运行时值边界.md#lua-引用与会话生命周期>)。

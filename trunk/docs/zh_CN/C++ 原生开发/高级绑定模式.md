# 高级绑定模式

本页介绍事件、初始化注入和值类型转换等高级绑定方式。

## 类元数据装饰器

类元数据装饰器写在所属类的注解中：

```cpp
BIND_CLASS(callbacks = true,
           invalid_vars(defaultRect, internalState),
           rect_range_vars(defaultRect = texturePath))
class Character : public Actor {
public:
  BIND_METHOD(metadata = false)
  virtual void _applyDirection(float x, float y);
};
```

`invalid_vars(...)` 隐藏字段，`rect_range_vars(...)` 把矩形关联到资源字段或范围字段。两者都只接受有序标识符，并且只能写在 `BIND_CLASS` 内。属性自己的矩形语义仍在 `BIND_PROPERTY` 中写作 `meta(RectRangeVars = "texturePath")`。`metadata = false` 不会禁用 callback，需要禁用时应改用 `callback = false`。见[绑定类](<绑定类.md>)。

成员装饰器与结构化花括号值的写法见[声明属性](<绑定类.md#声明属性>)。

## 事件、异步操作与循环

```cpp
BIND_REGISTER_EVENT()
BIND_METHOD()
virtual void onCreate();

BIND_METHOD(loop_node(ForEach))
void forEach(const RuntimeValue::Array &values);
```

事件与循环注解生成执行元数据，C++ 或 Lua 代码仍须实现对应协议。异步操作及其返回值、默认值规则见[声明执行行为](<函数、事件与执行.md#声明执行行为>)。

## 值、反向查找与辅助函数

```cpp
BIND_MODULE_PROPERTY()
extern std::string LANGUAGE;

class FocusTransition {
public:
  BIND_CLASS_PROPERTY(readonly = true)
  static const std::string DIRECTIONAL;
};

BIND_LUA_REVERSE(path = "Input.KeyName", source = "sf.Keyboard.Key")
BIND_LUA_HELPER(kind = "cast", path = "Cast")
```

模块属性公开在模块根，类属性公开在所属类上。已有的 Lua 值不会被 bindgen 重复挂到另一条运行时路径。反向绑定声明会在指定的规范路径上创建名称查找表。辅助函数使用通用原生实现。`eval` 只对调用方传入的表达式求值；可选的局部变量优先于运行时全局变量。表达式缺失或为空时返回 `nil`。非空表达式的求值是同步的，在可挂起的协程中调用会直接报错。

## 初始化、注入与值类型特征

```cpp
BIND_MODULE_INIT()
void initialiseRuntimeServices(lua_State *state);

BIND_INJECT(global = "_LUDORK_BLUEPRINT_EVENT_VALIDATOR")
void setBlueprintEventValidator(BlueprintEventValidator validator);

BIND_CLASS(opaque_identity = true)
class RuntimeIdentity {};

BIND_CLASS(dynamic_value = true)
class RuntimeValue {};
```

`BIND_MODULE_INIT` 在打开模块期间运行。`BIND_INJECT` 用 `global` 指定 Lua 来源回调，并连接到 C++ 设置函数，只在对应 Lua 状态仍然有效时可用。启用 `variadic = true` 时，setter 必须接收 `std::function<std::vector<T>(Fixed..., const std::vector<T>&)>`。零返回值与中间、末尾的 `nil` 依然彼此可辨，无需封装 table。上面两个 `BIND_CLASS` 标志选择转换特征与身份特征，不能与不兼容的 表值转换模式组合。引擎子系统使用带类型的运行时接口与固定的回调注册位置，而不是通用的字符串操作分发器。

## 限制

Bindgen 必须保持声明驱动。不得为某个玩法模块、类或成员名专门增设生成器分支，也不得用基础设施标记绕过不受支持的转换。

# 宏参考

本页汇总原生 C++ 模块中使用的 `BIND_*` 与 `LUDORK_CAST_*` 声明标记。具体选项语法与使用流程请参阅下文链接的对应专页。

## 绑定宏

| 宏 | 用途 |
|---|---|
| `BIND_CLASS` | 声明绑定类及其唯一模块根名称；`callbacks = true` 选取当前类已绑定的非静态虚方法以供 C++ 向 Lua 分派 |
| `BIND_ENUM` | 将 C++ 作用域枚举暴露为单个模块根 Lua 表与 LuaLS 类型 |
| `BIND_FUNCTION` | 绑定自由函数；`outpins(...)` 与 `latent(...)` 为内联选项 |
| `BIND_FUNCTION_GROUP` | 将同一头文件内所有已绑定的自由函数归入单张分组表 |
| `BIND_METHOD` | 绑定类方法或基于 Getter 的属性；除非标记 `metadata = false`，否则方法默认进入元数据；`callback = false` 将虚方法排除出当前类的自动回调选择 |
| `BIND_PROPERTY` | 绑定实例数据属性 |
| `BIND_INIT` | 绑定构造函数 |
| `BIND_REGISTER_EVENT` | 注册蓝图事件入口 |
| `BIND_INJECT` | 在受支持的位置注入由声明驱动的绑定代码 |
| `BIND_MODULE_PROPERTY` | 暴露模块级属性 |
| `BIND_CLASS_PROPERTY` | 暴露类级属性；`readonly = true` 禁止 Lua 写入，`type` 指定生成的 Lua 声明类型而不改变 C++ 存储或运行时绑定 |
| `BIND_LUA_REVERSE` | 描述反向 Lua/C++ 查找适配 |
| `BIND_LUA_HELPER` | 声明可复用的 Lua 绑定辅助函数 |
| `BIND_MODULE_INIT` | 注册模块初始化逻辑 |

无需暴露的声明保持不标注即可。`invalid_vars(...)`、`rect_range_vars(...)` 等类装饰器写在 `BIND_CLASS` 内；循环协议使用内联 `loop_node(...)`，而 `BIND_REGISTER_EVENT()` 为独立声明。

## 注解语法与专题链接

可变参数 `BIND_*` 标记在 C++ 编译期展开为空，由 Bindgen 直接解析原始词法单元：

- **原始词法与字面量**：不要为了迁就 C++ 解析器而给 `outpins(...)`、`latent(...)`、`nil` 或 `function` 等关键字加引号。`nil`、`true` 与 `false` 一律写作小写。
- **列表与嵌套数据**：`defaults` 与 `parameter_types` 使用花括号列表；结构化 `meta(...)` 值与属性 `default` 值使用可嵌套的花括号语法，而不是带引号的 JSON 字符串。
- **字符串默认值与字面量类型**：标量字符串默认值必须加引号（包括 `default = "None"`）以保留原始字符串值。类属性可通过 `BIND_CLASS_PROPERTY(readonly = true, type = "'Add'")` 声明精确的 Lua 字符串字面量类型，同时在 C++ 端继续使用 `std::string`。

## 原生转换声明

在类的 `public` 区域中，查询根类使用 `LUDORK_CAST_ROOT(Type)`，派生类使用 `LUDORK_CAST_DERIVED(Type, Bases...)` 并列出参与查询的直接基类：

- 每个动态转换目标与每个多态绑定类都必须声明自身的宏；从基类继承的声明不会自动注册派生类型。
- 非多态值类型无需声明转换协议。
- 生成的 Lua Adapter 会自动生成该协议，但其公开宿主类仍须自行声明。

这些宏会生成虚子对象查询方法以及 `std::string_view ludorkDynamicTypeKey() const noexcept`，不影响 Lua 名称或绑定基类。头文件与指针语义见[原生指针转换](<构建与模块布局.md#原生指针转换>)，Lua 包装行为见[原生对象包装](<运行时值边界.md#原生对象包装>)。

> **注意**：上表仅列出受支持的标记，并未穷举所有合法选项组合。`Pure`、执行协议与属性声明仍须遵守各自专页中的校验规则。

# 绑定类

使用 `BIND_*` 宏标注 C++20 类，即可将其统一暴露给原生 Lua、LuaLS 类型声明与蓝图元数据目录。

## 声明类

```cpp
#pragma once
#include <CoreMinimal.hpp>

BIND_CLASS()
class Counter {
public:
  BIND_INIT()
  explicit Counter(int initial = 0);

  BIND_PROPERTY()
  int value = 0;

  BIND_METHOD(Pure = true)
  int getValue() const;

  BIND_METHOD()
  void add(int amount);
};
```

头文件依赖与运行时值类型规则见 [Core 头文件与 Runtime 边界](<构建与模块布局.md#core-头文件与-runtime-边界>)。将类声明放在所属模块的 `include/Counter.hpp`，成员定义放在 `src/Counter.cpp`：

```cpp
#include "Counter.hpp"

Counter::Counter(int initial) : value(initial) {}

int Counter::getValue() const {
  return value;
}

void Counter::add(int amount) {
  value += amount;
}
```

CMake 会自动发现 `include/**/*.hpp` 与 `src/**/*.cpp`，重新构建模块即可更新绑定。假设 `Counter` 属于 `Engine` 模块，在 Lua 中可按如下方式调用：

```lua
local Engine = require("Engine")
local Logging = require("Global.Utils.Logging")

local counter = Engine.Counter.new(4)
counter:add(3)
Logging.info(counter:getValue())
```

### 命名、回调、继承与元数据可见性

- **模块根可见性**：模块根是该类在运行时的唯一公开入口。在 `BIND_CLASS` 上设置 `name = "..."` 可指定其 Lua 根标识符；在 `BIND_METHOD(name = "...")` 上指定的方法名对 `metadata = false` 的方法同样生效。
- **虚函数回调**：设置 `BIND_CLASS(callbacks = true)` 后，当前类已绑定的非静态虚方法会通过 Lua 分派。该选项不被子类继承，但子类重写基类已启用的回调方法时回调依然有效。使用 `BIND_METHOD(callback = false)` 可排除当前类的单个方法而不影响继承自基类的回调。回调选择独立于元数据与事件；不支持字符串列表，也不支持非虚函数或构造函数回调。
- **转换基类**：Bindgen 会根据 C++ 继承列表自动推断转换基类。传入 `cast_bases = {"BaseA", "BaseB"}`（必须是有序非空类型名列表，不能写成逗号分隔字符串）可补充祖先类型，或在 `bind_bases = false` 时显式提供基类。
- **已注册基类与 `runtime_bases`**：拥有已注册 Lua 类型的转换基类还会贡献其原生方法与属性，包括从 C++ 直接返回的 userdata。Bindgen 为已注册基类生成 `BindBase`，为无 Lua 类型的接口生成 `BindCast`。设置 `bind_bases = false` 仅关闭从声明基类的自动推断，不会隐藏显式指定的已注册基类成员；`runtime_bases` 则单独控制 Ludork 类组合继承层次。
- **从元数据排除**：逻辑上公开的 `BIND_METHOD` 默认进入编辑器元数据。对内部辅助函数或次要 Adapter 重载标记 `metadata = false`，可保留其在原生 Lua 与 LuaLS 中的可用性，同时避免生成多余的蓝图节点：

```cpp
BIND_METHOD(metadata = false)
void _updateCache();
```

暴露到蓝图元数据中的方法名在同一类型内必须唯一。

## 声明属性

`BIND_PROPERTY()` 用于暴露实例数据成员。可安全求值的布尔、数值、字符串与 `{}` 初始化器会自动推导为元数据默认值。如需指定显式默认值，请使用注解原生支持的纯数据语法；无法从 C++ 类型推断的编辑器语义则写入 `meta(...)`：

```cpp
BIND_PROPERTY(
    default = {0.0, 0.0})
sf::Vector2f defaultOrigin{0.0f, 0.0f};
```

位置项构成数组，命名项构成对象。Bindgen 直接解析这套花括号语法，无需它是合法的 C++ 表达式。使用 `BIND_METHOD(property = ...)` 声明的基于 Getter 的属性同样使用单数形式的 `default`。

`meta(...)` 内的结构化纯数据沿用同一套可嵌套花括号语法：

```cpp
BIND_PROPERTY(
    meta(Rely = {source = "autoSound", op = "!=", value = ""}))
float autoSoundInterval = 0.0f;

BIND_METHOD(defaults = {{}},
            meta(MoveRouteVars = {"route"}),
            outpins(default = nil))
void setRoute(
    const std::optional<std::vector<sf::Vector2i>>& route = {});
```

布尔值一律使用小写 `true` 与 `false`。花括号语法、协议 `nil` 以及拒绝带引号 JSON 的规则详见[宏参考](<宏参考.md>)。

### 显示名称

常规属性与方法无需声明 `DisplayName` 或 `DisplayDesc`，编辑器会自动格式化标识符（例如 `defaultOrigin` 显示为 `Default Origin`，C++ 与 Lua 名称保持 `defaultOrigin`）。真正的运算符别名可声明字面显示名称（如 `+`），但不得使用 `LOC(...)` 或默认描述。

### 基于 Getter 的属性

无参 Getter 可暴露为计算属性：

```cpp
BIND_METHOD(property = "volume", setter = "setVolume")
float getVolume() const;

void setVolume(float value);
```

除非通过 `type` 显式覆盖，否则属性类型取自 Getter 返回类型。该声明仅暴露一个属性，不会额外生成 Getter 或 Setter 节点。

计算属性还可配置 `component = true`，在保留组件元数据的同时将赋值路由至 Setter。`Actor.emitterComp` 即采用此模式，在被替换或赋值为 `nil` 时立即释放旧特效，即使 Actor 处于休眠状态也同样生效。

## 构造函数与排除成员

- **构造函数与静态属性**：使用 `BIND_INIT` 标记构造函数（Lua 中通过 `.new(...)` 调用），使用 `BIND_CLASS_PROPERTY` 标记类级值（对应 C++ 静态存储），使用 `BIND_MODULE_PROPERTY` 标记模块级值。未标注的声明不会纳入绑定。
- **值复制**：标注 `copyable = true` 的完整记录仅在所有成员均具备经验证的独立值语义时，才会生成 `copy()` 与 `deepcopy()`。标量、字符串、容器与嵌套独立值符合条件；指针、Lua 引用与共享资源不会仅因 `copyable` 而具备深拷贝能力。仅当显式的完整类型策略确认安全时，完整原生副本才会包含私有状态。

## 绑定作用域枚举

使用 `BIND_ENUM` 将固定的原生值集合共享给 Lua：

```cpp
BIND_ENUM()
enum class WeatherType {
  NONE = 0,
  RAIN = 1,
};
```

Bindgen 会暴露 `Module.WeatherType` 并生成对应的 `Enums.Module.WeatherType` 模块；`name` 选项同时决定两者名称。蓝图字段与签名使用 `{ enum = "Enums.Module.WeatherType" }`，Lua 调用与已保存的蓝图值则直接携带底层整数。请勿将枚举项重复声明为模块属性。源码注解、Stub 与交叉构建要求见[生成枚举模块](<生成元数据与 Stub.md#生成枚举模块>)。

对于键为字符串、值为数值／字符串／布尔值的既有 `const` 映射，可直接导出为标量枚举而无需定义 C++ `enum`：

```cpp
BIND_MODULE_PROPERTY(enum = true)
extern const std::unordered_map<std::string, std::string> FocusDirection;
```

`Engine.FocusDirection` 采用该形式，而 `Engine.Direction` 则是绑定的原生枚举。生成的枚举模块由构建系统管理，修改声明或映射源码后重新构建即可更新。

若需让标量属性在编辑器中显示枚举选择器，同时保持原有 C++ 与 LuaLS 类型不变，可使用 `metadata_type`：

```cpp
BIND_PROPERTY(metadata_type = {enum = "Enums.Engine.Direction"})
int direction = 0;
```

选择器保存所引用常量的实际值。参数与返回值的同类覆盖见[仅覆盖元数据签名](<函数、事件与执行.md#仅覆盖元数据签名>)。

## 绑定所属类专用的嵌套类型

公开的嵌套 `struct` 或 `enum` 使用与顶层声明相同的绑定标记：

```cpp
class Owner {
public:
  BIND_CLASS()
  struct Data {
    BIND_PROPERTY()
    int value = 0;
  };
};
```

该类型在 C++ 中记为 `Owner::Data`，在 Lua 中暴露为 `Module.Data`（或通过 `name` 指定其他名称）。外层所属类本身不必绑定，但嵌套类型必须可通过每一层外层类公开访问。采用公开前置声明加类外限定名定义时，应将绑定标记写在完整定义处。同一模块内若存在短名相同的 C++ 类型，须通过 `name` 为其分配互不相同的 Lua 名称。

## 值转换契约

使用 `BIND_CLASS(table_init = true)` 可支持从 Lua 表初始化字段固定的记录：表中提供的非 `nil` 可写属性按声明的编解码规则转换，缺失或为 `nil` 的字段保持 C++ 默认值；已有的原生实例也可直接传入。追加 `strict_fields = true` 可拒绝未知字段与非字符串键：

```cpp
BIND_CLASS(table_init = true, strict_fields = true)
struct Limits {
  BIND_PROPERTY()
  std::optional<double> minimum;

  BIND_PROPERTY()
  std::optional<double> maximum;
};
```

`strict_fields` 不会把可选字段转变为必填字段。

对于 `RuntimeData` 这类递归值容器，请使用 `BIND_CLASS(pure_data = true)`；可接受的值类型与 `std::variant` 转换规则见 [Lua 值转换](<运行时值边界.md#lua-值转换>)。

`pure_data`、`dynamic_value`、`opaque_identity` 与 `table_init` 是互斥的转换模式，其生成的类型表示见[默认值与类型](<生成元数据与 Stub.md#默认值与类型>)。

> **注意**：Bindgen 不推断项目专用的转换规则，也不解析不完整的跨模块类型。

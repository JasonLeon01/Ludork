# 项目模板

## 模板参考

新建项目窗口提供两张模板卡片 **Standalone** 与 **C++ Source**，以及一个独立的 **启用视频播放（FFmpeg）** 开关。

| 模板 | 原生源码 | 是否需要原生编译器 | 适用场景 |
|---|---|---|---|
| Standalone | 无 | 否 | 用随附的运行时编写 Lua、蓝图、数据与资产。 |
| C++ Source | 有 | 是 | 修改原生服务、绑定，或构建 iOS、HarmonyOS、Android 目标。 |

每种模板与 FFmpeg 开关组合各有独立模板。已有 C++ Source 工程可通过[打包项目 → Standalone 工程](<../编辑器用户指南/运行、调试与打包.md#将-source-转换为-standalone-工程>)转换为独立的可编辑工程，保留现有导出文件，而不是重新创建空白模板。C++ Source 项目首次运行前需要先**编译**再**导出**，Standalone 只需导出。后续操作见[运行、调试与打包](<../编辑器用户指南/运行、调试与打包.md>)。C++ Source 模板还在项目根目录提供用于格式化原生源码的 `.clang-format`。

在 Windows 上选择 C++ Source 后，会显示**编译器**和**获取 MinGW**。必须选中可用编译器才能创建项目；未检测到可用编译器时，**创建**按钮保持禁用。默认优先选择 MSVC，其次是 Ludork 下载的 MinGW，再其次是 `PATH` 中的可用编译器，包括 LLVM Clang。下载完成会立即刷新列表，无需重启编辑器。Standalone 不需要编译器。检测、下载和后续切换规则见 [Windows 项目编译器](<../编辑器用户指南/运行、调试与打包.md#windows-项目编译器>)。

macOS 上的 C++ Source 项目需要安装完整 Xcode，仅有 Command Line Tools 不满足要求。新建项目窗口每次打开时检测一次；未检测到 Xcode 时，选择 C++ Source 会在编译器区域显示**获取Xcode**，并禁用**创建**按钮。点击后会打开 Mac App Store 中的 Xcode 页面。安装完成后，关闭并重新打开新建项目窗口才能再次检测。创建 Standalone 项目不需要 Xcode。

## 获取模板

开发版编辑器附带本地模板。缺少模板时，新建项目会显示错误，不会联网下载替代模板。

正式版编辑器从对应的 GitHub Release 获取模板。Windows x64 使用 ZIP，macOS ARM64 使用 tar.gz；每个正式版本提供八个独立模板资产：

| 模板 | Windows x64 | macOS ARM64 |
|---|---|---|
| C++ Source | `game-source.zip` | `game-source.tar.gz` |
| C++ Source + FFmpeg | `game-source-ffmpeg.zip` | `game-source-ffmpeg.tar.gz` |
| Standalone | `game-standalone.zip` | `game-standalone.tar.gz` |
| Standalone + FFmpeg | `game-standalone-ffmpeg.zip` | `game-standalone-ffmpeg.tar.gz` |

模板与编辑器的完整版本号匹配，包括补丁版本。对应版本或模板尚未发布时，新建项目会提示模板不可用。

Windows 与 macOS 下载的四种模板统一使用 `~/Ludork/Templates/v<基础版本>/` 进行校验和离线复用，不依赖编辑器安装目录。实际路径见[用户数据目录](<../编辑器用户指南/启动页、工作区与快捷键.md#用户数据目录>)。开发版附带的本地模板仍是只读输入。

新建窗口显示下载或复制进度及解压进度。点击 **取消**，或在创建期间关闭窗口，会取消操作并清理本次未完成的项目和下载文件；已完成的有效缓存保留，供以后复用。

新项目使用编辑器当前的主次版本，例如编辑器 `1.0.7` 创建 `v1.0` 项目，不提供旧版本创建选项。可打开的项目版本见[项目版本](<../编辑器用户指南/项目设置与资产布局.md#mainproj>)。

## FFmpeg 选项

**启用视频播放（FFmpeg）**增加本地 MOV 和 MP4 播放能力，支持 H.264 视频和 AAC 音频，同时会增大包体。不包含其他编解码器、网络播放或硬件加速。

Windows 和 macOS 使用 FFmpeg 动态库，iOS、HarmonyOS 和 Android 使用静态库。发行要求，包括静态构建所需的 LGPL 重链接材料，见 `Licenses/FFmpeg/README.md`。在 macOS 上选择 FFmpeg 时还会显示兼容性提示。

## 模板目标

- 配置 [Ludork 简易服务器](<../简易服务器/部署与编辑器设置.md>)要求 C++ Source；Standalone 不显示 Game 测试服务器菜单或打包配置。生成的所有模板都默认禁用服务器，不携带测试或正式凭据。转换已有 Source 工程时，则可以将显式启用的 Release 服务器配置编译进 Standalone 运行时。
- 脚本编译、Shader 加密、数据加密、存档加密，以及 **将 Assets、Data 和 Scripts 打包为 .ldpak** 都属于打包选项，不是模板类型。完整的选项行为见[运行、调试与打包](<../编辑器用户指南/运行、调试与打包.md>)。

四种模板均不包含导出产物：`Scripts/Internal/UI/`、`Scripts/stub/Internal/UI/`、`Scripts/stub/Internal/UIWindows/`、生成的语言 Lua 文件、`Assets/Shaders/MaterialGenerated/` 和 `EditorCache/ProjectExport.json`。项目 `.gitignore` 也会忽略这些生成文件。模板保留 UI JSON、`Data/Materials` 下的源材质图、手写 Controller 和声明、`Scripts/Source/Locale/Core.lua`、通用数据和变量 Lua 及其声明，以及原生绑定声明；新项目通过导出生成 UI、语言和材质运行文件。Standalone 使用自带的预览编译器。

模板也会保留根目录下可选的 `MaterialExport.json`，用于保存[额外材质组合](<../编辑器用户指南/材质.md#材质组合>)；导出时，这些条目会与新项目中地图实际使用的组合合并。

保留的 `Scripts/stub/**/*.d.lua` 用于 Lua 语言工具，[游戏打包](<../编辑器用户指南/运行、调试与打包.md#散放与归档>)时会移除。

运行时许可证文本位于 `Licenses`，FFmpeg 变体另附 `Licenses/FFmpeg`；资产声明保留在对应资产旁。打包会包含现有许可证文本，但发行者仍需负责材料的完整性。

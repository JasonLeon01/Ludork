# 项目模板

Ludork 项目基于 **Standalone** 或 **C++ Source** 模板创建，两者均提供可选的 FFmpeg 视频播放变体。本指南介绍如何选择模板、核对平台前置条件，以及了解模板下载机制与目录构成。

## 模板参考

**新建项目**窗口提供 **Standalone** 与 **C++ Source** 两张模板卡片，以及独立的**启用视频播放（FFmpeg）** 开关。

填写用于新建目录的项目名称，并填写游戏专用的必填字段 **APP_NAME**。`APP_NAME` 用于标识游戏的[用户数据目录](<../编辑器用户指南/项目设置与资产布局.md#游戏配置>)与[打包后的应用程序](<../编辑器用户指南/运行、调试与打包.md#打包>)，请为每款游戏设置独立名称。该字段为空或无效时，**创建**按钮保持禁用；重命名项目目录不会更改 `APP_NAME`。

创建项目时，编辑器将 `APP_NAME` 代入模板的 `Scripts/Entry.lua.in`，生成普通且可编辑的 `Scripts/Entry.lua`，不再保留 `.in` 模板。此后如需修改应用名称，直接编辑 `Scripts/Entry.lua` 中的静态 `local APP_NAME` 声明即可。

| 模板 | 原生源码 | 是否需要原生编译器 | 适用场景 |
|---|---|---|---|
| Standalone | 无 | 否 | 使用预构建运行时编写 Lua、蓝图以及制作数据与资产。 |
| C++ Source | 有 | 是 | 修改原生服务或绑定，或面向 iOS、HarmonyOS、Android、WebGL 构建。 |

每张卡片与 FFmpeg 开关的组合均对应独立模板。如需将现有的 **C++ Source** 项目转换为可编辑的 **Standalone** 项目，请使用[打包项目 → Standalone 项目](<../编辑器用户指南/运行、调试与打包.md#将-source-转换为-standalone-项目>)；该操作会创建一个独立的新项目并保留原有导出产物，而非基于空白模板重新生成。

首次运行前，**C++ Source** 项目需依次执行**编译**与**导出**，**Standalone** 项目仅需执行**导出**。后续构建与导出流程请参阅[运行、调试与打包](<../编辑器用户指南/运行、调试与打包.md>)。**C++ Source** 模板还在项目根目录提供用于格式化原生源码的 `.clang-format`。

- **Windows**：选择 **C++ Source** 后，界面会显示**编译器**与**获取 MinGW**。创建项目前必须选择可用编译器，否则**创建**按钮保持禁用。检测优先级依次为 MSVC、Ludork 下载的 MinGW、`PATH` 中的可用编译器（含 LLVM Clang）；下载编译器后列表自动刷新，无需重启编辑器。**Standalone** 模板无需编译器。有关检测、下载与后续切换规则，请参阅 [Windows 项目编译器](<../编辑器用户指南/运行、调试与打包.md#windows-项目编译器>)。
- **macOS**：创建 **C++ Source** 项目需要安装完整版 Xcode，仅安装 Command Line Tools 不满足要求。**新建项目**窗口打开时检测一次：若未检测到 Xcode，选择 **C++ Source** 会显示**获取 Xcode**（打开 Mac App Store 中的 Xcode 页面）并禁用**创建**按钮。安装完成后，关闭并重新打开**新建项目**窗口即可重新检测。**Standalone** 模板不依赖 Xcode。

## 获取模板

开发版编辑器安装包内置本地模板。若本地模板缺失，**新建项目**会直接显示错误，不会联网下载替代模板。

正式版编辑器从对应的 GitHub Release 下载模板。Windows x64 使用 ZIP 归档，macOS ARM64 使用 `tar.gz` 归档。每个正式版本均发布以下八个模板资产：

| 模板 | Windows x64 | macOS ARM64 |
|---|---|---|
| C++ Source | `game-source.zip` | `game-source.tar.gz` |
| C++ Source（含 FFmpeg） | `game-source-ffmpeg.zip` | `game-source-ffmpeg.tar.gz` |
| Standalone | `game-standalone.zip` | `game-standalone.tar.gz` |
| Standalone（含 FFmpeg） | `game-standalone-ffmpeg.zip` | `game-standalone-ffmpeg.tar.gz` |

模板与编辑器的完整版本号（含补丁号）严格对应。若对应的 Release 或模板尚未发布，**新建项目**会提示模板不可用。

Windows 与 macOS 下载的四种模板统一缓存至 `~/Ludork/Templates/v<基础版本>/`，用于校验与离线复用，独立于编辑器安装目录（系统原生路径见[用户数据目录](<../编辑器用户指南/启动页、工作区与快捷键.md#用户数据目录>)）。开发版内置的本地模板为只读输入。

**新建项目**窗口会显示下载或复制进度以及解压进度。创建期间点击**取消**或关闭窗口，会中止操作并删除未完成的项目与下载文件；已完成且校验通过的缓存条目会保留供后续复用。

**新建项目**始终创建与编辑器 `主版本.次版本` 一致的项目版本（例如任意 `1.0.x` 编辑器均创建 `v1.0` 项目），不提供创建旧版本项目的选项。打开受支持的旧版项目由[项目版本检查](<../编辑器用户指南/项目设置与资产布局.md#mainproj>)处理。

## FFmpeg 选项

**启用视频播放（FFmpeg）** 可启用本地 MOV 与 MP4 播放支持（H.264 视频编码与 AAC 音频编码），同时会增加包体体积。不包含其他编解码器、网络流播放及硬件加速支持。

Windows 与 macOS 使用 FFmpeg 动态库，iOS、HarmonyOS、Android 与 WebGL 使用静态库。发行合规要求（包括静态构建所需的 LGPL 重链接材料）详见 `Licenses/FFmpeg/README.md`。在 macOS 上勾选 FFmpeg 时，界面会显示兼容性提示。

## 模板目标

- **Ludork 服务器**：配置 [Ludork 服务器](<../简易服务器/部署与编辑器设置.md>)需要 **C++ Source** 项目；**Standalone** 项目会隐藏测试服务器菜单与打包配置。所有模板默认关闭服务器功能，且不含测试或正式凭据。转换已有 **C++ Source** 项目时，可将显式启用的 Release 服务器设置内嵌至生成的 **Standalone** 运行时中。
- **打包选项**：脚本编译、着色器加密、数据加密、存档加密以及**将 Assets、Data 和 Scripts 打包为 .ldpak** 均属于打包选项，而非模板类型。完整的选项行为请参阅[运行、调试与打包](<../编辑器用户指南/运行、调试与打包.md>)。
- **排除的生成产物**：模板不包含 UI 与本地化导出产物（`Scripts/Internal/UI/`、`Scripts/stub/Internal/UI/`、`Scripts/stub/Internal/UIWindows/`、生成的本地化 Lua 文件与 `EditorCache/ProjectExport.json`，均已列入 `.gitignore`），也不包含材质缓存和发行配置 `Data/RuntimeSettings.json`/`.ldc`。**C++ Source** 模板额外排除项目根目录的 `build-web` 与 `dist`。新项目需执行**导出**以生成 UI 与本地化文件；材质由游戏在[初始化阶段自动准备](<../编辑器用户指南/材质.md#运行时生成>)。
- **包含的创作源文件**：模板包含 UI JSON、`Data/Materials` 下的源材质图、手写 Controller 及声明文件、`Scripts/Source/Locale/Core.lua`、通用数据与变量 Lua 及其声明、原生绑定声明，以及用于保存[额外材质组合](<../编辑器用户指南/材质.md#材质组合>)的可选文件 `Data/MaterialCombinations.json`（游戏初始化时将其与地图实际使用的组合合并）。
- **语言工具声明**：模板包含供 Lua 语言工具使用的 `Scripts/stub/**/*.d.lua`；这些声明文件在[游戏打包](<../编辑器用户指南/运行、调试与打包.md#未归档目录与归档>)时会被移除。

运行时许可证文本位于 `Licenses` 目录（FFmpeg 变体另含 `Licenses/FFmpeg`），资产声明存放在对应资产旁。打包过程会自动复制现有许可证文本，但确保声明完整合规由发行方负责。

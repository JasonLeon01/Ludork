# 声明式 UI 运行时契约

生成的 View 负责构造并管理原生 UI 对象树，Controller 则在其上叠加业务逻辑、数据观察与动态集合。本页定义 View、窗口与控件的运行时生命周期、所有权与释放保障。

## 创建 View

```lua
local InventoryView = require("Internal.UI.Inventory")

local inventory = InventoryView.new()
inventory:mount(uiManager, logicalSize)
```

`View.new()` 会实例化 JSON 资产、用对应生成的 View 类包装嵌套资产，并递归填充所有类型化引用，无需依赖 Controller。构造操作不会将界面树挂载到屏幕上，请显式调用 `mount` 或 `attachTo`。

- **View 成员**：每个 View 暴露 `assetKey`、`designSize: sf.Vector2f`、原生 `instance: Engine.AssetInstance`、类型化 `root`、`controls`（原生系统控件）与 `assets`（类型化子 View）。访问子资产中的具名控件可写作 `inventory.assets.ItemRow.controls.Label`；键名与资产内原始节点名完全一致，非 Lua 标识符名称须使用方括号索引。
- **资源共享**：同一顶层 View 内重复引用的嵌套资产共享已加载的资产定义与源纹理，但每个嵌套实例仍拥有独立的 View、原生控件、纹理裁剪区域与动画状态（绑定 Controller 时应传入该子 View）。`WrapBox` 扩容时复用同一批资源。新建顶层 View 或重建预览快照会重新分配资源。

## 绑定业务行为

窗口模块在文件内定义私有 Controller 并返回 `Ui.DefineWindow(viewClass, Controller, nativeBase?)`（`nativeBase` 默认为 `Engine.Canvas`）。返回的 UI 类继承 `nativeBase`，Controller（`UiController`）与生成的 View 仍为独立对象。调用 `Window.new(...businessArgs):mount(uiManager)` 即可创建并注册窗口；空 Controller 无需定义 `init`，窗口直接按模板原样显示。

### 构造生命周期

1. 创建原生宿主与生成的 View，将二者绑定至 Controller，并挂接 View。
2. 调用可选的业务 `init(...)`。此时 `self.ui` 为类型化 View，`self.view` 为 `Engine.AssetInstance`，`self.root` 为原生根节点，`self.host` 为窗口 UI（对外暴露 `window.ui`，保持 Controller 私有）。
3. 执行 `prepare`，依次触发 `bind`、`refresh` 与重新布局。
4. 调用可选的 `ready`（用于依赖已准备布局的业务逻辑），随后应用配置的初始隐藏状态。

`Ui.DefineWindow` 会将 Controller 实例方法（`camelCase`）、静态辅助函数（`PascalCase`）、`SCREAMING_SNAKE_CASE` 常量与 `Publish` 转发至公开窗口类，同时将构造钩子保持私有（参见[文件布局](<编写工作流.md#文件布局>)）。独立的行 Controller 与场景 Controller 使用 `Ui.Define(viewClass, definition, baseClass?)` 与 `Controller.new(model, ui?)`，传入的 View 必须匹配生成类且至多绑定一个 Controller。

### `Controller.windowOptions`

| 选项分组 | 字段与行为 |
|---|---|
| 定位与尺寸 | `position`、`centered`、`screen`（全屏范围）。除非请求全屏行为，否则宿主尺寸取自模板。 |
| 初始交互 | `hidden`、`returnButton`、`focusable`。 |
| 窗口基类 | `frame`（默认 `"WindowFrame"`）、`content`（默认 `"Content"`）。 |
| 可选择基类 | `list`、`scroll`。选择框与命中边界来自 ListView 的原生单元格布局。 |
| 转场动画 | `transitionTarget` 指定动画目标节点。 |

`windowOptions` 仅配置宿主行为，绝不复现 JSON 层级或求值业务表达式。

## 观察模型字段与绑定回调

- **`Controller:watch(target, field, method, immediate?)`**：通过原生 `Class.monitor` 监听表或 userdata 的字段。传入未绑定的 Controller 方法，回调签名接收 `(controller, newValue, oldValue)`。默认（`immediate = true`）立即触发一次，此时 `oldValue` 为 `Class.MISSING`；传入 `false` 则等待首次变更后再触发。返回的 `stop()` 用于取消该单条订阅；Controller 释放或集合行回收时会自动取消其拥有的全部观察。
- **浅层监听语义**：`watch` 仅监控对字段的直接赋值，表值字段内部的变化需要单独设置监听或触发显式刷新事件。相等性判断、`nil` 写入与错误传播规则见 [Class 工具](<../../快速入门/Ludork Lua 进阶.md#class-工具>)。
- **`Controller:bindCallback(method)`**：以弱引用包装未绑定的类方法（例如 `self:bindCallback(Controller.confirm)`），自动注入 `self` 并原样透传参数与返回值。Controller 释放、垃圾回收或集合行回收后回调停止响应，且行复用后旧回调仍保持失效。

## 准备、子窗口与挂载

- **窗口皮肤**：将 View 挂接到窗口宿主时会保留边框在资产中定义的 `windowSkin` 与 `repeated` 属性，不会被宿主默认值覆盖；显式调用 `applyWindowSkin()` 才会应用宿主设置。
- **窗口挂载**：`Window.new(...)` 自动准备并挂接其 View。`window:mount(uiManager)` 注册宿主一次，`window:unmount()` 解除注册同时保持窗口可复用，`window:dispose()` 执行终态释放。
- **子窗口**：`self:createChild("AssetName", ChildWindow, ...businessArgs)` 会调用 `ChildWindow.FromView(self.ui.assets.AssetName, ...)`（`FromView` 也接受显式传入的子 View）。两者均复用子 View 的既有控件与原始父级、绑定输入宿主并准备子 Controller。位置、尺寸与层叠顺序遵循生成布局，移动子宿主会同步更新其窗格，父 View 释放时自动释放子窗口。框架绝不从 JSON 自动发现 Controller，也不会隐式解析业务依赖。
- **输入宿主顺序**：输入宿主在原生子控件更新顺序中紧邻其 View 之前插入，使可选择宿主能在单行控件之前接管列表手势，同时维持视觉兄弟顺序不变。其余触摸事件（如返回按钮与原生子控件）透传给 View。
- **直接挂载 View 与通过 Controller 挂载**：直接操作原始 View 时，`View:prepare(logicalSize?)` 执行重排并返回根节点，`View:mount(uiManager, logicalSize?)` 准备并注册一次，`View:attachTo(parent, logicalSize?)` 准备并重新设定父级（不执行 Controller 准备）。`Controller:attachTo` 与 `Controller:mount` 先准备 Controller 一次，再调用 `View:attachPreparedTo(parent)` 或 `View:mountPrepared(uiManager)`，从而保留准备后应用的几何调整。
- **`Controller:prepare(logicalSize?)`**：每个绑定周期调用一次 `bind`，订阅声明的 `refreshEvents`，注册到共享资产更新通道（首次准备时创建；仅 `require` 模块或创建 View 不会订阅），执行 `refresh` 并准备 View。后续调用仅重复 `refresh` 与重排。省略 `logicalSize` 会沿用当前绑定周期内上次传入的尺寸（供行 Controller 完成动态布局与语言刷新）。集合行复用会开启新的绑定周期。

需要由内容驱动尺寸调整时，请调用 [`AssetInstance:reflowControl`](<../全局与 Core 模块/Core Modules/Engine/交互与声明式 UI 控件.md#assetinstance>)。固定布局应保留在 JSON 中，Controller 仅负责内容测量与模式切换。

## 首次使用时创建可选窗口

`Internal.UIBase.LazyWindow` 将可选弹窗的构造推迟到首次显示时：

- **`LazyWindow.new(factory)`**：仅保存工厂函数，不创建任何 UI。
- **`handle:get()`**：首次调用时执行 `factory`、缓存窗口并返回该实例；后续调用直接返回缓存实例。
- **`handle:peek()`**：返回已缓存窗口或 `nil`，绝不触发 `factory`。可见性检查、输入拦截、关闭、语言刷新与玩家重绑定应使用 `peek()`，避免提前构造未使用的 UI。
- **`handle:dispose()`**：释放已创建的窗口（若有）并丢弃 `factory`。释放为终态且不会触发 `factory`。

在 `factory` 内部 `require` 窗口模块（同步推迟其类定义加载）、调用 `Window.new(...)`、配置回调与焦点，并挂载到既有 `UIManager`；调用方随后执行 `handle:get():open(...)`。工厂在执行时读取当前玩家、游戏实例与配置。持有者可预先建立空焦点组及其相邻关系，并在挂载激活新窗口前填充控件。

每个独立弹窗（包括菜单子窗口）都应拥有各自的 `LazyWindow` 句柄。`Window.new(...)` 与 `View.new()` 始终构造完整对象树（含资产中编排的子 View）；懒加载仅推迟该次构造调用。再次打开时会复用已有窗口、Controller 与 View，保持正常的刷新与动画行为。

## 动态集合

行数随模型变化时使用动态集合；固定 JSON 子项请直接通过 `assets` 绑定。

- **集合操作**：`view:createCollection(container, RowControllerClass)`（在 Controller 内使用 `self:createCollection(...)`）在 Canvas 或 ListView 上挂载一个受管的 `UiCollection`，并摘除资产中的预览子项。`collection:add(model, logicalSize?)` 优先弹出空闲行或新建行，绑定 `model`、准备并挂接其根节点后返回 Controller。`collection.items` 按插入顺序保存活动 Controller；批量添加后调用 `collection:layout()` 更新 ListView 位置。
- **清空、对象池与释放**：`collection:clear()` 清空 `items`、隐藏并摘除根节点、清除原生回调与动画、取消观察与订阅，并清除旧模型及缓存的逻辑尺寸。每个集合最多池化 64 组空闲 Controller/View/控件树（不跨容器或窗口共享），超出部分直接释放。重复调用 `clear()` 安全无害。`collection:dispose()` 与父 View 释放会终态销毁全部活动行与空闲行。切勿跨越 `clear()` 持有行引用，也切勿直接销毁池中行。
- **行 Controller 生命周期**：
  - `init()` 每个实例仅运行一次：用于捕获模板颜色、固定尺寸、静态引用与所拥有的子集合；不得缓存模型拥有的对象。
  - `bind()` 每次绑定模型时运行：负责校验数据并注册回调、观察与订阅。
  - `refresh()` 必须覆盖全部依赖模型的文本、角色显示、颜色、显隐与尺寸（包括从有内容切换为空内容）。
  - 业务代码仅调用 `clear`、`add` 与 `layout`；`releaseForReuse()` 与 `reuse(model)` 仅供基础框架内部使用。
- **嵌套子项**：资产中编排的子 View 保留原父级并在刷新前恢复根节点的显隐与活动状态。绑定了独立 Controller 的子 View 在父行回收时会失去旧模型与绑定，父 Controller 须在 `bind()` 中为子 Controller 赋新 `model` 并调用 `prepare()`。嵌套动态集合随持有者一同清空与复用。顶层窗口保持常规生命周期，不进入行池。

## 重复模板控件

资产中编排的 `Engine.WrapBox` 持有一个模板并实例化 `count` 份独立原生子树，不会将模板后代展开到外层 View 的 `controls` 或 `assets` 中。通过从 1 开始的 `wrapBox:get(i)` 获取各实例原生根节点（无效下标会抛出错误），将 `Engine.ControlBase` 缩窄为具体原生类型前应先通过 `Class.isInstance` 检查。

`getCount()` 与 `setCount(count)` 读写非负实例数量（`0` 或空模板使控件保持为空）。重排、调整尺寸与修改间距均会保留既有实例；增大 `count` 时追加新实例，减小时仅释放尾部多余实例。每份子树维护独立状态，由 `WrapBox` 拥有更新、输入与释放生命周期。不要将 `WrapBox` 放入 `UiCollection` 中。

## 命名空间与属性值

生成引用遵循[创建 View](<#创建-view>)中定义的本地 `controls` 与子 `assets` 边界。`Controller:requireAsset(name)` 返回生成的子 View；原生 `instance:requireControl(name)` 与 `instance:requireAsset(name)` 返回本资产内的原生对象；`instance:getNodeByName(name)` 在子树中查找节点并拒绝歧义名称。

`AssetInstance:setProperty(name, propertyId, value)` 与 `UiController:setProperty` 要求传入属性声明的运行时类型；属性类型与可选值清除方式见 [AssetInstance](<../全局与 Core 模块/Core Modules/Engine/交互与声明式 UI 控件.md#assetinstance>)。嵌套 JSON 不能覆盖子资产的内部属性或层级。

## 动画播放

原生实例、生成 View 与 Controller 均提供 `hasAnimation(name, target?)`、`playAnimation(name, target?, onFinished?)` 与 `stopAnimation(name, target?)`，用于控制全局动画或资产内节点动画：

- **播放行为**：采用线性插值并立即应用时间点 `0`。自然播放完成时保持末帧并触发一次 `onFinished`。
- **并发与停止**：不同目标并发播放互不干扰。对同一目标启动新动画会先清除旧效果与旧回调，再从时间点 `0` 重新开始。`stopAnimation` 仅清除匹配动画的效果与待执行回调（含已保持的末帧）。隐藏或释放根节点会清除全部活动效果与待执行回调。
- **缺失动画与嵌套**：动画不存在时记录包含资产、目标与名称的警告日志，返回 `false` 并同步调用 `onFinished`。嵌套资产仅导出全局动画；父资产针对该嵌套节点的同名动画仅覆盖该实例（父资产的全局动画不会触发覆盖，子节点动画绝不导出）。

## 释放

- `View:dispose()` 释放其绑定的 Controller、嵌套 View 与动态集合，停止动画并卸载/摘除根节点。可通过 `View:own(child)` 托管额外实现 `dispose()` 的对象。
- `window:dispose()` 与 `Controller:dispose()` 释放所拥有的 UI 树，清除更新订阅、观察与生成控件上的原生回调，且支持安全重复调用。仅当存在树外外部资源或回调时，Controller 才需要额外清理。
- `UIManager` 销毁时会清除绑定到其生命周期的全部回调（含已摘除的控件）。`removeUI` 会保留回调供后续 `loadUI` 使用，加载或更改父级会转移所有权——从 `UIManager` 移除根节点不能替代 `dispose()`。

已释放的 UI 进入终态，不得复用。[Lua 热重载](<../Lua 运行时与模块.md#lua-热重载>)会更新兼容的 Controller 方法并保持存活 UI 状态与订阅不变，但不会重新执行 `bind`、重新挂载控件或重建 JSON 树。

# 声明式 UI 编写工作流

声明式 UI 根据 JSON 资产自动生成类型化的 Lua View，同时将业务逻辑保留在手写 Controller 中。可视化布局请使用 [UI 资产编辑器](<../../编辑器用户指南/UI 资产编辑器.md>)。

| 层级 | 职责范围 |
|---|---|
| JSON View | 层级结构、资产内节点名、静态控件属性、Slot、动画时间轴与仅用于设计的预览数据 |
| 生成的 Lua View | 完整的类型化控件与子 View 树、资产身份、挂载及所拥有对象的生命周期 |
| Lua Controller | 模型访问、回调、本地化与格式化文本、状态刷新及动态组合 |
| 窗口 UI | 原生窗口与输入状态、生成的 View 及其私有 Controller |
| 原生控件 | 渲染、测量、命中测试、焦点与基础交互状态 |
| `UIManager` | 挂载和移除已完成准备的根控件 |

> **重要**：严禁在 UI 资产中保存 Controller 函数、表达式、事件处理器或 `LOC(...)` 调用。固定位置、尺寸、间距与文本样式均应在 JSON 中编排；仅在动态内容需要测量或调整尺寸时，才由 Controller 读取已准备的控件。

## 文件布局

UI 资产统一存放在 `Data/UI` 下：

```text
Data/UI/
├── Inventory.json
└── Parts/
    ├── Inventory/ItemRow.json
    └── Shared/KeyPrompt.json
```

完整的屏幕、窗口、HUD 与浮层直接置于 `Data/UI` 下；归属单一 UI 的子部件置于 `Parts/<Owner>`，多个 UI 复用的公共部件置于 `Parts/Shared`。切勿仅按控件类型划分目录。

生成的 Lua View 严格镜像资产目录树。`Scripts/Internal/UI`、`Scripts/stub/Internal/UI` 与 `Scripts/stub/Internal/UIWindows` 下的全部文件均由生成器管理，切勿手工修改：

```text
Scripts/Internal/UI/
├── Inventory.lua
└── Parts/
    ├── Inventory/ItemRow.lua
    └── Shared/KeyPrompt.lua
```

- **手写 UI 模块**：公共基础模块位于 `Scripts/Internal/UIBase`。窗口模块（如 `Scripts/Source/Windows/WindowInventory.lua`）在模块内定义私有 Controller，并通过 `Ui.DefineWindow` 导出 UI 类。独立的行 Controller 与场景 Controller 各自存放在专用的 `Controller.lua` 模块中（如 `Source.Windows.WindowInventory.ItemRow.Controller` 与 `Source.Scenes.SceneTitle.Controller`）。
- **窗口声明**：窗口的手写 Stub 仅使用不带模块名的 `---@meta` 声明私有 Controller；生成器据此在 `Scripts/stub/Internal/UIWindows` 下派生公开窗口声明。采用普通十进制以外形式书写的数值常量（如 `1e3` 或 `0x20`）必须在 Controller 上使用 `---@field NAME type` 显式标注类型。参见[业务成员只声明一次](<Controller 示例.md#业务成员只声明一次>)。
- **生成器解析规则**：声明生成器从顶层 `local Name = require(...)` 的引号或长括号 Lua 字符串字面量中解析导入（解码合法 UTF-8 模块名），并要求模块以唯一的 `return Ui.DefineWindow(...)` 结尾。字符串、长注释或数字字面量语法错误会报告源文件、行号与列号。

## 创建 UI 并添加业务行为

1. 在 UI 资产编辑器中编写 JSON 资产，为所有需从 Lua 访问的节点设置稳定的名称。
2. 如需在其他 UI 资产中通过项目 Palette 嵌套该资产，请启用 **Exposed**。
3. 保存资产并点击**导出**生成 View，随后在窗口模块中 `require` 该 View。
4. 定义局部 Controller 并返回 `Ui.DefineWindow(ViewClass, Controller, nativeBase?)`。业务初始化写在 `init` 中，原生回调写在 `bind` 中，状态更新放在 `watch` 或 `refresh` 中。
5. 使用 `windowOptions` 配置初始宿主行为，使用 `createChild` 绑定资产中已编排的子窗格，使用集合填充可变长度行。参见[声明式 UI 运行时契约](<运行时契约.md>)与[声明式 UI Controller 示例](<Controller 示例.md>)。
6. 维护私有 Controller Stub 并重新生成。由持有者负责窗口的创建、挂载与释放，可选弹窗应采用[首次使用时创建](<运行时契约.md#首次使用时创建可选窗口>)方式。

> **注意**：基于 `WindowBase` 或 `WindowSelectable` 的资产应嵌套 `Parts/Shared/WindowChrome` 与 `Parts/Shared/WindowPauseMark`，节点名分别为 `WindowChrome` 与 `WindowPauseMark`。其 Slot 分别将边框装饰覆盖于窗口框架之上、将暂停标记置于内容区底边，窗口基类会自动绑定返回按钮、手柄提示与暂停标记行为。

## 资产变更后重新生成

移动资产或重命名节点后，请同步更新手写的 `require` 路径与节点引用，再点击**导出**。如需在不执行完整导出的情况下仅重新生成 UI View 与声明，可运行：

```bash
ludork-assets ui-assets generate <project-root>
```

常规保存与编译不会重新生成 UI 代码；从命令行启动或打包前请先执行导出（参见[运行、调试与打包](<../../编辑器用户指南/运行、调试与打包.md>)）。

生成过程强制执行严格的文件安全策略：

- 若输出路径被手写 Lua 文件或符号链接占用，生成器将拒绝写入；仅清理带有生成器标记的过期文件。
- 更新的 View、声明与仅变更大小写的目录重命名会作为单一原子批次安装。任一步安装失败都会回滚已应用的变更（若回滚自身失败，错误信息会列出受影响路径）。仅修改大小写的目录中若包含手写文件，重命名同样会被拒绝。

## 编写约束与约定

- **界面结构**：每个可见界面只设一个顶层资产，从 `Parts/<TopLevelName>/` 嵌套该界面专用的子窗格。被嵌套部件必须设置 `palette.exposed = true`，仅供运行时使用的辅助部件无需暴露。
- **动态内容与本地化**：显示前应先本地化 Tab 标签并填充动态集合；固定控件与固定行始终保持由 JSON 构造的原始实例。字面量 JSON `text` 仅保留给永久、与语言无关的符号，占位内容请使用仅用于设计的预览字段（参见 [UI 预览](<../../PreviewHost/UI、Actor、粒子与字幕预览.md#ui-预览>)）。
- **帧动画角色**：逐帧动画的角色与敌人请使用 [`Engine.CharacterView`](<../全局与 Core 模块/Core Modules/Engine/布局与图像控件.md#characterview>)。在 JSON 中提供预览默认值，运行时再调用 `setCharacter` 传入真实的 Actor 视觉数据。

# 装备与物品

创建背包 ID 稳定、槽位有效、成员图行为职责聚焦的物品与装备记录。

## 前置条件

- 包含所需背包标识符与槽位标识符的 Item、Equip 与 Class 通用数据。
- 从 `Source.MapActors.Item` 或 `Source.MapActors.Equip` 派生的蓝图父类。

## 步骤

- Item 的 `usable` 控制是否可从背包使用，`cost` 控制是否显示堆叠数量。是否消耗物品由 `onUse` 图决定。
- 背包内的使用逻辑放在 `onUse`，敌人掉落行为放在 `onDrop`。图目标与方法接收者的规则见[物品](<../Actor、敌人、物品与装备.md#物品>)。
- Equip 的 `slot` 必须匹配所选 Class 的槽位字典。
- 属性变化写进 `attrPlus`。`onEquip` 与 `onUnequip` 图只留给特殊行为。
- 图标放在 `Assets/Icons` 下，并通过资源选择器指定。

## Game 装备

`BP_Equip_Sword_A.json` 继承 `Source.MapActors.Equip`，设置 `ID = "Sword_A"`，由该 ID 解析 Equip 成员。

`attrPlus`、`onEquip` 与 `onUnequip` 的生效顺序见[装备运行时规则](<../Actor、敌人、物品与装备.md#装备>)。

## Game 物品

`BP_Item_Key_Y.json` 继承 `Source.MapActors.Item`，设置 `ID = "KEY_Y"`，同时匹配 Item 成员与黄门的 `needKeyID`。

持有 Item 时授予 `onUse` ability，移除最后一件时撤销。`Player:activateItem` 以该 Player 为目标。[读档](<../运行时数据、配置与存档.md#玩家>)会重建能力与 Effect，不重放成员图。

## 限制

重命名成员不会自动修复已存储的引用。Class 槽位不匹配和未知记录 ID 同样是明确的数据错误。

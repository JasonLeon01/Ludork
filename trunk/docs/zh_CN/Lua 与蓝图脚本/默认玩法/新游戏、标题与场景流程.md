# 新游戏、标题与场景流程

本页说明默认玩法如何从启动画面（`SceneInit`）流转至标题界面，再进入普通地图与组合式大地图。

默认入口创建 `Source.Scenes.SceneInit` 并将控制权交给原生 System 主循环。`SceneInit` 借助进度条准备共享数据与缓存，随后切换到标题场景。标题命令窗口按可见选项自适应高度：[WebGL](<../../编辑器用户指南/运行、调试与打包.md#webgl>) 显示**开始游戏**、**继续游戏**与**设置**，原生平台额外显示**退出游戏**。存读档窗口与设置窗口均在首次使用时构造，并在标题场景销毁前持续复用。

场景切换通过 `GlobalCore.SceneManager` 完成，画面冻结与转场遮罩通过 `GlobalCore.Transition` 控制，闪烁、震动与色调效果则使用 `GlobalCore.ScreenEffects`。

## 配置新游戏

开始新游戏时会创建或重置游戏实例、加载初始地图与玩家数据，随后进入地图场景。

- **玩家与区域**：`Data/Configs/System.json` 指定 `startPlayerBlueprint`（相对于 `Data/Blueprints`）与 `startRegion`。两者仅在开启新游戏时生效；**继续游戏**会从存档槽恢复保存的玩家类与当前区域。
- **初始地图与位置**：`startMap` 可指向普通地图、组合式大地图清单（如 `World_01/_world.json`）或已摆放的大地图子地图（如 `World_01/Map_03.json`）。目标为清单时 `startPos` 使用世界坐标，目标为子地图时使用子地图局部坐标。编辑器在同一棵地图树中展示这三种形态并保存选定路径。

地图窗口的创建与复用见[窗口、菜单、输入与控件](<窗口、菜单、输入与控件.md>)。

## 进入地图与组合式大地图

`GlobalFunctions.Scene.GotoMap` 遵循与 `startMap` 相同的目标路径与坐标规则。切换到当前活动大地图中的另一张已摆放子地图时会复用同一个 `WorldGameMap` 门面；未摆放的子地图为无效目标。

### 大地图门面与入口校验

- **统一世界视图**：`Scene:getGameMap()` 与 `Actor:getMap()` 暴露同一个世界坐标 `GameMap` 门面。子地图摆放（placement）提供通行性、Dir4 边缘、材质与地形，未覆盖的格子视为可通行的空洞。子地图数据缺失或不一致均会抛出错误。
- **大地图显示名**：门面从 `_world.json` 中必填的 `worldName` 读取 `mapName`，使玩家 HUD 等界面显示整个大地图的名称而非某张流送子地图。子地图仍保留自身 `mapName` 供单独加载使用。
- **入口重校验**：进入大地图时，运行时会重新校验扁平大地图目录、精确的 `_world.json` 文件名、必填 `worldName`、直接存放的 JSON 子地图文件、摆放记录与图层顺序。无关的非 JSON 普通文件会被忽略，非法数据会导致加载失败。

### 流送、模拟与转场

- **子地图生命周期**：流送子地图依次经历 `Unloaded`、`Reading`、`Prepared`、`Active` 与 `Dormant` 状态。流送优先处理摄像机邻域、取消过期读取，并通过[区域构建器的异步资源请求](<../全局与 Core 模块/Global APIs/GameMap.md#地图数据与区域构建器>)准备图块集与自动图块。
- **模拟与就绪屏障**：仅 `Active` 状态的 Actor 参与模拟（视口之外的 `Active` Actor 同样参与模拟但不渲染）。在所有可见摆放与图块分块（tile chunk）就绪前，摄像机保持上一帧完整画面，带碰撞的移动也无法进入未就绪区域。
- **进入转场**：启用转场时，进入大地图会冻结切出画面，直至目标视口及其必需的 Actor、光源与图块分块全部就绪；必需数据错误会在解除冻结前抛出。设置 `blockTransition = true` 可跳过转场遮罩但保留就绪屏障，周边区域的流送仍异步进行。
- **楼层传送数据**：`RegionDict` 仅定义楼层传送顺序，不描述组合式大地图的布局或流送规则。

### 地图装配与持久化状态

`Source.SceneComponents.MapBuilder` 负责项目地图装配并提供大地图区域工厂，而通用地图数据类型与 `Global.WorldGameMap.RegionBuildState` 接口归属 `Global`（参见[地图数据与区域构建器](<../全局与 Core 模块/Global APIs/GameMap.md#地图数据与区域构建器>)）。

普通地图加载与相邻楼层通行性预览共用 `MapBuilder:applyPersistentState(gameMap, inst, mapFile)`。该方法依次恢复地形改动、新增 Actor、已记录位置以及已销毁 Actor 的移除，期间不触发 Actor 的 `onCreate`；运行中的场景在绑定地图与玩家之后再启动存活 Actor。场景与组件所有权见 [SceneMap](<../源码类/SceneMap.md#scene>)。

## 配置继续游戏

标题命令窗口首次构造时会检查 `Engine.getSavePath()` 目录：

- 若目录中存在任意直接条目（即使是无关文件或子目录），默认预选**继续游戏**（`index = 1`）。
- 若目录不存在或为空，默认预选**开始游戏**（`index = 0`）。

此检查不解析存档文件，也不按格式筛选。语言刷新以及从设置或存读档窗口返回时会保持当前选中项；重新构造标题窗口时会再次检查该目录。

**继续游戏**通过 `GetSavePath(slot)` 读取当前构建所选的普通或加密存档，恢复游戏状态并打开已保存场景。存档缺失、损坏或不受支持时，会走明确的“未找到”或错误路径，不会构造残缺状态。

## 保持场景切换

请始终通过文档记录的 System 与场景 API 切换场景。C++ 运行时在帧更新间隙调度场景切换，确保活跃的逻辑帧不会被中途销毁，切出场景的窗口与临时资源也通过场景生命周期干净释放。

## 自定义标题

可根据项目需要修改标题 Lua 场景、窗口组合与 JSON 资产，确保所有文本键符合[游戏本地化工作流](<../../插件开发与安装/官方插件/游戏本地化工作流.md>)。

> **注意**：默认玩法不强制规定通用的存档升级策略或标题界面布局。发行前请根据产品需求自行定义受支持的存档版本、界面呈现与错误恢复提示。

# 运行时数据、配置与存档

本页说明默认玩法的配置文件、数据服务启动契约、运行时状态与持久化模型、组合式大地图存档记录，以及 `.json`/`.ldc` 存档格式。

## 配置

`Data/Configs` 存放项目配置 JSON，可变的用户偏好设置保存在[当前平台的游戏配置](<../../编辑器用户指南/项目设置与资产布局.md#游戏配置>)中。请通过配置 API 与编辑器控件读写配置，以确保未知配置节和键在往返读写后得以保留。

> **注意**：可选的[远程账号字典](<../../简易服务器/原生客户端 API.md>)属于独立服务，不会自动上传、下载或覆盖本地存档；需要读写的字段由玩法代码显式决定。

### 路径、常量与键名

- **配置资源与数据引用**：资源型 `file` 字段存储完整的 `/Game/Assets/...` 路径（`base` 与 `ext` 仅约束编辑器选择器）。在 `System.json` 中，`startPlayerBlueprint` 相对于 `Data/Blueprints`（`root = "Data"`，解析为 `Data.Blueprints.*`），`startRegion` 指定起始区域；两者仅作用于新游戏，存档会保留各自记录的玩家类与区域。
- **引擎常量与 Lua 配置模块**：网格单元尺寸在引擎编译时确定（默认 `32`，通过 `Engine.GetCellSize()` 读取，不在 `System.json` 中配置）。Lua 配置模块位于 `Scripts/Source/Configs`（`Source.Configs.*`）。`Source.Locale.Core.DEFAULT_LANGUAGE`（`en_GB`）为共享的初始与回退语言（`Source.Configs.Main` 亦沿用该值）；`Source.Configs.MapConstants.WORLD_MANIFEST_FILE` 为 `"_world.json"`；数据读取与存档统一使用 `Engine.ResourceFileConstants` 中的后缀。
- **初始数据键**：键名为相对于所属类别目录的路径，使用 `/` 分隔并仅去除末尾扩展名，保留内部点号（例如 `folder.v1/item.v2.json` 对应 `folder.v1/item.v2`）。动画键去除完整的 `.anim.json` 缓存后缀。
- **用户数据目录**：在 `Entry` 调用 `Engine.setAppName(APP_NAME)` 之后，`Engine.getUserDataPath(appNameOverride?)`、`Engine.getMainConfigPath(appNameOverride?)` 与 `Engine.getSavePath(appNameOverride?)` 分别解析用户数据根目录、配置文件路径与 `Save/` 目录。传入 `appNameOverride` 可查询其他应用名称而不改变当前应用名。所有启动模式均遵循相同的[目录规则](<../../编辑器用户指南/项目设置与资产布局.md#游戏配置>)，`LUDORK_EDITOR` 不会重定向这些路径。
- **加载用户配置**：`Source.Configs.Main.LoadOrCreate()` 返回用户配置路径与 `ConfigParser`；文件缺失时按当前平台默认值创建，遇到无法读取或损坏的 plist 文件时抛出错误而非直接覆盖。入口脚本选择独立于用户偏好（参见[入口与模块顺序](<../Lua 运行时与模块.md#入口与模块顺序>)）。
- **Android 路径**：Android 会在原生启动前将不可变运行时资产镜像到 `filesDir/ludork/runtime/<runtime-hash>`，并将可变配置与存档写入 `filesDir/ludork/user-data/<APP_NAME>`，既不修改运行时目录，也无需外部存储权限。

### 共享玩法配置

`Data/Configs/Gameplay.json` 保存针对共享脚本默认值的项目级覆盖项，可在[数据库 → 系统配置 → Gameplay](<../../编辑器用户指南/项目设置与资产布局.md#系统配置>) 中编辑。

| 键 | 类型 | 脚本默认值 | 效果 |
|---|---|---|---|
| `enemyDamageHintLevel` | `Enums.DamageHintLevel` | `BATTLE`（`1`） | 设置 `EnemyDamageText.EnemyDamageHintLevel`：`NONE`（`0`）隐藏预计伤害提示，`BATTLE` 显示敌人伤害读数，`MAP`（`2`）额外显示移动危险格的合计伤害。提示受所需物品持有状态控制；实际受击伤害粒子不受影响。 |
| `enemyDefeatShatterEffectEnabled` | 布尔 | `true` | 设置 `Enemy.DefeatShatterEffectEnabled`，控制[敌人击败粉碎特效](<资源、音频、视频与特效.md#着色器雾与转场>)。 |
| `hideDisconnectedRegions` | 布尔 | `false` | 设置 `GameMap.HideDisconnectedRegions`，为新构造的普通地图启用[非连通区域图块遮罩](<../全局与 Core 模块/Global APIs/GameMap.md#非连通区域隐藏>)。 |
| `enableShopRecord` | 布尔 | `true` | 设置 `GameInstance.EnableShopRecord`。关闭后停止新增商店记录并停用[已访问商店快捷入口](<窗口、菜单、输入与控件.md#已访问商店>)，不删除已有记录。 |
| `maxSaveSlots` | 正整数 | `100` | 设置 `WindowSaveSlot.MAX_SAVE_SLOTS`，用于存档槽列表及快捷存档、快捷读档与最新存档查询。调小后仅隐藏更大编号的槽位，不删除文件。 |
| `tutorialShrinkDuration` | 有限正数（秒） | `0.25` | 设置 `WindowTutorial.SHRINK_DURATION`，即教学遮罩收缩耗时。 |

- **JSON 覆盖 Schema**：字段使用字符串 `type`（`"int"`、`"float"`、`"bool"`），通过 `nullable: true` 允许沿用脚本默认值，通过 `enum: "Enums.DamageHintLevel"` 指定枚举选项。覆盖值保存在 `value` 中，不另设 `useDefault` 标志；新建 Gameplay 文件的所有覆盖默认均为 `null`。
- **`null` 与具体覆盖值**：`null` 选择**使用默认值**（保持脚本默认值生效，不赋值 `nil`），显式 `false` 与 `0` 属于具体覆盖（`0` 对伤害提示表示 `NONE`，但对要求正数的字段会触发校验失败）。移动速度、`GameMap.MapViewRect` 等 Actor 与地图默认值仍保留在各自的类或蓝图属性上。
- **`scriptDefault` 源码引用**：每个可空字段须声明 `scriptDefault: { module, field }`，指向 `Scripts` 下的 Lua 文件与其中的 `table.field` 赋值（例如 `Controller.MAX_SAVE_SLOTS`）。编辑器在不执行 Lua 的前提下解析唯一的无条件顶层赋值（支持标量字面量、导入的枚举成员或简单标量算术）；文件缺失或表达式不受支持时保持勾选**使用默认值**并报告错误。
- **启动应用与运行时覆写**：`Source.System.Init()` 会调用 `Source.Configs.Gameplay.Apply()` 校验所有字段，遇到无效类型、枚举值或范围时直接中止启动。修改 JSON 后需保存并重启游戏（Lua 热重载不会重读）。脚本可在运行时直接切换 `GameInstance.EnableShopRecord`，不会清空已记录的商店。

## 数据服务

`Global.Data` 负责共享数据加载、资源查询、蓝图类与图、Actor 构造以及静态预览，使用时请直接 `require`。`Source.Data` 负责项目启动、默认通用数据查询（如 `GetGeneralPlayerData`、`GetGeneralItemData`）及 `CreateGeneralAttributeSet(typeName, memberID)`。

`Source.Data.InitializeRuntime()` 在每个 Lua 会话中调用 `Global.Data.InitializeRuntime(options)` 一次（重复调用会抛出错误；仅 `require` 任一模块不会触发初始化）。自定义项目必须在启动阶段传入 `Global.Data.RuntimeOptions` 的全部四个必需字段：

| 必需选项 | 类型与用途 |
|---|---|
| `configResolver` | `(configName: string, settingName: string) -> string`；为空字符串覆盖项解析配置引用。 |
| `nodeModuleCandidates` | `(prefix: string) -> string[]`；按搜索顺序返回额外节点模块路径（优先尝试无前缀路径）。 |
| `conditionalActorBase` | `Class.ClassType<Engine.Actor>`；条件 Actor 基类，其子类在预览中暴露 `conditionVariable`、`conditionOperator` 与 `conditionValue`。 |
| `childActorComponentBase` | `Class.ClassType<Engine.Component>`；子 Actor 组件基类，其子类在预览中通过 `childActorComp` 提供 `className` 与 `relativePosition`。 |

两个基类选项必须传入已完成构造的类对象（而非模块名字符串或实例），并分别满足针对 `Engine.Actor` 与 `Engine.Component` 的 `Class.isSubclass` 检查。默认玩法传入 `Source.System.GetConfigValue`、按序搜索 `Source.` 与 `Global.` 的节点候选函数、`Source.MapActors.ConditionalActor` 及 `Source.Components.ChildActorComponent`，确保 `Global` 不依赖 `Source`。配置提供程序由 `Source.System.InstallRuntimeProviders()` 单独注册。

## 运行时状态

静态定义应保存在蓝图、配置与通用数据文件中，可变会话状态保存在 `GameInstance`、Actor 与组件上——切勿将临时状态写回源 JSON。

- `Global.Data.GetClassData(path)` 返回共享会话定义，参见[类定义与会话生命周期](<../蓝图脚本/执行流、事件与变量.md#类定义与会话生命周期>)。
- 使用 `Source.Configs.GeneralDataTypes.Create` 构造通用数据属性集，类型键来自 `Enums.GeneralDataKey`，成员键来自 `Enums.GeneralData.<TypeName>`（如 `Enums.GeneralData.Item`）。编辑器从实时数据解析这些枚举，并在保存时与 `Enums.Animation`、`Enums.Particle` 一并重新生成 Lua 模块，参见[通用数据与文本配置](<../../编辑器用户指南/通用数据与文本配置.md>)。

### Actor 静态显示数据

`Global.Data.GetActorPreviewData(classPath, classVarChanges?)` 返回 `Global.Data.ActorPreviewData`（空路径返回 `nil`；无效路径与非 `Engine.Actor` 类会抛出错误）：

- **解析流程**：合并蓝图与 Script Mixin 的继承默认值，随后按类型转换应用已声明的显示与条件覆盖。未知覆盖名称会失败；无关玩法值与 `BlueprintOnly` 覆盖会被跳过。
- **返回记录**：包含纹理与材质路径、首帧 `rect`、`translation`、旋转角度（度）、`scale`、`origin`、`visible`、`materialParameters`、条件字段，以及可选的递归 `child` 与 `childOffset`（来自声明式 `childActorComp`，循环引用会抛出错误）。每次调用均返回表及可变 `sf` 向量/矩形的独立副本，防止修改共享模板。
- **无玩法副作用**：提取过程既不构造玩法 Actor、不实例化图、不加载纹理、不触发组件或生命周期回调，也不初始化战斗状态。调用 `Global.Data.ClearActorPreviewCache()` 可丢弃已缓存的类显示模板而不影响共享类定义（清空楼层预览缓存时会自动调用）。

### 玩家

- **队伍存储与顺序**：`GameInstance` 在 `_playerKeys` 中维护有序键列表，在 `_players` 中存储玩家对象，以非空且唯一的 Player 通用数据键（`Player.ID`）为键。`getPlayers()` 返回实时字典；`getPlayerKeys()` 返回实时顺序（首键即 `getPlayer()` 返回的主玩家）。`getPlayerByIndex()` 解析零起始索引；`setPlayer(playerKey)` 与 `setPlayerByClass(playerClass)` 将已有成员提升为主玩家；`addPlayerByClass(playerClass, mapPath, position)` 追加成员及其必需的地图与格坐标；`removePlayerByClass` 会同步删除该键记录的地图。
- **玩家序列化**：存档镜像 `playerKeys` 与 `players`（每个键必须精确对应一条 `Player.ID` 相同的记录），并在 `attr` 同级要求字符串字段 `customName`（`""` 表示使用本地化通用数据默认名；非空值须预先去除首尾空白并符合 [Source.MapActors.Player](<../源码类/Player.md>) 的规则）。
- **持久化属性与背包**：每名玩家通过 `getNumericAttributeBases()` 在 `attr` 下保存有限数值型 Attribute Set Base（须匹配生成的 `int`/`float` Schema；旧存档缺失的键沿用初始 Base，派生 Current 值不保存，非数值字段从 Player 通用数据重建），并保存物品/装备数量、已装备 ID 与状态层数。
- **读档重建顺序**：读取时先恢复 Base 值，再依次恢复物品能力、装备效果与状态效果，不执行初始装备或成员图。句柄、派生 Current 值、临时效果、能力规格（spec）与标签均不保存——如需持久化自定义状态，请另行设计记录与重建逻辑。

### 游戏变量

初始游戏变量加载自生成的 `Scripts/Source/Configs/GameVariables.lua`（启动前请先在[游戏变量管理器](<../../编辑器用户指南/通用数据与文本配置.md#游戏变量管理器>)中保存修改）。列表与字典的初始值为普通 Lua 表而非 Standard 容器；空表经过 JSON 往返序列化后可能无法保留数组或对象形态。

- **新游戏与读档**：`GameInstance:init` 深拷贝生成的映射表，确保每次新游戏独立初始化（默认玩法声明了 `MTExample = 0` 与 `ShopPrice = 20`；运行时代码可写入动态键，但仅编辑器声明的键会出现在 `InstVar` 选择器中）。读取存档会整体替换变量表——生成的初始值仅用于新游戏，新增、删除或修改声明类型均不会迁移既有存档（修改类型仅重置项目初始值）。
- **受监听字段**：快照捕获逻辑值，同时 `deepcopy` 会剥离监听代理与订阅，使 `ConditionalActor` 监听器仅限当前会话。读档后 `onCreate` 自动重新订阅并重算可见性，无需额外存档字段。

### 地图 Actor 身份

- **地图标签**：地图 JSON 中的摆放 `tag` 成为 `Actor:getMapTag()` 读取的地图持久化标签——`GameMap:getActorByTag` 与 `GameInstance` 持久化均只使用该标签，与 `Actor.tag` 保持独立。无地图标签的 Actor 不会被持久化，记录中的地图路径统一经 `Global.Utils.MapPath.Normalise` 规范化。
- **新增与销毁记录对**：需跨越地图重建存活的运行时生成 Actor 会以生成的摆放标签写入 added 记录；销毁它们时写入的 destroyed 记录会屏蔽该 added 记录（`Reborn` 敌人复用同一机制，而不重用原标签）。
- **组合式大地图标签**：大地图运行时标签在摆放区内使用 `<child-file-stem>.runtime_default_<N>`，在空洞中使用 `<world-directory>.runtime_default_<N>`；所有标签在大地图存续期内保持预留，冲突会抛出错误。编辑器标签在全大地图范围内唯一，且在地图重命名后保持稳定。
- **类型化覆盖**：地图 `BPClassVarChanged` 与持久化 `classVarChanges` 仅保存经元数据、Script Mixin 与 `attrDefs` 解析出的已声明类字段值。未知字段名或 Schema 不匹配会导致加载失败；枚举覆盖保存底层标量，向量与记录应用类型化转换。

### 组合式大地图持久化

- **清单身份**：即使从子地图进入，主玩家的 `map` 条目仍保存 `_world.json` 清单路径。玩家、新增、移动与销毁记录统一使用清单身份、世界坐标与全局标签；存在冲突的新增或移动记录会导致加载失败。
- **恢复 Actor**：新增 Actor 若在 `actorPositions[tag]` 中存在记录则于该处生成，否则在原位置生成；已销毁标签直接跳过。摆放区 Actor 随对应子地图恢复，无需触发远处子地图 I/O；空洞中的 Actor 可立即恢复。
- **跨子地图移动的根 Actor（`worldMovedActors`）**：只要任意玩家的存档地图为大地图清单，存档就必须包含 `worldMovedActors`。该字段记录离开定义子地图的原始根 Actor（身份、当前所属对象、图层覆盖与世界坐标），并仅在其当前所属对象处重建；回到原位或被销毁时移除该记录。移动快照保留重建身份、`classVarChanges`、图层与位置，不保留任意 Lua 字段或计时器进度（需单独持久化或在 `onWorldWake` 中补算流逝时间）。
- **屏蔽与地形改动**：销毁某个标签会移除其移动记录，并在不加载缺失子地图的前提下屏蔽原始、新增、驻留及进行中的实例（标签继续保留；无效记录或冲突会失败）。地形改动保存子地图路径与局部坐标，在该子地图构建时应用并仅更新受影响的存活图层（空洞不可拥有地形改动）。

## 存档

默认玩法的存档 Schema 版本为 `1`（数值 `1`）。`SaveCodec` 仅接受当前结构与版本，直接拒绝不兼容存档而不做迁移。Schema 版本独立于应用版本及打包开发选项：开发破坏性格式变更期间请使用 `vN-dev`，发布前冻结为 `vN`。

> **注意**：[实时调试](<../../编辑器用户指南/运行、调试与打包.md#实时调试>)不会修改项目文件或存档 Schema，但在调试会话中执行存档会持久化受实时编辑影响的玩法状态。

### 存档数据集合

- **`telepoints`**：将规范化地图路径（大地图使用清单路径与世界坐标）映射到有序 `{ position = {x, y}, tag = "raw tag" }` 记录（运行时坐标为 `sf.Vector2u`，标签为未本地化字符串）。`GameInstance:recordTelepoint(mapPath, position, tag)` 为每个 `(map, position)` 保留首条记录；`getTelepoints(mapPath)` 返回对应记录，`getVisitedMapPaths()` 返回排序后的路径副本，`getTelepointsForMap(key)` 忽略扩展名匹配并返回副本。
- **`triggeredTutorials`**：按开始显示顺序存储去重后的引导键（运行时为 `list<string>`，存档为保留 `[]` 形态的 JSON 数组）。加载时会校验原生读取器的 `n` 计数与数组元素一致，拒绝空洞或非法键。`hasTriggeredTutorial(key)` 查询记录，`recordTriggeredTutorial(key)` 在遮罩开始收缩时记录一次（排队期间不记录）。缺少该字段的旧 v1 存档按空列表读取。
- **`shops` 记录格式**：共享的 `[mapPath, mapTag]` 二元组数组，采用规范化地图/清单路径与 `Actor:getMapTag()`。条目按完整二元组去重并保持首次访问顺序，空集合保存为 `[]`（缺少 `shops` 的旧 v1 存档按空读取）。
- **`shops` API 与事件**：`GameInstance:getShops()` 返回副本；`recordShop(mapPath, tag)` 在 `GameInstance.EnableShopRecord` 开启时追加记录（商店成功打开即记录，无需完成购买，参见[已访问商店](<窗口、菜单、输入与控件.md#已访问商店>)）；`removeShop(mapPath, tag)` 即使在关闭记录功能后仍可移除记录。两个方法均返回列表是否变更，仅在真实变更时发布 `Enums.EventKey.ShopRecordsChanged`（`Source.Configs.ShopRecordsChangePayload`，`{ instance = self }`），订阅方可据此比对 `instance`。移除后再次访问同一商店可重新记录。
- **`map`**：以 `playerKeys` 为键的对象，每名成员必须有且仅有一条非空规范化地图路径（多余键会导致加载失败）。`GameInstance:getCurrentMapPath()` 返回主玩家地图或 `nil`；`applyMapInfo` 写入该条目；`restoreFromData(data)` 应用校验通过的存档。

### 存档格式、加密与界面契约

- **格式选择（`SAVE_AS_LDC`）**：`false`（默认）写入明文 `.json`，`true` 写入压缩混淆的二进制 `.ldc`。**加密存档内容**决定 C++ Source 发行包的原生默认值。任何项目（包括 Standalone 项目）均可在 `Scripts/Entry.lua` 顶部、所有 `require` 调用之前通过 `SAVE_AS_LDC = true` 或 `false` 覆盖该设置；`Source.Save` 在首次加载时捕获该值并忽略后续赋值。
- **LDC 编解码与加密**：`Source.Save` 通过 `Engine.saveData` 与 `Engine.loadData` 读写，直接将 `.ldc` 解码为运行时数据而无需经由中间 JSON（不支持旧版压缩 JSON 格式的 `.ldc` 存档）。存档加密独立于项目 JSON 加密，但在打包选项中统一归入**加密游戏数据**。
- **读档与预览**：`GetSavePath(slot)` 返回当前格式下从 1 开始的槽位路径。预览信息异步加载，不构造玩法对象；确认读档时才调用 `Save.LoadGame(filePath)`。
- **存读档窗口**：`open` 的 `initialMode` 接受 `Enums.SaveLoadMode.LOAD`（`"load"`，默认）或 `.SAVE`（`"save"`；仅读档窗口保持读档模式）。关闭后 `onClose(reason)` 接收 `Enums.SaveLoadCloseReason.CANCEL`（`"cancel"`）、`.SAVED`（`"saved"`）或 `.LOADED`（`"loaded"`）。窗口展示加载中、空槽与失败状态，默认预选最近修改的槽位（无存档时选第 1 槽），并在打开动画结束后赋予焦点。新截图保持宽高比，最大为 `224 × 168` 像素（已有更大尺寸截图仍可读取）。

> **重要**：修改 `SAVE_AS_LDC` 不会重命名或迁移既有存档槽——请在发行前选定格式或自行实现迁移。存档版本升级、原子写入、备份、云同步以及自定义元组键记录格式均由项目自行负责。

## 数据边界上的原生容器

写入 JSON 或 LDC 之前，请先将 Standard 的 `list`、`tuple` 与 `dict` 转换为普通 Lua 表：

```lua
local Engine = require("Engine")
Engine.saveData("slot.ldc", payload:toTable())
```

解码任一格式均产出普通 Lua 表：数组通过 `n` 携带逻辑长度，根节点 `null` 与数组 `null` 槽位转为 `nil`，对象 `null` 字段保留 `cjson.null`。元组键字符串、`cjson.null` 处理与记录数组重建见 [Ludork Lua 进阶](<../../快速入门/Ludork Lua 进阶.md>)；切勿持久化内部元组哈希值。

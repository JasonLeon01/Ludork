# 装备与物品

配合稳定的背包 ID、匹配的职业槽位以及职责清晰的成员图，即可在 Item / Equip 通用数据与 `Source.MapActors.Item` / `Source.MapActors.Equip` 蓝图之间建立完整的物品与装备体系。

## 编写物品与装备

- **物品使用与堆叠**：在 Item 通用数据中启用 `usable` 允许从背包使用，设置 `cost` 控制堆叠数量显示；是否消耗物品由 `onUse` 图决定。
- **物品成员图**：将背包使用逻辑写在 `onUse`，将敌人掉落行为写在 `onDrop`（`GameplayEventData.target` 与 `self` 引脚规则见[物品](<../Actor、敌人、物品与装备.md#物品>)）。
- **装备槽位与加成**：每条 Equip 记录的 `slot` 必须与当前 Class 的槽位字典一致。固定属性加成写入 `attrPlus`，`onEquip` 与 `onUnequip` 图仅用于自定义附加效果。
- **图标存放**：物品与装备图标统一存放在 `Assets/Icons` 下，并通过资源选择器指定。

## 默认模板示例

- **装备（`BP_Equip_Sword_A.json`）**：继承 `Source.MapActors.Equip` 并设置 `ID = "Sword_A"`，关联对应的 Equip 记录。`attrPlus`、`onEquip` 与 `onUnequip` 的执行顺序见[装备](<../Actor、敌人、物品与装备.md#装备>)。
- **物品（`BP_Item_Key_Y.json`）**：继承 `Source.MapActors.Item` 并设置 `ID = "KEY_Y"`，同时匹配 Item 数据记录与黄门的 `needKeyID`。
- **能力归属与读档恢复**：持有物品时自动授予其 `onUse` 能力，移除最后一件时撤销；`Player:activateItem` 以该玩家为目标。[读档流程](<../运行时数据、配置与存档.md#玩家>)会直接恢复已保存的能力与效果，不会重放 `onUse`、`onDrop`、`onEquip` 或 `onUnequip` 图。

> **重要**：重命名通用数据成员不会自动更新已保存的蓝图或地图引用。职业槽位不匹配与未知记录 ID 都会触发明确的数据错误。

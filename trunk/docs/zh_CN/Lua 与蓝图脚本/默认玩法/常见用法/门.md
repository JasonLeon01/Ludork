# 门

使用 `Source.MapActors.DoorBase.DoorBase` 配合门的精灵图集以及物品或游戏变量标识符，可以创建需要钥匙开启或满足变量条件后自动开启的地图门。

`DoorBase` 继承 `tickable = false`，仅在开门或反向关闭动画播放期间启用逐帧更新。开门动画结束后，只要地图摆放标签非空，`DoorBase` 就会将其记录为已销毁，确保地图重建和读取存档后该门保持开启状态。

## 钥匙门

1. 从 `Source.MapActors.DoorBase.DoorBase` 派生通用门基类蓝图，配置纹理、源矩形、碰撞与开门默认参数。
2. 再派生按颜色区分的门蓝图——例如默认玩法中的 `BP_Door_Y.json` 继承自 `BP_Door_General`，并设置 `needKeyID = "KEY_Y"`。
3. 在 `onCollision` 中先判断门是否正在开启（若是则直接返回），并校验 `MeetPlayer`。
4. 读取 `needKeyID`，调用 `GetItemCount` 检查钥匙数量是否不小于 `1`。
5. 满足条件时，通过 `SUPER` 调用父类碰撞流程并扣除一把钥匙；失败分支可留空或连接自定义提示。

`needKeyID` 必须同时与 Item 通用数据成员及其拾取蓝图保持一致（例如 `KEY_Y` 与 `BP_Item_Key_Y.json`）。

## 条件门

将 `Mixins/Doors/ConditionDoor.lua` 挂载到 `DoorBase` 蓝图后，运行时会持续轮询 `openConditionName` 并与 `openConditionVal` 比较：

- `openConditionName` 为空时禁用轮询；指向尚未初始化的变量时按初始值 `0` 处理。变量达到 `openConditionVal` 时调用 `openDoor`。
- `openConditionName` 使用仅限数值的 `InstVar` 选择器，仅列出游戏变量管理器中的 `int` 与 `float` 条目；`openConditionVal` 使用 `InstVarValue`，自动匹配所选变量的数值输入控件。默认玩法内置了 `MTExample = 0` 供测试。

> **注意**：门不负责跨地图切换，场景传送请使用 `Teleporter`。重命名钥匙 ID 或游戏变量后，需要手动更新所有已保存的门引用。

# 默认模板概述

Game 项目提供可运行的默认玩法，也是新建项目模板的来源。可在此基础上定制游戏规则、界面与资产。

## 入口与模块

应用名称与发行设置遵循[打包规则](<../../编辑器用户指南/运行、调试与打包.md#打包>)。`Scripts/Entry.lua` 负责初始化运行时并将控制权交予原生主循环；原生模块加载顺序见[入口与模块顺序](<../Lua 运行时与模块.md#入口与模块顺序>)。

启动流程会显式调用下列函数——仅 `require` 对应模块不会初始化服务：

| 调用 | 职责 |
|---|---|
| `Engine.setAppName(...)` | 在加载项目模块前设置应用的用户数据目录与资源覆盖。 |
| `Source.Locale.Core.Init()` | 在读取配置与选择语言前加载本地化字典。 |
| `Source.Configs.Main.LoadOrCreate()` | 读取[当前平台的游戏配置](<运行时数据、配置与存档.md#配置>)，文件缺失时以默认设置创建。 |
| `Source.Data.InitializeRuntime()` | 向 `Global.Data.InitializeRuntime(options)` 传入项目回调与预览基类，在首个场景前创建共享数据服务并注册数据与蓝图提供程序。 |
| `Source.System.InstallRuntimeProviders()` | 在首个场景前注册配置提供程序。 |
| `Source.System.Init()` | 应用游戏、音频与[共享玩法配置](<运行时数据、配置与存档.md#共享玩法配置>)，并在进入原生主循环前通过 `GlobalCore.Display` 准备显示资源。 |

`Entry` 还会在构造 `SceneInit` 之前初始化 Latent 图与原生 System。提供程序每个会话仅注册一次；[Lua 热重载](<../Lua 运行时与模块.md#lua-热重载>)不会重新执行启动流程。配置与存档路径见[运行时数据、配置与存档](<运行时数据、配置与存档.md>)。

### `SceneInit` 启动图与缓存准备

每次启动时，`SceneInit` 会淡入一张全屏启动图，灰色背景中央以白字显示 `"Made With Ludork Engine"`：

- **显示时序**：淡入耗时 `0.30` 秒，完全显示至少 `0.20` 秒（若初始缓存检查尚未结束则持续等待直至完成），随后用 `0.25` 秒淡出，再显示常规的 Init 背景、进度条与阶段提示。
- **准备阶段**：淡入期间，`SceneInit` 检查哪些材质需要导出、哪些着色器需要编译、哪些动画需要压缩。其[必需任务](<../../快速入门/Ludork Lua 进阶.md#协作任务与文件批次>)按顺序执行这三个阶段（自动跳过无需执行的阶段），随后加载共享游戏数据。
- **进度与完成**：每个实际执行的阶段平分进度条，条下方显示跟随当前游戏语言的提示文本。当所有缓存均已最新时，唯一提示为“正在加载游戏数据…”。任务完成后进入标题场景；任一必需步骤失败均会中止启动。参见[规划图形缓存](<../全局与 Core 模块/Core Modules/Engine/地图与材质.md#规划图形缓存>)。

移动端后台切换与恢复行为遵循 [SceneBase 生命周期](<../全局与 Core 模块/Core Modules/GlobalCore/场景与系统.md#scenebase>)。

## 玩法布局

| 路径 | 职责 |
|---|---|
| `Scripts/Global` | 共享基础设施（`Global.Data`、`Global.Audio` 下的地图音频、`Global.Utils.MapPath`），通过[数据服务](<运行时数据、配置与存档.md#数据服务>)契约与项目启动及玩法查询解耦。 |
| `Scripts/Source/MapActors` | 可复用的地图 Actor 类。 |
| `Scripts/Source/Utils` | 玩法辅助模块，包含 Enemy 与 GameInstance 的实现模块及 `Source.Utils.AnimationCache`。场景、窗口与组件保留在 `Scripts/Source` 各自目录中。 |
| `Scripts/GlobalFunctions` | 独立的 Lua 蓝图函数库（路径以 `GlobalFunctions.` 开头，独立于原生根模块）。 |
| `Scripts/Internal` | 实时调试与 UI 基础层，包含共用窗口基类。 |
| `Scripts/Internal/UI` | 由**导出**从 `Data/UI` 生成的 Lua View。生成的 UI 与语言文件不随模板分发，也不纳入版本控制；首次运行前请先导出项目（参见[声明式 UI 编写工作流](<../声明式 UI/编写工作流.md>)）。 |
| `Scripts/Mixins` | 可直接附加的 Script Mixin 模块及配套 `_meta.lua` 文件。 |
| `Data/Blueprints` | 游戏专用的 Actor 蓝图类。 |
| `Data/Materials` | 源材质节点图；`SceneInit` 会在用户数据目录中构建运行时着色器与元数据（模板仅包含源图，不含缓存）。 |
| `Data/General` | 物品、敌人、装备、职业、玩家、状态与特殊效果的通用数据数据库。 |
| `Data/Maps`、`Data/Tilesets` | 可玩地图与图块集定义。 |
| `Engine/` | 原生 C++ 运行时、模块与依赖。 |

原生源码的归属与依赖见[构建与模块布局](<../../C++ 原生开发/构建与模块布局.md>)。

## 模板变体

根据[项目模板](<../../快速入门/项目模板.md>)选择 C++ Source 项目或 Standalone 项目变体。更新 Game 项目不会自动修改既有项目，需要逐项目同步变更或重新生成模板。

已有的 C++ Source 项目可[转换为 Standalone 项目](<../../编辑器用户指南/运行、调试与打包.md#将-source-转换为-standalone-项目>)，同时保留已编写的玩法、声明与当前导出文件。Lua、`Scripts/stub` 与 `_meta.lua` 的所有权规则见[Lua 运行时与模块](<../Lua 运行时与模块.md>)。

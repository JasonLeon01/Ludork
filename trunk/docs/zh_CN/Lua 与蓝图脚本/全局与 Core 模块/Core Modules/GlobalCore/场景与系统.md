# GlobalCore：场景与系统

本页记录 `SceneBase` 生命周期与计时器 API，以及 `GlobalCore` 下的静态运行时服务：`System`、`Display`、`Graphics`、`ScreenEffects`、`Transition`、`SceneManager` 与 `RuntimeDiagnostics`。`SceneBase` 方法表格省略作为首个蓝图目标引脚暴露的隐式 `self` 接收者；其下所有运行时服务均为静态类型，方法不接收调用对象。

## SceneBase

玩法场景基类，管理逐帧回调、UI 管理器、动画与计时器。

- **线程模型**：在 HarmonyOS 上，游戏线程依次执行 `onTick`、推进本帧到期的 `onFixedTick` 步长并渲染画面。WebGL 在浏览器主线程上运行同样的回调与渲染。其他原生宿主则在专用场景逻辑工作线程中运行场景逻辑，由游戏线程负责渲染。
- **窗口关闭**：在运行时更新或输入处理期间（含输入或 UI 回调中）关闭窗口时，当前帧会在后续 UI 更新、发射器模拟或渲染前立即结束，随即停止场景逻辑并按正常场景退出生命周期调用 `onQuit`。
- **失焦与挂起**：在 Android、iOS、HarmonyOS 与 WebGL 上，窗口失焦（或 Web 页面隐藏）会暂停场景与 UI 更新、渲染、运行时回调与场景计时器，同时继续处理系统事件。同一进程返回前台时保留场景与 Lua 状态，重置帧更新与固定更新时钟并直接恢复，不补算后台经过时间。关闭应用仍遵循正常退出生命周期。

### 场景计时器

`scene:addTimer(interval, task, params, blocking)` 返回 `Engine.AsyncOperation`。到期时先执行 `task`，再以 `true` 完成并恢复蓝图 `TimeUp` 分支。

若回调抛出 Lua 运行时错误，引擎会记录 Lua 调用栈、取消该操作并解除其输入阻塞；等待方遵循[操作取消规则](<../Engine/事件与模块根.md#asyncoperation>)，同一轮更新中到期的其他计时器仍正常继续执行。

仅限 Lua 的 `scene:cancelTimers()` 取消所有未完成计时器并清除其输入阻塞。在计时器回调内部调用它时，还会取消当前操作并跳过余下未执行的回调。场景退出或销毁时会自动取消计时器。

## Display

`GlobalCore.Display` 负责窗口、逻辑尺寸、显示缩放、输入法与画面呈现设置。`Display.initializeDisplay(title, gameSize, iconPath, cursorPath)` 从 Lua 准备显示环境，不包含在蓝图元数据中。

### 显示缩放语义

- **配置缩放与有效缩放**：`getConfiguredScale()` 返回已配置的显示偏好（含默认值 `0`，表示全屏）。`getScale()` 返回应用最大渲染缩放后，渲染与输入实际使用的正数有效缩放。非有限值或负数会归一为 `1`。
- **应用与保存方法**：`setScale` 同时应用并保存该值；`applyScale` 仅应用；`saveScale` 仅保存。
- **桌面端窗口**：桌面端传入 `0` 选择无边框全屏且不更改显示模式；正数值设定固定尺寸的独立窗口（禁止拖拽边框缩放），必要时按宽高比以黑边居中显示。
- **macOS 渲染倍率**：配置的窗口缩放以 Cocoa 客户区 point 计量，而 `getScale()` 与 `Engine.GetScale()` 返回的有效渲染缩放基于实际可绘制像素（含 Retina backing scale）并受最大渲染缩放上限约束。Backing scale 变化时重建渲染目标并刷新文字，但不改变逻辑窗口尺寸。
- **可配置性（`isDisplayScaleConfigurable()`）**：独立桌面窗口（含 HarmonyOS 2-in-1）及开启自由多窗模式的 HarmonyOS 平板返回 `true`；嵌入式宿主、普通移动设备与 WebGL 返回 `false`。
- **WebGL**：画布尺寸由页面 CSS 与浏览器设备像素比（DPR）决定；配置缩放（包括 `0`）不会调整画布尺寸或请求全屏，最大渲染缩放仍限制内部渲染分辨率。
- **HarmonyOS 2-in-1 与自由多窗平板**：HarmonyOS 2-in-1 遵循桌面端协议（默认 `0`）。在 HarmonyOS 手机与平板上，ArkTS 宿主监听 `freeWindowModeChange`，并在开启自由多窗模式或处于该模式返回前台时重新应用配置缩放：正数值请求 `round(gameSize * scale)` 像素客户区（附加窗口装饰以确定外框 Stage 尺寸），`0` 请求最大化或全屏，保持禁止拖拽调整大小，若受系统尺寸限制则以居中黑边保持宽高比。
- **最大窗口化缩放（`getMaximumWindowedScale(gameSize)`）**：返回当前可用窗口空间可容纳的最大缩放——桌面端与 HarmonyOS 2-in-1 使用当前窗口的装饰工作区（无窗口时取主显示器），可配置移动端宿主则使用宿主提供的上限（HarmonyOS 自由多窗模式开启或恢复前台时刷新）。嵌入式宿主、不可配置移动端宿主、逻辑尺寸为零或可用尺寸未知时返回 `nil`。

### 抗锯齿语义

抗锯齿默认值为 `8`，无效值退回 SFML 默认值。`setAntiAliasingLevel` 仅保存该值而不重建当前上下文，并在下次初始化显示时生效。SFML 可能协商采用其他受支持等级。

### 帧率语义

`getFrameRate()` 返回配置的目标帧率（默认 `60`）。`0` 表示不限帧率并关闭主动限帧，但垂直同步仍独立生效并可能限制画面呈现。`setFrameRate` 同时应用并保存，`saveFrameRate` 仅保存。不限时固定更新步长为 `1/60` 秒，正数目标帧率下为 `1/framerate` 秒。

### iOS 图形上下文

iOS 启动时选择 Metal，见 [MRB 渲染](<../../../../C++ 原生开发/构建与模块布局.md#mrb-渲染>)。

## Graphics

`GlobalCore.Graphics` 负责渲染画布、视图、绘制、有序全屏着色器链与帧提交。

> **重要**：Graphics 画布纹理采用预乘 Alpha。自定义全屏着色器必须输出预乘颜色或不透明颜色。

### 最大渲染缩放语义

`getMaximumRenderScale()` 返回有效物理像素渲染缩放的上限：`0` 表示不限，默认值为 `2`，无效值同样退回 `2`。`setMaximumRenderScale` 在帧间生效而不调整窗口尺寸并同时保存；`saveMaximumRenderScale` 仅保存。

例如，逻辑尺寸为 `640×480`、配置缩放为 `1.5` 的游戏在 Retina 2× 显示器上对应 `960×720` Cocoa point 窗口：上限不限时按 `1920×1440` 渲染（有效缩放 `3`），上限为 `2` 时则在同一窗口内按 `1280×960` 渲染。

### 光照渲染倍率语义

`getLightingRenderScale()` 返回 `0.5`、`0.75` 或 `1`（默认 `1`，无效值同样取 `1`）。`setLightingRenderScale` 应用并保存该值，同时重建直接光照目标并使静态缓存失效；`saveLightingRenderScale` 仅保存。表面遮罩、透光率与占用保持全分辨率。

## Transition

`GlobalCore.Transition` 负责转场请求与冻结背景。`requestTransition` 接受空可选值或完整的 `/Game/Assets/Transitions/...` 逻辑路径，不自动补前缀。

- **完成时机**：`setTransition`、`freezeTransitionBackground` 与 `requestTransition` 均返回以 `true` 完成的 `Engine.AsyncOperation`。冻结请求在捕获转出画面后完成，转场在最后一帧提交后完成。蓝图需要 `Frozen` / `Finished` 分支时，请使用 [Transition 节点](<../../../节点函数/Transition.md>)。
- **取消规则**：发起同类型新请求会取消前一个未完成操作。`cancelTransitionBackgroundFreeze()` 取消冻结操作并清除冻结状态，而 `cancelPendingTransition()` 仅取消尚未应用的转场请求，不中断已开始的转场。运行时重置或关闭时会取消剩余操作。

## RuntimeDiagnostics

暴露仅限 Lua 的性能分析查询与采样记录器（`metadata = false`，不生成蓝图节点）：

| 方法 | 参数 | 返回值 | 说明 |
|---|---|---|---|
| `isPerformanceProfilerEnabled` | — | `bool` | 静态方法。仅限 Lua（`metadata = false`）。 |
| `recordWorldStreamingPerformance` | `queueDepth: int`, `reading: int`, `prepared: int`, `active: int`, `dormant: int`, `cacheBytes: int`, `publishMilliseconds: float`, `visibleTileChunks: int`, `activeActors: int` | — | 静态方法。仅限 Lua（`metadata = false`）。 |

原生性能输出还会在每条 `mainFrames` 记录中包含 `textureUpload`（帧纹理上传耗时，单位毫秒，包含图形上下文激活开销）以及 `textureStreaming` 对象：

| 字段 | 说明 |
|---|---|
| `cacheHits`、`mergedRequests` | 当前会话内命中已就绪纹理以及合并到在途工作的累计请求数。 |
| `decodedCount`、`uploadedCount`、`failedCount` | 当前会话内累计的 CPU 解码次数、GPU 上传次数以及解码/上传失败次数。共享工作按每次加载计数而非按订阅者计数；已启动的工作在取消后仍可能计入。 |
| `cancelledCount` | 当前会话内被取消的挂起订阅数。GPU 上传完成后释放句柄不会增加此计数。 |
| `decodeMilliseconds`、`uploadMilliseconds`、`uploadedBytes` | 累计读取/解码时间（毫秒）、GPU 上传时间（毫秒）与估算上传字节数。 |
| `pendingRequests`、`decodingRequests`、`readyRequests` | 当前排队、解码中以及已解码待上传的工作项数量。 |
| `readyBytes`、`peakReadyBytes` | 当前与峰值已解码像素积压字节数。不含解码器临时缓冲与 GPU 分配，因此不代表总内存占用。 |

已解码积压与每帧上传预算如何控制资源就绪，见 [TextureManager 调度限制](<资源管理器.md#textureloadrequest>)。

相关服务：天气与远景由 `WeatherController` 和 `PanoramaController` 管理；逐地图雾效位于各 `GameMap` 上（`getFogSettings()` / `setFogSettings(settings)`，见[地图与雾效](<地图与雾效.md>)）；音频开关与音量由 [AudioManager](<资源管理器.md#audiomanager>) 管理。

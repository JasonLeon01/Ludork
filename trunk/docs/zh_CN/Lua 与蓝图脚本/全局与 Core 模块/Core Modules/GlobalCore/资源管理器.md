# GlobalCore：资源管理器

本页记录 `GlobalCore` 下的原生静态资源管理器（`AudioManager`、`FontManager`、`ShaderManager` 与 `TextureManager`）以及仅限 Lua 的 `TextureLoadRequest` 句柄。各管理器方法均为静态方法且无接收者；`TextureLoadRequest` 方法为仅限 Lua 的实例方法。

所有通用管理器均要求大小写精确匹配的 `/Game/Assets/...` 路径，透明兼容未归档文件与 `.ldpak` 归档，并[优先读取用户目录资源](<../../../../编辑器用户指南/项目设置与资产布局.md#运行时资源查找>)。原生绝对路径、`Assets/...` 路径与类别相对路径均无效。

归档压缩对调用方透明：支持 seek 的流会逐块解压并报告原始文件大小与字节位置，且对每个加载的数据块以及完整文件读取均校验 CRC32。

`AudioManager.setEffect(audioType, effect)` 接受 `"Sound"`、`"Voice"` 或 `"Music"`，为该类别后续播放注册回调（传入 `nil` 清除回调；不影响已在播放的声源）：

- **回调契约**：签名为 `fun(source: sf.SoundSource, control: GlobalCore.AudioEffectControl, sampleRate: integer)`，其中 `source` 与 `control` 均非 `nil`。每个新声源在开始播放前按播放设备当前采样率调用一次，且必须恰好安装一个非空处理器（未安装或重复安装均同步失败）。
- **隔离 Lua 处理器**：调用 `control:attachLuaProcessor(source, moduleName, resolverName, effectName, sampleRate)`，传入三个项目必需提供的字符串（原生层无默认模块或解析函数）。每次挂接都会创建独立隔离的 Lua 状态，加载 `require(moduleName)`，调用 `resolverName(effectName)`，再以 `(nil, control, sampleRate)` 调用返回的 attacher 以生成 `sf.SoundSource.EffectProcessor`。
- **控制句柄与错误传播**：隔离状态中的控制句柄仅暴露 `isCancelled()`、`beginTail()` 与 `finishTail()`，不可再次挂接处理器。模块加载、解析与处理器创建错误会同步向上传播而不会退回无处理音频；后续音频回调中的错误则在管理器更新期间传播。
- **搜索路径与隔离**：隔离状态继承 `AudioManager` 初始化时捕获的模块搜索路径，因此须在加载 `GlobalCore` 之前配置额外路径。主状态中的闭包与对象无法传入音频状态。内建预设、播放生命周期与取消规则见[默认玩法音频](<../../../默认玩法/资源、音频、视频与特效.md#音频>)。

## TextureManager

支持同步（`load`）或异步（`request`）加载纹理。`request` 立即返回 `TextureLoadRequest`，文件读取、归档解压与图像解码在后台工作线程执行；运行中的 System 帧循环将已解码图像上传至 GPU 后再发布 Ready 状态。

> **重要**：发起纹理请求并不意味着纹理立即可绘制。请在后续更新中轮询句柄状态，切勿使用阻塞当前帧的循环等待。

### 函数与事件

| 方法 | 参数 | 返回值 | 说明 |
|---|---|---|---|
| `load` | `filePath: string`, `sRGB: bool = false`, `area: sf.IntRect = nil`, `smooth: bool = false` | `sf.Texture` | 静态方法。 |
| `request` | `filePath: string`, `sRGB: bool = false`, `area: sf.IntRect = nil`, `smooth: bool = false`, `priority: int = 0` | `GlobalCore.TextureLoadRequest` | 静态方法。仅限 Lua（`metadata = false`）。 |
| `getPath` | `texture: sf.Texture` | `string \| nil` | 静态方法。仅限 Lua（`metadata = false`）。 |
| `getMemory` | — | `int` | 静态方法。 |

缓存与查找规则：

- **`getPath(texture)`**：在当前缓存中查找精确匹配的纹理实例并返回其原始资源路径，不读取文件也不持有该纹理。在管理器外部创建的纹理或因清理缓存而移出的纹理返回 `nil`。返回路径不编码 `area`、`sRGB` 或 `smooth` 加载选项。
- **缓存共享**：`load` 与 `request` 共用同一份缓存与在途任务。精确路径、`sRGB`、`area` 与 `smooth` 共同构成缓存键（优先级不参与构成缓存键）。针对同一缓存项的重复请求共享解码与上传，并各自返回独立的订阅句柄。
- **就绪与重试语义**：缓存命中会立即进入 Ready 状态。同步 `load` 可直接完成匹配的挂起请求而无需等待下一帧，因此也能在 System 帧循环启动前使用。失败结果不会被缓存，后续请求可重新尝试加载。

### TextureLoadRequest

`TextureManager.request` 返回的实例句柄。它在被取消或释放前一直持有已就绪的纹理，且不会使其他持有者的引用失效。管理器在普通平台上保存弱纹理引用，在 iOS 上保存强引用直至缓存清空。

| 方法 | 参数 | 返回值 | 说明 |
|---|---|---|---|
| `getStatus` | — | `string` | 仅限 Lua。返回只读常量 `TextureLoadRequest.PENDING`（`"pending"`）、`READY`（`"ready"`）、`FAILED`（`"failed"`）或 `CANCELLED`（`"cancelled"`）。不等待，也不抛出保存的加载错误。 |
| `getTexture` | — | `sf.Texture` | 仅限 Lua。Ready 时返回就绪纹理，Failed 时抛出保存的加载错误，Pending 或 Cancelled 时抛出状态错误。不等待。 |
| `resolve` | — | `sf.Texture` | 仅限 Lua。在调用线程上同步完成请求并返回纹理；Failed 时抛出原始错误，Cancelled 时抛出状态错误。 |
| `setPriority` | `priority: int` | — | 仅限 Lua。更新当前挂起订阅的整数优先级（数值越大越优先，相同优先级按请求顺序处理）。已完成、失败或已取消的句柄不受影响。 |
| `cancel` | — | — | 仅限 Lua。释放本次订阅并将句柄标记为 Cancelled（Ready 或 Failed 后亦可调用）。可安全重复调用，已取得的纹理仍有效。 |

这些方法与常量仅限 Lua 使用，不生成蓝图节点。`TextureLoadRequest` 并非 `Engine.AsyncOperation`，不能传给 `asyncio.await`。请在常规更新中轮询状态，并在 Ready 或 Failed 时调用 `getTexture()`，确保必需资源的加载错误能正常传播。

调度、取消与预算行为：

- **共享订阅**：共享工作由当前所有挂起订阅中的最高优先级决定。取消或释放单个句柄不影响其他订阅者；当最后一个订阅者离开时，排队中的工作会被取消，在途结果会被丢弃（已经开始的解码或上传不会中断）。运行时关闭时会取消未完成请求，并在关闭图形上下文前等待解码工作线程结束。
- **工作线程与积压上限**：解码工作线程按需启动，并发上限遵循[当前进程的文件读取上限](<../../../../快速入门/Ludork Lua 进阶.md#协作任务与文件批次>)。待上传的已解码像素积压达到 64 MiB 时暂停启动新的后台解码，已在运行的解码继续完成。即使 `area` 仅选取较小的 GPU 纹理区域，积压仍按完整解码图像计入。
- **每帧上传预算**：每帧在 8 MiB 字节预算与 1 ms 时间预算内最多启动两次 GPU 上传（本帧首张纹理超过 8 MiB 时仍允许继续，已开始的上传不中断）。这些属于调度限制而非帧耗时或总内存硬上限，解码期间仍可能短暂持有额外像素副本与编解码缓冲。移动应用挂起时上传暂停。

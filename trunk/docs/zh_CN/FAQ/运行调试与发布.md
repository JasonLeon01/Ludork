# 运行调试与发布

## 可以在哪些平台开发和发布游戏？

编辑器支持 Windows x64 和 Apple Silicon macOS。游戏除这两个平台外，还可发布到 iOS、HarmonyOS 和 Android。移动端打包需要 C++ Source 项目和 Apple Silicon macOS；Standalone 使用编辑器所在平台的运行时。最低系统版本见[支持的平台](<../Ludork 文档.md#支持的平台>)，所需工具见[打包](<../编辑器用户指南/运行、调试与打包.md#打包>)。

## 为什么不能运行游戏？什么时候需要编译或导出？

首次运行前必须成功完成**导出**。C++ Source 项目还需要通过**编译**或 `tools/build_cpp` 成功完成 Debug 构建。编译生成原生代码，导出生成 UI 与语言运行文件，SceneInit 负责准备材质。Lua、UI JSON、游戏数据和本地化内容的修改不需要重新编译原生代码。准备失败时，先查看报告的第一个错误。详见[编译、导出与运行](<../编辑器用户指南/运行、调试与打包.md#编译导出与运行>)。

## 实时调试会把修改保存回项目吗？

实时调试只修改当前运行时实例，不写入项目文档，也不提供撤销/重做。请在运行前启用，并使用**独立窗口**。游戏存档仍可能保存受实时编辑影响的玩法状态。可编辑范围与实例生命周期见[实时调试](<../编辑器用户指南/运行、调试与打包.md#实时调试>)。

## 为什么打包项目的确认按钮是灰色的？

将鼠标悬停在禁用按钮上可查看原因。入口脚本必须保留有效的静态 `APP_NAME`，其初始值在[新建项目](<../快速入门/项目模板.md#模板参考>)时填写。声明规则和其他要求见[打包](<../编辑器用户指南/运行、调试与打包.md#打包>)。

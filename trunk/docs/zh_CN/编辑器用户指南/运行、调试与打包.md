# 运行、调试与打包

通过编辑器主工具栏或命令行工具构建、导出、运行、实时调试与打包 Ludork 项目。本页涵盖桌面端、移动端与 WebGL 构建、Windows 编译器管理、Lua 热重载及发行签名流程。

## 编译、导出与运行

主工具栏按**编译 → 导出 → 运行**顺序排列流程操作；Standalone 项目隐藏**编译**按钮。

| 操作 | 作用 | 执行时机 |
|---|---|---|
| **编译** | 保存项目并构建 Debug 可执行程序、原生绑定与预览运行时，完成后不启动游戏。 | C++ Source 项目首次运行前，以及修改原生 C++ 代码或绑定后。 |
| **导出** | 保存项目、执行 Export 插件 Hook，并生成 UI View、Lua 类型声明与本地化文件。 | 首次运行前，以及修改 UI 资产、本地化工作簿、生成产物或工具标识后。 |
| **运行** / **停止** | 校验通过后启动游戏。准备与运行期间切换为**停止**，点击可取消准备或终止游戏进程。 | 完成首次成功导出（C++ Source 项目还需完成 Debug 构建）后。 |

直接执行裸 CMake 构建不会启用**运行**按钮，须通过**编译**或 `tools/build_cpp` 完成 Debug 构建。失败或取消的导出不计为成功导出；一旦导出失败，在修复首个校验、Hook 或生成错误前无法执行**运行**或**打包**。

- **导出范围之外**：游戏变量与通用数据在保存时即时生效，生成的 Lua 文件纳入版本控制，不由**导出**负责。普通保存、编译、直接运行与模板创建不会生成 UI 文件。
- **独立命令行生成器**：`ui-assets generate` 仅输出 UI 文件，不执行 Export Hook，也不写入完整的编辑器导出记录。
- **材质与预览**：材质在[游戏初始化](<材质.md#运行时生成>)阶段独立准备，不属于导出步骤。预览运行时的配置见 [PreviewHost：构建、发布与排错](<../PreviewHost/构建、发布与排错.md>)。

### 打开项目时的自动准备

打开 C++ Source 项目时，编辑器在校验项目数据前会先检查已生成的原生绑定、构建与预览产物以及 UI 与插件导出文件。若缺少产物或准备记录，编辑器会直接基于磁盘现有文件自动触发 Debug 编译与导出，不保存尚未完整加载的项目数据。

进度对话框会跟踪当前步骤，完整日志写入 `~/Ludork/Log/<项目标识>/Ludork.log`（按项目绝对路径区分）。任何编译或导出失败都会取消打开流程并报告日志路径。仅修改源码不会在打开项目时触发自动重编。删除 `EditorCache` 后，C++ Source 项目会在下次打开时重新准备，而 Standalone 项目仍需在运行前手动执行一次**导出**。

若生成文件已存在，但蓝图字段或地图中的 Actor 覆盖属性未通过 Schema 校验，编辑器会弹出**重新构建并导出项目**提示。点击确认将重新编译、导出、重载并再次校验；点击取消则退出程序。若重试后仍存在错误，编辑器会通过常规无效数据对话框报告，不再重复提示重建。单纯的 JSON 语法错误不会触发此恢复流程。

### 增量运行、编辑锁与窗口模式

首次构建与导出成功后，若相关文件有改动，点击**运行**会提示**编译后运行**或**导出后运行**；取消或失败均会中止启动。修改 Lua、UI JSON、游戏数据与本地化内容无需重新编译原生代码。

- **编辑锁定**：编译、导出与运行准备期间，编辑器会禁用重复触发、文档编辑、撤销／重做与编辑快捷键，直至操作完成。游戏自然退出、取消或失败时恢复编辑；关闭项目会取消进行中的准备操作。
- **进度反馈**：准备、编译、导出与打包期间，工具栏会显示动画指示器（悬停查看当前步骤）且不自动切换底部页签，需要查看日志时可手动切至**控制台**。保存与引用检查使用统一的[编辑进度窗口](<启动页、工作区与快捷键.md#编辑与保存>)。
- **独立窗口**：在单独的游戏窗口中运行，同时保留编辑器内当前地图或大地图的视图。除非运行前启用了**实时调试**，否则游戏运行期间仍维持编辑锁定；**控制台**、**性能监视器**与帮助窗口保持可用。
- **嵌入模式（仅 Windows）**：在编辑器内部嵌入运行画面并锁定游戏视口布局。其他平台始终使用独立窗口。Windows 无法获取嵌入句柄时会以 `EmbeddedHandleUnavailable` 失败。

## Windows 项目编译器

Windows C++ Source 项目的原生编译器配置保存在 [Main.proj](<项目设置与资产布局.md#mainproj>) 中。点击**编译**按钮旁的小箭头并选择**更改项目编译器**即可切换；**新建项目**与 Windows **打包项目**（含 Source 转 Standalone）同样提供该选择器。Standalone 项目无需也不显示编译器选择。

### 支持的工具链与检测

| 工具链 | 检测方式与要求 |
|---|---|
| **MSVC** | 需要 Visual Studio 2022 C++ 生成工具（支持独立安装的 Build Tools），仅安装 IDE 不满足要求。 |
| **MinGW** | 从 Ludork 用户数据目录（列表中以括号标注来源）及已保存的用户／系统 `PATH` 检测。不限定具体 GCC 版本、C 运行库、线程模型或异常模型。 |
| **LLVM Clang** | 从已保存的用户／系统 `PATH` 检测。使用面向 Windows x64、采用 MSVC ABI 的 `clang-cl.exe`（需自行安装，编辑器不提供下载入口）。所需工具见[构建项目](<../C++ 原生开发/构建与模块布局.md#构建项目>)。 |

鼠标悬停在列表项上可查看可执行文件完整路径，同一编译器仅列出一次。项目已配置的有效 MinGW 或 LLVM Clang 即使后续移出 `PATH` 仍可继续选用。列表检测仅读取路径、版本与目标架构，不初始化构建环境或试编译；创建项目、切换编译器及实际构建时会验证工具链及依赖，其中 MinGW 与 LLVM Clang 须能编译并运行 C++20 测试程序。

**新建项目**与**更改项目编译器**均提供**获取 MinGW** 按钮（即使本机已安装其他编译器）。点击后会下载固定的 [WinLibs UCRT GCC 14.2.0（64 位、POSIX 线程、SEH）版本](https://github.com/brechtsanders/winlibs_mingw/releases/download/14.2.0posix-19.1.1-12.0.0-ucrt-r2/winlibs-x86_64-posix-seh-gcc-14.2.0-mingw-w64ucrt-12.0.0-r2.7z)至 `~/Ludork/Toolchains/WinLibs-14.2.0-ucrt-r2/mingw64/`，依次完成 SHA-256 校验、解压与验证并刷新列表。

有效安装后按钮显示**已安装**。取消或失败仅清理未完成的下载与解压临时文件，保留已有安装以供重试。下载操作不会改动现有项目的编译器，也不会修改系统或用户 `PATH`。

### 切换编译器与构建产物

在构建、导出或打包进行期间无法切换编译器。切换已有项目的编译器（含通过**打包项目**切换，或在同种编译器的两套安装间切换）须经过二次确认，确认框会列出原编译器与目标编译器。取消确认不会停止进程、删除文件或保存配置。新建项目的首次选择及重选当前编译器无需清理确认。

1. 确认切换后，编辑器停止本项目的游戏进程与全部预览宿主，等待进程退出与文件句柄释放，并在清理期间禁止重启。
2. 使旧的原生构建与预览记录失效，删除本项目 Windows 桌面端的 CMake 缓存、原生中间产物、依赖构建输出、启动器及 Debug／Release 二进制文件。源码、资产、存档、已有发行包与其他平台的构建目录均不受影响。
3. 仅当清理全部成功后，编辑器才将新编译器写入 `Main.proj`。常规切换后需重新执行**编译**；在**打包项目**中确认的切换会直接以新编译器继续构建与打包。生成有效的新构建产物后，预览功能自动恢复。

> **警告**：若文件占用或其他错误中断清理，编辑器会报告具体路径，但不会终止无关外部应用；请关闭占用文件的程序后重试。清理或保存失败时，`Main.proj` 仍保留原编译器，但已删除的构建产物不会还原，需重新构建。清理启动后关闭对话框无法绕过校验或强行继续打包。

各编译器共用相同的产物路径：`build`（CMake）、`bin/Debug` 与 `bin/Release`（可执行文件与运行库），以及 `build/launcher/<configuration>/Main.exe`（打包启动器）。

编译器身份属于构建状态的一部分：若配置与现有缓存不匹配，编辑器会触发上述确认与清理流程；命令行构建则直接返回错误，不会静默切换编译器或删除文件。详见[构建项目](<../C++ 原生开发/构建与模块布局.md#构建项目>)。

## 服务器连接

在 C++ Source 项目中，通过**游戏 → 测试服务器设置**配置本地开发服务器后，须重新执行 Debug **编译**。通过**打包项目 → 启用 Ludork 服务器**可单独配置 Release 连接（每次打开默认为空；dev 测试包同样使用 Release 连接）。Standalone 项目隐藏这两个选项。详见[简易服务器](<../简易服务器/部署与编辑器设置.md>)。

## 实时调试

点击**运行**前启用**编辑 → 开发工具与设置 → 实时调试**，即可在编辑器中直接修改运行中的地图。该选项默认关闭，准备或运行期间不可切换，且依赖**独立窗口**模式（切换至嵌入模式会自动清除并禁用该选项）。准备、编译与导出阶段仍维持常规编辑锁定。

游戏运行后，编辑器自动跟随玩家所在的普通地图或组合式大地图的当前子地图，禁止手动切换地图。大地图空洞、加载中的地图、无存活玩家的场景以及断开连接的会话均为只读状态。

**文件浏览器**仅允许浏览与定位资源（新建、重命名、移动、删除与编辑项目文件均被禁用）。实时视口的显示规则见[地图与世界预览](<../PreviewHost/地图与世界预览.md#视口选项>)。

| 区域 | 实时调试允许的操作 | 锁定／只读项 |
|---|---|---|
| **图块** | 在可编辑图层上绘制、擦除、取样与填充（画笔与[项目地图编辑](<图块集、自动图块与地图.md#图层与绘制>)一致）。 | 图层结构、显隐状态、图块集绑定、地图属性、大地图摆放与隐藏图层。 |
| **Actor** | 选中与删除存活 Actor（含玩家、运行时生成的 Actor 与子 Actor）；移动顶层 Actor（同时取消其当前移动路线）。 | 新增、粘贴或复制 Actor；直接移动子 Actor（含修改**角色信息**坐标）。 |
| **角色信息** | 查看属性值并编辑普通变量，包括内层类型受支持的 `Optional[T]`（允许设为 `nil`，非空值须符合声明类型）。 | **组件**、父类、蓝图标识与地图 tag。 |

- **实时同步**：Actor 的位置、生成、销毁与正在查看的变量值与游戏进程实时同步。删除操作执行正常的 Actor 销毁流程与生命周期回调。隐藏 Actor 按[地图预览规则](<../PreviewHost/地图与世界预览.md#actor-与图层辅助显示>)保持可检查状态。
- **子 Actor**：**世界大纲**将子 Actor 嵌套在其当前父 Actor 下。在地图画布上单击或拖动子 Actor 时，会选中并连同所有后代一起移动其顶层宿主。在**世界大纲**中可单独选中子 Actor，查看或修改其普通变量，或按正常生命周期删除它。
- **会话边界**：实时编辑不支持撤销／重做，也不会改动项目文档或将其标记为已修改。所有修改仅作用于存活的地图或 Actor 实例（包括休眠中的大地图区域实例），不会重放至重建后的实例（重建实例仍遵循项目定义与常规玩法持久化数据）。

> **注意**：实时调试期间游戏存档功能正常运行，可能将实时修改后的玩法状态写入存档。实时调试保护的是项目源数据，而非存档槽。

点击**停止**、游戏自然退出或启动失败后，编辑器会恢复项目地图视图与运行前的选中状态，并丢弃临时快照。焦点位于编辑器时，**独立窗口**中的游戏继续运行。

## 运行中重载 Lua

无需重启游戏即可热重载 Lua 函数：

1. 在外部编辑器中保存已修改的 Lua 源文件。
2. 在**控制台**中输入 `$r`，按 `Enter` 或点击**发送**。

热重载会更新已有函数定义，同时保留当前场景、对象与运行时状态。游戏须由编辑器启动且使用未归档的 Lua 源文件。控制台会报告重载结果；涉及数据结构或模块结构调整时可能需要重启游戏。详见 [Lua 热重载](<../Lua 与蓝图脚本/Lua 运行时与模块.md#lua-热重载>)。

## 打包

选择**文件 → 打包项目**，在左侧目标列表中选择打包平台。

| 宿主操作系统 | 可用打包目标 |
|---|---|
| **Windows** | Windows、WebGL（浏览器；C++ Source）、Standalone 项目（C++ Source） |
| **macOS** | macOS、iOS（C++ Source）、HarmonyOS（C++ Source，需 DevEco Studio）、Android（C++ Source，需 Android Studio）、WebGL（浏览器；C++ Source）、Standalone 项目（C++ Source） |

**WebGL（浏览器）** 位于[转换为 Standalone 项目](#将-source-转换为-standalone-项目)正上方。下文的发行版本、服务器、加密与归档选项适用于各游戏发行包目标。

右侧面板依次展示平台专属选项与通用设置；启用签名后，签名表单位于最下方并以水平分隔线隔开。切换目标会保留本次会话已填写的输入，点击**确认**仅采用当前所选目标的配置并打开构建日志窗口（过程显示动画指示器，完成或失败后启用**关闭**按钮）。

### 前置条件、应用标识与 Hook

- **macOS Xcode 检测**：在 macOS 上，C++ Source 项目打包 macOS、iOS 或转换为 Standalone 项目时需安装[完整 Xcode](<../快速入门/项目模板.md#模板参考>)。打开**打包项目**窗口时检测一次；若未安装，这些目标的**确认**按钮会变为**获取 Xcode**（点击直接前往 Mac App Store，不保存也不打包）。安装完成后须关闭并重新打开**打包项目**窗口以重新检测（切换目标或重新聚焦窗口不会重试）。已有 Standalone 项目、Android 与 HarmonyOS 不受此检测限制。
- **`APP_NAME` 校验**：生成游戏发行包需要有效的入口脚本与兼容模板。由[新建项目](<../快速入门/项目模板.md#模板参考>)写入 `Scripts/Entry.lua` 的顶层 `local APP_NAME` 必须唯一、赋值为非空静态字符串字面量且不可重新赋值，按 Lua 字符串规则解码后为合法 UTF-8 单层目录名（不能为 `.` 或 `..`，且不含 `/`、`\`、`:` 或控制字符）。
  - 若入口脚本存在字符串、长注释或数字字面量语法错误，提示会精确指出文件、行号与列号。打开或重新聚焦打包窗口时会执行检查；定义缺失、非法或为动态表达式时，**确认**按钮置灰（悬停查看原因）。
- **显示名称与应用标识**：移动端与 macOS 的应用显示名称直接取自 `Data/Configs/System.json` 中 `title.value` 的原始文本（不能为空且不含控制字符，不解析本地化键）。`APP_NAME` 用于生成稳定的应用／Bundle ID 及合规的 `<game-name>` 文件名前缀。修改标题或版本号不改变安装标识，但修改 `APP_NAME` 可能需要重新配置签名或描述文件。
- **导出与 Hook**：编辑器每次打包都会先执行一次完整**导出**（含 Export Hook 与 UI 生成）；随后游戏打包会执行 before-Pack Hook（Standalone 转换跳过此步；官方 Locale Tools 插件的 before-Pack Hook 仅用于排除 `Data/Locale/Locale.xlsx`）。命令行运行与打包直接使用已有 UI 与语言导出文件，不执行导出。材质程序在游戏初始化时生成，不依赖导出产物或前置检查。
- **暂存构建**：游戏打包仅处理暂存副本，不修改项目源文件。预览注册表规则见 [PreviewHost 可编辑模板与游戏成品](<../PreviewHost/构建、发布与排错.md#可编辑模板与游戏成品>)。
- **移动端资源替换**：Android、HarmonyOS 与 iOS 仅在资源转换与校验全部成功后才替换已准备的构建资源。替换前失败或取消会保留原有资源；替换期间出错且无法还原时会报告保留的恢复目录；替换完成后取消或清理失败会保留新资源（不回滚）并报告残留的恢复或暂存目录。

> **提示**：若打包提示输出路径访问被拒绝，请关闭正在运行的已打包游戏及打开输出目录的文件管理器窗口后重试。语言服务器与杀毒软件也可能短暂占用生成文件。

### 加密、凭据与调试符号

**加密游戏数据**统一控制脚本编译以及着色器、JSON 与存档加密；仅勾选其中部分子项时显示为不确定状态。

- **存档加密**：**加密存档内容**设置 C++ Source 运行时的默认值；Standalone 项目在 `Scripts/Entry.lua` 中通过 `SAVE_AS_LDC` 配置。详见[存档](<../Lua 与蓝图脚本/默认玩法/运行时数据、配置与存档.md#存档>)。
- **数据加密**：将暂存副本中的 JSON 转换为压缩并混淆的二进制 `.ldc`，源 JSON 仍可正常编辑。包含旧版压缩 JSON LDC 格式的发行包须重新打包。
- **运行时设置**：着色器加密覆盖 `Assets/Shaders` 中的源文件，数据加密覆盖打包后的 Data。打包器会在暂存区写入 `Data/RuntimeSettings.json`（含 `encryptShaders`、`encryptData` 两个布尔值），并随常规 Data 加密与 `.ldpak` 一并处理，用于控制运行时生成的材质着色器与元数据加密方式，不触碰源项目。开发项目等缺少该文件时两项默认均为 `false`；文件无效会导致材质准备失败。模板与 Standalone 转换不包含该文件（见[运行时生成](<材质.md#运行时生成>)）。

> **重要**：签名密钥、证书、密钥库与描述文件务必保存在项目及版本仓库之外。路径必须为可读的绝对路径，且不含 NUL、CR 或 LF 字符；密钥别名与密码同样不能包含 NUL 或换行符。
>
> 已保存的配置仅在 `~/Ludork/<平台>-signing.json` 中记录路径与密钥别名（见[用户数据目录](<启动页、工作区与快捷键.md#用户数据目录>)）；密码由操作系统凭据存储保管，日志会自动脱敏，且绝不会写入项目或生成的构建文件。

**调试符号**：Windows 发行包不含 PDB 文件，Android 与 HarmonyOS 发行包会剥离原生库中的调试符号。如需事后调试，请保留对应的原生构建产物。

### 打包与排除的文件

所有打包目标均包含 `Assets`、`Data` 与 `Scripts`。Windows、macOS、Android 与 HarmonyOS 还会复制 `Licenses` 及项目根目录的 `LICENSE.md`、`THIRD_PARTY_NOTICES.md`、`THIRD_PARTY_NOTICES_zh_CN.md`（iOS 同样从项目添加这些文件）。Windows、macOS 与启用 FFmpeg 的 WebGL 包同时包含 `ThirdPartySource`。

以下内容始终排除；暂存完成后若残留其中任一项或任意 `.d.lua` 文件，打包将直接失败：

- 任意层级的 `.DS_Store`、`.git`、`.vs`、`.idea`、`.vscode`、`.emmyrc.json`、`.gitignore` 与编辑器动画缓存（`*.anim.json`）
- 项目根目录的 `EditorCache`、`Cache`、`Intermediate`、`Log` 与 `Scripts/stub`
- [地图列表顺序](<图块集、自动图块与地图.md#地图列表与组合式大地图>)文件 `Data/Maps/_info.json` 与 `Data/Maps/<world>/_info.json`
- `Assets/Shaders/MaterialGenerated`、构建工具与预览组件
- before-Pack Hook 排除的文件

打包还会剥离 UI 中仅供设计使用的 `editor` 数据。无论 Data 采用 JSON、加密 `.ldc` 还是 `.ldpak`，UI 资产键均不带扩展名，Controller 引用均保留逻辑 Lua 模块路径。位于 `Assets`、`Data` 或 `Scripts` 内部的同名 `EditorCache`／`Cache` 目录以及 `Data` 其他位置的 `_info.json` 均作为普通项目内容正常打包。

### WebGL

WebGL 打包需要 C++ Source 项目、Emscripten SDK **7.0.0**、CMake 与 Ninja。可通过 `EMSDK` 环境变量、`PATH` 中的编译器或命令行 `--emsdk <目录>` 指定 SDK。缺少前置条件时打包器会直接报告错误，不会自动安装工具或替换依赖。已有项目需要支持 Web 的 SFML 与 LuaSF 源码（见[原生构建输入](<../C++ 原生开发/构建与模块布局.md#构建项目>)）。Standalone 项目无法构建 Web 运行时。

- **输出目录**：`dist/<game-name>-<full-version>-webgl`（指定自定义输出目录时替代 `dist`），包含 `index.html`、`Main.js`、`Main.wasm`、`Main.data` 及可用许可材料。构建与校验全部通过后才发布；失败或取消会保留既有产物。
- **支持特性**：支持正式／dev 元数据、before-Pack Hook、Lua 编译、着色器／数据／存档加密、`.ldpak` 与可选 Ludork 服务器集成，无签名选项。共用资源收尾流程准备好 `Assets`、`Data` 与 `Scripts` 后，Emscripten 会将该未归档目录或归档布局直接封入 `Main.data`，不另行发布独立下载目录。启用 FFmpeg 的项目支持[本地视频播放](<../Lua 与蓝图脚本/默认玩法/资源、音频、视频与特效.md#视频>)。
- **托管与运行限制**：
  - 须通过 HTTP 或 HTTPS 服务器托管完整目录（切勿使用 `file://` 直接打开 `index.html`），确保 WebAssembly 的 MIME 类型为 `application/wasm`，并保持生成文件名完整且位于同一目录。
  - 基于 WebGL 2 在单个 canvas 上运行，同时支持键盘、鼠标、触摸及[受支持的浏览器手柄与文本输入](<../Lua 与蓝图脚本/全局与 Core 模块/Core Modules/Engine/输入与服务.md#web-输入>)。
  - 加载完成后自动启动（`SceneInit` → 标题画面）。若浏览器阻止音频自动播放，游戏先静音运行，并在首次常规点击或触摸时解锁音频。
  - 全屏、后台降频与本地存储由浏览器管控；图形上下文丢失后需刷新页面。
  - 不支持几何着色器、自定义图片光标（使用系统光标）、原生嵌入式 WebView 窗口、编辑器控制台连接与实时调试；运行日志输出至浏览器控制台。
- **命令行入口**：Windows 运行 `tools/pack_web.bat <项目> [dist]`，macOS 运行 `sh tools/pack_web.sh <项目> [dist]`，或直接调用 `ludork-pack web-pack`。传入 `--check` 仅检测环境而不构建；命令行打包前须先在编辑器内完成导出。详见[浏览器用户数据](<项目设置与资产布局.md#游戏配置>)与[发行客户端配置](<../简易服务器/部署与编辑器设置.md#配置发行客户端>)。

### 将 Source 转换为 Standalone 项目

在 Windows 或 macOS 上打开 C++ Source 项目后，在**打包项目**中选择 **Standalone 项目**，即可为当前主机平台构建 Release 运行时与配套预览组件，并在 `dist/<源项目目录名>-standalone` 生成可继续编辑的项目。

- **导出与内容**：先保存并执行一次完整导出（含 Export Hook），跳过 before-Pack Hook。保留可编辑的 `Assets`、`Data`、`Scripts`、已有 UI 与本地化导出、材质图、`Data/MaterialCombinations.json`、UI 设计数据、Lua 声明、本地化工作簿、许可文件、适用第三方源码、`.emmyrc.json` 以及 VS Code Lua／EmmyLua 配置。
  - 排除原生源码、构建目录、Git、存档、日志与本地缓存；`EditorCache` 仅包含重新发布的预览元数据。
- **`Main.proj` 更新**：复制 `Main.proj`，将 `Cpp` 与 `packaging.dev` 设为 `false`，移除 `compiler`，并保留项目版本、FFmpeg 标记、发行版本与其他键；源项目的发行版本与 dev 偏好不被改动（已确认的 Windows 编译器切换仍按 [Windows 项目编译器](#windows-项目编译器)规则写回源项目）。
  - 发行版本、dev、加密、Lua 编译与 `.ldpak` 控件在此模式下隐藏。已有导出产物支持直接运行，但 `EditorCache/ProjectExport.json` 不会被复制或伪造，因此在编辑器内首次点击**运行**仍可能提示先导出。
- **Ludork 服务器**：**启用 Ludork 服务器**默认关闭。启用后，填写的 Release URL 与密钥将编译进运行时，生成的 Standalone 项目无法再修改该原生配置（见[发行客户端配置](<../简易服务器/部署与编辑器设置.md#配置发行客户端>)）。
- **macOS 签名**：复用游戏打包的签名身份、证书、密码、环境变量与本机凭据存储流程（未配置时采用 ad-hoc 临时签名）。对运行库、预览组件与根目录 `Main` 签名，仅向 `Main` 应用 entitlements，并校验签名后的预览组件。产物保持为可编辑目录（不封装为 `.app`，不对目录整体签名）；不提供公证，已保存的公证配置不生效。
- **命令行入口**：运行 `tools/pack_standalone.sh`（macOS）或 `tools/pack_standalone.bat`（Windows），参数为 `<source-project> [standalone-directory]`（完整输出路径）与可选 `--check`；参数说明见 [tools/README.md](https://github.com/JasonLeon01/Ludork/blob/main/tools/README.md)。
  - 命令行会校验已有 UI 导出（缺失或过期时需先在编辑器中导出，不支持无头导出）。暂存组装与校验全部完成后才替换目标路径，失败或取消均保留旧产物；输出路径不能覆盖源项目或其输入目录，且路径中禁止包含符号链接。

### 发行包与开发包

在打包选项中可设置**发行版本**（`packaging.version`，默认 `"1.0.0"`），C++ Source 项目还会显示**内部测试包（dev）**（`packaging.dev`，默认 `false`）。点击**确认**且参数有效时，两者同步保存至 `Main.proj`；点击**取消**则不写入。Standalone 项目始终写入 `packaging.dev=false`（即使旧项目曾设为 `true`）。

基础版本号必须由三段非负十进制数组成（如 `1.0.0` 或 `0.1.0`），总长度不超过 127 字节，不得含 `v` 前缀、前导零、日期或预发布后缀。版本号不在 `Scripts/Entry.lua` 中定义。

所有游戏打包命令均支持 `--version 1.0.0` 与 `--release`，C++ Source 项目另支持 `--dev`。命令行参数仅覆盖当次打包的 `packaging.dev`，不回写 `Main.proj`。Standalone 项目始终按正式版打包，忽略旧配置中的 `packaging.dev=true` 并拒绝 `--dev`。

打包器在启动时采集一次 UTC+8 构建时间并贯穿全部阶段。正式包直接使用基础版本号作为完整标识，dev 包则追加 `YYYYMMDDHH`（例如 `2026-01-01T07:00:00+08:00` 打包 `1.0.0` 得到 `1.0.0.2026010107`）。dev 模式不改变 Release 优化级别、签名、加密或安装标识。

| 平台字段 | 两种模式共用的值 | 示例（`2026-01-01T07:00:00+08:00`） |
|---|---|---|
| Android／HarmonyOS `versionName`；Apple `CFBundleShortVersionString` | 基础版本 | `1.0.0` |
| Android／HarmonyOS `versionCode` | `YYMMDDHH` 整数 | `26010107` |
| iOS／macOS `CFBundleVersion` | `YYMM.DD.HH` | `2601.1.7` |

- **日期与构建号限制**：构建日期须位于 `2000–2099` 年间，替换输出前会校验各平台上限。同一小时内重复打包会生成相同构建号；商店要求更高构建号时请等待至下一小时。产物名称在平台、架构、变体与签名后缀之前采用 `<game-name>-<full-version>`；重复打包同一标识仅替换对应产物。
- **`Data/BuildInfo.json`**：打包时在暂存区写入，包含 `version`、`fullVersion`、`dev` 与 `builtAt`（带 `+08:00` 时区的 ISO 8601 时间）。dev 包与正式包均按常规 Data 加密与 `.ldpak` 流程处理该文件，绝不写回源项目的 `Data`。应用发行版本独立于顶层[项目兼容版本](<项目设置与资产布局.md#mainproj>)及[存档 Schema 版本](<../Lua 与蓝图脚本/默认玩法/运行时数据、配置与存档.md#存档>)。

### 未归档目录与归档

所有平台默认以未归档的 `Assets`、`Data` 与运行时 `Scripts` 目录组织资源（WebGL 将该布局直接封入 `Main.data`）。`.ldpak` 归档选项默认不勾选；启用后，三个目录的完整内容分别打包为根目录的 `Assets.ldpak`、`Data.ldpak` 与 `Scripts.ldpak`，原有相对路径与 Lua 模块名保持不变。

加密与 Lua 编译均在归档之前执行，`.ldpak` 本身不加密内容。移动端打包遵循相同契约，且 Android 与 HarmonyOS 不会对 `.ldpak` 进行二次压缩。打包器会拒绝符号链接、大小写冲突、非法路径、输出冲突、损坏归档、缺失根目录、未归档与归档混用布局及旧式分组归档。

### Windows 与 macOS

Windows 输出 `dist/<game-name>-<full-version>/Main.exe` 及配套运行库；macOS 输出 `dist/<game-name>-<full-version>.app` 并以 System 标题作为显示名称。自定义输出目录将替代 `dist`。输出目录及其祖先路径均不可为符号链接或目录联接。

由 Standalone 项目打包的游戏发行包在根目录保留启动器，并将运行时二进制置于 `Binaries`（Windows）或 `Contents/Frameworks`（macOS）。适用时会附带 FFmpeg 声明与源码提供材料（见 [FFmpeg 选项](<../快速入门/项目模板.md#ffmpeg-选项>)）。

#### macOS 签名与公证

macOS 目标下的**签名应用**默认不勾选：

- **未勾选时**：采用本机环境变量（`LUDORK_MACOS_SIGNING_IDENTITY`、`LUDORK_MACOS_SIGNING_CERTIFICATE`、`LUDORK_MACOS_NOTARY_*`）配置签名；若均未设置则执行 ad-hoc 临时签名（无发行者证书或公证）。
- **勾选时**：在下方表单中提供 `.p12` 证书与密码、可选签名身份，以及可选公证凭据（Apple ID 搭配 Team ID 与专用密码，或 App Store Connect 密钥搭配密钥 ID 与 Issuer ID）。表单输入在本次打包中优先于环境变量；选择已保存证书会自动从 `~/Ludork/macos-signing.json` 恢复配置。公证要求真实签名身份，依次完成签名、提交 Apple、等待审批并装订票据；ad-hoc 身份将被拒绝。

证书签名与公证（覆盖编辑器、CI 与命令行；ad-hoc 临时签名除外）在遇到临时网络或服务故障时——包括公证通过后票据暂不可用的情况——会按 `5`、`15`、`30` 秒退避重试（每项操作最多尝试 4 次，仅重试失败目标并保持原选项）。无效凭据、证书、签名、被拒提交及失效或撤销票据会立即失败。

| 操作 | 单次超时 | 重试说明 |
|---|---|---|
| 签名、票据装订／验证、公证查询 | 2 分钟 | 最多 4 次（`5` 秒、`15` 秒、`30` 秒退避）。 |
| 凭据校验 | 5 分钟 | 最多 4 次。 |
| 提交上传 | 15 分钟 | 获得提交 ID 后，重试直接等待该 ID 而不重复上传。 |
| Apple 公证处理等待 | 每次等待 15 分钟（最多 4 次） | 等待或票据步骤失败时会输出提交 ID 供手动查询。 |

### iOS

在 macOS 上构建面向 iOS `16.3` 及以上版本的包，需要 C++ Source 项目、含 iPhoneOS SDK 的完整 Xcode 安装，且已完成 Xcode 首次启动设置。

- **签名应用（默认不勾选）**：未勾选时由 Xcode 使用已登录的 Apple Development 团队自动签名（设置 `LUDORK_IOS_DEVELOPMENT_TEAM` 时优先采用）。勾选后须在表单中提供 Team ID、`.p12` 证书与密码及 `.mobileprovision` 描述文件进行手动签名（证书与描述文件必须同时提供；团队或应用 ID 不匹配时拒绝）。表单值在本次打包中覆盖环境变量，选择已保存证书会从 `~/Ludork/ios-signing.json` 恢复配置。
- **输出与真机导出**：默认仅生成 `dist/<game-name>-<full-version>.ipa`，无需连接设备。勾选**导出到 iPhone** 后会安装并启动至唯一一台由 `xcdevice` 报告可用的物理 iPhoneOS 设备（iPhone 或 iPad，不支持模拟器）。解锁、信任与开发者模式提示由设备本身弹出；设备未信任开发者描述文件时当前会表现为签名错误。

### HarmonyOS

HarmonyOS 打包需要 C++ Source 项目、Apple Silicon Mac 及安装了 OpenHarmony 原生 SDK 的 DevEco Studio。产物为单个 `arm64-v8a` HAP，面向 HarmonyOS `6.0.2` / API `22`，在手机、平板与二合一设备上均使用 OpenGL ES 3。

- **签名 HAP（默认不勾选）**：未勾选时输出 `dist/<game-name>-<full-version>-harmony-unsigned.hap`。勾选后提供 `.p12` 密钥库、`.cer` 证书、`.p7b` Profile、密钥别名与密码（密钥密码默认与密钥库密码一致），无需连接设备即可输出 `-signed.hap`。
  - 已保存配置位于 `~/Ludork/harmony-signing.json`（密码存于 macOS Keychain），选择同一密钥库会自动恢复；失败时保留上次成功产物。命令行参数见 [tools/README.md](https://github.com/JasonLeon01/Ludork/blob/main/tools/README.md)。
- **Profile 与剪贴板权限**：支持有效且已签名、与包名匹配的 Debug 与 Release Profile。仅当已验证 Profile 通过 `acls.allowed-acls` 授权 `ohos.permission.READ_PASTEBOARD`，或具备 `system_basic`／`system_core` 访问级别时，HAP 才声明该权限；未签名包及无该授权的包均省略此权限。
- **真机导出**：勾选**导出到已连接的 HarmonyOS 设备**可对单台已开启开发者模式的连接设备执行签名、安装并启动。HDC 接受设备上报的 `default`、`phone`、`tablet` 与 `2in1` 类型，校验 Profile 对该设备的授权，并在无法读取设备类型时中止。安装失败会附带设备诊断信息。

### Android

Android 打包要求在 macOS 上的 C++ Source 项目，并将 Android Studio 安装在 `/Applications` 或 `~/Applications`。请另行安装 SDK Platform `36`、Build Tools `36.0.0`、完整的稳定版 NDK `r27` 及以上版本（打包时自动选用本机符合条件的最高 NDK 版本）与本机 CMake `3.28` 及以上版本。

生成的 APK 以 API `36` 为目标，支持 Android `7.0` / API `24` 及以上版本及双向横屏，仅输出 APK 而不安装或启动。

- **签名 APK（默认不勾选）**：未勾选时发布 `dist/<game-name>-<full-version>-android-arm64-v8a-unsigned.apk`。勾选后选择 JKS 或 PKCS12 密钥库（支持 `.keystore`、`.p12`、`.pfx`、`.pkcs12`，自动识别格式），填写密钥别名与密码（密钥密码默认同密钥库密码），并可将路径与密钥别名保存至 `~/Ludork/android-signing.json`（选中同一密钥库时自动恢复）。签名成功时仅发布 `dist/<game-name>-<full-version>-android-arm64-v8a-signed.apk`。

> **警告**：Android 要求已安装应用的更新包使用相同的签名证书；使用不同密钥签名的更新包会被设备拒绝安装。
